# 自动获取预览文件

[客户端设计](README.md) · [计划编辑](plans.md) · [全局预览契约](../architecture/preview-obtaining.md)

本页定义客户端如何维护自动预览取回、保存用户意图和展示结果。相机预览图片及预览视频都是正式产物，区别于浏览器把图片缩小显示。主机能力、选择、取消及调度以全局契约为准；实施状态与实际运行证据分别由[实施计划](../superpowers/plans/2026-10-09-client-spec-sync.md)和[验证记录](verification.md)跟踪。

## 开关与派生动作

新建计划默认开启“自动获取预览文件”。开关是用户意图；每个符合条件的拍摄对应的自动取回动作是客户端维护的派生内容。用户通过开关管理，普通界面不要求编辑自动动作的名称、来源、时间或筛选参数。可以查看完整动作及生成参数，但不会因折叠而从导出内容删除。

开关具有开启、关闭和“尚未设置”三种状态。“尚未设置”表示没有可靠的开关资料，界面应明确显示“自动预览尚未设置”，不能将其显示为关闭。客户端保留计划中的显式动作，直到用户选择开启或关闭后，才按该选择维护自动取回。

客户端按当前设备、拍摄类型及参数类型的明确预览支持声明判断。开关开启但没有适用动作时保持开启，显示当前没有适用动作；之后新增符合条件的拍摄时自动生成。自动取回沿用拍摄时间，保留明确自动用途及来源引用，一个拍摄最多一个。手动预览取回及其他普通动作独立管理，不根据名称相似而认作自动动作。

| 开关及能力状态 | 派生内容处理 | 导出 |
| --- | --- | --- |
| 尚未设置，任意能力状态 | 保留显式动作，不自动增加、删除或修改自动取回 | 不因开关尚未设置而阻止导出；仍按完整计划及所需能力校验 |
| 关闭，自动用途及关联可以可靠确认 | 移除自动预览取回，保留全部手动动作 | 按完整计划校验 |
| 关闭，但正文、身份或自动字段尚不能可靠解释 | 保留当前输入及诊断，等待关系明确后再移除 | 不用猜测的旧关系生成合法计划 |
| 开启，能力有效，拍摄选择完整且明确支持预览 | 维护一个对应自动取回 | 拍摄及生成动作全部合法后可导出 |
| 开启，能力有效，当前拍摄选择明确不支持预览，或类型明确改为非拍摄 | 按下文独立条件移除该来源的自动取回 | 当前动作按自身规则校验 |
| 开启，设备／拍摄类型／参数类型未选完或输入非法 | 保留未完成输入，不猜测支持；对尚不能可靠判断的既有派生关联保留待核实状态 | 阻止导出未完成计划 |
| 开启，能力加载失败、无法解释或无法可靠取得 | 保留开关，暂停依赖能力的派生；已证明的名称恢复和明确非拍摄判断按下文分别处理 | 阻止依赖该能力的计划导出；恢复有效后自动协调 |

已导出请求保持固定正文；能力变化只影响尚未导出的草稿及新建内容。自动维护不改写用户拍摄参数，不为非法输入补默认值，也不改变手动取回。

### 独立事实与协调顺序

客户端每次协调都分别判断四类事实：正文及自动关联是否可靠；来源当前类型、设备和参数是否完整；名称和时间是否有效且没有对应未完成输入；当前能力是否成功加载并明确声明支持。能力加载错误即使保留了此前有效说明，也表示当前支持判断不可用。名称恢复不声明设备支持，明确非拍摄也不需要设备能力证明，不能用一个条件遮蔽其他已知事实。

尚未设置不执行自动维护。其他状态先核对正文、稳定来源与取回身份、显式自动用途、来源引用及已经保存的可靠名称依据。自动字段或覆盖它们的祖先尚未完成、身份缺失或重复、引用与已保存投影矛盾时，保留输入并诊断，不根据旧值恢复或删除。仅当这些前提可解释时，关闭执行明确移除，开启按下表判定。

| 开启时的独立条件，按处理顺序判断 | 确定处理及后续资格 |
| --- | --- |
| 来源当前类型明确为已知非拍摄，且类型及其祖先没有未完成输入 | 移除该来源的自动取回；能力故障、名称冲突或时间未完成不改变这个已知事实。未知类型或未完成类型不能进入此分区。 |
| 来源仍为拍摄，类型、设备及参数足以判断，当前可靠能力明确不支持预览 | 移除对应自动取回；名称或时间问题不遮蔽已确定的不支持事实。类型、设备、参数或其祖先未完成时不能根据旧值判定。 |
| 尚不能确定上述移除条件 | 保留已有自动项。能力未知不授予不支持事实，也不使用此前说明增加自动项、更新依赖能力的参数或时间。 |
| 已证明关联的来源名称当前合法、在本次保留的全部动作中唯一，且名称及祖先没有未完成输入 | 更新对应来源引用和可靠名称依据，保持原取回身份；此恢复不依赖能力是否可用，也不要求其他用户字段已经填写完整。 |
| 名称仍重复、非法、缺失或尚未完成 | 保留可靠原引用及当前用户输入，说明待修正的事实；不能用歧义名称重新配对。 |
| 当前类型、设备、参数及有效能力明确支持，且来源输入和时间完整有效 | 生成缺少的对应自动项或更新派生参数与时间；存续自动项保持身份。 |
| 支持关系未知、当前选择非法，或派生所需输入尚未完成 | 保留已有项、未完成输入和诊断；不补默认值、不猜支持。此前独立成立的移除或名称恢复仍按其结果保留。 |

移除资格先确定，名称唯一性再以本次保留的全部普通和自动动作计算。同次已经明确移除的自动项不继续制造名称冲突。来源名称冲突既可以通过修改来源消除，也可以通过其他冲突动作改名或删除消除；每次重新判断当前集合，不能要求用户必须再修改一次来源。普通或自动动作后来改名制造冲突时，同样保留原来可靠的关联依据。再次协调相同草稿不重复生成或重新分配身份。

完整正文尚未可解析时，客户端保留原文和局部未完成输入，不从上一次成功解析的内容重建当前正文。局部输入保存及明确动作集合替换继续遵守[公共编辑规则](../architecture/client-editing.md#整组动作替换与移除)。

## 编辑联动与身份

下表中的拍摄编辑联动适用于开关开启的草稿。开关关闭时，客户端不生成自动取回；开关尚未设置时，客户端只应用用户的显式编辑，不维护自动取回。此时即使新增了支持预览的拍摄，也不自动增加取回；既有来源引用若因编辑而失效，按完整计划校验提示错误。

| 草稿事件 | 客户端处理 |
| --- | --- |
| 开启开关 | 为每个符合条件的拍摄补齐自动取回 |
| 关闭开关 | 删除本草稿自动取回，手动动作保持原样 |
| 新增或复制拍摄 | 判断支持情况，为符合条件的新拍摄创建独立自动取回 |
| 拍摄改名，或其他动作改名／删除消除冲突 | 按当前名称及可靠关联恢复来源引用，保留自动取回身份；无法确认时保留原输入与诊断 |
| 修改拍摄时间 | 能力及派生所需输入可靠时同步自动取回时间；未完成时间保留且阻止导出 |
| 修改设备或参数类型，仍支持预览 | 更新派生内容，保留自动取回身份 |
| 修改后当前可靠能力明确不支持，或类型明确改为已知非拍摄 | 按独立事实判定移除对应自动取回，不因名称或时间未完成而忽略已知事实 |
| 删除拍摄 | 删除其对应自动取回 |
| 能力说明成功重载 | 按开关状态处理全部未导出草稿；开启时自动协调，支持关系未变时不重复生成或重建身份；尚未设置时保留显式动作 |
| 能力说明加载失败 | 此次失败重载保留草稿，只更新能力故障观察；后续局部编辑的名称恢复及非拍摄判断按独立条件处理，恢复有效后继续能力派生 |
| 复制计划为新草稿 | 继承开关状态，包括尚未设置，创建独立草稿身份及关联，再按该状态和有效能力处理 |

草稿动作身份不使用可修改名称或数组位置代替；导出时生成协议要求的来源引用。生成名称须满足整份计划唯一性，不改名覆盖用户动作。反复打开、刷新或重新协调同一草稿不得产生重复取回。

自动维护以可可靠解析的编辑内容为依据。JSON 尚未写完或动作身份关联无法确认时，保留用户原文，等待可判定后再协调，不能用自动生成内容覆盖未完成输入。客户端依据协议中的显式自动用途和来源引用识别自动取回，不凭动作名称猜测。用户选择开启后，客户端复用可靠关联并补齐缺失的自动取回；选择关闭后，客户端移除明确标记为自动预览用途的动作，保留手动取回。非法或重复关联必须按协议校验，不能为了生成动作而猜测来源。

## 外部导入与整份 JSON 替换

客户端区分新建计划、恢复已有编辑意图和替换计划正文。开关资料只有与对应正文一同可靠保存和恢复时，才能用于恢复编辑意图；自动取回的数量或存在与否不构成开关资料。

| 操作 | 开关状态 | 正文处理 |
| --- | --- | --- |
| 新建空白计划 | 默认开启 | 按开启规则维护后续新增拍摄的自动取回 |
| 重新打开本地草稿，或复制有完整编辑资料的计划 | 继承保存的开启、关闭或尚未设置状态 | 恢复正文及关联，再按该状态处理 |
| 导入外部计划，且有与正文对应的可靠开关资料 | 继承所保存的状态 | 按该状态处理导入正文 |
| 导入外部计划，但没有可靠开关资料 | 尚未设置 | 保留全部显式动作，不自动维护取回 |
| 替换整份计划 JSON，且有与替换正文对应的可靠开关资料 | 使用替换内容所携带的状态 | 以替换后的正文为依据，按该状态处理 |
| 替换整份计划 JSON，但没有可靠开关资料 | 尚未设置，不继承被替换草稿的开关 | 保留替换正文中的全部显式动作，不自动维护取回 |
| 仅编辑单个动作的参数 JSON | 保留草稿开关状态 | 应用局部编辑，再按该状态处理 |

普通计划 JSON 不包含客户端开关资料。整份替换遵守[编辑结构替换确认](../architecture/client-editing.md#按动作类型保存编辑内容)：用户取消替换时保留原草稿；仅查看 JSON 不改变开关或正文。用户确认替换后，尚未写完或非法的 JSON 原文也必须保存，不被自动生成内容覆盖。开关及关联属于客户端编辑资料，不增加公共协议字段。

仅修正或移除整个 `actions` 字段时，按[整组动作替换与移除](../architecture/client-editing.md#整组动作替换与移除)明确确认并清除旧集合资料，自动预览成为尚未设置，集合外输入保留。正常局部编辑、添加、删除、复制及显示状态继续遵守[动作显示状态与追加接纳](../architecture/client-editing.md#动作显示状态与追加接纳)，不把这类操作当作整组替换。

## 保存、导出与恢复

开关的三种状态、拍摄的草稿身份、自动取回关联、正文及未完成编辑内容作为同一草稿版本保存。保存失败保留页面状态并提示；响应未知时核实完整版本，不因正文相同而忽略开关或关联变化。“尚未设置”允许保存，重新打开或复制时仍保持该状态。

导出必须使用同一份有效能力目录和同一草稿版本，按开关状态处理后执行完整校验，后端独立验证自动动作、唯一关联、时间及用途。开关尚未设置时，客户端直接校验显式正文，不先生成或删除自动取回；正文合法即可导出。若导出期间能力或草稿已变化，重新核实最新一致内容，不能把旧能力下的动作与新拍摄参数拼成请求。可靠保存原请求后，其自动取回动作、来源及请求身份固定，再下载不重新生成。

复制已导出计划时继承当时保存的开关；即使当时没有适用拍摄、正文中没有自动取回，也不能从“零个自动动作”推断开关关闭。因此客户端导出记录应同时保留用于复制的开关资料，该资料不改变固定请求正文。通过报告恢复的记录依靠显式自动用途及关联组织展示，不依赖本地草稿。

外部导入及整份替换遵守[开关恢复规则](#外部导入与整份-json-替换)。已知关闭不能被默认开启覆盖，尚未设置也不能根据动作数量改为开启或关闭。仅报告取得的记录仍遵守既有原请求可用性规则，不补造原请求或复制依据。

## 计划记录与媒体展示

自动取回默认并入对应拍摄记录；独立动作及 delivery 身份完整保留。用户可以展开技术详情或查看全部动作。手动取回保持独立动作展示。展示只使用报告公开的状态、结果、来源及交付字段，不从终态补造设备开始或结束经历。

| 自动取回或本地文件情况 | 默认展示 |
| --- | --- |
| 等待来源、修复、设备或正在取回 | 拍摄记录下显示简短阶段，不伪造实时进度 |
| 主机已经发布，本地尚未收到 | 显示等待接收，与获取成功分开 |
| 本地已可靠核验且可读取 | 展示预览图片或预览视频，折叠正常取回细节 |
| 取回失败、取消或本地文件核验失败 | 突出结果与原因，提供详情；拍摄成功不遮蔽该异常 |
| 报告尚未提供完整关联 | 保留可见的独立记录及待关联说明，不凭名称合并或隐藏异常 |

计划可以汇总已知预览获取完成数、等待数与失败数；汇总须明确基于动作结果还是本地接收，不从增量报告当前子集推算完整总数。自动取回未结束仍是计划未完成工作，隐藏细节不改变计划状态。

显示相机预览时标明其对应原文件；存在修复成品时，说明当前原片预览不代表修复结果。自动取回实际交付修复成品时，显示“修复成品已收到”，关联成品真实 `output_id`，不将其改名为预览产物。后续普通取回仍是独立请求；可提示已有合格本地副本，不能擅自删掉用户明确请求。

媒体导入、精确文件名关联、大小与摘要校验以及恢复沿用[媒体文件流程](result-browsing.md#图片与视频文件流程)。只收到预览不表示原文件已经收到。拍摄与取回的关联用于展示，不能把 delivery 从所属取回动作复制到拍摄实体内。

## 后续操作

用户可在计划、拍摄动作或具体产物上准备取回和清理。普通取回未指定 ID 时排除预览并按原片优先修复成品；按 ID 精确选择。清理按计划或动作包含原文件、预览及修复成品，按 ID 仅处理所选文件。界面使用“取回默认产物”“清理该计划／动作的全部源产物”等准确说明，不能把默认取回标为全部文件。

用户取消拍摄时，主机只有在该拍摄允许取消或已经终态时，才联动其可靠关联的自动取回；拍摄拒绝取消时，该关联取回继续原流程。组取消逐成员判断资格。取消整个计划时，计划内自动取回本身是直接目标，不依赖来源拍摄是否允许取消；单独取消自动取回只处理该取回。完整执行规则由[取消联动](../architecture/preview-obtaining.md#取消联动)定义。

客户端提交用户选择的原始取消目标，依据报告显示各项实际结果，不根据已经收到的动作子集另造联动目标。来源拍摄拒绝取消与计划内取回已处理可以同时成立；已发布交付的撤回、既有终态及保留的正式源产物和本地副本分别展示，不能把取消解释为全部文件删除。

## 验收与实施边界

验证新建默认开启、明确关闭及复制继承、开启但无适用动作、每种编辑联动、反复重载不重复生成、能力故障与恢复、未完成 JSON、保存失败和响应丢失、导出期间版本变化。

按[独立事实与协调顺序](#独立事实与协调顺序)组合覆盖可靠／矛盾关联、名称合法／冲突／未完成、明确非拍摄／未知类型、明确不支持／能力不可用以及派生输入完整／未完成。能力故障时分别验证不增项、不更新依赖能力的参数和时间、不凭旧说明删除，以及可靠名称恢复和明确非拍摄移除；名称恢复还覆盖其他动作改名或删除消除冲突。

按导入与替换表覆盖可靠开关资料存在及缺失两类输入，并分别提供含自动取回、不含自动取回和含非法关联的正文。验证尚未设置时正文保持、保存恢复、复制继承、能力重载和新增拍摄不触发维护、合法正文可导出而非法正文仍被拒绝；显式开启不重复生成，显式关闭仅删除自动取回。验证整份替换不继承原草稿开关，取消替换和仅查看不改变草稿，局部参数编辑保留开关，未完成原文不会被覆盖。验证只收到报告时仍能按可靠关联组织记录，部分报告先到不误隐藏动作。

验证取回失败醒目、等待与本地未接收分开、预览已收但原文件未收、修复成品替代、原片预览说明、手动取回独立展示及查看全部动作。按计划／动作／ID 分别验证取回和清理范围，客户端准备操作不提前改写主机状态。
