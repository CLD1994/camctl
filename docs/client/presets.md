# 拍摄参数预设

[客户端设计入口](README.md) · [计划编辑与交接](plans.md)

相机可能有多种参数类型，每种类型又有不同的可调参数。用户可以把某台设备的一组常用拍摄参数保存为预设，之后在编辑该设备的动作时选择使用。预设的公共含义、展开规则及相机参数约束由[能力、参数类型与用户预设](../architecture/camera-capabilities.md#能力参数类型与用户预设)定义；本页补充客户端的设备关联与使用范围。

## 预设与设备的关联

第一版按 `device_id` 分别保存和使用预设。用户选定设备及拍摄动作类型后，客户端提供与该设备、动作类型对应的预设；预设中的参数类型及参数值还须符合当前已启用的设备说明。

例如，用户为设备 `cam0` 保存“白天巡检”录像预设。之后编辑 `cam0` 的录像动作时可以选择这份预设；编辑 `cam1` 时使用 `cam1` 自己的预设。两个设备即使恰好使用相同的参数类型名称，也不能据此认为它们属于同一个驱动参数契约。

一份预设需要明确关联以下内容；表格描述业务信息，不限定客户端数据库的表结构：

| 信息 | 用途 |
| --- | --- |
| 预设名称 | 帮助用户识别一组常用参数 |
| `device_id` | 确定预设适用的设备标识 |
| 拍摄动作类型 | 确定预设对应哪一种拍摄能力，遵守第一版动作接入范围 |
| 完整 `params` | 保存参数类型 `params.type` 及该类型的具体参数值，按选定设备的规则解释 |

这里关联的是配置中的设备标识，不以参数字段恰好相同或文件名相似推断设备相同。使用预设不能绕过当前动作对设备、能力和参数类型的选择与校验。

## 在动作编辑区使用预设

预设操作位于拍摄动作的编辑区域，与该动作的参数表单和 JSON 编辑共用当前参数。用户先选择设备和拍摄动作类型，再使用对应预设或填写参数。

| 操作 | 输入与处理 | 结果 |
| --- | --- | --- |
| 保存为预设 | 用户为当前合法拍摄参数提供名称；后端检查设备、动作类型、参数类型及参数值后保存 | 创建一份独立预设，用于之后选择使用 |
| 应用预设 | 用户选择与当前设备及拍摄动作类型对应的预设，把其完整 `params` 复制到当前动作 | 参数进入当前草稿，可继续调整；动作名称、执行时间和业务策略等公共字段保留 |
| 更新预设 | 用户明确选择同设备、同拍摄动作类型下的已有预设，用当前合法 `params` 更新它 | 更新该预设以后提供的参数，不联动已经使用过它的草稿或已导出请求 |

例如，用户应用“白天巡检”后，为本次录像调整了某个参数。草稿自动保存这些修改，预设仍保留原来的常用值。用户希望以后也使用新值时，才点击“更新预设”，明确保存到选中的预设。

### 保存预设与保存草稿

创建和更新预设检查的是这组拍摄参数及其设备、动作类型关联，不要求整个草稿已经填写完整。录像执行时间尚未填写，或者其他动作仍有输入错误时，只要当前拍摄参数合法，就可以保存预设。预设不保存计划名称、动作名称、执行时间、组成员关系或整份计划的请求身份。

草稿自动保存与预设保存分别处理。无效或未写完的参数可以作为草稿保留，但不能作为新的有效预设保存，也不能覆盖已有合法预设。保存为新预设与更新已有预设由用户明确选择，不能只凭名称相同把新建操作改成覆盖。

后端可靠保存后才显示预设创建或更新成功。校验失败时显示具体字段问题，保留当前编辑内容及原预设；写入失败或提交结果无法确认时显示实际失败或未确认结果，再依据保存记录核实，不能让网页提示代替实际持久化结果。

每份预设保存最新一次明确创建或更新成功的内容，后续打开和应用均使用它；保存与备份恢复的边界见[草稿、预设与原请求](storage-and-recovery.md#草稿预设与原请求的保存)。

### 应用后的参数与后续修改

应用预设替换当前动作的完整 `params`，包括 `params.type`；表单据此显示对应参数结构。旧参数中没有出现在预设里的字段不继续混入。预设中省略的可选字段仍然省略，显式的 `null`、空字符串、`0` 和 `false` 均保持原值，不因为界面展示默认值就自动写入参数。

参数复制到草稿后，立即按当前已启用说明检查。存在参数错误或当前无法取得有效规则时，保留填入的内容并明确显示问题，导出继续遵守完整校验要求；可以保存待修正草稿，不把应用操作本身当作参数已通过校验。设备和拍摄动作类型不匹配的预设不能通过应用操作悄悄改变当前目标。

修改当前动作参数只改变当前草稿，其他草稿及预设保留原值。明确更新预设后，已经应用过它的草稿仍使用此前复制得到的参数；要采用新值，用户再次应用预设。计划导出保存的是这次草稿里的具体参数，后续不再动态读取预设。

## 设备说明更新后的预设

预设创建时保存合法参数，后续设备说明可能变化。例如，原来的参数类型被移除，或某个参数的允许取值收窄，原先合法的预设便可能暂时无法用于新计划。

客户端保留预设原有内容，依据后端当前已启用的说明检查适用性。按表从上到下判断，后续各行以前面条件均不成立为前提：

| 当前情况 | 处理 |
| --- | --- |
| 没有可用的已启用说明，无法核验设备规则 | 保留已有预设，显示规则不可用，不宣称预设已通过当前校验 |
| 当前编辑动作的设备或拍摄动作类型与预设不一致 | 不把该预设作为当前动作可选的适用预设，不自动改变目标设备或动作类型 |
| 设备、拍摄动作类型或预设中的参数类型已不在当前可用目录中 | 保留预设并说明不再适用，不自动改写成另一个设备或参数类型 |
| 相关设备和类型仍可用，但参数未通过当前规则 | 保留原值并显示具体问题，不能据此导出新计划 |
| 设备、动作类型、参数类型及参数值均符合当前规则 | 预设可用于对应动作；整份计划导出仍需执行完整校验 |

若更换相机后继续使用同一个 `device_id`，仍按该标识当前对应的设备说明重新校验，不能沿用旧规则作出有效判断。能力说明的读取失败、保留此前已启用说明及重新加载行为继续遵守[客户端部署与能力说明加载](../architecture/client-deployment.md#启动与重新加载)。

计划发给 camctl 时，包含明确的拍摄动作类型和展开后的 `params`，不要求主机读取客户端预设。预设后续修改不改变已经导出的原请求或主机已经受理的动作。

## 验收依据

- 当前拍摄参数合法但动作时间或其他计划内容未完成时，可以保存预设；当前参数无效或 JSON 未写完时，只能按草稿规则保留，不创建有效预设或覆盖原预设。
- 应用预设后验证完整 `params` 替换及 `params.type` 对应表单更新，公共字段保留，旧参数不混入，缺省与各类显式空值保持原样。
- 修改已应用参数并自动保存草稿，验证原预设不变；明确更新预设后，其他既有草稿和导出请求仍保持原值，再次应用才取得新值。
- 预设参数因规则变化失效时，应用到匹配设备的草稿后显示错误并保留待修正内容，不能据此导出；覆盖预设保存校验失败、写入失败和结果未知，确认界面不虚报成功。
- 为不同 `device_id` 保存同名或内容相同的预设，验证各自设备关联独立，编辑动作时只提供对应设备和拍摄动作类型的适用预设。
- 按设备说明更新表，覆盖规则不可用、设备或能力不匹配、类型移除、参数不再合法和全部合法；保留原值，错误不被自动改写成其他设备或参数。
- 同一设备标识更新为新的参数契约后，验证使用当前已启用规则重新检查；计划导出仍保存明确参数，主机执行不依赖客户端预设记录。
