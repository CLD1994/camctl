# MVP 验收

[客户端设计入口](README.md) · [职责与关键操作](architecture.md)

第一版客户端应通过本页六组验收场景，验证用户从部署、编辑和交接，到查看结果、发起后续请求及恢复数据的完整流程。验收依据是本目录已确定的行为和公共协议；各专题的决策表继续定义完整的状态分类。

文档与 JSON 检查只能证明规格产物相互一致。软件交付还需运行本页描述的实际操作和测试，才能说明流程可用；运行入口和软件验证范围见[客户端验证说明](verification.md)。

## 准备配套资料

验收需要一个按既定目录部署的客户端、可用的测试能力说明，以及匹配执行计划身份的报告和图片或视频资料。

| 资料 | 用途及要求 |
| --- | --- |
| 能力说明 | 包含验收场景所需的已启用拍摄能力及参数规则；没有真实设备时使用明确标注为演示的说明 |
| 执行计划与配套报告 | 报告中的请求、计划、动作和产物关联与相应输入一致，遵守[客户端协议样例](../architecture/client-protocol-examples.md)和公共 Schema |
| 与报告相配的测试图片或视频 | 报告给出该实际文件的完整名称、大小与 SHA-256；媒体内容与报告核验值必须匹配 |
| 局部同步报告样例 | 使用[状态同步业务演练](../../protocol/examples/status-sync/README.md)及其中的历史编号，验证缺口、补齐、清理状态和累计确认 |

协议样例中的报告可以用于结构、身份及状态合并测试。验证真实媒体导入时，应另行准备内容一致的图片或视频与配套报告；不能把任意文件改成相同文件名后，宣称它应通过摘要核验。验证视频播放时，还须使用浏览器可以解码的测试视频。不同独立场景分别准备一致的初始数据，避免把彼此无关的样例身份混成同一套历史。

这些资料可以验证客户端处理规则。真实设备的拍摄和媒体格式验收按[验证记录的外部边界](verification.md#外部验证边界)跟踪；客户端样例不会证明相机执行或第三方传输结果。

## 场景一：首次部署并准备录像计划

1. 在空数据目录部署并打开网页，确认提供“创建客户端数据”；点击后建立客户端数据并进入三个正常入口。
2. 在“设备说明”查看已启用的设备与参数规则。手工替换说明文件后重新加载，确认显示实际结果，并按公共规则更新可用能力。
3. 在“计划”的“草稿”中新建一份采集计划，添加录像动作和引用它的取回动作，使用测试设备已声明的参数类型。时间、名称和引用按公共协议填写。
4. 在内容尚未填写完整时等待保存，再重新打开草稿，确认恢复的是最新一次保存成功的未完成输入。修正后才允许导出。
5. 保存一份合法拍摄参数预设，应用后修改当前动作，确认预设与当前草稿独立；明确更新预设后，重开预设取得最新保存值，已经应用过它的其他草稿保留原值。

按[私有保存及公共资格](storage-and-recovery.md#草稿预设与原请求的保存)补充以下输入分区，保存后通过重开、复制或实际后端读取检查：

| 输入或操作 | 验收结果 |
| --- | --- |
| 正文尚未完成，或当前／停用类型保留业务非法文本 | 结构合法的私有编辑资料可以保存并恢复原文；当前公共内容不合法时不能导出，停用类型的业务错误不阻止当前合法类型。 |
| 数学值为整数的小数或指数写法 | 在字段范围内按整数接受；编辑、保存及公共校验保持相同数学含义。 |
| 非整数被浮点舍入成整数，或非零极小数下溢为零 | 原事实经过编辑、本地接口、存储、重开、下载与复制仍保持，整数分支拒绝；合法数值及参数规则的组合分支按原分类判断。 |
| 用户显式替换字段为新的整数值 | 新输入取得对应资格，即使浮点值与旧输入相同，也不恢复被替换的旧依据。 |
| 预设参数不合法，或合法参数写入失败 | 保留旧预设及当前编辑，失败不显示为创建或更新成功。 |

按[按参数类型保存编辑内容](../architecture/client-editing.md#按参数类型保存编辑内容)验证同一动作内的独立参数。测试能力说明中，普通录像 `example_record` 的 `standard` 档参考码率为 95 Mbps，另一类型 `example_record_from` 由用户填写参考码率。完成以下过程，所有其他公共字段保持合法，保存并重新打开后再次往返检查：

| 操作或输入 | 验收结果 |
| --- | --- |
| 普通录像选择 `standard`，填写 60 秒 | 当前参数可估算约 712.5 MB。 |
| 首次切换到可调参考码率类型 | 当前参数只有所选 `type`，码率和时长均未填写，不复制原 60 秒、不自动选择首项或写入 Schema 默认值。 |
| 在可调参考码率类型填写 70 Mbps 和 10 秒 | 当前参数可估算约 87.5 MB。 |
| 返回普通录像，再返回可调参考码率类型 | 分别恢复 `standard`／60 秒及 70 Mbps／10 秒，估算分别恢复约 712.5 MB 和 87.5 MB；其他类型的拍摄字段不混入当前参数。 |
| 在一类参数的数值成员留下未完成原文，再切到另一已合法类型 | 原文随离开类型保存，当前合法类型可估算和导出；切回后恢复原文，当前估算暂停并阻止导出。 |
| 整个参数、类型身份或其祖先有未完成原文 | 参数类型选择暂停，原文和全部类型资料保持；修正自身输入后按对应整体替换或类型选择规则处理。 |
| 仅存在停用参数类型资料，查看整份 JSON，再尝试替换 | 查看不写入；替换前仍需确认全部类型资料的清理范围，取消保留，确认才清除。 |
| 查看、折叠、切换表单与 JSON 或重复选择当前类型 | 不隐式补值或产生额外保存版本。 |

补充参数 JSON 和预设跨类型提供全文时采用明确内容、同类型替换不产生重复权威、切换外层动作类型后内层资料共同恢复，以及切换设备后资料保持并按当前能力校验。当前参数中的额外字段通过普通校验和参数 JSON 修正。数值字段说明同时验证包含与严格边界，并保留直接字段及本地引用中的原数字词元。

通过实际服务保存并读取一份含非法指针或非规范动作位置原文的草稿，保留当前及停用外层分支的参数类型资料，并覆盖自动预览已关闭但仍有派生预览动作的情况。页面能够读取并呈现既有问题区，不出现未处理的渲染异常；无法可靠归属时暂停相关转换和估算，原文、正文及资料均保持，不能通过清空它们使页面读取成功。

按[整组动作替换与移除](../architecture/client-editing.md#整组动作替换与移除)覆盖同数、异数、空数组和整个字段移除。取消保留全部原文与显示状态；确认后自动预览为尚未设置，清除旧集合资料并保留集合外未完成输入；祖先未完成、候选非数组及正文无法解释分别诊断。局部编辑、添加、删除、复制、显式开关和能力协调验证存续动作的折叠与局部 JSON 模式保持，新动作独立；旧无资料草稿查看或刷新不被动生成身份。

按[参数选项分类](../architecture/client-editing.md#参数选项联动)分别验证完整有限目录、独立字段、级联对象和无法推导的规则。普通录像的分辨率、视野、防抖、光圈和码率档位提供选项，录像时长提供数值输入，曝光按[对象参数级联编辑](../architecture/client-editing.md#对象参数级联编辑)先选 `mode` 再展示对应成员。复杂兄弟字段或其数值精度损失不取消当前合格字段的选项；根组合、依赖或未知断言仍阻止无法证明的独立选择。时长或曝光有未完成输入时仍可修正独立枚举，保存及重开保持两者原文。完整有限目录仍双向筛选，相关未完成输入暂停联动。缺省不补首项，非法原值保留，局部候选取全部断言的交集，空允许集与未知推导分开。选择其他字段保持直属与嵌套数字词元，当前候选无法准确校验时使用高级修正入口；设备说明页与编辑页使用相同分类。

普通录像时长及原数字边界按[相机参数契约](../architecture/camera-parameters.md#普通录像时长)核对。客户端验收还要确认字段表单、说明页、技术详情、校验摘要和 HTTP 诊断消费同一已启用规则；超界或非整数输入不能因 JavaScript 数字舍入而获准导出。测试覆盖直接字段、数组、本地引用、条件分支、嵌套默认值及数字字符串，并确认查看或切换表单／JSON 不改变草稿内容和保存版本。

数值步进验证 `0.3` 满足 `multipleOf: 0.1`，相邻长小数不满足；完整目录和独立字段均保留合法的 `0.3` 选项。补充零、负数、长整数、极小步进和巨大指数，零或负步进仍作为规则错误拒绝，不用浮点容差接纳不合法值。

按[校验与导出](../architecture/client-editing.md#校验与导出)验证当前字段反馈：

| 输入或操作 | 验收结果 |
| --- | --- |
| 新建或切换到电机动作，位置及最大允许延迟均未填写 | 顶部各有一项对应字段反馈，两个控件均有实际红框和短说明；修正一项只清除这一项，另一项保持，全部合法后摘要消失。 |
| 当前参数、策略、来源或取消目标为非对象 | 保留原值，在对应 JSON 显示红框、对象要求及可见焦点；来源／目标选择控件不承接父对象结构错误，不把结构错误改成子字段缺项。 |
| 曝光缺失或首次选择模式 | 先选择 `mode`，再展示该模式的必填成员；不补模式或子参数首项，不产生浏览保存版本。 |
| 普通录像选择 `manual` 或 `auto` | 分别展示 ISO 或 EV 的能力选项，已有合法内容回显，计划只含当前模式允许字段；其他设备与仅含模式的分支按自身规则展示。 |
| 模式切换、刷新、保存重试、重启、复制和导出后继续编辑 | 各模式的完整值、数字词元和成员原文分别保留，切回恢复；停用模式不进入请求或当前业务校验，保存核实包含完整资料。 |
| 曝光非法标量、未知模式、混用字段或未完成对象原文 | 保留原值和诊断，提供明确重新填写及高级修正；取消重填全部保留，确认后只清该对象内容、原文及分支资料。 |
| 模式缺省，或当前已选择模式缺少必填成员 | 未选择模式时，摘要定位模式选择器；已选择模式时，摘要和红框只指向当前分支的真实错误，不要求另一分支的成员。完整原始诊断及数量保留在技术详情中，点击定位不修改草稿。 |
| 参数类型或动作类型切换、动作复制删除及派生结构变化 | 对象分支资料随所属内容共同移动或删除；新动作不继承资料，其他动作与停用外层分支保持。 |
| 整体对象、参数、动作或计划替换 | 明确值优先，不恢复停用副本覆盖新值；按替换范围处理分支资料，整份或整组替换先说明并确认，取消保持全部内容。 |
| 当前 Schema 有引用、布尔节点或级联无法解释的规则 | 保留原规则及可用高级修正入口；设备说明展示完整原节点，查看不写入。 |
| 当前有未完成原文，草稿正文同时有解析或规则诊断 | 分别标明当前输入与草稿正文，不假定正文完整；字段、参数 JSON 和整份计划 JSON 共用分类，全部责任、数量、技术详情与两类输入定位保持。 |
| 已声明的直接设备字段没有标题或标题为空白 | 未完成输入显示字段标识；未知或继承属性、身份不匹配仍显示未识别输入，不猜测或修改内容。 |
| 报告范围为空、`since` 缺起点、`full` 合法或范围未知 | 空范围只要求选择；合法的 `since` 范围不因 `full` 候选失败而标红；未知值保持错误，不能默认选择。 |
| 当前来源或取消目标的每种唯一字段形状中含坏值 | 只显示当前模式的真实字段错误，不要求其他候选成员，不把当前 ID 同时说成额外字段。 |
| 选择空产物列表，或同时填写互斥的来源／筛选／列表并包含坏 ID 或非法列表 | 空列表定位添加入口；真实互斥组合明确说明涉及的设置并可定位 JSON，独立可证明的 ID、列表及筛选错误共同保留；单项修正只清除该项。 |
| 自动用途带入列表，筛选缺失／非法或来源不适用 | 同时显示方式冲突与自动用途当前的来源／筛选责任，已填写列表的非法状态继续反馈；修正字段或移除列表分别只清除对应责任，完整合法后摘要消失。手动或未知用途不因自动候选而要求专属字段。 |
| 设备 Schema 的独立叶子失败与真实组合失败同时发生 | 两项责任均保留，`oneOf` 多匹配不因叶子错误消失；原始技术详情可核对完整诊断。 |
| 设备 Schema 的两个独立 `allOf` 规则分别包含同目标的 `oneOf` 零匹配或多匹配 | 两项组合责任均出现在顶部、动作数量及参数 JSON 说明中；同一规则的重复事实可以归并，原始诊断全部保留。 |
| 设备 Schema 要求 `a.b`、`[x]`、`01`、`a/b~c` 或嵌套字段 | 从真实校验生产者定位对应控件或最窄 JSON，缺失键不依靠当前对象猜测。 |
| 停用类型保留非法值或未完成原文，当前类型合法 | 当前摘要、数量及导出只取当前输入；切回后恢复原文并显示该类型错误，缓存内容保持。 |
| 查看、展开及点击定位，再读取已保存草稿 | 草稿内容和保存版本不变；普通输入、文本区域和下拉的错误红框、说明关联与可见焦点保持。 |

顶部、动作数量、控件说明与定位必须反映同一份呈现。后端仍独立拒绝未修正的当前正文；参数区不另输出笼统的黄色错误摘要。

通过条件：三个入口可找到对应操作，草稿保存不丢失未完成输入，当前能力规则与预设行为符合约定，导出检查的是最新完整计划。

### 并发编辑与冲突解决

在独立验收数据中，让浏览器 A、B 连接同一个客户端后端并打开同一份未导出草稿。两页先读取同一个可靠保存版本，再分别执行下表操作。同步、冲突及同次操作核实的完整分类以[草稿的自动保存与并发冲突](storage-and-recovery.md#草稿的自动保存与并发冲突)为准，反馈与选择界面按[草稿并发冲突交互](page-interactions.md#草稿并发冲突交互)验证。每个场景检查两页实际完整输入和后端实际保存内容，不能仅观察提示文字或计划正文。

| 两页起点与操作 | 必须观察的结果 |
| --- | --- |
| A 连续输入并在最后一次修改后短暂停顿，B 保持已读取的完整内容且没有在途或未确认操作 | A 保留 450 ms 自动保存；B 接纳 A 的可靠完整版本，更新正文、编辑资料和保存时间，无须用户处理冲突，也不把轮询接纳写成另一保存版本 |
| B 修改后又恢复为已确认基线，且没有在途或未确认操作；A 保存不同完整内容 | B 按清洁页面的分类接纳 A 的可靠版本，不能仅凭曾经编辑过就持续锁在冲突中 |
| B 留有未保存修改；A 保存与 B 原基线完全相同的内容，仅使后端版本推进 | B 保留完整本页修改，接纳实际保存基线版本后继续普通保存，不制造只有版本号推进的冲突 |
| B 留有不同的本页输入；A 成功保存另一版本 | B 保留本页完整输入及可靠已保存版本，暂停向原草稿自动写入，持续显示冲突入口，不静默覆盖任一侧 |
| B 留有未完成数值或 JSON 原文；A 成功保存另一版本 | 未完成输入参与差异和完整版本选择，不以此前合法正文替换 B 的输入；业务校验与保存、冲突反馈分别显示 |
| A、B 的完整内容已经相同，双方均没有在途或未确认操作 | B 可接纳可靠保存版本并解除实际差异；不能据此声称某次旧保存请求已经执行 |
| B 的保存尚在执行，或响应未知且读取不可用、旧条件写入仍可能改变目标；读到的版本只有相同正文或完整内容恰好相同 | B 仍先核实自己的固定保存尝试；读取内容相同不能代替同次操作结果，不能提前显示成功或开放绕过核实的选择 |
| B 的保存结果未知，多次轮询及主动重新核实；核实先失败后取得可靠结果 | 本页输入和同次核实责任一直保留，失败显示实际阶段；重复核实不重复提交，也不重复消费已接纳结果，可靠结果取得后才转入相应保存或冲突状态 |
| B 保存响应丢失，该写入的依据随后被 A 的新写入取代；B 的请求已结束并取得可靠不同当前版本 | 说明旧保存结果不能证明，但在确认旧条件写入已不能改变目标后开放完整版本选择；分别另存、采用及明确替换可完成，完成后不重发旧输入，也不把旧写入说成成功 |
| B 以版本 1 提交 Y 后响应丢失；A 先保存 Z，再保存 Y，B 取得版本 3 且完整内容为 Y，但写入依据不属于 B | 以更高版本证明旧条件写入不能再改变目标，允许明确采用完整已保存版本结束旧调度；说明当前输入已经保存而 B 的旧写入结果仍不可确认，不要求再次替换相同内容，也不把 A 的写入认作 B 的保存 |
| B 在冲突面板选择将本页另存为新草稿 | 直接以完整本页输入创建独立草稿，不先刷新保存到原草稿；原已保存版本保持，成功前 B 的完整输入保留，共同转交成功后直接进入新草稿，不显示异常弹窗 |
| B 的另存请求已发出但响应丢失，重复核实或重试后确认成功 | 固定同次尝试及其内容，最终只产生一个新草稿；异常弹窗自动显示，未知期间放弃不可用，保留固定完整输入及编辑限制，不以另一次创建代替核实 |
| B 的另存明确没有完成写入，随后重试同次尝试 | 失败不显示已另存，异常弹窗提供重试和放弃；重试沿同身份同完整输入，成功只接纳一个副本；放弃停止所选安排并保留原会话完整输入 |
| B 的另存已经创建成功，响应未知期间新草稿被编辑、导出或删除，或原草稿被导出或删除 | 核实仍指向同次创建及同一新草稿，展示目标实际状态，不写回创建快照，不因目标后续变化自动创建副本；原草稿终态不阻止独立核实。目标终态结束创建核实但保留待决定限制；正文先说明重试将按保留输入另存新草稿，点击后才使用新身份，旧事实保持；放弃仅结束所选转交并保留输入 |
| B 选择使用已保存版本，并分别取消、确认放弃输入 | 取消保留本页全部输入；确认后完整接纳已保存版本，全部本页未保存正文和资料共同放弃，后续自动保存不把旧本页版本写回 |
| B 选择用本页版本替换已保存版本，展示差异后确认；A 没有再次修改 | 以展示时的远端版本执行条件写入，可靠成功后后端和 B 都取得本页完整版本；查看面板和取消确认不改变双方内容 |
| B 已查看或确认采用、替换时，A 再次成功保存、导出或删除原草稿 | 旧确认不能覆盖新事实；确认失效异常的重试更新完整差异并返回确认，放弃停止这次选择并保留输入及原冲突限制；终态时不覆盖，导航不能丢失待决定提示 |
| B 查看冲突后继续修正本页输入，或可靠读取到另一个已保存版本 | 面板按新的完整内容更新，两侧继续独立展示；旧采用和替换确认资格撤销，不能把旧比较与新内容一起提交 |
| B 已有可靠已保存观察，之后读取失败或无法确认目标状态 | 保留本页输入与此前实际观察，显示读取问题；不能自动采用或根据旧观察授权新替换，不能把读取失败解释为删除 |
| A 导出或删除原草稿，B 仍有本页不同输入 | B 保留完整输入，展示原草稿已导出或删除，不能保存、覆盖或重新创建原 ID；B 仍可将本页输入另存为新草稿，原导出记录或删除事实保持 |
| B 存在在途或未确认的导出、删除或追加，A 的版本或生命周期发生变化 | 原操作先按自身契约核实，冲突选择不能绕过该责任；核实之后按可靠结果处理，不把未确认操作解释为普通清洁页面 |
| 双方正文相同，仅未完成输入、动作类型资料、参数类型资料、对象模式资料或自动预览资料之一不同 | 分别以每类资料单独构造差异，再覆盖组合差异；每一类都能触发完整版本判断并在面板可见，选择成功后完整保留所选一侧，不逐字段拼接 |
| 完整版本含当前及停用外层动作类型、各自参数类型、嵌套对象模式、原数字词元、非法或未完成原文，以及自动预览开关和派生关联 | 分别执行另存、使用已保存版本及替换后，实际重开所选保存版本并往返切换所属类型和模式；原文、内容及归属与选择一致，不恢复未选侧资料，也不把相同 `Number` 投影当作相同原输入事实。另存建立独立自动预览身份并保持可靠关联；使用已保存版本和替换按对应完整版本保留业务内容及关联含义，内部身份需要重新建立时遵守[动作显示状态与追加接纳](../architecture/client-editing.md#动作显示状态与追加接纳)的统一映射规则 |
| 原草稿没有持久化动作身份资料；A 增加、删除或重排动作，B 按清洁页面同步或确认采用已保存版本 | B 正确显示新动作数量、顺序及内容，不沿用旧位置的折叠或局部 JSON 状态猜测同一动作，不补造持久化身份；有可靠稳定身份的版本仍按既有显示规则接纳 |
| A、B 从同一版本分别新建不同动作，然后 B 采用 A 的保存版本或明确以本页版本替换 | 不同新动作取得不同稳定身份；两页接纳结果时不把另一新动作当成原动作沿用折叠或局部 JSON 状态，可靠关联及全部所属分支内容仍对应所选动作 |
| A 已新增动作后，B 明确以基于旧版本的本页内容替换，再新增另一动作 | 身份分配不因完整替换回退；新增动作不复用 A 曾分配给另一动作的身份，两页跳过中间观察时也不能错认存续动作 |
| 双方有同名动作、不同顺序、改名动作或一侧动作原文无法解释 | 差异面板显示两侧各自的完整顺序、数量及实际内容，不按名称猜测对应项；无法解释的一侧保留原文和诊断，技术详情可查看全部事实 |
| 仅用键盘打开面板、查看完整差异、选择或取消，再关闭面板；另行覆盖提交、未知及异常待决定状态 | 焦点范围、Tab、Shift+Tab、Enter 和 Escape 符合交互规则；关闭面板或异常弹窗不解除冲突、核实或待决定限制，锁定期间不能修改输入、重复选择、导出、删除或追加，必要状态持续可见并可被辅助技术感知 |

另行验证未保存输入的刷新和关闭提醒，提醒不承诺尚未保存的会话输入可以跨刷新恢复。核对保存时间来自可靠后端记录，并区分已保存但业务不合法、保存失败、结果未知、冲突及原草稿终态。反馈测试断言事实、结构、顺序、操作资格及焦点行为，机器字段和版本条件精确断言；中文说明不逐字锁定。

#### 并发选择异常弹窗补充矩阵

前表 28 行的顺序和含义保持，以下 M 编号独立跟踪异常分区。状态及按钮语义分别以[另存的确认与重试](storage-and-recovery.md#另存的确认与重试)、[采用与替换的异常处理](storage-and-recovery.md#采用与替换的异常处理)为依据；呈现与焦点按[并发选择异常弹窗](page-interactions.md#并发选择异常弹窗)验证。记录须分别标出会话单元、组件组合和真实双浏览器证据；局部测试通过不能代替实际页面、导航及完整资料往返证明。

| 编号与实际场景 | 必须观察的结果 |
| --- | --- |
| M1：三种选择分别正常成功 | 完整共同接纳后直接进入所选目标，不出现异常弹窗，焦点到实际目标入口。 |
| M2：另存创建或核实请求仍在执行，重复点击或调用旧回调 | 不重复请求或转交，放弃暂不可用；输入固定，领域层拒绝编辑及其他写操作。 |
| M3：另存 `unknown`、`invalid` 或读取资格不可用 | 自动显示异常及实际原因；重试先核实固定身份和完整输入，放弃暂不可用，不生成新身份。分别覆盖错误身份、完整资料不匹配和核实读取失败。 |
| M4：可靠 `not_created`，分别重试和放弃 | 重试以同身份同完整输入创建；放弃后原会话仍持有完整输入，不再有同份独立未处理恢复条目；原冲突继续禁止自动保存。 |
| M5：创建可靠成功且目标可编辑，源显示、目标会话、Map、导航准备或校验分别失败 | 任何首个共同提交前的拒绝都保留双方原内容、显示与导航；重试只完成本地转交，创建计数不增加；放弃保留源完整输入及新草稿。 |
| M6：创建可靠成功，目标分别被删除和导出 | 核实结束但待决定限制保持；重试正文明确新另存，点击后才以保留输入和新身份创建，旧创建与终态保持。放弃保留完整输入，不复建旧目标。 |
| M7：M4–M6 分别叠加源草稿仍冲突、已删除或已导出 | 放弃只结束所选责任，冲突继续暂停自动保存，源终态继续只读；保留输入仍可供后续明确另存，普通观察及导航不覆盖输入或隐藏待决定入口。 |
| M8：采用或替换确认后可靠内容变化，或替换版本条件拒绝 | 自动显示异常；重试更新完整差异并要求新确认，不自动 PUT；放弃保留全部本页输入，冲突未解决时继续限制写入。 |
| M9：采用本地接纳失败，资格分别保持、失效后恢复、内容改变 | 资格仍成立时重试仅本地接纳；失效的旧确认不能复活，重新核实并重新确认；放弃在可靠资格成立时保留输入和后端事实，未可靠核实期间不能清除责任。 |
| M10：替换已可靠写入，本地完整显示接纳失败 | 分别点击重试和放弃，均不再次 PUT；页面分别表达已写入与本地处理是否完成，保留输入、真实后端内容和版本，不撤销写入或显示未写入。 |
| M11：外部 prepare 或 validate 返回前后，责任代次、所选身份、本页版本、完整资料或观察资格变化 | 首个共同 commit 前拒绝旧操作，任何一侧内容、Map、selected、页签及显示均不部分提交；旧 preparedEdit、定时器、按钮、导航回调不能绕过限制或在放弃后恢复选择。 |
| M12：同一会话有多个独立恢复输入，或同时保留未知写入、导出、删除、追加责任 | 重试和放弃只处理明确关联责任，不按相同正文合并或整组清空；已保存事实和独立责任分别显示，beforeunload（离页提醒）消费全部未结束责任。 |
| M13：异常自动打开、键盘浏览、Escape 隐藏及重新打开 | 自动聚焦不触发决定；Tab 和 Shift+Tab 留在弹窗内，背景点击不关闭；执行中不能关闭，其余时候隐藏不解除限制，重新打开入口持续可见且焦点可达。 |
| M14：保存结果核实入口读到可靠未写入，随后继续普通操作 | 核实入口只读，不调用 flush 触发新 PUT；普通保存仍按原资格执行，保存期间允许继续输入；并发选择异常规则不扩展到所有普通错误。 |
| M15：源导出观察触发页面导航，或关闭弹窗、切换草稿、等待超过 3 秒 | 完整输入及待决定提示仍可访问，Editor 卸载不消除领域限制或责任；隐藏后的旧回调不可操作，提醒不承诺跨刷新恢复。 |

M4–M10 的输入同时包含未完成原文、停用类型和对象模式、原数字词元及自动预览资料；分别断言每份完整内容及责任归属，不能只检查正文或数量。任务七在隔离真实页面覆盖实际按钮、导航和双浏览器交错；组件故障注入只能证明其对应的准备失败或旧回调分区，验证记录须明确边界。

## 场景二：导出、交接与重送

1. 导出完成的采集草稿，取得包含固定 `request_id` 的计划 JSON。原请求可靠保存后，该项进入只读计划记录。
2. 再次下载同一记录，确认身份和正文保持，累计确认仅按有效覆盖独立处理。
3. 用户标记已递交，页面展示标记时间，并仍根据报告证据判断主机是否受理及执行。重复标记保持原时间；清除后显示未标记，再次标记记录新时间，原请求及主机结果保持各自事实。
4. 复制这份计划为新草稿并修改。再次导出形成新的请求身份，原计划仍保留自己的交接与执行事实。
5. 覆盖下载中断但原请求已经保存的情况：重新打开记录仍能取得同一请求。原请求尚未保存成功时，保留草稿与实际失败结果。

以部署约定的真实 Node.js 模块方式启动默认服务，从未初始化进入 ready，保存合法的不依赖设备的草稿，以同一完整草稿及能力观察首次导出。验证默认随机源生成合法范围内的规范字符串，下载匹配固定身份和正文；终止后使用同一数据目录重启，无需重新初始化，下载原字节并重试原固定导出，保持同一记录。进程终止恢复、优雅停机和真实设备断电分别说明证据范围。

按[身份分配失败规则](plans.md#导出与原请求)分别注入候选越界、随机源错误、确认冲突及耗尽、首次查询失败和若干确认冲突后查询失败。只有可靠占用结果允许重选；其他失败保留真实诊断、旧请求和完整草稿，不留下新请求或导出标记。已有固定请求优先复用，不依赖新分配。

通过条件：不会因重复下载或页面未收到响应而制造新执行意图；复制产生独立的新请求；人工标记可更正，标记时间不冒充实际交付时间，清除不改变主机任务。

## 场景三：导入报告和媒体，查看结果

分别验证图片或视频先到、报告先到，以及同次混合选择的流程：

| 操作及阶段 | 预期结果 |
| --- | --- |
| 媒体文件完整保存，报告尚未到达 | 文件保留并等待报告，用户原文件保留 |
| 报告成功应用，媒体文件尚未到达 | 计划详情展示执行和交付事实，媒体显示等待接收 |
| 文件与有效报告映射齐全 | 自动关联并比较大小、摘要，无需重新导入此前已保存的文件 |
| 核验通过且图片文件可读取，格式受支持 | 在对应计划详情显示图片预览，并提供原文件下载 |
| 核验通过且视频文件可读取 | 在对应计划详情提供播放与原文件下载 |
| 核验通过，但浏览器不能解码视频编码或预览图片格式不受支持 | 显示无法预览或播放，仍可下载原文件，保留已有核验与主机动作结果 |
| 重复导入相同报告或相同媒体文件 | 依据原有接收和文件记录处理，不重复制造计划、交付或持久化媒体副本 |

补充一份包含动作失败或取回部分成功的合法报告，确认计划已结束时仍能分别查看各动作结果、成功交付和失败原因。网页应正确表达“主机已发布文件”“本地文件已保存”“本地核验已通过”这几种不同事实。

检查每份已接受报告都保留原文件名与完整原始字节，摘要与原文件名匹配。重新导入同一报告时复用已有原文；导入新报告后，旧报告原文仍可作为输入依据，页面继续展示合并后的状态。

## 场景四：从结果准备下一份计划

在计划详情选择已有产物或动作，将再次取回、取消或源产物清理加入用户选定的草稿。检查引用由可靠对象身份填写，草稿原有内容保留；按需填写执行时间，再校验并导出。

来源状态由报告决定。仅在客户端加入动作或导出计划，不会使原动作变成已取消，也不会使产物变成已清理。新的取回按新请求产生独立交付；相机源产物清理与个人电脑保存的视频分别处理。

通过条件：新请求能够准确表达所选对象和操作意图，原计划与本地文件在收到相应证据前仍显示实际状态。后续报告到达后，按相同协议更新结果。

顶部状态同步及计划、动作、产物的入口沿共同[追加接纳](../architecture/client-editing.md#动作显示状态与追加接纳)验证当前目标、其他已有草稿和新草稿。当前无身份资料的目标直接成功及响应丢失后确认成功时，旧动作显示状态保持，新项展开；完整可靠资料按 ID 保持，资料项数不对应则在发出追加前拒绝。准备失败、未知、冲突、明确未追加后重试和已追加但本地接纳失败分别保留各自事实，后者不重发业务追加；重复轮询不重复消费显示转换。

## 场景五：发现缺少历史并补齐

使用[录像 A/B 的完整历史](../../protocol/examples/status-sync/history.md)，在独立的验收数据中执行：

1. 客户端已经完整保存到位置 20，导入报告 3 `(40,45]`。保留原状态、抛弃该报告并保存缺口诊断，页面提示需要补齐已知缺失的历史。
2. 重新导入报告 2 `(20,40]`，完整进度更新到 40，但历史缺失提示仍保留。
3. 再次导入报告 3，更新到 45，解除当前提示并保留此前诊断。
4. 从第 1 步的状态另行验证同步路径：点击“准备状态同步”，默认从可靠的报告 1 之后补齐；选择已有或新草稿后正常导出、递交。主动选择完整同步时，生成相应完整同步参数。
5. 按业务演练导入能衔接的补齐报告，验证录像 B、录像 A 的清理结果及相关状态正确合并，未出现的既有子成员仍保留。报告可靠保存后，下一份真实业务输入可以附带合格累计确认。

再验证同次选择报告 2 和报告 3 时，无论文件选择和上传完成的先后如何，都先应用能够衔接的内容；大视频的上传不阻塞报告结果展示。某份报告校验失败时，按实际剩余覆盖处理。

通过条件：缺口判断、同步参数与提示消除分别由正确依据决定。导出、人工递交、主机同步动作成功和视频接收均不能代替报告合并。

## 场景六：中断、文件不符与恢复

以下情况分别验证，不要求在同一次操作中人为叠加全部故障：

| 情况 | 预期结果及恢复方式 |
| --- | --- |
| 图片或视频上传未完成时关闭网页 | 保留中断结果，重新选择后从头导入 |
| 完整媒体文件正在核验时关闭网页，后端正常运行 | 核验继续，重新打开网页可查看实际结果 |
| 后端重启，完整媒体文件尚未核验 | 根据保存记录和文件事实继续处理；可核验时从本地文件开头计算摘要 |
| 一批报告中部分已提交，后端随后中断 | 保留成功报告及覆盖，重新选择原批文件时仅继续尚未成功接受的内容 |
| 本份报告的原始内容保存失败 | 本份导入失败，不能部分保存成功接收、业务更新或确认；此前成功的报告保留 |
| 同名媒体内容不同，已有报告证明新文件正确、旧文件错误 | 新文件完整保存并核验后替换，保留原失败诊断；其他组合按[同名媒体规则](files-and-status.md#重复导入同名媒体文件)处理 |
| 能力说明加载失败 | 按此前有无已启用说明分别展示；数据库正常时仍可导入报告和使用不依赖拍摄参数的功能 |
| 数据库或文件无法可靠读取 | 显示具体故障或无法确认，保留诊断及已有数据，按恢复规则处理 |
| 停止容器、复制完整数据目录并恢复 | 草稿、原请求、预设、交接记录、报告原文与进度、图片、视频及其关联随同恢复；旧备份需要的补齐按同步规则处理 |

通过条件：每种失败都保留实际已完成结果，未完成和未知不被显示为成功。完整分类见[数据保存与恢复](storage-and-recovery.md)及各操作决策表。

## 验证层次与交付判断

单元测试验证具有独立契约的局部行为，例如报告覆盖判定、同步起点选择、参数校验结果或文件开放条件，通过测试替身隔离真实数据库、文件和网络。

集成测试验证真实协作者组合，包括后端与 SQLite 的原子保存、文件保存和恢复、网页与后端交互，以及部署后的完整使用流程。使用真实文件、数据库或子进程的检查属于集成测试，遵守仓库测试分类。

实现后的交付检查应证明：

- 按文档可完成首次部署，并找到三个入口中的主要操作。
- 草稿、导出、手工交接记录、报告处理、媒体核验与后续请求形成完整流程。
- 正常路径以及各专题规定的必要失败处理有对应验证，尤其是请求身份、报告覆盖和文件一致性。
- 已完成的软件和真机验收、当前仍待 Action6 延时摄影及 OSMO 360 II 调试的范围，以及保留的后续部署与传输验收分别列明，见[验证记录的外部边界](verification.md#外部验证边界)。

具体测试框架、测试函数划分和实施顺序在实现计划中确定，不能用文档链接检查代替这些运行证据。

## 自动预览及范围操作

按[自动预览验收](automatic-previews.md#验收与实施边界)覆盖开关三种状态、外部导入与整份替换、局部编辑、能力变化、自动动作身份与完整保存版本、派生导出、折叠展示和异常可见性。能力失败时，已证明名称恢复和明确非拍摄分别判断，未知支持不转为不支持；其他动作改名或删除消除名称冲突后继续恢复。

按[计划级控制](automatic-previews.md#计划级控制)在真实浏览器验证单一入口的交互：已确定状态一次点击往返；尚未设置的打开、悬停、方向键和取消不改变完整草稿、不安排保存；首次明确启用或禁用只接纳一次意图，焦点回到入口，保存重开恢复该选择。保留复制及完整替换的原有分区，尚未设置的合法显式正文仍可导出。

分别验证忙状态、动作身份问题及各类导出、删除、追加锁下的入口禁用和菜单关闭。关闭过渡中的两个实际 Portal 选项须保持不可操作，强制激活也不改变内容、版本或保存次数；会话已同步加锁但界面尚未重绘时，旧菜单项也不能接纳编辑或产生未处理错误。普通保存期间继续允许选择并可靠保存最新意图。验证能力与关联具体诊断、开启但无适用拍摄的说明、手动取回的身份及完整参数保持，以及 1280px 与 390px 无横向溢出。

两个拍摄各有独立自动取回，与一次取回选择组或计划中的多个来源，是不同发布责任。按[自动取回的责任](../architecture/preview-obtaining.md#自动取回的责任)、[按计划取回](../architecture/obtaining-outputs.md#按计划取回与预览筛选)及[开始发布的条件](../architecture/obtaining-outputs.md#开始发布的条件)验证：

| 场景 | 必须观察的结果 |
| --- | --- |
| 同一计划的 A、B 分别对应独立自动取回 X、Y | X 按 A 的来源、修复和准备事实独立发布，Y 未完成不阻止 X。 |
| 一次组或计划来源取回选择 A、B | A 可以先准备文件；该次取回只有全部固定来源和所选条目取得最终准备结果后，才开始发布成功文件，不等待非产物动作或整个计划 completed。 |
| 达到开始发布条件，部分条目准备失败 | 保留逐项失败，发布成功准备的文件；允许逐文件交接，不把统一开始条件解释为同时或原子发布全部文件。 |
| 主机已经发布，本地尚未收到 | 客户端显示等待接收，本地核验通过才开放合格副本。 |

按[取消联动](../architecture/preview-obtaining.md#取消联动)分别验证单个拍摄允许／已终态／拒绝取消、组内混合资格、整个计划和单个自动取回。动作或组中的拒绝成员不授予其联动资格；整个计划中的自动取回作为直接目标独立处理。报告保留各项结果、既有终态、交付撤回及产物保留事实，客户端不另造联动目标。

公共字段和共享样例以根 `protocol` 为准。客户端集成证明报告消费、可靠关联和媒体展示；主机或跨组件集成另行证明实际产物选择及大小替代、准备、独立及范围发布、取消和清理执行。使用报告夹具不能宣称主机已执行，软件协作验证也不能替代真实设备联调。
