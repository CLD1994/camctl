# 同机文件批次

[文件拷贝](file-copy.md) · [取回](obtaining-outputs.md) · [清理](output-cleanup.md)

同一取回或清理动作在一台相机上的全部文件构成一个文件批次。批次取得设备后连续处理其成员；不同动作不能在文件之间穿插使用该相机。不同相机独立调度，主机正式源文件不申请相机批次。

## 申请与执行

批次只能在动作已到计划时间、目标身份可靠且来源条件满足后申请设备。取回等待该相机全部来源拍摄进入终态、相关产物处理结束并固定完整选择；等待期间不占相机。其他相机的未完成来源不阻止本相机批次。自动预览沿其独立取回动作应用同一规则。

选中成员先完成建档。使用同步副本的本地读取及可能换回相机来源的判定先独立完成；确实需要相机读取或查询的剩余成员再申请批次。已完成内容校验、仅剩本地准备或发布的成员不延长设备占用。尚未取得批次时，尊重已到时拍摄以及按既有文件顺序更早就绪的内部检查、修复输入读取。

清理先建立逐产物限制，保护此前已经取得资格的读取。该相机完整目标集合仍存在旧读取依赖时，清理等待而不占设备，允许旧取回完成。批次占用不授予读取资格，也不撤销原有保护。

没有持有者时，合格批次依次比较所属动作的 `scheduled_at`、取回先于清理、`plans.id` 和原 `actions` 数组位置。已经持有设备的批次保持归属，不被后来到达的候选抢占。

| 当前事实 | 处理 |
| --- | --- |
| 来源或完整目标尚未确定 | 等待，不占相机，不消耗调用次数 |
| 相机由其他批次、拍摄或尚未收场的调用占用 | 等待，不消耗调用次数 |
| 清理目标仍被旧取回依赖 | 保持删除限制，等待，不取得批次占用 |
| 批次持有设备，成员读取或删除正在执行 | 继续原成员，其他批次等待 |
| 批次持有设备，成员等待有限重试 | 保留批次和累计预算 |
| 动作取消，但实际调用或结果保存尚未收场 | 继续原责任收场，保留占用 |
| 本机全部成员均已完成设备相关处理 | 可靠释放批次，选择下一批 |

普通拍摄准备、启动、设备检查及其他文件读取不能穿插持有中的批次。必要停止及原实际调用的收场始终保留推进机会；停止与当前实际调用仍遵守驱动传输互斥，不能同时访问不支持并行的控制通道。

## 完成、取消与恢复

取回的设备阶段包括可能要求重新读取的校验和有限重拷；全部本机成员均已完成设备读取与内容校验，或最终失败、取消且实际读取结束后释放。仅剩本地准备、发布、等待组内其他相机或对外传输时不占相机。清理完成全部本机删除、必要查询及相关调用结果保存后释放。分页当前页处理结束不能代表整批结束。

批次归属由状态库保存，独立于逐文件读取机会；释放一份文件不释放整批。重启恢复先接续原占用、成员进度与剩余预算。取消、超时、异常及提交结果未知都不能直接清空归属；先核实原实际调用和已保存事实，再按相同规则释放。

Hasselblad 的所有实际 USB 调用共享原机身的互斥边界，覆盖身份检查、拍摄准备、拍摄、下载、删除和列表查询。下载结束后对本地文件的读取不持有 USB 互斥。

## 持久化边界

`device_file_batches` 保存所属动作、目标设备、取得占用及释放的历史事件引用。同一设备最多有一条尚未释放的批次记录。该表及对应事件属于数据库整体格式 V9；V8 通过显式升级保全原表、历史及预算，升级不根据旧尝试伪造批次归属。

升级前已经持有逐文件机会且原读取尝试仍未结束的文件，先沿原票据完成当前读取、校验及实际收场，不增加尝试次数，也不补造批次。该原文件结束后，同动作剩余文件再应用完整来源等待和批次申请规则。已有批次记录的动作不能采用这项升级续接方式。
