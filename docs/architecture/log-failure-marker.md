# 报告故障标记

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

本页定义 camctl 如何跨 `run` 识别同一轮报告故障，并保证该轮只尝试交付一份日志副本。首次触发、故障恢复及副本交接见[日志副本交付](log-delivery.md)。正式标记、标记临时文件和日志副本承担不同职责，分别判断其存在性、内容及清理资格。

## 跨 run 的独立状态文件

第一版采用独立的小型状态文件，以正式文件是否存在表示跨 `run` 的故障状态：存在表示本次故障持续，不存在表示当前没有故障标记。首次报告失败时创建，报告本地处理可靠恢复成功后删除。首次部署不预先创建该文件。文件位于实际 `staging/logs` 下，由 camctl 留在本地维护；主程序不领取它，普通日志轮换不删除它。日志副本被传走或删除，不改变该状态文件的存在性。

第一版以故障标记文件能够正常删除为明确运行假设。业务状态报告的本地处理可靠恢复成功后，camctl 删除故障标记文件并同步所在目录；本次故障结束，之后再次发生报告故障时可以建立新标记。故障标记删除的设计与验收按这一正常流程展开。

正式状态文件的存在性及其内容是这组故障标记及日志副本管理信息的权威来源，检查和读写不依赖业务状态数据库可用。文件内容保存本次身份及日志副本处理进度；是否仍处于一轮故障由文件存在性判断。业务历史及报告责任继续由状态数据库管理，重复错误继续写入普通日志。

| 保存的信息 | 含义 |
| --- | --- |
| 故障轮次标识 | 将多次报告尝试及多次 `run` 关联到同一轮故障 |
| 本次日志副本身份及文件名 | 识别本次已尝试交付的日志副本 |
| 最后可靠确认的处理阶段 | 区分已开始复制、副本已完整保存、已移入 `ready` 并完成目录同步等事实；具体字段与状态枚举在实现设计中细化 |

存在性检查与内容读取分别判断，首次触发资格按下表处理。文件存在只表示本次已建立标记，不证明日志副本已准备完成或成功发布。执行本表前，先按[故障标记异常后的再检查](#故障标记异常后的再检查)判断本次是否允许检查；同一故障在本次运行中已经因检查或创建错误暂停尝试时，不因后续报告再次失败重复执行本表。

| 正式状态文件的存在性 | 内容读取结果 | 新一次报告失败的处理 |
| --- | --- | --- |
| 可靠确认不存在 | 不适用 | 创建新故障标记及日志副本身份，可靠保存成功后再复制日志；创建失败或保存结果未知时停止本次日志副本交付流程 |
| 可靠确认存在 | 内容有效 | 本次故障持续，不触发另一份日志副本；camctl 使用已保存身份和进度识别本次日志副本，失败或中断的交付流程不自动接续 |
| 可靠确认存在 | 内容无法读取或无效 | 仍能确认存在故障标记，不触发另一份日志副本；身份和进度保留为未知，不由内容读取失败推断无故障 |
| 无法可靠确认是否存在 | 不适用 | 记录实际检查错误，保留存在性未知，不当作不存在，也不据此开始新一轮；按再检查规则暂停本次运行中同一故障的后续尝试 |

存在性检查成功取得正式文件信息时判为存在，明确返回路径不存在时判为不存在；父目录搜索权限不足等检查错误须单独保留，不能捕获所有文件操作异常后统一返回“不存在”。已经确认文件存在后，内容读取失败不改变该存在性判断。此处只要求正确区分检查结果，不增加独立轮询或复杂的故障探测机制。

下表定义文件操作能够可靠完成时的正常更新流程；恢复成功的依据遵守[首次失败与重复失败](log-delivery.md#首次失败与重复失败)。

| 当前可靠状态与新事件 | 更新及后续处理 |
| --- | --- |
| 正式状态文件可靠确认不存在，发生报告处理失败 | 创建状态文件，保存新故障轮次及日志副本身份，再复制日志并将本次副本移入 `ready` |
| 本次日志副本准备或发布取得可确认的结果 | 保存对应的实际处理进度，不将已触发记成已发布 |
| 本次尚未恢复，后续报告处理再次失败，包括跨 `run` 的情况 | 沿用已有轮次及日志副本身份，继续记录普通日志，不因重复失败创建日志副本 |
| 正式状态文件存在，报告本地处理已可靠恢复成功 | 删除状态文件并同步所在目录，结束本次故障标记；日志副本的既有交接事实仍按其实际状态处理 |
| 正式状态文件可靠确认不存在，报告本地处理成功 | 保持无故障标记，无须创建状态文件 |
| 上一轮状态文件已可靠删除，之后再次报告处理失败 | 创建新状态文件及新的日志副本身份，再按首次触发流程处理 |

创建或更新采用先完整写入临时文件、同步文件，再原子放置到正式路径并同步目录的方式；更新已有文件时原子替换，不先删除正式文件而暴露无故障标记的间隙。只有正式状态文件作为故障标记，临时文件按[标记临时文件清理](#故障标记的临时文件)处理。本次结束后的迟到进度更新不得重建已删除的状态文件。状态文件操作与日志副本发布分别跟踪实际结果；具体编码和接口在实现设计中确定，可复用标准库的 JSON 编解码及文件操作能力。

故障标记文件与日志副本分别保存。进程可能在故障标记文件已经建立、日志副本尚未写完时退出，也可能在日志副本已经移入 `ready`、但交接结果尚未记回时退出。故障标记文件仍存在时，进度记录未更新或交接目录中没有日志副本，都不能单独证明日志副本从未交给主程序，也不能据此重新触发另一份日志副本。故障标记创建失败按下节处理，再检查遵守[故障标记异常后的再检查](#故障标记异常后的再检查)，日志副本按[失败清理规则](log-delivery.md#日志副本的失败清理)处理。首次标记可靠创建后，后续进度更新失败遵守[进度更新失败](#故障标记的进度更新失败)，不单独阻止本次日志副本交付。

## 故障标记创建失败

本次故障标记及日志副本身份可靠保存成功，是开始复制日志并将副本移入 `ready` 的前置条件。创建结果包含文件完整写入、文件同步、放置到正式路径及所在目录同步的实际结果；只确认正式文件存在，不等于已经完成这些持久化步骤。

| 故障标记创建结果 | 本次日志副本交付处理 |
| --- | --- |
| 所需写入、同步及正式路径放置均已确认成功 | 开始复制日志并将本次副本移入 `ready`；标记成功本身不证明日志副本已生成或发布 |
| 创建操作失败，可靠确认正式标记尚未建立 | 记录实际错误，停止本次日志复制与交接，不宣称标记已保存 |
| 已确认放置到正式路径，但后续目录同步失败或未确认 | 保留已有标记及实际操作结果，停止本次日志复制与交接，不将其解释为确定未创建 |
| 无法可靠确认创建操作的结果 | 保留未知及实际错误，停止本次日志复制与交接，不以删除可能存在的标记后重新创建来掩盖未知结果 |

错误通过仍可用的普通日志和 stderr 记录。标记创建失败不递归触发日志副本交付，也不单独停止录像或其他业务；原报告错误、状态库错误及其他执行前提错误仍按各自规则处理。保留可能已创建的标记，不因本次失败撤销故障标记来重新触发日志副本交付。

本节规定停止本次日志副本交付流程。同一故障在本次运行中的后续尝试按下节暂停；业务状态报告可靠恢复后发生的新故障仍按首次触发处理。已经建立故障标记的轮次遵守[失败后不自动重试的规则](log-delivery.md#日志副本的失败清理)。标记保存留下的临时文件按[所属清理规则](#故障标记的临时文件)处理，不能把临时文件当作正式标记，也不能以清理临时文件为由删除可能存在的正式标记。

## 故障标记异常后的再检查

camctl 检查正式故障标记时无法确认其存在性，或者创建标记失败、创建结果未知时，停止本次日志副本交付，并在本次 `run` 中暂停同一故障的后续尝试。重复报告失败、新业务变化、调度重扫及时间经过都不解除该暂停，也不触发再次检查或创建标记。已经确认正式标记存在但内容无法读取或无效时，继续按标记存在抑制另一份日志副本。

暂停仅控制日志副本流程，不阻止普通日志追加、业务状态报告按自身规则恢复，或报告恢复后结束故障。以下表格按先后条件判断：

| 后续事件与正式标记状态 | 处理 |
| --- | --- |
| 业务状态报告的本地处理已可靠恢复 | 按既有正常删除流程结束旧故障，解除本次故障的暂停；此后再次发生报告故障时，允许尝试创建新标记并交付新的日志副本 |
| 报告尚未可靠恢复，仍在发生标记检查或创建错误的同一次 `run` 中 | 继续记录普通日志，不重新尝试检查或创建标记，也不重新复制日志 |
| 下一次正常 `run` 再检查，可靠确认正式标记存在 | 保持故障持续；不补做此前失败或中断的日志副本交付；内容读取失败也不改变该判断 |
| 下一次正常 `run` 再检查，可靠确认正式标记不存在 | 仅在报告处理再次失败时尝试创建新标记，可靠创建成功后再复制日志；文件不存在本身不触发复制 |
| 下一次正常 `run` 再检查，仍无法确认正式标记是否存在 | 记录实际错误，在这次运行中再次暂停同一故障的日志副本尝试 |

下一次正常运行不沿用上次进程内的暂停标志，而是重新核实正式标记。进程内暂停控制同次运行的尝试次数，跨运行的故障判断仍以正式标记和可靠恢复证据为依据。重启本身不表示故障恢复；已建立的正式标记也不会因为重新检查而失去效力。再次创建失败继续适用本节，不增加定时检查或独立重试会话。

业务状态报告只有部分步骤成功、收到 ACK、主程序领取或删除文件，都不解除暂停。报告本地处理可靠恢复时，按第一版故障标记能够正常删除的假设结束旧故障；故障标记错误不会永久禁用同次进程处理后来新故障的能力。

## 故障标记的进度更新失败

首次标记及日志副本身份可靠创建成功后，后续保存处理进度失败或结果未知，不单独阻止仍在进行的首次日志副本交付。camctl 记录实际标记保存错误，保留正式标记及原日志副本身份；只要副本自身的准备和交接条件仍满足，就继续本次流程。不能因进度更新失败重新创建故障轮次、复制另一份日志，或重投已经交出的文件。

| 标记与日志副本的实际状态 | 处理 |
| --- | --- |
| 首次标记尚未可靠创建 | 按创建失败规则停止，不开始复制日志 |
| 首次标记已可靠创建，后续进度保存失败或未知，副本自身的操作正常 | 记录标记错误，按已可靠取得的副本操作结果继续本次复制、同步或移入 `ready`；不把未保存进度描述为保存成功 |
| 首次标记已可靠创建，但日志副本读取、写入、同步或移入 `ready` 本身失败或未知 | 按副本失败规则处理实际文件，不因允许标记更新失败而忽略副本错误 |
| 日志副本已经移入 `ready` 或 `processing`，随后标记更新失败 | 保持交接文件不变，记录实际已知结果，不撤回或重投 |
| 进程中断后重启，正式标记仍存在，无论进度是否完整 | 抑制重复交付，不恢复此前失败或中断的复制、移动流程 |

本节只允许正常进行中的首次流程继续，不授予失败流程重试资格。后续实际阶段产生新的进度时可以按原流程保存，不为某次失败的更新设置独立重试循环。故障结束与进度更新须由所属流程协调；报告可靠恢复并删除正式标记后，旧流程的迟到更新不得把标记重新建立，也不得覆盖后来新故障的标记。

## 故障标记的临时文件

标记保存流程使用与正式标记、日志副本明确区分的专用临时文件名，保存操作拥有该临时路径。文件是否成为故障标记，只以正式路径为准；临时文件即使内容完整，也不授权日志复制，不在恢复时自动提升为正式标记。

一次保存操作实际结束、相关句柄关闭且不再需要临时文件后，保存流程清理自己留下的临时文件。进程中断或清理失败留下的旧临时文件，在后续 `run` 取得会话锁后的日志目录检查中，按专用用途和归属分别处理；不依赖状态数据库可用。

| 检查到的文件及操作状态 | 处理 |
| --- | --- |
| 可以确认是已结束标记保存操作留下的临时文件，且无人继续使用 | 尝试删除；完整和未完整写入的临时文件采用同一规则 |
| 本次仍在使用的临时文件，或无法确认保存操作已经结束 | 保留，不与正在进行的保存竞争 |
| 正式标记、日志副本、其他用途文件，或用途及归属无法确认 | 不由临时文件清理删除，继续按各自规则处理 |
| 检查或删除临时文件失败 | 记录实际错误及残留，本次不循环重试，不单独终止业务；后续启动检查再核实 |
| 可靠确认临时路径已经不存在 | 无须删除，不据此推断正式标记或日志交付的状态 |

清理临时文件不删除正式标记，不改变同一故障的尝试资格，也不触发日志副本补投。相关文件操作继续遵守实际完成规则，不能把协程取消当作文件操作已经停止。

## 验收要求

### 进度更新、临时文件与再检查

验证首次标记创建失败阻止复制，与首次创建可靠成功、仅后续进度更新失败时继续交付的区别。分别在日志复制前、完整副本保存后、移入 `ready` 后使标记更新失败或结果未知，验证本次身份不变、正常副本流程继续、已交接文件不撤回；再组合副本自身失败，验证仍按失败规则停止且不补投。重启、报告恢复及新故障分别覆盖旧进度缺失、迟到更新及标记轮次隔离。

临时文件清理覆盖完整或未完整、旧操作已结束或仍在进行、归属明确或未知，以及检查和删除失败。验证正式标记及日志副本不被误删、临时文件不自动成为正式标记、清理不触发复制；集成测试组合真实目录与受控保存中断，不连接真实设备。

按“故障标记异常后的再检查”组合检查错误、明确创建失败和创建结果未知，验证同次运行的重复报告失败、新变化及调度重扫均不重新尝试；下一次正常运行分别覆盖正式标记存在、不存在和检查失败。已有正式标记时不补做失败或中断的日志副本交付；标记不存在且报告再次失败时才尝试创建。覆盖同次运行中报告完整恢复后再次失败，验证新故障取得首次尝试机会；仅局部成功、ACK 或文件领取不能解除暂停。

### 存在性、创建与故障轮次

独立状态文件的单元测试按存在性及正常更新表验证：不存在时首次失败先创建标记再复制日志；已存在时即使内容无法读取或无效也不触发另一份日志副本；存在性未知不当作不存在；重复失败沿用身份并只记录实际确认的进度；可靠恢复后删除标记，之后再次失败创建新轮次；迟到更新不重建已结束轮次的标记。集成测试组合真实状态文件与文件交接，验证首次部署不预建标记、恢复后的正常删除及目录同步、原子更新不暴露无标记间隙，以及日志副本被领取并删除后，后续 `run` 仍能识别原故障持续；普通日志轮换不删除状态文件，状态库不可用而状态文件及交接目录可用时仍可交付日志副本。创建、进度更新及中断处理按前述决策表覆盖，区分首次标记是否可靠建立与后续进度是否保存成功。

存在性检查的单元测试分别控制成功、明确不存在及权限等检查错误，验证检查错误保留实际原因并阻止以“不存在”为由新建轮次；另行验证已确认存在后内容读取失败，仍按已有故障标记处理。

故障标记创建的单元测试按创建结果表覆盖成功、正式标记尚未建立时失败、已放置但目录同步失败及结果未知，验证只有可靠成功才开始日志复制与交接；失败保留实际错误和可能已创建的标记，不递归触发日志副本交付、不单独停止业务，也不改写原报告或状态库错误。集成测试组合真实文件操作与受控故障，覆盖写入、文件同步、正式路径放置和目录同步各阶段失败，检查失败路径没有日志副本交给 `ready`，已经建立的正式标记不被删除以重试。
