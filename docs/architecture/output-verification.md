# 产物与文件流程验收

[返回设计总览](README.md) · [阅读路线](reading-guide.md) · [行为规则](outputs.md)

本页集中验证正式产物、取回与清理的协调、文件拷贝与续传、交付身份及中断恢复。单元测试验证局部行为契约，集成测试验证真实软件组件的协作；设备交互使用受真实接口约束的测试替身。真实设备联调、目标主机性能测量和物理断电验证单独安排，不作为软件集成测试的运行条件或通过门槛。

## 验收要求

### 单元测试

按[取回中间文件的保留与清理](obtaining-outputs.md#取回中间文件的保留与清理)覆盖取回未结束、最终失败、取消，与读写仍在进行、已停止及未知的组合。未结束项保留续传；失败或取消项仅在确认停止后删除自己的半成品。组合已准备成功的 A 和失败半成品 B，验证只清理 B、A 仍须发布；原片、派生成品及其他请求文件均保留。

完整副本的单元验收组合取回有效或已取消、文件在 `staging` / `ready` / `processing`、操作已结束或尚未确认，以及文件归属未知等状态。有效取回的完整副本保留；取消后仅删除本次仍在 `staging` 且相关操作已结束的副本；进入交接目录后按撤回与所有权处理。正式源产物此前已被合法清理，不改变已取消副本的删除资格。清理失败不恢复取回，也不将取消动作报告为全部处理成功。

按[取回中间文件清理失败与后续处理](obtaining-outputs.md#取回中间文件清理失败与后续处理)覆盖清理成功、文件查询或删除失败及结果未知，分别组合状态保存与报告职责完成或失败。局部清理问题可延后，数据库与必要报告错误仍为会话错误；本次有限尝试结束后，调度重扫和收尾检查不重启尝试，原动作及计划不恢复执行。

按[新取回遇到删除限制](output-cleanup.md#新取回遇到删除限制)覆盖旧资格、新请求、有效限制、限制已解除及状态未知。新请求在限制有效时对应项立即失败且不开始拷贝；旧资格继续受保护。组合单项和多项请求验证失败范围、其他项继续处理及整体结果。限制后来解除、重启和同一请求重送均不恢复已失败项。

隔离产物目录、设备文件和交付存储协作者，验证产物选择、部分成功、开始发布的条件、文件名规则、清理限制、取消及重取身份。

按取回动作的[参数](obtaining-outputs.md#参数)和[校验与失败处理](obtaining-outputs.md#校验与失败处理)覆盖六种来源形式，以及 `params`、`source` 缺失、非对象、空对象、字段混用和非法组合；另行覆盖 `output_ids` 空数组和动作自身的所属组字段错误。公共结构合法时只将错误取回登记为 `failed`，保留输入与诊断，不执行或创建 delivery；其他动作一同受理。已有请求重试仍忽略本次正文。

按[精确 ID 取回的逐项判定](obtaining-outputs.md#精确-id-取回的逐项判定)覆盖 ID 存在性、来源归属、实际可用性及查询结果的有效分区。分别验证全部合法、合法与无效混合、全部无效，以及已清理、存在删除限制、文件缺失和暂时等待的区别。无效 ID 不阻止其他合法项继续取回，来源不匹配时不读取其他动作的文件；状态库错误不能冒充无效 ID 后继续普通执行。空列表、重复 ID 和格式非法仍属于受理时的参数错误。

报告单元测试验证不存在和归属不匹配分别通过错误详情保留请求中的 ID，不提供不成立的产物或交付关联；同一来源的多个无效 ID 保留独立失败项。混合结果中成功交付仍保留，全部条目处理和必要交接完成后整体失败；全部 ID 无效时不创建 delivery，也不因成功项为零而汇总为成功。重送与恢复不重复失败项，不恢复已经保存的最终失败。

按[本计划内的产物引用](obtaining-outputs.md#本计划内的产物引用)覆盖局部名称存在、缺失、来源类型不适用及混用引用，仅该取回在受理时失败；重复动作名属于公共结构错误，按整份拒绝处理。局部引用只在本计划解析，支持数组中的前向引用；其他计划的同名动作或组不能成为目标。已有请求重试不重新解析正文。

按[按动作实例 ID 查找来源](obtaining-outputs.md#按动作实例-id-查找来源)覆盖目标存在且类型适用、类型不适用、不存在、查询错误、结果未知，以及曾确认来源存在但其记录缺失。受理阶段不查询目标，取得执行资格后确认目标缺失或类型不适用时仅取回失败。取消及已有终态优先；已经保存的结果不会因重启、同一请求重送或后续来源出现而改变。

按[取回与清理的执行时间](outputs.md#取回与清理的执行时间)覆盖计划时间之前、恰好到达、延后及时间未知，验证两类动作均不提前执行、不因延后进入 `expired`。区分业务等待、单次通信超时与重试耗尽；延后不能重置预算，也不能覆盖已有终态。

按[延后执行时的取回与清理顺序](outputs.md#延后执行时的取回与清理顺序)覆盖取回时间较早、清理时间较早及两者相同，并分别改变受理顺序和加载顺序。验证较晚或同一计划时间的清理不能抢先限制取回，较早清理产生的限制也不会被较晚取回绕过；已有资格、删除限制和终态按原规则保留。

按[再次清理已完成的产物](output-cleanup.md#再次清理已完成的产物)覆盖完整清理记录、未完成或部分失败、删除结果未知、目标不存在及数据库错误。已确认清理完成时本项成功且不调用删除协作者；报告保留本次请求、目标及此前已清理的含义。未经可靠核实的路径缺失或交付副本删除不能进入该成功分支。

按[批量清理结果](output-cleanup.md#批量清理结果)覆盖全部成功、部分失败、全部失败及仍有未完成项，包含此前已清理、目标不存在、删除失败和结果未知。目标不存在不能阻止其他合法目标执行；数据库异常不能当作逐项目标不存在处理；取消及既有终态不被汇总覆盖。

按[清理取消](output-cleanup.md#清理取消)的逐项收场与取回限制表验证取消：来源集合尚未确定、条目尚未删除、等待旧取回、删除调用仍在进行、删除成功、明确失败及结果未知，并组合多个清理项分别取得不同结果。分别组合没有其他限制、其他请求仍有限制和限制未知；验证只解除本次请求可撤销的限制。已有条目终态保持，动作取消不抹去成功或失败项；取消先于删除派发生效时不发出删除，已经发出的调用须跟踪实际结果。当前调用结束后不再发出新的删除或普通重试。

按[删除中断后的恢复](output-cleanup.md#删除中断后的恢复)覆盖请求资格与目标记录分类，以及每个目标文件不存在、仍存在和未知的分类，再组合多个产物的不同结果。每项只在自身文件确认不存在时补记完成，全部清理项成功才能汇总为动作成功；设备不可达或查询失败不能当作不存在，终态请求不能自动继续删除，未知或缺失的完整目标记录不能当作空集合。验证重试耗尽、恢复结果保存失败及提交未知时保留实际状态。

按[长期保留](outputs.md#长期保留)覆盖有无有效清理请求，以及取回完成、传输完成、保存时间增长和空间不足的组合，验证所有正式产物采用相同保留规则。无清理请求不能删除正式产物；有请求仍需满足旧取回优先及取消规则。

按[等待录像动作结束](obtaining-outputs.md#等待拍摄动作结束)覆盖取回资格、录像是否结束、产物有无及查询异常的分区。验证等待期间不提前固定部分产物或判无产物失败；录像进入不同终态后按正式产物处理；已取消的取回不能因录像结束恢复执行。

按[组内录像分别准备与统一发布](obtaining-outputs.md#组内拍摄分别准备与统一发布)覆盖全部未结束、部分结束、全部结束及取回取消，包含未来录像尚未开始、录像失败或取消、查询错误和跨计划同名组。验证已结束成员分别固定完整选择并开始准备，未结束成员仍等待；任何成员尚未完成判定时，不能发布已有成功文件或汇总整体终态。恢复保留逐成员选择，不遗漏未来成员或重复创建交付。

按[按组取回的成员筛选](obtaining-outputs.md#按组取回的成员筛选)覆盖类型产物能力与动作状态的组合。非产物动作尚未开始、运行中或已结束均不影响取回等待、发布及失败汇总；录像尚无产物仍须保留为来源，终态无产物仍记失败，不能通过筛选隐藏失败录像。成员或类型查询未知须明确处理，不当作可忽略成员。组取消及报告组织仍使用原组成员。

按[组来源的确定](obtaining-outputs.md#组来源的确定)覆盖本计划内及指定计划实例的组引用，与来源未解析、存在有效成员、目标缺失、成员均不产生产物和查询错误的组合。本计划内引用在受理时解析，跨计划引用在首次执行时解析；可靠的缺失或无产物来源只使该取回失败。有效集合保存后恢复不重新选择；产物尚未生成或已清理不改变来源类型的判定，仍按运行时可用性处理。

按[逐产物解除读取依赖](output-cleanup.md#逐产物解除读取依赖)与[准备完成与断电恢复](output-cleanup.md#准备完成与断电恢复)覆盖单个和多个已有取回的依赖组合，以及写入、校验、落盘、事务提交的成功、失败和未知。只有所有已有取回均不再需要读取才允许删除；某项最终失败或取消还须确认读取与重试停止。验证准备完成与依赖解除在同一事务中保存，删除源文件不影响已准备交付的发布资格。

按[已结束动作没有正式产物](obtaining-outputs.md#已结束动作没有正式产物)覆盖动作终态与产物情况的分区，验证无产物时取回失败且不创建 delivery。动作未结束、引用缺失、查询失败或未知，以及曾产生但已清理的产物均不能误入该分支。保留 `output_ids = []` 的参数错误语义。

按[取回失败项的报告表达](obtaining-outputs.md#取回失败项的报告表达)覆盖来源无产物、有产物但尚无 delivery、delivery 已创建后最终失败、仍可重试以及来源未知的分区。验证身份字段按实际记录提供，三次读取失败只形成一个文件最终失败项；失败项与交付错误同源且一致。已有失败而其他来源仍未结束时，报告可以表达失败项，但不提前结束动作或发布文件；恢复和重复报告不新增失败项，客户端随动作自身字段整体更新 `result.failures`。

录像组另行覆盖每个成员均有产物、部分成员无产物及全部成员无产物，并组合产物取回成功、失败、重试或发布未完成。无产物项关联来源动作，不创建虚构产物或 delivery；存在无产物项时整体失败，但仍须完成其他文件的必要发布。录像失败但留有产物不自动使取回失败，数据库错误不能当作成员无产物。

按[部分成功](obtaining-outputs.md#部分成功)表覆盖全部成功、部分失败、全部失败，以及其他项仍在重试、等待发布或发布结果未知的情况。验证整体状态与逐项结果一致，某项失败不能提前结束动作或扣留成功项；取消及既有终态不能被结果汇总覆盖。

按[重启后选择续传位置](file-copy.md#重启后选择续传位置)覆盖各分区，验证续传偏移、尾部截断、已完成数据范围及错误分类。覆盖实际读取长度小于请求长度、提前结束，以及写入、同步、截断、进度提交失败或结果不确定；未可靠保存的字节不能推进进度。进度提交前的文件和目录同步顺序属于断电恢复契约，须明确验证。

按[按文件累计读取尝试](file-copy.md#按文件累计读取尝试)覆盖默认上限、合法配置、分段成功、明确读取失败、次数耗尽、断电恢复、取消及历史未知。用在不同位置发生的多次读取失败验证同一文件累计计数，成功段不重置预算；用多文件和不同请求验证各自计数。内部历史及其恢复结果须保留已用次数和当时采用的上限。分别验证普通取回与录像检查、修复输入的读取：报告按冻结历史中所属交付、动作或处理的适用公开结果表达失败。仅次数、配置依据或复制进度变化而公开字段未变时，不增加 `change_seq`。

按[文件读取的无数据超时](file-copy.md#文件读取的无数据超时)覆盖首批数据等待、阈值之前与达到阈值、间歇性新数据、持续慢速读取、非文件响应、主机处理阶段、排队与重试等待、正常结束及提前结束。验证默认阈值和合法配置，非法零值、负值、非有限数值或类型错误不能作为缺省值。使用可控单调钟验证计时，不依赖测试实际等待。

按[同一相机的拷贝并发限制](file-copy.md#同一相机的拷贝并发限制)组合取回、异常原片检查和内部修复入口，验证同一相机最多有一份活动拷贝，分段保存进度不允许另一份文件插入。等待不消耗读取次数；取消或最终失败后，实际读取结束前不能启动另一份拷贝。分别验证不同源相机独立协调、主机派生文件拷贝不占相机机会，以及控制操作仍遵守驱动兼容性。

按[等待重试时保留拷贝机会](file-copy.md#等待重试时保留拷贝机会)覆盖仍可重试、取消、预算耗尽、读取尚未停止或状态未知，以及源内容读取完成。验证等待期间其他文件不能开始、重试继续原进度和预算、符合解除条件后才选择其他文件。源内容读完后发生校验失败的重拷须重新参与选择，不追溯抢占另一份活动拷贝。

按[多个候选文件的选择顺序](file-copy.md#多个候选文件的选择顺序)覆盖所属动作时间不同、同时间跨计划、同计划不同动作以及同动作多文件。取回使用取回动作时间，检查和修复使用所属录像时间，重拷沿用原依据；未具备读取条件的较早请求不阻挡合格候选。另行验证已有活动拷贝及重试保留优先于候选排序，排序数据缺失或未知不能使用加载顺序替代。

按[读取正确性与文件校验](file-copy.md#读取正确性与文件校验)覆盖摘要支持、不支持和能力未知，以及摘要相同、不同、获取失败和结果未知的分区。读取失败或结果未知、主机摘要计算失败、源端校验未通过时不能交付该副本；不支持源端摘要的驱动仍须满足可靠读取契约，并提供主机端 SHA-256。

按[摘要不一致后的有限重拷](file-copy.md#摘要不一致后的有限重拷)覆盖执行资格与剩余次数的组合，验证重新开始、次数耗尽及取消后的处理。摘要获取失败或结果未知不能冒充内容不一致；同一不一致结果的重复处理不能重复扣减次数。

验证重拷上限未配置时，首次拷贝不计数，只允许额外一轮重拷；这一轮仍摘要不一致即失败。另行覆盖合法零值和正整数、非法负值和类型错误，以及配置变化后未完成处理采用本次上限且累计次数不变；降低上限不裁剪旧计数，提高上限不重新激活终态。新一轮重拷中断后恢复原轮次，不额外增加次数。

组合读取错误和摘要不一致，验证两项预算独立累计且不互相补充：读取报错后的续传不增加重拷次数，摘要不一致后的重拷不增加或清零读取计数。分别耗尽其中一项并保留另一项额度，验证相应失败不能借用另一项额度继续。第三次读取完成后仍可使用已有重拷额度，但后续读取再失败即结束该文件。

资格判定的单元测试从[资格授予状态表](outputs.md#延后执行时的取回与清理顺序)推导，分别覆盖已有资格、有效删除限制、两种时间先后、同时间、条件未满足、取消与终态，以及查询和提交结果未知。用受约束的存储替身验证业务排序与资格保存的契约，不将协程调度顺序作为预期依据。

### 集成测试

本节验证软件组件组合，设备交互使用受契约约束的替身，不连接真实设备。受控故障和进程中断用于验证软件恢复，实际硬件性能与物理断电另行联调；范围遵守[第一版完善与验收范围](README.md#第一版完善与验收范围)。

通过两个计划输入入口提交格式合法的精确 ID 取回，组合真实 SQLite、受管文件、取回流程、文件交接及报告生成。在同一请求中选择来源 A 的可用产物、已清理产物、不存在的 ID，以及来源 B 的产物，验证只为 A 的可用产物准备和交付文件；其余目标分别报告实际原因，动作最终为 `failed`。在逐项判定保存后及成功副本交接前后中断，验证恢复沿用结果与交付身份，不读取 B 的文件、不重复交付成功项，也不因随后出现对应 ID 的产物或解除限制而恢复失败项。状态库查询失败时验证原会话错误生效，不能将其转换为普通 ID 不存在。

组合相机读取适配、真实中间文件与状态库，模拟分段尚未完整返回但持续取得文件字节的慢速读取，验证持续时间超过阈值仍可完成。另行模拟停滞到达阈值、主机处理阶段暂停读取及断电恢复，验证超时只消耗读取预算、可靠进度不因收到未落盘数据而推进、恢复不累计断电时间，重启前已记录的超时不被撤销。

组合状态库、相机读取替身、主机文件与摘要校验，在读取错误后续传成功，再制造源端与主机摘要不一致。分别在新重拷轮次登记前后中断恢复，验证读取计数保持、重拷计数只增加一次、新轮次进度不会连接上一轮无效副本；两类失败及计数均可从内部历史追溯，报告保留最终业务结果及错误。

组合真实 SQLite、中间文件与受接口约束的驱动替身，在同一文件的不同进度处报告读取错误，验证第三次明确失败后按默认预算结束该文件。分别在尝试登记后、分段进度保存后及明确失败记录保存后中断并恢复；已登记而未结束的尝试继续原身份，已有失败须保留，重试仍须消耗下一次尝试。计数与失败事实不能因重启丢失或重复增加，其他文件保留各自预算。

组合设备操作协调器、相机驱动替身、真实 SQLite 和中间文件，同时安排取回与内部处理拷贝，并在存在多份半成品时重启恢复。验证同一相机读取不会重叠，各文件保留原身份及可靠进度；等待组成员、主机校验或媒体处理不占用相机拷贝机会。当前驱动联调还须验证文件拷贝期间的录像与必要停止操作满足已确认的兼容性契约。

在 A 读取失败、已保存重试等待且 B 可执行时中断会话，重启后改变候选加载顺序，验证仍为 A 保留拷贝机会。分别让 A 恢复成功、取消或耗尽预算，确认 B 只在原保留解除后取得机会；必要录像停止仍能执行，各入口不建立独立的并行拷贝。

### 行为覆盖清单

以下按行为组织，执行时按上述单元测试与集成测试边界归类。

#### 正式产物

- `output_id` 稳定；
- 原片和修复产物独立；
- 所有正式产物保留到客户端显式清理，取回、传输、保存时长及空间不足不触发自动删除；
- 清理不级联。

#### 产物取回

- 默认排除预览，并逐原片优先选择对应修复成品；
- 精确选择 `output_ids`，不存在、归属不匹配或不可取回的目标逐项失败，其他合法目标继续取回；
- 提前提交的单个录像全部产物取回等待录像动作结束，跨重启保留请求；
- 按组取回按类型筛选产物来源，不等待非产物动作；失败且无产物的录像仍保留为失败项；
- 本计划内引用在受理时确定来源，跨计划引用在首次执行时确定；取回自身的参数错误、来源缺失或无产物来源仅使该动作失败；
- 按 group 取回一组录像时，成员结束后分别选择并准备，全部成员及产物处理结束后才发布；
- 单个已结束动作未产生正式产物时，取回失败并报告原因；
- 部分失败仍交付成功项；
- 全部成功时整体为 `succeeded`，部分或全部失败时整体为 `failed`，报告保留逐项结果；
- 全部条目结束后才开始发布；
- 文件逐个发布；
- 每个新请求产生独立 delivery；
- 相机视频拷贝支持跨主机重启的断点续传；
- 取消撤回 ready；
- processing 不可撤回。

#### delivery 文件名

- 实际文件名使用完整 `delivery_id` 和文件类型扩展名，路径安全且长度有界；
- 同一产物的两次独立取回使用不同实际文件名，同一请求恢复沿用原名；
- 实际文件名历史唯一，传输删除或撤回后也不复用；
- `display_name` 保留完整可读名称及中文，可重复且不参与路径构造；
- 来源名称很长时不增加实际文件名长度；
- 报告保存两个名称，客户端按 `file_name` 唯一关联，不按显示名称或文件名解析推导身份。

#### 产物清理

- 新请求再次清理有完整清理记录的产物时，该项成功且不重复删除；
- 批量清理逐项处理，目标不存在不阻止其他项；取消未生效时，全部成功则整体成功，全部结束且至少一项失败则整体失败；
- 删除中断后按原完整目标集合恢复，全部确认不存在才补记完成，未知不冒充成功；
- 已获得资格的取回优先；
- 每个产物的所有已有取回解除读取依赖后，即可清理，无须等待整组发布；
- 新取回被阻止；
- 删除部分失败仍禁止新取回；
- 清理取消按每个产物判断，保留已完成删除，停止尚未发生的删除；
- 某产物未开始删除且没有其他限制时，取消后恢复新取回资格；该产物已开始删除或结果未知时保持限制；
- 动作取消与逐项实际结果分别报告，重启不继续被取消请求的删除。
