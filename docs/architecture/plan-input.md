# 执行计划输入契约

[返回设计总览](README.md) · [请求受理与会话](protocol-session.md) · [客户端协议样例](client-protocol-examples.md) · [阅读路线](reading-guide.md)

本专题定义客户端执行计划的公共字段、基本值类型、额外字段和校验顺序。`run <plan-path>` 与 `submit <plan-path>` 使用同一输入契约；受理事务、幂等和会话接管由[请求受理与会话](plan-acceptance.md#整份校验与原子受理)定义。拍摄参数的字段、范围和组合由目标驱动的参数类型契约定义，公共输入校验不调用设备。

**阅读提示：** 先看[计划的作用与受理含义](concepts.md#为什么要区分计划产物和交付)，再按顶层字段、动作公共字段和校验顺序查阅。JSON 样例见[正常录像与取回](client-protocol-examples.md#样例一录像与取回成功)。

本页使用的 UTF-8 是文本编码方式；ASCII 表示相应字符集，其中英文字母、数字和这里列出的符号用于机器标识。可读名称允许中文等 Unicode 字符，长度按 Unicode 码点计数，不按文件字节数计数。UTC 是协调世界时，计划时间统一按它解释。

## 输入文件与基本值类型

输入文件采用 UTF-8，包含一个完整 JSON 值；根值必须是对象。JSON 前后允许空白，不能包含注释、尾随逗号、额外 JSON 值或非 JSON 数值常量。文件无法完整读取或不能解码、解析时，不从片段识别请求或 ACK，按[输入计划文件读取失败](cli-commands.md#输入计划文件读取失败)及输入解析失败规则处理。

对象成员名必须唯一，包括转义还原后同名的成员。出现重复成员名时，输入不能被无歧义地解释，按输入解析失败处理；不采用“保留第一项”或“保留最后一项”的解析结果继续受理。完整读取及这种无歧义解析在幂等查询之前完成。

字段名大小写敏感，字段值不做隐式类型转换。字符串 `"60"` 不等于数值 `60`，布尔值不作为整数，`null` 不表示省略。合法的数值表示按数值判断：例如要求整数的字段可以接受数值恰为整数的 JSON 数字，不因指数或小数表示方式改变其数学值；仍须满足该字段的范围。

| 值类型 | 合法条件 | 比较及用途 |
| --- | --- | --- |
| 标识字符串 | 1～128 个字符，首字符为 ASCII 字母或数字，其余为 ASCII 字母、数字、`_`、`-` 或 `.` | 大小写敏感、完整精确比较；用于 `request_id`、设备 ID 及实例 ID 引用，不按前缀推导业务身份 |
| 可读名称 | 1～128 个 Unicode 码点，无首尾空白，不含 U+0000～U+001F、U+007F～U+009F 控制字符 | 保留中文及原字符，不做大小写、空白裁剪或 Unicode 归一化；用于计划名、动作名及组名 |
| 非负整数 | JSON 数值，值为整数，范围 0～9007199254740991 | 用于本专题声明的非负整数约束；布尔值、数字字符串均不合法 |
| 正整数 | 上述整数范围中大于 0 的值 | `last_report_id` 的数字表示见报告专题 |
| 时间字符串 | 满足下节的 UTC 时间字面量 | 静态校验日期与表示，不使用当前主机时间判断业务资格 |

以上标识字符串是输入合法性约束，不规定 CLI 内部的 ID 分配算法。CLI 对外分配的计划、动作、产物和交付 ID 须满足该约束，使客户端可以原样用于后续引用；实际文件名还遵守[Delivery 与文件名](outputs.md#delivery-与文件名)。驱动的 `params.type` 由其参数契约定义，不根据这里的标识字段另行推导驱动能力。

## 时间字面量

时间采用 `YYYY-MM-DD HH:MM:SS`，可在秒后附加 `.` 和 1～6 位小数。例：`2026-09-13 09:00:00`、`2026-09-13 09:00:00.250`。所有值均表示 UTC，不能按主机或客户端的本地时区解释。

年份为 0001～9999，月、日、时、分、秒使用固定宽度，日期必须真实有效；小时为 00～23，分、秒为 00～59。小数是秒的小数部分。字面量不带时区后缀或首尾空白，不接受斜杠日期、Unix 数字时间戳或其他格式的字符串；客户端将用户选择的本地时间转换为 UTC 后生成该格式。

`created_at` 表达客户端生成计划的时间，不作为主机时间可信性的证据。受理不要求它早于当前主机时间，也不要求它早于每个动作的 `scheduled_at`。`scheduled_at` 是否已到或已过期由取得执行资格后的调度判断，静态校验只判断字段表示是否合法。

允许小数秒不改变[尽力按时执行的保证](scheduling-execution.md#scheduled_at)，也不承诺设备以微秒精度开始采集。报告重建继续使用已冻结的时间事实及生成规则。

## 顶层字段

下表定义完整计划首次受理的公共字段。`last_report_id` 是同一输入对象中的独立 ACK 字段，不属于以 `request_id` 固定的计划正文。

| 字段 | 是否必填及合法值 | 首次受理时非法或缺失的结果 |
| --- | --- | --- |
| `request_id` | 必填，标识字符串，由客户端生成 | 拒绝本次计划；可独立判断的 ACK 仍处理 |
| `created_at` | 必填，时间字符串 | 拒绝整份计划 |
| `name` | 必填，可读名称，不要求跨计划唯一 | 拒绝整份计划 |
| `actions` | 必填，至少包含一个元素的数组，每个元素必须是动作对象 | 缺失、非数组、为空或有非对象元素时拒绝整份计划 |
| `last_report_id` | 可省略；提供时须满足[报告编号与水位的数值范围](status-reports.md#报告编号与水位的数值范围)，且能够查询到已登记报告 | ACK 校验错误；不因此拒绝合法计划或阻止原计划复用 |

首次受理的顶层对象只允许上述字段。额外字段属于计划公共结构错误，拒绝整份计划；能独立处理的合法 ACK 仍按其规则处理。例如 `lastReportId` 不能替代 `last_report_id`，也不能因为拼写相似而自动更正。

已受理 ID 的重送仅需具备可以无歧义提取的合法 `request_id`；本次正文的缺省、变化或额外字段均不参与重新校验。`last_report_id` 每次仍独立校验和处理。客户端正常重送应继续保留原计划内容，示例见[客户端确认与重送](plan-acceptance.md#客户端确认与重送)。

## 动作公共字段

每个动作对象只允许下表列出的公共字段。合法动作名称是计划内部名称引用的基础，已支持类型是确定参数契约的基础，因此这两项错误与动作自身参数错误分开处理。

| 字段 | 合法条件 | 首次受理时的错误范围 |
| --- | --- | --- |
| `name` | 必填，可读名称；在本计划全部动作中精确唯一 | 缺失、非法或重复时拒绝整份计划 |
| `type` | 必填，字符串，必须对应本版已经实现的动作类型 | 缺失、无法识别、未知或仅预留未实现时拒绝整份计划 |
| `device_id` | 是否需要由动作契约决定；提供时为标识字符串，设备与能力须满足动作契约 | 仅该动作初始 `failed` |
| `scheduled_at` | 是否需要由动作契约决定；提供时为时间字符串 | 仅该动作初始 `failed`；可省略不表示可填写 `null` |
| `group` | 可读名称，且动作允许成为组成员；省略表示不属于组 | 仅该动作初始 `failed`，非法组值不产生有效成员关系 |
| `params` | 提供时必须是对象；必填性、字段和值由动作契约决定 | 仅该动作初始 `failed` |
| `policy` | 提供时必须是对象，只包含该动作支持的业务策略 | 仅该动作初始 `failed` |
| 其他字段 | 不属于本版动作公共结构 | 在动作类型与名称合法的前提下，仅该动作初始 `failed` |

名称唯一性检查使用完整输入，包含之后会因自身参数错误而失败的动作，不先丢弃失败动作。两个动作仅因大小写或不同 Unicode 字符表示而名称不同，则按不同名称处理；客户端自行选择易于阅读和区分的名称。

合法 `group` 与其他参数分别校验：允许属于组的动作即使其他参数失败，仍保留合法组成员关系。`obtain_action_outputs` 的动作公共字段 `group` 必须省略，`params.source.group` 则是独立的来源引用。

## 第一版动作入口

本表说明当前动作的公共字段和参数入口，具体业务语义由链接的责任专题定义。后续扩展动作或驱动时，由其能力与参数契约声明合法字段；实现不应在公共校验器中另写一套相机参数完整清单。

| 动作 | `device_id` | `scheduled_at` | `params` | `policy` |
| --- | --- | --- | --- | --- |
| `camera_take_photo`、`camera_timelapse` | 必填，且目标设备支持该能力 | 必填 | 必填；按[单张拍摄与延时摄影](camera-capture.md)及设备参数契约校验 | 必填，包含非负整数 `max_delay_ms` |
| `camera_record` | 必填，且目标设备支持该能力 | 必填 | 必填；按[拍摄参数契约](camera-capabilities.md#计划字段与参数校验)校验 `type` 及其参数 | 必填，包含非负整数 `max_delay_ms` |
| `obtain_action_outputs` | 省略；设备由来源决定 | 必填 | 必填；包含 `source`，可选 `output_ids`，见[取回参数](obtaining-outputs.md#参数) | 可省略或为空对象 |
| `delete_action_outputs` | 省略；设备或主机位置由产物决定 | 必填 | 必填，包含非空 `output_ids` 数组，见[清理参数](output-cleanup.md#清理参数) | 可省略或为空对象 |
| `cancel_task` | 省略；由取消目标决定 | 可省略 | 必填，包含目标对象 `target`，见[取消参数](task-cancellation.md#取消参数) | 可省略或为空对象 |
| `report_status` | 省略 | 可省略 | 必填；提供 `scope: "full"` 或 `scope: "since"` 配合 `after_report_id`，完整组合见[同步入口](status-sync.md#请求入口) | 可省略或为空对象 |

本表中要求省略的字段，即使提供合法类型的值，也属于该动作自身参数错误。例如给取回动作提供 `device_id` 不会改变产物实际来源，也不静默忽略该值。`report_status` 按报告与 ACK 规则确定覆盖区间，调用方可以请求完整同步或以已登记报告为起点的局部同步，具体报告范围由同步专题确定。

动作未声明支持的业务策略属于自身参数错误。`max_delay_ms` 不能为取回、清理、取消或报告动作增加过期窗口；这些动作若提供该字段，仅该动作初始 `failed`。当前拍摄参数类型的策略要求按驱动契约执行。通信次数、超时和退避字段来自本地配置，计划不能通过 `policy` 覆盖。

首次受理时，参数对象中的额外字段按其所属动作的参数契约判为自身参数错误。拍摄动作的完整参数结构由驱动单一来源提供，既用于静态校验与生效参数固化，也用于部署说明；框架不把未来驱动尚未实现的字段静默当作已支持。

## 校验顺序与错误优先级

下表按输入处理阶段规定先后关系。整个输入处理结果，包括计划受理或拒绝、有效 ACK 与应保存的诊断，仍使用同一次受理事务边界；设备访问和报告文件发布不属于校验。

| 阶段与条件 | 计划分支 | ACK 分支 |
| --- | --- | --- |
| 文件无法完整读取、UTF-8 解码失败、JSON 语法错误或对象成员名重复 | 保存输入读取或解析失败，不提取片段身份 | 不从片段吸收 ACK |
| JSON 已无歧义解析，但根不是对象 | 保存公共结构拒绝，无法提取有效请求身份 | 无法从该根取得 ACK，不将它虚构成一个已读取的 ACK 值 |
| 根是对象，`request_id` 缺失或非法 | 拒绝计划，不用错误 ID 查询或注册实例 | 按字段是否提供及其实际值独立处理 |
| `request_id` 合法，受理关联查询失败或结果未知 | 会话错误；不推断为新请求 | 同次事务按会话错误处理，不宣称部分处理成功 |
| `request_id` 已有成功受理关联 | 复用首次计划；跳过本次正文公共字段、动作及参数校验 | 始终独立处理当前输入的 `last_report_id` |
| `request_id` 尚未受理，公共字段、全部动作对象、名称或类型有整份拒绝条件 | 完整诊断后拒绝本次计划，不注册部分动作 | 始终独立处理 |
| 新请求通过公共结构检查 | 按动作契约检查自身字段、参数和本计划内引用，登记各动作的合法初始状态 | 始终独立处理 |
| 没有整份拒绝条件，所有输入结果能够可靠保存 | 一次注册计划及全部动作；自身错误动作初始 `failed`，其余 `pending` | 保存适用的累计确认或 ACK 错误 |
| 写入、提交失败或结果未知 | 按会话错误处理，不宣称部分受理成功 | 不宣称 ACK 一定已吸收或一定未吸收 |

本计划内动作名及组引用基于完整输入判断，允许引用数组中靠后的动作。跨计划来源、取消目标、清理目标及局部同步起点报告的实际存在性按执行时规则确认；在受理时不通过相机查询、文件拷贝或其他业务操作验证它们。

只要存在整份拒绝条件，它就优先于所有单动作错误。单个动作可以具有多个已确定的字段错误，诊断应保留具体位置和值；多个错误不产生多次动作执行或多个动作实例。输入合法性检查不执行当前时间到期判断，不从某个来源动作的初始失败推导其他动作也必须初始失败。

错误字段路径指向首次提交的完整计划，例如 `actions[1].params.source.action_name`，数组下标从 0 开始。报告中的动作子集合顺序不改变该路径。业务错误字段的具体输出遵守[客户端协议样例中的错误表达](client-protocol-examples.md#错误表达)及对应动作契约；会话错误由[会话错误与恢复边界](session-errors.md)定义。

## 验收要求

公共类型按缺省、`null`、错误类型、边界值和合法值分类。标识与名称覆盖长度边界、中文名称、首尾空白、大小写及精确相等；整数覆盖布尔值、数字字符串、小数值与数学值为整数的数值表示。时间覆盖真实日期、日期越界、秒级和允许的小数秒精度，以及格式正确但相对当前时钟位于过去或未来的值；后两者不在受理时判为过期。

同一输入分别经 `run` 与 `submit` 受理，验证公共结构错误拒绝整份计划、动作自身错误只使该动作初始失败，且无设备副作用。已有 ID 的重送组合正文缺省、额外字段或参数错误，以及 ACK 合法、非法、未提供，验证正文复用与独立确认规则。

额外字段分别置于根对象、动作对象、`params` 及 `policy` 中，按所属层级判定。重复对象成员属于解析阶段错误，不使用解析器隐式覆盖后的结果；不能从相同 ID 或合法 ACK 的片段越过该阶段。全部动作名称及类型检查须先于实例注册，整份拒绝时不遗留动作、取消意图或删除意图。

使用[客户端协议样例](client-protocol-examples.md#阅读与使用范围)及其样例驱动定义，验证合法计划能够按本契约解释，错误引用样例仍只产生预期的单动作失败。真实设备接入改用对应的正式参数定义。分别验证取消四种目标组合、删除空列表或重复 ID、报告参数省略或为空时的动作初始失败、合法完整和局部同步、起点报告数值边界及非法参数组合，以及无时效动作不接受 `max_delay_ms`。
