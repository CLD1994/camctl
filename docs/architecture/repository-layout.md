# 仓库目录与组件边界

## 组件与共享资源

| 路径 | 责任 |
| --- | --- |
| `apps/client` | 本地网页、Node.js 服务、客户端存储、依赖与组件测试 |
| `apps/camctl` | ARM Linux 上的 Python CLI，实现设备调度、持久化和产物管理 |
| `apps/host-demo` | C 语言主程序调用示例，供对接方参考进程管理与文件交接 |
| `protocol` | 机器可读 Schema 与标准协议样例的唯一来源 |
| `docs/architecture` | 全局业务、协议语义与组件协作设计 |
| `docs/client`、`docs/camctl`、`docs/host-demo` | 各组件的设计入口、运行与验证说明 |
| `tests/integration` | 跨组件真实协作者组合测试 |
| `demos` | 完整业务演示的说明、生成脚本和可提交输入 |
| `scripts` | 跨组件检查与开发脚本 |
| `.local`、`tmp` | 不入库的本地运行、验收与临时资料 |

组件内部测试分别放在自身 `tests/unit` 与 `tests/integration`。仅涉及客户端前后端的测试仍属于客户端。只有跨独立组件的协作验证放在根测试目录。

客户端的 `shared` 只服务客户端内部；跨语言协议通过 `protocol` 共享。发布物应包含自己所需的协议资源，不能要求目标机器具有源代码仓库。各组件独立管理依赖、构建和交付。

## 运行数据与路径

现有日常数据保留在仓库根 `data`，运行说明使用显式 `CAMCTL_DATA_DIR` 指向它。未设置时客户端仍按进程工作目录下 `data` 解释；启动界面要求显式初始化的规则保持不变。移动源码不移动或创建业务数据库。

Docker 构建上下文为仓库根，客户端 apps/client/Dockerfile 与 Compose 放在组件目录。Compose 的数据挂载指向根 `data`，目录缺失时拒绝自动创建。

演示生成文件与大型媒体不作为公共协议样例。协议样例仅有一份权威文件，报告文件名中已有摘要的字节必须保持不变。

## 主程序 demo

主程序 demo 使用 C，运行目标为 Linux，用于演示真实 CLI 进程控制、退出结果判定及文件交接。它不实现 camctl 业务调度，也不承担第三方传输系统。仓库整理阶段提供职责与对接规格入口；可运行实现及其测试作为独立实现任务完成。
