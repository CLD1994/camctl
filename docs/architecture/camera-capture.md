# 单张拍摄与延时摄影

[设计总览](README.md) · [设备能力](camera-capabilities.md) · [报告结构](report-format.md)

## 输入与设备能力

第一版支持 `camera_take_photo` 和 `camera_timelapse`。两者使用拍摄公共字段：`device_id`、`scheduled_at`、`params.type` 和 `policy.max_delay_ms` 必填，可属于动作组。设备、动作、参数类型共同确定参数规则，所有参数按驱动 Schema 校验，受理时固化生效参数。设备不支持某能力时不能将请求改成其他动作。

单张拍摄执行一次拍摄，不要求一次拍摄只产生一个文件，例如设备可以提供多个图片格式。延时摄影在有限采集任务完成后自动结束；张数或采集持续时间由设备参数契约确定，固定类型可以固定其值。持续时间指采集过程，不是输出视频的播放时长。设备可只支持一种结束方式；支持两种时，参数规则必须明确选择及组合限制。框架不统一规定参数字段名，也不从描述文字猜测结束条件。

驱动必须提供可验证的有限结束条件、完成依据、文件归属和写入完成依据、设备操作兼容性、有限查询及停止预算。部署说明列出实际可执行的参数类型。真实命令映射和设备响应由设备接入验证，协议样例不能证明设备已经接入。

## 正常执行与恢复

启动窗口与调度、效果登记和重试遵守[公共执行规则](scheduling-execution.md)。先保存操作意图，再访问设备；同一动作的重试和重启沿用原身份、固化参数与已消耗预算，不重新执行一次已确认的拍摄。驱动只有在能够保证安全重复或设备端去重时才可重发结果未知的拍摄命令。

| 已知情况 | 行为 |
| --- | --- |
| 尚未到时间或设备不具备执行资格，仍在窗口内 | `pending`，报告实际等待条件 |
| 启动窗口错过或启动重试耗尽窗口 | 按公共规则 `expired`，区分未尝试与已有尝试 |
| 已开始拍摄，完成条件尚未满足 | `running`，保存可靠进度 |
| 已确认采集目标完成，文件归属及写入完成核实仍在进行 | 仍为 `running`，不提前声明成功 |
| 目标完成且所有适用有限处理结束，产物集合已确定 | 登记文件及 `succeeded`，在同一历史事务提交 |
| 明确失败，有限收场结束 | 登记符合保留条件的文件并提交 `failed`，附错误 |
| 重启后设备仍在执行原任务，身份与进度可靠 | 继续观察原自动结束任务，不从零开始计数或计时 |
| 重启后已完成，可可靠关联原任务及文件 | 对账并完成原动作，不再次拍摄 |
| 启动效果、完成条件、归属或写入状态无法确认 | 按原预算有限核实；预算耗尽仍未知时报告失败与未确认事实，不猜测成功或不存在 |
| 数据库无法可靠读写或提交结果未知 | 停止依赖该状态的执行，按会话错误和提交对账恢复 |

成功不以“发现某个文件”代替设备任务完成；张数进度不等于正式产物数量。一个采集可以生成多份文件，也可以生成合成视频。断电后不得用主机墙上时间差补造可信采集时间。设备自动结束是否完成必须有驱动证据。

## 取消、失败与文件保留

取消优先于普通执行和重试。停止只针对能够归属本动作的设备效果，复用已有补偿流程及剩余预算。取消不能越权停止其他动作或归属未知的设备活动。

| 动作状态 | 文件事实 | 结果 |
| --- | --- | --- |
| 尚未启动，收到取消 | 无本次文件 | `canceled`，不启动，不创建虚构产物 |
| 正在执行，收到取消 | 任意 | 阻止继续拍摄，完成适用的有限停止和文件核实 |
| 取消或失败的有限处理结束 | 已拍完、确认属于本动作、写入完成 | 登记为正式产物，长期保留并允许按可用性取回；动作仍为 `canceled` 或 `failed` |
| 取消或失败的有限处理结束 | 文件未完成、归属不明或完成情况未知 | 不登记为可用正式产物，保存实际诊断；未知不能解释为不存在，也不授权删除可能属于其他任务的文件 |
| 已终态 | 任意 | 保留既有结果和正式产物，不因后来取消或设备查询改写原结论 |

产物登记与动作终态原子提交；运行阶段可以报告拍摄进度，不对外发布部分正式产物集合。每个符合条件的原始文件独立分配 `output_id`，`kind: original`，实际已知时填写 `media_type`。图片没有视频时长，使用媒体时长未知状态，不伪造零秒或已通过视频检查。清理只能通过显式产物清理请求，不能以取消为由删除已保留正式产物。

有限停止结束仍无法确认设备已停止时，保留停止失败及残留效果事实，目标动作仍按取消规则结束；发起取消的动作按所需处理是否成功分别判定。后续会话的新观察保存为独立事实，不能覆盖旧的未确认结果。历史回放不执行设备操作。

录像的取消内容处理继续由[录像取消](camera-recording.md#camera_record-取消)定义。

## 拍摄结果报告

两种动作使用 `capture_result`：`capture` 表达采集结果；可选 `start`、`stop` 使用公共有限尝试结构，分别记录实际启动与停止。未执行停止不能伪造停止成功。已开始执行必须有 `result.capture`。

| `capture` 字段 | 契约 |
| --- | --- |
| `status` | `running`、`completed`、`failed`、`canceled`、`unconfirmed` |
| `captured_count` | 可选非负安全整数，只表示可靠确认已完成的采集次数；未知省略 |
| `elapsed_s` | 可选非负数，可靠采集持续时间；未知省略，不是视频播放时长 |
| `error` | `failed`、`unconfirmed` 必填；其他状态不提供 |

`succeeded` 要求采集 `completed`；终态不能仍报告采集 `running`。`running` 动作可报告采集 `completed`，表示仍在完成文件核实。取消后报告 `canceled` 或停止/完成无法确认的 `unconfirmed`，并保留符合条件的正式产物。初始受理失败及其他未执行动作不携带执行结果。

正式产物仅随已执行的 `succeeded`、`failed`、`canceled` 动作报告；全部产物选择等待来源终态。组取回包含三种拍摄动作，不以是否成功筛选来源。交付仍只嵌套在取回动作下，来源通过 ID 关联，图片和视频遵守相同大小及 SHA-256 核验规则。

## 验收

覆盖仅拍照、仅录像、仅延时和多能力设备；按张数、按持续时间、固定参数及非法参数组合；未启动取消、运行中取消并保留部分图片、停止未知、失败但保留文件、断电后任务仍执行或已结束、启动结果未知禁止不安全重拍、数据库提交未知、同请求重送不重复产物。分别验证执行状态、产物可取回、交付发布和客户端接收，不能相互推导。

## 预览文件

参数类型声明支持预览时，按[预览产物契约](preview-obtaining.md#能力与产物身份)登记预览及对应原文件关联，不能将预览混同为另一份原始照片或原始视频。用户取消拍摄同时联动自动预览取回，已登记正式产物仍按既有规则保留。
