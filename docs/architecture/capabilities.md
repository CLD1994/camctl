# 能力说明格式

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

本专题定义 `camctl describe` 导出的 JSON 字段，以及客户端如何从中找到拍摄参数的校验规则。命令输出与失败处理见 [`describe`](cli-commands.md#describe)，同步时机、整份加载和 Schema 标准见[相机拍摄](camera-capabilities.md#部署时向客户端提供说明)。

**阅读提示：** 这份说明回答“已部署设备允许客户端填写什么”，不表示设备此刻在线或空闲。先看结构与完整示例，再核对 Schema 引用；生成和手工交接的背景见[拍摄能力说明](camera-capabilities.md)。

## 文档结构

一份说明对应当前单台主机的完整设备配置，按“设备 → 拍摄动作 → 参数类型”组织。根对象包含 `devices` 数组，各层数组元素都是对象：

```text
devices[]
    device_id
    driver_id
    actions[]
        type
        parameter_types[]
            type
            name
            description
            schema
```

| 所在对象 | 字段 | 类型与含义 |
| --- | --- | --- |
| 根对象 | `devices` | 必填数组，列出全部已配置设备；允许为空 |
| 设备 | `device_id` | 必填非空字符串，对应执行计划中动作的 `device_id` |
| 设备 | `driver_id` | 必填非空字符串，标识本地配置为该设备绑定的驱动；执行计划无需重复填写 |
| 设备 | `actions` | 必填数组，列出该设备在所部署版本中实际支持的拍摄动作 |
| 拍摄动作 | `type` | 必填非空字符串，对应执行计划中动作外层的 `type` |
| 拍摄动作 | `parameter_types` | 必填非空数组，列出该设备执行此动作时接受的参数类型 |
| 参数类型 | `type` | 必填非空字符串，对应动作的 `params.type` |
| 参数类型 | `name` | 必填非空字符串，供用户选择时阅读的名称 |
| 参数类型 | `description` | 必填非空字符串，说明拍摄任务、固定设置及必要的使用条件 |
| 参数类型 | `schema` | 必填对象，该参数类型的完整 JSON Schema，校验对象为动作的整个 `params` |

第一版的外层对象使用表中字段。必填字段缺失、值为 `null`、类型不符或出现未定义的外层字段，均属于说明格式错误。`schema` 内部按 JSON Schema 解释，不套用外层对象的字段清单。JSON 对象出现重复键也属于格式错误，不能依赖解析器取最后一个值。

标识按字符串精确匹配，唯一性范围如下：

| 标识 | 唯一性范围 |
| --- | --- |
| `device_id` | 整份说明 |
| 拍摄动作的 `type` | 所属设备的 `actions` 数组 |
| 参数类型的 `type` | 所属设备、所属拍摄动作的 `parameter_types` 数组 |

多台设备可以使用同一个驱动，不要求 `driver_id` 在文档中唯一。同一参数类型标识可以出现在不同驱动或不同拍摄动作下，客户端须结合设备与动作选择规则。使用同一驱动的设备仍各自导出其生效说明，内容从同一份驱动定义及相应配置生成，不另外维护副本规则。

数组顺序不承担身份、调度优先级或默认选择含义。`name` 和 `description` 只供人阅读，不作为匹配身份；只有一个参数类型时，生成计划也必须显式填写 `params.type`。

## 空目录与定义错误

默认没有配置设备时，完整输出为以下对象，并按命令契约以换行结束。可解析文件见[空设备说明](../../protocol/examples/capabilities/empty-devices.json)。

```json
{
  "devices": []
}
```

| 条件 | 导出或加载结果 |
| --- | --- |
| 配置合法，设备目录为空 | 上述空目录是有效说明；客户端仍可生成 `report_status` 等无需拍摄设备的动作 |
| 设备及驱动定义完整有效，但明确没有本版已接入的拍摄能力 | 保留设备及驱动标识，`actions` 为空数组 |
| 设备实际支持某拍摄动作，且参数类型与规则完整有效 | 列出该动作及全部可用参数类型 |
| 已列出拍摄动作，但 `parameter_types` 为空或缺失 | 定义不完整，整份导出或加载失败 |
| 外层结构、标识唯一性、动作与参数类型关联、Schema 或必要引用有错误 | 整份导出或加载失败，不启用部分内容 |
| 导出时无法可靠取得设备配置或所需驱动定义 | 导出失败，不用空目录或空 `actions` 代替未知结果 |

空 `actions` 只表达已知的能力集合，不表达设备离线、正在录像或查询失败。能力说明不承担运行状态探测；实际动作接入范围以[拍摄能力与参数类型](camera-capabilities.md#能力参数类型与用户预设)为准。

## 参数 Schema 的内容与引用

每个 `schema` 是可以单独加载的完整参数规则。导出时将它所需的规则一同放入该对象，复用定义可放在 `$defs` 中；引用按该 Schema 的资源边界解释。例如，`#/$defs/frame_rate` 指向所选 `schema` 内的定义，不指向整份能力说明的根对象。规则复用及内嵌资源的标准机制见 [JSON Schema 结构说明](https://json-schema.org/understanding-json-schema/structuring)。

驱动内部可以共享定义，导出时为各参数类型生成完整内容。客户端加载一个参数类型，不需要从其他设备或参数类型条目补齐规则，也不依赖外部文件或临时联网下载。内嵌独立 Schema 资源时，其标识须能在该对象包含的资源中明确解析，版本声明仍遵守[拍摄参数的 JSON Schema](camera-capabilities.md#拍摄参数的-json-schema)。

为了直接检查参数类型与 Schema 的对应关系，导出根规则须满足：

- `schema.type` 为 `"object"`。
- `schema.required` 包含 `"type"`。
- `schema.properties.type.const` 与外层参数类型的 `type` 相同。

其余字段和约束可以按 JSON Schema 组合表达；导出规则须完整约束驱动允许的输入。即使某个固定任务不开放任何调整项，也提供一份只接受对应 `type` 的参数对象规则。

参数类型的 `name` 与 `description` 说明整个任务；具体参数的人类可读名称、含义和单位使用 Schema 中相应字段的 `title`、`description` 表达。默认值和合法性约束按既有 Schema 契约表达，客户端不再从另一份手写字段清单取得规则。固定设置应在任务说明中清楚说明，并由 Schema 限制调用方可填写的字段。

## 客户端选择与校验

对执行计划中的一个拍摄动作，依次执行：

1. 用 `action.device_id` 在 `devices` 中查找设备。
2. 用 `action.type` 在该设备的 `actions` 中查找拍摄动作。
3. 用 `action.params.type` 在该动作的 `parameter_types` 中查找参数类型。
4. 使用选中条目的 `schema` 校验完整 `action.params`，保持输入原样。

设备、动作或参数类型没有匹配项时，说明当前已启用目录不提供该选择；客户端提示用户修正计划，不猜测相似名称、不选择数组首项替代。已匹配且规则有效时，参数不符合规则属于输入错误。目录本身未成功加载或规则无效时，属于能力说明错误。两类错误遵守[既有校验分区](camera-capabilities.md#拍摄参数的-json-schema)，不能互相替代。

通过参数校验后，客户端仍校验计划结构、时间、业务策略及引用等要求。表单生成、JSON 编辑及输入保留遵守[客户端计划编辑](client-editing.md)。`actions` 是设备支持的动作类型目录，不包含计划中的动作实例、执行进度或运行结果。

## 完整示例

[演示设备说明](../../protocol/examples/capabilities/demo-device.json)包含一台虚构设备 `demo_cam0`，绑定虚构驱动 `demo_camera`，在 `camera_record` 下提供两种演示参数类型：

| 参数类型 | 演示用途 |
| --- | --- |
| `demo_adjustable` | 固定录像 60 秒，可选择示例中的分辨率与帧率组合 |
| `demo_fixed` | 固定录像 60 秒、1080p、30 帧/秒，只填写类型标识 |

这些标识、参数和值仅用于解释格式，不定义实际相机的参数契约。真实驱动的正式类型仍依据实际设备另行设计。

选中 `demo_cam0` 的 `camera_record` 和 `demo_adjustable` 后，以下完整 `params` 符合演示规则：

```json
{
  "type": "demo_adjustable",
  "resolution": "1080p",
  "frame_rate_fps": 60
}
```

同一规则允许 `4K / 30`，拒绝 `4K / 60`。选择固定任务时，`params` 只包含 `"type": "demo_fixed"`；额外提交帧率等字段会失败。两个参数类型的任务说明与 Schema 一同交付，客户端无需为这两个演示类型分别手写校验规则。

## 验收要求

- 导出空设备配置，得到明确的空目录；有效的无拍摄能力设备保留设备条目，定义读取失败则导出失败。
- 检查各层字段类型、必填性、重复键和唯一性；同名参数类型在不同合法作用域下可区分，同一作用域重复时整份失败。
- 按设备、动作、参数类型逐级选择，验证不会使用其他条目的规则，也不会因目录顺序改变而匹配到不同规则。
- 单独加载每个参数 Schema，检查版本、类型标识与全部引用；缺失依赖或类型关联不一致时整份说明无效。
- 用演示文件检查完整结构及示例参数的预期结果；真实驱动接入时，用其自身规则与参数样例验证浏览器、客户端后端和 camctl 的同源判定及输入保持不变。
- 将字段检查接入既有整份加载流程，验证成功整体替换、失败不启用部分目录，历史记录与用户预设仍按加载契约处理。

## 参数类型的预览支持

每个参数类型须能明确声明是否支持预览，来源为驱动权威定义；照片预览为图片，录像预览为低分辨率视频。同一设备同一动作的不同参数类型可以不同。预览声明与整份能力说明一起导出、校验和启用，不能因声明无法解释而当作不支持。字段形式及缺省语义在[协议落实边界](preview-obtaining.md#验收与协议落实边界)中列为实施前事项；上文既有字段表尚未包含此扩展。业务与受理规则见[预览文件与自动取回](preview-obtaining.md)。
