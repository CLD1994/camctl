# ADB 调用返回与运行假设

[驱动职责](camera-capabilities.md#驱动执行与产物边界) · [结果保存](../camctl/database/operation-fields.md#普通尝试结束结果的保存边界) · [联合验收](../camctl/database/consistency-verification.md#调用结果与中断恢复)

## 三类事实与操作分工

camctl 要求设备删除文件时，驱动在主机上启动本地 `adb`，由设备执行删除命令。正常结果等待超时后，驱动可能已经终止并回收本地 `adb`，却没有收到设备命令的退出结果，也不知道文件是否已经删除。驱动分别表达本地主机调用、设备命令和业务效果；普通尝试使用[统一结果结构](../camctl/database/operation-fields.md#结束结果的统一结构)保存收场依据、实际观察及适用调用信息。

| 事实维度 | 表达范围与依据 |
| --- | --- |
| 本地主机调用 | 本地进程是否启动、是否确认退出，以及停止正常等待的原因；发出终止请求不等于已经退出 |
| 设备命令 | 保存实际收到的远端退出结果，或用于收场判定的适用运行假设；采用假设不表示本次观察到了远端退出 |
| 业务效果 | 按具体操作契约表达文件删除、命令拒绝、拍摄启动或完成等事实；未取得可靠依据的部分保留未知 |

通用 ADB 执行部分负责本地进程生命周期、超时或中止原因、接收的输出，以及是否取得可靠远端退出信息。具体设备操作负责根据命令和响应解释业务证据，并声明适用的收场方式。业务层负责尝试预算、重试、取消、恢复和数据库保存；驱动不自行补发原业务命令。

本地调用错误与已知业务效果可以同时存在。驱动已经取得可靠成功证据、随后调用异常时，同时返回成功事实和调用错误。非零退出码不单独证明文件仍存在，发令成功不单独证明拍摄完成。阻塞或异步的执行方式不单独定义业务完成含义。

## 共享 ADB 服务端的生命周期

camctl 每次执行 `adb shell ...` 等调用时启动本地 ADB 客户端。客户端通过主机上的共享 ADB 服务端与设备通信；客户端负责本次调用，服务端维护连接并为多次调用提供通信。共享服务端可以跨 camctl 会话持续运行，不归某个动作、尝试或执行会话独占。

第一版使用 ADB 自带的服务端启动机制。客户端发现本机服务端没有运行时，允许其启动服务端；该过程计入本次驱动调用的正常等待时限。camctl 和 C 接入模块不另设服务端监督、重启流程或业务重试预算。服务端恢复可用不构成重发设备命令的授权，业务层仍按原尝试、效果核实及有限重试规则推进。

本次客户端及受管执行工具留在所属 camctl 的进程组中；共享服务端按 ADB 自身机制建立独立会话后，在组外持续运行。接入模块按[本地进程收场责任](../host-demo/design.md#接入模块的本地进程收场责任)处理原组，不通过 `adb kill-server` 或按进程名称批量终止来清理一次调用。

| 服务端及本次调用的情况 | 处理规则 |
| --- | --- |
| 服务端已经运行，客户端可以连接 | 使用现有服务端执行本次调用 |
| 本机服务端未运行 | 允许客户端按 ADB 自身机制启动服务端，继续受本次调用时限约束 |
| 服务端启动或连接失败，或者等待超过本次调用时限 | 按调用错误或超时规则完成客户端收场；是否派发及业务效果根据实际证据判断，不能仅凭连接错误推断无效果 |
| camctl 已退出，服务端尚未脱离原进程组 | 服务端启动进程可能随原组被终止；后续有资格的调用可以再次触发 ADB 自身的服务端启动 |
| camctl 已退出，服务端已经脱离原进程组 | 保留共享服务端，继续确认原组内客户端及其他受管执行工作已经结束 |
| 服务端异常退出，本次调用未取得可靠结果 | 保存实际掌握的结果与错误，按原操作契约核实效果和决定重试；服务端再次启动不重置原尝试次数 |

部署使用固定的一套 ADB 程序；连接同一共享服务端的调用不混用其他版本，运行期间不替换该程序。版本不匹配可能触发 ADB 自身的服务端重启，影响其他正在执行的调用。维护时停止相关业务调用后再处理服务端及工具版本；版本与启动行为按目标主机联调核验。

客户端收场、共享服务端存活和设备业务效果分别判断。共享服务端继续运行不阻止适用操作按下节运行假设收场，也不能作为旧命令已结束或业务成功的证据。正式规则的公开源码依据见[服务端核验记录](../superpowers/notes/2026-09-28-adb-call-cleanup-experiments.md#共享-adb-服务端的公开实现核验)。

## 第一版普通前台命令的运行假设

第一版对目标 ADB 驱动声明适用的普通前台命令采用运行假设：本地 ADB 客户端退出并完成本地资源收场后，依赖 ADB 的连接关闭机制收场远端命令，假定原远端命令会在后续相关设备操作开始前结束。USB 断线后，后续设备操作仍须满足目标设备可通信等原有执行条件。

该假设适用于通过 `shell_v2` 执行、工作由本次前台命令承担且响应连接挂断的普通操作，例如按此形态执行的单文件删除和存在性查询。具体驱动约束命令形态和适用范围；交给独立服务、脱离调用继续运行或忽略挂断的任务不据此判定业务结束。拍摄活动继续按所属启动、停止和完成契约处理，本地文件操作及其他独立执行方继续遵守各自的收场规则。

本地进程已退出、相关本地资源已收场且操作适用该假设时，业务层可以使用“依据运行假设收场”的判定继续处理，不逐次查询远端 PID。结果按[第一版 ADB 结果记录](../camctl/database/operation-fields.md#第一版-adb-运行假设的结果记录)可靠保存；固定适用条件由驱动规格、实现及测试保证，每次尝试保存必要结果及当次数据。记录不补造远端退出响应、退出码、观察时间或精确结束时刻。远端是否实际退出缺少本次观察，与业务层依据运行假设继续处理可以同时成立。

这是一项第一版运行前提，不是每次调用都取得了远端结束证据。其保证范围不包含远端命令延迟到后续相关操作开始之后仍继续执行的情况；已有可靠证据与假设不符时，保留诊断并停止依赖该假设的操作。底层系统持续失去响应仍由部署侧处置，不增加专门恢复机制，也不承诺任何进程都能限时结束。

[ADB 收场实验与后续重构参考](../superpowers/notes/2026-09-28-adb-call-cleanup-experiments.md)记录该选择的实测依据及限制。实验中的查询时刻和官方测试的等待值不定义固定收场时限；第一版不以额外等待固定秒数来冒充远端结束确认。

## 超时、取消与恢复判定

正常等待的时限及起点遵守各操作契约，文件操作见[设备文件删除与查询的计时](configuration.md#设备文件删除与查询的计时)。超时后停止正常等待，保留超时事实及此前取得的可靠证据。本地 `adb` 仍在运行时，按[本地 ADB 客户端的终止宽限](configuration.md#本地-adb-客户端的终止宽限)发送 `SIGTERM`；宽限到期仍未退出时发送 `SIGKILL`，并等待确认退出及回收。取消触发的本地客户端终止采用同一规则。已经确认退出时完成其余本地资源清理，不重复终止。发出信号与确认退出分别解释。

完成本地收场后，驱动返回实际掌握的三类事实及适用的收场依据。下表先检查本地收场及已知矛盾，再解释远端结果或运行假设；取消、已有终态、状态库错误及操作预算继续按所属流程处理。

| 当前情况 | 收场判定与后续处理 |
| --- | --- |
| 本地调用尚未退出，或相关本地资源尚未收场 | 继续本地收场，不因正常等待超时而认定调用已收场 |
| 已取得与运行假设不符的可靠证据 | 保留实际事实，停止依赖该假设的操作，不以假设覆盖观察 |
| 已可靠确认本次命令尚未派发且不会再执行，本地责任已收场 | 使用未派发依据，无需推导远端退出；已保存的尝试身份及次数按原规则保留 |
| 本地收场完成，取得可信远端退出结果，且操作契约保证相关命令工作随之结束 | 使用实际结束依据；业务效果按命令及响应解释 |
| 本地收场完成，发令命令已可靠确认结束，但业务工作由独立任务承担 | 结束本次发令责任；独立任务的启动、停止及完成继续按所属设备活动契约处理 |
| 本地收场完成，没有可靠远端退出结果，操作适用普通前台命令运行假设 | 按运行假设完成本次命令收场；没有独立业务证据时仍保留效果未知，不直接重发删除 |
| 本地收场完成，没有可靠远端退出结果，操作不适用该假设 | 按该操作的设备活动或恢复契约处理，保留尚未解决的责任 |

例如，普通文件删除超时并完成本地收场后，驱动按适用运行假设结束本次命令责任，删除效果仍可为未知。清理项有执行资格及查询预算时，使用原存在性查询流程核实文件；设备不可通信或查询失败仍是未知，次数及最终结果按原有限处理规则保存。取消已经生效时按取消收场规则处理。命令收场不等于清理项完成，只有本项核实、取消收场及必要结果保存均满足条件，才进入适用终态并释放处理归属。

重启继续沿用原清理项、流程、尝试及累计次数。适用该假设时，先确认原本地调用责任已经收场，再使用该假设恢复后续处理；仅有 camctl 重启事实不单独证明旧本地 ADB 客户端已经退出。已经可靠保存的收场判定使用当时的依据，不补做远端进程查询来改写历史；未保存的判定在恢复中按实际本地收场情况及适用驱动契约建立。效果未知仍按原文件核实规则处理，提交结果未知仍先核实原事务。

异步发令接口继续区分发送、启动和完成。发令命令收场只结束本次发令责任；独立拍摄活动是否结束、文件是否写完及产物集合是否齐备，仍需各自契约规定的依据。单次文件存在性查询仅表达文件观察，不作为远端进程退出证明。
