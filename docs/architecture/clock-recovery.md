# 主机时间检查与受限恢复

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

主程序会先尝试校时，camctl 仍须判断当前时间能否用于调度。本页定义时间不可信时允许做哪些有限处理，以及为什么应保存其余工作等待后续会话。正常时间与启动窗口见[调度与设备执行](scheduling-execution.md)。

**阅读提示：** 先区分日期时间的墙钟与测量经过时长的单调钟，见[恢复术语](concepts.md#断电恢复中常见的词)。随后分别阅读 `submit`、正常 `run` 和时间异常时的处理，联合验收见[调度专题](scheduling-execution.md#验收要求)。

## 时钟防御

### submit

`submit` 不进行启动墙钟可信性检查。

只验证时间字段：

- 格式；
- 结构；
- 静态合法性。

不依据当前本机时间判断：

- 动作是否已过期；
- 是否已经到 scheduled_at。

### run

`run` 按[请求受理与会话](protocol-session.md)的“`run` 的启动顺序”，在取得会话锁、验证状态库并完成适用的计划受理后，进行墙钟可信性检查。

时钟检查读取可信历史时间下界，再检查当前墙钟，必要时延迟复检。带计划启动的受理事务在此之前已经结束，墙钟复检等待不持有该事务。

计划受理阶段的本机时间尚未经过启动校验，不能用于推进可信历史时间下界。首次受理、幂等复用及受理拒绝的时间记录均遵守这一规则。

### 时钟正常

进入正常：

- 恢复；
- 调度；
- 执行；
- 报告。

### 时钟异常

复检仍失败时，不进入正常时间调度。

进入：

> 有限安全收场模式。

处理已经存在并且能够证明安全的遗留收场责任，以及下节允许的立即取消请求。取消产生的收场仍须证明属于被取消的目标。

不：

- 启动新的普通定时动作；
- 用错误墙钟判断 pending 动作已经过期；
- 依据错误墙钟推断录像已录多久。

受限收场结束后，本次 `run` 仍以时钟异常退出。 收场期间再发生状态库等会话错误时，按[会话错误与恢复边界](session-errors.md)停止依赖已失效条件的工作，并保留实际错误和设备事实。

时钟异常不回滚启动阶段已经提交的计划受理结果。新计划的普通动作保留等待处理的状态，后续实际启动的会话再按当时的时间与设备条件判断执行资格。

录像停止后的文件拷贝、媒体核验与修复不属于本模式允许的安全收场。已停止但后处理未完成的录像按[安全收场与后续处理的衔接](camera-recovery.md#安全收场与后续处理的衔接)保存进度，等待后续正常会话；未完成的后处理不能使当前受限会话转入普通执行或持续等待。

### 时钟异常期间的取消

墙钟复检仍失败时，`run` 允许执行已受理、未填写 `scheduled_at` 的 `cancel_task`，包括本次启动时新受理的取消请求。该资格只允许取消指定计划或动作、按已保存关联联动自动预览取回及完成其必要收场，不授予其他普通动作执行资格；`submit` 仍只负责受理。

先检查取消动作自身的持久化状态，再判断时间和目标。已取消或已进入其他终态的取消动作保持原结果，不重新执行；已形成的遗留收场责任按各自恢复规则处理。已经开始且仍未完成的取消，按已保存的目标和进度恢复能够证明安全的有限收场，不重新判断原计划时间或扩大目标。对于尚未开始的取消动作，按下表处理：

| `scheduled_at` | 目标查询结果 | 处理 |
| --- | --- | --- |
| 已填写 | 任意 | 保留待执行状态，不依据不可信墙钟判断已到时间或过期 |
| 未填写 | 可靠定位到指定计划或动作 | 执行该目标范围内的取消，按目标类型处理必要收场及可撤回交付 |
| 未填写 | 可靠确认目标不存在 | 按既定寻址规则记录 `target_not_found`，本次取消结束 |
| 未填写 | 查询失败、关联不明或结果未知 | 保留诊断并按对应错误处理，不能当作目标不存在，也不能扩大取消范围 |

例如取消计划 P1 时，同一相机当前正在执行 P2 的录像，不能为了完成 P1 的取消而停止 P2。只有证据确认正在进行的录像属于取消目标时，才按录像取消规则尝试停止；归属无法确认时保留未知事实。设备操作仍遵守有限重试与安全收场约束，不用取消请求绕过这些条件。

目标已经终态时保持其历史终态；目标为取回动作时，仍按所属规则处理其可撤回 delivery。源产物与其他动作的文件继续遵守各自生命周期。取消处理不依赖错误墙钟安排等待，必要超时及有限等待使用当前会话的单调钟。

受限会话仍不持有普通接纳资格。并发 `submit` 按既有接管协议判断 `needs_run`；本节不承诺受限会话持续接纳后来的工作。允许的取消及有限收场结束后，本次 `run` 仍返回时钟异常，不因尚有普通待执行动作而转入正常调度。

### 时钟异常期间的事件

保留实际墙钟读数，但明确：

```text
wall_time_trusted = false
```

这类时间不能更新未来启动校验所使用的可信墙钟下界。

业务顺序和报告覆盖使用：

- `change_seq`
- `report_id`
- 状态机身份

而不是依靠错误墙钟排序。

### v1 已知边界

运行中的墙钟跳变：

> v1 不持续监测、不主动处理。

稳定但错误的外部时间源：

> 缺少外部可信基准时无法判定。
