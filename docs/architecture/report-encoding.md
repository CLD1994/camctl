# 状态报告的确定字节编码

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

本页定义第一版生成器如何把冻结报告输出为确定的 JSON 字节。同一 `report_id` 重建时必须保留原字节、摘要和文件名。字段含义见[字段契约](report-format.md)，历史冻结见[从历史重建报告](status-reports.md#从历史重建报告)。

## 文件生成与实体排序

报告生成从冻结历史取值。对象成员顺序、字符串转义、数值编码及实体排列使用已登记报告的确定生成规则；客户端不依赖这些排列来识别身份。对既有报告重建必须保持原字节、文件名和摘要，不能因 Schema 校验只关心 JSON 值就改变原文件。

第一版生成器对以下实体集合分别按完整 ID 的 ASCII 字典序升序排列，保留大小写，不将 ID 中的数字片段转换为数值排序。排序限定在各自所属集合内，不表达动作执行顺序。

| 实体集合 | 排序字段 |
| --- | --- |
| `plans` | `plan_instance_id` |
| 每个计划的 `actions` | `action_instance_id` |
| 每个动作的 `outputs` | `output_id` |
| 每个动作的 `deliveries` | `delivery_id` |
| `plan_file_diagnostics` | `diagnostic_id` |

参数、结果等自身字段中的普通数组保留原有顺序；业务规则规定的逐项结果顺序继续有效。实体排序不扩大报告选择范围，同一实体在所属集合中只出现一次。生成批次的大小不改变这些顺序或最终字节。

## 第一版生成器的结构与排版

| 项目 | 固定规则 |
| --- | --- |
| 文件编码 | UTF-8，不带 BOM（文件开头的编码标记） |
| 空白与结尾 | 紧凑输出，不加缩进或分隔空格；完整根对象之后固定写入一个 `LF` 换行符 |
| 对象自身字段 | 按字段名的 Unicode 码点字典序升序输出，不依赖字典构造顺序或数据库返回列顺序 |
| 实体子集合字段 | 放在所属对象的自身字段之后；根对象先 `plans` 后 `plan_file_diagnostics`，计划输出 `actions`，动作先 `outputs` 后 `deliveries`；只输出适用的集合 |
| 自身字段中的 JSON 对象 | 递归按字段名的 Unicode 码点字典序排序；其中的普通数组保留原有顺序 |
| 可选的空实体集合 | 统一省略 |
| 字符串 | 中文直接以 UTF-8 输出；引号、反斜杠及换行等字符使用固定的 JSON 转义规则 |

实体子集合按所在协议层级识别，不能仅凭字段名判断。例如参数对象中的同名字段仍属于参数值。输入参数等自身字段内的 `[]`、`{}`、`null` 和字段省略保留各自含义，不因紧凑输出而相互替换。自身字段的存在性继续服从各字段契约。

以上是 camctl 生成报告的规则；客户端仍按协议解析合法 JSON，不依赖对象成员排列识别业务身份。分段生成只改变每次写入的字节数量，不改变分隔符、排版或结尾。

## 字符串与转义

字段名和字符串值采用相同的字符编码与转义规则。输入的字符完整性遵守[输入文件与基本值类型](plan-input.md#输入文件与基本值类型)，合法代理转义对还原为对应字符；输出保持字符内容，不做 Unicode 归一化。

| 字符分区 | 输出规则 |
| --- | --- |
| 双引号、反斜杠 | 分别使用 `\"`、`\\` |
| 退格、换页、换行、回车、制表符 | 分别使用 `\b`、`\f`、`\n`、`\r`、`\t` |
| 其余 U+0000～U+001F 控制字符 | 使用 `\u00xx`，十六进制字母小写 |
| 其余 Unicode 标量值，包括中文、表情及正斜杠 | 直接以 UTF-8 输出，不额外转义 |

未配对代理码点不是合法字符串内容；输入解析失败的诊断使用可编码的转义文本描述它。诊断中的字面反斜杠仍按上表转义，使客户端看到的是错误字符的文字表示。字符转义不改变字段的合法性要求，例如名称禁止控制字符的约束继续有效。

## 精确数值与统一写法

camctl 对输入数字保持精确数值，校验、保存、历史恢复和报告输出不得通过浮点转换或舍入改变该值。报告仍输出 JSON 数字，不将数字改成字符串。字段自身的类型与范围约束继续有效，错误输入值按既有原始输入和诊断规则保留。

数字按以下统一规则生成，不要求保留原输入的尾随零或指数写法。令 `a` 为数值的绝对值，各分区互斥且覆盖全部有限数值：

| 数值分区 | 输出格式 |
| --- | --- |
| 数值为零，包含带负号或小数尾随零的写法 | `0` |
| 非零，`0.000001 ≤ a < 10²¹` | 普通十进制；整数不带小数点，小数去掉小数部分末尾多余的零 |
| 非零，`a < 0.000001` 或 `a ≥ 10²¹` | 科学计数法；小数点前一位非零数字，尾数去掉小数部分末尾多余的零，无小数部分时省略小数点 |

非零负数在数值前保留一个负号。科学计数法使用小写 `e`；正指数不带 `+`，负指数保留负号，指数不带多余的前导零。普通十进制绝对值小于 1 时保留小数点前的 `0`。所有格式保留完整精确数值，不限制有效数字数量，不通过舍入选择格式。分区条件决定写法，不改变字段允许的数值范围。

| 输入数值示例 | 统一输出 |
| --- | --- |
| `1`、`1.0`、`1e0` | `1` |
| `1.2500` | `1.25` |
| `1.0000000000000001` | `1.0000000000000001` |
| `0.0`、`-0` | `0` |
| `1e-6` | `0.000001` |
| `0.00000012` | `1.2e-7` |
| `-0.00000012` | `-1.2e-7` |
| `1e20` | `100000000000000000000` |
| `1e21` | `1e21` |

这些规则在首次生成及重建时保持一致，不随本次进程配置改变。非 JSON 数值常量继续按既有契约拒绝，不属于上表的格式选择范围。

实现采用的数值类型及贯穿保存、恢复的要求见[精确数字与统一输出方向](../camctl/data-types.md#精确数字与统一输出方向)。客户端读取的仍是既有 JSON 数字类型。
