# 客户端部署与能力说明加载

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

本专题定义个人电脑上的客户端目录、Docker 持久化方式，以及能力说明的启动加载与手动重新加载。客户端技术组合见[客户端的本地部署](#客户端的本地部署)，能力说明的内容与同步责任见[相机拍摄](camera-capabilities.md#部署时向客户端提供说明)。

**阅读提示：** 本页的部署对象是用户个人电脑上的客户端。先看技术组合和目录，再按人工交接步骤加载能力说明；主机上的 camctl 初始化另见[首次部署](initialization.md)。

## 客户端的本地部署

客户端以易用性和易部署为目标，部署在用户的个人电脑上。采用本地后端配合浏览器网页的形式，通过 Docker 提供应用运行环境；用户通过 `localhost` 的本地端口访问界面。部署人员可以安装所需软件，负责准备 Docker 运行环境及应用部署包。

第一版客户端采用以下技术组合：

| 职责 | 选型与边界 |
| --- | --- |
| 浏览器界面 | TypeScript；提供计划编辑、文件选择、导出与状态展示 |
| 本地后端 | TypeScript，运行于 Node.js；处理客户端业务并提供构建后的前端网页资源 |
| 拍摄参数校验 | Ajv；浏览器与后端共用校验配置和错误转换代码，规则来自能力说明 |
| 客户端持久化 | SQLite；由后端保存客户端数据，并统一处理报告合并和累计确认进度 |
| 应用部署 | Docker Compose 管理单个应用容器；前端网页资源和后端随同一应用版本交付 |

固定的计划和接口结构通过共享的 TypeScript 类型及相关代码保持一致；报告公共类型与结构校验从[状态报告字段契约](report-format.md)的 Schema 读取或生成。设备专属拍摄参数按部署时导入的 JSON Schema 在运行时校验；具体字段由驱动定义，遵守[拍摄参数的 JSON Schema](camera-capabilities.md#拍摄参数的-json-schema)。

拍摄参数以根据 Schema 生成的表单作为主要编辑入口，保留 JSON 编辑以处理复杂参数。两种编辑方式共用当前动作的完整参数和校验规则；正常流程、视图切换及导出前校验见[客户端计划编辑](client-editing.md)。

应用部署包包含后端、前端网页资源及所需运行时依赖。客户端的草稿、原请求、预设、已保存的报告状态和确认进度由本地后端管理，持久化数据与容器生命周期分开。部署目录内的 `data/` 通过目录挂载提供给容器，能力说明为 `data/device-capabilities.json`，客户端数据库为 `data/client.db`；重新创建或更新应用容器时继续使用原有数据。具体路径见[部署目录](#部署目录)，加载入口见[启动与重新加载](#启动与重新加载)。

客户端 Docker 应用运行在用户个人电脑上；主程序和 camctl 运行在嵌入式 Linux 主机上，职责见[运行环境与协作分工](system-context.md)，两者通过既定的人工交接和消息传输流程交换计划与报告。

## 部署目录

部署人员在用户电脑上选定一个普通目录放置客户端部署包。目录名称与绝对位置由部署人员选择，下面以 `camctl-client` 为例；包内相对路径固定：

```text
camctl-client/
    apps/client/compose.yaml
    data/
        device-capabilities.json
        client.db
```

| 路径 | 职责 |
| --- | --- |
| `apps/client/compose.yaml` | 应用提供的 Docker Compose 配置，启动包含后端与网页资源的单个应用容器 |
| `data/` | 用户电脑上的持久化目录，在启动前准备并赋予应用所需的读写权限 |
| `data/device-capabilities.json` | 用户手工复制覆盖的完整能力说明；客户端按本专题加载 |
| `data/client.db` | 客户端后端管理的 SQLite 数据库，保存草稿、原请求、预设、报告状态及累计确认进度 |

Compose 将相对于配置文件的 `../../data/` 整体映射为容器内的 `/app/data/`。源码构建上下文为仓库根目录，包含 `apps/client` 和 `protocol/schemas`。后端从 `/app/data/device-capabilities.json` 读取说明，使用 `/app/data/client.db` 保存客户端数据。目录映射采用 Docker 的 bind mount（绑定挂载），让容器直接访问用户电脑上的指定目录，机制见[目录挂载说明](https://docs.docker.com/engine/storage/bind-mounts/)。

挂载整个目录，使用户通过文件管理器复制、覆盖或替换能力说明文件后，后端重新打开固定路径即可读取当前文件。后端不要求用户进入容器操作文件。SQLite 运行所需的伴随文件也位于持久化目录，不能只持久化数据库主文件而把必要数据留在容器临时存储中。

重新创建或更新应用容器时继续挂载同一个 `data/`，不清空或用部署包中的初始数据覆盖它。能力说明的加载不删除、替换或重建 `client.db`。本目录用于个人电脑上的客户端；嵌入式主机上 camctl 的配置、状态库及交接目录继续遵守各自契约。

部署配置提供客户端镜像构建和启动入口，用户通过本机 `localhost` 端口访问网页。具体操作见[运行说明](../client/running.md)，容器部署由部署人员验证。

## 启动与重新加载

客户端后端启动时，从固定路径读取能力说明。网页提供“重新加载能力说明”按钮，供用户在复制覆盖文件后主动触发同一加载流程；重新加载无需重启容器。

加载流程如下：

1. 后端完整读取本次文件内容，按[能力说明格式](capabilities.md)及[Schema 契约](camera-capabilities.md#拍摄参数的-json-schema)校验全部结构、关联和参数规则。
2. 全部检查成功后，一次性启用本次完整说明，替换此前用于生成新计划的能力目录。
3. 后端向网页提供已启用的完整说明，网页据此更新设备选择、参数表单和校验规则，并显示加载成功。

网页使用后端提供的已启用说明，不独立读取电脑上的能力文件，也不以自己另外缓存的一份规则决定当前可用能力。一次导出前校验使用同一份启用快照；重新加载不能让这次校验的不同动作分别使用新旧规则。

文件被覆盖本身不触发规则切换。已经运行的客户端在用户点击重新加载或下次启动加载前，继续使用此前已启用的说明。加载完成后，当前草稿与预设保留原有内容，按新规则重新校验；不自动更换设备、参数类型或参数值。已导出的原请求与历史记录遵守既有保留规则。

成功加载后，网页完成当前参数规则更新及草稿重新校验，再恢复相关拍摄计划的导出操作。浏览器反馈不能代替后端对实际准备导出内容的校验，具体要求见[客户端计划编辑](client-editing.md#校验与导出)。

## 加载结果与现有数据

加载结果由“本次文件是否完整有效”和“本次加载前是否已有启用说明”共同决定：

| 本次文件 | 此前已启用说明 | 处理与可观察结果 |
| --- | --- | --- |
| 完整有效 | 无或有 | 一次性启用本次完整说明，网页显示加载成功；新计划使用本次规则 |
| 缺失、无法读取、JSON 有错误或规则无效 | 无 | 显示具体加载错误，能力说明处于不可用状态；用户补齐或修正文件后再次点击加载 |
| 缺失、无法读取、JSON 有错误或规则无效 | 有 | 显示本次加载失败，并明确当前仍使用此前成功加载的说明；不启用本次文件的任何部分 |

有效的 `{"devices": []}` 是明确的空设备目录，加载成功时也整体替换此前目录。文件缺失、读取失败或内容错误不等价于空目录，客户端不能自动生成空说明来掩盖加载错误。

此前已启用的说明是当前进程已经完整读取、校验的内容；加载失败时保留它，不意味着恢复磁盘上的旧文件，也不保证下次启动仍能取得它。每次后端启动均按固定路径中的当前文件重新加载。

能力说明不可用时，网页仍提供加载入口、已有数据查看和报告导入等不依赖拍摄参数规则的功能；含拍摄动作的新计划在取得有效规则前不能导出。`report_status` 等无需拍摄参数的计划仍按自身契约校验。这里以客户端数据库及其他相应职责正常为前提，不能把数据库故障当作能力说明错误处理。

## 人工交接步骤

1. 在嵌入式主机上执行 `camctl describe`，按命令契约确认正常退出且导出内容完整有效。
2. 将该文件手工复制到个人电脑部署目录下的 `data/device-capabilities.json`，覆盖对应文件。
3. 客户端尚未启动时，由启动流程加载；客户端已运行时，在网页点击“重新加载能力说明”。
4. 确认网页显示加载成功，再使用新目录选择设备和生成计划。失败时依据提示修正文件并再次加载。

实际传输部门的计划和报告交接流程保持既有约定；本流程只更新部署时提供给客户端的能力与参数规则。

## 验收要求

- 从部署目录启动应用，确认后端读取映射目录中的说明并将客户端数据保存在同一持久化目录；重新创建容器后已有数据保留。
- 使用文件管理器替换说明文件后，验证点击重新加载可读取新内容，无需重启容器；仅覆盖文件而未加载时，当前规则不变。
- 覆盖表中全部加载分区，区分有效空目录、文件缺失和非法说明；失败不启用部分规则，已有说明保留时网页明确提示实际使用来源。
- 启用新说明后，验证浏览器与后端使用同一份规则，当前草稿保留原值并重新校验，历史与已导出的请求不被改写。
- 验证单次导出校验不会混用不同次加载的规则；未完成网页规则更新时，不能凭此前的校验结果导出相关拍摄计划。
- 启动时说明不可用但数据库正常，验证网页可补齐说明、查看已有数据、导入报告及准备合法的无拍摄动作计划；重新加载不改动数据库身份或确认进度。
