# 客户端计划编辑

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

本专题定义第一版网页中的动作编辑方式。客户端采用表单作为主要入口，拍摄参数来自能力说明，内置动作来自各自协议；保留 JSON 编辑以处理非法输入和通用表单无法充分表达的参数。部署及人工交接见[客户端的本地部署](client-deployment.md#客户端的本地部署)，拍摄参数规则来自[能力说明](capabilities.md)。

## 内置动作与公共字段

所有已支持动作均有普通表单入口。公共字段按[第一版动作入口](plan-input.md#第一版动作入口)决定必填、可选或禁止。取回动作不显示所属组编辑入口；直接通过 JSON 带入的非法所属组或设备字段保留并提供明确移除操作。拍摄、电机控制、取回、删除的执行时间标为必填，取消和报告标为可选；无效时间原值保留，不能因控件无法显示而自动删除。切换动作类型遵守下节的独立编辑内容规则。拍摄和电机控制提供必填的 `max_delay_ms` 编辑；取回、删除、取消和报告的策略只允许缺省或空对象，不提供业务策略设置。

| 动作 | 表单模式 | 写入字段 | 组合限制 |
| --- | --- | --- | --- |
| 电机控制 | 位置控制 | `params.position`、`scheduled_at`、`policy.max_delay_ms` | 位置按[通知协议](../../protocol/host-notifications.md#电机参数)校验整数表示；不填单位、不选相机设备或拍摄参数类型，业务范围由主程序定义 |
| 取回 | 本计划动作 | `params.source.action_name` | 提供本计划拍摄动作候选；界面不提供按产物 ID 精确筛选 |
| 取回 | 本计划组 | `params.source.group` | 提供包含拍摄动作的组候选；禁止 `output_ids` |
| 取回 | 指定动作实例 | `params.source.action_instance_id` | ID 可手工输入，本地未知不等于不存在；可启用按产物 ID 精确筛选 |
| 取回 | 指定计划实例的组 | `params.source.plan_instance_id`、`params.source.group` | 禁止 `output_ids` |
| 取回 | 当前计划 | `params.source.current_plan = true` | 选择当前计划中的产物来源动作；禁止 `output_ids` |
| 取回 | 指定计划实例 | `params.source.plan_instance_id` | 不带 `group`，选择该计划中的产物来源动作；禁止 `output_ids` |
| 删除产物 | 明确列出产物 | `params.output_ids` | 必填非空、无重复的 ID 数组；空列表不表示全部 |
| 删除产物 | 本计划动作 | `params.source.action_name` | 清理该动作的全部正式产物；不同时提供 `output_ids` |
| 删除产物 | 指定动作实例 | `params.source.action_instance_id` | 清理该动作的全部正式产物；不同时提供 `output_ids` |
| 删除产物 | 当前计划 | `params.source.current_plan = true` | 清理当前计划中产物来源动作的全部正式产物；不同时提供 `output_ids` |
| 删除产物 | 指定计划实例 | `params.source.plan_instance_id` | 不带 `group`，清理该计划中产物来源动作的全部正式产物；不同时提供 `output_ids` |
| 取消 | 原请求／计划实例／动作实例／指定计划的组 | `params.target` 内分别为 `request_id`／`plan_instance_id`／`action_instance_id`／`plan_instance_id` 与 `group` | 每次恰好一种组合，不能按名称取消 |
| 报告 | 完整同步 | `params.scope = "full"` | 不携带报告起点 |
| 报告 | 局部同步 | `params.scope = "since"` 与 `params.after_report_id` | 起点只能选择客户端已可靠保存、且 `to_wm` 不超过本地完整累计覆盖水位的报告；不能自动选首项 |

只有“指定动作实例”提供“仅取回指定产物”附加选项，默认关闭；启用后逐项填写产物 ID。本计划中的动作或组尚无可供用户选择的产物 ID，不显示此选项；指定计划实例中的组、当前计划和指定计划实例同样不提供按产物 ID 精确筛选。切换为不提供该选项的来源时清除当前 `output_ids`。JSON 带入的产物 ID 筛选保留并提示通过 JSON 核对或明确移除；协议是否允许仍由协议校验判断，界面限制不改变协议。列表可添加、修改、删除条目，不自动去重、裁剪字符串或转换类型。

取回的来源、筛选和用途遵守[公共输入组合](plan-input.md#取回来源筛选与预览)，客户端不另行定义机器字段。普通取回默认排除预览，并优先选择对应修复成品；手动预览取回使用 `filter: "preview"`，与自动用途分开处理。按产物 ID 精确取回不与 `filter` 混用。范围清理包含所选动作或计划的全部正式产物，不支持组来源，也不提供 `filter`、`purpose` 或取回的默认替代规则。

| 输入／操作状态 | 编辑与恢复行为 |
| --- | --- |
| 缺省参数或对象、已识别的引用组合 | 展示普通表单；必填缺失允许继续编辑但阻止导出 |
| 改选来源或取消目标模式 | 提前说明会替换原引用；仅在用户选择时切换模式，需要填写的引用从空字段开始，不猜测目标；选择当前计划时写入 `current_plan: true`；改为非指定动作实例来源同时清除 `output_ids` |
| 报告参数缺省或为空对象 | 保留输入，提示必须选择完整或局部同步并补齐必填项，阻止导出；不自动补成完整同步 |
| 改选报告模式 | 提前说明会替换报告参数；用户选择时生成对应参数；局部同步的起点仍待用户选择 |
| 参数非对象、引用组合混用、额外字段或控件无法表示的值 | 保留并展示原值与 JSON 修正入口；提供明确重新填写入口，不在渲染、刷新或切换视图时修正输入 |
| 参数中存在未完成输入 | 保留原文；暂停会覆盖这段输入的表单操作，先修正或明确放弃 |
| 草稿重新打开、折叠或能力说明变化 | 用户参数原样显示；仅自动预览派生动作按开关和可靠能力协调，不替用户参数填默认值 |

正常表单编辑、JSON、历史记录生成的后续动作、自动保存与导出使用同一份草稿。前后端继续使用协议校验器；表单只限制合法选择，不独立认定跨计划目标存在。JSON 是高级编辑入口，合法内置动作不要求用户手写 JSON。

**阅读提示：** 从用户添加一个拍摄动作开始阅读。表单和 JSON 编辑使用同一份参数；随后各节说明切换编辑方式、发现错误和导出时怎样保留用户输入。

### 按动作类型保存编辑内容

同一动作的名称和执行时间共用；其他字段（包括设备、所属组、参数、策略及未知字段）和这些字段的未完成输入按动作类型独立保存。当前类型的权威内容是当前计划正文；其他类型仅保存于客户端草稿编辑资料，不进入协议正文。

| 操作或状态 | 结果 |
| --- | --- |
| 选择当前类型 | 内容不变 |
| 首次选择另一类型 | 保存原类型内容，新类型只保留共用字段，不自动填设备或参数 |
| 切回已填写类型 | 恢复该类型的完整内容和未完成原文，按当前能力重新校验 |
| 未选择类型、未知或非法类型 | 同样保留独立内容，不猜测所属类型 |
| 当前类型有未完成输入 | 允许切换；切走后保留该输入，只校验当前类型；切回后继续提示并阻止导出 |
| 共用字段或整个动作存在未完成输入 | 保留输入；无法确定切换边界时禁用类型切换 |
| 自动保存、失败重试、结果核实、刷新及重启 | 当前内容与各类型内容作为同一草稿版本保存和恢复，不单独提交 |
| 删除动作 | 删除对应的全部类型内容，后续动作的内容保持对应 |
| 添加动作、从历史追加动作 | 新动作有独立内容，不继承其他动作的类型内容 |
| 导出、复制已导出请求 | 只使用当前协议正文，不带入其他类型的编辑资料 |

参数 JSON 只编辑当前类型并保留其他类型内容。整份计划 JSON 可以改变动作数量和顺序，因此开始修改前若存在其他类型内容，必须明确确认以当前计划替换整个编辑结构（同时清除其他类型内容）；取消时保留完整草稿。仅查看 JSON 不清除任何内容。此确认只适用于整份计划替换，不用于正常类型切换。

### 整组动作替换与移除

用户通过 JSON 修正整个根 `actions` 字段时，新数组代表一组新的编辑内容。客户端先确认能够保留计划的其他字段，再说明本次操作会清除旧动作身份、自动预览开关资料、全部停用类型资料及动作集合内未完成输入，由用户明确确认。确认后自动预览为“尚未设置”，动作显示状态重新建立，新动作默认展开。即使新旧数组长度或内容相同，也不能据此继承旧身份。

应用整个数组修正和明确移除整个 `actions` 字段使用下表。各行自上而下判定；取消或资格不满足时，不提交正文或编辑资料变化。正常逐项添加、删除、复制、类型切换和局部参数编辑继续使用各自规则。

| 当前条件或用户选择 | 正文、资料及页面行为 |
| --- | --- |
| 修正路径不是整个根 `actions` 字段 | 按对应局部编辑规则处理，不执行整组清理。 |
| 路径不能按 JSON Pointer（JSON 指针）规则明确解释 | 保留路径和原文，指出路径错误，不猜测它属于动作集合。 |
| 根对象等祖先仍有覆盖动作集合的未完成输入 | 保留全部输入和资料，先修正祖先；不能根据上次解析的正文补造当前其他字段。`/actions` 自身和其后代输入属于本次整组确认范围。 |
| 当前完整正文无法解析为对象 | 保留正文、候选输入和资料，说明当前无法修改其中的动作字段；不能凭候选数组重建其余计划。 |
| 数组修正尚未形成可解析 JSON 数组，包括语法错误、重复成员名，或值是对象、标量或 `null` | 保留候选及原正文，说明解析或数组资格问题，不进入成功替换，也不清除旧资料；用户可以保存输入并继续修正。 |
| 数组修正可用，或选择移除整个字段，但尚未确认 | 展示本次整组操作及清理范围，保持原正文、资料和显示状态。 |
| 用户取消确认 | 保留原正文、全部未完成输入、开关、身份、停用类型资料、折叠和局部 JSON 模式。 |
| 用户确认数组替换 | 写入用户提供的精确数组；清除上述旧动作资料和集合内未完成输入，保留集合外输入及正文其他字段。空数组或业务非法的元素可以继续编辑和保存，公共导出仍须完整校验。 |
| 用户确认移除整个字段 | 删除 `actions` 字段并清除同一范围的资料，保留其他正文和输入；不生成空数组替代缺省，导出按缺少合法动作列表报告问题。 |

集合内输入按有效 JSON Pointer 解码后的首段恰为 `actions` 判断。`/actions_extra` 和首段为 `actions/other` 的路径不属于该集合；无法解释的路径保留原文和诊断，不猜测清理范围。它们不阻止已经明确的整组结构替换，但仍按未完成输入规则阻止导出。所有保留和替换的数字继续遵守[原输入保存规则](../client/storage-and-recovery.md#草稿预设与原请求的保存)。

## 自动预览与来源范围编辑

新建计划的自动预览开关默认开启，客户端维护派生动作而非要求用户逐项编辑；完整身份、能力重载、保存及导出规则见[自动预览](../client/automatic-previews.md)。开关包含开启、关闭和“尚未设置”三种状态；客户端保留明确的自动用途与来源关联，手动预览取回独立管理。

整份 JSON 替换和外部导入遵守[开关恢复规则](../client/automatic-previews.md#外部导入与整份-json-替换)：没有对应的可靠开关资料时置为尚未设置，保留显式动作，不继承被替换草稿的开关。局部参数 JSON 编辑保留开关；未完成原文不能被自动协调覆盖。

## 正常编辑流程

新增动作只填写动作名称，用户依次选择动作类型、该动作需要的目标设备和参数类型，不按目录顺序预选。尚未选择动作类型时提示选择后填写参数，不显示空白的参数 JSON 编辑器；已有参数仍保留编辑入口。动作类型候选由本版已接入动作与当前能力目录确定，不受草稿中已选或残留设备字段限制。

| 动作类型与能力状态 | 动作候选 | 目标设备栏 |
| --- | --- | --- |
| 未选择、未知或无效的动作类型 | 无需设备的内置动作，以及当前目录中至少一台设备支持的已接入拍摄动作 | 不显示 |
| 已选需要设备的拍摄动作 | 同上 | 显示，仅列出支持当前动作的设备 |
| 已选无需设备的内置动作 | 同上 | 不显示，残留设备字段按公共字段规则显式移除 |
| 能力说明不可用或没有可用拍摄能力 | 仅无需设备的内置动作 | 已保存的拍摄动作仍显示设备栏，候选为空，保留失效选择 |

动作类型决定设备栏是否出现；设备能力只决定该动作可选择哪些设备。未选择类型时，已有设备值作为待确定适用性的原值展示；未知类型不推断设备要求。通过类型选择器改为内置动作时，将拍摄设备保存在拍摄类型内容中；切回后恢复原选择并按当前能力校验。

空 `actions` 表示该设备没有本版可用拍摄能力，不能获得其他设备的能力。已保存但不再匹配候选的设备、动作或参数类型，显示原值及不可用提示，作为禁用的诊断项保留；用户仍可清除设备选择或改选合法值。切换设备只修改设备字段，其他参数、策略及未完成输入保持原样；动作类型按独立内容规则切换。能力重新加载、刷新和打开草稿保留用户输入；自动预览派生动作按[开关维护规则](../client/automatic-previews.md)协调，不适用组合由既有前后端校验阻止导出。

设备说明按每台设备实际声明的拍摄能力分别展示任务，并标明能力名称；空能力明确说明没有本版可用拍摄任务。通用说明不假定所有设备具有录像或画质调整功能。第一版接入范围仍遵守拍摄能力规格。

用户在计划中添加拍摄动作，依次选择拍摄动作类型、目标设备和参数类型。设备及类型选项来自当前成功启用的能力说明，按[设备、动作、参数类型的关联](capabilities.md#客户端选择与校验)取得对应 Schema。选择结果写入动作的 `device_id`、外层 `type` 和 `params.type`；网页根据这些字段显示当前选择。

选定参数类型后，网页展示其名称、任务说明和固定设置，并根据 Schema 为普通参数生成控件。用户填写参数，浏览器即时校验并指出字段或组合错误；完成整个计划后，由客户端后端校验当前准备导出的完整内容，再生成计划 JSON 文本供用户交接。

动作名称、执行时间、业务策略等公共字段仍按[执行计划输入契约](plan-input.md)编辑和校验。拍摄参数表单处理选定类型的 `params`，不能代替整份计划校验。此流程用于准备新请求；已经导出的请求按[确认与重送规则](plan-acceptance.md#客户端确认与重送)保留原内容和身份。

## 根据 Schema 生成表单

表单控件及说明从同一份已启用的参数 Schema 派生。普通字段的第一版编辑能力如下；具体控件外观由客户端实现确定：

| 参数形态 | 编辑行为 |
| --- | --- |
| 明确的字符串字段 | 提供文本输入，保留字符串值 |
| 明确的整数或数值字段 | 提供数值输入，按用户有效输入生成对应 JSON 数值；未填写或尚未完成的输入不解释为 `0` |
| 布尔字段 | 提供明确的真假选择；字段缺省与显式 `false` 分开表达 |
| 明确列出的枚举选项 | 提供选项选择，写入所选项原有的 JSON 值和类型 |
| 嵌套对象、数组或其他通用表单无法充分表达的结构 | 提供 JSON 编辑入口，保留完整参数和同源校验 |

参数类型的名称与任务说明使用能力说明中的 `name`、`description`；具体字段的名称、含义和单位使用 Schema 中相应的 `title`、`description`，同时保留字段标识以便定位。必填性、默认值及取值限制按 Schema 展示，不另外维护一套相机专属的表单校验规则。

可选字段允许保持未填写。缺省、显式 `null`、空字符串、`0` 和 `false` 按用户实际输入及 Schema 分别处理；控件不能将这些值互相替换。Schema 中的默认值展示为说明，打开表单或切换视图不自动把它写入参数。校验及 camctl 首次受理时的生效参数计算遵守[默认值契约](camera-capabilities.md#拍摄参数的-json-schema)。

固定任务可能只需要 `params.type`。此时网页展示任务的固定设置，不生成驱动没有开放的调整项。

### 字段显示与必填性

正常字段以控件内的值为准，不另列“当前值”或重复的缺省提示。字符串选项显示原字符串，不显示 JSON 的引号；写入的值仍保持原有类型。所有必填输入字段统一标明“必填”，包括计划名称、动作名称、动作类型、需要的目标设备、拍摄参数类型、按类型要求的时间、业务策略、来源／目标、产物 ID 和 Schema 必填项。动作列表及动作卡片标题只展示标题和摘要。必填字段不提供“省略”操作；缺失或未完成时阻止导出。

| 字段分类 | 展示与缺省处理 |
| --- | --- |
| 普通选填字段 | 直接展示控件，不用勾选启用；打开时不生成值 |
| 普通选填字段已有值或未完成输入 | 提供明确“清空（不填写）”操作，移除该字段及未完成输入 |
| 字符串输入 | 用户编辑后保存原字符串，包括空字符串；缺省通过清空操作表达 |
| 数字或 JSON 输入 | 未完成文本仍保留，不把空白或无效值当作默认值；缺省通过清空操作表达 |
| 枚举或布尔选择 | 空选项表示未填写，`false`、`0`、空字符串等合法选项仍保留真实值 |
| 附加功能（指定产物筛选） | 先勾选才展示内容；启用后其内部必填字段标明必填，关闭时移除该功能参数 |

显式 `null` 与缺省分开保留。清除待修正输入是放弃这段输入，不代表必填字段已经满足。

仅当原值无法被控件正常表达时，在字段旁展示待修正的原值与原因。字段标识用于辅助定位，主要标签、选项和说明优先面向普通使用者。

### 参数选项联动

可完整枚举的参数使用当前完整 Schema 推导合法组合，所有下拉框双向联动。对字段 F，候选值只有在保留其他已填写字段后，仍存在一组满足完整 Schema 的参数时才可选择；未填写字段只在计算中尝试可能值，不向草稿写入默认值。以[演示参数类型](capabilities.md#完整示例)为例，已选 `4K` 时帧率只提供 `30`；已选 `60` 帧时分辨率只提供 `1080p`。要换到与已有选择冲突的配置，先清空对应选择，再选择新组合。清空是编辑中的未完成状态，不能导出。

| 状态 | 控件与数据行为 |
| --- | --- |
| 规则可完整枚举，其他已填字段兼容 | 仅展示存在合法补全的选项；选择只写入当前字段 |
| 字段尚未填写 | 展示“请选择”；用全部合法补全计算其他字段选项，不自动选首项 |
| JSON、预设、旧草稿或说明重新加载带来非法值或非法组合 | 保留原值，独立提示问题；非法原值仅用于显示，不作为可选择项；用户可清空或选择兼容值修正 |
| 未完成输入影响组合判断 | 保留原文，暂停相关选项选择；先修正或放弃未完成输入 |
| 完整规则下不存在兼容选项 | 明确显示无兼容选项，引导清空冲突字段或使用参数 JSON，不自动替换其他值 |
| 规则有效但无法可靠枚举，或组合规模超过客户端处理上限 | 明确说明不能生成联动选项，使用 JSON 编辑这些参数并执行完整校验；不把未知解释成无合法组合 |

第一版的自动联动覆盖根对象以 `additionalProperties: false` 封闭、所有属性可由常量、枚举或布尔值限定的参数，包括本地引用和完整 Schema 中的条件、交集、并集、互斥及依赖约束。可选字段的缺省也是一个独立候选。最多检查 4096 个候选组合；超出时使用上述复杂参数入口。非有限字段仍可用普通输入控件编辑，复杂结构通过 JSON 编辑。联动能力不会改变能力说明的加载合法性及后端完整校验。

### 动作折叠

每个动作可独立展开和收起，并提供“全部展开／全部收起”。新加入的动作默认展开。收起时保留动作顺序、名称、类型、执行时间及问题数量，用户无需展开即可识别待修正动作。折叠只是当前页面的显示状态，不写入执行计划，不改变参数、未完成输入或自动保存；展开后恢复原来的编辑内容。删除动作后，其他动作的折叠状态与对应动作一致。

### 动作显示状态与追加接纳

同一草稿页面中的折叠和局部 JSON 模式属于各个动作。局部编辑、明确添加／删除／复制、显式开关及能力派生协调时，存续动作保持自己的显示状态，新动作取得独立状态；删除的动作不把状态留给后续动作。已有可靠身份按身份对应；缺少身份资料时，只有操作中明确保存的添加或删除位置能够证明对应关系。名称、数组长度或内容相等本身不能证明身份。

完整可靠身份资料指结构合法、身份唯一，并且每个当前动作都有对应资料。它与完全没有资料及资料项数不对应是不同状态，下表分别判定追加资格与接纳方式。

仅查看整份 JSON 或取消替换保留表单显示状态；确认整份替换或[整组动作操作](#整组动作替换与移除)后重新建立结构。旧草稿缺少身份资料时，查看、刷新、折叠和普通局部编辑不被动写入身份，也不改变自动预览的“尚未设置”。结构变化无法可靠解释时，页面保留输入、显示具体诊断并提供整份 JSON 修正入口，不先写入再报告对应错误。

从状态同步、计划、动作或产物入口向草稿加入后续动作时，客户端先固定目标草稿、完整已保存版本及明确追加位置。只有确认后端已经保存了该次追加，页面才接纳其结果。接纳表示把这份可靠结果用于当前草稿页面，并保持存续动作状态；它与后端完成追加是不同步骤。

| 操作结果、目标及资料条件 | 页面接纳与恢复 |
| --- | --- |
| 目标尚未可靠创建，或准备期间读取、保存及版本核对未完成 | 保留操作输入、原页面及诊断；不发送本次追加，不生成成功的显示转换。此前已完成的读取或保存仍按实际结果表达。 |
| 动作身份资料存在，但资料项数与原正文动作数不同 | 在形成追加预期前拒绝，说明身份资料与正文不对应；不发出本次追加请求，保留正文、资料、开关及显示状态。不能补齐或清除资料来把此分区变成成功。 |
| 资料结构或身份唯一性无效，或正文无法可靠解释 | 按已有编辑资料和正文资格诊断，不作为一种可成功追加的资料类别。 |
| 追加仍在途、响应未知且核实读取失败，或结果与固定预期冲突 | 保留该次目标、版本、预期、位置和原页面状态；继续核实同一操作，不重复追加。 |
| 已可靠确认本次未追加 | 保留旧动作状态；允许针对同一目标的可靠最新版本重新准备追加，新的预期和位置属于这次新尝试。 |
| 直接确认已追加，或响应未知后由原操作依据确认已追加 | 使用同一接纳流程：固定实际结果并完整检查对应关系，成功后再更新页面、解锁和报告完成。 |
| 当前页面仍打开目标草稿，旧新结构都有完整可靠身份 | 按实际版本中的身份保持存续动作状态，新身份有独立状态；能力派生的增删仍须有可靠版本和身份依据。 |
| 当前页面仍打开目标草稿，完全没有动作身份资料，但本次追加已确认 | 使用该次固定的明确追加位置保持原动作状态，新项默认展开；不被动增加资料或改变尚未设置状态。 |
| 目标不是当前打开的草稿，或本次创建了新草稿 | 仅接纳目标草稿的完整结果；其页面以后打开时独立初始化，不继承其他草稿的折叠或 JSON 模式。 |
| 已确认追加，但实际派生结构无法可靠对应，或页面拒绝接纳 | 保留已追加事实和实际结果，显示接纳诊断；当前本地版本和显示状态不部分改变。恢复只重试对同一结果的本地接纳，不重发追加。 |
| 同一结果、重复观察或轮询再次到达 | 已接纳的版本转换不重复执行，不新增显示身份或副本，不回退到旧版本。 |

上表先判断是否可靠完成追加，再判断当前目标页面与资料条件；不同入口只决定新增动作参数，不另设身份规则。客户端保存草稿的原始数字和未完成输入继续遵守[保存规则](../client/storage-and-recovery.md#草稿预设与原请求的保存)。

## 拍摄参数初始展示与预设

| 参数状态 | 默认展示 |
| --- | --- |
| 尚未填写 `params` | 提示选择设备与参数类型，不打开 JSON，不生成默认参数 |
| 已有对象且匹配参数类型 | 参数表单 |
| 已有对象但类型尚未选择或不可用 | 保留对象，提示选择有效类型，提供 JSON 入口 |
| 已有非对象值或未完成 JSON | 显示原值的 JSON 修正入口，不覆盖输入 |
| 用户主动选择 JSON | 显示同一份参数的 JSON 编辑器 |

拍摄参数预设默认折叠，用户展开后选择、应用或保存预设；折叠不修改参数或预设。

## 时间显示与选择

执行时间输入、动作摘要、草稿更新时间及计划记录中的时间按浏览器当前时区显示。普通界面不显示 UTC 原值或时区转换提示；协议与完整 JSON 仍使用原有 UTC 格式。有效时间仅在用户修改时转换回协议值，浏览、折叠和切换视图不修改保存值。

点击时间输入框的任意位置打开浏览器日期时间选择器，并保留键盘输入能力。浏览器不支持选择器接口时继续使用原生输入。控件无法显示的原值保留，提示无法显示并提供完整计划 JSON 修正入口，不自动清空或用当前时间替换。

## 表单与 JSON 共用参数

两种编辑方式操作同一个拍摄动作的完整 `params`，不分别维护两套可导出参数。JSON 编辑入口显示当前完整对象，包括 `type`，使用同一份能力说明选择规则并执行校验。

从表单进入 JSON 编辑时，使用当前参数生成文本。JSON 已能解析为对象时，其内容成为当前参数，表单据此显示可表达的字段；即使参数未通过 Schema 校验，也保留内容并提示错误。JSON 中修改了 `params.type` 时，类型选择和校验依据同步使用该值，未知类型按输入错误显示。

表单不能完整表达对象中的某些字段时，保留这些字段并提供 JSON 编辑；修改表单中的其他字段不能丢弃它们。切换视图本身不改变字段是否存在、字段值或 JSON 值类型。JSON 的缩进及对象键顺序可以随展示变化，不属于参数业务内容。

尚未完成的 JSON 文本保留在当前编辑状态中，并显示解析错误。该文本修正前，不能用旧的已解析对象覆盖它，也不能导出旧对象冒充当前编辑结果。JSON 对象出现重复键时，同样按输入错误处理。

表单不能提供合适控件与校验器不能解释 Schema 是两种不同情况。前者可通过 JSON 编辑继续使用有效规则；后者遵守[能力说明加载失败规则](camera-capabilities.md#客户端加载能力说明)，不能绕过校验生成计划。

## 拍摄视频大小估算

普通录像和延时摄影的参数编辑区域共用一份只读估算。客户端从当前动作的设备、动作类型和参数类型精确取得已启用规则，再读取完整当前参数；表单和参数 JSON 不维护各自的估算缓存。元数据格式见[参数类型的视频大小估算](capabilities.md#参数类型的视频大小估算)，计算公式、单位和有序状态分类见[视频大小估算设计](../superpowers/specs/2026-10-10-video-size-estimate-design.md#估算资格与状态分类)，页面呈现见[拍摄视频大小提示](../client/page-interactions.md#拍摄视频大小提示)。

未完成输入覆盖计划根、动作集合、当前动作、选择字段或当前参数时，客户端保留原文并撤下有效数值，不读取上次解析值代替当前输入。路径无法可靠解释时暂停估算并显示范围诊断。其他动作及无关公共字段的输入问题不遮蔽当前估算，整份计划仍按各自规则校验。可选参数省略、显式值无效及查表不覆盖分别表达，不补 Schema 默认值，也不选择其他档位。

### 重载与完整状态观察

客户端先暂停估算，等待已发出的状态读取结束并保存编辑会话，再发出重载请求。状态观察指一次完整状态读取所返回的实际启用说明、加载诊断和草稿；页面及会话共同接纳这一组事实，不拼接不同读取中的成员。较旧成功观察不覆盖较新成功观察；更晚的读取失败不使此前成功观察失效。业务操作继续根据自身读取返回的原观察判定保存、导出、删除或追加结果，读取成功本身不代表这些操作成功。

估算暂停与恢复遵守批准设计的[能力加载与页面更新](../superpowers/specs/2026-10-10-video-size-estimate-design.md#能力加载与页面更新)。下表归纳客户端重载准备和核实期间的操作结果。

| 起点与实际事件 | 估算状态与恢复 |
| --- | --- |
| 没有待核实责任，准备保存或状态读取失败，尚未发重载请求 | 结束本次准备，按原能力观察及保留输入重新计算，同时报告准备失败。 |
| 已有结果待核实责任，再次准备失败，尚未发新重载请求 | 保留前次待核实责任和请求已结束的事实，继续暂停；随后新发的合格成功观察仍可恢复。 |
| 正在准备、请求在途或等待请求结束后的观察 | 暂停数值；准备期间发起的观察不能解除暂停。 |
| 重载请求已经发出，但响应或后续读取未取得 | 保留输入与实际已知说明，结果继续待核实，不补造重载成功。 |
| 请求结束后新发的合格完整状态观察成功 | 共同接纳实际启用说明、加载诊断及草稿，再按当前输入恢复；无需能力版本发生变化。 |
| 待核实期间读取再次失败，或只有请求结束前发起的观察返回 | 继续暂停，保留核实责任。 |
| 合格观察已经确认结果后，另一读取失败 | 报告该读取错误，不重新建立已完成的重载核实责任。 |

所有完整状态读取共用发起资格与接纳次序，包括刷新、保存和导出核实、删除核实、导出记录读取、递交标记、上传失败核实、后续动作准备与核实及查看目标。加载失败而保留旧说明时，估算显示此前说明提示；失败文件中的字段不启用。能力不可用、自动预览协调和导出限制继续遵守[加载结果与现有数据](client-deployment.md#加载结果与现有数据)。

估算显示、折叠、模式切换和计算本身不修改或保存输入，不改变自动预览开关及派生动作。估算不进入计划、生效参数或报告。合法能力说明缺少估算信息、引用当前缺省值或查表没有覆盖当前合法选项时，估算不增加导出限制；非法估算声明仍使整份能力加载失败。

## 校验与导出

对于包含拍摄动作的新计划，按下表从上到下判断当前参数编辑结果。每一行均以不满足前面行的条件为前提：

| 当前条件 | 反馈与后续行为 |
| --- | --- |
| 控件输入尚未形成有效 JSON 值，或 JSON 文本存在语法错误、重复键 | 保留当前输入并指出问题；不导出计划，不使用旧值代替 |
| JSON 有效，但拍摄 `params` 不是对象 | 提示参数必须是对象，保留内容供修正；不导出计划 |
| 参数为对象，但能力说明不可用，或设备、动作、参数类型无法匹配有效规则 | 区分说明加载错误与选择错误；保留参数供修正，不导出该计划 |
| 匹配规则有效，但参数不符合 Schema | 提示对应动作、字段或组合错误；允许继续通过表单或 JSON 修改，不导出计划 |
| 参数符合规则 | 参数校验通过；整份计划还须通过公共字段、业务条件及客户端后端的导出前校验 |

以上参数规则仅应用于拍摄动作。没有拍摄动作的计划按自身动作契约校验，例如空设备目录下仍可准备和导出合法的 `report_status` 计划。

浏览器负责即时反馈，后端校验实际准备导出的最新完整计划，不根据浏览器先前的通过提示或旧的草稿值直接导出。两处使用同一份已启用的规则及既定校验配置。校验器不自动转换类型、删除字段或填入默认值；例如 JSON 中的 `"30"` 不能因字段要求整数而变成 `30`。

输入错误应定位到对应动作及字段；组合错误还应说明相互约束的参数，帮助用户作出修改。草稿可以处于未完成或非法状态，导出成功才表示当前内容已完成客户端校验；它不表示 camctl 已受理、设备在线或计划已经执行。

## 验收要求

- 使用能力说明中的演示类型，验证逐级选择、名称与单位显示、普通字段控件以及只填写类型的固定任务。
- 验证合法参数可通过两种编辑方式得到相同的参数对象；切换视图保留字段缺省、显式值和 JSON 值类型。
- 在表单中验证参数双向联动、缺省时的合法补全及清空后重新选择；JSON 或预设带入非法组合时，验证原值保留、能定位原因且不会自动替换。JSON 中的数值字符串保持字符串并按规则报错。
- 验证必填标签一致，普通选填字段直接显示，字符串选项不带 JSON 引号，清空选填字段不混淆缺省与显式值；指定产物筛选仍按来源与勾选状态展示。
- 验证多动作的单独及全部折叠、收起后的错误提示、添加和删除动作后的状态对应，以及未完成输入在折叠和展开后保留。
- 编辑表单无法表达的参数及额外字段，验证通过 JSON 仍能修正；切换视图或修改其他字段不丢失原内容。
- 从有效参数进入未完成、不可解析、重复键或非对象输入，验证保留当前内容、阻止导出且不回退导出旧值；修正后重新校验。
- 分别验证规则有效但表单不支持、参数不符合规则、规则本身不可用，保持三者的处理区别。
- 验证浏览器提示通过后，后端仍校验此次导出的完整计划；其他公共字段有误时不能仅凭参数通过而导出。
