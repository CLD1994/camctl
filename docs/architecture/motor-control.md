# 电机控制动作

[返回设计总览](README.md) · [计划输入](plan-input.md#第一版动作入口) · [主程序通知协议](../../protocol/host-notifications.md)

`motor_control` 在计划指定的有效时间窗口内，向 TX2 主程序发送一条位置控制通知。camctl 负责受理、调度、持久化和报告；camctl host 解析通知，调用主程序注册的电机控制函数；主程序解释位置的单位、业务合法范围并执行实际控制。

通信为单向通知。动作成功表示完整通知已写入通信通道，不证明 host 已调用回调、主程序已接受位置或电机已到位。发送结果不确定时不重发。实现与机器定义的接入进度见[实施路线图](../superpowers/plans/2026-09-30-camctl-implementation-roadmap.md#电机控制与主程序通知接入)。

## 输入与受理

公共字段遵守[执行计划输入契约](plan-input.md)。本动作的 `params` 只包含整数 `position`；字段表示及 C `int` 转换边界由[通知协议的电机参数](../../protocol/host-notifications.md#电机参数)统一定义。客户端、camctl 与 host 使用同一结构规则，均不推导位置单位、零点或设备的业务合法范围。

| 字段 | 契约 |
| --- | --- |
| `type` | 必须为 `motor_control` |
| `name` | 必填，遵守公共名称及计划内唯一性规则 |
| `scheduled_at` | 必填，使用公共 UTC 时间格式 |
| `policy` | 必填，只包含必填的非负整数 `max_delay_ms`，范围沿用公共非负整数定义 |
| `params` | 必填，遵守电机参数结构 |
| `device_id` | 必须省略；实际电机由主程序注册的回调确定 |
| `group` | 可省略；提供时遵守公共组名规则 |

首次受理使用公共的整份拒绝与单动作失败分类。动作自身字段错误使该动作初始为 `failed`，不发送通知；原始参数及错误按公共规则保存。合法受理固定原始参数和时间策略，后续执行、请求重送及恢复不重新解释位置。主程序是否已注册回调属于执行条件，不在 `submit` 中通过发送通知检查。

电机控制不建立相机驱动绑定，不使用拍摄能力说明或拍摄参数类型，不产生正式产物。按组取回时不将电机动作作为产物来源。动作在同一计划中的排列不建立“电机到位后再拍摄”的依赖；单向通知没有可用于这种依赖的到位证据。

## 调度与发送边界

发送窗口为 `scheduled_at <= trusted_wall_now <= scheduled_at + max_delay_ms`，两端均包含。时间格式、可信墙钟、唤醒和过期原因沿用[公共调度](scheduling-execution.md)。窗口约束 camctl 开始发送通知的时刻，不约束 host 调用回调的时刻或电机运动的完成时刻。

只有正常 `run` 执行电机通知；`submit` 只受理。时钟不可信时不开始发送。未来仍待执行的电机动作参与会话驻留和新计划接管判断。电机通知不占用相机驱动的通信或拍摄资源。

取得执行资格后，camctl 先可靠保存唯一发送意图，再检查时间、取消和本次发送资格，随后使用[主程序通知通道](../../protocol/host-notifications.md#通道与生命周期)。只有创建该意图的本次执行流程可以继续发送；恢复流程不能把已存在但没有结果的意图当作新的发送许可。意图提交失败或提交结果未知时不发送，先按状态库契约核实。

最后检查发现墙钟失去可信性或其他公共执行前提失效时，不开始发送，按对应会话规则处理。在中断前未能可靠保存未发送结论时，恢复仍使用下面的发送结果不确定分区，不能以推测补造未发送事实。

一个动作只安排一次通知发送尝试。发送失败不进入相机通信重试，host 的进程重启也不为该动作增加发送机会。完整消息写入后保存发送结果；结果与动作终态、父计划状态和对应历史在同一事务内提交。

## 状态判断与恢复

下面按顺序判定。状态库读取、提交或事实一致性失效时，先按状态库错误处理，不执行表中的业务推断。表中的“可靠未发送”必须有当前执行流程或已保存事实作为依据，不能由“没有成功记录”推导。

| 动作与发送事实 | 时间或其他条件 | 处理与可观察结果 |
| --- | --- | --- |
| 动作已有终态 | 任意 | 保留终态，不发送 |
| 恢复时存在发送意图，没有可靠的发送结果或未发送结论 | 任意，包括窗口已结束 | 以 `failed` 结束，说明发送结果不确定，不重发，不伪装为过期或取消 |
| 没有发送意图，或本次流程能够可靠证明尚未进入发送 | 取消已可靠生效 | 结束为 `canceled`，不发送 |
| 没有发送意图，尚未执行 | 时间早于 `scheduled_at` | 保持待执行，按公共唤醒规则等待 |
| 没有发送意图，或本次流程在最后检查时可靠确认未发送 | 时间超过窗口末端 | 结束为 `expired`，按首次窗口观察确定过期原因 |
| 没有发送意图 | 时间在窗口内，通知通道不可用 | 结束为 `failed`，说明通知通道不可用，不发送 |
| 没有发送意图 | 时间在窗口内，通道可用且无生效取消 | 保存发送意图，最后检查资格，通过后发起发送 |
| 本次流程持有已提交的发送意图，尚未进入发送 | 最后检查发现取消或窗口结束 | 保存可靠未发送结论，与对应的 `canceled` 或 `expired` 终态一起提交 |
| 本次发送明确失败 | 包括无法写入完整消息 | 结束为 `failed`，保留实际步骤和错误，不再发送 |
| 本次完整消息已写入通道 | 结果可以可靠保存 | 结束为 `succeeded`；成功含义仅为通知已发送 |
| 本次完整消息已写入，结果保存失败或提交未知 | 状态库无法可靠确认 | 按状态库错误处理，不再发送；后续根据可靠持久化结果进入已有终态或发送结果不确定分支 |

发送意图已保存、但进程尚未真正写入消息就中断，也属于恢复时无法确认是否发送的分区。该动作不重发，可能因此没有触发实际电机控制。这是本动作选择的不重发语义。

## 取消

取消入口继续支持计划、动作、组及请求 ID，按[公共取消寻址](task-cancellation.md)逐项处理。在同一动作的执行协调边界内串行决定取消生效与开始发送，不能依据过时的“尚未发送”观察取消已经进入发送的动作。

| 目标事实 | 本次取消结果 |
| --- | --- |
| 已有终态 | 保留终态，按公共规则表达目标已结束 |
| 可靠确认尚未开始发送 | 允许取消；可靠保存后禁止发送 |
| 正在发送，或无法排除通知已经发送 | 本次逐项取消失败，说明不支持撤回；目标沿原发送或恢复流程结束 |

host 不从回调队列中撤销已经接收的控制通知。回调没有停止或撤回含义，camctl 不因取消协程、关闭管道或结束 CLI 进程而宣称电机停止。

## 持久化与报告

持久化须区分尚无发送意图、意图已保存但结果不确定、可靠未发送、完整写入和明确写入失败。普通动作状态不能替代发送事实。发送事实随动作永久保留，与当前投影在同一事务内写入不可变历史；历史回放只恢复事实，不写管道、不调用主程序。

发送意图和结果由可独立更新的专属记录保存，首次确定的参数继续属于动作输入，不在只读执行定义中修改发送进度。具体表、列、整数编号及历史事件按[数据库存储分工](../camctl/database/common.md#普通列子表与-json-的分工)接入；记录缺失与结果未知不能合并处理。

报告提供公共动作字段、原始 `input_params`、`policy`、状态及适用的错误或过期原因。电机动作不提供 `effective_params`、正式产物、交付或 `device_execution`，也不补造实际位置、回调执行结果或电机运动状态。发送成功使用公共 `succeeded`，不另建与该状态重复的成功结果字段；客户端将其解释为“控制通知已发送”。

运行失败须分别说明通道不可用、发送明确失败和恢复时发送结果不确定。错误在机器协议中按独立原因登记，客户端能够区分；具体公共错误码及数据库编号随接入在权威登记中确定，不在本专题另建编号清单。错误不影响其他满足条件的普通动作；状态库等公共执行前提失效仍按会话错误规则处理。

## 验收要求

- 单元测试覆盖输入合法、缺失、非整数、整数表示边界及额外字段；以状态表推导发送、过期、取消和恢复分支。业务位置超出主程序自身允许范围不能被 camctl 擅自更正。
- 在窗口开始前、恰好开始、窗口末端及末端之后检查发送次数；最后资格检查发现窗口结束时不写通道。
- 组合真实受理入口、SQLite、CLI、host 和记录调用参数的主程序替身，验证只向回调传入一个 `int position`，消息写入与回调执行分别观察。
- 在意图提交前后、消息写入前后及结果提交前后安排受控中断。分别证明未保存意图的待执行动作仍按时间资格处理，已有不确定意图的动作恢复后零次重发，成功终态及同请求重送不再发送。
- 组合 `run`、`submit`、相机动作、未来动作、取消及报告维护，验证接管、会话退出和其他动作不会遗漏；失败后的报告能区分过期、明确发送失败和发送结果不确定。
- 历史回放、报告重建及客户端再次导入均不得发送电机通知。实际电机运动与主程序业务范围验证另行联调，不作为软件集成测试的运行前提。
