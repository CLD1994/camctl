# camctl 更新能力与主程序接入

camctl 负责自身的离线软件更新、数据库迁移、失败回滚和中断恢复。更新实现及其构建资源属于 `apps/camctl`，由 camctl wheel 交付。部署工具负责构建交付物并调用组件的安装入口。

## 更新交付与独立入口

Python 专用更新包只包含 camctl wheel、锁定依赖、适用目标架构的离线 wheel，以及版本、来源和完整摘要信息。它不携带主程序或客户端。组件更新器校验完整文件集合、摘要、平台与版本后才开始本次更新；不联网安装依赖。

wheel 内提供仅依赖标准库的维护引擎。部署时，camctl 的发布逻辑在原虚拟环境外建立稳定维护入口，绑定安装根目录和基础 CPython 3.11。主程序通过显式 `updater_path` 定位该入口，不从任意 `camctl_path` 猜测安装根目录或基础解释器。普通 camctl 命令和维护入口使用一致的配置来源；显式配置仍由 `--config` 传递。

新部署在安装 wheel 后准备维护入口。已有部署首次接入时，从新 wheel 的维护资源准备入口，再开始原环境更新；不能通过先替换原 wheel 来取得更新能力。资源和绑定信息先可靠保存，最后发布可执行入口。普通 wheel 安装不等于已经准备了某个部署的维护入口。

稳定入口先处理未完成更新，再解释新的更新包。每个事务在修改前可靠冻结自己的维护引擎及摘要；恢复只运行该事务的引擎。修改原虚拟环境、恢复旧软件或接收后续更新包，都不能改变仍在执行的引擎。引导路由契约稳定，普通软件更新不改写稳定入口；需要改变引导契约时单独维护其发布与恢复能力。

原虚拟环境路径、V9 数据库维护起点、备份、文件归属、残留写入者、可靠完成点和错误诊断遵守[组件版本与软件更新](versioning-and-updates.md)。恢复过程中不能依赖原虚拟环境仍可导入。

## 主程序接口

`camctl_host.h` 提供阻塞式更新接口。接口接收显式配置、维护请求和调用方持有的结果对象，不依赖模块已经初始化。请求表达应用指定更新包或只恢复未完成事务；适用时指定客户端能力同步目标。接口只控制本模块拥有的普通业务进程，不声称其他独立 host 或 CLI 已停止。

| 模块状态或输入 | 更新接口行为 |
| --- | --- |
| 基本参数非法，或工作线程、回调线程调用会等待自身的维护 | 拒绝本次调用，不进入更新；交付实际参数错误或死锁错误。 |
| 同一进程已有更新调用 | 拒绝第二个维护请求，不自动排队或重试整次更新。 |
| 尚未初始化 | 使用传入的维护配置执行，不先启动普通 camctl。 |
| 正在运行或停止中 | 核对与当前实例的维护配置一致，停止接纳新工作，沿现有停止流程等待提交、领取、进程组、输出、回调、诊断及在途调用收场，然后维护。 |
| 已经停止 | 直接维护，不重新初始化。 |
| 更新成功、原环境未修改或回滚已核实 | 返回实际结果，保持停止，由主程序重启。 |
| 收场失败、仍有恢复责任或结果未知 | 保持停止和诊断责任，不启动普通业务。 |

初始化、停止与更新在同一进程协调。更新不能把自己计入普通在途调用后再等待该计数归零；其他线程的停止不能提前报告更新写入者已经结束。接受维护后不自动重建工作线程，也不自动重试整次软件更新。

配置了 `updater_path` 时，`camctl_host_init` 在启动任何原虚拟环境进程前，通过稳定入口做只读启动资格检查。存在未完成更新、原写入者仍占用资格或结果不能核实时，拒绝启动；主程序可以先调用维护接口完成恢复。该检查不通过执行原 `venv/bin/camctl --version` 探测。

## 机器结果与诊断

维护的参数、stdout 及退出状态组合由根 `protocol` 的软件更新协议统一定义；C 与 Python 从同一来源读取或生成。更新结果独立于 `run`、`submit` 的业务会话结果和有限重试。

| 可观察结果 | 调用方可认定的事实 |
| --- | --- |
| 请求未开始执行 | 仅本次维护未开始，不能据此断言不存在上次遗留责任。 |
| 新版本可靠提交 | 本次应用成功。 |
| 原部署确认未修改 | 没有开始修改本次部署。 |
| 原环境已核实恢复 | 目标更新未完成，原部署可供后续重启。 |
| 仍需恢复 | 存在未完成责任，继续保持停机。 |
| 结果缺失、非法、信号退出或相互矛盾 | 结果未知，不解释为已经回滚。 |

stdout 只输出一份机器结果，诊断交给 stderr 和更新日志。结果保留收据或诊断路径以及实际阶段；完整异常、原始工具输出与收场错误仍由 camctl 维护流程保存。C 的有界捕获保留截断事实，不能替代完整更新日志。必要收场不等待诊断通道，诊断失败不能撤销可靠完成结果。
