# camctl 更新能力与主程序接入

camctl 负责自身的离线安装、数据库迁移、失败回滚和中断恢复。C 接入模块负责停止本模块的普通工作、调用环境外的维护入口，并在允许启动后自动建立新的普通运行周期。主程序只提交更新包并判断调用是否成功。版本、备份和强制重建的规则由[组件版本与软件更新](versioning-and-updates.md)定义；发布与现场操作见[更新操作说明](../camctl/software-updates.md)。

## 交付物与环境外的维护入口

Python 专用更新包交付 `camctl-update.zip`，包含 camctl wheel、锁定依赖、两种目标架构的离线 wheel 和经过摘要核验的元数据。也可提供已解压目录。组件校验完整文件集合、摘要、平台、发行版本及更新模式，不联网安装依赖。强制标志及完整新配置属于包内容，不能由主程序传入另一组未经包校验的清理指令。

wheel 提供仅依赖标准库的维护引擎。组件发布器在原虚拟环境外建立稳定维护入口，绑定部署目录、普通可执行文件和独立的基础 CPython 3.11。`updater_path` 由部署入口显式提供；host 不解析 TOML，也不根据任意 `camctl_path` 猜测部署目录。基础解释器、维护入口、未完成事务的冻结引擎和完整备份在环境重建期间保持可用。

新部署在安装和显式初始化后发布维护入口。已有部署首次接入时，从新 wheel 的资源发布入口，不能先替换原 wheel 来取得更新能力。发布须核对目标绑定，可靠保存资源后才发布可执行入口；未完成事务存在时不得替换其恢复入口。已有更新责任始终先由该事务可靠冻结的引擎处理，不能用后来的更新包替代原恢复程序。普通更新不改写稳定入口。

配置来源保持与普通 CLI 一致：显式来源使用实际 `config_path`，默认来源由运行账户解析；配置不存在时使用内置默认值。更新记录保存来源模式、有效路径、原有存在事实及内容身份。未完成事务使用记录中的来源恢复，不根据当前配置重新推导原数据库或目录。

## 主程序接口

公开入口为：

```c
int camctl_host_update(const char *bundle_path,
                       const char *client_data_path);
```

接口使用已成功初始化实例保存的配置、回调和维护入口。`bundle_path` 是 ZIP 或已解压目录的绝对路径；`client_data_path` 可为 `NULL`，指定时同步能力说明并将该文件纳入事务。接口阻塞至本次维护和适用的普通资源重建完成。恢复动作、维护结果结构和重新运行入口均由组件内部使用，主程序无需解释维护状态或选择恢复分支。

返回 `0` 表示本次新包已经可靠提交，且普通资源已重建、首次 `run` 已安排。返回 `-1` 表示本次更新流程未成功，`errno` 保留实际本地错误或相应的更新失败；失败详情直接交付到 `processing` 的独立诊断文件。原部署恢复成功仍属于本次更新失败。运行安排的成功含义与 `camctl_host_init` 一致，不代表相机操作或完整业务验收已经成功。

| 输入或实例状态 | 处理 |
| --- | --- |
| 参数非法、未初始化或未配置稳定维护入口 | 修改部署及停止普通业务之前拒绝。已知实例的失败使用其诊断路径；没有实例配置时交付实际本地错误，不猜测 `processing`。 |
| 模块工作线程或回调线程调用 | 返回 `EDEADLK`，避免等待自身。 |
| 已有维护、正在构造新实例或存在未收场候选资源 | 返回 `EBUSY`，不并行维护、不自动排队。 |
| 普通实例正在运行或停止中 | 停止接纳新工作，沿共同停止边界确认提交、领取、进程组、输出、回调、诊断和在途借用收场，再维护。 |
| 普通实例已经可靠停止 | 使用保存的配置执行维护，满足启动资格后自动建立新的普通运行周期。 |

更新不重送首次计划，也不重新提交已取消返回的内存请求。新运行周期从数据库恢复已保存业务，重新建立有限重试预算、队列和子进程管理状态。注册的回调保持有效。

### 生命周期所有权与并发停止

一个内部维护负责人持有从停止、应用、必要恢复到重新运行的完整责任。普通调用不能在这些阶段插入新任务；负责人可以执行自己持有许可的停止和重建，不能被自己的维护标志拒绝。

外部显式停止与更新按同一生命周期状态协调。更新重建前接受到的外部停止意图最终保持停止，更新不重新启动业务，并以失败及 `ECANCELED` 交付这次自动运行被取消的事实；新包已经可靠提交时保留提交结果。新运行周期已经发布后接受的停止，沿正常停止流程收场。不能让停止调用等待维护结束、维护又等待这些停止调用退出而形成互等。

旧实例的所有停止观察者和在途借用退出后才能释放其内存。重建失败时，已创建但尚未确认结束的线程、描述符和候选实例保留实际管理责任；不能只换回旧指针就认定已经可靠停止。资源清理继续执行必要步骤，清理错误独立诊断，不覆盖原失败。

## 普通启动自动恢复

配置了 `updater_path` 时，`camctl_host_init` 在执行任何原虚拟环境程序之前调用稳定入口内部恢复，包括普通主机重启后的第一次初始化。入口先取得更新资格，检查持久记录；存在未完成事务时先恢复并核验，没有未完成责任时确认允许启动。原环境不能导入、配置已被强制更新替换或数据库已部分发布，都不能使恢复依赖这些新对象。

| 已确认的部署事实 | 普通启动或更新后的内部行为 |
| --- | --- |
| 没有未完成更新，或终态已经可靠确认 | 建立普通资源并安排 `run`。 |
| 更新在修改前失败，原部署确认未改变 | 自动恢复普通运行，本次更新返回失败。 |
| 更新失败，原环境和原数据全部核实恢复 | 自动恢复原版本普通运行，本次更新返回失败。 |
| 应用结果缺失、非法、信号退出或不能确认 | 完成维护进程组收场，再通过稳定入口恢复；核实允许启动后恢复普通运行，本次应用仍返回失败。 |
| 事务在更新或回滚期间中断 | 按原冻结记录继续恢复；全部恢复并可靠记录后再启动。恢复本身可以再次中断。 |
| 仍有维护写入者、恢复未完成或资格未知 | 保留恢复责任及诊断，不执行可能部分安装的环境；后续普通启动继续同一恢复路径。 |

维护检查、恢复和安装进程继续遵守主程序的 `SIGCHLD` 回收分工。环境更新资格覆盖真实安装和迁移写入者，父进程退出不能代替写入者已经结束。模块不修改主程序的全局信号处置，不终止其他独立 host 或 CLI。

## 私有机器结果

维护进程的参数、JSON 和退出状态由根 `protocol` 的软件更新协议统一维护；Python 和 C 从该来源读取或生成。主程序的成功或失败接口不削减组件内部需要的事实。

内部至少分别保留本次应用结论、部署效果、启动资格和普通资源状态。未开始、未修改、可靠提交、核实恢复、仍需恢复和未知不能合并；允许启动不表示本次更新成功，进程退出零也不能替代可信结果和持久终态核验。原应用失败与后续恢复失败各自保存，不互相覆盖。

路由先恢复旧事务、再应用新包时，内部接收两阶段结果，公共 stdout 仍只有一份完整机器结果。stdout 缺失、截断、多份、非法或与退出事实矛盾时保留未知；仅 stderr 截断不撤销可信结果，但必须保留截断事实。原始字节按长度保存，不能以 C 字符串截去 NUL 后面的内容。

## 更新诊断直接交付

本次更新失败、启动恢复实际执行、维护资格未允许、结果不可信，或者维护及重建出现错误时，结果消费者准备一份独立诊断，直接原子发布到本实例 `processing` 根目录。主程序按照普通待传文件处理，无需下一次 `claim`，也无需读取返回结构。

诊断包含以下实际事实：更新包及配置来源、发生阶段、本次应用结论、后续恢复结论、普通重建结果；维护调用的原始 stdout、stderr 和进程诊断及其长度、已读量、截断和读取错误；实际 PID/PGID、工作目录、启动 errno、退出码或信号及其已知状态。未取得的事实明确保持未知。原更新引擎记录的异常及工具失败内容须随诊断交付，不能仅提供远端无法读取的本地收据路径。更新日志和收据仍留在部署的更新证据目录。

启动恢复的诊断可以使用原事务可靠保存的日志和收据说明中断及恢复过程；不能编造已经丢失的旧进程输出。多个实际失败可以在同一份本次维护诊断中关联，重复等待不为同一结果生成多份诊断。

维护诊断使用不依赖普通日志及 writer 线程存活的发布边界。先冻结结果并完成必要恢复和适用的普通重建，再在生命周期互斥之外交付；诊断通道阻塞或失败不能阻挡必要停止、恢复或已经安排的普通工作，也不能改变可靠提交和公开返回结论。

发布在 `processing` 内的隐藏准备目录完成：写完并同步完整文件、关闭文件后，以不覆盖既有文件的原子重命名发布到根目录，再同步相关目录。每次维护使用唯一身份，复用同一结果的发布状态。发布前失败保留已经准备好的完整材料和实际进度；改名已经成功但目录同步失败时保留原文件，不撤回或另写重复诊断。尚未完成的准备材料不作为待传文件暴露。传输后的删除及再次发送仍由主程序负责，诊断机制不推断远端已经收到。


强制更新可靠提交后，组件在普通运行已经安排后非阻塞启动旧环境归档。它是内部维护任务，主程序接口和返回结构不增加归档状态。组件负责该进程及其输出和停止收场；归档中断由下次普通启动继续。压缩包的内容、媒体排除、可靠发布及提交后清理规则见[旧环境归档](versioning-and-updates.md#强制重建后的旧环境归档)。
