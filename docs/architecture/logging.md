# 运行日志

[返回设计总览](README.md) · [请求受理与会话](protocol-session.md) · [阅读路线](reading-guide.md)

本专题定义普通运行日志的保留与通道故障处理，并提供日志副本交付的入口。camctl 自身与第三方日志共用[按级别接纳的策略](../camctl/logging-runtime.md#日志异步投递入口与有界队列)，来源只影响重要日志满载时是否允许丢弃。CLI 的 stdout 结果、stderr 诊断及退出状态由[进程结果协议](cli-commands.md#stdout-与退出状态)定义。

**阅读提示：** 运行日志用于近期排查问题，永久业务历史保存在数据库。普通日志在本地轮换；报告首次失败时准备一份日志副本，交给主程序传输。普通日志与日志副本分别遵守[本地轮换](#文件轮换)和[副本交付](log-delivery.md)规则。

## 日志用途

普通运行日志用于排查近期运行问题。计划受理、动作结果、设备恢复证据及报告重建依据仍按[持久化规则](system-foundations.md#持久化与配置基础)写入数据库并永久保留；这些事实不能只写日志而不保存到状态库。

业务恢复与报告重建依据数据库历史，日志轮换或删除不会删除业务历史。日志文件不登记为正式产物、delivery 或状态报告。

## 配置与默认值

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `paths.log_file` | `$HOME/.camctl/camctl.log` | 正在写入的日志文件 |
| `session.log_level` | `WARNING` | 日志级别 |
| `session.log_max_size` | `"10 MiB"` | 单文件轮换阈值，按文件字节数判断 |
| `session.log_file_count` | `3` | 保留文件总数，包含正在写入的文件 |
| `session.log_queue_capacity` | `1000` | 每个进程日志队列允许等待的最大记录条数 |
| `session.log_queue_low_watermark` | `700` | 第一水位，达到后停止接纳 `DEBUG`，对 `INFO` 采样 |
| `session.log_queue_high_watermark` | `800` | 第二水位，达到后停止接纳 `INFO`，剩余位置供警告和错误使用 |
| `session.log_info_sample_probability` | `0.1` | 两个水位之间每条 `INFO` 独立被选中的概率，默认值表示 10% |

轮换阈值遵守[容量配置的表示](configuration.md#容量配置的表示)，换算后须为大于等于 1 的整数个字节。文件总数须为大于等于 1 的整数；0、负数、布尔值及其他错误类型属于本地配置错误。配置文件可省略这些字段，按[默认值与覆盖规则](configuration.md#本地配置的加载与更新)处理。配置更新后，后续进程使用新值；日志策略属于会话配置，不作为动作执行预算固化。

队列容量与两个水位均为正整数，按条数配置，不使用字节容量字符串；完整生效配置须满足 `0 < log_queue_low_watermark < log_queue_high_watermark < log_queue_capacity`。采样概率使用有限数值，合法范围为闭区间 `[0, 1]`：0 表示采样区间内全部省略 `INFO`，1 表示该区间内全部选中。布尔值、错误类型、非有限概率及不满足范围或组合关系的值均属于本地配置错误；不自动修正水位或随容量缩放。省略字段先补默认值，再校验整组配置。

第一版的实际部署保证日志级别能够接纳 `ERROR` 及以上记录。

这些参数可在部署时分别调整，每个进程启动时读取并在本次运行内固定；报告子进程使用主进程传入的生效配置，各进程独立计算队列条数。默认值是用于联调的初始工程取值，不代表已经测得固定内存占用或日志吞吐保证；实际资源占用还取决于记录大小和待投递协程。接纳与采样的完整行为由[水位规则](../camctl/logging-runtime.md#日志按水位接纳并顺序消费)定义。

## 日志接纳与退出

队列采用[按水位接纳并顺序消费](../camctl/logging-runtime.md#日志按水位接纳并顺序消费)：积压增加时逐步限制 `DEBUG` 和 `INFO`，为警告和错误保留接纳空间；已入队记录按顺序处理，不因后来的高级别日志而淘汰。

因水位、采样或满载而省略的记录按级别计数，正常退出时按[丢弃汇总规则](../camctl/logging-runtime.md#日志丢弃计数与退出汇总)最多写一条 `WARNING` 摘要。被配置级别正常过滤的记录不计入；摘要遵守当前日志级别，突然终止时不保证保存计数或摘要。

自身重要日志等待入队时，取消不撤销投递责任；所属协程确认入队或按通道禁用规则结束投递后再最终结束。必要业务停止独立推进，具体边界和正常退出顺序见[重要日志等待期间的取消与退出](../camctl/logging-runtime.md#重要日志等待期间的取消与退出)。

## 文件轮换

当前文件使用 `paths.log_file`。归档文件在该路径后追加数字后缀，`.1` 是最近一份，数字越大表示越旧。按默认配置，正常保留的文件为：

```text
$HOME/.camctl/
    camctl.log
    camctl.log.1
    camctl.log.2
```

设换算为字节数的轮换阈值为 `B`，保留总数为 `N`。处理一条日志前，先按表判断；只有配置合法且相关文件操作可以完成时，才适用表中的正常结果。

| 当前文件状态 | 处理 |
| --- | --- |
| 当前文件不存在 | 创建当前文件并写入本条日志，不因缺少当前文件而清空已有归档 |
| 当前文件大小小于 `B` | 向当前文件追加本条日志 |
| 当前文件大小大于等于 `B`，且 `N = 1` | 轮换时淘汰旧内容，只保留新当前文件并写入本条日志 |
| 当前文件大小大于等于 `B`，且 `N > 1` | 将当前文件转为最近归档，已有归档依次后移，删除超过 `N - 1` 份的最旧归档，再写入新当前文件 |

阈值按一条完整日志写入后的大小判断，因此跨过阈值的那条日志可以使文件略大于 `B`；下一条写入前轮换，不为凑齐阈值截断诊断内容。重启沿用已有文件的实际大小与归档顺序，不重新累计一套进程内文件额度。

将保留数量调小时，下一次写入前清理本机制管理的超限旧归档，使正常完成后的文件总数符合新值。清理范围仅为所配置日志路径对应的归档文件，不扩大到其他目录、状态库或业务文件。

## 多进程共用

相同日志路径对应一组文件和一个保留上限；并发运行的 `run`、`submit` 共用这组文件，而不是每个进程各保留 `N` 份。

追加与轮换须在所有写入进程之间协调，避免某个进程移动归档时另一个进程仍把新日志写进旧文件。一次正常完成的写入追加到当前文件，轮换后保持上述归档顺序及数量上限；不能仅以进程内互斥保护多个进程共享的日志路径。

第一版采用[普通日志执行与多进程轮换方案](../camctl/logging-runtime.md#普通日志执行与多进程轮换)：各进程使用 `janus` 有界队列连接日志投递入口与专用 `QueueListener` 日志线程，由 `concurrent-log-handler` 的 `ConcurrentRotatingFileHandler` 通过文件锁协调共享文件的追加与轮换。协程使用可等待入口，同步来源经 `QueueHandler` 及接纳适配进入同一队列；接口语义与分级目标见[日志异步投递入口与有界队列](../camctl/logging-runtime.md#日志异步投递入口与有界队列)。各进程独立管理自身生命周期，使用同一路径及一致的轮换配置；一个进程退出不关闭其他进程的日志通道。

## 日志通道故障

普通文件日志是辅助诊断通道。在配置已经合法的前提下，日志目录或文件无法创建、打开、追加、刷新或轮换，均不单独导致会话失败，也不触发录像应急停止。仅为写日志而使用的进程间协调失败，同样按日志通道故障处理，不扩大为会话排他或接纳资格失效。

轮换失败时，只要进程间写入协调仍然有效且当前日志文件可以追加，就继续记录日志。故障期间文件可能超过轮换大小，归档数量与顺序以实际成功的操作为准；后续日志仍按正常流程尝试追加与适用轮换，不为本条日志反复重试轮换。首次识别轮换故障时，向可用的 stderr 提示一次实际已知的路径、操作和原因，重复故障不反复提示。

无法创建、打开、追加或刷新当前日志文件，或无法可靠协调多进程写入时，停止本次进程后续的文件日志写入和轮换，首次禁用时向仍可用的 stderr 提示一次实际原因。提示直接使用 stderr；关闭失败通道或输出诊断时发生的错误，不得形成递归记录或无界重试。正常 stderr 诊断仍可继续输出。

| 条件 | 日志处理 | CLI 及业务处理 |
| --- | --- | --- |
| 日志配置字段本身不合法 | 不用默认值掩盖错误 | 按本地配置错误处理 |
| 配置合法，轮换失败，进程间写入协调仍有效且当前文件追加成功 | 继续记录日志，首次识别轮换故障时向可用的 stderr 提示一次；不把轮换失败解释为追加失败 | 继续原有职责，不改变动作结果或会话结果 |
| 配置合法，当前文件无法创建、打开、追加或刷新，或写入协调失效，包括轮换失败后又发生这些错误 | 禁用本进程文件日志，首次禁用时向可用的 stderr 提示一次 | 继续计划受理、调度、录像及报告等原有职责，不改变动作结果或会话结果 |
| 本进程文件日志已经禁用，之后又有日志产生 | 跳过文件日志，不反复打开、写入、轮换或重复提示同一禁用状态 | 继续按业务与会话契约执行 |
| stderr 诊断也无法输出，但 stdout 和其他必要职责仍可完成 | 停止对失败的诊断通道反复写入，不把日志转写到 stdout | 不仅因辅助诊断丢失而结束会话或停止录像 |
| 同时发生状态库、报告、设备操作或 stdout 结果通道等其他错误 | 在剩余可用诊断通道保留实际信息 | 各错误按原责任边界处理；日志故障不能掩盖它们或把失败改成成功 |

文件日志禁用只作用于发现故障的进程，不修改持久化业务状态或其他进程的日志开关。下一次实际启动的 CLI 可以按配置重新尝试使用现有日志文件；这不是重建业务状态或清空归档的理由。

一次运行可能只留下部分文件日志。关键业务事实仍须按数据库契约保存；不能因为日志通道不可用而省略持久化。若数据库无法写入，仍按[会话错误及应急停止](session-errors.md#正在录像时的应急停止)处理。其他职责正常完成时，`run` / `submit` 可照常输出成功结果；`submit` 的 `needs_run` 仍按实际持久化工作和接纳资格计算，日志故障不参与该判断。`describe` 以能力说明是否完整导出判断结果，`init` 以[本地初始化职责](initialization.md#命令结果)是否完成判断结果。

## 日志副本交付

报告处理首次失败时，camctl 准备当前普通日志的副本并交给主程序。触发、准备、失败清理及启动清理由[日志副本交付](log-delivery.md)定义；跨 `run` 的故障轮次、标记保存及重复抑制由[报告故障标记](log-failure-marker.md)定义。日志副本的成功交接不代表业务状态报告已经完成，也不代表客户端已经收到。

## 验收要求

单元测试按配置合法性和文件状态分类，验证默认值、阈值以下、恰好达到阈值、跨过阈值、保留数量为 1 和大于 1，以及重启继续采用已有文件大小。通过受接口约束的替身验证轮换顺序、最旧归档淘汰与删除范围，日志文案不逐字断言。

集成测试使用真实文件系统验证追加、轮换、减少保留数量及重启后的文件内容与数量；使用真实并发进程验证同一路径的写入与轮换共同满足约束。在不会触发正常淘汰的场景中，每条成功写入的测试日志完整出现且不重复；发生淘汰时按最旧归档边界判断，不要求已淘汰内容仍然存在。验证普通日志删除不修改状态库、产物及报告文件。

单元测试按“日志通道故障”分类，验证配置非法与日志 I/O 故障的不同结果、轮换失败但追加成功时继续记录、轮换失败后追加也失败时禁用、协调失效、首次禁用、后续跳过、stderr 提示次数、诊断通道再次失败，以及关闭时不递归记录。替身只隔离日志写入和协调边界，不能把原业务异常模拟成日志故障后吞掉。

集成测试组合真实 CLI、SQLite、stdout/stderr 管道及受接口约束的设备适配，通过受控日志故障验证：轮换失败但仍能追加时保留后续日志，后续轮换成功时恢复正常归档；日志无法写入时录像继续按目标停止，业务历史与报告正常保存；`submit` 仍返回正确的 `needs_run`；`describe` 仍可完整导出。再组合真实状态库故障，验证原会话错误及有限应急停止仍生效；组合报告文件处理故障时，验证普通设备动作继续及报告责任保留。验证本进程禁用不影响其他进程，后续新进程可以重新尝试文件日志。
