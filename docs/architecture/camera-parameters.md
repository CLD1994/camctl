# 当前相机录像与原生延时参数

[返回设计总览](README.md) · [阅读路线](reading-guide.md)

本专题定义当前 ADB 相机普通录像和原生延时的参数组织。录像生命周期见[相机拍摄](camera-recording.md)，框架的参数类型扩展机制见[拍摄能力与参数类型](camera-capabilities.md)，参数规则的导出见[能力说明格式](capabilities.md)。

**阅读提示：** 先了解[拍摄能力、参数类型与预设](camera-capabilities.md#能力参数类型与用户预设)。本页将手动、自动曝光及固定设置分开说明，并说明当前启用的 Action6 与 OSMO 360 II 普通录像和原生有限延时。

## 适用范围与资料依据

本页记录当前 ADB 相机普通录像与原生延时的参数结构。Action6 与 OSMO 360 II 普通录像、OSMO 360 II 原生延时及 Action6 原生延时均有正式任务定义。各任务的软件验证、真机进度和对应计划统一列在本页末尾，避免本页与验证记录维护两套状态。Action / Action6 与 OSMO 360 / 360 II 的历史命令及会议记录见[相机控制交接资料整理](../hardware/camera-control-handoff.md)；这些资料用于解释命令资料来源，不单独证明设备行为已通过真机验收。

本专题定义普通录像和原生延时的参数组织、曝光分支及相机固定设置。当前驱动和计划实际开放的参数类型由能力说明导出；启用范围、设备证据和待完成计划以本页末尾链接的[组件验证记录](../camctl/verification.md)及对应计划为准。交接资料中的 5—20 秒和 8 秒均为参考时长，不据此制定执行计划的时长限制或默认值。

## 普通录像与曝光选择

每个目标驱动在当前普通录像的 `camera_record` 下使用一种参数类型，通过 `params.exposure.mode` 选择曝光方式。手动和自动曝光共享该驱动的普通录像参数类型标识、公共画面参数，以及启动、计时、停止和产物处理流程。

| 字段 | 职责 |
| --- | --- |
| 动作的 `type` | 为 `camera_record`，选择录像动作 |
| `params.type` | 选择目标驱动声明的整套普通录像参数契约；两种曝光方式使用相同标识 |
| `params.duration_s` | 必填数学整数，单位为秒；Action6 与 OSMO 360 II 接受 `1` 至 `9223372036854775`，不设置默认值 |
| `params.exposure` | 必填对象，包含曝光方式及该方式允许的设置 |
| `params.exposure.mode` | 必填字符串；`manual` 表示手动曝光，`auto` 表示自动曝光 |
| `params.exposure` 中的其他字段 | 由所选曝光分支和驱动定义约束 |

`exposure` 属于当前相机的录像参数契约。其他驱动可以按自身任务定义参数结构；框架仍允许一种拍摄能力拥有多种参数类型。客户端预设保存选定设备、参数类型和具体参数值，生成计划时按既有规则展开。

曝光决定画面接收到多少光。快门时间表示每次曝光持续多久，ISO 表示相机的感光增益设置；自动曝光由相机按设备规则调整，曝光补偿 EV 表达在自动结果上希望偏亮或偏暗的程度。白平衡用于处理画面色彩，色温的单位 K 是开尔文。这里先解释这些字段的用途，实际可调范围以已接入驱动为准。

### 普通录像时长

Action6 与 OSMO 360 II 的 `duration_s` 表示主机计时的目标录像秒数。两种曝光方式使用相同的时长规则。整数按 JSON 数值的数学值判断，因此 `1`、`1.0` 和 `1e0` 均表示合法的一秒；字符串不转换为数字。

以下分类以其余录像参数合法为前提。输入必须显式提供时长；Schema 和驱动默认值均不补充该字段。

| 时长输入 | 校验结果 |
| --- | --- |
| 字段缺失 | 参数错误，不补默认值 |
| 为 JSON 数字，数学值为整数，且位于 `1` 至 `9223372036854775` | 校验通过，保留原精确数值 |
| 为 JSON 数字，但数学值不是整数 | 参数错误，不舍入或截断小数秒 |
| 为整数，但小于 `1` 或大于 `9223372036854775` | 参数错误，零不表示无限录像 |
| 为字符串、布尔值、`null`、对象或数组 | 参数错误，不转换类型或推断时长 |

上限由[录像执行定义的目标时长](../camctl/database/execution-definitions.md#录像执行定义的目标时长)的毫秒表示范围确定：最大整数秒为 `9223372036854775807 // 1000`，即 `9223372036854775`。受理后的目标秒数仍精确转换为 `target_duration_ms`，最大合法值对应 `9223372036854775000` 毫秒。该参数范围不承诺设备停止精度；执行、产物完成判定和恢复继续遵守[相机拍摄](camera-recording.md)的规则。

### 曝光分支

| 曝光方式 | 参数组织与执行含义 |
| --- | --- |
| `manual` | 固定曝光设置由动作参数或驱动明确的固定设置确定。开放 ISO 调整时使用 `exposure.iso`；本分支不接受 `exposure.compensation_ev` |
| `auto` | 驱动调用相机的自动曝光功能，曝光补偿使用 `exposure.compensation_ev`。本分支不接受固定 `exposure.iso` 或要求固定快门的输入；相机实际调整的项目与范围由设备契约定义 |

色彩、分辨率、帧率、视角和防抖等设置，按各自字段与设备组合规则定义。选择自动曝光本身不表示这些设置也采用自动控制；白平衡采用下文确定的固定值。

以下 JSON 以 Action6 为例，只展示 `params` 中的 `exposure` 部分，用于说明字段组织，不是可单独提交的完整拍摄参数。OSMO 的曝光对象只有模式字段，见下文[可选参数](#osmo-360-ii-的可选参数)。示例数值来自交接资料，不定义默认值、完整取值范围或对所有相机的适用性。

手动曝光的结构示例：

```json
{
  "exposure": {
    "mode": "manual",
    "iso": 800
  }
}
```

自动曝光的结构示例：

```json
{
  "exposure": {
    "mode": "auto",
    "compensation_ev": 0
  }
}
```

### MVP 的固定设置

当前普通录像将以下设置作为驱动执行流程的一部分，执行计划不提供相应调整字段：

| 曝光方式 | 快门 | 白平衡色温 |
| --- | --- | --- |
| `manual` | 固定为 `1/60` 秒，由驱动设置 | 固定为 `5200 K`，由驱动设置 |
| `auto` | 按相机的自动曝光规则处理 | 固定为 `5200 K`，由驱动设置 |

驱动在拍摄准备中执行相应设置操作。手动快门的固定值只用于 `manual` 分支，不在进入自动曝光后强制设为 `1/60` 秒。

固定设置属于驱动参数契约，在能力说明的任务说明中展示；客户端不生成调整控件，执行计划不重复填写。参数 Schema 只接受已开放字段，提交额外的快门或白平衡调整字段属于动作自身参数错误，不静默忽略。

后续完整交接确认可调整选项时，可在同一录像参数类型中增加相应字段及约束，并补齐驱动操作映射。沿用既有的驱动定义、同源 JSON Schema 和 `camctl describe` 导出机制，再按部署流程同步客户端；无需为这类字段扩展改变框架的动作接口。已受理动作继续使用首次受理时确定的生效拍摄参数，遵守[参数固化规则](camera-capabilities.md#计划字段与参数校验)。

### 相机会话准备

Action6 与 OSMO 360 II 在每台相机、本次执行会话的首次拍摄准备时，按顺序请求跳过时间设置、关闭自动休眠、关闭延时摄影熄屏省电及选择仅充电。关闭延时摄影熄屏省电用于避免相机因进入省电模式而断开 ADB 连接。Action6 随后还关闭两路屏幕实时画面，适用于未连接主屏幕和前置屏幕的设备。具体命令由[相机会话设置](../hardware/camera-control-handoff.md#相机会话设置)登记。

会话设备配置使用独立预算，普通参数准备另行计时；首次配置与同会话后续拍摄的提前资格、预算冻结及恢复遵守[拍摄准备规格](../superpowers/specs/2026-10-25-capture-preparation-design.md#准备保存与启动)。

设置取得可靠接受结果后，同会话后续拍摄准备复用记录；新会话清空内存记录，并在需要拍摄时执行设置。普通录像与原生延时共用这些准备步骤，设置在动作自身的拍摄参数及 START 之前执行。文件访问与恢复 STOP 沿各自原操作执行。除下述 Action6 临时特例外，工具即使退出 0，stdout 明确报告服务不存在或服务查找失败时，设置仍为未确认，不缓存接受结果，也不继续 START。本地命令被接受不表示相机实际状态已独立读回；通用调用、期限与失败规则见[驱动执行边界](camera-capabilities.md#驱动执行与产物边界)。

**Action6 临时输出处理：** 以下四条精确命令只核实本地调用正常完成，忽略 stdout 和 stderr 的文字内容，包括服务不存在、服务查找失败等提示。指令对 Action6 的有效性与返回格式尚待官方确认；取得确认后须据此复核本规则及相应测试。

- `simulate_device -n DualGuiCmd 12`
- `simulate_device -s DevicePowerUserIdleControlAutoShutdownTime 0`
- `simulate_device -s DevicePowerUserIdleControlLapseLockTime 0`
- `simulate_device -s 0xa13cdabe 3`

这四条命令仍受工具启动失败、超时、取消、退出缺失、信号终止、非零退出及输出获取失败或不完整的约束。正常完成后继续后续准备，并按相同会话缓存规则复用。观察中的 `confirmation_basis = action6_simulate_device_output_unchecked/v1` 只表示按本临时规则核实调用完成，不证明设置有效或相机状态已读回。普通录像的版本化设置调用历史无损保存 stdout 和 stderr；软件恢复准备沿同一命令解释规则执行并保存原调用结果。两路实时画面、其他参数、START、STOP 和 OSMO 均不适用此特例。

### OSMO 360 II 的可选参数

普通录像的参数对象包含 `type`、`duration_s`、`bitrate` 和 `exposure`；原生延时另有 `interval_s`。这些字段均必填，`exposure` 只包含必填的 `mode`，允许 `manual` 或 `auto`。录像时长按上文规则填写，延时的采集间隔、时长域及严格大小关系见[时间参数定义](../hardware/camera-control-handoff.md#间隔与采集时长限制)。

两种拍摄模式的 `bitrate` 均允许 `standard` 和 `high`，标称值与命令由[官方交接资料](../hardware/camera-control-handoff.md#曝光码率与录像触发)说明。每个动作显式保存所选档位；驱动在每次拍摄准备时发送对应设置，相邻动作选择相同档位也分别发送。

手动曝光请求固定 ISO 800、1/60 秒快门和 5200 K 白平衡；普通录像自动曝光请求固定 EV 0 和 5200 K 白平衡，延时自动曝光沿用该模式的相机自动设置。画面为全景 8K／30 fps，普通录像请求 D-Log M。延时固定输出视频。上述固定值在任务或分支说明中展示，Schema 接受的用户调整字段以本节首段为准。

除[相机会话准备](#相机会话准备)外，普通录像的固定画面格式命令在本会话首次普通录像准备时发送，并按相同规则复用可靠接受记录。

视频大小估算继续使用独立的固定假定参考值，任务说明与估算元数据一致；该参考值不随本节码率档位切换，也不代表设备实际平均码率。

### Action6 的光圈要求

Action6 每次普通录像准备在曝光设置后发送 D-Log M 命令 `42 3d`，再按原命令顺序设置视角、防抖、所选光圈和所选码率。

Action6 普通录像的 `aperture` 是必填字段，适用于 `manual` 和 `auto` 两种曝光方式。Schema 和 `camctl describe` 从同一驱动定义导出此规则；新请求缺少字段、提交 `null`、其他类型或未知枚举值时，在派发设备命令前拒绝。合法值为 `f2.8` 和 `f4.0`，分别发送完整命令 `0x26 1801` 和 `0x26 9001`。

严格完整的 `00` 响应会记录 `setting_applied` 观察，但设备没有独立读取设置实际值的接口，因此该观察不能核实相机实际采用的光圈值。`e3` 的含义仍未知；收到 `e3` 时不建立 `setting_applied` 观察，但这两条精确光圈命令在调用正常收场后仍允许后续设置和 START。驱动把原完整命令、调用状态、效果、错误及 stdout 保存在版本化设置调用历史中。其他设备响应以及已经收场的退出、工具或输出完整性错误也保留实际调用事实；未收场异常、取消、中断、启动窗口资格失效和整次 START 剩余期限仍阻止后续派发。其他设置、START 与 STOP 不获得此例外。

### Action6 的码率要求

Action6 普通录像的 `bitrate` 是必填字段，适用于两种曝光方式；合法值为 `standard` 和 `high`。新请求缺少字段、提交 `null`、其他类型或未知枚举值时，在派发设备命令前拒绝。OSMO 360 II 没有开放 `aperture` 字段，其自身码率规则不受本节改变。

所选码率每次新普通录像请求都执行对应的 `simulate_device -s bitrate 1` 或 `simulate_device -s bitrate 2`。工具、通道、退出状态和输出完整性检查通过时，调用历史记录 `setting_command_accepted`，只表示本地命令被接受；不表示相机实际码率已独立读回。任一检查失败时保留该码率调用的真实失败，并停止后续设置和 START。光圈错误不会覆盖随后实际发生的码率或 START 失败；若 START 已派发且结果未知，不重试第二次 START。

驱动将本次普通录像中实际派发的每条设置命令及其完整结果保存为同一版本化 `calls` 记录，包括完整命令、状态、效果、错误、结果文档和原始 stdout。外层结果仍描述最后实际终结的 START、设置失败或派发门禁，不将前序设置成功拼成 START 观察。已保存的旧动作继续按首次受理时的 `effective_params` 解释：历史请求若没有 `aperture` 或 `bitrate`，仍按旧编码规则不发送该字段对应的命令；当前 Schema 不重新受理或改写历史动作，也不补默认值。

### Action6 原生延时参数

Action6 原生延时使用正式参数类型 `action6_timelapse`，字段与普通录像参数类型分开定义。参数对象只接受 `type`、`interval_s`、`duration_s`、`outputs` 和 `exposure`；不接受普通录像的光圈、码率、分辨率、视野或防抖字段。延时命令、固定任务和产物要求见[单张拍摄与延时摄影](camera-capture.md#action6-原生有限延时任务)。

| 字段 | 要求与含义 |
| --- | --- |
| `params.type` | 必填，固定为 `action6_timelapse`。 |
| `interval_s` | 必填，使用 Action6 已登记的延时间隔选项，单位为秒。 |
| `duration_s` | 必填，使用已登记的有限采集时长选项，单位为秒，且必须严格大于 `interval_s`。时间选项的完整定义由[延时摄影资料](../hardware/camera-control-handoff.md#间隔与采集时长限制)及同源 Schema 提供。 |
| `outputs` | 必填，选择 `video`、`video_raw` 或 `video_jpeg`；所选输出的必需原片见[Action6 延时任务产物规则](camera-capture.md#action6-原生有限延时任务)。 |
| `exposure` | 必填对象。`manual` 分支只接受固定请求 ISO 800；`auto` 分支只接受模式字段，不提交 ISO 或 EV。 |

`interval_s`、`duration_s`、`outputs` 和曝光方式分别选择已有的 Action6 原生延时任务组合；时间选择不隐式切换曝光或输出。原生延时执行[相机会话准备](#相机会话准备)，其固定拍摄任务不增加普通录像的光圈、码率、视野、防抖或色彩模式设置。缺少 `outputs`、字段类型错误、时间组合无效或出现未开放字段时，Action6 原生延时参数校验失败，不补默认值。

### 分支校验

以下规则以设备、动作、参数类型已经匹配到有效定义为前提，按表中顺序判断；每行以此前条件不成立为前提。参数错误沿用[计划字段与参数校验](camera-capabilities.md#计划字段与参数校验)：客户端阻止导出错误计划，camctl 首次受理时仅将对应录像动作登记为 `failed`，保留零次执行尝试，整份拒绝优先级保持既有规则。

| 条件 | 结果 |
| --- | --- |
| `exposure` 缺失、为 `null` 或不是对象 | 参数错误 |
| `mode` 缺失、不是字符串，或值不属于该驱动支持的曝光方式 | 参数错误，不推断曝光方式 |
| `mode` 为 `manual`，但提交了自动曝光补偿字段 | 参数错误，不忽略不适用字段 |
| `mode` 为 `auto`，但提交了固定 ISO 或固定快门设置 | 参数错误，不将固定值解释为自动调整的范围 |
| 曝光方式及前述字段归属合法，但提交了 MVP 未开放的快门或白平衡调整字段 | 参数错误，不覆盖驱动固定设置 |
| 分支选择及字段归属合法，但缺少该驱动要求的字段，或字段值、组合不符合规则 | 参数错误，指出对应字段或组合 |
| 曝光设置及其余拍摄参数均符合有效规则 | 拍摄参数校验通过，继续既有公共字段校验和调度流程 |

条件分支、允许字段及组合约束属于该参数类型的同源 JSON Schema。规则本身无效或无法取得时，遵守既有规则处理失败语义，不判为用户参数错误。

客户端先选择曝光方式，再展示该设备 Schema 声明的成员选项：Action6 的 `manual` 展示 `iso`，`auto` 展示 `compensation_ev`；OSMO 两个分支只选择模式，其固定值展示在说明中。模式切换分别保存并恢复各模式的编辑内容，首次进入时不补子参数；级联编辑与草稿资料的行为遵守[对象参数级联编辑](client-editing.md#对象参数级联编辑)。客户端按相应 Schema 分支校验完整曝光对象，曝光方式或字段改变后按当前完整参数重新校验。其他普通字段的独立选项遵守[参数选项联动](client-editing.md#参数选项联动)，高级编辑与输入保留见[表单与 JSON 共用参数](client-editing.md#表单与-json-共用参数)。切换视图不丢弃字段，也不绕过曝光分支校验；校验不另外维护一套相机字段清单。
