# 客户端运行、备份与恢复

客户端在个人电脑运行，浏览器访问本机服务。它通过文件导出和导入与主机交换资料；日常操作从网页完成。

## Windows 本地运行

需要 Node.js 24.16 或同一主版本的后续版本。PowerShell 在仓库根目录执行：

```powershell
npm ci
npm run build
New-Item -ItemType Directory -Force data
npm start
```

打开 [客户端](http://localhost:4310)。首次页面展示实际使用的数据目录，核对后点击“创建客户端数据”。普通启动不会创建业务数据库。

主机导出的真实能力说明应放到 `data/device-capabilities.json`。文件更新后，在网页“设备说明”中点击“重新加载能力说明”。仓库中的 `docs/superpowers/specs/camctl/examples/capabilities/demo-device.json` 仅用于软件流程测试，不代表真实设备配置。

可使用环境变量指定其他目录或端口：

```powershell
$env:CAMCTL_DATA_DIR = 'C:\camctl-client\data'
$env:PORT = '4310'
npm start
```

指定目录须事先存在并可读写。本地默认绑定 `127.0.0.1`，通过 localhost 访问。停止服务使用运行终端的 Ctrl+C，确认进程结束后再备份。关闭浏览器不停止后端视频核验。

## Docker Compose 部署

容器部署与验证由部署人员执行。仓库提供单应用容器配置，整个 `data/` 绑定到容器 `/app/data/`，本机端口为 4310。

```powershell
New-Item -ItemType Directory -Force data
docker compose up --build -d
docker compose logs -f client
```

然后打开同一客户端地址，按网页初始化。已有数据目录应继续复用，更新镜像不覆盖数据。`create_host_path: false` 使缺失的宿主目录明确导致部署错误，避免挂载位置错误时静默创建目录。

停止服务：

```powershell
docker compose stop
```

## 网页操作

1. 在“计划 → 草稿”新建计划，编辑动作、时间和拍摄参数。页面显示的保存结果对应实际保存的输入，未完成内容可以保存，但不能导出。
2. 完成检查并导出 JSON。已经保存的原请求进入计划记录，再次下载沿用原身份；修改意图通过复制为新草稿处理。
3. 手工交给传输部门后，可标记已递交。标记时间只表示记录时间，主机受理和执行仍以报告为准。
4. 在“文件导入”混合选择报告与视频，逐文件查看结果。视频完整保存后，后端继续核验；已核验文件在对应计划详情播放或下载。
5. 在结果详情准备取回、取消、清理或状态同步，加入选定草稿后检查并导出。

## 数据目录

| 内容 | 用途 |
| --- | --- |
| `client.db` 及 SQLite 伴随文件 | 草稿、预设、固定原请求、人工标记、报告原始字节、状态与完整覆盖、导入记录和文件关联 |
| `device-capabilities.json` | 当前磁盘能力说明；实际启用结果以网页为准 |
| `uploads/` | 后端管理的完整视频副本及上传处理中间文件，内部名称不承担业务身份 |

数据库中的视频路径相对于持久化目录保存，允许完整目录恢复到其他绝对位置。不要单独移动或整理内部文件；文件后缀也不表示它已经接受、完整或核验成功。

## 停机备份

1. 停止本地服务或容器，确认后端已经停止写入。
2. 将整个 `data/` 复制到它之外的独立备份目录，包括数据库伴随文件及视频。
3. 确认复制完整成功，再重启原服务。

仅关闭网页不满足停机条件。复制中断或失败的目录不能作为完整备份，不能从不同备份拼接数据库与视频。

## 从备份恢复

1. 保持目标服务停止。已有目标数据先移开保留。
2. 将选定的完整备份复制成目标 `data/`，不要零散覆盖到含其他数据的目录。
3. 检查挂载路径与权限，复制成功后启动。
4. 核对草稿、原请求、报告进度和视频记录。恢复只包含备份时已保存的资料；网页未保存输入不在其中。

数据库缺失但仍有业务文件、库损坏或初始化不完整时，应用显示数据故障，不建立替代空库。能力说明加载失败与数据故障分别处理：此前存在有效说明时，当前进程继续使用此前说明；下次启动仍读取磁盘当前文件。

旧备份收到无法衔接的报告时，页面保留最后可用状态并提示历史缺失。使用“准备状态同步”生成新请求；足够覆盖的报告被成功应用后才解除提示。

## 开发验证

```powershell
npm run typecheck
npm run build
npm run test:unit
npm run test:integration
```

浏览器集成测试需要安装配套 Chromium：`npx playwright install chromium`。测试使用独立临时目录，不把测试数据写入日常 `data/`。含摘要的报告样例由 `.gitattributes` 固定 LF；不得在导入时归一化字节来绕过摘要检查。

自动化软件测试不代替真实相机、厂商视频编码与第三方文件交接联调。容器运行结果由实际部署检查确认。
