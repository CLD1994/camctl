# 客户端验证范围

本页区分软件实现验证与部署、设备联调。完整业务验收依据为[客户端六组场景](superpowers/specs/camctl-client/acceptance.md)。

## 自动化检查入口

| 检查 | 命令与内容 |
| --- | --- |
| 类型检查 | `npm run typecheck`，检查后端、网页和共享规则的接口 |
| 构建 | `npm run build`，构建随本地服务交付的网页 |
| 单元测试 | `npm run test:unit`，严格 JSON、能力规则、动作参数、报告历史与合并、媒体范围，以及网页保存和操作恢复状态 |
| 集成测试 | `npm run test:integration`，先构建当前网页，再验证真实 SQLite、协议样例、文件保存、HTTP 和浏览器 |

`npm test` 依次执行单元测试及上述集成检查。浏览器测试始终使用本次源码生成的网页，避免旧构建产物掩盖实际修改。

协议、持久化、文件服务及网页保存与恢复已完成独立代码评审。本次表单与设备指南改动由实施者按规格逐项审查，未派遣 subagent。报告校验覆盖合法乱序、同一水位自身事实一致、最终逐项结果保留，以及取回失败与交付最终错误同源；无效输入不取得成功报告、覆盖进度或累计确认资格。

本地服务已提供最新构建的网页，网页与状态接口均可访问；已有日常数据目录正常打开，测试资料使用独立目录。上述结果不包含下文列出的外部部署和设备联调。

完整测试使用默认并行配置执行，单元测试、集成测试、类型检查及生产构建均通过。

### 拍摄动作与媒体结果

- 三种拍摄动作按设备能力提供选项与参数表单；真实浏览器验证单张拍摄、按张数结束的延时摄影及类型切换后的输入保留和导出。
- 报告验证覆盖取消后保留的正式图片产物、捕获进度及最终结果不可回退、有限尝试编号和预算约束。
- 图片与视频共用保存、关联、核验及恢复流程；新增 PNG 测试覆盖报告与文件的两种到达顺序、恢复、原始字节和响应类型。现有文件集成测试覆盖错误副本补发及读取失败。
- 默认动作摘要、业务详情、技术详情分层展示；同一产物多次交付分别保留，取回动作仅使用自身交付的副本。
- 100 张图片的真实浏览器场景验证每页 12 项、跨页选择、筛选、图片解码、放大、跨页方向键导航和 Escape 关闭。另用隔离数据检查桌面三列及 390px 窄屏两列布局，均无横向溢出。
- 未知类型和 SVG 作为附件下载，允许预览的媒体使用报告声明的类型并设置 `nosniff`。
- 本地服务重启后处于 `ready`；草稿、导入记录、媒体记录、报告快照及同步进度与重启前一致。

三种拍摄能力的演示目录见 [demo-capture-devices.json](superpowers/specs/camctl/examples/capabilities/demo-capture-devices.json)。这是演示参数，不代表真实驱动已经支持对应设备；真实设备执行与容器部署仍需外部联调。
### 草稿管理与编辑体验

- 未导出草稿可明确确认删除；覆盖取消删除、自动保存衔接、删除持久化、版本冲突、导出后拒绝删除和晚到写入不能重建。
- 删除响应丢失时按可靠状态核实；网络不可用或后端数据故障时保留输入并锁定操作，恢复连接后可继续核实。
- 新录像动作尚未填写参数时显示选择引导；拍摄参数预设默认折叠，显式展开后可应用和保存。
- 普通界面的时间按当前时区显示；浏览器验证时间输入的文本区域点击会调用日期时间选择器，修改后保存正确的协议时间。
- 桌面与 390×844 窄屏检查删除入口、预设折叠和本地时间展示；窄屏无横向溢出。

### 表单与设备指南

动作编辑与保存调整后，重新执行全部 501 项单元测试、类型检查、生产构建及全部 211 项集成测试（其中编辑与评审浏览器场景 73 项），均通过。浏览器覆盖未选类型时隐藏设备栏、录像时显示并过滤设备、四种内置动作隐藏设备栏，以及切回录像恢复原设备值。

- 新增动作不预选类型；动作类型决定设备栏是否显示，设备候选受所选动作的能力要求限制，空目录、无拍摄能力设备和不可用说明仍允许导出状态报告请求。
- 真实浏览器验证先选动作类型再选设备，以及能力重新加载后原设备、动作与参数作为不可用值保留；完整录像草稿失去设备能力后不能导出，刷新仍保持原值。
- 设备指南标明任务所属拍摄能力；新增动作未选类型时提示选择后填写参数，桌面与 390×844 窄屏检查没有页面横向溢出。

- 取回、删除、取消和报告均有专用表单；取回与取消引用组合由表单和共享校验器使用同一份定义，增量报告起点也使用共享判定函数。
- 浏览器验证取回四种来源、禁止所属组、仅指定动作实例提供附加产物筛选、删除列表及重复 ID 拒绝、取消四种目标、报告三种范围和可靠同步起点；通过真实后端导出验证结构与数值类型。
- 类型切换按类型保存设备、所属组、参数、策略及未完成输入，名称和时间共用；验证往返、刷新、数据库重开、删除前项后对应关系、历史追加以及保存响应丢失核实。当前合法类型可导出，其他类型资料不进入协议。
- 普通选填字段直接显示；统一必填标签，保留显式空字符串、0、false、null 及 Schema 默认值的区别，明确清空表示不填写；正常控件不重复显示当前值，字符串选项不带 JSON 引号。
- 查看整份 JSON 保留其他类型资料，实际替换前确认；取消不改写草稿，确认后仅保留本次完整计划。参数 JSON 编辑继续保留其他类型资料。
- 有限组合通过完整 Schema 推导，覆盖双向联动、条件必填、引用旁约束、互斥分支、缺省候选、非法旧值及不可枚举状态。
- 浏览器验证折叠与展开保留未完成输入、删除后折叠状态对应，以及 JSON、预设、保存和重新加载的衔接。
- 能力重新加载后，指南和表单使用新规则，原草稿不被改写；空设备目录、设备无拍摄任务及加载失败保留旧说明分别验证。
- 有限组合联动的范围及复杂参数入口见[公共编辑规则](superpowers/specs/camctl/client-editing.md#参数选项联动)，指南布局见[设备使用说明页](superpowers/specs/camctl-client/device-guide.md)。

## 媒体验证资料

`tests/helpers/media.ts` 使用浏览器录制短 WebM 视频，计算真实大小和 SHA-256，并生成字段匹配的报告。它用于验证浏览器播放和文件一致性，不代表真实相机拍摄结果。已有协议样例中的视频摘要是占位值，不能给任意视频改名后宣称匹配。

## 本地浏览器检查

Windows 本地浏览器已检查首次初始化、三个页面入口、缺少设备说明时的提示，以及部分失败报告的计划与动作结果。使用独立验收目录验证了从正式产物准备取回：草稿引用准确的动作和产物 ID，执行时间保留待填写状态。

390×844 窄屏下，草稿控件能够纵向排列，页面内容宽度与可用视口宽度一致，没有横向溢出。测试数据与日常 `data/` 分开保存。

设备指南已在桌面与 390×844 视口实际检查：任务卡片、允许组合表和技术详情按阅读顺序呈现；窄屏使用单列布局。实际草稿页检查了字段标签、可选字段和必填提示的显示，日常草稿未用于写入测试。

内置动作表单使用独立验收数据检查了 1440 像素桌面与 390×844 窄屏：来源引用和产物列表可直接编辑，取回动作不出现所属组入口，窄屏无横向溢出。字段标签排版调整后重新构建并复验编辑和恢复相关的浏览器测试。

未完成的参数 JSON 在切换整份计划视图后仍显示原文与路径，整份 JSON 保持只读；使用对应路径的“应用修正”后恢复编辑。新增修正区在 390×844 视口中能纵向操作，修正按钮和输入框均可见。

## 外部验证边界

容器部署与验证由用户执行。本机测试不作为 Docker 运行成功的证据。

真实设备的拍摄参数、厂商视频编码兼容性、传输部门保留文件名与原字节的能力，需要实际相机及协作方资料进行联调。客户端核验与网页播放分别判断：文件核验成功但编码不受浏览器支持时，仍可下载原文件。

### 页面反馈、记录折叠与导入分页

- 操作提示仅在发起页面显示，产生后 3 秒消失；验证切换页面、同文案再次触发重新计时，以及异步完成后的页面归属。
- 计划详情和动作可独立折叠，名称和状态保持可见；轮询更新、父计划折叠再展开均保留动作选择。
- 导入记录每页最多 10 个文件，支持首尾禁用和上一页、下一页；一个批次包含 23 个文件时分为 10、10、3 条，轮询不会返回第一页。
- 额外编辑内容在计划页完整保留，离开该页隐藏，返回后可以另存；连接和业务诊断依据实际状态展示。
- 桌面 1440 像素与手机 390×844 页面已查看截图，折叠和分页控件可见，手机导入页无横向溢出。
