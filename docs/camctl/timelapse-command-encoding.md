# Action6 与 OSMO 360 II 延时摄影候选编码

本页定义两款相机延时摄影的有界候选命令编码，供纯命令生成、驱动派发和 Action6 诊断共同消费。时间允许值由生产参数定义 `adb_cameras/timelapse_parameters.py` 集中维护，参数含义与组合关系见[时间参数](../hardware/camera-control-handoff.md#间隔与采集时长限制)；本页不另建允许值清单。

第一版编码格式由本页指定的八个完整模板身份、四字节替换窗口、时间单位和小端顺序固定。可信入口按首次受理的参数和该格式解释已保存事实，不读取当前新请求时间允许值；允许值只约束当前 Schema 与新请求受理。收窄允许值会改变新请求结论，不会改写已受理参数及其第一版负载。若未来需要第二种编码格式，必须先单独设计并冻结可区分的格式身份及其兼容消费规则，再实现对应入口；本页不预设该身份。

## 保障范围与证据等级

候选生成器根据型号、原曝光上下文和输出选择已有完整模板，仅替换受样例支持的四个时间字节。生成结果的含义是“符合本页规则的样例推导候选”，不是设备已经接受或完成拍摄。当前整秒域允许按此规则形成候选；未来扩展时间域或精度时，先重新核对数值表示、未知位及模板适用条件，再统一扩展权威定义和消费者。

证据等级|能够证明的内容|不能由该等级推导的内容
-|-|-
资料明文|[硬件交接资料](../hardware/camera-control-handoff.md)提供任务参数、完整负载、型号各自的曝光与输出上下文，以及设置顺序。|没有明文定义完整协议字段宽度和所有固定字节的含义。
样例推导|不同参数的完整样例支持本页的字节替换关系；独立预期可以验证生成结果及非时间字节保持。|候选可构造不证明设备支持该时间组合，不构成完整厂商协议定义。
设备依据|适用设备、固件和工具上的实际结果，或者明确限定保障范围的运行假设，支持其覆盖的执行事实。|设置响应、实际开始、采集结束、单文件完成和集合齐备不能相互代替。

原文、整理稿和生产查表是同一资料的派生表示，不能作为多个独立来源计数。样例之间的字节一致性支持候选规则，但不能排除原资料共同存在错误。

## 完整模板与选择分区

完整字面量由[Action6 组合命令](../hardware/camera-control-handoff.md#间隔持续时间与输出组合命令)、[OSMO 手动上下文命令](../hardware/camera-control-handoff.md#30-秒间隔下的时长候选)和[OSMO Auto 上下文命令](../hardware/camera-control-handoff.md#三组任务的组合参数)提供。生产编码模块集中维护这些模板，其他消费者读取或生成相同规则，不自行复制模板集合。

型号|曝光上下文|输出|采用的完整模板样例|长度
-|-|-|-|-
Action6|手动 ISO 800|video|30 s／5400 s 的仅视频完整样例。|17 字节。
Action6|手动 ISO 800|video+RAW|30 s／5400 s 的 video+RAW 完整样例。|17 字节。
Action6|手动 ISO 800|video+JPEG|30 s／5400 s 的 video+JPEG 完整样例。|17 字节。
Action6|Auto|video|8 s／1800 s 的仅视频完整样例。|17 字节。
Action6|Auto|video+RAW|8 s／1800 s 的 video+RAW 完整样例。|17 字节。
Action6|Auto|video+JPEG|8 s／1800 s 的 video+JPEG 完整样例。|17 字节。
OSMO 360 II|手动 ISO 800|video|30 s／600 s 的 `040700…01` 完整样例。|16 字节。
OSMO 360 II|Auto|video|8 s／1800 s 的 `040000…00` 完整样例。|16 字节。

表中的曝光列只确定资料已有的使用上下文。OSMO 两种形态的偏移 1 和末尾字节保持原值；资料没有证明它们表示曝光，编码器不解释或重算这些字节。相同时间规则不允许跨型号借用模板，也不允许从一种输出模板修改未知字段构造另一种输出。

Action6 的旧 5400 s、6000 s 样例可以作为模板及字节核对依据，不扩大新请求时长域。OSMO 25 s 样例的正文写 100 min，旁注要求改为 2 h；按时间关系解码得到 7200 s，只能说明它与旁注一致。该项保留原完整字面量和相互冲突的说明，不作为新候选模板或独立完整预期，也不通过推导改写原说明。

## 时间字节替换

字节偏移从完整 `6c` 负载的首字节按零开始计数，切片右端不包含在内。编码前完成整组参数、模板结构和数值表示检查；检查通过后复制完整模板，再执行下表两处替换，一次返回完整负载。

切片|候选数值|表示方式|替换边界
-|-|-|-
`[3:5]`|`interval_s × 10`，单位为十分之一秒。|精确非负整数的两字节小端表示，低位字节在前。|只覆盖偏移 3、4。
`[5:7]`|`duration_s`，单位为秒。|精确非负整数的两字节小端表示，低位字节在前。|只覆盖偏移 5、6。

负载长度以及 `[0:3]`、`[7:]` 的每个字节都保持所选模板原值，包括含义未知的非零字节和零字节。两字节是候选替换窗口的宽度，不是已经确认的完整厂商字段宽度；不将相邻零字节视为已知高位，也不补写校验和或其他字段。

所有计算使用输入的精确数学值。`1`、`1.0` 和 `1e0` 秒具有相同含义，编码前不通过二进制浮点投影、截断或舍入改变数值。间隔保持 Schema `number` 和通用精确数值能力；当前允许值由同源域限制新请求，但不是第一版格式的表示条件。候选数值必须为数学整数并能完整放入替换窗口，不能靠截断低位字节处理超界值。

样例对这组关系的支持如下：Action6 的 8、25、30 秒分别对应 `50 00`、`fa 00`、`2c 01`，1800、5400、6000 秒分别对应 `08 07`、`18 15`、`70 17`；三种输出均保持相同时间关系。OSMO 自身的 8、30、40 秒符合相同间隔关系，固定 30 秒间隔的七条不同持续时间样例符合秒数小端关系，Auto 的 1800、18000 秒样例也符合。Action6 手动每种输出只有一组时间，跨时间核对借助同型号、相同输出且非时间字节相同的 Auto 样例，不能宣称手动分支本身具有多组时间证据。

## 输入、缺口与历史事实

新请求先通过当前完整 Schema，再选择模板和检查候选表示。可信原生效参数入口只供公共处理器消费首次受理事实，不能暴露为调用方跳过校验的开关。该接线由[参数计划 P2](../superpowers/plans/2026-10-16-osmo360ii-timelapse-parameters.md#p2-原输入冻结执行定义及能力过滤)交付，先于 D1 扩展编码。

入口及条件|结果与边界
-|-
新请求字段、精确数值域或时间关系不符合当前 Schema|报告参数错误，不构造负载，不修改原输入或选择相邻允许值。
新请求完整合法，型号、曝光和输出分区有完整模板，模板结构及表示检查通过|返回样例推导的完整候选，不附加设备已生效或已完成事实。
参数合法但分区没有模板|明确报告命令映射缺口，沿既有内部规则错误分类处理，不改报参数非法，不回退到其他型号、曝光或输出。
模板不能按完整十六进制解码，长度不符，或候选窗口不完整|报告编码结构错误，不发送任何设置，不补零、裁剪或替换模板。
候选数值不是数学整数，或超出两字节表示范围|报告编码表示错误，不取整、截断或越过窗口改写未知字节；新域扩展先修订编码契约。
已受理事实具有原有依据的完整字面量|可信入口按原参数、原格式与原映射解释完整负载，不用当前新请求 Schema 拒绝它，不用新候选覆盖原字节。
已受理事实依据某个候选格式形成|沿该事实的原格式、参数和依据解释，不因当前参数域或模板更新改写原要求；缺少必要事实时明确报告缺失。
历史或诊断记录缺失必要事实、原负载不一致，或确实没有可解释映射|保留具体缺失或矛盾，不用当前最短模板、默认值或新请求重新拍摄来补齐。

完整参数合法性、候选可构造性和正式任务可用性分别判断。参数合法且候选齐备，仍不能使缺少可调用任务工厂的能力进入正式 `describe` 或受理目录。

## 派发、诊断与恢复边界

候选编码函数是纯转换，不访问设备、目录、数据库或主机时钟。编码检查失败须在第一条设备设置前暴露，不能先发送部分设置才发现时间负载缺口。

实际派发保留各型号的原设置顺序：Action6 在模式和分辨率后发送一次完整 `6c`，再配置所选曝光；OSMO 在自己的模式、分辨率和曝光设置后发送一次完整 `6c`。曝光命令沿各型号现有上下文，不因时间选择而切换。设置全部满足适用门控后才允许唯一一次 START；原绑定、资格、剩余期限、取消与设置失败门控继续有效，不引入隐藏重试。

Action6 新诊断消费同源时间规则及本型号 Auto／仅视频候选，并保存精确参数、完整负载及其格式和依据。旧记录只读复查沿原请求、原负载、原调用和原目录基准核对，不按当前新请求 Schema 改判，不发送设置或 START。候选编码软件交付不自动恢复已暂停的采集，也不提供 Action6 延时 STOP。

同请求重送与恢复使用首次固定的生效参数、执行定义和原设备事实。START 未知不重发，不替换目录基准或生成新的拍摄身份；编码规则更新不补造任何发送、实际开始、完成或文件事实。

### OSMO START 调用

OSMO 360 II 新验证请求的 START 使用 `dji_mb_ctrl -R diag -g 1 -t 0 -s 2 -c 01 01`，省略可选的 `-o` 参数。参数可省略的依据见[用户确认记录](verification.md#osmo-start-可选参数的用户确认2026-10-17)。默认响应等待值及单位保持未知；START 返回处理和受管外层期限遵守[完成与正式业务接入设计](../superpowers/specs/2026-10-18-osmo360ii-capture-completion-design.md#设备证据与完成方式)，工具调用等待不表示采集时长。

OSMO 较长间隔采集的通信可用性另按[低功耗现场依据](verification.md#osmo-360-ii-延时低功耗与-adb-恢复的现场确认2026-10-17)核对。候选时间字节和 START 响应不提供持续在线、连接恢复时间、文件写完或集合齐备的保证；Action6 的连接恢复行为以其[固件缺陷现场记录](verification.md#action6-长间隔延时固件缺陷与验证暂停2026-10-17)为准，不从 OSMO 结论推导。

### OSMO 响应处理与可用接口

本节维护 OSMO 360 II 原生延时的当前响应处理约定，依据为[用户确认记录](verification.md#osmo-360-ii-响应处理与可用接口的用户确认2026-10-17)。适用场景为该型号自身的延时设置及原生 STOP 流程；不推广到 Action6、普通录像的其他命令或未列出的响应。Auto 的 `ee` 采用用户暂定的正常处理约定，官方核实尚未完成，不表述为官方协议定义。

每次控制调用先核对工具退出 0、stderr 为空、输出完整且只有一条完整的响应帧，再按命令及上下文解释响应。传输失败、超时、取消、输出截断、缺帧或多帧分别保留原错误与未知事实，不由下表的设备响应约定覆盖，也不自动重发 START。

| 命令及上下文 | 响应 | 当前处理及证据范围 |
| --- | --- | --- |
| OSMO 原生延时 Auto 流程的曝光设置 `1e 0000` | `00`，或暂按正常处理的 `ee` | 允许继续原设置顺序及唯一一次 START；保留实际响应，`ee` 的官方核实继续由用户跟进。 |
| 已执行原生延时 STOP `01 00` 后重复执行同一 STOP | `df` | 按正常重复停止响应处理；用户确认重复 STOP 没有副作用，可安全重复。不由 `df` 自行定义其他场景的码义。 |
| 其他当前有成功样本的 OSMO 原生延时设置、START 或首次 STOP | `00` | 按正常响应推进相应步骤；不把前两行的特殊响应集合移用到其他命令或上下文。 |
| 任一命令收到不符合其适用约定的响应 | 其他响应 | 保留原始调用并停止依赖该结果的后续步骤，不改写为正常或自动换用另一种模式命令。 |

正常响应、参数独立回读、实际开始、设备空闲、单文件写完及集合齐备分别记证。用户确认当前没有可供使用的参数回读接口或媒体解析说明，因此不把提供这些接口作为继续验证的前提，也不增加未经定义的查询步骤。请求值和正常响应可以作为设置流程的记录；未取得独立实效证据的参数继续注明这一边界。当前完成与文件运行假设以[完成与正式业务接入设计](../superpowers/specs/2026-10-18-osmo360ii-capture-completion-design.md)为准；正式实现和验收仍按[实施计划](../superpowers/plans/2026-10-18-osmo360ii-capture-completion.md)跟踪。

## 软件验收

纯候选及派发的软件验收由[驱动计划 D1](../superpowers/plans/2026-10-16-osmo360ii-timelapse-driver.md#d1-纯命令生成与逐条派发)承担，至少覆盖：

- 预期直接取自无冲突的独立完整样例，不由被测生成器制造。逐字比较 Action6 三种输出和两种曝光上下文、OSMO 两种上下文的完整字面量；保留域外旧样例解释能力，排除有冲突的 OSMO 25 s 项作为模板或完整预期。
- 从权威时间域枚举当前全部 134 对合法时间，在每个受支持曝光／输出分区检查构造、长度及全部非时间字节。独立核对最短、最长、低字节进位及高位边界，不能只断言生成后再由同一函数反解相等。
- 验证等价数字词元、邻近不等值、域外、错误类型、缺字段、严格大小关系、缺模板、坏模板及表示超界。编码错误检查零设备调用；新请求校验不修改输入。
- 验证新候选与可信原生效参数入口的隔离：旧完整字面量仍可按原事实派发，相同域外值的新请求被拒绝；旧记录只读核对不依赖当前允许值。
- 逐型号验证设置顺序、门控、原绑定与剩余期限、唯一 START；设置失败、取消或未知结果不产生后续派发或隐藏重试。

D1 通过只表示候选构造和派发的软件契约通过；诊断资源、安装版链、ARM 及设备结果按各自任务独立验收。

## 表示风险与设备输入

当前域的最大候选间隔数值为 36000，即 `0x8ca0`；最大时长为 18000，即 `0x4650`，均可放入候选窗口。但样例没有定义字段的符号、位域或更宽结构，数值可表示不能推出设备支持。

待核对范围|已有依据与未决边界
-|-
最短 1 s／300 s|时间字节由既有完整样例外推；OSMO 手动／仅视频已有[用户现场整体确认通过记录](verification.md#osmo-360-ii-最短延时手工演示的现场验收2026-10-16)，逐项回读未归档。Action6 及 OSMO Auto 的设备适用性仍分别核实。
最长间隔|两款样例的间隔高字节只出现 `00`、`01`。按位从零计数，36000 会设置此前未观察的第 10、11、15 位；不能排除受限位域、带符号字段或标志位。
Action6 最长时长|既有最大样例为 6000 s；按位从零计数，18000 s 会设置此前未观察的第 14 位。OSMO 自身已有 18000 s 完整样例，不能代替 Action6 依据。
完整模板适用性|分别核实型号、固件、工具、曝光／输出上下文与未知字节的适用条件；OSMO 两种形态的上下文关联没有证明其字段含义。
执行与文件|按[OSMO START 调用](#osmo-start-调用)核实默认响应等待、外层调用期限、设置／START／STOP 响应、结束方式、STOP 重复安全性、文件归属、单文件完成及集合齐备的依据。

OSMO 最短候选的软件交付可供[独立设备试验 D2](../superpowers/plans/2026-10-16-osmo360ii-timelapse-driver.md#d2-明确返回结束及产物契约)消费，不要求真机逐项运行全部组合，也不默认增加状态查询接口。未取得所需设备输入和有效执行契约时，正式任务工厂保持关闭；时间推导、主机等待、`00`、文件出现或 USB 断连均不能代替这些事实。Action6 正式延时继续遵守自身设备接入门槛，不借用 OSMO 的停止或完成依据。
