# 输入类型、精确数字与编码适配

[设计入口](README.md) · [实现总览](implementation.md) · [实施准备](implementation-readiness.md)

本页说明输入如何转为内部类型，以及数值如何经过校验、保存、历史恢复和报告输出而保持精确。公共输入的合法性由[输入契约](../architecture/plan-input.md)定义，报告字节格式由[字段契约](../architecture/report-format.md)定义；这里说明实现这些契约所需的适配。

## 输入校验与内部类型

按[输入校验顺序](../architecture/plan-input.md#校验顺序与错误优先级)分阶段处理，不能先要求整个输入转换成一份完全合法的执行模型：

- 完整读取并无歧义解析后，才取得请求身份及 ACK；解析包含全部字段名和字符串值的 Unicode 完整性检查。未配对代理码点按整份解析失败处理，诊断使用可编码的转义文本；不从失败的读取或解析结果提取身份。
- 已受理的 `request_id` 重送时复用原计划，跳过本次正文校验，独立处理本次 ACK。
- 新计划的公共结构错误与单个动作自身错误分别处理，保持整份拒绝的优先级。
- 原始结构化输入保持原样；合法动作的生效参数按驱动定义补齐后单独保存。
- Schema 无效、必要引用缺失或规则不可解释属于规则处理错误，不能当成用户参数错误。

驱动直接维护拍摄参数 Schema，同一份规则用于 camctl 校验及能力说明导出，客户端使用导出的规则。参数默认值与说明保持同源；公共字段、引用和业务资格由对应业务规则判断。完整契约见[拍摄参数的 JSON Schema](../architecture/camera-capabilities.md#拍摄参数的-json-schema)。

转换为数据库字段时遵守[空值与状态组合](database/common.md#空值与状态组合)。原始 JSON 字段省略与显式 `null` 分别保留；数据库列的 `NULL` 由该字段的固定语义或已保存状态解释。读取适配分别表达记录不存在、合法空值和读取错误，不将数据库异常转换为空值或默认值。

## 整数枚举与协议边界

数据库状态与类型列遵守[整数枚举规则](database/common.md#状态与类型的整数枚举)。复用标准库 `IntEnum` 的整数值与成员转换能力，业务代码使用具有明确含义的枚举成员；持久化适配负责写出整数并在读取后恢复所属枚举类型。

转换前按字段契约检查输入类型与合法性，不因为值可以转换成某个枚举成员就接受布尔值、数字字符串或浮点数作为内部枚举的整数存储值。不同枚举类型各自解释自己的编号，不能只凭整数相等混用状态或类型。

公共输入先按公共 Schema 校验，再把适用的协议字面量转换为内部枚举；受理失败需要保留的原始值仍按原输入保存。公共报告通过对应关系将内部枚举转换为协议规定的字面量，不能因 `IntEnum` 可以作为整数使用，就把内部编号直接输出到要求文本的字段。日志和诊断使用明确的成员名称或说明表达含义。

验证覆盖合法值的写入与读回、错误类型、未定义编号、可空组合、不同枚举类型，以及已有编号在新增成员后保持不变。对具有公共表示的枚举，检查协议合法值与转换关系完整对应，报告输出符合公共 Schema；原始错误输入及开放外部值继续保持其事实。具体数值映射与数据库约束由同一权威定义提供。

## 精确数字与统一输出方向

数值在输入校验、数据库保存、历史恢复和报告输出之间保持精确。标准库 `json` 将整数字面量解析为 `int`，将带小数点或指数的数字原文直接交给 `Decimal`，不先转为 `float`。原始结构化输入保留精确数值，不要求保留数字的尾随零或指数写法；报告按[精确数值与统一写法](../architecture/report-encoding.md#精确数值与统一写法)输出 JSON 数字。

| 输入分类 | 整数字段的类型判断 |
| --- | --- |
| 整数字面量，例如 `1` | 按整数判断，再检查字段范围 |
| 带小数点或指数且数学值为整数，例如 `1.0`、`1e0` | 按整数判断，再检查字段范围 |
| 数学值不是整数，例如 `1.0000000000000001` | 不满足整数字段要求，不先舍入或截断 |
| 字符串、布尔值、null 或其他 JSON 类型 | 不满足整数字段要求，不隐式转换 |

原始输入的保存不因字段校验失败而舍入或修改该值。整数身份、范围及安全整数边界按字段契约判断，不能以 Python 对象是否属于 `int` 作为完整校验规则。非 JSON 数值常量继续按输入解析规则拒绝。

相机 Schema 中的数值约束采用相同的精确表示；为 `jsonschema` 适配精确数字类型和相关数值判断。适配须覆盖整数识别、范围、倍数、数值相等及其参与的组合规则，不能只替换类型判断而遗漏其他数值操作。数据库存储、派生投影、快照和跨模块传递均须保持同一数值；正文的文本存储及统一数字适配见[精确 JSON 与配置适配](#精确-json-与配置适配)。

`Decimal` 的文本构造可以保留输入值，算术操作仍受计算精度和舍入规则影响。数字格式遵守[精确数值与统一写法](../architecture/report-encoding.md#精确数值与统一写法)，格式选择和去除多余尾随零也必须保持精确。整数识别、倍数判断、持久化与编码的适配方式见[精确 JSON 与配置适配](#精确-json-与配置适配)，设备转换按具体驱动单位和范围实现；不因选用了 `Decimal` 就假定所有后续运算自动精确。

相关能力见 [Python JSON 解析](https://docs.python.org/3.11/library/json.html)和 [Decimal](https://docs.python.org/3.11/library/decimal.html)。

验收覆盖上述类型分区、字段范围边界、带小数或指数的等值数字、精确 Schema 数值约束，以及输入保存后经当前投影、历史快照和正反向恢复再输出的数值一致性。协议定义为数值的报告字段不得被编码为字符串，也不得通过浮点转换改变原始数值。对象 ID 按[对象 ID 契约](../architecture/plan-input.md#对象-id)在数据库中保存为整数，在公共 JSON 中编码为规范十进制字符串；身份转换同样不得经过浮点数。

## 日期时间的精确适配

数据库日期时间列遵守[日期时间的存储](database/common.md#日期时间的存储)，公共输入与报告遵守[时间字面量](../architecture/plan-input.md#时间字面量)。转换层使用明确的 UTC 起点，通过整数的日、秒和微秒计算时间戳，反向转换同样使用整数运算。运行机器的本地时区不参与这些转换。

| 数据来源或操作 | 处理与必须保持的结果 |
| --- | --- |
| 合法公共时间字符串 | 按实际日期及固定秒级格式校验，生成整秒对应的精确整数微秒；小数秒输入按非法格式处理 |
| 原始输入缺省、为 null 或含非法时间 | 保留原始存在性、类型和值，按所属字段契约处理；不通过默认 0、裁剪或舍入生成有效时间 |
| 数据库时间列用于查询和比较 | 使用整数值与明确的微秒单位，覆盖起点之前及之后的合法日期 |
| 公共报告表达原始时间意图 | 从可靠保存的整数时间按固定秒级格式还原；非法输入和字段存在性按原事实表达 |
| 历史恢复或快照恢复日期时间列 | 使用已保存事实恢复同一整数微秒值；时间可信性随原事实恢复，不根据本次时钟重新判断 |
| 日期时间转换或已有记录无法可靠解释 | 按所属输入错误或状态库错误规则处理，不返回空值、起点或本次时间作为替代 |

验证覆盖公共协议允许的最早和最晚日期、起点两侧、零、秒级输入、跨日及闰日；内部观测时间另覆盖一微秒差异，并确认相同输入在不同本地时区设置下得到相同整数。非法日期、任意小数秒、错误 JSON 类型及缺省分别按字段契约验证。历史与当前投影中的时间往返恢复后保持一致；公共时间按唯一格式输出，报告冻结字节保持一致。微秒存储精度不表示设备执行具有微秒级准时保证。

## 录像目标时长的精确适配

录像执行定义的 `target_duration_ms` 使用[正整数毫秒契约](database/execution-definitions.md#录像执行定义的目标时长)。驱动从生效参数及任务定义提供目标时长，动作适配层按明确单位精确转换；例如 1.5 秒对应 1500 毫秒，1.0005 秒不能表示为整数毫秒，不默认舍入。数学值为整数的小数或指数写法沿用 JSON 整数判定，字符串和布尔值不隐式转换。

换算须保持整数及小数的精确值，并检查内部表示范围与驱动业务范围。持久化和恢复继续使用精确 JSON 文本适配，不经过 SQLite `REAL` 或二进制浮点数重建目标值。与单调钟、历史时间或媒体时长比较时先明确单位；单位换算不能造成整数溢出、精度丢失或提前满足停止条件。实际媒体时长不因目标使用毫秒而被压缩到相同精度。

验证边界值、精确与非精确转换、不同 JSON 数值写法、驱动输入不合法与内部转换错误的分类，并覆盖目标及实测时长只差不足一毫秒时的比较结果。既有驱动合法范围仍是设备能力边界，不以内部整数最大值扩大设备承诺。

## 精确 JSON 与配置适配

CLI 参数解析使用标准库 `argparse`；TOML 读取使用 Python 3.11 的 `tomllib`，通过 `parse_float=Decimal` 保留配置中的精确小数。配置层负责按字段覆盖、严格类型和组合校验。命令语法错误和业务输入错误分别映射到已有退出协议；不能直接沿用 `argparse` 的默认退出码作为全部 CLI 错误行为。[argparse](https://docs.python.org/3.11/library/argparse.html)、[tomllib](https://docs.python.org/3.11/library/tomllib.html)

输入和 Schema 中的数值都使用 `int` 或有限 `Decimal`，排除 `bool` 的整数继承关系。只允许本地登记的 Schema 引用，使用 `referencing.Registry` 管理引用，不在受理时访问网络。字段默认值由驱动适配层按权威定义应用，不能假定 Schema 校验器会修改输入。

精确数字适配集中在一处：

`contracts.schemas` 提供统一的精确校验器构造、包内 Schema 读取及本地引用登记。受理、报告和能力说明通过该边界使用相同的数字规则；受理层只将规则错误与文档错误映射为所属错误类型。Schema 正文和引用资源均按精确 JSON 方式读取，根规则与独立资源的版本遵守[参数 Schema 版本契约](../architecture/camera-capabilities.md#拍摄参数的-json-schema)。

| 操作 | 实现方向 | 必须保持的结果 |
| --- | --- | --- |
| JSON 解析 | 标准库解析，重复键检查，整数读作 `int`，小数和指数读作 `Decimal` | 非有限值、重复键及非法 Unicode 按既有输入层级失败 |
| `integer` 判定 | 精确判断数学值是否为整数，排除布尔值 | `1.0`、`1e0` 合法；接近整数但不相等的数不合法 |
| `multipleOf` | 用 `Fraction` 从精确数值构造有理数，判断商的分母是否为 1 | 不受 Decimal 上下文精度影响，不通过浮点计算倍数 |
| 比较、相等和组合规则 | 两端均保持精确类型，验证范围、`const`、`enum` 和 `uniqueItems` | 数学相等与 JSON 类型规则共同成立，`true` 不等同数值 1 |
| 持久化 | 原始输入、事件、投影和快照的 JSON 正文存为文本；按同一精确方式读取 | 不经过 SQLite `REAL` 或 JSON 数值提取来重建精确正文 |
| 报告数字编码 | 根据 `Decimal.as_tuple()` 的符号、数字和指数直接生成规定格式 | 不使用会按上下文舍入的 `normalize()` 或先转 `float` |
| 业务计算和设备转换 | 精确运算后按驱动声明的单位与合法范围转换 | 不通过默认舍入让不支持的参数变成另一个合法输入 |

标准库负责字符串转义；报告编码适配只负责固定字段顺序、逐批实体输出、标点和规定的数字格式。普通第三方 JSON 编码器的 Decimal 支持并不自动满足本项目的数字写法及实体分批要求。复用范围与具体缺口见[数字能力核验](integration-readiness.md#精确数字核验)。
