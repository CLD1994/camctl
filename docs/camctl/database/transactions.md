# 数据库事务接口与恢复边界

[数据库入口](../database-schema.md) · [数据库执行线程](../persistence-runtime.md) · [事件格式](history-formats.md)

本页定义必须共同提交的业务操作。名称描述接口职责，不限定 Python 类名、函数签名或目录拆分。写接口接收类型化输入、稳定的 `operation_key` 及已取得的外部证据；在写事务内读取可靠旧状态、判断资格、形成事件，再由同一事件应用规则更新投影、目录和快照进度。查询不执行设备或文件副作用。

## 公共完成与失败契约

接口返回已提交业务结果、确认未执行、确认回滚，或提交结果未知。业务拒绝是可以可靠提交的结果，SQLite 错误不是业务拒绝。调用协程取消后，已开始的数据库工作仍由执行层跟踪到结果；不能从等待者消失推断事务未提交。

提交成功后需要重新调度的业务操作，由负责流程完成结果接手及通知，遵守[调度交接](../implementation.md#调度通知与待处理工作的交接)。调用协程被取消不取消这一接手责任；提交后通知前进程退出，则由下一次启动恢复持久化工作。

提交未知时先停止依赖步骤，重新建立可用连接后按同一 `operation_key` 查询完整事务，核对输入、阶段及目标。可靠存在则复用原结果，可靠不存在且原事务已经不可能迟到提交时才按原业务资格重做。查询失败、事务仍可能在途或输入不一致均不能重做。该机制不保证数据库之外的设备命令、文件移动自动幂等；这些步骤按各自的意图与结果记录恢复。

更新必须使用写事务刚读到的值，或带相应状态及事件版本的条件更新。不能将先前缓存的一整行写回，覆盖独立 ACK、文件结果或取消事实。状态库错误按会话错误处理；不把外部操作已经完成但保存失败解释为“操作没有发生”。

## 分配事件编号与核对引用

写事务取得可靠旧状态后，确定本组事件的类型、顺序和数量，再按[编号分配规则](../history-storage.md#序号分配范围与初始化边界)确定事务 ID 及事件范围 F～L。事件正文按[逐字段引用规则](history-formats.md#事件引用与事务边界的编码)填写：本事件引用使用 E，本事务完整边界使用 L，既有历史引用使用原来的可靠编号。事件可以分批形成和保存，不要求把整笔事务的全部正文同时放入内存；引用 L 的正文在编码前必须已经知道最终范围。

若形成事件期间发现实际事件数量与原范围不符，不能按旧 L 提交。程序须在同一事务内重新确定完整范围、重新形成受影响的正文及引用并重新校验，或回滚整笔事务。事务首尾、事件归属、当前投影和目录必须使用同一组最终编号。报告冻结取本事务之前的完整已提交边界，其覆盖水位及 ACK 等依据也从该边界的可靠状态取得，不能混入尚未提交的部分修改。

行级检查核对字段的前后值、适用分支及引用类型；整笔事务检查确认应共同保存的目标事件齐全、首尾真实且引用归属正确。SQL 的延迟外键允许本事务内稍后插入被引用行，但只能保证引用目标存在，不能代替事件分支、对象归属、末位身份及冻结范围检查。任何检查失败都回滚整组变化。提交未知仍先核实原 `operation_key`，不得先把内存中分配的编号当作已提交历史使用。

## 写操作目录

| 原子操作 | 输入及事务内前提 | 一起提交的内容 | 提交后的允许行为 |
| --- | --- | --- | --- |
| 初始化 | 目标库可靠不存在，显式部署入口 | 完整目标结构、索引、格式元信息、唯一初始运行状态；无虚构事件 | 按初始化落盘契约提供正式状态库 |
| 处理输入 | 完整读取/解析结果或实际输入错误；事务内查 `request_id` 与 ACK 报告 | 首次计划及全部动作、可靠自动关联、本计划来源集合、输入诊断、有效 ACK 及适用同步结束 | 新执行资格仅在提交成功后可见；`submit` 不执行设备或文件交付 |
| 开始动作 | 原动作非终态、时间及所属会话资格成立 | `RUNNING`、执行标记、适用处理责任、父计划状态及历史 | 可以进入该类型的实际等待或执行流程 |
| 保存窗口观察 | 已取得可信读数且位于启动窗口；原观察为空 | 首次观察及事件 | 再检查设备资格；观察不证明已经启动 |
| 固定来源或目标 | 完整可靠解析结果，动作仍有资格；取消先完成自身目标检查 | 集合全部成员、所属固定状态、必要选择/明细及历史 | 才能逐成员推进；失败或重启不得重新扩大集合 |
| 首次授予录像启动机会 | 必要准备已完成；事务内核对占用、保留、取消、窗口、预算及候选顺序 | 表达首次归属的 `ACTIVE` 启动流程、原活动身份、本次尝试意图、累计次数、采用参数及历史，见[启动共同提交](waiting.md#首次启动机会与尝试的共同提交) | 可靠提交后派发；提交未知先核实，未取得结果不退还次数 |
| 记录调用意图 | 实际目标、当前配置、累计次数、窗口/取消/安全条件全部通过 | 流程、尝试、新累计次数、实际采用参数及副作用可能性 | 提交成功后才派发该次普通调用 |
| 记录调用结果 | 原尝试身份和真实结果，调用已完成适用收场；核对目标及操作仍由原责任拥有 | 尝试、流程、设备/文件观察及相关历史 | 根据已知效果和剩余资格决定继续、等待或结束 |
| 开始状态查询或一轮产物核实 | 按[查询用途与目标](operation-fields.md#查询用途责任键和目标字段)核对原责任，相关调用已完成收场，当前执行资格和剩余次数允许继续 | 原流程或首次建立的流程、新尝试意图、累计次数及目标设备的实际配置依据；产物核实开始还保存适用的集合核实状态 | 提交成功后执行本次查询或本轮检查。轮内分页沿用原尝试，结果提交未知时先核实原事务 |
| 保存查询或整轮核实的结果 | 原尝试和目标一致，已有实际响应或可靠失败依据，调用已完成适用收场 | 尝试结果、仍需继续或结束的流程、适用重试等待、设备和文件观察、结果集合及适用动作结果；相关对象历史一起保存 | 按[流程结束分类](operation-fields.md#一次查询结束与整项核实结束)继续或结束。一次响应成功不单独结束仍需继续的责任，重新检查不刷新原次数 |
| 补记应急停止 | 本会话对该录像的应急处理已经结束，相关调用已完成适用收场；原内存事实完整，事务内核对活动归属、责任键和原补记事务，并按[字段组合](operation-fields.md#应急记录的结构约束与事务校验)检查全部尝试、固定配置及停止依据 | 一条最终应急流程、全部实际尝试、适用设备观察及原动作历史；没有尝试时不创建尝试行。公开结果实际变化时共同保存对应报告目录，具体组合见[最终补记](operation-fields.md#应急停止的最终补记) | 只确认记录保存结果，不派发停止、不重开应急流程；提交未知先核实原事务，保存失败不交由主程序恢复业务 |
| 释放相机读取机会 | 原拷贝身份、当前归属和实际读取结束依据可靠，满足重试或取消的释放条件 | 原拷贝的机会变化、相关业务事实及历史，见[读取机会](waiting.md#相机读取机会与未完成责任) | 触发同相机候选重新判断；下一次授予仍核对资格、排序及占用 |
| 释放设备活动占用或结束启动保留 | 原占用或保留责任可靠，满足所属业务的释放条件 | 原活动占用的变化，或结束启动保留的动作及流程变化、相关结果、所属历史及适用报告目录；具体边界见[活动与启动保留](waiting.md#设备活动启动保留与未完成责任) | 重新检查候选资格与顺序；释放不自动授予下一候选机会 |
| 固定设备文件或集合 | 驱动归属、写完及集合依据分别可靠 | 文件记录、活动的检查状态、结果依据及历史 | 具备内部处理资格时可读完整文件；正式取回仍等登记 |
| 记录拍摄结束 | 所有适用结果已确定；在事务中再次检查取消和已有终态 | 拍摄终态、正式产物及关联、内部文件提升、父计划变化及历史 | 沿固定来源关系通知依赖方；取回选择与范围清理集合由各自事务保存，见[来源处理](waiting.md#来源结束的共同提交) |
| 授予文件资格 | 逐产物按计划时间排序，同时间取回优先；检查全部有效限制及已有读取者 | 获准取回的资格、依赖、交付、拷贝、目标文件及读取流程共同建档；清理限制或逐项拒绝及产物派生状态按各自分支保存 | 获准后才能准备读取或进入删除；不能按协程唤醒顺序抢先 |
| 保存可靠拷贝段 | 工作线程已结束本段写入并完成要求的同步；轮次和原进度一致 | 可靠字节、相关文件事实及历史 | 从已提交位置推进下一段；保存未知先停下核实 |
| 开始整片重拷 | 摘要确实不一致、原调用已结束、有额外轮次与读取资格 | 原身份下增加重拷数、归零可靠进度、重置待办及历史 | 截断/重建并同步后另记重置完成，再读取 |
| 保存副本准备完成 | 完整长度、目标摘要、比较结果及同步可靠 | 交付准备状态、完整文件事实、取回项源依赖解除及自身历史、适用目录 | 后续仅依赖独立副本；按受影响产物通知清理重新检查，不必等其他来源或客户端确认 |
| 记录交接意图与结果 | 先保存意图；实际移动和目录同步在事务外完成 | 分别保存交接意图、可靠完成或未知/失败结果、文件所有权及历史 | 完成事实成立后取回可汇总；不能在缺失文件时自动重投普通交付 |
| 推进清理 | 目标固定、限制生效、已有读取已停止；删除与查询分别预算 | 删除/查询尝试、逐项状态、文件事实、产物可用性与清理汇总及历史 | 已清理结果可以满足其他请求；保留各请求自身结果 |
| 应用取消 | 固定目标；按派发实际阶段及停止能力判定 | 目标取消标记、本次取消效果、必要独立收场责任及历史；或可靠拒绝 | 目标独立继续收场，发起者取消不撤销已生效责任 |
| 保存撤回结果 | 原交付和原撤回责任，实际文件位置及操作结果 | 交付自身事实、仍在等待的取消交付项、适用目标汇总及历史 | 不删除 `processing`；旧取消请求已终态时不改其结果 |
| 清理中间文件 | 归属和用途可靠，相关实际操作已结束，符合本次额度 | 文件清理实际结果、适用业务变化、历史清理游标及历史 | 后续从可靠游标继续；失败保留责任但不原地重试 |
| 冻结报告 | 同一事务所见的完整历史边界、业务水位、ACK、未结束同步 | 报告固定依据及管理历史 | 在独立进程按原边界分批恢复和编码 |
| 记录报告发布 | 原报告、确定字节、移动及同步证据 | 每次成功发布、报告投影、满足的本地同步责任、报告动作成功及父计划变化 | 报告管理自身不触发报告；动作结果变化正常报告 |
| 吸收 ACK | 有效且真实存在的报告；不以报告 ID 大小比较业务水位 | 单调累计水位和所有合格同步结束 | 同水位 ACK 也能结束同步；不生成确认 ACK 的报告 |
| 保存可信时间 | 正常启动检查通过，使用原下界及实际检查读数 | 下界和历史；每会话至多一次 | 才进入普通执行；后续业务事务不顺便推进下界 |
| 保存快照 | S 是完整边界，内容及计数属于 S，对象真实存在 | 快照及按写事务最新计数计算的进度 | 无新权威事件、无新业务水位，不单独延长会话 |

一个表中的操作可以组合成同一 SQLite 事务。例如显式同步开始、动作开始和计划开始必须共同提交；失败或成功汇总也可在最后一个逐项结果事务中完成。表中拆行是责任说明，不授权拆开已经规定的原子边界。

## 关键状态组合

| 已保存事实与外部阶段 | 恢复依据与动作 |
| --- | --- |
| 尚无调用意图 | 不推断外部操作发生；仍须核对是否有其他原责任记录 |
| 意图已保存，进程中断前是否派发不明 | 保留可能效果，核实原目标；不能仅凭有剩余额度重新发令 |
| 读取尝试没有可靠失败结果，文件进度已保存 | 核实源身份和目标长度后继续原尝试；目标超出可靠长度的尾部按拷贝规则处理 |
| 读取尝试已经失败 | 保留旧失败；本次新增尝试仍从原累计数继续，重启只重新计时 |
| 文件已写完，准备完成事务未确认 | 读取依赖仍未确认解除；核实同步、摘要及提交结果，不凭长度解锁清理 |
| 普通交付有移动意图，准备、ready、processing 均无文件，且没有可靠完成记录 | 按交接结果无法确认保存失败，不重拷、不生成第二个交付 |
| 报告文件不在交接目录，但原报告尚需补投 | 根据冻结历史重建相同字节，沿用报告 ID；不套用普通交付的最终失败规则 |
| 取消已生效，旧调用随后返回 | 保存真实设备或文件结果，继续必要收场；不把目标改成普通成功或失败 |
| 删除可能已经发生后取消 | 本项取消不解除不可撤销限制；其他请求和原产物事实保持 |
| 源文件后来被清理，交付副本此前已可靠准备 | 交付继续依赖自己的完整副本，不能因源文件缺失撤销准备事实 |
| 动作已终态但设备或文件仍有责任 | 按独立记录继续符合范围的收场；不重开动作，不恢复普通重试额度 |

## 查询接口与分页

所有列表接口接受限定的父对象或业务区间、固定历史上界、最后一项稳定 ID 及正整数批量上限。返回本批结果和下一位置，错误不返回空批；达到末尾才返回完成。生产实现可以调整接口组织，但必须保持这些语义。

调度查询按范围加载未完成动作、有效启动责任、仍占用设备的活动及适用文件责任，并独立发现已结束流程下尚未结束的尝试；不遍历全部历史计划。报告对象选择与对象状态恢复分别使用目录索引；父对象按需补齐。对同一完整边界查询到的数据才能一起用于历史报告，不能将分批读到的新投影混合为过去状态。快照读取不授予写入或设备执行资格。

## 实现与验证门槛

结构检查验证每个表的主键、引用、唯一性、索引及行内状态组合。生产持久化实现还必须用真实 SQLite 验证以下完整链路：原子受理及并发重送、意图先于副作用、集合一次固定、资格与删除竞争、可靠段与重拷、准备完成与依赖解除、普通交付失联、取消与迟到结果、残留收场、报告冻结与 ACK、快照准备期间的新变化。

每条链路覆盖提交前中断、确认回滚、提交成功但通知尚未交付、提交结果未知以及重启读取。相同历史分别正常应用、从初始状态回放、从快照正向恢复和从新投影逆向恢复，结果应一致；只对实际改变的对象增加计数。软件集成使用受真实驱动契约约束的替身，不连接具体设备，也不把进程中断等同于物理断电保证。
