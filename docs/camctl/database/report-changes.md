# 报告变化目录与字段依赖

[数据库入口](../database-schema.md) · [一致性验收](consistency-verification.md)

## 历史恢复关联与报告变化目录

设备文件 F 已被登记为产物 O，事件 E 保存 F 新取得的 SHA-256。F 的历史关联指向 E，F 的累计变化计数增加；O 自身记录未变，其历史计数保持。报告变化目录登记“事件 E 需要更新产物 O”，报告选中 O 后分别恢复 O 与 F 在 H 的状态，再生成 O 的 `checksum`。目录只保存事件和应报告对象的关联，不保存第二份文件校验值。

### 两类目录的结构与职责

历史恢复与报告选择使用独立的派生目录。全部目录都从权威事件及事件发生时的业务关系生成，可按相同规则重建；不能作为独立业务事实写入。

| 目录 | 一行表示什么 | 字段及约束 |
| --- | --- | --- |
| `entity_event_links` | 一条事件改变了某个对象自身需要恢复的记录 | `id`、`entity_type`、`entity_id`、`event_id`、`change_count`；对象与事件唯一，对象与累计计数唯一，不保存报告选择用的 `change_seq` |
| `report_entity_changes` | 一条事件使某个现有报告实体需要更新 | `id`、`entity_type`、`entity_id`、`event_id`、`change_seq`；对象与事件唯一，业务序号非空且等于事件的业务序号，不保存或推进对象变化计数 |

目录采用单列整数主键。历史目录包括设备文件、主机中间文件及其他历史对象；报告目录的目标限定为动作、交付、产物、计划和计划文件诊断。设备文件、中间文件、报告发布管理、ACK 等内部对象不作为报告目录目标。多态引用按统一对象类型登记校验，编号范围在枚举登记中统一维护。

同一对象可因同一事件同时出现在两类目录中，也可只出现在其中一类。报告目录记录不是待消费的消息，发送报告或收到 ACK 不删除或改写它；各次应报告变化永久保留，不能只保存最后一次业务序号。

| 事件对对象的影响 | 历史恢复目录 | 报告变化目录及计数 |
| --- | --- | --- |
| 对象自身记录变化，且自身报告字段变化 | 保存恢复关联 | 登记该对象；自身变化计数按事件增加一次 |
| 对象自身记录变化，仅为内部事实 | 保存恢复关联 | 不因该内部变化登记报告对象；自身变化计数仍增加 |
| 对象自身记录未变，但独立文件的变化改变其报告字段 | 不为该对象保存恢复关联 | 登记该报告对象；该对象自身计数不变 |
| 独立交付变化使所属取回结果变化 | 交付按实际变化保存恢复关联 | 登记交付，报告补齐所属取回；取回仅因补齐不增加目录记录或计数 |
| 仅引用某对象，既未改变其自身记录，也未影响其应报告内容 | 不保存该对象的恢复关联 | 不登记该对象，不增加计数 |

### 公开字段的依赖登记

每个公开字段均须登记它读取哪些历史事实、何时出现、如何转换，以及这些事实变化后应更新哪个报告对象。字段生成和报告变化判断使用同一份机器登记；新增字段时同时补齐来源和变化规则，不能只修改编码器。

具体列、关系、出现条件及固定转换由[机器登记](report-dependencies.json)统一定义，[登记格式与消费规则](report-dependencies.md)说明其解释方式。下表用于说明覆盖范围；字段生成与变化判断读取机器登记，不能把本表另外编码成一份映射。

| 公开事实 | H 时的数据来源 | 变化后须选中的报告对象 |
| --- | --- | --- |
| 计划及动作共同字段、输入和错误 | 所属计划或动作的自身记录 | 对应计划或动作 |
| 检查、修复及取消内容处理 | 原拍摄动作所属处理记录 | 原拍摄动作；单次尝试变化但公开结果未变时不触发 |
| 动作结束后的设备执行情况 | 原动作所属设备执行记录 | 原动作；第一版由原拍摄动作的设备活动记录提供事实，按[设备执行情况](../../architecture/report-format.md#动作结束后设备是否仍在执行)判断出现和消失 |
| 取回失败列表 | 自身来源选择、取回项，以及 H 时关联的全部交付 | 自身失败选中取回；交付失败选中交付并补齐取回 |
| 清理和取消逐项结果 | 所属动作的处理项；这些行的变化与相关业务事实共同保存 | 所属清理或取消动作 |
| 产物大小和摘要 | 产物引用的独立文件在 H 的事实 | 产物；只改变文件时产物历史计数仍不增加 |
| 产物可用性、清理、媒体及来源关系 | 产物自身及其所属来源关系 | 产物；按既定规则共同保存派生变化 |
| 交付状态、错误、名称、完整大小及摘要 | 交付自身、所属拷贝及适用目标文件在 H 的可靠事实 | 交付，再补齐取回及计划；字节进度变化本身不触发 |
| 自动预览展示关系、报告动作结果、输入诊断 | 对应动作或诊断自身事实 | 所属动作或诊断 |

来源动作结束及实际新产物按各自变化报告；依赖方取得交付、逐项失败或最终结果时再报告这些事实。内部配置采用、拷贝分段、查询和停止尝试仅在确实改变公开结果时产生对应报告目标。报告重建只组合 H 的事实，不重新执行设备观察、调度或完成判断。

### 文件到报告字段的依赖

判定以已有报告字段的实际值及存在性为依据；某列被写入不等于必然产生报告变化。事件契约登记源字段、适用关系、字段映射及报告目标规则。该登记与报告字段生成共用权威映射，不在写入器、报告生成器和检查脚本中分别维护相互独立的完整清单。判定只读取本次受影响字段及其必要关联，不生成或比较整份报告。

| 保存的变化与适用关系 | 报告处理 |
| --- | --- |
| 设备文件的 `sha256` 或 `size_bytes` 改变，且已有正式产物通过 `device_file_id` 引用它 | 产物 `checksum` 或 `size` 的公开值变化时登记该产物 |
| 主机文件的 `sha256` 或 `size_bytes` 改变，且已有正式产物通过 `intermediate_file_id` 引用它 | 产物相应公开值变化时登记该产物 |
| 设备文件的存在性、观察错误等使产物可用性或清理汇总实际变化 | 按原派生规则共同保存产物字段；产物同时取得自身历史关联及报告目录记录。文件观察本身不跳过派生规则直接替换产物状态 |
| 文件的原名称或媒体类型得到可靠补齐，并同步改变已登记产物的对应列 | 按实际产物变化登记报告；仅内部文件字段变化且产物公开值未变时不登记 |
| 主机文件的内部维护状态改变，未改变任何公开业务结果 | 只保存文件历史，不因此登记报告对象；内部责任继续按所属流程处理 |
| 普通交付目标文件的可靠大小或摘要改变 | 按交付已有的完整大小及摘要来源规则核对公开值，实际变化时登记交付；不能用部分长度替代完整大小。拷贝、目标文件及交付共同变化时按对象与事件去重 |
| 文件事实使已有的录像处理、取消后废弃清理等业务汇总改变 | 由所属事务保存相应处理记录，再按其实际报告字段变化登记动作；文件的操作结果不直接改写动作终态 |
| 原动作所属设备执行记录变化，改变已终态动作的 `device_execution` 内容或出现条件 | 登记原动作；后续由其他动作发起停止时仍更新原动作的设备执行情况，不改变原动作终态 |
| 源文件的新观察尚未被某次拷贝采用，或源文件在依赖解除后被删除 | 不改写各次拷贝已保存的固定源依据，也不因此登记所有引用该源文件的交付；拷贝实际保存了新的校验或失败事实时，按该次变化处理 |
| 文件尚未对应任何受影响的现有报告字段，或仅内部定位、归属证据、能力声明变化且公开值未变 | 只保存文件历史，不因文件存在或被引用而分配业务序号。动作处理结果或产物登记等另外发生的变化分别按其事件处理 |

同一事件对同一报告目标命中多条规则只登记一次；分别影响多个目标时全部登记，共用事件的业务序号。文件变化没有公开影响时，不对全部引用者传播更新。产物或交付入选后，父对象继续按既定结构补齐，不额外产生事件或业务序号。

### 保存、恢复与历史关系

事件处理器在原业务写事务内核对真实前值和关联，保存实际业务变化，并派生恢复关联、报告目标和计数。存在至少一个报告目标时，为事件分配一个 `change_seq`；没有报告目标时该值为空。关联读取失败、应有目标缺失或归属矛盾均按状态库错误处理，不能当作没有报告影响而继续提交。目录、事件、投影及快照维护进度整体提交；回滚不留下目录记录，提交未知沿原事务身份核实，重查不重复分配序号或增加计数。

报告影响按事件发生时已建立的关系判断。F 先取得摘要、后来才登记 O 时，旧文件事件不补挂 O；O 的创建事件负责使 O 入选，并带上当时已知的文件事实。同一事务中先保存文件事实、后创建产物或交付时也遵守该规则，最终仅公开完整提交边界。新建或改变业务关联本身影响公开内容时，由建立或改变关联的事件登记相应报告目标，不能只依赖文件恰好同时变化。

重建报告目录时，按历史顺序及原事件版本重建当时的业务关系和报告影响，核验既有事件业务序号及目录预期。不使用数据库最新引用关系解释旧事件，不修改旧事件或重新分配业务序号。报告生成只读取可靠目录；必要目录缺失或损坏按状态库错误处理，不临时扫描当前关系猜测应报告对象。

### 报告选择与查询范围

报告按固定 `(from_wm, to_wm]` 从 `report_entity_changes` 选择目标，核对事件属于 H 以内的已提交历史，按对象类型及整数 ID 去重和分页，再补齐 H 时的父对象。对象自身恢复只读取 `entity_event_links`；生成字段所需的交付或文件分别恢复到同一 H。普通增量、完整同步和按历史起点同步使用同一目录规则，ACK 的后续变化不改写已冻结范围。

报告目录同时需要按业务区间定位的访问路径和按对象 ID 续读的访问路径。以下规则控制候选加载和续读，不将全部目录、引用者或完整对象载入 Python 内存。索引及查询须使用有代表性数据和实际统计信息验证，目录拆分不代替查询验证。

## 报告对象选择的索引与分页

某份报告只涉及最近两百条变化时，先定位这两百条关联，再取出其中不同的对象即可。完整同步涉及大量对象时，逐页按对象 ID 继续读取；每页都重新按业务区间扫描并排序，会重复处理前面已经筛选过的关联。

两条路径使用同一个冻结范围和入选规则，仅选择对象身份，不读取完整对象或事件正文。输入包含状态库身份、报告的 H、`from_wm`、`to_wm`、对象类型及实体批次上限。先核验冻结记录、完整历史边界与业务水位的对应；可靠目录保证 `change_seq` 与所属事件一致，范围内关联属于 H 以内的历史，后续提交的序号不会进入该范围。目录缺失、损坏或冻结依据不一致属于状态库错误，不能通过放宽范围继续生成。

### 两种索引

`report_entity_changes.change_seq` 非空，以下两个索引覆盖目录中的全部关联：

```sql
CREATE INDEX report_changes_by_sequence
ON report_entity_changes(entity_type, change_seq, entity_id);

CREATE INDEX report_changes_by_entity
ON report_entity_changes(entity_type, entity_id, change_seq);
```

对象与事件的唯一性仍由目录定义保证。两种索引都只覆盖候选选择所需的列；对象历史恢复继续使用独立的恢复目录，不将报告索引当作历史恢复索引。

### 有上限的候选预查询

第一版候选容量为 **4096 条目录关联**。这是选择算法的内部工程上限，不是报告对象总量限制，也不是新增用户配置；它与每页返回对象数分别管理。每个冻结范围和对象类型只在开始选择时执行一次预查询，最多取得容量加一条，用于判断能否完整容纳本次候选：

```sql
SELECT change_seq, entity_id
FROM report_entity_changes
WHERE entity_type = :entity_type
  AND change_seq > :from_wm
  AND change_seq <= :to_wm
ORDER BY change_seq, entity_id
LIMIT :probe_limit;
```

`:probe_limit` 为上述容量加一。该查询使用业务序号范围索引，不带对象分页游标、不执行 `DISTINCT`，防止为了找出少量不同对象而无界扫描大量重复关联。水位、对象 ID、类型和限制参数均按验证后的整数绑定，不接受数字字符串、浮点数或布尔值替代整数。

| 预查询结果 | 后续选择路径 |
| --- | --- |
| 查询失败或取消 | 按相应错误或取消处理，不解释为范围为空 |
| 没有目录关联 | 本类型选择完成 |
| 返回条数不超过候选容量 | 已取得该类型在固定范围内的全部关联。在这个有上限的候选集中提取 ID、去重并按整数升序排序，释放关联行；按实体批次上限逐页交付 ID，不为后续页面重新查询业务区间 |
| 返回容量加一条 | 尚未读取完整集合，不能将前面这些行作为第一页输出。释放预查询结果，采用下面的按对象 ID 续读路径 |

容量按关联行数判断，同一对象重复变化也占容量；不执行全范围 `COUNT` 来决定路径，不仅根据 `to_wm - from_wm` 或“完整同步”名称推测工作量。应用内候选存储的上限与数据库总规模无关，排序仅处理有界的整数 ID；类型处理完成后释放该集合。任务重启后可以从冻结范围重新选择，不将上次预查询缓存作为可靠历史。

### 大范围按对象 ID 续读

首批的 `after_id` 为 0，以后取上一批最后一个对象 ID。`page_limit` 使用本次会话的 `history.entity_batch_size`，完整参数规则见[实体读取批次](../historical-state-query.md#实体与事件读取批次分别配置)。

```sql
SELECT DISTINCT entity_id
FROM report_entity_changes
WHERE entity_type = :entity_type
  AND entity_id > :after_id
  AND +change_seq > :from_wm
  AND +change_seq <= :to_wm
ORDER BY entity_id
LIMIT :page_limit;
```

此写法让对象 ID 承担续读位置，业务水位作为取出的索引项过滤条件。`+change_seq` 使用 SQLite 的一元加号，阻止该条件成为业务序号索引的范围查找条件，避免每页又选择区间扫描与整体去重排序。它也会去除表达式的类型亲和性，因此目录列必须是非空整数，绑定的水位也必须是整数；不能删去输入类型约束。相关行为见 [SQLite 一元加号规则](https://www.sqlite.org/optoverview.html#disqualifying_where_clause_terms_using_unary_)。

在目标 SQLite 版本及实际索引集合上，查询应从对象类型和 `entity_id > after_id` 定位覆盖索引，按 ID 连续去重，不使用全范围临时排序。验证通过的查询形态作为实施依据；升级 SQLite、改变索引或增加筛选条件时重新验证计划与实际工作量，不能仅依据一元加号或索引名称宣称性能成立。`INDEXED BY` 不作为未经验证的索引调优开关，其强制性质见 [SQLite 索引约束说明](https://www.sqlite.org/lang_indexedby.html)。

查询成功返回空集合表示本类型读完；有结果时交付升序且无重复的 ID，下一页严格越过最后一个 ID。结束本页查询及短读事务后，再恢复对象、补齐 H 时的父对象并生成内容。更改页大小不改变入选集合、排序或报告字节。这里的游标属于固定范围内的全局对象类型选择；父对象补齐和按父对象读取子集合使用各自已有接口和分页位置，不混用游标。

### 成本与故障边界

小范围路径至多保留候选容量加一条小记录，且只做一次范围读取。大范围路径不保留全量对象身份，工作量来自按 ID 向后读取的目录索引及每页定位，不应随页数重复扫描整个业务区间或已经越过的对象前缀。

大范围路径仍可能读取该类型不在业务区间内的历史关联；一个对象历史很长或匹配对象稀疏时，单页读取量也可能明显超过返回对象数。候选容量是第一版的固定工程选择，不承诺对所有分布都选择最优计划，也不承诺 `LIMIT` 限定磁盘读取量或查询时长。现有报告时限、取消及短读事务规则继续适用。增加目录总量、重复变化密度及区间外关联时，验收记录计划和执行工作量；目标设备上的延迟、内存与 I/O 单独测量。

两条路径都只读主状态库，不创建持久化候选表或新的临时文件责任。事务间新增的报告变化只追加更大的业务序号，不能进入已冻结范围；既有目录关联不改写。切换路径发生在交付第一批之前，读到部分候选后失败不能交付不完整报告或继续使用未经核实的另一状态库。
