# 来源关联与取回明细

[数据库设计入口](../database-schema.md) · [CLI 资料入口](../README.md)

本页定义自动预览关联、固定来源成员、逐来源文件选择和逐目标取回责任。固定选择方式见[取回执行定义](execution-definitions.md#取回执行定义的选择方式)，选中文件的副本与交付事实见[产物、交付与文件记录](outputs-files.md)。

完整字段、状态编号与空值规则见[来源及处理明细字段](workflow-fields.md)，结构约束见 [workflows.sql](schema/workflows.sql)。

## 自动预览取回关联

`auto_preview_links` 保存自动预览取回动作与来源拍摄动作之间的明确关联，以及受理时可靠取得的自动用途和设备能力依据。两个动作仍分别保存在 `actions` 中；关联表回答哪个取回动作负责自动获取哪个拍摄动作的预览，`output_origins` 则回答某份预览或修复成品对应哪份原文件。

关联及能力依据与计划、动作和对应历史在同一受理事务中保存。重启和同一请求重送沿用原受理结果，不依据后续设备能力重新计算。关联属于取回动作自身状态，历史恢复和对象快照包含这些信息；保存关联本身不增加来源拍摄动作的历史变化次数。

关联按[自动取回的责任](../../architecture/preview-obtaining.md#自动取回的责任)区分有效关系与失败时保留的依据：

| 受理结果 | 保存与使用规则 |
| --- | --- |
| 自动预览取回通过校验 | 保存同一计划内的来源拍摄关联及能力依据；同一来源至多有一个有效的自动预览取回 |
| 多个自动预览取回可靠地声明同一来源 | 所有冲突取回均初始失败；分别保留可靠关联、原输入和完整冲突原因，不能通过只保存其中一条关联消除冲突 |
| 自动预览取回存在其他参数错误 | 保存可靠取得的自动用途、来源及能力依据；无法确认的信息不补造，原输入和错误由动作保存 |
| 普通手动取回 | 按普通取回规则保存来源，不建立自动预览关联 |

关联记录的存在不表示动作已通过校验或具备执行资格。报告中的 `action.automation` 按[预览与范围选择的报告契约](../../architecture/report-format.md#预览与范围选择的报告契约)生成；取消流程根据已保存的自动用途和来源关联，按[取消联动](../../architecture/preview-obtaining.md#取消联动)处理相关取回及交付。

## 取回与范围清理的来源成员

`action_dependencies` 由取回和范围清理共用。每条记录表示一个取回或清理动作以某个拍摄动作为产物来源；同一所属动作的来源成员不重复。来源成员描述要处理哪些拍摄动作的产物，文件选择则描述最终要处理哪些正式产物，两者分别保存。

| 字段 | 存储类型与约束 | 含义 |
| --- | --- | --- |
| `id` | `INTEGER PRIMARY KEY`，正整数 | 本条来源关联的身份 |
| `action_id` | 非空 `INTEGER`，正整数，外键引用 `actions.id` | 使用该来源产物的取回或范围清理动作 |
| `depends_on_action_id` | 非空 `INTEGER`，正整数，外键引用 `actions.id` | 产生正式产物的来源拍摄动作 |

三个身份字段均遵守[主键与身份引用](common.md#主键与身份引用)的 64 位整数范围；关联自身的主键按该表分配，两个引用沿用所指动作的身份。表设置 `UNIQUE (action_id, depends_on_action_id)`，禁止同一所属动作重复关联同一来源，允许不同取回或清理动作引用相同来源。两个外键保证引用真实动作，业务写入流程同时核对所属动作和来源动作的类型、输入范围及适用的自动预览关联。来源是否成功不决定关联能否成立，失败或取消的拍摄仍可能留下正式产物。

动作、组及计划来源均保存为具体来源动作的成员关系。取回支持组来源，范围清理仅支持动作或计划来源；计划中的取回、清理和报告等非产物来源动作不加入集合。原始计划、组或动作描述保留在所属动作参数中，本表保存成员身份；计划 ID、组名、选择方式和文件选择结果由各自记录承担。来源等待的判断见[来源处理规则](waiting.md#来源等待的记录与转换)。

来源成员按[取回来源规则](../../architecture/obtaining-outputs.md#校验与失败处理)和[清理参数规则](../../architecture/output-cleanup.md#清理参数)在适用时点解析。需要在首次受理时解析的本计划引用，与计划和动作一起保存；需要在执行时核实的实例引用，在取得相应执行资格后解析。完整来源集合、所属动作的来源解析状态及对应历史在同一事务中保存。集合固定后，重试和重启恢复沿用原成员，不重新扩大范围。

所属动作的处理状态区分尚未确定来源、来源集合已可靠固定和来源解析已失败。成员记录的数量不能替代这些状态；来源不存在、类型不适用和数据库查询失败分别按所属流程处理，不能统一解释为来源集合为空。精确 ID 清理直接处理指定产物，不建立范围来源成员。

| 来源成员的使用场景 | 成员记录与后续流程的边界 |
| --- | --- |
| 普通取回 | 每个来源完成拍摄及适用的产物处理后，可以分别固定文件选择和准备副本；全部来源及条目满足取回条件后，才将成功准备的文件移入 `ready` |
| 自动预览取回 | 来源成员从已保存的 `auto_preview_links` 关联派生，不能独立修改来源；关联存在仍不替代动作的执行资格判定 |
| 范围清理 | 等待全部来源及其产物处理结束后，固定完整的清理文件集合，再按清理规则逐项处理 |

`action_dependencies` 保存稳定的来源成员关系。逐来源的选择进度、选中的文件和处理结果分别由取回或清理流程保存，不因为共用关系表而共用状态机。来源成员属于引用它们的取回或清理动作自身状态，随该动作进行历史恢复和快照保存；仅建立来源引用不增加被引用拍摄动作的历史变化次数。

事务未提交时，来源集合不能作为已经固定的执行依据；提交结果未知时先按状态库规则核实，不重新解析或重复创建关系。正常恢复沿用原关联身份，历史恢复使用目标历史边界处的成员，不用之后的来源或选择结果解释过去。业务执行不删除已经固定的来源成员。

验证字段非空、正整数范围、两端外键及组合唯一性；同一关联重复写入受到约束，不同所属动作引用同一来源合法。业务验证覆盖动作、组和计划来源展开、非产物来源排除、自动预览来源一致、精确 ID 清理不创建成员，以及失败或取消的拍摄仍可作为来源。组合真实数据库、受理和执行解析流程验证完整集合与状态及历史原子保存，回滚不残留部分成员，提交未知先核实，重送与重启保持成员及身份。无成员时仍按所属动作的来源解析状态判断，不能据行数推断解析成功、失败或尚未完成。

## 取回的来源选择与目标明细

取回动作使用两张明细表保存文件选择和逐项处理。一个来源尚未结束、一个来源已结束但没有产物，以及一个已选文件尚未创建交付，分别需要保留不同的处理状态，不能仅凭交付记录是否存在判断。

| 明细表 | 一条记录的职责 | 与其他表的边界 |
| --- | --- | --- |
| `obtain_source_selections` | 保存一个取回动作对一个固定来源的文件选择进度，以及适用的来源级选择结果 | 来源成员由 `action_dependencies` 确定；具体文件和显式请求目标由 `obtain_items` 保存 |
| `obtain_items` | 保存一个取回动作的一个具体目标、读取资格及依赖状态，包括实际选中的产物，或显式指定但尚待判定、判定无效的请求目标 | 可靠确认产物存在且属于指定来源时才建立产物关联；实际交付创建后关联 `deliveries` |

取回进入执行且来源集合已固定后，每个固定来源恰有一条来源选择记录。选择状态及报告含义遵守[预览与范围选择的报告契约](../../architecture/report-format.md#预览与范围选择的报告契约)：尚未完成选择时为 `pending`；完整选择可靠保存后为 `fixed`，其中实际选中的产物可以为空。来源选择状态与完整选择结果在同一事务中保存；重试和恢复不重新选择或扩大已固定集合。

首次固定以所属取回动作保存的 `execution_spec_json.selection_mode` 为选择方式，精确 ID 的值与顺序从该动作的 `input_fields_json.params.output_ids` 取得。写事务读取当前可靠的来源和产物事实，按共同选择规则核对待保存快照的完整条目、顺序、选择依据、比较大小及错误。快照与原请求或当前事实不一致时，整笔事务回滚，选择保持 `pending`；不能用调用方提供的结果替代缺失或无效的执行定义及原请求。已经固定的选择按原保存结果恢复，不重新应用当前目录。

| 来源或目标的情况 | 保存位置与结果 |
| --- | --- |
| 来源整体尚未可靠确定 | 由所属动作保存来源解析状态和实际错误，不虚构来源选择记录或无产物结果 |
| 来源已固定，但该来源的文件选择尚未完成 | 来源选择记录保持 `pending`，不以没有目标记录表示选择已完成 |
| 来源选择已完成，可靠确认存在选中产物 | 来源选择记录为 `fixed`；每个选中产物在 `obtain_items` 中保存身份和选择依据 |
| 来源选择已完成，没有选中产物 | 来源选择记录为 `fixed`；是否构成来源级失败按取回规则判断并保存，空选择本身不决定成功或失败 |
| 显式请求目标尚待判定 | 目标明细保留请求值和未完成状态；尚未可靠取得的产物或交付身份不补造 |
| 显式请求目标可靠确认不存在或不属于指定来源 | 目标明细保存请求值及具体失败原因，不把该请求值当成选中产物关联，不创建交付 |
| 实际选中的产物在创建交付前最终失败 | 目标明细保存实际产物关联及最终错误，不为表达失败创建交付 |
| 目标已有交付记录 | 目标明细关联交付；交付阶段的进度与最终结果由交付事实提供，不在两处独立维护结论 |

实际选中产物的选择依据包括适用的原文件关联、预览关联及比较时保存的完整大小，具体内容遵守[选择契约](../../architecture/obtaining-outputs.md#产物选择)。显式请求中的多个无效 ID 分别保留目标明细，不能因为缺少实际产物关联而合并。来源级无产物失败由来源选择记录表达，不创建虚假的文件目标。

报告通过产物、交付及逐项最终失败表达实际结果；逐项最终失败按[取回失败项的报告表达](../../architecture/obtaining-outputs.md#取回失败项的报告表达)从来源选择、目标明细及已关联交付的历史事实生成。同一最终失败只报告一次，临时等待和单次尝试失败不自动成为最终失败。

两张明细表属于取回动作自身状态，其历史恢复和对象快照包含相应记录；已关联交付仍按交付对象自身的历史与快照规则管理。明细、受影响的动作状态及对应历史按业务事务共同保存，同一请求重送或重启恢复沿用原记录和已确定结果。

## 取回的读取资格与依赖

普通取回以 `obtain_items.delivery_id` 永久表达该项曾经取得读取资格的事实，以 `source_dependency` 保存当前是否仍需保留源文件。资格由取回项自身的交付关联推导；当前是否允许继续读取，还须检查取消、最终结果、操作预算及其他执行条件。清理通过产物关联查询 `source_dependency = 1` 的取回项，不能用交付是否存在或是否终态代替源依赖判断。

本节适用于普通取回的全部来源方式及自动预览取回；录像内部检查和修复输入继续由原录像处理责任管理。其拷贝与读取流程遵守[共同建立规则](file-fields.md#拷贝与读取流程的关联)。

### 资格判定与保存边界

共同建档接收已可靠选中的取回项及产物身份、源文件身份和完整长度等建档依据。在写事务中核对动作及条目资格、取消与已有结果、设备绑定等执行前提、有效删除限制，以及当前相关候选的业务顺序。候选按[逐产物资格授予规则](../../architecture/outputs.md#延后执行时的取回与清理顺序)协调；选择结果的保存先后和协程唤醒顺序不能代替计划时间及同时间取回优先规则。

按以下顺序判断；取消及已有结果的处理仍须保留必要的独立收场责任：

| 事务内核对结果 | 保存与后续行为 |
| --- | --- |
| 必需事实无法可靠读取、已有责任缺失或记录矛盾 | 按状态库错误处理，不推测允许读取，不创建替代责任 |
| 取消已生效，或该项已有最终结果 | 保持原事实，按所属取消或收场规则处理，不重新授予资格 |
| 已有完整交付关联及准备责任 | 复用原身份及已保存的源依赖；后来的删除限制不撤销原资格 |
| 尚无资格，已有有效删除限制 | 保存本项最终失败，不创建交付 |
| 尚无资格，已可靠确认产物不可取回或必要执行前提不满足 | 按所属错误规则保存结果，不创建交付 |
| 尚无资格，仍需完成必要确认或等待排序靠前的合格候选处理 | 保持尚未建档，按所属流程继续确认或协调，不提前建立源依赖 |
| 尚无资格，符合排序与资格规则，建档依据可靠且完整 | 共同保存交付、源依赖及全部准备责任，提交后继续 |

成功建档在同一数据库事务中保存以下事实：取回项关联唯一交付并进入 `DELIVERY_CREATED`，`source_dependency = 1`；交付处于待准备状态；目标中间文件具有稳定路径和交付归属；拷贝具有可靠源身份、完整长度及初始进度；唯一 `READ_FILE` 流程通过 `operation_runs.copy_id` 关联拷贝，尚未消耗读取尝试。上述事实的历史、对象关联和适用业务变化序号共同提交。

建档保存责任和初始状态。目标路径登记不表示文件已经存在，拷贝建立不表示已经读取字节；实际文件创建、读取、写入和同步在提交成功后进行。缺少可靠建档依据时，按所属文件确认或错误规则处理，不补造长度、摘要或完成状态。

### 交付关联与源依赖的状态组合

在完整已提交边界，合法组合及其含义如下。交付关联一旦建立，失败、取消、撤回和中间文件清理均保留原值；每份交付的取回动作与产物必须与取回项一致。

| `delivery_id` | `source_dependency` | 含义及约束 |
| --- | --- | --- |
| 空 | 0 | 尚未取得资格；待判定、已选中、失败和取消由取回项自身状态区分 |
| 非空 | 1 | 曾取得资格，仍需保留源文件；交付、拷贝、目标文件记录及读取流程完整存在 |
| 非空 | 0 | 曾取得资格，源依赖已经可靠解除；后续使用独立副本或继续必要收场 |
| 空 | 1 | 非法，缺少与保护责任共同建立的交付关联 |

同一取回项的源依赖只在首次共同建档时从 0 变为 1，解除后保持 0。读取重试、续传和摘要不一致后的有限重拷发生在源依赖仍有效期间，沿用原交付、拷贝及读取流程。

已有交付后，先检查依赖是否已经解除；仍有效时，先处理所属动作已生效的取消及交付自身的最终结果，再按普通准备阶段判断。此处最终失败或取消来自对应责任记录，不要求将取回项的 `DELIVERY_CREATED` 改为交付终态。所需事实无法可靠确认时先核实或按所属错误处理，不推测解除依赖。

| 已有交付后的处理阶段 | 源依赖的保存规则 |
| --- | --- |
| 依赖已解除，随后发布、失败、取消、撤回或清理交付副本 | 保持 0；副本缺失或损坏按实际错误处理，原取回不重新建立源依赖 |
| 最终失败或取消，实际读取或后续重试尚未确认停止 | 保持 1，继续必要收场；失败或取消标记不证明读取已经停止 |
| 最终失败或取消，实际读取及后续重试已确认停止 | 可靠保存停止依据并将依赖设为 0，交付关联保持 |
| 副本完成写入、必要校验和落盘 | 与副本准备完成事实共同提交依赖为 0，交付关联保持 |
| 排队、读取、等待重试、校验或仍允许重拷 | 保持 1；排队未读取也要求清理保留源文件 |

相机读取机会由拷贝单独取得和释放。等待机会不消耗读取尝试；源内容全部读完且设备读取已结束时，可以释放相机机会，而校验及可能重拷仍要求保留源依赖。本地主机源文件拷贝不占用相机读取机会。相机机会、源文件保护及目标中间文件清理分别满足各自条件，不能用其中一项的解除推断其他操作已经安全结束。

### 中断恢复与历史归属

| 中断阶段或保存结果 | 恢复要求 |
| --- | --- |
| 建档事务未提交或确认回滚 | 本次资格、保护和交付责任均未生效；不执行依赖本次建档的文件操作 |
| 建档成功，目标文件尚未创建或读取尚未开始 | 复用已保存身份、路径及原源依赖，继续具有执行资格的准备工作 |
| 提交结果未知 | 核实原事务，确认前停止依赖步骤，不另建身份或提前操作文件 |
| 建档后文件创建、读取或校验失败 | 由原责任保存实际结果；依赖是否解除按失败或取消后的停止条件判断 |
| 副本已完整，但准备完成事务尚未提交或确认回滚 | 保留源依赖；恢复核实原副本，再共同保存准备完成与依赖解除 |
| 依赖解除已经提交 | 保持解除事实，按独立副本或收场责任恢复；不以历史资格重新读取源文件 |
| 恢复发现应有的交付、拷贝、目标文件记录或读取流程缺失、重复或归属矛盾 | 按状态库错误处理，不解释为尚未建档，不通过新建责任或清空关联掩盖矛盾 |

取回项的交付关联和源依赖属于取回动作自身历史及快照。恢复到完整边界 H 时，从该边界的取回项判断历史资格和源依赖，不读取交付最新状态补算。交付及其准备记录按自身历史恢复；共同建档、准备完成和依赖解除均保存可逆前后值，在完整事务边界检查跨对象一致性。回放不执行文件操作。

### 取回项与交付的状态职责

取回项保存本次请求的目标、选择依据、交付建立前的处理状态、永久交付关联及当前源依赖。交付保存独立副本的准备、发布、失败、取消和适用撤回事实。两类记录通过稳定关联共同表达一份文件的取回过程。

| 业务阶段 | 取回项保存的状态及事实 | 交付保存的事实 |
| --- | --- | --- |
| 显式目标尚未可靠判定 | `UNRESOLVED`，保留请求值 | 尚无交付 |
| 已可靠选中实际产物，尚未完成交付建档 | `SELECTED`，保留产物和选择依据 | 尚无交付 |
| 建立交付前目标处理最终失败 | `FAILED`，保存本项目标处理的错误，交付关联为空 | 不为承载该失败建立交付 |
| 建立交付前取消并结束目标处理 | `CANCELED`，保留已知请求和产物事实，交付关联为空 | 不建立普通交付 |
| 获得读取资格并共同建立交付 D | `DELIVERY_CREATED`、`delivery_id = D`、`source_dependency = 1` | 保存待准备责任，拷贝及读取流程按共同建档规则存在 |
| D 后续准备、发布或取得最终结果 | 保持 `DELIVERY_CREATED` 和原交付关联，源依赖按实际条件变化 | 保存本交付的实际进度、最终结果及适用错误 |
| D 后续撤回或所属残留文件清理取得结果 | 保持 `DELIVERY_CREATED` 和原关联；已经解除的源依赖保持解除 | 对应交付、撤回或文件清理记录保存实际事实，已有取回动作终态保持 |

`DELIVERY_CREATED` 表示本项已经建立交付，不表示交付仍在执行或已经成功。建立交付后，取回项不随 D 的失败或取消转为 `FAILED`、`CANCELED`，也不复制 D 的最终错误到本项错误字段。取回项自身的错误用于交付建立前的目标处理失败；有关联交付时，副本处理结果沿关联从交付取得。

整体取回的执行流程根据来源选择、取回项和关联交付共同判断是否仍有工作、是否满足发布条件及能否保存动作终态。不能仅凭全部取回项已为 `DELIVERY_CREATED` 就认定副本准备完成或取回成功。单次尝试失败且仍允许重试时，仅保存原操作结果；其他来源及文件继续按自身条件推进。取消、重启、重送及后续清理均保持原身份、关联和已保存决定。

### 取回项与交付的最终失败归属

取回项 601 已为产物 O 建立交付 D，D 在准备或发布副本时最终失败，具体失败原因由交付保存。取回项保持 `DELIVERY_CREATED` 及其与 D 的关联；本项目标在交付阶段的处理结果由 D 的事实提供，取回动作的失败列表由相应业务结果生成。

| 失败发生的业务阶段 | 最终失败事实的保存责任 |
| --- | --- |
| 尚未建立交付，目标不存在、不属于指定来源、不可取回或其他目标处理前提不满足 | 取回项保存本项目标处理的最终错误及可靠身份；不为承载错误创建交付 |
| 已建立交付，副本准备或发布最终失败 | 交付保存自身最终错误；取回项保持 `DELIVERY_CREATED` 和交付关联，本项目标在交付阶段的结果沿关联取得 |
| 单次操作失败，所属责任仍允许重试或核实 | 原操作记录保存实际结果，不据此提前生成取回项或交付的最终失败 |
| 最终结果确定后，残留副本清理或其他独立收场取得新结果 | 原最终失败保持，后续结果由对应责任记录保存 |

取回动作与交付均可向用户表达同一最终失败。历史查询按[同一边界查询规则](../historical-state-query.md#取回与交付的同一边界历史查询)取得关联结果。交付关联一旦建立继续永久保留，源依赖仍按实际读取及重试停止条件解除，不能从最终失败本身推断已经停止。
