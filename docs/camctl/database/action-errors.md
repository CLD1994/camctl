# 动作最终错误与分支覆盖

[动作错误字段](plans-actions.md#动作最终错误字段) · [公共错误登记](../../../protocol/errors/workflow-codes.json)

公共登记中带有 `action_error_id` 的条目构成格式 1 的动作最终错误全集。`action_error_id` 就是 `actions.error_code` 的数据库值；同条记录唯一确定公共 `code`、`stage` 和详情结构。编号显式分配，SQL 合法集合及未来 Python `IntEnum` 从该登记生成或核对，不能按清单顺序编号。其他条目服务于文件、处理项或取消明细，不能直接写入动作最终错误列。

## 选择顺序

先判断已有终态和生效取消，后判断普通执行结果。数据库不可用、事务未知、驱动定义无法加载等会话错误不由本表转换为动作失败。取消后的操作错误保存在操作或收场记录中，原动作继续按取消规则结束；已有终态永久保留。

| 动作与实际失败条件 | 最终错误 | 详情及下层事实 |
| --- | --- | --- |
| 受理时一般自身字段、设备能力、参数、时间、策略、组或引用组合不合法 | `action_validation_failed` | `issues` 保存全部错误的原字段路径、原因及实际提供的值；缺失值不补 `null` |
| 本计划名称引用不存在，且没有其他独立校验错误 | `source_action_not_found` | 保留原字段路径和名称 |
| 自动预览重复关联，且没有其他独立校验错误 | `duplicate_auto_preview` | 同来源及完整冲突取回名称 |
| 明确不支持自动预览，且没有其他独立校验错误 | `preview_not_supported` | 来源及参数类型 |
| 可靠确认未启动、没有待核实原尝试，尚在启动窗口内但启动次数已经耗尽 | `start_attempts_exhausted` | 实际上限与累计次数；窗口已经结束时按过期规则；次数达到上限不提前结束正在等待结果或核实的最后一次尝试 |
| 尚在启动窗口内，驱动确认不可重试的启动拒绝 | `device_start_failed` | 原始拒绝在启动尝试中保存；不将未知响应当作拒绝；窗口已结束且可靠确认未启动时按过期规则，已有失败终态不改写 |
| 拍照或延时摄影有明确任务失败、提前结束、无产物或结果不满足证据 | `capture_failed` | 活动身份及固定原因；保留能够登记的正式文件 |
| 启动是否发生、任务是否完成或完整文件集合经有限核实仍不明确 | `capture_result_unconfirmed` | 活动及未知阶段；保留实际设备占用 |
| 录像普通停止有限处理后仍未确认完成 | `recording_stop_failed` | 活动及原停止流程；设备残留独立保存 |
| 实测或可靠连续控制证据已经证明时长不足 | `recording_too_short` | 指向实际媒体检查或设备活动依据，至少一个引用必填 |
| 必要录像核验无法证明成功，且没有更具体的已知不足事实 | `recording_processing_failed` | 内部处理身份与检查、时长、媒体或源文件失败分类 |
| 需要使用原设备时，部署缺少该设备或驱动标识已改变 | `device_binding_unavailable` | 原设备、预期驱动、适用的实际驱动和原因；跨文件处理先按项失败再汇总 |
| 历史设备或输出范围仍被未解决活动占用，且没有适用的安全收场路径 | `device_activity_unresolved` | 历史活动及设备；不无期限等候 |
| 运行时来源实例或范围可靠确认无效 | `source_resolution_failed` | 原始来源及具体不存在或类型不适用分类 |
| 取回存在逐来源、逐目标或交付最终失败 | `obtain_items_failed` | 详情为 `{}`；完整失败项从所属明细生成，不在错误详情复制数组 |
| 清理存在逐项最终失败 | `cleanup_items_failed` | 同上，逐项事实与尝试各自保留 |
| 取消存在逐目标或逐交付最终失败 | `cancel_items_failed` | 同上，已生效取消不撤销 |
| 取消完整候选集合包含发起者自身 | `cancel_self_target` | 发起动作身份；尚未向任何目标施加取消 |
| 取消寻址对象可靠确认不存在 | `cancel_target_not_found` | 原目标描述；不建立虚构取消项 |
| 局部状态同步的起点报告不存在 | `sync_report_not_found` | 原请求的起点报告 ID |

多个独立受理错误统一使用 `action_validation_failed`。每个问题的 `context` 保留对应关系或完整冲突名称，不能为了使用一个专用码丢弃其他错误。完整计划结构、未知动作类型或动作名称非法属于整份拒绝，不创建这些动作错误记录。

拍摄已经有明确失败证据时，不能选“不确定”掩盖已知失败；取消及过期优先级仍按业务状态机。窗口结束不将待确认的原尝试转为过期：可靠确认启动后继续，可靠确认没有启动后按过期分类，有限核实后效果仍未知时使用 `capture_result_unconfirmed`。完整分区见[窗口结束与在途启动](../../architecture/scheduling-execution.md#窗口结束与在途启动)。修复失败本身不撤销已证明的录像成功，只有它使必要成功依据无法成立时才进入对应失败分支。非相机动作的逐项错误与动作汇总分开；驱动的任意错误名称不一对一映射动作码，而是结合实际效果、资格和预算选择表中分支。

## 登记与验证

写入入口校验动作码存在、阶段唯一、详情满足对应 Schema，以及与动作受理分类、实际状态和关联证据一致。受理错误只能用于未执行的 `FAILED`；执行错误只能用于已开始执行的 `FAILED`。动作非失败时两个最终错误字段均为空；过期原因和取消收场错误使用各自字段。

公共错误定义的 `action_error_id` 必须为唯一正整数。协议检查编译每条详情 Schema，现有报告样例继续使用原公共码和阶段。数据库结构验证核对整数合法集合；生产实现验证表中每个业务分支、驱动错误映射、报告输出和历史回放，不能只验证样例中出现过的错误。
