# 数据库一致性与历史恢复验收

[数据库设计入口](../database-schema.md)

以下条目定义需要执行的验证，不表示实现或测试已经完成。软件集成验证使用真实 SQLite 和受接口契约约束的设备替身，不连接真实相机。目标主机事务耗时与资源占用单独测量。

## 等待与来源结束

契约见[逐项等待](waiting.md)。

- **验收 01**：来源成功、失败、过期和取消分别覆盖有产物与无产物的合法情况；拍摄及适用产物处理、登记满足条件后才选择，依赖方不继承来源终态。
- **验收 02**：同一来源被多个取回与范围清理引用，分批通知全部相关未完成责任。取回逐来源推进，范围清理等全部来源；后续页及未缓存依赖方不遗漏。
- **验收 03**：分别交错提交来源结束、依赖建立和动作首次执行，来源先结束时仍能选择，关系先建立时能收到后续处理通知；重复通知不重复固定结果。
- **验收 04**：取消先提交、来源结束先提交、选择先提交及依赖方已有终态分别验证。取消保留实际选择进度，不把未完成伪装成已固定，不重新开启普通选择。
- **验收 05**：来源终态及所属产物事实共同提交；逐来源完整选择与状态、范围清理完整集合与清理项分别共同提交。各自覆盖提交前中断、明确回滚、提交未知及提交后通知或后续处理前退出。
- **验收 06**：在来源结束前、结束后尚未选择、选择完成及取消后的完整边界查询。来源关系、来源事实和选择进度均取自同一 H，后续变化不改写旧报告。
- **验收 07**：从初始状态回放、快照正向恢复和当前投影逆向恢复所得成员、来源完成事实、选择及条目结果一致；恢复历史不执行文件选择或外部操作。
- **验收 08**：来源结束而依赖方自身记录未变时，依赖方不增加自身历史计数；确实影响公开字段时按依赖映射登记报告目录。重复检查没有重复历史或次数消耗。
- **验收 09**：同一动作两项工作保存不同重试配置，彼此不覆盖。同次运行计时、重启完整间隔计时及报告固定 H 分别验证；一项间隔结束不改变另一项。
- **验收 10**：依赖的类型、范围、成员唯一性及归属覆盖合法与非法情况。解析未完成、解析失败、固定空来源、选择未完成、固定空选择及有选择结果分别处理，数据库错误不冒充空结果。
- **验收 W-01**：逐项覆盖来源处理分类表及两种来源初始化时点。来源已满足条件且选择仍为 `PENDING` 时，正常通知和启动恢复都能继续；已有 `FIXED` 结果不重选。范围清理不处理部分来源集合，取回准备可以逐来源推进但发布仍遵守整体条件。

- **验收 W-02**：受理时已固定来源和执行时才解析来源的取回均具有唯一来源选择记录；范围清理不创建取回选择行。覆盖创建事务回滚、提交未知、重送及恢复，不能出现来源责任已开始但所需选择记录缺失。
- **验收 W-03**：按重试转换表覆盖等待进入、计时完成但设备仍受阻、可派发、取消、预算降低、再次失败及重启。两份交付各自计时，动作汇总不会相互覆盖；H 时沿原交付关联恢复等待，后来清除标记不改变旧报告。

- **验收 W-04**：设备活动或启动保留阻挡多个候选时，持有者变化只保存其实际事实及历史，候选自身没有变化时不增加历史计数。覆盖活动进行中、未知、可靠释放，以及启动明确失败后的保留、间隔完成但条件受阻、再次尝试、确认启动、取消、最终失败和过期。间隔完成不结束保留；原动作终态不解除未知活动占用；同一相机没有两个有效录像启动保留者。
- **验收 W-05**：交错提交候选取消、活动占用释放、保留结束及下一候选授予，保持资格、窗口和既定顺序。覆盖多个候选、后续页及未缓存工作；授予前取消不启动，授予后取消沿原责任收场。提前、重复及迟到通知只触发检查，不修改后来取得的归属；检查与等待交接不遗漏变化。排队和重新检查不消耗尝试次数。
- **验收 W-06**：覆盖归属变化事务提交前中断、确认回滚、提交未知、提交成功但通知前退出及下一候选取得机会后重启。先恢复原保留、设备活动及独立收场，再选择候选；调用意图已保存但发送不明时核实原任务，不重复启动。从初始状态回放、快照正向恢复和当前投影逆向恢复在同一完整边界一致；不补造调度观察，后续变化不改变旧报告字节。逐项验证新工作、时间、重试、启动结果、活动观察、保留结束、取消及兼容条件变化能触发必要检查。

- **验收 W-13**：按首次启动共同提交分类表覆盖准备未完成、取消、终态、窗口或预算不足、原尝试未知、其他保留、冲突活动、排序落后、首次选中和有效保留下的安全重试。首次归属、尝试、额度与可能效果不可部分提交；准备占用本身不消耗启动次数，重试保留不提前建立下一尝试。跨页选择仍按既定顺序，已有归属及原活动身份保持。
- **验收 W-14**：首次及后续启动分别覆盖事务回滚、提交未知、意图提交后派发前中断、派发后结果保存前中断、可靠未派发、明确无效果失败、启动成功及未知效果。只有可靠提交才派发，恢复先核实原责任，已提交次数不退还；取消先于及后于意图提交分别按实际阶段处理。失败与保留、启动确认与保留结束各自共同提交，三种历史恢复路径一致；前置基准与输出范围占用沿原契约恢复。

- **验收 W-15**：按[录像启动状态表](recording-start.md)覆盖每个合法状态、次数与间隔组合，以及非法组合。首次登记进入 `ACTIVE`，明确失败后的允许重试、间隔结束受阻及有限核实均保持 `ACTIVE`；成功、取消、过期、确定失败及核实耗尽分别结束。启动 `EXPIRED` 可以保留已有尝试，后续残留收场的 `EXPIRED` 仍限零次；所有结束状态不因配置提高或迟到结果重开。
- **验收 W-16**：按动作与流程共同推导每台设备的启动持有者，覆盖标记 0/1、最后一次额度尚在执行、配置降低后的资格复查、窗口结束判定、取消和后处理。两个候选交错尝试首次授予，事务内始终至多一个持有者；多持有者、非法组合及读取失败报一致性或状态库错误，不能挑一个继续。限定设备的分页查询不得遗漏已有持有者，未完成工作索引与实际查询计划在后续结构实现中验证。
- **验收 W-17**：分别让可靠启动确认、取消或过期先于原调用收场保存，验证启动流程已结束但尝试仍为 `RUNNING` 的合法组合。运行及恢复均发现该尝试与独立活动；迟到错误如实保存，不覆盖启动成功或已有终态，不重开普通启动。每个相关事务覆盖回滚、提交未知和提交后退出，三个历史恢复路径在同一 H 得到相同持有者、流程结果及未完成收场。

- **验收 W-18**：按[窗口结束与在途启动](../../architecture/scheduling-execution.md#窗口结束与在途启动)覆盖三种拍摄动作、窗口起止边界、无尝试、可靠未派发、无效果等待重试、在途调用、有限核实、可靠启动及核实耗尽。窗口内发出、窗口后成功确认时继续拍摄，实际确认时间不改成窗口内时间；未知结果不能被过期覆盖。最后一次额度仍在处理、截止前已失败及取消先提交分别保持正确结果。
- **验收 W-19**：意图提交后派发前跨过窗口时不发出调用，保留已占用次数及可靠未派发事实。分别在意图提交、调用开始、收到结果及结果事务提交的前后中断；提交未知先核实，只有意图时不猜测未派发，窗口外不补发。启动恢复沿原身份和有限预算核实，可靠有无效果及核实后仍未知分别取得对应结果，不重新给予旧调用一次正常等待期限。
- **验收 W-20**：调用原截止时间与启动窗口分别触发，窗口结束不刷新超时、次数或核实预算。核实期间取消及终态先后交错，迟到成功或错误不改写已有终态，活动与实际调用独立收场。三个历史恢复路径在同一 H 得到相同动作、流程、过期原因、占用及待处理责任，回放不读取当前时钟或发出设备调用。集成测试使用受驱动契约约束的替身验证窗口后确认，不依赖真实相机计时。

## 相机读取机会与调度交接

契约见[读取机会](waiting.md#相机读取机会与未完成责任)、[触发路径](../../architecture/file-copy.md#读取工作的发现与唤醒)和[调度交接](../implementation.md#调度通知与待处理工作的交接)。以下入口均覆盖普通取回、自动预览、录像原片检查、修复输入、读取重试及整片重拷。

- **验收 W-07**：同相机多个未完成拷贝共用唯一机会，不同相机独立推进。分段间隙、允许的重试保留、取消但实际读取未结束均保持原归属；满足释放条件后保存原持有者变化，其他候选自身事实不变时没有历史写入。仅需主机处理的工作不申请机会，源保护按自身条件解除。
- **验收 W-08**：按读取机会分类表覆盖缺失或矛盾记录、提交未知、取消、已有持有者、其他条件未满足、排序落后及选中。交错提交取消、释放和授予，保持既定顺序、原身份与额度。排队及重复通知不增加次数；旧持有者重新取得机会后，旧释放通知不修改新归属。
- **验收 W-09**：逐项覆盖触发路径表，包括新建拷贝、来源及修复成品完成、机会释放、重试时间、重置完成、设备兼容性和控制通道变化、取消及实际调用收场。内部变化不借助新计划周期检查仍会被处理；提前通知、检查期间通知、检查后等待前通知及等待中通知均有效。多相机合并保留全部范围，更早截止时间打断旧等待，处理完成后不会空转。
- **验收 W-10**：原协程取消时，数据库操作未开始撤回、已经开始后成功、回滚及提交未知分别处理。原责任拥有者或接手方完成结果消费及适用调度；成功释放后其他候选可以推进，原取消拷贝不恢复普通读取，提交未知不重复授予。负责流程异常不得静默丢失责任。
- **验收 W-11**：启动扫描和按设备候选查询分批进行，最优候选位于后续页、详情已淘汰及初始化期间出现新提交时仍正确发现和排序；已有机会优先恢复。保留终态后的独立收场，不因内存队列为空退出，也不扫描全部历史详情。后续批次有明确继续处理安排。
- **验收 W-12**：授予及释放分别覆盖提交前中断、确认回滚、提交未知、提交后通知前退出，以及下一候选已取得机会后重启。从初始状态回放、快照正向恢复、当前投影逆向恢复取得同一边界的归属、进度和结果；后续接手及取消不改变旧报告字节。历史回放不运行调度或补造未保存的观察。

## 取回、读取保护与清理

契约见[取回建档](sources-obtaining.md#取回的读取资格与依赖)、[清理协调](cleanup-coordination.md)和[产物汇总](output-cleanup-state.md)。

- **验收 11**：普通交付、录像内部检查及修复输入拷贝分别验证唯一读取流程、错误归属、缺失或重复流程；覆盖首次创建、重试、续传、重拷、取消、提交结果未知和恢复。三种历史恢复路径取得相同的流程、尝试及预算，并生成相同报告内容。
- **验收 12**：对动作、组、计划、显式 ID 及自动预览取回分别验证共同建档。覆盖无资格拒绝、完整建档、既有责任复用及非法字段组合；交付、拷贝、目标文件记录、读取流程、取回项关联与源依赖必须整体提交，提交前不得执行依赖它们的文件操作。
- **验收 13**：交换取回与清理候选的唤醒及选择保存顺序，验证资格仍按业务顺序决定；覆盖取消先提交、建档先提交、已有删除限制及建档后新增限制。两个取回读取同一产物时，排队项仍受保护，一个取回解除依赖不代替另一个解除。
- **验收 14**：覆盖读取未开始、正在读取、等待重试、校验及重拷期间的失败或取消；只有可靠确认读取及后续重试停止才解除依赖。验证相机机会已释放但源依赖仍有效、源依赖解除但目标文件清理仍须等待本地操作结束的边界。
- **验收 15**：覆盖建档及准备完成事务提交前中断、回滚、提交成功但通知前退出和提交未知。恢复保留原身份、次数、关联及依赖；依赖解除后副本缺失、损坏、取消、撤回或清理均不重新读取源文件。相关记录缺失或矛盾进入状态库错误分支。
- **验收 16**：在建档前、建档后及依赖解除后的完整边界，分别从初始状态回放、快照正向恢复及当前投影逆向恢复，验证相同的资格和依赖事实。后续交付或清理继续变化不改变已冻结报告字节；资格和源依赖恢复不依赖交付的最新状态。
- **验收 17**：分别在已有零个、一个和多个有效源依赖时建立清理限制，均共同保存限制和 `PENDING_DELETE` 及适用产物汇总。目标此前已清理、取消已生效、已有终态及记录查询失败分别进入所属分支；待处理项缺少真实目标或有效限制属于一致性错误。
- **验收 18**：多个取回依赖同一产物、多个清理项待处理时，非最后及最后一个源依赖解除均不单独改写清理项。每次按受影响产物触发检查；仍有依赖时不取得处理归属，无依赖时按其他条件排序。覆盖同事务解除多项依赖、取回取消但读取未停、多产物、重复及提前通知；无事实变化不追加历史，不消耗调用次数。
- **验收 19**：交换清理取消、源依赖解除及处理归属取得的提交顺序。未取得归属且没有可能派发工作时，取消保存本项终态、可撤销限制解除及适用汇总；已取得归属则按原调用收场。取消项不重新开启，其他请求限制仍有效。`PENDING_DELETE` 与源依赖并存合法，`DELETING` 与有效源依赖并存须报一致性错误。并发建立取回资格与删除限制时保持共同事务和既定顺序。
- **验收 20**：源依赖解除事务分别覆盖提交前中断、回滚、提交未知和提交后通知前退出。正常通知及启动恢复从待处理项结合依赖找到后续工作；最优候选不在缓存或位于后续页时仍按既定顺序选择。三种历史恢复在同一 H 取得相同清理项、依赖和产物汇总，后续变化不改写旧报告。源依赖变化而清理及产物自身事实未变时不增加其自身历史；进入 `DELETING` 与适用汇总变为 `running` 共同提交。
- **验收 21**：同一产物存在多个清理请求时，覆盖删除中、查询中、删除重试间隔和查询重试间隔，验证只有当前清理项推进外部操作，其他项保持待删除且不消耗次数。跨重启沿用原处理归属和预算，不用排队请求绕过原重试间隔。
- **验收 22**：分别覆盖当前清理项取消、调用超时、调用尚无适用收场依据、已取得依据但终态保存未知，以及具备收场依据但删除效果未知。调用尚未收场时，尝试保持 `RUNNING`，取消事实仍可先保存；调用收场并保存尝试结束结果后，本项仍有其他责任时继续保持 `DELETING`。满足收场条件并可靠保存清理项终态后，才允许其他请求接手。有限核实结束后仍未知不阻止保存实际最终结果，后续请求使用自己的查询预算核实。
- **验收 23**：按接手决策表组合文件已清理、可靠仍存在及效果未知，与删除和查询额度有余或耗尽分别验证。额外覆盖先观察存在、后发出结果未知的删除，确认旧观察不能绕过核实。查询确认不存在与读取既有完成记录分别报告 `absence_confirmed` 和 `already_cleaned`，不生成虚假尝试。
- **验收 24**：C1 失败或取消后，已排队且有效的 C2 可以按自己的授权继续，C1 的终态及预算保持。C2 后来成功不改写 C1；C1 成功后 C2 保存自身确认结果，三个历史恢复路径保持各自状态及次数，产物后来的完成事实不改写 C2 的旧报告。
- **验收 25**：验证同一产物最多一个 `DELETING` 项，首次先查询及首次先删除均取得同一类处理归属，查询、重试和取消收场期间归属保持。终态保存与归属释放使用同一次状态变化，覆盖提交前中断、回滚、提交未知及重启；三种历史恢复路径取得相同处理者。多个处理中项、终态项相关调用仍缺少适用收场依据等矛盾进入一致性错误分支。
- **验收 26**：验证删除和查询流程仅通过 `cleanup_item_id` 关联清理项，每项每种流程唯一，类型、责任键、目标及动作归属一致。覆盖首次删除成功而无需查询、先查询后删除、直接复用完成事实而无需流程，以及等待源依赖或其他处理者时不创建流程、不消耗次数。缺失应有流程、重复流程及归属矛盾均进入一致性错误分支。
- **验收 27**：首次进入 `DELETING`、创建所需流程及登记第一次尝试整体提交；后来首次使用另一种操作时，该流程与第一次尝试整体提交。分别在提交前、明确回滚、提交未知、提交成功但未派发及派发后结果未保存时中断，验证不提前调用、不重复建档，且已占用次数不退还。取消先提交时不登记普通尝试，尝试先提交但取消先于派发生效时不发出调用，按原取消规则收场。
- **验收 28**：查询确认仍存在后再次删除、删除结果未知后再次查询，沿用各自原流程及独立累计次数；覆盖重试间隔未结束、预算耗尽、流程已结束和跨重启，不因查询响应成功或重启重新获得预算。三种历史恢复路径在各完整边界取得相同的清理项、流程、尝试及配置依据；后续创建另一种流程或增加尝试不改变旧报告字节。
- **验收 37**：同一产物有多个待处理清理项时，分别覆盖计划时间不同、时间相同但所属计划不同、同计划同时间但原数组位置不同。交换协程唤醒、明细保存及数据加载顺序，正常调度和重启恢复均选择同一合格候选。较早候选尚未具备条件时不占位；后来具备条件的较早候选可以先于尚未取得归属的项，但不能抢占已在 `DELETING` 的项。排序依据缺失或不可读进入状态库错误分支。
- **验收 38**：按候选分类表覆盖取消、已有终态、前置条件未满足、应当保存的执行失败、源依赖等待、其他处理者存在及无当前处理者。排队不创建调用或消耗次数；所需操作按各自预算判断，未知删除效果必须先查询。已有清理完成事实时，多个仍有效项分别保存 `already_cleaned`，不要求依次取得操作归属，也不新增尝试；原失败及取消项保持原结果。
- **验收 39**：分别在前一项终态提交前后、下一项建档前后以及两个事务之间中断，覆盖明确回滚、提交未知和提交成功但通知丢失。无已保存处理者时重新选择，有已保存处理者时恢复原项，不使用内存接班者延续未提交的选择；历史恢复保持各边界原有处理者和等待项，后续接手不改变旧报告字节。
- **验收 40**：按产物清理汇总表覆盖六种状态及优先级，组合多个请求等待、处理中、失败、取消及可靠完成。取消生效但处理项尚未收场时保持 `running`；当前项失败而另一项待删除时变为 `pending`；已清理完成不被后续请求的失败或取消覆盖。未知目标及尚未生效的意图不改变真实产物汇总。
- **验收 41**：仅清理状态变化而产物可用性不变时，验证相关事实、产物汇总、事件关联及业务序号共同提交，增量报告能选中产物。新增等待项但产物报告字段均未变化时，不产生额外产物报告变化；只有汇总错误内容变化时仍应选中产物。覆盖回滚、提交未知及各完整边界的三种历史恢复，后续清理推进不改变旧报告字节，也不读取其他清理项的最新值补算旧汇总。
- **验收 42**：多个已结束清理项仍留下限制时，以最终结果事件顺序选择产物清理错误。将计划时间、清理项 ID 和墙钟时间的顺序设置为与最终结果事件不同，验证选择不受它们影响；后续无关修改不改变顺序。较晚结束但未建立限制的失败、完整解除限制的取消均不替换旧错误，仍留下限制的取消按其实际结束原因参与。
- **验收 43**：覆盖候选最终结果与产物错误共同提交前中断、回滚、提交未知和同一事务内新增结束事实。不得跳过缺失或矛盾的候选依据选择旧错误；三种历史恢复路径取得相同产物错误，后来请求结束不改变旧报告字节。各清理项自身结果和预算保持独立。
- **验收 44**：取消已生效后，分别提供本项从未派发删除且确认不会再派发、调用仍需收场、可靠清理成功、可靠删除失败且文件仍在、删除结果未知的事实。未知分支仅在必要收场完成后保存 `CANCELED`、`DELETE_UNCONFIRMED` 和目标产物，保留限制及原尝试依据；未派发分支不生成未知错误，可靠成功分支不被取消覆盖。仅最后一次尝试未派发不能抹去本项此前可能发生的删除；未耗尽查询预算时不生成耗尽错误。
- **验收 45**：取消项终态、错误、限制与产物汇总在同一事务内保存，覆盖提交前中断、回滚、提交未知及报告冻结。分别验证没有其他责任、另有待删除项、另有处理中项及后来清理成功时的产物汇总；原取消项及三种历史恢复路径保留其当时的未知结果，后续成功不改变旧报告字节。
- **验收 46**：产物从带错误的 `incomplete` 进入 `pending` 或 `running` 时，状态变化与 `cleanup_error_json` 清空共同提交，新报告省略产物的 `cleanup.error`，原清理项错误保持。仅受理尚未具备条件的新请求不清空错误；新请求取消并解除本项限制后，若旧限制仍在，产物回到 `incomplete` 并按原错误选择规则恢复汇总原因。覆盖回滚、提交未知及三个阶段分别冻结的报告，三种历史恢复路径取得各自原有错误或空值，不读取当前错误替代旧值。
- **验收 47**：取消后可靠确认删除失败且文件仍在时，清理项保存 `CANCELED`、`FILE_DELETE_FAILED` 和目标产物，原尝试保留具体调用错误及效果依据，已形成的不可撤销限制保持。仅提供超时、通信错误或非零退出码而没有可靠效果结论时，不能进入该分支。被选为产物错误来源时使用本项实际错误；后续清理成功及历史报告重建均不改写本项原结果。
- **验收 48**：`final_event_id` 覆盖未结束时为空、首次保存三种终态及创建时直接终态的必填规则。普通尝试结束、取消标记、请求重送、重启及后续产物变化不得改写该引用。验证引用不存在、指向其他项、普通进度或尝试结果、终态缺少引用、非终态带引用及原引用被替换等非法组合。
- **验收 49**：最终结果、`final_event_id`、历史正文和适用产物汇总共同提交，覆盖回滚和提交未知；正文明确保存引用的前后值，快照保留该字段。三种历史恢复路径在创建前、未结束及已结束边界分别得到不存在、空引用和原事件编号，正常错误排序直接读取清理项引用并保持既定结果。
- **验收 50**：同一产物的多个有效错误候选具有相同 `final_event_id` 时，固定选择清理项 ID 最大的一项；最终结果事件不同时，较新的事件优先于较大的清理项 ID。同一事件保存多个清理项结果是合法引用，逐项核验事件确实包含各自终态。交换事件正文中记录排列、查询返回及加载顺序，正常汇总、重启和三种历史恢复保持相同选择；较大编号但没有留下限制的项仍被排除。
- **验收 51**：按取回项与交付职责表覆盖目标未判定、已选中、建档前失败或取消、共同建档，以及交付后续准备、发布、失败、取消和撤回。交付存在后取回项保持 `DELIVERY_CREATED`、永久关联及独立源依赖，不重复保存交付终态或最终错误。整体取回根据来源、目标和交付事实判定，不能因全部条目已建档提前发布或成功；重送及重启不另建交付，已失败、取消或撤回交付也不重新授予资格。

- **验收 69**：按[取回字段表](workflow-fields.md#取回目标字段)组合状态、选择依据、目标、交付、源依赖及错误。覆盖五种合法状态及直接创建最终结果；逐一拒绝无交付却有依赖、已建交付却复制错误、错误两列仅一列有值、已解除依赖重新开启、交付与产物或动作不匹配等组合。覆盖普通来源和自动预览，不因 SQL 接受一行就跳过共同建档与历史转换校验。
- **验收 70**：按[清理字段矩阵](workflow-fields.md#清理项的字段组合)覆盖每种允许组合及不允许的状态、限制、错误、成功依据和最终事件引用组合。额外覆盖建立限制前失败、建立限制后未派发即失败、先查询而尚未删除、取消并解除限制、取消但留下未知删除效果；终态不得丢失目标或留下未收场调用。验证较早失败项与后来产物完成可以合法并存。
- **验收 71**：分别以本项删除成功、本项查询确认不存在和读取已有完成记录保存三种 `outcome`。只有前两类要求相应实际流程和尝试，复用完成记录不新增调用或消耗次数；正常核实和中断恢复的不存在证据均可保存 `ABSENCE_CONFIRMED`。覆盖直接创建成功项、取消后收到实际成功、提交前中断、回滚和提交未知，三种历史恢复保留原成功依据，后续产物变化不替换本项结果。
- **验收 72**：按[产物字段矩阵](output-cleanup-state.md#汇总字段的合法组合)覆盖六种清理状态、错误空值与可用性组合，分别验证行内约束及依据全部相关事实生成汇总的事务。`incomplete` 必须有合格错误，其他状态不得残留旧清理错误；可用性错误按独立规则保留。取消项仍有限制时不得据其名称生成产物 `canceled`，历史恢复使用当时已保存的汇总。

## 中间文件的路径与定位

契约见[用途目录与路径规则](file-fields.md#中间文件的路径与用途目录)。这些验收验证生产文件流程、持久化及真实文件系统的协作；现有 SQL 只检查路径非空及唯一，不代替用途、文件名和文件系统校验。

- **验收 F-01**：对四种用途分别核对根目录、固定子目录、文件 ID 和可选扩展名。覆盖带扩展名及不带扩展名的合法名称、最长名称、错误用途目录、错误 ID、前导零、绝对路径、重复分隔符、额外层级、`.`、`..`、反斜杠、NUL 和超长名称。改变 CLI 工作目录及配置文件位置，不改变同一登记的解释；路径不附加第二层 `staging`。
- **验收 F-02**：交付副本、录像输入、处理临时文件及修复目标均先登记再创建。覆盖登记回滚、提交未知、登记后尚未创建即中断、分段续传、重拷及取消；恢复沿用原身份和路径。修复目标从不完整到完整，再提升为正式产物时保持原位置；未完成目标不能取回，已提升文件不进入自动清理，显式清理采用产物责任。
- **验收 F-03**：分别覆盖正确目录内文件存在或可靠不存在、父目录缺失、权限错误、用途目录或目标为符号链接、目标是目录，以及身份不明的已有文件。错误保留实际阶段和原因，不能以“不存在”或“清理成功”覆盖。普通交付移动前后及移动结果未知时，按工作位置和交接文件名恢复；进入 `processing` 后保持主程序所有权。
- **验收 F-04**：在文件创建、准备完成、提升、交接及清理前后保存完整边界，分别从初始历史回放、快照正向恢复和当前投影逆向恢复，取得相同的路径、责任和状态。文件已经删除不影响历史查询；历史恢复不访问文件、不移动文件，也不重新创建旧路径。状态报告、日志副本和故障标记不进入普通中间文件清理。
- **验收 F-05**：首次初始化共同保存三处目录绑定，重复初始化保留实例身份及业务历史。分别改变一处及多处目录，验证 `run`、`submit` 和报告子进程在使用业务数据或产生副作用前拒绝不匹配配置；`describe` 不依赖状态库。元信息缺失、非法与配置不匹配分别诊断，不能用当前配置补建绑定；配置相同但报告目录访问失败仍按报告职责处理，日志副本不依赖状态库可用。
- **验收 F-06**：按[阻止切换的完整分类](../../architecture/configuration.md#哪些情况阻止切换目录)，独立组合数据库责任与实际目录内容。覆盖 `REQUIRED` 但文件尚未创建、四种未完成清理阶段、已提升但未清理的成品、文件已不存在但责任未结束、未完成交付与撤回，以及本地报告责任。已结束记录、未来尚未建立文件责任的动作和仅剩远端确认分别不作为旧路径责任；原目录的报告、日志副本、故障标记、未知文件及检查错误仍分别阻止切换。不能以新目录为空、动作终态或取消等待替代完整判定。
- **验收 F-07**：原配置仍有责任时，显式 `init` 拒绝切换；恢复原配置可以继续正常处理。责任全部结束、原目录只余空目录，且新目录不存在或只有空目录时，允许切换。覆盖根目录规范化、不同工作目录、相同或互相包含的根目录、实际目录别名、新目录已有文件、目录权限和原子移动条件；使用真实目录及受控文件错误，验证初始化不复制、移动或清理业务文件，主程序使用新交接路径后才恢复领取。
- **验收 F-08**：在新目录准备前后、绑定提交前后及返回前中断。验证三路径共同更新或保持旧值，失败残留的空目录不构成切换成功；提交未知按重新读取的完整绑定判定，不混用新旧目录。配置切换保留数据库身份、历史、文件 ID、累计 ACK、同步责任及报告字节，历史回放不恢复旧部署绑定。正常入口不扫描全部旧文件，显式切换分批检查且不无界积累目录项。

## SQLite 运行库与部署版本

按[统一运行库要求](../sqlite-runtime.md)验证版本条件、实际能力及各入口行为。现有规格检查只能证明当前开发环境的基本能力和版本判定逻辑；以下包含尚待生产实现及目标部署执行的验收。

- **验收 V-01**：从统一条件文件取得主线门槛和回移例外，验证主线门槛前一版、门槛本身及后续版；逐个验证回移修复版、相邻未列入版及其他旧分支。版本按整数分量比较，缺失、非法类型及不完整版本拒绝通过。默认检查拒绝文档版本表与条件文件不一致，消费者不得各自保存另一套完整允许清单。
- **验收 V-02**：记录实际 Python 路径、Python 版本、`sqlite3.sqlite_version_info` 及 SQL 返回的版本与构建身份。系统命令行工具与 Python 使用不同版本时，以后者判断。使用隔离库验证 STRICT、JSON、增量 BLOB 分段读写和文件库 WAL/FULL，并执行全部规格 SQL；缺少能力、线程支持不满足要求或无法完成检查时停止并保留具体原因，不通过取消 WAL 或放宽约束继续。
- **验收 V-03**：覆盖 `init`、`run`、`submit` 和报告子进程的兼容、不兼容与检查失败分支；拒绝发生在业务库打开之前，不创建空业务库、不改写动作及历史、不发布文件。`run`、`submit` 的不兼容返回 `configuration_error`，初始化报告失败；报告子进程启动失败保留责任，主进程执行条件可靠时普通设备工作继续。版本合格后实际数据库错误仍按状态库错误处理，`describe` 不新增 SQLite 资格前提。
- **验收 V-04**：在目标 Python 3.11 / ARM64 发行物固定具体构建，使用该解释器运行相同检查并记录结果。组合真实 WAL 连接、读视图、提交及既定历史恢复、报告流程验证；更换构建后重新执行。版本样例和临时库检查不证明所有允许版本均经过实测，也不代替目标存储上的性能与物理断电验证；软件集成测试继续按项目规则独立执行。

## 历史引用与事务边界

契约见[逐字段编码及恢复规则](history-formats.md#事件引用与事务边界的编码)和[事务编号分配](transactions.md#分配事件编号与核对引用)。下列验收需要生产事件保存及恢复组件共同运行；现有设计检查只证明字段分类、目标、派生方式与实际结构一致。

- **验收 J-01**：从规则文件取得全部业务引用、派生历史列及基础表引用，逐列核对正文、投影和目录。拒绝遗漏分类、业务引用误归派生、错误计算方式及外键目标不一致。整数编号采用精确类型和范围；布尔值、数字字符串、浮点数、未允许的空值和 0 均拒绝，覆盖超过 JavaScript 安全整数范围的合法 ID。
- **验收 J-02**：组合单事件和多事件事务，分别保存本事件引用、既有事实引用及创建事务末位引用。同步在首条或中间事件创建时仍引用最终末位；末位目标稍后插入合法。拒绝指向中间事件、另一事务末位、未来事务、错误对象及错误分支。分批读取只在完整事务结束后提供状态，最后一批缺失或读取失败时整次查询报错。
- **验收 J-03**：覆盖普通尝试的空结果到首次结果、应急尝试的空意图和创建时结果、清理项直接创建终态、交付意图及首次交接、同步结束、可信时间首次建立及推进。首次事实不被后续观察覆盖；报告多次发布允许替换最近成功发布引用，失败时保持。基准按首次收集、追加、固定、中断后非空重收和空重收分别恢复首尾及旧范围，JSON 内的完成依据保留原活动引用。
- **验收 J-04**：交错保存多个对象的历史，同一事件改变某对象的多行及多列，只增加一次该对象计数。逆向撤回后，最近事件取该对象此前的关联，不能取 E−1；报告管理历史与输入诊断分别按其自身规则计算。缺少创建依据、关联不完整或计数矛盾时拒绝恢复；验证每个快照内的派生值与自身边界一致。
- **验收 J-05**：分别在初始化边界和已有完整历史时冻结报告；冻结依据必须早于本次事务首条事件。事务内新业务变化、ACK 或同步责任不能混入该冻结依据。报告重建、补投及后续管理变化保留原冻结边界和报告字节；核对报告目录的事件与业务序号成对引用，以及快照的对象、边界、计数和最近快照引用。
- **验收 J-06**：事件数量与预分配范围不符、事件目标缺失、写入失败或业务引用校验失败时，重新确定范围并重做受影响编码，或共同回滚；不能提交旧末位。提交结果未知时先按原操作身份核实，不重复分配事实。对各类引用分别比较从初始状态回放、快照正向恢复及当前投影逆向恢复的结果，精确还原旧整数、空值和对象不存在状态，且不执行外部副作用。

## 整数编号与字段约束

契约见[整数枚举](common.md#状态与类型的整数枚举)，本节核对权威编号定义、SQL、事件规则、报告映射及生产程序之间的一致性，不代替各业务状态转换验收。

- **验收 E-01**：检查定义格式、重复 JSON 键、表列及 JSON 成员定位、成员名、整数类型、正数范围及组内编号唯一性；不同组使用相同编号合法。核对普通枚举、布尔列、外部来源和固定值的分类互斥且覆盖完整，事件类型、版本及历史对象资格从各自来源取得。公共错误的动作编号和各明细表编号分别去重，详情及阶段由对应公共条目取得，内部定义不得复制错误编号。未知值、布尔值冒充编号、字符串编号、重复成员或编号均拒绝；生成的编号一览与来源不一致时检查失败。
- **验收 E-02**：从权威定义核对 SQL 的实际接受集合与程序枚举。列值检查覆盖全部合法值、空值、未定义值及整数边界；真实表的组合检查分别提供满足前提的合法记录和违反前提的非法记录，不能只比较 SQL 源码文本，也不能把某条样本因其他字段错误而被拒绝当作编号检查通过。定义成员漏入 SQL、SQL 额外接受成员、事件状态条件或程序编号漂移均须使检查失败。生产适配还须验证写入、读取、JSON 内部分类、同一历史边界恢复及公共错误码、阶段、详情的转换；字符串、布尔值和浮点数不得冒充枚举编号，即使 SQLite 可以无损转换也必须在入口拒绝。

## 调用结果与中断恢复

契约见[ADB 返回](../../architecture/adb-execution.md)、[尝试结果](operation-fields.md#普通尝试结束结果的保存边界)和[接入模块](../../host-demo/design.md#接入模块的本地进程收场责任)。

- **验收 29**：删除超时后，分别组合本地收场是否完成、是否取得远端退出依据、是否适用普通前台命令运行假设，验证按决策表继续处理。适用假设且本地收场完成时，无需远端 PID 查询即可进入原文件效果核实流程；不补造退出证据、不直接重发删除或释放尚有处理责任的清理归属。覆盖请求终止后退出、宽限结束后强制终止并回收，以及本地进程已退出，不把终止请求当作退出证明。
- **验收 30**：分别提供只保证发送、保证启动和保证任务完成的响应，验证具体设备操作只返回其保证范围内的事实；非零退出码不单独证明文件存在。可靠业务成功证据先到、调用错误后到时，两者均保留。
- **验收 31**：实际退出证据与依据运行假设收场分别随尝试结束结果共同保存和恢复，不因假设生成远端观察；尚未完成适用收场时，尝试保持 `RUNNING`。覆盖超时、取消、本地收场未完成时中断、结束结果保存前后中断及提交未知，沿用原身份与预算；已保存的假设依据不因重启改写为观察。单次文件查询不代替远端退出证据，发令命令收场不代替异步拍摄活动结束。
- **验收 32**：使用真实 Linux 进程和无设备副作用的测试工具，分别覆盖 camctl 正常退出及异常退出后存在零个、一个和多个遗留执行进程。旧 camctl 已退出且存在遗留执行进程时，验证直接发送 `SIGKILL`；camctl 仍运行时的调用超时继续使用原驱动收场流程。确认接入模块在旧执行进程停止前不启动新的 `run`，发送终止信号本身不触发放行；其他进程组及并行 `submit` 不受影响。该验证属于软件集成测试，不要求连接真实相机。
- **验收 33**：覆盖原调用身份或归属无法确认、退出信息取得失败、进程检查失败和终止失败，验证保留管理责任及诊断。分别处理仍可能执行的进程和已退出待回收的进程，覆盖主线程已退出但其他线程仍存活，以及检查期间进程退出的情况。先保留旧 camctl 的退出记录，确认原组执行工作结束后再回收；不回收第三方主程序负责的其他子进程结果，身份保留与回收顺序须防止将后来的进程误作原调用处理。
- **验收 34**：旧调用收场期间收到 `needs_run: true`、存在异常重启安排，以及自动重试预算耗尽时，均按原启动规则合并或保留责任，收场不刷新次数。恢复后的业务操作沿用原身份和预算；本地进程被结束不直接生成文件删除成功、无效果或拍摄结束事实。
- **验收 35**：普通调用超时后、收场完成前冻结报告，验证内部尝试仍为 `running`，报告按所属动作和逐项结果表达已保存的取消及业务事实。收场及结果保存后重建原报告，字节保持不变；三种历史恢复路径取得相同的尝试状态和依据。运行日志中的超时记录不进入数据库历史回放。
- **验收 36**：分别在发现超时、完成收场、结果事务提交前后及提交未知时中断。删除和启动沿原可能效果核实；未保存失败的读取按原资格及可靠进度续传，不增加次数，已保存失败则只按新增尝试规则处理。取消或已有终态先于恢复时，不重新开启普通工作；可靠成功事实与调用错误均保留，未知效果不被收场完成改写。

- **验收 R-01**：按尝试字段表验证运行中三项结果字段均为空，成功、失败及结果未知均有完整 `result_json` 和结果事件引用；成功无错误，失败及未知必有错误。缺少收场依据、外层格式或证据版本未知、观察结构错误及证据与操作不匹配均拒绝，不通过默认值接受。结果对象中的观察数组为空，与结果列为 SQL `NULL` 分别处理。
- **验收 R-02**：组合明确调用失败与效果未知、无效果、已确认三种情形。删除超时且效果未知时保存失败、超时及适用运行假设；取得可靠删除成功证据后通信异常时，同时保留错误及成功观察，清理结果依据可靠事实判断，不因尝试失败直接重发删除。单独的本地退出、假设收场或非零退出码均不能生成业务成功。
- **验收 R-03**：分别提供本地正常退出、本地信号终止、可信远端退出消息和没有远端消息的结果。仅本地退出码为 255 时省略 `remote_exit_code`；具有可信远端 255 结果时可以保存。只发出终止请求尚未确认退出时，不能填本地终止结果或提交结束状态；非 ADB 适配器按自身退出契约验证，不套用 ADB 的数值范围。
- **验收 R-04**：分别使用实际结束证据、适用运行假设和可靠未派发依据结束尝试。按[第一版 ADB 结果记录](operation-fields.md#第一版-adb-运行假设的结果记录)验证固定类型及版本、未使用宽限时的空正文、实际使用宽限时的精确数值，以及本地退出结果和业务观察分别保存。驱动测试验证运行假设的适用范围、本地实际收场后才返回结束结果，以及已有矛盾证据时不放行。只保存意图后重启不能推断未派发；实际确认未派发且不会迟到执行时，仍保留原次数。异步拍摄的发令结束不生成活动结束或文件完成观察。
- **验收 R-05**：在正常返回、调用错误、收场完成、结果事务回滚或提交未知及重启恢复各边界验证完整结果保存。按[ADB 恢复记录](operation-fields.md#第一版-adb-未完成调用的恢复记录)验证类型、版本及空正文；只有意图且原调用结果未取得时保存未知结果，不补造原响应、超时、终止宽限或时刻。分别覆盖主机收场保证成立、不成立、已有结束结果、读取可以续传及不适用普通前台命令假设；沿用原身份和次数。删除调用中断后，新查询确认文件不存在时，原尝试保持未知，文件与清理结果按新观察推进；新查询失败时仍保留未知，不据此直接重发删除。三种历史恢复保留原结果版本和观察，后来查询、配置及驱动变更不改写旧结果；验证公开字段不因内部证据增加而自动扩展。

- **验收 R-06**：按[终止宽限配置](../../architecture/configuration.md#本地-adb-客户端的终止宽限)验证缺省、正数及小数覆盖、非法类型、零、负数及非有限值；各设备共用本地值，计划不能覆盖，运行内固定。使用可控单调钟和子进程替身覆盖已经退出、宽限内退出、宽限到期仍未退出、发送信号时恰好退出；提前退出立即收场，到期才升级，重复取消与部分输出不刷新宽限。发送 `SIGKILL` 后尚未确认退出时，不保存尝试结束或放行冲突操作。
- **验收 R-07**：组合正常调用超时、读取无数据超时及用户取消，验证它们分别触发适用的本地终止且不重置原尝试次数。实际采用的 `terminate_grace_s` 与结束依据共同保存，正常返回及没有原结果的恢复不补造该值；配置改变后三种历史恢复保留原依据。camctl 已退出时接入模块仍直接强制终止遗留执行进程，不使用宽限；共享 ADB 服务端及其他工具不被该配置自动纳入终止范围。

- **验收 R-08**：按[共享服务端生命周期](../../architecture/adb-execution.md#共享-adb-服务端的生命周期)覆盖复用现有服务端、客户端触发启动、启动或连接失败、启动期间调用超时，以及服务端异常退出。启动等待计入本次调用时限；服务端恢复不直接重发业务命令、不刷新尝试次数，不将未知效果改为无效果。软件测试使用受启动和连接契约约束的替身；固定 ADB 版本及真实启动行为单独在目标主机联调。
- **验收 R-09**：用真实 Linux 进程和无设备副作用的工具模拟客户端与共享服务端，分别在服务端脱离原组之前、之后中断 camctl。验证原组内启动进程和执行客户端按组收场，已脱离的服务端保持运行，不妨碍原组收场完成；同时覆盖服务端脱离与原组终止并发。不能仅因服务端存活就阻止后续会话，也不能因此跳过仍在运行的客户端。不调用全局 `adb kill-server`，不影响其他组或并行 `submit`；测试结束时由测试自身回收模拟服务端。该验证属于软件集成测试。

- **验收 R-10**：按[启动与回收约定](../../host-demo/design.md#受管工具的启动与主程序回收约定)，使用真实 Linux 进程验证独立组在 camctl 开始执行前已经建立，普通工具及包装程序创建的后代保持组归属，`run`、`submit` 与主程序所在组相互独立。用系统接口替身覆盖建组失败与启动失败，验证不退回主程序组执行，有已创建进程时先完成适用收场再按原规则重试；程序确实执行后返回 `127` 不判作明确未启动。
- **验收 R-11**：分别覆盖 `SIGCHLD` 默认处置、显式 `SIG_IGN`、`SA_NOCLDWAIT` 以及不抢先回收模块子进程的信号处理方式。前提不满足时不启动 camctl、不修改主程序全局设置；双方按具体 PID 回收时各自取得正确结果。注入 camctl 被其他代码提前回收的情况，验证保留诊断和管理责任，不再根据旧 PID 发送组信号，不以事后转交退出码代替身份保护。系统接口替身验证这些行为分支，真实信号及回收协作由软件集成测试验证。
- **验收 R-12**：覆盖成员检查不可读、权限不足、归属无法确认、终止失败及收场期间成员退出的情况，验证未知状态不被解释为没有遗留工作，不放行可能冲突的新调用。审计 ADB 客户端、`ffmpeg`、`ffprobe` 及实际采用的包装程序的全部启动入口，确认不自行脱离、不转交组外执行且保留查询与终止权限；共享 ADB 服务端按 R-09 的独立范围验证。第三方主程序的实际回收逻辑和目标工具行为另列联调核验，初始化检查不作为完整证明。

- **验收 R-13**：按[明确返回的记录](operation-fields.md#明确返回和可靠未派发的结果记录)覆盖业务成功、仅发令成功、失败且无效果、失败且效果未知，以及可靠效果先到而调用错误后到。验证实际返回类型及版本、观察和退出信息各归其位，本地退出本身不生成业务成功，部分读取进度不被当成尝试结束；异步发令结束不使设备活动直接完成。
- **验收 R-14**：按[可靠未派发的记录](operation-fields.md#明确返回和可靠未派发的结果记录)覆盖登记前取消或过期、登记后阻止派发、设备收到命令后拒绝、重启只有意图，以及同一读取尝试已有部分进度后停止后续调用。只有整次尝试可靠未执行且不会迟到执行时保存未派发类型及 `NO_EFFECT`；登记前不创建尝试，登记后不退还次数，已有尝试的可能效果保持。使用同步点验证取消与派发的先后关系；结果提交回滚或未知时沿原责任核实，不重新派发来补结果。

## 活动查询的责任与计数

契约见[活动查询的责任范围](operation-fields.md#活动查询的责任范围)。

- **验收 Q-01**：B、C 为各自启动而检查同一相机，可靠响应均关联到活动 A，验证观察到的活动身份相同、查询流程和计数分别归属 B、C；B 耗尽额度后不消耗 C 的额度。查询记录归属触发动作历史；同时改变 A 的活动事实时，原活动所属动作取得相应历史，旧录像终态保持。
- **验收 Q-02**：同一责任在调度重入、通信重试、原请求重送及跨会话恢复时保持流程身份和累计次数。覆盖意图提交回滚、提交未知、意图已保存但结果未保存，以及流程已结束；核实原事务不重复分配流程或尝试，恢复不重开终态流程。原调用未完成适用收场时，新的独立预算不绕过相关执行限制。

- **验收 Q-03**：同一录像先核实启动结果、后来核实停止结果，验证两者查询流程及次数独立，查询次数与发令次数分别保存。启动或停止发生多次尝试时，各自的核实次数跨尝试累计，不按每次发令重新取得查询预算。正常停止转入取消停止及重启恢复时，沿用原停止核实身份与次数；直接响应已满足确认要求时不追加查询。
- **验收 Q-04**：按查询目的解释可靠观察：确认本次录像已启动可完成启动核实；停止核实观察到仍在录制时，在仍具继续资格的分支保持原查询责任和累计次数。覆盖次数耗尽、取消及已有动作终态，查询响应成功不被当作录像动作成功，后续观察不重开已结束核实流程。按完整历史边界恢复两类查询的次数、结果及实际采用的配置依据。

- **验收 Q-05**：执行前检查覆盖相机没有已登记活动、观察到已知残留、观察到其他动作正常活动、未知活动及查询失败。流程目标取自发起动作已保存的设备绑定，观察对象变化不刷新次数；不创建虚构活动，不凭无记录推断空闲，不授权停止未知活动。已取得空闲观察但尚未实际执行时仍按真实资格检查；正常占用等待不引入周期查询。
- **验收 Q-06**：启动确认已保存后，分别覆盖源文件关联查询、录像运行期间重启对账，以及延时摄影预计结束后的查询。它们按活动核实责任跨会话累计，不重开启动核实，不因一次可靠的运行中观察就关闭仍需继续的责任。不支持或未采用状态查询的任务不创建该用途的尝试；转入停止处理、取消和预算耗尽时不通过切换用途刷新同一责任额度。
- **验收 Q-07**：B 检查相机后为 A 建立残留收场，覆盖停止响应已可靠确认结束、响应未知需查询、多次停止尝试、B 取消或过期及重启。执行前检查、残留停止发令、残留收场查询分别累计；不消耗 A 原停止核实及 B 自身停止核实的次数。可靠停止证据可以满足执行前判断时不为流程形式重复查询；已开始的残留收场按原结束规则继续，终态流程不重开。
- **验收 Q-08**：产物结果核实覆盖空集合、单文件、多文件及跨批次读取，一轮只消耗一次尝试。分别验证完整满足、明确不满足、暂未齐备、读取失败、取消及额度耗尽；明确不满足不被当作暂时未知重试。批次之间中断保留已用次数和部分可靠事实，重新检查计新轮次，不能把部分结果当成整轮完成。结果提交未知先核实原事务，已有完整结果不因重启重查；查询与结果核实的历史恢复使用原次数及原依据。

- **验收 Q-09**：按[查询与核实配置](../../architecture/configuration.md#状态查询与产物核实的配置)验证六项默认值和逐字段覆盖，拒绝布尔值、非整数次数、非正次数或时限、负间隔及非有限秒数。各查询用途使用同一配置但独立计数；本次运行固定，跨运行新尝试采用本次值并保存依据。上限降低后原次数保持，上限提高不重开已结束责任，历史恢复不加载新配置修改旧值。
- **验收 Q-10**：用可控单调钟验证首次检查、失败或条件暂未满足后的间隔、业务规定的更晚检查时间、独立责任首次查询，以及有无重试等待要求的重启恢复。验证单次设备查询期限覆盖启动和完整响应、输出不续期、超时不退还次数；产物核实的后续批次不增加次数或等待轮次间隔，整轮可超过单次调用时限。轮内查询失败不隐式重复设备调用，原调用未收场或原事务提交未知时不以新轮次绕过处理。

- **验收 Q-11**：按[查询用途与字段组合](operation-fields.md#查询用途责任键和目标字段)验证五种用途、非查询操作的空用途、未知编号、缺少或多余目标、责任键与字段不符及重复责任。执行前检查可以在没有活动记录时保存；其他用途必须引用真实活动。跨表验证启动、停止及残留收场流程的实际归属，拒绝只有责任键正确而关联错误的记录。结束后的流程仍占用原身份，提高上限不能创建同一责任的新流程。
- **验收 Q-12**：按[配置与历史保存](operation-fields.md#查询和结果核实怎样保存配置与历史)验证执行前检查采用发起动作绑定设备的配置，其余查询及结果核实采用目标活动原设备的配置。用途在创建后不可改变；两类操作的三项配置均完整保存。历史恢复采用当时值，配置变化只影响仍可继续的责任。按[流程结束分类](operation-fields.md#一次查询结束与整项核实结束)覆盖正常响应但仍需继续、明确未达到目标、次数耗尽且结果未知、失去执行资格，以及取消后仍须继续的停止核实。

## 应急停止的最终补记

契约见[会话应急停止](../../architecture/session-errors.md#正在录像时的应急停止)、[最终补记](operation-fields.md#应急停止的最终补记)及[事件目录](history-formats.md#事件正文版本-1)。以下是实施验收要求，不表示已有生产实现或测试。

- **验收 S-01**：组合可靠目标、排他资格、驱动安全重复停止能力、已知配置及进程仍可运行的条件；仅在执行资格成立时进行有限应急停止。数据库不可写不单独阻止停止；正常业务失败、报告文件失败和普通日志失败不单独取得应急资格。`submit` 不发出设备调用。
- **验收 S-02**：按[应急记录组合](operation-fields.md#应急记录的结构约束与事务校验)覆盖零尝试且上限未知、零尝试且上限已知、已有尝试且上限已知及已有尝试但上限未知。零尝试按可靠停止确认或未能尝试分别保存成功或失败，已有尝试按停止是否确认保存成功或未确认；已有尝试却上限未知、超过限额、配置不全、结果与次数矛盾均拒绝保存。停止确认先于首次发令时不创建虚假尝试，须保存事件中的可靠观察；调用成功但未确认停止不保存成功流程。尝试超时、未知效果及已确认效果分别保留。
- **验收 S-03**：以第一次超时、第二次确认停止及多个录像分别收场的组合验证共同补记。中途不写进行中的应急流程；每个目标结束且调用收场后才共同保存流程、全部尝试及适用活动事实。重复错误不重置同一会话额度，已结束目标不等待其他目标或整个会话退出，也不重开流程；普通停止预算及动作既有终态保持。
- **验收 S-04**：在真实写入事务中验证普通尝试缺少意图事件引用、应急尝试伪造意图引用、应急结果引用错误事件、尝试关联到其他流程、使用普通事件创建应急尝试、补记进行中尝试、尝试缺项或重复编号均被拒绝。已结束且配置完整的普通尝试也不得省略意图引用，不能仅凭 SQL 接受空值就绕过父流程种类检查。验证责任键与会话、活动一致，同一会话同一目标不能重复保存，后续会话可以有独立责任；普通先提交后派发规则保持，应急补记回放只重建事实，不派发命令。
- **验收 S-05**：覆盖不能发起补记、确认回滚、提交成功及结果未知。诊断分别表达 `not_recorded`、`recorded`、`unknown`，不混淆停止结果；未知先核实原事务，重复保存沿原身份，不重新执行停止，不无限等待数据库恢复。主程序只处理进程协议与诊断，不根据业务详情操作设备或补写状态库。
- **验收 S-06**：在两次尝试之间、停止确认后补记前及提交期间中断。即使此前数据库可写，也允许未最终保存的应急记录全部缺失；后续 camctl 先确认状态库可靠，再使用实际历史与新设备观察，不能根据日志或最终错误消息补造旧尝试。旧记录为未确认、后来观察到停止时，保留原记录并追加新事实；状态库不可用时不进入普通执行或创建空库。
- **验收 S-07**：在补记前后分别冻结完整边界，从初始状态回放、快照正向恢复、当前投影逆向恢复取得相同流程、尝试和设备事实。内部历史在补记前不包含该记录，补记后包含完整最终记录；报告按各边界已保存的动作结果和适用设备执行情况生成，公开字段未变时不因补记本身产生报告变化。覆盖设备已停止但补记未提交、提交后设备执行提示消失、动作尚未终态及原动作已有失败或取消结果，验证退出诊断不进入历史报告、可靠停止不改写原动作结果。其他录像继续收场、原进程退出及后续新观察均不改变旧边界。软件集成测试使用受驱动契约约束的替身，不依赖真实相机或物理断电。

## 设备活动占用释放

契约见[设备活动占用的释放条件](operation-fields.md#设备活动占用的释放条件)。以下分别验证 SQL 可表达的行内约束、事件处理器掌握的跨表依据，以及调度和恢复的组合行为。

- **验收 O-01**：组合发送状态、活动状态、采集判定及占用状态，验证释放必要条件。已结束且采集判定待定的活动可以释放；录像采集判定为空且活动已结束时可以释放，不补造采集依据。设备完成依据与 `ACTIVE` 或 `UNKNOWN` 的组合被拒绝；未结束且无其他依据时，采集判定为空不能通过 SQL 的空值语义绕过约束。可靠未派发或无效果拒绝与实际活动状态矛盾时拒绝保存。分别验证未定或不适用的判定不能附带完成依据，已确定判定不能缺少依据；真实事务沿所属动作检查录像三项采集字段为空，单张拍摄与延时摄影不能省略采集判定。
- **验收 O-02**：时间与产物分支组合固定完成方式、可靠发送、等待完成、完整集合及满足产物要求的依据。SQL 分别拒绝缺少发送时间、等待安排或完成引用、集合尚未确认，以及完成方式、发送状态或活动状态矛盾的记录；真实事务继续核对等待事件属于原活动、时间计算和结果 `outcome = 1` 的实际依据。缺少任一必要事实或存在相矛盾的活动观察时不放行；条件齐备且没有设备状态观察时可保持 `UNKNOWN` 并释放，不伪造 `ENDED`。明确采集失败但活动仍可能存在时保留占用，不用经过目标时长代替完成契约。
- **验收 O-03**：以 A 已停止、文件依靠拍摄前后比较且归属尚未固定、B 准备在相同输出范围拍摄为例，验证 A 为 `ENDED + HELD`，B 不执行冲突拍摄。归属限制解除后保存 `RELEASED`；A 的主机媒体检查或修复尚未完成不单独保留相机占用。任务具有独立输出范围且其他条件成立时，不无条件等待动作终态；其他设备和兼容操作继续。
- **验收 O-04**：分别从正常完成、普通停止、取消停止、可靠未派发、无效果拒绝、恢复对账、后续残留收场和应急补记进入释放判定，验证统一条件和实际证据。按[各入口的事件要求](operation-fields.md#共同提交与全部释放入口)检查事件应用顺序：每次行修改都满足约束，必要设备观察和集合结论不能晚于依赖它们的完成依据或释放记录。动作失败但设备仍在执行时不释放，停止成功不重写已有动作终态或原失败流程；应急结果未可靠补记时不凭内存事实推进依赖释放的新业务。
- **验收 O-05**：交错活动结束、文件归属确定、占用释放、独立调用收场及下一候选授予。活动占用已释放但调用或驱动兼容性仍阻挡时，不派发冲突调用；全部条件满足后仍按下一动作的窗口、取消、预算及排序决定。迟到观察和重复通知不清除新活动占用，`ENDED + HELD` 不被报告为仍在录像。
- **验收 O-06**：在结束依据、文件归属和占用变化共同提交的前后注入回滚、中断及提交未知。核实原事务，不重做停止来补记录；提交后通知丢失由启动恢复接续。从初始状态回放、快照正向恢复、当前投影逆向恢复取得相同活动、占用、完成依据及文件责任；后续释放或新拍摄不改变旧报告，回放不操作设备或读取当前配置重算。

## 独立历史与报告重建

契约见[文件历史](outputs-files.md#文件独立历史与关联查询)、[同边界查询](../historical-state-query.md#取回与交付的同一边界历史查询)和[报告目录](report-changes.md)。

- **验收 52**：取回项的交付关联保持不变，交付依次保存准备中、准备完成和发布最终失败，分别查询各完整边界，验证后来保存的状态及错误不进入先前结果。取回与交付使用不同位置的快照、不同读取边界及不同恢复方向时，与从初始状态回放的结果一致；后续业务继续推进，重建同一报告仍保持原字节。
- **验收 53**：覆盖动作尚不存在、取回项尚无交付、已有可靠关联，以及关联目标在 H 不存在、所属取回或产物矛盾、所需历史损坏的情况。H 之后建立的交付不进入旧结果；非法关联和恢复依据进入状态库错误分支，不读取当前交付或补默认值。共同建档事务前后仅能取得各自完整状态。
- **验收 54**：同一取回的多个交付中，既有本次增量范围内新失败的交付，也有范围之前已经失败的交付，以及尚未取得最终结果的交付。取回的完整失败列表取自全部相关交付在 H 的事实，不遗漏较早失败，也不将尚未结束的交付判为最终失败；用于查询的额外交付不因此自动进入报告交付集合。改变批次大小和恢复路径，验证结果及排列保持一致。
- **验收 55**：只有交付保存最终失败、取回主记录及取回项均未变化时，验证事件关联和计数只更新交付，交付具有应报告的业务序号；报告选中交付后补齐取回及计划，客户端取得完整且包含新失败的取回结果。覆盖多个交付同时入选及取回同时直接入选，父对象只输出一次；普通增量、完整同步和按历史起点同步均满足该规则。
- **验收 56**：分别覆盖交付与取回项共同变化、取回自身保存终态，以及仅交付内部变化且所有应报告内容不变。核验实际对象关联、计数、业务序号及快照维护进度；同一事件对同一对象不重复计数，多个应报告对象共用本事件的业务序号，补齐父对象不生成新的业务变化。覆盖提交回滚、提交未知、提交成功但通知丢失后的报告恢复。
- **验收 57**：取回计数保持不变，交付在两个冻结边界之间保存最终失败，验证两个边界的完整取回结果不同，缓存不得仅凭取回计数复用旧失败列表。同一状态库、同一取回及同一 H 的可靠结果可复用；改变缓存命中情况、分页大小和恢复方向，不改变同一报告的字节。
- **验收 58**：设备文件早于产物登记，随后补齐摘要并被清理，分别查询文件创建前、产物登记前后、摘要取得前后及清理前后，验证文件历史独立且身份保持。文件和产物使用不同快照及恢复方向时，与初始回放结果一致，后续观察不改变旧结果。多个取回共用源文件时不重复创建源文件身份。
- **验收 59**：普通交付的源文件与目标中间文件分别具有独立历史。副本准备完成后清理源文件，验证已保存的准备结果、固定源长度及校验依据不被改写；目标文件后续交接、撤回或清理按自身实际事实恢复。修复中间文件提升为正式产物时，文件身份与历史连续，提升前后的业务清理资格分别正确，快照保留稳定引用并按同一 H 查询文件。
- **验收 60**：覆盖文件在 H 尚未登记、合法无关联、应有关联缺失、引用文件在 H 不存在、身份或归属矛盾及文件历史损坏的分类。文件与相关产物或交付共同保存前后中断、回滚及提交未知时，分别取得可靠的完整事务结果；改变缓存命中、文件恢复批次和快照位置，不改变历史查询结果或冻结报告字节，回放不执行外部操作。
- **验收 61**：按文件完成、产物登记与 SHA-256 分类验证：满足登记条件且已有校验值时保留或共同保存；尚未取得时仍按既定时点登记；仅有校验值但缺少必要登记条件时不登记；适用内部处理的必需校验不能绕过。支持源端 SHA-256 的取回覆盖一致、不一致、获取失败及结果未知，明确不支持时才适用原降级规则，主机最终校验值仍必需。同一固定文件已有可靠源端值时可以复用；后来取得校验值不改变此前冻结报告。
- **验收 62**：仅设备文件取得 SHA-256、产物自身记录不变时，文件取得恢复关联并增加自身计数，报告目录登记产物，产物计数及快照维护进度不变。分别重建取得摘要前后的报告，验证旧值、新值及实际入选对象；在文件和产物两种类型中使用相同整数 ID，验证目录不会混淆身份。
- **验收 63**：按文件报告依赖表分别覆盖设备文件到产物、主机文件到产物、普通交付目标文件到交付，以及文件事实引起录像检查、取消内容处理等业务汇总共同变化的路径。内部拷贝进度和普通中间文件自动清理未改变公开结果时不产生报告变化。覆盖仅错误内容变化、状态变化但所需公开值不变、多个源字段命中同一目标及一条事件影响多个目标，核验目录、业务序号和计数分别正确。
- **验收 64**：文件事实发生在产物或交付关联建立之前、之后及同一事务内的不同事件时，验证旧事件不补挂后来才存在的目标，建立关联的事件能报告当时完整事实。后续新建引用者不改变旧报告入选集合；报告目录从初始历史重建后与原目录一致，不依赖最新业务关联。
- **验收 65**：同一文件的多个取回已分别保存固定源依据，文件后来取得新观察或被删除时，不批量改写拷贝或选中无关交付。仅定位、归属证据等内部变化且没有公开影响时，文件历史及计数正常保存，事件无业务序号；对应公开处理结果实际改变时仍能按其事件入选。
- **验收 66**：事件、两类目录、业务序号及投影共同保存，覆盖回滚、提交未知、重查已提交事务及提交成功但通知丢失。报告目录不得指向内部文件类型、不存在目标或不匹配的事件业务序号；必要关系读取失败和目录损坏不能降级为无变化。恢复关联与报告关联分别去重，不通过修改计数或清空错误绕过非法组合。
- **验收 67**：普通增量、完整同步和按历史起点同步均从报告目录选中对象，交付或产物入选后父对象完整补齐且只输出一次。覆盖同一对象在区间内多次变化及区间后继续变化，改变查询批次、缓存命中及正反向恢复路径，冻结报告的对象集合、顺序和字节保持一致。
- **验收 68**：分别检查窄区间增量与宽区间完整同步的带游标分页；保持入选对象数量不变并增加无关内部文件历史和区间外报告变化，检查额外读取成本，再增加入选对象数量验证分批处理。使用有数据且已更新统计信息的样本验证查询计划、读取量及有序去重，不能沿用原无游标空表检查作为性能依据，也不能先加载全量对象或目录到应用内存。

### 快照成员与历史文件集合

按[自身记录与快照成员](history-formats.md#自身记录与快照成员)及[历史文件分页](../historical-state-query.md#按历史边界分批查找关联文件)验证内部历史能力；这些验收不要求公开全部内部记录。

- **验收 H-01**：逐表覆盖自身记录归属。取回快照包含来源选择和取回项，交付快照包含普通拷贝及读取流程、尝试，录像快照包含内部处理及拷贝；三个快照都不包含独立文件行。产物快照包含自身来源关系及清理汇总，不包含清理动作的条目。覆盖残留停止、应急停止与各用途状态查询的不同归属，尤其验证查询预算归发起动作、实际活动变化归原动作。每个业务行恰有一个历史归属，未知分支及缺失归属链必须失败。
- **验收 H-02**：只改变所属子表、只改变独立文件及同一事件共同改变多个对象时，核对恢复目录、主对象历史元数据、计数和快照维护进度。同一事件改变一个对象的多行只计一次；复用事件正文不跨对象混用行。快照包含边界处全部自身成员，包括终态和失效行；使用从初始状态独立回放的行集合识别快照漏行、重行及混入其他对象，不仅比较已输出行的值。
- **验收 H-03**：构造先登记未知来源文件、后来确认来源、再登记正式产物、取得摘要及删除文件的完整历史。分别在每个边界按直接引用、观察者、确认来源、主机原责任查询，验证“不存在”“存在但无关联”“存在但集合为空”和错误各自独立。来源只能由未知变为固定值，主机原责任及快照成员的所属关系不可转移；文件提升和实际删除保留原文件身份、责任及历史。
- **验收 H-04**：分别使用批次上限 1、2 和默认值查询多页文件。安排一整页候选在 H 均不属于所查来源，下一页仍有有效文件，验证空有效页不结束扫描，继续位置取最后检查的候选。覆盖空表、空集合、候选数恰好一页、多个文件类型具有相同 ID，以及按 H 的状态过滤；不同批次取得相同升序集合，不无界扫描来填满有效页。
- **验收 H-05**：在两个实际读取连接间交错分页与提交。分别在游标之前、之后补齐旧文件来源，新增文件，推进清理、错误及用途；H 处的成员及状态保持。每个文件投影与其读取边界 C 一起取得，不借用候选查询的 C；不使用当前清理状态排除历史成员。注入候选查询失败、恢复失败、非法游标和取消，验证错误不被当作空页或完成，部分结果不发布。
- **验收 H-06**：对清理阶段推进、来源结束、交付最终失败、文件摘要补齐及中间文件清理分别保存冻结边界。组合对象计数未变、不同对象使用不同快照和恢复方向、已有缓存及无缓存；当前投影逆向恢复、快照正向恢复和初始状态独立回放取得相同内部结果。对于最终选定的公开字段，再比较同一 `report_id` 的入选集合、顺序及字节；内部查询依赖不自动扩大报告对象集合。

### 报告对象分页的具体查询验证

按[索引与分页规则](report-changes.md#报告对象选择的索引与分页)补充以下集成验证，使用真实 SQLite 与目标结构；样本的预期入选集合从测试输入事实独立计算，不调用被测选择函数生成预期。

- **验收 P-01**：从报告目标类型登记取得适用类型，覆盖无关联、上下水位相等、开闭边界、ID 不连续、同序号关联多个对象、同对象多次变化及不同类型使用相同 ID。覆盖候选容量减一、恰好容量和容量加一条关联；前两项完成有界选择，后一项在输出前切换续读路径。错误和取消不返回“读完”。
- **验收 P-02**：分别使用一项、多项和超过候选数量的实体页大小读完集合。各页与完整结果均无重复、无遗漏、按整数升序；有界路径只执行一次范围预查询，大范围路径不用 `OFFSET`，每页严格越过最后一个 ID。高重复密度按关联行数决定容量，不能为凑不同 ID 无界扫描预查询；参数类型严格校验，包括水位字符串和布尔值。
- **验收 P-03**：分别在无统计、空库执行 `ANALYZE` 后填充数据、代表性数据上执行 `ANALYZE` 的数据库中验证真实首批和后续游标查询。预查询按类型及业务区间使用覆盖索引；大范围查询按类型及对象 ID 定位覆盖索引，无全范围临时去重排序。结合实际执行工作量验证，不逐字断言整个 `EXPLAIN QUERY PLAN` 输出；SQLite 版本和索引集合改变后重新执行。
- **验收 P-04**：组合均匀变化、少数对象的大量重复变化、大量区间外历史及稀疏匹配。保持少量入选关联不变，将目录规模扩大，验证有界路径不改为扫描该类型全部历史；保持大范围数据不变而缩小页面，验证不会出现每页重复扫描完整业务区间的增长。记录查询次数、索引访问方式和 VM 指令等执行工作量；具备实际访问计数能力时另记访问量，不把指令数当作磁盘 I/O 或只凭 `FULLSCAN_STEP = 0` 判断索引查询高效。
- **验收 P-05**：在预查询后和大范围页面之间提交新事件，既包含旧对象的新变化，也包含新对象。冻结范围结果不变；新的 ACK、页面大小及缓存命中不改变报告字节。查询失败、取消、连接关闭或报告进程重启时，丢弃临时候选，沿报告既定身份与冻结范围重新生成，不把部分候选当作完整结果。
- **验收 P-06**：测量候选峰值和完整选择工作量，确认只保存容量以内的整数身份及本批状态，不预载对象历史，不新增主库写入或持久化候选责任。验证全局对象类型游标、父对象补齐和子集合游标分别管理；增加父对象条件或其他生产筛选条件的查询另行检查计划，不能以基础查询通过代替全部调用入口。

共同提交按相关索引定位并分批读取记录；分批读取不拆分必须共同提交的事务。不能先提交来源终态、稍后才解除等待。若实际依赖规模使保证无法满足既定运行边界，应带测量证据重新讨论。
