# 报告字段依赖的机器登记

[报告变化规则](report-changes.md) · [字段登记](report-dependencies.json) · [公共字段契约](../../architecture/report-format.md)

产物 O 引用设备文件 F。F 后来取得摘要时，生成器需要从 F 的历史读取摘要，事件处理器也需要知道这个变化可能更新 O。两者读取同一份[字段登记](report-dependencies.json)，分别取得字段值与受影响的报告对象。登记不保存第二份摘要，也不把 F 变成公开报告实体。

## 职责与权威来源

公共 Schema 定义输出结构，数据库字段规格定义已保存事实，内部枚举登记定义整数编号，公共错误登记定义错误编号与阶段。字段依赖登记连接这些来源，统一保存关联、出现条件、转换和报告目标。生成器及事件处理器读取或生成相应规则，不另建完整映射清单。

登记的 `format_version` 为 1，配合报告保存的生成格式使用。已有报告仍使用其原生成规则；不能使用后来变化的映射重解释旧报告。第一版实现和验收遵守既有格式范围，不在本登记中设计跨版本迁移。

| 登记部分 | 机器含义 |
| --- | --- |
| `entities` | 公开实体的数据库主表、身份、是否允许进入报告变化目录，以及父对象的关联键。`report` 只承载冻结元信息。 |
| `relations` | 两端具体列构成的关联。`cardinality` 表达从 `from` 所在记录查找 `to` 所在记录时的基数。反向查询按实际引用者逐项处理。 |
| `projections` | 一种公开实体或嵌套结果的生成规则，包含公共 Schema 引用、根表、报告归属、关联、出现条件及逐字段表达式。 |
| `assertions` | 生成字段前必须满足的既有跨字段不变量，登记其输入列及正式契约位置。它们不重新执行完成判定或外部观察。 |
| `routes` | 来源事实变化后查找待比较报告对象的路径。路由取得候选，不自动判定已经发生公开变化。 |
| `sql_pending` | 正式字段契约中存在、实际 SQL 尚未提供的精确列和外键。逐项指向规格依据，检查输出单独列明。 |

`schema` 使用公共报告 Schema 内的 JSON Pointer（JSON 节点路径）。媒体、原始错误及诊断数组本来就以公共结构保存，因此用 `read` 的 `json` 编码整体引用对应 Schema；其成员按原结构逐项同名映射。原输入和驱动参数中的开放成员保留实际值，不建立另一份成员白名单。

## 取值和出现条件

每个投影先检查其适用的已保存事实及组合，再计算 `when`。值为假时省略整个结果；值为真时按字段各自的 `when` 与 `value` 生成。`empty: omit` 只用于契约允许省略的空对象；普通结果数组保留空数组。缺少必需输入、引用目标缺失或组合矛盾均为状态库错误，不能通过条件为假掩盖错误。

`exists` 只判断历史查询已可靠取得的存在性。允许不存在的记录可以使该条件为假；查询失败、历史损坏及本应存在却缺失的记录不参与普通真假判断。所有条件都使用同一 H 的记录。

| 表达式 | 规定行为 |
| --- | --- |
| `literal` | 使用登记的常量。 |
| `read` | 读取明确列；`identity` 保持值，`id` 将精确正整数转为规范十进制字符串，`utc_seconds` 将整数微秒还原为规定的 UTC 秒级时间，`json` 无损解码结构化值。输出对象或数组必须使用 `json` 并引用对应公共结构，不能直接输出 SQL 中的 JSON 文本。无效值不能转成缺省值。 |
| `json_has`、`json_member` | 分别判断原 JSON 是否有指定成员和取得其原值。成员存在且值为 `null` 与成员缺失分别处理。 |
| `extra_input` | 从原输入中剔除公共计划 Schema 的动作字段，剩余键值组成额外输入对象；为空时省略。 |
| `enum` | 先按内部登记解释整数成员，再按本字段的显式映射输出公共值；没有映射的输入为错误，不使用名称猜测或默认值。 |
| `enum_is`、`not_null`、`eq`、`exists` | 使用原值或已登记枚举判断条件；可空枚举为 SQL `NULL` 时不匹配任何成员。非法非空枚举仍是错误。 |
| `all`、`any`、`not` | 按书写顺序进行布尔判断，允许短路；不把状态库错误解释为假。 |
| `cases` | 按顺序取第一个成立分支，否则执行 `otherwise`；分支内的出现条件和省略同样参与字段变化判断。 |
| `omit`、`error` | 分别表达合法省略与状态库错误，二者不可互换。 |
| `project` | 按被引用投影生成完整嵌套对象；保留父级已经恢复的上下文，沿其声明的关联建立子级上下文，不查询最新投影。 |
| `rows` | 沿指定关系分页读取完整固定成员集合，按 `order_by` 取得记录，再逐项生成；不按今天的状态删减过去的成员。 |
| `entities` | 仅输出本次报告选中的实体及结构要求的父对象，按精确整数 ID 排序，空实体集合省略。`encoding_order` 是该层子集合的精确正整数顺序，必须从 1 开始连续且唯一；子集合按此顺序放在自身字段之后，不依赖 `fields` 对象成员的书写顺序。它不表示读取父对象的全部子实体。 |
| `registered_error` | 从所属表的整数码在公共错误登记中取得 `code` 和 `stage`，将同一记录的详情 JSON 解码为 `details`。不能套用另一种明细的错误编号。 |
| `failure_union` | 按下节定义汇总来源、取回项和交付的最终失败；每条失败沿其原身份生成，不把尝试次数当成失败项数量。 |

关联记录的空值组合仍由各表契约校验。例如动作原设备字段同时出现在有效普通列和非法输入 JSON 中属于错误；不能由 `cases` 任取一份。设备完成依据与活动观察矛盾时，先报状态库错误，不能通过省略 `device_execution` 把矛盾隐藏起来。

投影根表表示当前记录角色。例如 `cancel_item` 沿 `cancel_target` 读取的是被取消动作的类型，父级取消动作仍由 `cancel_items.action_id` 关联。执行器为每个嵌套投影建立独立上下文，不让同名表的父级记录覆盖子级目标记录。

## 集合与逐项结果

来源依赖可以在取回进入执行前固定，范围清理也使用来源依赖，因此 `dependency_selection` 的全局基数为 `optional_one`。取回已经进入执行且来源固定后，`executing_obtain_has_selections` 要求每条依赖都有唯一来源选择记录；执行后才固定来源时，两者也必须共同建立。取消或终态允许这些记录保持 `PENDING`，不允许记录消失。合法空来源必须由解析状态和业务规则证明，不能仅由零行推断。具体转换见[来源等待](waiting.md#来源等待的记录与转换)。

取回失败的三个分支如下。查询范围是该取回在 H 的全部固定来源、明细及关联交付，不受本次报告的交付增量子集合限制。

| 保存的事实 | 失败项及报告归属 |
| --- | --- |
| 来源选择具有最终错误 | 从来源选择的错误及依赖关系取得来源身份；归取回动作。 |
| 取回项为 `FAILED`，尚未创建交付 | 从该项取得实际产物关联及错误；归取回动作。请求中无效的产物 ID 只保留在错误详情中。 |
| 关联交付为 `FAILED` | 从交付取得最终错误、交付与产物身份；归交付，报告补齐所属取回并重新生成其完整自身字段。 |
| 条目尚未完成或内部尝试仍可重试 | 不新增最终失败项；其他已经成立的失败继续保留。 |

三个分支使用各自表和主键作为内部身份；重复返回同一身份属于错误，不通过静默去重隐藏查询或归属问题。不同无效请求 ID 各有取回项，不能按缺席的产物、交付身份合并。交付与取回项已经存在的唯一关联须在恢复时核对。

失败数组先按固定依赖 ID 排序，再按登记中的分支顺序、分支身份排序。清理和取消数组按首次固定成员时保存的明细 ID 排序；精确清理在共同登记目标时按原请求顺序分配明细 ID。来源范围清理按固定选择顺序分配。由此分批读取和不同恢复路径都保留同一结果顺序；不按后来完成顺序重排。

交付 `size` 来自该次拷贝保存的完整源长度，`sha256` 来自该轮完整目标摘要。准备完成所需的长度、校验和目标文件事实由 `delivery_complete_file_consistency` 对应契约核对。源文件后来新增观察或被清理不替换这些固定依据；未完成字节数不能代填长度。

## 依赖展开与报告更新

依赖从表达式自动展开，不另存一份手写字段依赖列表。展开范围包括取值列、条件列、JSON 成员路径、关系两端、存在性、成员身份、排序键，以及适用前置校验的列。沿 `project`、`rows` 和 `failure_union` 继续展开被引用投影；遇到 `entities` 时保留独立实体边界，不能把其全部自身字段并入父对象的变化条件。

事件处理器沿登记的关联按需、分批定位候选。对受影响的字段，用事件前后的可靠记录执行同一生成规则，并比较值与存在性；无需生成整份报告。事件前后的关联分别使用当时已建立的关系，新建对象或关系由创建事实负责，旧文件事件不补挂后来的产物。

| 比较结果 | 目录与序号 |
| --- | --- |
| 公开字段值不变，出现条件也不变 | 不登记该报告对象；内部历史仍按实际变化保存。 |
| 字段值变化，或字段出现、消失 | 按路由登记受影响的公开实体。 |
| 同一事件多条规则命中同一实体 | 只登记一次；不同实体分别登记，共用该事件的业务序号。 |
| 选中产物或交付后需要父对象 | 沿 `entities.parent` 在同一 H 补齐；不为补齐本身增加父对象历史计数、目录记录或业务序号。 |
| 只有报告元信息、ACK、尝试或内部维护变化，没有公开字段影响 | 不产生新的应报告业务变化。 |

路由中的 `when` 同样参与候选分类。主机文件作为录像内部副本时，不存在普通交付身份，不能沿普通交付路由构造报告对象。没有匹配的已建立报告关系是合法无目标；应有关系缺失、目标不存在、读取失败或归属矛盾则按状态库错误处理。

持久化时，字段生成、变化判断及历史回放共用本登记的版本。事件、投影、目录及相关计数继续共同提交；提交未知按原事务身份核实，重试不重复分配序号。登记不改变快照成员，也不把文件行复制进引用对象的快照。

## 检查与实施边界

在仓库根运行：

```sh
node --disable-warning=ExperimentalWarning scripts/check-report-dependencies.mjs
node --disable-warning=ExperimentalWarning --test tests/integration/report-dependenc*.test.mjs
```

检查使用 Node.js 24 的 SQLite 接口读取真实规格 SQL，并复用客户端已锁定的 Ajv。它核对公开字段覆盖、嵌套结构、枚举转换、关联两端、父对象补齐、错误编号职责、来源列及引用闭合。需要独立生成的新字段未登记、登记引用已不存在字段或关联错误都会使检查失败。原样保存的公共 JSON 子树继续整体引用同一 Schema，不复制内部成员清单。

`sql_pending` 逐项列明目标契约和实际 SQL 的差异；声明必须被登记实际使用，不能掩盖任意未知列。SQL 同步后移除相应声明，检查即改用实际列和外键。该名单不是 SQL 实现已完成的证据。

第一版登记的 `sql_pending` 为空，全部来源列和关系使用实际 SQL 校验。历史对象的编号、主表及目录资格由[内部登记](enum-registry.json)的 `history_objects` 提供；报告字段登记中的公开实体与这些报告目标须对应，内部文件仍只作为读取依赖。

条件场景从具体已保存事实检验设备提示出现和解除、原输入省略与 `null`、结果分支、交付固定依据等规则。检查器不执行全部业务不变量，也不代替生产事件处理器、Python 生成器、真实历史恢复、完整目录重建或跨组件集成。后续实现须读取本登记，并完成[历史与报告验收](consistency-verification.md#独立历史与报告重建)规定的验证。
