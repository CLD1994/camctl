## 输入恢复与复现范围

八档对照复用了[前一轮诊断](../2026-10-25-integration-batch-write-analysis/metadata.json)的同一份 200 成员冻结数据库。所有连接和原有测试进程已结束；每档关闭当前连接，检查没有 WAL／SHM 旁文件，再恢复相同物理路径，以保留已登记的路径身份。打开后核对完整逻辑摘要，操作后再核对整个数据库的逻辑摘要，不能只凭返回成功认定等价。

完整逻辑摘要取自同版本 SQLite 的 `connection.iterdump()` 全部输出，包含数据库结构和全部表记录，按原输出连接后计算 SHA256。本次没有执行视频文件内容写入，输入文件大小事实不代表实际视频字节吞吐。

`metadata.json` 和原样脚本中的绝对路径是历史执行来源，不是正式步骤的前置条件；冻结数据库二进制没有纳入仓库。不能在已有业务数据库上直接运行该原样恢复脚本。需要重新测量时，从 `source_head` 创建独立源码副本，按组件指南发布其资源，使用 `_ready_world(独立目录, count=200)` 创建本次专属输入。冻结前保存申请和新操作键、完成 WAL 检查点并关闭连接，再在本次专属物理路径执行相同对照。世界构造与 SQL 包装的实现可参照[已归档准备过程](../2026-10-25-integration-batch-write-analysis/probe.py)以及相应源码基线中的原测试，不另维护业务准备逻辑。新世界的身份和摘要会变化；每档应与本次自己的基线、返回值和保存结果比较。

对照采用原测试的 SQL 计数包装；前三组单独改动及合并档各一次，普通原实现前后各一次，内存跟踪只比较原实现与合并档各一次。所有档串行运行。开关、输入与完整性证据比历史绝对耗时更适合用于复现；这些样本不能代替正式源码回归、全量回归或目标主机性能验收。

补充验证在该副本的对照进程结束后串行运行，91 项全部通过，含未更改规模和门槛的原容量测试。`validation/README.md` 解释外部函数替换及通过用例标准输出未保存的限制；实际三档峰值没有恢复，不能将门槛数值当成实测峰值。顶层 `archive-manifest.json` 维护本目录其他证据文件的归档摘要；验证子目录中的清单是当时临时目录的原始来源记录。

归档时仅去除了 `validation/capacity-source.txt` 末尾的空白行，正文和门槛没有改动。该文件的来源摘要保留在子目录清单，归档后摘要见顶层清单。
