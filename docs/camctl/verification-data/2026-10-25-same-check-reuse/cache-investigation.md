## 第一优先：一个函数内使用已经取得的局部值

### A1：一次构造索引，复用已核验的文件创建身份

位置：`persistence/repositories/result_pages.py:350–396`。

1. 现在第 378 行为每个 CREATE 重新 `dict(file_ids)`；将身份索引移至循环外，函数内构造一次。最多 128 项，与本页规模一致，不增加跨调用缓存。
2. 第 354 行已取得、核对文件完整身份，并保存其创建事件身份到 `expected_created`；第 388 行又通过 `row_facts` 取同一文件的 `created_event_id`。这个函数只执行读取，没有中间业务写入，也不把前一阶段对象传进来，可以在当前局部索引中保留 `(file_id, created_event_id)`，用于第 389 行的原有比较。只保留所需整数，不保留额外的完整行字典。
3. `expected_created` 本来就是按 `file_ids` 顺序过滤生成。第 392–393 行的嵌套 `any` 可直接从此列表生成期望身份对，仍保留现有完整三元组和顺序比较。

它减少重复小字典、查找和可能的缓存复制／计量；不能保证每次第二次读取都是 SQL 命中，也不能据此计算 SQL 节约量。缓存可能已被同一页的其他读取挤出，因此局部复用甚至可能同时减少 SQL。没有新的全组成员集合，函数返回后释放；最多 128 项的临时索引仍须通过原峰值验收。

风险：低到中。主要是错用键、改变旧文件／新文件区分或 CREATE 原顺序。不可只用数量代替当前逐项精确比较。

### A2：同一局部事件成功解码后只做一次相同结构检查

证据链：`history/decoding.py:35–59` 的 `decode_event_row` 在返回前已执行 `validate_event_structure`。

- `result_pages.py:334–336` 将原事务的每条 SQL 行解码为局部事件；第 366 行又对这些 CREATE 做相同结构检查。
- 第 409–413 行解码 INDEX_FILES；第 434 行再次检查同一局部对象的结构。
- `_load_at_record:469–470/477–481` 先解码原行，再调用 `_decode`，后者第 196 行又检查同一结构。

可以在刚解码、未暴露给其他参与者、未修改对象的直线数据流中复用这次成功检查，继续执行全部 RESULT_PAGE 专有载荷、事务位置、来源、身份和关系比较。对于 `_decode`，建议保留默认入口的完整检查，将页载荷解释拆成私有步骤；只有紧接着真实 SQL 解码成功的内部路径进入该步骤，并继续明确核对 RESULT_PAGE.APPEND 身份。不要给任意调用者一个可随意传入的 `skip_validation=True`。

不能直接全局删除 `_decode` 的结构检查：`_page_guard:1617`、`finite_cancel.py:144/316`、`capture.py:6116/6154/6231` 也使用它，输入不都来自紧邻的历史行解码。保留这些实际调用端的检查，不能把提案事件自带的“已验证”标记作为证明。

风险：中。减少的是一个读取函数中同一局部对象的重复结构检查，不是取消独立守卫或复用上一阶段授权。每次原行缓存命中仍重新解码并完成一次结构检查，符合现行第 306 行。

### A3：已有函数局部记录去重，作为次要后续

`read_pages:582–593` 已有 `verified` 局部表；当 `cursor == first` 时，可以直接使用刚读取的首记录，再执行所有当前票据和游标比较，无须第二次 `_at_record`。`read_page_at:650–651`、`read_last_page:664–665` 也有取得页后再走 `read_page` 重取的模式，但须先明确调用时真实读事务和可见状态边界，不能把事务外先读到的页直接当作后一次可见状态。

这几条没有出现在 N200 函数剖析清单中，不计入该样本预期收益；不应因此扩大第一步范围。

## 第二优先：保持隔离规则，减少通用缓存本身的计算

### B1：对确实平坦的内建字典提供复制快路径

`row_facts` 返回值经常是字典，但 `actions`、`device_files` 等行可含 JSON 字典和列表，不能统一改成 `dict.copy()`。可以先只诊断顶层类型与平坦程度；若平坦字典占比足够大，再对“精确内建 dict，且全部键和值都是精确内建不可变标量”的情况使用浅复制，其余完整回退到现有 `deepcopy`。

这一快路径在保存与命中两处都要保持字典实例隔离；`dict` 子类、数值子类、嵌套容器、数据类和自定义复制对象继续走原实现。额外类型扫描和回退本身也有成本，是否获益需要同一冻结输入对照。

风险：中，因影响所有复用入口。先测值形状，优先做 A1/A2，不预设它会快。

### B2：递归字节计量只调整遍历实现，不改变预算含义

可评估减少 `_retained_size:123–143` 的生成器及递归调度开销，或让遍历在已严格超过 2 MiB 后立即返回“超限”，因为这类结果本来不会登记。必须保留一个键和值共用的 `seen`、别名去重、循环容器、数据类字段及其 `__dict__` 大小；低于预算时的结果须与原计量相同。超限时不得先淘汰已保存的小值。

这种提前停止只帮助确实超限的条目。现有归档没有“超限拒绝次数／遍历深度”的记录，不能把 1,459,304 次递归全部视为可删除工作。它也不能消除当前先做 `deepcopy` 的成本。不要以 `sys.getsizeof` 顶层大小或固定每条估值替代递归预算。

风险：中。自定义对象、重复引用与递归图是现有实际契约，不能仅按本次 JSON 样本重写一个不支持它们的复制／计量器。合并复制与计量为一遍需同时处理复制 memo、别名、循环、数据类、自定义复制行为以及键和值共享，复杂度较高，暂不作为第一步。

## 哪些“不可变”值不能直接返回

- `EventEnvelope` 和 `RowImage` 虽是 frozen 数据类，`history/events.py:34–65` 的 `evidence`、`values` 实际来自 JSON 字典，里面可以有列表；字段标注 Mapping 不保证底层不可变。
- `SavedResultPage` frozen，但其中 `ResultPage` 含 `ObservedFile.locator/evidence`，以及 `CallOutcome.observations[].data` 的字典／列表；`capture/result_inputs.py:20–53`、`operations/models.py:120–129` 明确了这条嵌套链。
- 一个 tuple 中放入字典，或者只套只读映射视图，都不足以证明整个对象图不再改变。现有 `test_read_reuse.py:325–364` 明确要求这些真实类型的返回值与缓存隔离。
- `TransactionRange`／`HistoryBoundary` 的声明字段都是整数，适合以后单独审计为小型不可变值，但不能以所有 frozen 数据类都可共享为规则。若改为不复制，需限定具体类型及成员条件，并检查既有返回值隔离约定；它们体积小，当前没有证据证明值得先改。

将 JSON 全部改为递归不可变表示、给业务值增加自定义 `__deepcopy__` 共享行为，会影响解析、精确数值／布尔区分、比较和公共返回形状，应单独评估；不能只为了通过缓存优化绕过现有可变值隔离。

## 需要另行决定的设计变化

下列做法改变明确的现行设计，不能并入上述局部整理：在三页缓存中保留 SavedResultPage／EventEnvelope／完整解码字典图；命中后完全跳过原行解码和页结构检查；让规划与独立检查共享证明；跨事件清空点或写入代保留通用缓存；增大 3 页、128 条或 2 MiB；保留整批／全组成员表以取代流式读取；取消实际当前资格、边界、反向覆盖或原键完整组核实。

原页命中后仍解码是明确选择，不是未经实现的缺口。A2 可去掉紧接着的第二次相同结构检查；若目标是去掉整个原页命中的解析，必须先讨论第 306 行及内存驻留方案。
