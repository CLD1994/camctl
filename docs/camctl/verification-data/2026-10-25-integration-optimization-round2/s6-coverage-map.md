# Hasselblad 预设前缀的静态覆盖映射

2026-10-25 UTC，基线为 `f8121feb5bfcb2c38839cb5f240b7a4de32fca66`。本记录核对正式优化计划 S6 的覆盖承接，尚未实施或重新运行测试。完整身份、原断言、参数正文、源码位置及既有能力文件摘要见同目录 [机器记录](s6-coverage-map.json)。后续运行改动以 S5 的稳定客户端接口为起点。

## 六类输入与独立执行世界

`PhotoCase.params_text` 将格式与三组参数组合成六类。每类保留一个完整网页代表，另一来源继续独立拍摄、取回、上传并确认报告。来源取自部署配置，不进入拍摄参数。因此配对世界的完整 `params_text` 相同，数据库中固定的 `output_storage` 仍不同。

| 格式 | 参数组合 | 完整网页代表 | 真实 Application 导出世界 |
| --- | --- | --- | --- |
| RAW | `0.000667`；M、ISO 100、f/8；manual 5500K；MF 移动 5 | `raw-host-0.000667` | `raw-device-0.000667` |
| RAW | `0.000333`；S、ISO 100；auto；AF-S | `raw-device-0.000333` | `raw-host-0.000333` |
| RAW | `0.00025`；M、ISO 100、f/8；daylight；MF 省略移动量 | `raw-host-0.00025` | `raw-device-0.00025` |
| JPEG | `0.000667`；M、ISO 100、f/8；manual 5500K；MF 移动 5 | `jpeg-device-0.000667` | `jpeg-host-0.000667` |
| JPEG | `0.000333`；S、ISO 100；auto；AF-S | `jpeg-host-0.000333` | `jpeg-device-0.000333` |
| JPEG | `0.00025`；M、ISO 100、f/8；daylight；MF 省略移动量 | `jpeg-device-0.00025` | `jpeg-host-0.00025` |

六个代表包含 host 与 device 各三项，并贯通四种格式×来源组合。原三个定向预设用例继续保留：它们均为 JPEG/M/manual/MF 移动 5，只改变短快门，继续承接不刷新执行时间及过期时间刷新等定向行为。其参数不能代替 RAW、S、auto、AF-S、daylight 或 MF 不移动的网页见证。

此映射保持原 29 个 pytest 身份、12 个正常拍摄世界和六个故障世界。完整照片网页前缀由原 21 次变为九次：六个正常代表加三个原定向用例；另六个正常世界及六个故障世界由真实客户端 Application 导出。各世界仍使用独立存储、状态库及文件责任。

## 能力说明的等值范围

已只读比较最终冻结轮保存的 12 份真实正常世界能力文件，host、device 各六份。完整 JSON 仅 `/devices/0/delete_supported` 不同，分别为 `true` 与 `false`；Schema、名称、说明、预览声明及设备／动作／参数身份相同。机器记录保存每份文件的路径、字节数、SHA-256 与删除该字段后的精确比较摘要。

当前基线的 `catalog.py`、Hasselblad 的定义、配置、参数及任务说明源码，与产生这些文件的冻结源码逐字节一致。生产目录只按来源选择主机或设备的删除声明；部署任务绑定只改变 `output_storage`，能力文档不导出任务工厂。这与[公共能力规则](../../../architecture/camera-capabilities.md#部署时向客户端提供说明)一致。

这个等值关系只支持复用网页参数分区。host 正式文件归档及相机离线交付，与 device 工作副本回收及按机内名称下载，继续在原独立世界中实际验证。

## 原网页断言的承接

| 原观察或断言 | 六个网页代表及原三个定向用例 | 另六正常及六故障世界 |
| --- | --- | --- |
| 从实际安装能力按设备、动作和参数类型选择 Schema；实际选择格式与对象分支 | 继续操作真实控件，覆盖两种格式、M/S、三种白平衡、MF/AF-S，以及移动量存在与省略 | 自身客户端按实际能力完整校验；仅据此证明后端导出成立 |
| `source_draft_text` 的快门词元 | 保留原字段及精确断言 | 读取真实保存草稿 `draft_text`，核对自身完整参数和快门词元 |
| `reopened_draft_text` 的快门词元 | 实际关闭并重建 Application、Files、HTTP 和浏览器，再读原草稿 | 由同输入类的网页代表承接重开步骤 |
| `applied_draft_text` 的快门词元 | 实际创建独立草稿并应用预设，保留原字段及精确断言 | 由同输入类的网页代表承接应用步骤；自身保存草稿另行等值核对 |
| `preset_params_text` 的快门词元 | 实际保存预设，保留精确断言 | 由同输入类的网页代表承接预设步骤 |
| `reopened_preset_params_text` 的快门词元 | 实际重开原预设，保留精确断言 | 由同输入类的网页代表承接预设重开步骤 |
| `preset_http_text` 的快门词元及定向用例的 HTTP 201 | 继续核对真实 POST 响应与正文 | 由网页代表及原定向用例承接 HTTP 边界 |
| `request_text` 的快门词元及实际下载正文 | 继续保存网页下载原文 | 保存真实 `downloadRequest` 的同一序列化正文，并核对磁盘文件全文、请求身份及词元 |
| 原草稿／预设应用后不变、独立草稿身份、完整参数、公共字段及时间刷新 | 继续执行原检查；原三个定向用例的完整等值断言保持 | 自身草稿与请求检查实际动作数、身份、完整参数、策略和时间；依原刷新策略选择执行时间 |
| 显式关闭自动预览 | 保留原真实网页步骤 | 真实草稿表达相同的关闭意图，导出恰有一个拍摄动作 |

机器记录逐项保存原 249 个 Python `assert` 节点的责任函数、行号、正文及承接规则，并展开七路 UI 词元与十组浏览器操作的映射。六类覆盖的是原输入已见证的正向分区。源码数据流显示，原照片前缀先整份填入 JSON，清除预览元数据，应用预设后经 `unset` 菜单禁用预览；这些输入未见证初始 `enabled` 等其他分支。本次没有重新验证浏览器渲染。

真实 Application 路径使用既有 `createDraft → exportDraft → downloadRequest`。当前测试接缝只给出请求身份、时间及 ACK 摘要，实施时需增加从实际保存对象取得的草稿身份／正文、完整请求正文与实际能力摘要。每个世界都在导出完成后、启动或提交前核对自身凭据，涵盖不会进入成功精度辅助函数的未保存 START 结果场景。回执只记录真正执行的步骤。

## 六个故障世界

下表身份是测试函数及参数后缀；完整 nodeid 和该实例 `tmp_path` 下的世界根共同组成机器身份。`PhotoCase.name` 不含 `focus_override`，单独使用它不能区分故障世界与正常世界。

| pytest 身份 | 实际输入 | 继续保留的故障与恢复断言 |
| --- | --- | --- |
| `saved_start_recovers_without_replay[jpeg-host-0.000667]` | JPEG/M/manual/MF 移动 5 | START 结果完整提交后终止旧组；新组沿原活动、尝试和事务恢复；双角色各两次独立取回；设置、对焦、拍摄不重放 |
| `saved_start_recovers_without_replay[raw-device-0.000333]` | RAW/S/auto/AF-S | 同上；保留原设备源定位及四次独立下载 |
| `complete_commit_receipt_loss_reuses_request[jpeg-host-0.000667]` | JPEG/M/manual/MF 移动 5 | 真实 COMMIT 后回执未知；另一只读连接核实原完整申请、原键及 H；重启和重复取回保持原身份 |
| `complete_commit_receipt_loss_reuses_request[jpeg-device-0.000333]` | JPEG/S/auto/AF-S | 同上；保留设备源登记、回收及下载断言 |
| `missing_start_result_never_replays` | JPEG/M/daylight/MF 移动 5 | 原 START 仅意图；真实旧组收场及恢复 horizon；UNKNOWN、未知占用、原双工作文件、无产物、不重放 |
| `report_rebuild_keeps_frozen_bytes` | JPEG/M/manual 5500K/MF 省略移动量 | 真实目录发布失败；新进程按原 H 重建相同报告身份、名称、字节和摘要；原管理事务及四次独立交付保持 |

最后两项的 `focus_override` 参数没有与六个正常网页代表完全相同的组合。它们只共享已被网页实际覆盖的字段分支；各自完整参数与词元必须由真实草稿和请求独立核对。未保存 START 结果的场景原本没有成功产物、成功历史精度或 ACK 断言，其未知结果责任保持。

## 业务合同及证据边界

[参数规格的安装版验收](../../../superpowers/specs/2026-10-20-hasselblad-photo-parameters-design.md#安装版的完整业务验收)要求四种格式×来源组合分别贯通完整业务过程，短快门至少覆盖三个。原 H8 实施记录曾明确每个请求从选值、预设重开和导出开始；当前 S6 明确批准按六类迁移覆盖。实施时，运行指南需要准确描述新的实际路径，原业务最低四组合契约保持。

12 个正常世界的 C host、安装版 CLI、一次 capture、精确 argv、双角色与原来源、四次独立交付、三种上传次序、网页累计 ACK、原请求重送及固定 H 前后核对继续实际执行。六个故障世界保留各自原事务、门闩、旧进程组收场及恢复语义。普通 Application 导出与 HTTP 导出使用同一真实后端，但 HTTP 显式携带浏览器能力版本，DOM 选值、预设及网页下载仍只由实际网页路径证明。

此静态记录没有产生新的运行结果或耗时收益。S5 稳定后需以其接口实施并取得原 29 身份的实际结果，才能确认覆盖迁移及收益。
