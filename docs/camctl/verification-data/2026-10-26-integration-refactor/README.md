# 集成测试重构的阶段证据

实施目标与未完成事项见[重构记录](../../integration-test-refactor-2026-10-26.md)及[优化计划 S13](../../../superpowers/plans/2026-10-25-integration-test-optimization.md#s13通过公开入口重构保留的集成测试)。

`stage-1/manifest.json` 记录协调分支身份、各执行分支身份及报告含义。压缩的组报告保存当时的原目标映射、命令与结果；它们是阶段快照，不能代替最终组合验证。报告尚未更新的文件仍按未完成处理。

`stage-1/coordinator` 保存协调分支实际执行的日志、JUnit 与进程收据。`combined-support-separate` 中各目录使用独立 pytest 进程；较早的 `combined-support` 是主动中断的跨目录调用，退出为 2，不计作范围通过或耗时对照。数据库基础支持另有独立运行记录。

`.json.gz`、`.xml.gz` 和 `.log.gz` 都是标准 gzip 文件。可用 `gzip -dc 文件路径` 查看，JSON 还可以接 `python -m json.tool` 便于阅读。最终证据将另建阶段目录，保留本次快照。

`capacity-513/` 保存 513 项容量负载的实际命令、源码逐文件摘要、sudo 委派与独立受限 worker 收据、阶段计时、业务结果和 pytest 日志。协调者已独立核对合计限额、合计峰值、事件、退出与回收，并确认其中记录的 329 份生产及协议文件与协调分支一致。测试源身份仍按该次运行记录识别。

`stage-2/manifest.json` 保存第二批逐目标映射、252／86／99／21／18 项的完整运行记录、来源内存增长诊断，以及协调分支单元全范围和窄复核记录。`databases/` 由原库以 SQLite 备份 API 取得完整视图，再经完整性检查和压缩，包含目录调用取消、原文件结果遗漏与本地纯停止的证据。清单记录原来源、解压后摘要、压缩文件摘要及各文件含义；各组报告仍保留其运行时点，不代表同一次全量运行。

`stage-3/manifest.json` 续增默认恢复、输出诊断、流式规则及分段副本消费者的阶段交付，保存协调分支 349 项组合的命令、完整日志、JUnit 和源码摘要。生产边界核对记录包含当时 21 个工作区，与本次禁止生产修改的范围对应。各执行者报告中尚待审查的候选保留原分类，不计作已确认生产缺陷。
