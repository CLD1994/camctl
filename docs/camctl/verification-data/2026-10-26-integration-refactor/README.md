# 集成测试重构的阶段证据

实施目标与未完成事项见[重构记录](../../integration-test-refactor-2026-10-26.md)及[优化计划 S13](../../../superpowers/plans/2026-10-25-integration-test-optimization.md#s13通过公开入口重构保留的集成测试)。

`stage-1/manifest.json` 记录协调分支身份、各执行分支身份及报告含义。压缩的组报告保存当时的原目标映射、命令与结果；它们是阶段快照，不能代替最终组合验证。报告尚未更新的文件仍按未完成处理。

`stage-1/coordinator` 保存协调分支实际执行的日志、JUnit 与进程收据。`combined-support-separate` 中各目录使用独立 pytest 进程；较早的 `combined-support` 是主动中断的跨目录调用，退出为 2，不计作范围通过或耗时对照。数据库基础支持另有独立运行记录。

`.json.gz`、`.xml.gz` 和 `.log.gz` 都是标准 gzip 文件。可用 `gzip -dc 文件路径` 查看，JSON 还可以接 `python -m json.tool` 便于阅读。最终证据将另建阶段目录，保留本次快照。

`capacity-513/` 保存 513 项容量负载的实际命令、源码逐文件摘要、sudo 委派与独立受限 worker 收据、阶段计时、业务结果和 pytest 日志。协调者已独立核对合计限额、合计峰值、事件、退出与回收，并确认其中记录的 329 份生产及协议文件与协调分支一致。测试源身份仍按该次运行记录识别。

`stage-2/manifest.json` 保存第二批逐目标映射、252／86／99／21／18 项的完整运行记录、来源内存增长诊断，以及协调分支单元全范围和窄复核记录。`databases/` 由原库以 SQLite 备份 API 取得完整视图，再经完整性检查和压缩，包含目录调用取消、原文件结果遗漏与本地纯停止的证据。清单记录原来源、解压后摘要、压缩文件摘要及各文件含义；各组报告仍保留其运行时点，不代表同一次全量运行。

`stage-3/manifest.json` 续增默认恢复、输出诊断、流式规则及分段副本消费者的阶段交付，保存协调分支 349 项组合的命令、完整日志、JUnit 和源码摘要。生产边界核对记录包含当时 21 个工作区，与本次禁止生产修改的范围对应。各执行者报告中尚待审查的候选保留原分类，不计作已确认生产缺陷。

[第八批证据](stage-8/README.md)保存结果页 47／146 项、清理与诊断 253 项、日志启动扫描 27 通过及一项失败、单元 9371 通过及一个跳过的独立运行。完整源码清单、失败库及其 WAL／SHM、根目录非 Python 静态审查与参数比较分别归档，保留原来源与压缩前后摘要。静态判定不替代执行，多个源码快照的结果不合并为一次全量回归。

[第九批证据](stage-9/README.md)保存取消与媒体的后续运行、旧新映射、启动扫描独立诊断、无保存故障的媒体竞争复现，以及两个历史慢节点的分阶段计时。独立运行和静态交接分别标明来源；缺失的单项源码摘要、不同诊断窗口、未到达的断言及导入路径核对限制均明确保留。

[第十批证据](stage-10/README.md)保存报告选择观察器调整后的完整 43 项运行、精确测试源与单文件差异。作者与协调分支的生产、测试目录内容相同，记录仍只有作者那次运行，不补造协调分支执行；其余私有观察及当前连接匹配限制保持明确。

[第十一批证据](stage-11/README.md)保存分段历史准备的 35 项、报告观察的 43／1／1 项阶段结果，以及最终集成源码两文件的 88 项组合。相同节点在不同阶段的运行分别记录；早期源码缺项、拼接导入路径与独立预检的证据边界均明确保留，不能合称整目录或全量通过。

[第十二批证据](stage-12/README.md)保存三份冻结源码的静态边界审计；候选及设计不作运行验收。[第十三批证据](stage-13/README.md)保存共享时钟的实际前后对照、分目录验证、读取诊断既有失败、延时启动及一个尚未采纳的只读样本原型，分别保留其源码、覆盖变化和预算更正。

[第十四批证据](stage-14/README.md)保存共享准备端口的旧新对照、五目录运行与实际失败、默认读取的媒体竞争单节点对照，以及 513 项容量补验。早期源码缺项、不同快照及独立导入预检均分别标明；容量采用专属委派，实际业务叶组的合计峰值为 36,020,224 字节，不外推任意规模或严格无交换能力。后续异常身份修正、自然等待和媒体时钟证据另行归档。

[第十五批证据](stage-15/README.md)补齐共享准备异常身份的红绿对照及 31 项停止点运行，并引用第十四批实际已有的修正后 495 项载荷；另保存自然等待 27＋1 的新旧事实比较、完整 299／13 项运行，以及媒体时钟两次各 20 项运行和比较。早期两分区探针的精确源码缺失，现存三分区源码按后续快照识别；静态分段入口核查不作为运行通过。

[第十六批证据](stage-16/README.md)保存冻结 105 文件的 2137 通过／30 失败，以及另一快照的完整 history 349、persistence 952 项通过，分别保留命令、逐节点、源码、资源与收场证据。事务各批、固定样本与真实生成、异步准备修正及命名也分别归档；三组早期 dirty 源码缺项按实际标明。该目录另保留两组早期作者记录，它们不计入本轮两目录结果。普通组件运行与独立容量叶组的计量范围分开，原始失败不由后来单节点通过回填。

[第十七批证据](stage-17/README.md)保存结果扫描四文件的各轮 85 项、工厂状态两文件的各轮 41 项、冻结六文件的 126 项，以及 Action6 各阶段和冻结四文件的 23 项。协调者独立核验 117 个载荷、21 份 Git 源码及五份补丁；三份中间测试源码缺项保持原记录。两个组合各有 1358 份实际源码与资源的前后清单，其中 27 份生成资源没有对应 Git blob；这些范围不合称一次全目录回归。

[第十八批证据](stage-18/README.md)保存拍摄后续批次的代码、独立评审和实际数据库比较，以及 `86956015` 十八文件的 363 通过、两项既有失败和对应失败库。协调者独立核验 182 个载荷、50 份 Git 源码及五份差异；原运行的命令或测试源码缺项仍按实际保留。配对三十项仅作分阶段成本诊断，历史缓存与候选容量仅作静态调查，不计作优化实现或功能缺陷复现。

[第十九批证据](stage-19/README.md)保存逐文件索引的生成、旧分类与静态计数修正、最终校验和协调者独立重算，以及就绪文件九项原拥有者重送的公开入口调查。静态索引覆盖 658 个源文件，不给出未经收集和去重的剩余实例总数；就绪文件的两次十五项运行没有代码变化，不作迁移或提速声明。
