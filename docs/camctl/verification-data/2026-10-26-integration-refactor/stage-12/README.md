## 必须保留的场景差异

分段检查审计把伪造来源集合的目标时长 1000 毫秒（1 秒）与检查请求 60 秒或 60 帧区分开来；拒绝目标分别是 61 秒和 61 帧。常规预算是 3 次、10 秒、间隔 0 秒，只有真实耗尽节点使用 1 次、10 秒、间隔 0 秒。默认分段为 4 MiB，而 _inspection_runtime 路径使用 4 字节。这些输入不可合并为一组等价场景。

共享准备审计也保留各自时钟和预算：默认 consumer 与自定义 callback 的来源、冷重开和取消阶段各有不同初值。精确预算 None 语义仍未裁决。后续实现需逐项对应原目标、时刻、预算、存储键和停止边界，不能仅以 AST 候选数量或 partial35 通过代替覆盖审查。

分段检查报告指出 inspect_segment 与 read_inspection_for_member 是有文档支持的入口；前者还创建或恢复检查责任、读取并探测文件，不能只称为查询。生产 Action6 消费路径并未因此把测试手造 MediaFlow/runtime 变成公开构造入口。原报告建议先从真实来源与处理器确定目标，再分开验证独立检查请求的拒绝条件、读取故障和冷/同 owner 收场；缺少正式入口或物理中断边界的节点应保留为未决。报告另将正式会话采用合法 1ms 轮询时的媒体同文件冲突列为独立事项，但本静态审计没有运行该用例，不据此将这 16 个节点归为生产缺陷。

## 解释边界和完整性

三份审计均固定记录 caaba 基线，并声明未运行测试。remaining survey 的 650 个源摘要随原 JSON 保存；consumer 审计还记录其 AST 输入的逐文件摘要。阶段 A 的后续实施状态不回写为审计执行结论。各组的提案与未决项保持原有范围，不补造新的源码、运行或全量合规判断。

后续预算更正和真实数据库对照另存[第十三批证据](../stage-13/README.md)。原审计中的 START 装配字段不能直接用作实际尝试预算；该批 photo/timelapse 样本由正式入口冻结为一次、三十秒及空重试间隔，其他任务和 CHECK 分别核对。原审计文件保持原字节，后续状态以 S13 及阶段记录为准。

manifest.json 记录来源路径、原始与 gzip 字节数、SHA-256、gzip mtime 和 JSON 解析检查。归档器只按确切路径读取并压缩六个输入文件；没有递归扫描大型运行证据目录、复制源码树或运行测试。
