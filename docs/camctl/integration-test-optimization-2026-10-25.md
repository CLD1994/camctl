## 结果页重复证明的生产成本

同一个原结果页会被分类、成员读取、文件完成及配对等消费者反复读取，每次都重新核验整页关系。native 单例中仅一个页事件就发生 8,909 次完整核验；history 增长目标的主要成本同样发生于构造真实世界，测量主体开始之前已经付出大部分成本。

最终实现按[事务与校验阶段边界](persistence-runtime.md#结果页证明的事务与校验阶段范围)复用最多三份紧凑的原 SQL 历史行和完整事务范围。命中后重新解码，不长期持有 `SavedResultPage`、事件及字典对象图；未命中时先释放超窗旧记录，再查询、解码及完整核验。`row_facts` 直接使用原列描述解码，省去重复的列名元组。

普通提案返回后，以及有限／有界入口每条上下文形成后，先清空记录，再由独立守卫从实际数据库重新建立证明。候选页不进入已提交缓存，动态资格和当前引用仍实际核对；事务结束命令发出前停用记录。原 12 项 after-proposal 矩阵与缓存生命周期反例共同约束该边界。

首轮 cleanup 模块历史估算只有 60.710 秒，因为原来九个实例在工厂接口处提前失败；修正后完整 11 项耗时 963.170 秒，最后独占一个执行槽。入口现从原 CSV 的失败状态推导分片候选，按本次清单拆分；没有历史失败的短模块仍共享一次准备。失败耗时是完整成本的下界，不能当作等价成本预测。真实短失败模块、新节点与全部通过控制组的[运行器验证](verification-data/2026-10-25-integration-runner/failed-history-summary.json)保留恰好一次分配的证据。

每槽在源码之外设置私有 `PYTHONPYCACHEPREFIX`，安装版 CLI 与 pytest 只在各自前缀写字节码。五次相同安装版 `describe` 的独立对照中，禁止写缓存的中位数为 1.034 秒；私有空缓存首次为 1.678 秒，后四次中位数为 0.837 秒。冷成本和热成本分别记录，共享依赖与安装物未被写入；该局部结果不能直接外推整轮收益，详见[冷暖对照](verification-data/2026-10-25-integration-runner/python-startup-measurement.json)与[隔离复验](verification-data/2026-10-25-integration-runner/python-cache-summary.json)。

首轮 bootstrap 对 `os.replace` 注入错误时，观察器也调用了被替换函数，随后内部报错，811 个已收集主实例未执行。观察器现在在导入时固定自身文件操作与计时函数；产品故障注入保持生效，真实观察磁盘错误仍会传播。原 bootstrap 文件 22 项通过，具体见[观察器回执](verification-data/2026-10-25-integration-runner/observer-summary.json)。观察器成功写入几条记录不能证明测试完成，最终验收还须核对清单、每项阶段、任务退出与子检查。

下表承接[原始候选调查](integration-test-timing-2026-10-25.md)，补充本记录其他章节之外的决定。历史耗时只说明原运行成本，不代表可以全部省去。

| --- | --- |
| outputs 的 40 个 catalog-conflict 实例 | 保留。原合计 2.614 秒，可合并 read／fix 的准备，但收益小；当前优先减少主要重复证明，不引入顺序依赖。 |
| bootstrap 的多文件完成与等待成功 | 保留。约 4 秒的重复会话尚未合并；若同时合并未完成轮次，还需新的确定同步点，不能直接去掉原等待。 |

| capture 四种原生延时空尾结果 | 保留。尾空、中间空及取消的成功／失败来源优先级属于不同结果；共同读取成本由生产页证明优化承担。 |

## 后续测试设计的依据

1. 先说明真实协作者和失败分区，再决定测试层级。局部值域的等价单元覆盖可以承接重复断言；实际导入、资源登记和安装物仍需要集成见证。
2. 分开记录准备、操作和结果核对。测试体中的建库仍属于准备成本，调用栈中的热点也须确认发生于哪一段。
3. 共享只读来源时，为改变状态的消费者保留独立身份。拒绝矩阵只有在每次完整回滚、事务结束和相关事实不变得到核对后，才适合同库复用。
4. 缓存已证明内容仍须限定真实事务、候选上界与独立守卫范围。条目数上限不能替代字节峰值测量；严格三页消费者不能由不进入该分支的大夹具冒充。
5. 尽量在准备完成后选择执行时间，用确定同步点安排故障。成功等待同时观察本请求明确失败，保留原成功预算和完整成功断言。
6. 并发前逐项隔离源码生成、构建、工具缓存和数据库。排序要识别历史失败造成的成本下界，不把早期失败误认为短任务。
7. 采集工具本身也要验证故障边界。清单覆盖、阶段完整性、嵌套子检查和退出码共同决定结果是否有效，墙钟变短不能掩盖未执行的测试。

这些原则的通用要求由[共享测试规则](../../.agents/rules/testing.md#控制集成测试成本)维护，本记录只保存本次发现和证据。
