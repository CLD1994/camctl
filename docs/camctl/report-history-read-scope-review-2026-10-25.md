# 报告历史读取范围审查（2026-10-25）

本记录审查报告生成实际需要的历史事实，以及完整对象恢复附带处理的记录。原始审查源码为 `d9c1bac98a4fdf2177470d17f810aa84c095aa4f`；下文的原调用链、问题与直接动作测量均对应该基线。已实施范围见本文末节，完整报告的优化前后对照见[软件验证记录](verification.md#报告必要历史读取的验证与安装2026-10-25)。行为依据是[报告字段契约](../architecture/report-format.md)、[字段依赖登记](database/report-dependencies.md)、[历史状态查询](historical-state-query.md)和[快照维护](history-snapshots.md)。实施的保障范围由[报告读取与完整历史恢复的责任](historical-state-query.md#报告读取与完整历史恢复的责任)定义。

## 结论与责任边界

报告已经按覆盖区间和固定历史位置 H 选择对象，也已将独立产物、交付与父动作分开写出。问题发生在对象入选之后：每个动作都先完整恢复自身记录，再从中取出公开字段需要的事实。这会处理操作流程、尝试、结果页目录、拍摄基准，以及不参与本次报告的分段集合和成员。

报告专用读取按实际公开内容取得必要事实；完整对象恢复保留全部自身成员。快照读取范围遵守 S 状态及选定回放区间，分别测量投影读取、事件解码、快照加载和行校验成本。

报告的完整自身字段是公开协议中属于该对象的全部字段，不等于数据库中归属于该动作的全部内部记录。另一方面，公开字段的依赖也不止最终显示的列：出现条件、关系、身份、排序、完整性计数和适用前置校验都属于必要输入。字段依赖继续由机器登记统一定义，不另外维护完整清单。

## 实际调用链

真实 `HistoryRepository` 的报告生成走 [generation.py](../../apps/camctl/src/camctl/reporting/generation.py) 的有界分支。随后 [bounded_generation.py](../../apps/camctl/src/camctl/reporting/bounded_generation.py) 的 `_write_action` 无条件打开 `open_segment_history`；不是先恢复动作主行，再判断是否需要分段详情。

[bounded.py](../../apps/camctl/src/camctl/history/bounded.py) 先按业务格式和动作所有权取得候选表的计数、最大身份，分批读取整行并复制到临时数据库，然后执行选定方向的历史恢复，最后校验全部恢复行及所有分段集合。即使没有需要回放的事件，候选复制和行校验仍会执行。这个过程没有扫描全库所有对象；已有动作所有权、固定上界和分批读取约束。

`_action_facts` 最终只向投影提供动作主行、H 处唯一正式发布的集合、适用的有限关联和同步主行。分段错误、覆盖结果、取回失败、清理项和取消项由各自端口展开。因而当前完整恢复范围大于后续实际消费范围。

## 报告真正使用哪些事实

下表归纳读取职责，不代替字段依赖登记。

| 报告内容 | 必须取得的事实与边界 | 可评估缩小的范围 |
| --- | --- | --- |
| 动作输入、状态、错误与生效参数 | H 处动作主行及适用自动预览关系。 | 不参与公开分支的操作流程、尝试和内部目录行。 |
| 录像检查、修复与取消内容处理 | 适用的处理记录；运行中动作也可能已经产生这些结果。 | 与已经成立的公开结果无关的内部操作经历。不能把所有运行中动作都简化成只有主行。 |
| 终态拍摄的设备执行情况 | H 处活动记录、派发和完成依据的有效组合。 | 不参与该判断的内部尝试。不能只取最终显示的状态列。 |
| 分段错误详情 | 来源动作，按适用错误契约取得 H 处正式集合、相关成员、缺口、范围及真实产物和文件关联；允许尚无集合的情形仍按原规则表达。 | 其他版本、未发布集合及其完整成员。存在发布集合时仍需证明唯一性及数组完整。 |
| 视频覆盖结果 | 正式集合保存的判断、默认范围、检查前缀及关联原片。 | 不参与覆盖判断的集合和内部操作记录。 |
| 取回失败列表 | H 处全部来源选择、取回项和关联交付；必要时补齐产物来源身份。 | 内部尝试，以及同一批关联交付的重复遍历。不能只检查本次报告入选的交付。 |
| 清理与取消逐项结果 | 完整处理项；取消还需要目标主行及适用撤回项。 | 被引用对象的完整执行经历；同一目标主行的重复恢复。 |
| 普通产物与交付 | 产物来源、文件事实；交付还需拷贝完整性和适用目标文件事实。 | 只展示交付时附带恢复的源产物完整展示数据、配对事实及操作尝试。须保留拷贝和目标文件的一致性依据。 |
| 状态同步与电机动作 | 同步成功时的本地报告身份；电机动作的输入、状态和错误。 | 与对应公开分支无关的动作内部记录。 |

`segment_sets.member_count` 不是直接公开的报告字段。覆盖结果公开的数量来自 `assessment_json` 内的默认范围，含义也不同。但是，机器登记的 `segment_error_expansion_at_same_h` 将集合文件总数列为分段错误展开的校验依赖，不能据此把该列从所有报告分支排除。应按具体公开分支判断是否需要它。

## 分项修复建议与验收条件

### 报告依赖范围与完整动作恢复耦合

任意动作入选都会支付完整候选复制和校验成本。建议新增明确范围的报告读取入口：先恢复动作主行，根据适用公开分支取得必要关联，再分批展开增长关系。范围从权威依赖登记推导，并补齐前置校验依赖；不能另写完整表清单。

保留通用完整句柄。快照维护通过该句柄编码全部自身状态，通用历史查询还支持精确旧版本和未发布集合。直接缩小原句柄会改变这些消费者的契约。

验收应覆盖全部动作类型、执行前后和终态分支，比较固定报告字节；实际查询的必要行缺失、归属矛盾及违反必要关系约束的多余记录仍须失败。合法的 H 后创建成员应排除，不能混入报告，也不能借用较晚的一次赋值事实。增加无关操作尝试和旧集合时，报告专用投影行读取、解码和临时落盘不应随之增加；事件正文成本须另记。

报告保障公开内容依赖的事实、历史和必要关系完整正确；完全无关的内部投影行不属于每次生成的全面审计范围。通用完整恢复及快照维护继续检查全部自身成员。报告入口收窄时，必须保留所依赖事实的必要核验，不能将两类入口的故障检测范围混为一谈。

### 取消目标主行重复恢复

`_result_rows` 已恢复目标主行供取消项投影，`emit_result` 随后再次恢复同一目标和 H，只为判断是否展开取回撤回项。可传递首次取得的目标事实，保留不存在报错和撤回项完整性。单元覆盖普通目标、取回目标、H 时尚不存在的目标，并核对每项只恢复一次。

### 取回失败汇总重复遍历全部交付

`_failure_rows` 在每个来源依赖内重新遍历该取回动作的全部交付。来源有 M 个、交付有 D 个时，交付遍历规模可达 M×D，另有关联查询成本。

建议按 H 处已恢复的取回项关联分组读取，或一次有界交付遍历后用可再生临时结构按来源组织；保留来源、分支、身份的既定输出顺序和唯一性检查。单元覆盖多个来源、没有入选当前交付增量的失败、H 后新增关联及不同批次下字节一致。不能通过只检查入选交付来减少次数。

非失败交付当前也在判断是否输出失败项之前读取产物主行。可评估延后该展示依赖，但必须保留全部必要关联存在性和归属校验；不能用当前交付状态替代 H 处状态，也不能用条件不成立掩盖必需引用损坏。

### 交付展示附带恢复完整产物与源文件

`_merge_delivery` 先完整恢复交付，再调用 `_merge_output`，继续恢复源文件及适用配对事实。建议区分交付的必要来源身份、拷贝和目标文件证明，与产物本身的完整展示依赖。

单元覆盖未完成、已准备、已发布、失败和取消交付；保留已经可靠保存的长度和摘要，拒绝拷贝与目标文件矛盾。仍须核对每条关联的 H 处存在性，不能只读取最终显示的摘要列。

### 报告事件批次配置未进入恢复调用

`GenerationSpec.event_batch_size` 已由报告工作进程传入，默认 256；真实生成路径的主行、完整对象和动作句柄调用未转传它，实际使用默认 128。动作句柄还将批量硬限为 128，直接补传默认 256 会失败。

应独立闭合事件批次与行候选批次的责任，再向全部报告恢复入口传递有效设置。单元使用足以跨事件页的同一历史，对多个合法设置验证读取页数与固定字节，覆盖默认值和大于 128 的合法设置。这是配置落实缺口，不是本次范围过宽的主因。

### 每次完整恢复重新建立完整校验结构

`_validate` 为每个动作新建 `ProjectionRowValidator`；[row_validation.py](../../apps/camctl/src/camctl/persistence/row_validation.py) 在进入校验范围时执行完整权威结构脚本。缓存只复用了脚本文本，没有复用已建好的空结构。上述两个动作恢复各自建立了约 784 KiB 的校验数据库，用于检查 8 行或 16 行记录。

可评估复用空校验结构，或只建立必要且依赖闭合的权威结构；每个对象的唯一性账本、临时行与失败清理仍须独立，不能因复用而积累全部历史对象，也不能以手写弱化结构替代原约束。单元需覆盖连续两个对象、同一对象重试、唯一性冲突、前一对象失败及资源释放。当前没有拆出该固定成本的墙钟占比，不能据临时库大小直接估计提速。

### 分批短读重复打开和检查源库

`HistoryRepository._read_connection` 每次调用 `_connect`，后者通过 `open_existing` 打开只读数据库并检查格式、结构和连接设置；短事务结束后关闭连接。候选页多次使用这个入口，即使没有回放事件，也会重复承担打开和核验成本。短读事务本身是必要约束，但不意味着每一页都必须重建连接。

可在保持短事务释放、实例身份和格式核验契约的前提下评估有限连接复用，核对连接错误、取消和关闭后的处理。单元需确认页间没有遗留事务、实例变化与必要读取错误仍按原规则失败、资源及时关闭。当前没有按阶段分离这部分 SQL，不能给出它在 440 条 SELECT 中的具体占比，也不能直接把全部重复查询归因于连接检查。

## 缩小范围之后仍然存在的成本

当前 `entity_event_links` 按整个动作的自身变化计数，内部操作、结果页和基准变化也计入。事件分页逐条检查结构、目录计数连续性及完整事务范围。因此，只减少投影候选行，不会自动跳过这些事件正文。

`report_entity_changes` 用于选择报告对象，不能替代恢复目录。它不包含所有内部恢复事实，文件变化还可能影响产物公开字段而不改变产物自身记录。若要继续减少事件读取，应单独证明所需恢复事实能够被完整定位。

已有正式发布集合唯一索引可用于定位候选，再核对发布边界与 H；它不证明所有相关行都能直接使用当前值。发布后检查记录等自身数据仍可能变化。已有创建字段也只能用于登记了该字段的表，不能给全部自身表统一添加创建边界条件。

快照直接提供 S 状态，后续只按选定区间恢复到 H。读取、构建和独立回放验收各自承担其职责，分项测量分别解释快照加载、实际事件读取及行校验的成本。
