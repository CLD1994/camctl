# Hasselblad 正式源与同步副本

[驱动入口](hasselblad-driver.md) · [单张拍摄](../architecture/camera-capture.md) · [文件拷贝](../architecture/file-copy.md)

本专题定义 Hasselblad 原图、预览的正式来源，DEVICE 首次来源观察、同步主机副本的一次比较，以及有限复用和清理。设备可用性、旧未知活动及原调用收场继续遵守[可用性恢复](hasselblad-availability-recovery.md)。

## 正式来源与冻结模式

首次受理保存的 `execution_spec.output_storage` 决定本动作的来源模式。驱动需要该模式时，控制申请显式传递原定义；不能用执行时当前配置替换原模式。

| 模式 | 正式来源及完成依据 | 同步主机文件的用途 |
| --- | --- | --- |
| HOST | 本次可靠控制返回及已核验的主机原图、预览。归档、登记、恢复和取回只使用主机正式文件，不增加相机文件查询或下载。 | 本地双文件是正式源，沿原身份归档并保留。 |
| DEVICE | 原可靠拍摄的固定机身、机内原图定位，以及实际指定读取得到的完整内容。原图和预览各自形成大小、SHA-256、格式和完成事实。 | 仅为同步副本候选。缺失、损坏、不可读取或与相机不同，只影响其复用与清理，不决定相机正式源是否成立。 |

相机只保存原图。DEVICE 预览表示固定原机身、原图定位及 `thumbnail` 读取种类取得的完整字节，不表示机身另存一份预览文件。原图使用 `original` 读取种类。两种角色分别登记，并保持预览到原图的正式关联；JPEG 原图及预览不因媒体类型相同而合并。

工具正常退出、完整双流、唯一可靠成功标记及适用的身份与响应解释仍是控制事实的要求。HOST 依赖严格的本地主机双文件依据，不用机内定位补证本地文件；DEVICE 依赖可靠机内定位，不用主机名称代替机内文件名。主机副本的信息与相机定位分别保存；本地副本的内容错误不改写已知相机拍摄效果。原 START 或保存未确认时先完成原责任，不能为取得文件再拍一次。

DEVICE 主机 `saved` 记录缺失、无效或冲突时，单独保留同步副本诊断；它不否定已经可靠取得的控制成功及机内定位。对无法可靠关联的路径不授予复用或删除权限。成功标记冲突、机内定位冲突、进程失败或必要双流不完整仍按实际控制事实处理；HOST 的必要本地双文件记录和核验保持严格要求。

## DEVICE 首次来源观察

原 START 保存可靠拍摄返回、固定机身及机内定位后，在原活动的 RESULTS 责任中分别观察原图和预览。首次观察尚无可用的源大小及摘要，不伪造已有 READ 票据，不用同步副本大小或摘要构造循环证明。

当前工具没有远端 stat 或独立摘要端口。首次观察使用原机身、原图直接文件名及读取种类执行实际指定下载；正常完整返回后，以有界缓冲核对普通文件、格式、完整长度、SHA-256、文件稳定性及必要同步。摘要表达这次可靠完整来源读取所得的内容，不声称是机身独立计算的远端摘要。原始调用、双流及错误按既有诊断责任保存。

相机来源事实可靠保存后固定到各自设备文件身份；后续取回、续传和报告使用该事实。下载数据不符合已固定身份时保存实际读取失败，不用新数据覆盖原大小或摘要。SOURCE 观察、同步副本比较、缓存选择及正式产物是不同事实，保存引用能沿原操作和完整历史事务核实。

| 已保存的事实 | 后续处理 |
| --- | --- |
| 原调用或结果保存仍未收场 | 等待原拥有者，不新增下载或比较。 |
| 角色完整来源事实已可靠保存 | 复用原引用，不因新轮次、调度重入或重启重新下载该角色。 |
| 一角色成功，另一角色尚未确认 | 先完成已保存页的子责任，只继续未确认角色。 |
| 当前尝试只有意图且旧本地执行已可靠收场 | 沿原尝试保存实际未知，次数不退还；需要新的实际观察时再登记下一轮。 |
| 来源明确不满足必要文件要求 | 保存明确失败及合格文件，不把它当作暂时未知重复核实。 |
| 可重试错误或来源未知耗尽 | 有限结束，保留原错误及合格来源；不从同步主机副本补造相机事实。 |
| 保存回执未知 | 先按原完整申请、原键、原时刻和原页引用核实。 |

原图和预览均合格时共同登记并成功。原图合格、预览最终不合格时按必要产物规则失败，同时保留合格原图；只有预览合格时保存实际观察，没有合格原图产物就不虚构配对发布预览。已有终态、绑定失败及单张取消边界继续优先，拍摄、对焦及其前序设置不因结果观察失败重放。

### 次数与期限

沿原 `results/<activity_id>` 使用 `result_check` 的累计轮数、间隔与单次调用期限。一轮是一项 RESULTS 尝试，每轮每个尚未确认角色至多一次调用，正常按原图、预览顺序逐页保存；某次调用失败使本轮结束，下一轮只处理未完成角色。已完成角色保留原实际返回及引用，不能伪装成本轮新下载。

照片来源观察核实原可靠定位固定的两个角色，不是重新扫描目录。因此允许引用前轮已可靠完成的角色；通用目录扫描的当前轮完整集合规则保持。

每角色的原身份核对与指定下载共用 `result_check.call_timeout_s` 的一次期限，命令间不重置。H6 目标相机配置显式使用 180 秒，既有轮数和间隔继续采用目标配置；不改变全局 10 秒默认值。START 原期限仅承担原控制调用，后续普通 READ 继续使用自己的期限和累计预算。到达正常等待期限后，必要的工具、输出读取、本地文件操作及原保存仍须实际收场，不能把期限当作文件线程已终止的证明。

## 同步副本只比较一次

相机来源已完整可靠时，对同一角色的同步主机副本直接确认一次，保存真实事实、比较结论和文件处理选择。之后正常调度与恢复消费原已保存结论，不重新读取相机或反复计算同步副本摘要来改变资格。

| 相机来源 | 同步副本的实际事实 | 保存的结论与文件处理 |
| --- | --- | --- |
| 完整有效 | 完整大小及 SHA-256 相同 | 保存一致结论，优先选择同步副本作为有限复用缓存，清理重复的来源观察下载副本。 |
| 完整有效 | 完整大小或 SHA-256 不同 | 保存不一致结论，同步副本固定清理；可选择本次可靠相机观察下载作为有限复用缓存。 |
| 完整有效 | 可靠缺失或明确无效 | 保存缺失或无效事实，不授予该同步副本复用资格；相机观察下载可独立作为缓存。 |
| 完整有效 | 本地读取或比较未可靠完成 | 保存原错误及未确认事实，不冒充一致或不一致；不授予同步副本资格，相机观察下载仍可独立作为缓存。 |
| 尚未可靠取得 | 任意 | 先沿原来源观察责任处理，不授予相机缓存资格，不用主机副本替代来源。 |

每角色只固定一份缓存选择。相机观察下载是另一份已完整取得的检查副本，不能把它与被判定不一致的同步副本混淆。不一致同步副本不因稍后文件仍在或当前配置变化重新进入比较。没有已绑定等待者时，不为未来请求保留缓存。

本地文件身份、路径所有权、实际文件操作保护及各 delivery 的最终大小与摘要校验继续履行。缓存消失等具体故障沿原责任回到同一相机来源，不重新比较旧同步副本、不重选原资格，不新建 delivery 或刷新读取预算。

照片缓存已经读完但交付摘要不符时，先保存实际不符和原 READ 收场事实，再沿既有重拷、目标重置及所有适用剩余额度，使用同一 copy、delivery 和原角色的相机源继续。该结果不直接证明缓存损坏，不改写原一次比较或缓存选择。已经可靠分配的新轮可以按原额度执行；确已耗尽任一必需预算时按原规则失败，不为切回相机增加机会。此规则只适用于照片来源缓存，其他主机源和视频沿各自规则处理。

## 有限复用与文件清理

采用[来源临时副本的有限复用](../architecture/file-copy.md#来源临时副本的有限复用)。原图、预览各自有准确来源、角色、一次决定及选中缓存。照片不得伪造视频检查记录或 `inspection_id` 获得复用资格。

来源结果、正式产物和终态共同提交的完整事务为固定截点 H。以该次产物创建或明确终态事件定位原完整事务，不用后来变化的 `actions.last_event_id` 替代 H。H 时已运行且仍等待本来源的取回可绑定相应缓存，H 后新取回直接访问相机。output 始终关联 DEVICE，缓存不变成主机正式源。

一致性决定与选中缓存、未选文件的处理资格共同可靠保存。选中缓存须等仍需使用它的固定等待者及相关实际文件操作收场后清理。未选的不同步副本或重复观察下载，在一次决定可靠保存、自身结果保存与实际工具／文件操作已收场后即可清理，不等待使用另一缓存的取回结束。清理失败保存真实错误并在既有维护额度内继续，不能因失败而改回可复用。

缓存作为读取源时，保留释放命令与独立守卫均核对以该文件为来源或目标的原 READ，以及实际文件使用保护。取回动作终态可以结束其等待者保留理由，不能替代仍在进行的读取收场。读取按[用途目录与文件规则](database/file-fields.md#中间文件的路径与用途目录)打开实际目录和普通文件，目录及文件描述符共同归原 READ 拥有；不以末级文件检查代替用途目录检查。

原 `capture-work/<activity>/` 与首次来源下载工作目录都有各自创建前保存的责任和独占范围。清理必须核对原意图、固定归属、实际调用及文件操作收场、已保存的比较或选择，以及准确原路径。未归档副本无需先满足完整照片归档条件才能清理；也不能用归档路径缺席冒充原工作目录已清理。未知目录或不能可靠关联的文件不由扫描范围自动取得删除授权。

维护按原责任分页，并受每次运行额度控制；暂不能清理的责任也推进续查位置，后续再核对。不能因比较完成就删除仍被结果保存或绑定取回使用的文件，也不能把清理临时副本当作删除相机正式源。

## 数据与验证边界

来源观察、一次比较、缓存选择和清理资格必须由持久事实闭合。现有 RESULTS 流程、尝试、结果页、有格式的有界观察、设备文件、中间文件及历史截点可以承载时，沿原结构实现；不为固定两个角色建立不断增长的 JSON 清单。事务守卫从原连接独立核对角色、机身、定位、来源观察、缓存文件及 H 的等待者，不采纳生产调用方的“已确认”布尔值。

来源、比较及归档事实形成或改变时验证其完整依据。普通读取、保留判断和后续交付使用已可靠保存的归档、角色页、设备文件及 H 的直接关系，不反复重解析原 START／PREPARE 双流或递归核验整条旧来源链；新的交付关系仍由本次事务独立核对。

既有终态、已登记文件身份、旧摘要及旧报告不静默修正。新动作按本专题形成新来源事实。改变旧产物可取回性或现场格式转换属于另外的明确工作，不通过重写历史完成。实现证明必须新增不兼容结构时，先明确具体缺口和现场处理方案，再部署。

验证分别覆盖 HOST 无相机文件访问、DEVICE 两种格式与两种角色、同步副本一致／不一致／缺失／无效／未确认、比较不重放、原键保存恢复、跨轮角色复用、H 前后等待者、独立交付、原源回退及准确清理。软件集成、实际安装与真机分别记录其范围；未执行的组合结果不由隔离单元替代。
