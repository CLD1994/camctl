# Hasselblad 正式源与同步副本

[驱动入口](hasselblad-driver.md) · [单张拍摄](../architecture/camera-capture.md) · [文件拷贝](../architecture/file-copy.md)

本专题定义 Hasselblad 原图和预览的正式来源、同步文件的有限复用及取回责任。设备可用性、旧未知活动及原调用收场遵守[可用性恢复](hasselblad-availability-recovery.md)。

## 正式来源与冻结模式

首次受理保存的 `execution_spec.output_storage` 决定来源模式。DEVICE 新动作同时保存 `photo_source_policy = deferred`；恢复使用原执行定义。业务保证相机中的原图不会被修改，相机及 `hb_cli` 负责原图、预览及拍摄时同步文件之间的对应关系。

| 模式 | 正式来源及完成依据 | 主机文件的用途 |
| --- | --- | --- |
| HOST | 本次可靠控制返回及满足 HOST 完成依据的主机原图、预览。 | 两个文件为正式源，沿原身份归档并保留。 |
| DEVICE | 原可靠拍摄返回中的机身、机内原图定位和各自读取角色。 | `capture` 产生的同步文件可供已等待的取回有限复用。 |

相机只保存原图。DEVICE 预览使用同一机身、原图定位及 `thumbnail` 读取种类；原图使用 `original`。两种角色分别登记，预览关联其原图。原图及预览的 DEVICE 记录在拍摄结果形成时不声明已读取的大小、SHA-256 或媒体类型。JPEG 原图及预览即使类型相同也保持独立身份。

清理任一 DEVICE 角色时，同张照片的原图与预览共同进入清理范围。物理删除前保护两者已经取得资格的取回，可靠缺席及原删除未知结果由两者共享；具体处理见[清理正式产物](../architecture/output-cleanup.md#清理含义)。HOST 模式的原图和预览是独立主机文件，继续按各自正式身份清理。

工具正常退出、完整双流、唯一可靠成功标记及适用的身份和响应解释仍是控制事实的要求。HOST 依赖本地主机双文件依据；DEVICE 依赖可靠机内定位。DEVICE 主机 `saved` 记录缺失、无效或冲突时，只影响相应同步文件的复用资格；无法可靠关联的路径不获得文件访问或删除权限。拍摄结果或保存未确认时沿原责任恢复，不重复拍摄。

## HOST 完成依据

HOST 模式的原图和预览来自可靠 `capture` 返回。camctl 解析两份 `saved` 记录及配对关系，核对所属工作目录中的普通可读文件、正长度及工具报告长度、文件稳定性、完整 SHA-256 和必要同步。原图继续履行适用的 JPEG 边界或 RAW 文件头检查。

预览的媒体内容有效性由 `hb_cli` 保障。RAW 和 JPEG 的 HOST 预览在完成检查、归档及归档恢复时不检查 JPEG 文件头、标记结构、EOI 或解码结果；camctl 保留工具生成的完整字节。取回按独立交付文件的实际内容计算大小和摘要。

## DEVICE 拍摄结果

`capture` 可靠成功并提供唯一合法机内定位后，camctl 依据原 START 结果及活动身份登记原图、预览和配对关系，再保存动作终态。该过程不发起原图或预览下载，不计算相机来源内容的大小、摘要或格式。`capture` 自身仍由 CLI 将照片同步到主机工作目录。

原 START 所报告的同步文件按角色归档到原文件责任。归档处理目录项及必要同步，不读取照片内容或与另一次相机下载比较；`size_bytes` 保存 CLI 对该主机文件的报告值，摘要保持未知。无法归档时记录实际错误，设备正式源仍按原可靠拍摄结果成立。原调用、保存及实际文件操作尚未收场时，继续持有其责任。

## 同步副本的有限复用

来源结果和动作终态共同提交的完整事务为截点 H。H 时已运行且仍等待本来源的取回，可在自身选择和清理资格成立后复用对应角色的同步文件；H 后新取回从相机读取。正式产物始终关联设备文件，同步文件不成为正式源。独立交付各自计算实际大小和 SHA-256，遵守[来源临时副本的有限复用](../architecture/file-copy.md#来源临时副本的有限复用)。

同步文件的原角色、拍摄返回、归档责任及 H 上的等待者由保存事务独立核对。缓存缺失或本地读取失败时，在原读取预算允许的条件下，沿同一交付和读取责任切回相机。已绑定的取回及实际文件操作全部收场后，按原文件责任有限清理缓存；没有等待者时不为后来的请求保留。工作目录及清理错误按原责任处理，不删除相机正式源。

## 按需取回与恢复

实际取回需要相机源时，驱动按原机身和机内名称执行指定角色下载。`list`、`info` 和 `download` 共用 180 秒读取准备期限；下载工具正常收场后，camctl 取得本次下载文件的实际长度，保存该次读取长度，再组织分段交付。最终 SHA-256 对应该次交付文件。后续读取按设备配置的无数据期限及原累计尝试预算处理。

拍摄同步预览和后续相机预览可以有不同的大小和字节；它们分别采用实际交付的大小和摘要。一次读取中断后重新从相机下载时，先可靠保存本次长度和目标重置，再从零写入，避免将不同下载的字节拼接。已经保存完整 READ 结束的交付沿原本地收尾责任恢复，避免为完成交付再次下载。相机绑定失败、读取失败和保存结果未知继续保留各自的真实错误与责任。

## 历史与格式

新 DEVICE 语义要求数据库整体格式 V7。已存在的 V6 库须先备份并显式执行 `camctl init --upgrade-photo-source --config <config.toml>`；普通 `init`、`run` 和 `submit` 不自动升级。升级保留旧动作、产物及历史；旧动作按首次受理时保存的原来源语义继续恢复。完整升级规则见[数据库整体格式检查](persistence-runtime.md#数据库整体格式检查与显式升级)。

验证分别覆盖两种照片角色、原可靠拍摄结果、无拍后下载、H 前后取回、同步文件缺失、本次下载长度变化及中断恢复。软件模拟、实际安装及真机结果分别记录。
