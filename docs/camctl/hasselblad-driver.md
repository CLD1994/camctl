# Hasselblad CFV 100C 单张拍摄接入

[设计入口](README.md) · [单张拍摄](../architecture/camera-capture.md) · [正式产物](../architecture/outputs.md)

## 设备与拍摄参数

Hasselblad CFV 100C 通过 ARM Linux 主机上的现有 `hb_cli` 二进制接入。驱动不修改厂商工具，所有工具进程通过 camctl 的受管进程入口运行。工具的使用方法见 [hb_cli 使用说明](../hardware/hasselblad/hb_cli.md)，已取得的接口证据见[单张拍摄接口核验](../superpowers/notes/2026-10-12-hasselblad-cfv100c-probe.md)。

驱动仅提供单张拍照能力，动作类型为 `camera_take_photo`，参数类型为 `hasselblad_photo`。每次动作执行一次拍摄，固定设置 `drive-mode single`，按明确参数选择 RAW（3FR）或 JPEG，并设置曝光、白平衡和对焦。完整参数域、命令顺序及调用结果分类由[单张参数与中文选项规格](../superpowers/specs/2026-10-20-hasselblad-photo-parameters-design.md)定义，不在本页复制允许值表。驱动从同一参数定义提供受理规则和 `camctl describe` 的能力说明，声明支持原图配对预览。客户端使用现有拍摄、取回和报告协议。

快门字段 `shutter_s` 使用同源目录声明的规范分数字符串。计划、生效参数、报告和工具调用保留同一个字符串；数值和小数字符串均不受支持。光圈、ISO 及其他数值字段保持各自类型。

本地配置确定工具路径、目标相机序列号、USB 产品标识及正式源的存储位置。工具只按产品标识选择设备；执行前须确认该产品标识下恰有一台相机，并读取序列号与配置核对。没有匹配设备、存在多台匹配设备、身份不一致或查询失败时，不发送拍摄命令。部署采用单机稳定连接的运行假设。

调用前固定原机身的预期身份，实际响应另行保存观察；DEVICE 正式源沿可靠拍摄身份固定机身，后续读取不得改用新配置中的另一台相机。固定时点、物理资源归属和绑定变化由[原机身身份](hasselblad-availability-recovery.md#原机身身份的固定与核对)定义。

驱动将配置中的整数产品标识传给 `hb_cli --pid` 时，使用带 `0x` 前缀的四位小写十六进制形式，例如 `10` 写作 `0x000a`。

哈苏工具调用失败时，原 `ERROR` 诊断包含本次已执行步骤的 `elapsed_ms`，以整数毫秒表示从调用工具入口到返回或实际收场的耗时；启动失败的步骤记录启动尝试耗时。超时后的必要收场也计入耗时，因此它可能超过调用期限。未执行的步骤不虚构耗时，历史错误也不会补造计时。

每次实际 `hb_cli` 调用还通过 `external_tool` 的 `INFO` 日志记录开始与返回；返回记录的 `elapsed_ms` 包含进程启动、等待、退出和输出收场的耗时。`step_name` 对应驱动的步骤名称，`tool_call_id` 关联同一次调用的起止，记录还包含实际命令、调用期限及已知退出和错误事实；设备、活动和尝试身份在调用方掌握时一并记录。返回不表示相机操作成功。查看这些 `INFO` 记录须配置 `log.level = "INFO"` 或更低，并受日志水位、采样和轮换规则约束；原错误继续由错误诊断记录，日志级别和通道规则见[运行日志](../architecture/logging.md)。

哈苏通过[公共拍摄准备流程](../superpowers/specs/2026-10-25-capture-preparation-design.md)提前核对机身并设置参数，准备期间保持动作未开始。对焦模式随参数提前设置；MF 的相对调焦与 AF-S 的自动对焦仍在真正 START 内执行，二者按原参数分支互斥。准备不派发 `capture`，也不创建照片文件责任。默认提前量、设备占用、原调用保存及新会话凭据核验均由公共合同管理。

实际 START 持有匹配准备凭据时，仅执行对应对焦与拍摄步骤；旧的完整控制入口仍支持在同一次调用内核对身份、设置和拍摄。START 按[取消边界](../superpowers/specs/2026-10-20-hasselblad-photo-parameters-design.md#start-调用与取消边界)及[采集效果与步骤事实](../superpowers/specs/2026-10-20-hasselblad-photo-parameters-design.md#尝试结果采集效果与步骤事实)分别解释，每条新命令仍须满足时间窗口及剩余期限。实际 START 的完整调用期限作为首次受理的固定执行依据保存，涵盖该调用内的对焦、曝光、原图及缩略图传输；后续恢复沿用原值。设置成功不能代替拍摄完成。

## 正式源的部署选择

`devices.<id>.hasselblad.output_storage` 决定新受理单张动作的正式源位置，接受 `host` 或 `device`，省略时采用 `host`。拍摄计划提交完整拍摄参数，不承载该部署选择。首次受理将部署选择与完整 START 调用期限保存到动作执行定义；执行、重启及历史恢复使用原定义，后续部署变更不迁移已有文件，也不改变旧动作的源模式。

| 部署模式 | 正式源 | 主机照片的处理 | 再次取回 |
| --- | --- | --- | --- |
| `host` | 主机原图与配对缩略图 | 归档并长期保留，只有正式产物清理请求可以删除 | 从主机源创建独立交付，无需相机连接 |
| `device` | 相机原图与由同一原图取得的配对缩略图 | 与首次可靠相机读取比较一次；相同副本按固定等待者有限复用，不同副本固定清理 | 固定等待者可使用选中缓存，后到请求按原机身和读取种类取得相机内容 |

`capture` 可以同时向相机与主机保存原图，并向主机保存配对缩略图。主机 `saved` 名称、`camera file:` 返回的机内完整路径及其直接文件名分别保存；`download original` 和 `download thumbnail` 仅传机内直接文件名，不能使用主机名称替代。缺失、冲突及非法定位按[拍摄响应分类](../superpowers/specs/2026-10-20-hasselblad-photo-parameters-design.md#拍摄响应与机内定位分类)分别处理。相机文件归属依赖本次可靠控制响应，不要求调用 `images` 建立拍摄前后差集。两模式的来源、完成依据及同步副本处理由[正式源与同步副本](hasselblad-source-authority.md)完整定义。

## 主机正式源文件

相机工具把本次原图和缩略图写到主机。camctl 将这两份文件分别登记为 `original` 和 `preview`，保存预览到原图的关联。正式源文件长期留在主机，只有明确的正式产物清理请求才允许删除。每次取回创建独立 delivery；主程序传输并删除 delivery 后，正式源文件继续可用于新的取回。

主机文件使用独立的拍摄原图、拍摄预览用途，保存所属动作、稳定文件身份、固定相对路径、完整大小和 SHA-256。原文件名、内容类型及原图与预览配对依据来自本次可靠调用结果及文件检查。用途整数编号由数据库枚举登记提供，其他表示从登记取得。

文件形成前先持久化所属动作和文件责任。工具自行生成文件名，因此每次调用使用该动作或活动独占的工作目录；目录身份从已保存责任确定，重启沿用原目录。工具输出只允许引用此目录中的普通文件。完整文件归档到已登记的正式路径，归档及恢复不得覆盖未知文件。厂商生成名称保留为可读元信息，不直接作为正式路径。

工具成功返回后，须同时取得严格可解析的成功响应、原图和配对缩略图的路径及字节数，并核对文件类型、实际大小和摘要；原图的内容检查及预览的保障分工遵守[HOST 完成依据](hasselblad-source-authority.md#host-完成依据)。必要文件与目录同步后，才形成可靠完成事实。成功结果不依赖相机 `images` 中出现新增条目。

## 相机正式源与主机临时文件

相机模式按冻结的 DEVICE 定义解释控制响应，在原 RESULTS 责任中分别执行原图和预览的首次可靠指定读取。原图和缩略图分别登记为设备文件及正式 `original`、`preview`，保存原设备绑定、原图文件名、读取种类、完整大小、SHA-256 和配对关系。两种读取种类的文件身份不同，缩略图定位使用原图文件名。正式源位于相机；主机副本不提升为正式产物。

相机源的大小与摘要来自首次可靠相机读取的完整内容，固定后不因后续下载改变。该摘要不表示机身独立计算的远端值；驱动不声明独立摘要查询端口，也不假设工具提供相机端摘要命令。首次观察与后续普通 READ 使用不同责任和预算，不以尚未成立的源身份反向证明首次观察。

创建主机文件前保存动作与文件责任。相机来源可靠取得后，每角色对同步副本比较一次，保存比较结论、缓存选择及准确清理责任；规则和固定等待者见[一次比较与有限复用](hasselblad-source-authority.md#同步副本只比较一次)。不一致副本固定清理，选中缓存仅供来源提交时已等待的取回使用。清理先核对结果保存、工具和实际文件操作收场，并沿有限维护额度继续；回收不删除相机照片，也不改变正式产物。未知拍摄文件仍按原责任保留。

`hb_cli download` 将完整文件保存到主机。普通取回的每次实际设备读取使用已保存 READ 尝试确定的独占工作目录，下载前核对原机身身份；只下载指定原图或缩略图。身份核对与完整下载共用 180 秒准备期限，后续读取沿用部署配置的无数据超时。取得文件后核对类型、完整大小及来源观察固定的 SHA-256，才向既有分段拷贝流程提供指定偏移起的字节。下载与读取过程使用有界缓冲，不把整份原图放入 Python 内存。首次 RESULTS 下载另按[来源观察期限](hasselblad-source-authority.md#次数与期限)及其准确工作目录维护，不伪装成普通 READ。

主机交付仍从可靠进度继续写入；当前工具不提供相机端偏移下载，因此重新建立读取时可能需要重新下载完整源文件。下载和交付期间主机须有相应临时空间。正常结束、错误和取消均先完成实际工具与文件操作收场，再回收下载副本；主机重启遗留的下载目录按原 READ 责任核实和回收，不能仅凭目录存在推断读取完成。

每次正常 `run` 最多核对 `cleanup.work_file_limit_per_run` 个原 READ 责任，该额度及续查位置独立于既有中间文件维护。维护按数据库中的原 READ 意图分页，只删除能关联原责任且相关操作已经收场的下载目录，不枚举或删除未知目录。暂不具备删除资格的责任也推进续查位置，后续运行可继续核对其他责任；完成一轮后重新核对。删除失败保留具体会话错误与原目录，下次正常运行继续核实。原 READ 的目录尚未安全处理且本次无法再推进时，向会话交付具体维护前提错误并结束本次运行；下次实际启动后沿游标、原额度及原票据继续，不将本地维护等待记为相机读取失败。共用的准备失败与收场分类见[文件拷贝契约](../architecture/file-copy.md#读取会话准备失败与等待)。

`hb_cli` 提供机内照片删除命令；本驱动未声明相机正式源的删除及独立存在性查询能力，工具命令存在本身不改变该声明。显式清理请求涉及此类设备源时，相关处理项以既有 `file_delete_failed` 错误结束，其他目标继续独立处理；不发起设备删除尝试，不修改文件存在性为缺席。相机模式不执行主机模式的本地正式源清理，也不以删除临时副本代替正式产物清理。设备未连接、绑定不匹配、下载失败、内容不符或清理能力缺失均保留对应事实，不解释为文件已成功删除。

## 完成、失败与恢复

单张拍摄没有设备停止接口。可靠未进入驱动 START 调用时允许取消；整次调用已经开始或可能开始后拒绝取消，不能以 `capture` 尚未发送作为重新允许取消的依据。具体阶段与竞争处理见[START 调用与取消边界](../superpowers/specs/2026-10-20-hasselblad-photo-parameters-design.md#start-调用与取消边界)。`hb_cli stop` 的含义是关闭相机电源，不属于此驱动的动作停止操作。

| 已保存的调用及文件事实 | 处理 |
| --- | --- |
| 尚未发送拍摄，窗口、预算或其他适用资格阻止后续派发 | 保存真实设置结果、阻止原因及本次采集无效果事实，不重放原 START；采集无效果不否定已发生的设置或调焦 |
| HOST 成功响应与两份完整主机文件依据充分 | 归档原图及预览，在同一业务事务保存正式产物、配对关系及动作成功 |
| DEVICE 控制返回可靠，机内定位及原机身已固定 | 沿原 RESULTS 责任观察相机内容；同步副本错误不改写原采集事实，不重拍 |
| DEVICE 两角色来源及必要处理可靠完成 | 在同一业务事务保存设备产物、配对关系、有限缓存关联及动作成功 |
| 工具错误、超时、中断或输出不能可靠解释 | 保存原错误及已知效果，保留本次工作文件；没有可靠完成依据时保持结果未确认，不重发拍摄 |
| 原成功结果已保存，归档或登记尚未完成 | 核对原文件身份、大小和摘要，继续归档及原登记责任，不执行新的拍摄 |
| 原结果保存回执未知 | 先核实原完整申请；沿原键、原文件和原结果继续，不重新调用相机 |
| 重启后存在工作文件，但缺少可靠成功及完成依据 | 保留文件和具体未知原因，按有限核实规则结束；文件存在或大小稳定不能代替成功响应 |
| 已归档文件或已登记产物存在，原保存结果需要恢复 | 核对既有内容和关联，复用原身份；内容、归属或配对矛盾时保留错误，不追加或改写产物 |

原 START 仅保存意图、缺少实际结果时，本地控制恢复只在可靠的旧执行收场边界与固定历史边界成立后保存原尝试的未知结果。该恢复不重放设置、相对调焦或拍摄，也不补造入口、活动结束或占用释放事实；具体依据见[原尝试结果与恢复](database/operation-fields.md#正常返回恢复与历史保存)。

后续有效拍摄或 DEVICE 读取被原未知活动阻挡时，使用[独立可用性恢复](hasselblad-availability-recovery.md)。驱动提供独立检查端口，保留不支持活动查询和停止的声明；检查只返回本次身份与工具事实，旧占用的正式释放由公共事务负责。HOST 本地工作不需要该检查。

适用模式的完整来源事实已经可靠保存后，登记及主机文件处理沿原责任继续，不重新拍摄。HOST 的归档、取回及报告不要求相机继续连接；DEVICE 已完成来源观察后的登记、报告及主机副本回收不要求相机连接，尚未完成的来源观察和后续实际设备读取仍需原机身可用。主机原图和预览使用既有本地偏移读取、落盘、摘要比较及文件交接规则；正式清理作用于各自指定文件，不级联删除配对文件。

公共报告继续使用 `original`、`preview`、`preview_of_output_id`、名称、类型、大小、摘要和可用性等已有字段。JPEG 原图和预览同为 `image/jpeg`，仍按已保存角色分别登记及处理，不以媒体类型决定文件用途。客户端保留现有通用失败摘要，步骤详情留在原操作尝试与内部历史。内部文件承载位置不改变产物与 delivery 的身份。

## 验证与交付

软件验证覆盖部署选择与首次受理固化、实际输出样式的严格解析、身份核对、设置与启动资格、完整调用期限、部分和异常结果、双模式文件登记、主机文件归档与回收、事务重送、进程中断恢复、相机原图及缩略图下载、独立多次取回、主机正式源显式清理、报告及历史恢复。真实文件、进程和数据库组合归组件集成测试；测试替身受工具接口契约约束，单元测试隔离真实 I/O。

ARM 验证使用已安装发布包及独立数据目录，通过正式计划完成单张拍摄、原图和预览取回、结果报告，并核验交付文件与正式源文件的大小及摘要。软件检查、ARM 部署和真实设备结果分别记录。

相机模式的实施进度由[相机正式源计划](../superpowers/plans/2026-10-14-hasselblad-camera-source.md)维护，主机模式的接入记录见[单张接入计划](../superpowers/plans/2026-10-12-hasselblad-integration.md#实施状态)。双模式的软件证据见[本次验证记录](verification.md#hasselblad-双正式源的软件验证2026-10-14)，此前主机模式的 ARM 真实业务证据见[现场验收](verification.md#hasselblad-arm-真实拍摄与取回验收2026-10-12-utc)。
