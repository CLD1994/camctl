# Hasselblad CFV 100C 单张拍摄接入

[设计入口](README.md) · [单张拍摄](../architecture/camera-capture.md) · [正式产物](../architecture/outputs.md)

## 设备与拍摄参数

Hasselblad CFV 100C 通过 ARM Linux 主机上的现有 `hb_cli` 二进制接入。驱动不修改厂商工具，所有工具进程通过 camctl 的受管进程入口运行。工具的使用方法见 [hb_cli 使用说明](../hardware/hasselblad/hb_cli.md)，已取得的接口证据见[单张拍摄接口核验](../superpowers/notes/2026-10-12-hasselblad-cfv100c-probe.md)。

驱动仅提供单张拍照能力，动作类型为 `camera_take_photo`，参数类型为 `hasselblad_photo`。每次动作执行一次单张 RAW 拍摄，设置 `drive-mode single` 和 `capture-format raw`，沿用相机已有曝光、白平衡及对焦设置。驱动从同一参数定义提供受理规则和 `camctl describe` 的能力说明，声明支持原图配对预览。客户端使用现有拍摄、取回和报告协议。

本地配置确定工具路径、目标相机序列号及 USB 产品标识。工具只按产品标识选择设备；执行前须确认该产品标识下恰有一台相机，并读取序列号与配置核对。没有匹配设备、存在多台匹配设备、身份不一致或查询失败时，不发送拍摄命令。部署采用单机稳定连接的运行假设。

驱动将配置中的整数产品标识传给 `hb_cli --pid` 时，使用带 `0x` 前缀的四位小写十六进制形式，例如 `10` 写作 `0x000a`。

设置与拍摄共用一次已持久化的 START 尝试和完整调用期限。每次新设备派发前检查原动作取消、时间窗口及剩余期限，设置成功不代替拍摄完成。单张任务的完整调用期限覆盖准备、参数设置、曝光、原图及缩略图传输，作为首次受理的固定执行依据保存；后续恢复沿用原值。

## 主机正式源文件

相机工具把本次原图和缩略图写到主机。camctl 将这两份文件分别登记为 `original` 和 `preview`，保存预览到原图的关联。正式源文件长期留在主机，只有明确的正式产物清理请求才允许删除。每次取回创建独立 delivery；主程序传输并删除 delivery 后，正式源文件继续可用于新的取回。

主机文件使用独立的拍摄原图、拍摄预览用途，保存所属动作、稳定文件身份、固定相对路径、完整大小和 SHA-256。原文件名、内容类型及原图与预览配对依据来自本次可靠调用结果及文件检查。用途整数编号由数据库枚举登记提供，其他表示从登记取得。

文件形成前先持久化所属动作和文件责任。工具自行生成文件名，因此每次调用使用该动作或活动独占的工作目录；目录身份从已保存责任确定，重启沿用原目录。工具输出只允许引用此目录中的普通文件。完整文件归档到已登记的正式路径，归档及恢复不得覆盖未知文件。厂商生成名称保留为可读元信息，不直接作为正式路径。

工具成功返回后，须同时取得严格可解析的成功响应、原图和配对缩略图的路径及字节数，并核对文件类型、实际大小、内容标识和摘要。必要文件与目录同步后，才形成可靠完成事实。成功结果不依赖相机 `images` 中出现新增条目。

## 完成、失败与恢复

单张拍摄没有设备停止接口。尚未拍摄的动作按既有资格取消；已启动或可能启动后的取消沿用单张拍摄契约。`hb_cli stop` 的含义是关闭相机电源，不属于此驱动的动作停止操作。

| 已保存的调用及文件事实 | 处理 |
| --- | --- |
| 尚未发送拍摄，资格检查阻止后续派发 | 保存真实设置结果、阻止原因及本次拍摄无效果事实，按原动作规则结束或等待 |
| 成功响应与两份完整文件依据充分 | 归档原图及预览；将文件提升、产物登记、配对关系和动作成功在同一业务事务中保存 |
| 工具错误、超时、中断或输出不能可靠解释 | 保存原错误及已知效果，保留本次工作文件；没有可靠完成依据时保持结果未确认，不重发拍摄 |
| 原成功结果已保存，归档或登记尚未完成 | 核对原文件身份、大小和摘要，继续归档及原登记责任，不执行新的拍摄 |
| 原结果保存回执未知 | 先核实原完整申请；沿原键、原文件和原结果继续，不重新调用相机 |
| 重启后存在工作文件，但缺少可靠成功及完成依据 | 保留文件和具体未知原因，按有限核实规则结束；文件存在或大小稳定不能代替成功响应 |
| 已归档文件或已登记产物存在，原保存结果需要恢复 | 核对既有内容和关联，复用原身份；内容、归属或配对矛盾时保留错误，不追加或改写产物 |

来源文件已经在主机并具有可靠完成依据后，归档、取回及报告不要求相机继续连接。需要新设备调用时，继续核对原设备与驱动绑定。主机原图和预览使用既有本地偏移读取、落盘、摘要比较及文件交接规则；正式清理作用于各自指定文件，不级联删除配对文件。

公共报告继续使用 `original`、`preview`、`preview_of_output_id`、名称、类型、大小、摘要和可用性等已有字段。内部文件承载位置不改变产物与 delivery 的身份。

## 验证与交付

软件验证覆盖实际输出样式的严格解析、身份核对、设置与启动资格、完整调用期限、部分和异常结果、主机文件归档、事务重送、进程中断恢复、独立多次取回、显式清理、报告及历史恢复。真实文件、进程和数据库组合归组件集成测试；测试替身受已取得的工具接口约束，单元测试隔离真实 I/O。

ARM 验证使用已安装发布包及独立数据目录，通过正式计划完成单张拍摄、原图和预览取回、结果报告，并核验交付文件与正式源文件的大小及摘要。软件检查、ARM 部署和真实设备结果分别记录。
