### 队列与监听线程核验

[Janus 2.0.0](https://github.com/aio-libs/janus/tree/v2.0.0)提供同一队列的同步和异步接口；关闭时需要完成通知任务的清理。其 `_put` 在同步锁保护下执行，随后才增加未完成任务计数，能够承载小范围的原子水位拒绝适配。该扩展点属于内部接口，生产适配必须隔离并绑定版本。

临时验证使用容量为 2 的队列：先放入一条记录，再让低优先级记录被策略拒绝，验证容量和未完成计数没有增加；填满队列后，重要记录的协程等待，消费者取出一条才使它完成。最终读取顺序保持 FIFO，`join` 和 `aclose` 正常结束。验证没有以真实随机数替代边界断言。

[Python 3.11 QueueListener](https://docs.python.org/3.11/library/logging.handlers.html#queuelistener)的停止标记默认通过 `put_nowait` 插入，`stop()` 随后同步等待监听线程结束。临时验证确认队列满时插入停止标记会抛出 `Full`。因此生产关闭路径必须先结束生产并处理已接纳任务，再停止监听线程；事件循环不得直接执行线程等待。

Janus 负责等待机制，项目只适配接纳规则、来源路由、结果通知与生命周期。不另建一套线程条件变量或异步队列来代替 Janus。

### 日志文件处理器核验

[CLH 0.9.29](https://pypi.org/project/concurrent-log-handler/0.9.29/)的大小轮换处理器在同一共享锁内执行轮换与追加，追加后刷新缓冲；保留数量为 1 时，`backupCount=0` 的实现会截断正在轮换的文件。该行为与包含活动文件的计数转换相符。

源码中存在捕获错误后调用诊断入口或 `handleError()` 的分支；函数正常返回不等于轮换或追加成功。项目需要适配阶段结果及一次性 stderr 提示。复制副本可以在持锁调用 `do_write()` 的范围内追加，但必须将副本故障与原日志追加故障分开。

临时验证使用两个独立启动的进程，各自创建文件处理器，并发写入及轮换后逐条核对全部 80 条记录；另验证保留数量为 1 时只留下轮换后的活动内容。持锁复制验证在触发错误写入后安排另一进程尝试轮换，确认复制期间后者等待，副本完整包含触发记录。上述验证使用开发环境中的 CLH 0.9.29 与 portalocker 4.4.0。

实际接入仍须覆盖轮换失败但可追加、追加失败禁用、调整保留数量、取消及完整日志生命周期；临时验证不代表生产适配验收。第三方组件的线程后台队列工具不参与方案，队列职责由标准库与 Janus 承担。

### 精确数字核验

[jsonschema 的类型扩展机制](https://python-jsonschema.readthedocs.io/en/stable/validate/#type-checking)允许替换整数识别，关键字校验也可以单独适配。默认 Draft 2020-12 校验器对 `Decimal("1.0")` 的 `integer` 判断为假；较大 Decimal 的默认 `multipleOf` 路径可能触发 `InvalidOperation`。这两种结果均不满足项目精确数值契约。

临时适配只替换整数判断和 `multipleOf`：从精确 `int` / `Decimal` 构造 `Fraction`，用分母判断整数及倍数关系。验证覆盖 `1.0`、`1e0`、略大于整数的长小数、布尔值及超过默认 Decimal 精度的大数，并在三种上下文精度下取得相同结果。[Fraction 的 Decimal 输入](https://docs.python.org/3.11/library/fractions.html)

另验证低精度上下文中的 `Decimal.normalize()` 会改变长小数，因此它不能直接用于规定的无损报告编码。生产编码按数字元组生成文本；仍须单独验证普通与科学计数法的分区、负零、Unicode、深层数组及分批生成。这里没有实现完整编码器，也没有证明所有 Schema 组合规则已适配。

### SQLite 查询与连接核验

临时 SQLite 数据库使用 WAL 和显式事务。读连接建立视图后，另一个连接追加事件，原读事务仍看到原边界；结束读事务后才能看到新事件。对实体类型、ID 及事件序号建立复合主键后，H 处末条关联查询使用索引查找，未执行整表扫描。确认回滚的插入不保留序号占用。

另验证 `mode=rw` 打开不存在的路径时报错，且不会留下新库。这证明选定接口具备防止日常入口隐式建库的能力，不证明完整初始化实现已经验收。

临时库规模只用于验证访问行为，不能推出目标存储上的吞吐量、报告时限或峰值内存。临时脚本不进入生产包；后续测试从本文及业务契约独立推导。

## 设备证据与联调输入

本节是单独设备联调的证据清单，不是第一版软件集成测试的环境要求或通过门槛。软件集成测试以受接口契约约束的设备替身提供响应；具体设备和现场负载到位后，再安排真实协议、性能与存储测量。

资料能够支持“存在候选控制操作”的判断，不能单凭命令文本证明响应、归属或断电后的连续性。已约定的设备能力继续作为接入契约；下表描述如何补齐可供驱动消费的证据，不把未完成联调改写成设备不支持。

| 设备接缝 | 驱动必须提供的结果 | 联调场景与通过条件 |
| --- | --- | --- |
| 设备绑定与参数定义 | 稳定绑定标识、适用版本、合法参数及默认值、明确预览声明 | 多设备与重连后仍操作目标设备；受理和能力导出使用同一规则 |
| 启动与状态查询 | 本次启动响应的可靠成功判据，正在录像状态及路径 | 正常响应、响应丢失和无法解释分别记录；不把调用退出码单独当成录像证据 |
| 录像与文件归属 | 将设备录像和文件关联到已保存动作的证据 | 启动后关联保存前中断；既有文件、编号变化及设备重启不造成错认 |
| 停止与写入完成 | 目标停止结果，以及源文件不会继续增长的依据 | 正常停止、响应丢失、重复停止和后来查询；不凭瞬时大小不变认定写完 |
| 连续计时 | 能证明同一次录像连续性的设备或历史依据 | 主机重启、时间不可信和相机重启分别判断；不沿用上一会话单调钟 |
| 按位置读取和摘要 | 固定源身份、完整长度、按偏移读取及源端摘要 | 中断续传后字节一致；偏移不支持或文件变化时明确报错；不安装相机端新依赖 |
| 删除及存在性查询 | 指定目标删除结果，可靠不存在与查询错误的区分 | 删除响应丢失后查询；另一份录像继续执行且其文件不受影响 |
| 预览与原片配对 | 同源关系、预览完整大小、写完依据及实际候选数量 | 不按目录返回顺序配对；存在多个候选时先取得事实，再讨论选择规则 |
| 控制与传输并发 | 文件读取期间必要停止命令仍可执行 | 持续传输中发出停止并测量响应；内部修复输入和普通取回共用单文件读取资格 |

设备接入交付物包括：每项操作的输入与分类结果、解析器受控样例、正常执行链的联调记录，以及上表关键中断点的观察结论。设备专有材料在对应受控资料中维护；正式实现规格只记录抽象能力与证据条件。

没有实际设备和完整响应资料时，可以实现接口及符合契约的替身，不能宣称完成真实适配。只有联调证明设备无法满足既定保证，才进入产品取舍；不能用猜测命令、选择最新文件或放宽验证来填补缺口。
