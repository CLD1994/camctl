## 实现与结果

| 范围 | 原行为及修改 | 修改前 | 修改后 |
| --- | --- | ---: | ---: |
| 报告首次初始化 | 固定引用和类型包装保留原规则接受范围；公共 Schema 的成功解析和完整检查按实际资源字节有限复用，每次返回独立副本。三个新进程、无分析器计时中位数。 | 1.072 秒 | 0.731 秒 |
| 同动作 READ，1000 个候选 | 相同可靠视图复用一次完整性检查，同动作按拷贝主键续页。三次完整枚举的中位数。 | 25.04 毫秒 | 9.80 毫秒 |
| 同动作 READ，10000 个候选 | 每页 100 项，包括末尾空页，共 101 页；候选序列摘要相同。 | 1766.96 毫秒、101 次完整性查询 | 94.86 毫秒、1 次完整性查询 |
| 多动作 READ，10000 个候选 | 同一规模的候选分散到各动作，动作切换保留完整排序。候选序列摘要相同。 | 1721.36 毫秒 | 751.15 毫秒 |
| 50 动作报告子进程 | 短读事务只绑定一次实例，同事务尾部恢复复用刚核对的当前边界。 | 8140 次 SELECT | 7136 次 SELECT |
| 报告实例身份查询 | 同一真实事务内省去重复核对，外部连接继续独立核对。 | 1720 次 | 1116 次 |
| 报告最新事务边界及最大事件查询 | 两类查询分别计数，跨事务重新取得当前边界。 | 各 604 次 | 各 504 次 |

READ 的规模诊断使用内存 SQL 合成投影，保留真实列、主键和索引，省略外键及状态 CHECK 约束。它测量查询筛选、顺序和增长成本，不代表完整、合法的业务世界。生产每轮消费一页并通过后续唤醒继续；完整枚举耗时不能当作一次生产调度调用耗时。多动作场景仍会重复执行完整排序，不能据此宣称所有分布达到线性复杂度。持续写入或回滚会保守重置旧分页位置，收益取决于实际工作集及变化频率。

报告规则初始化仍有固定成本。上述结果没有省略派生报告、错误详情或精确数字校验，也没有引入持久化的预编译规则缓存。报告查询数量的减少约为 12.3%，但 SQL 在原样本中只占约 55 毫秒，不能将查询数量下降直接换算为端到端提速。

## 最终整合后的流程对照

使用同一临时流程脚本，基线发行包和修改后源码分别采用独立字节码缓存目录。各自先执行一个单动作场景预热，再执行两个独立新库的 50 动作场景。每个场景依次运行官方 `init`、`submit`、`run`，然后重开空会话；每阶段限制为 90 秒。

| 阶段 | 基线两次计时 | 修改后两次计时 | 基线／修改后中位数 |
| --- | --- | --- | --- |
| submit 进程 | 0.997、1.001 秒 | 0.998、1.044 秒 | 0.999／1.021 秒 |
| run 进程 | 5.132、5.184 秒 | 4.615、4.001 秒 | 5.158／4.308 秒 |
| 空会话重开 | 0.775、0.735 秒 | 0.737、0.718 秒 | 0.755／0.727 秒 |

四个计量场景的 50 个动作均成功，均形成 2 份报告、263 条历史事件。进程计时包含导入、装配、报告子进程、等待和收场；采样次数有限，修改后两次 `run` 有约 0.61 秒差异，因此本记录只报告当前开发环境的观测结果，不将其作为稳定提速比例或目标 ARM 主机承诺。SQL 另行单次采样，未与上述无分析器计时混用。

## 语义与异常诊断

- 报告初始化：新旧引用、类型包装的接受结果和异常相同；覆盖非法规则、本地引用、未登记引用、Decimal、整数和布尔值。资源内容改变后重新校验，资源缺失和非法派生规则继续报错，调用者修改返回值不会污染另一份返回值或共享登记。完整报告派生义务的摘要一致。
- READ：混合持槽、动作、计划及拷贝顺序的候选序列一致，坏来源、坏绑定、缺失和重复 READ 仍被发现。稳定两轮从拷贝 1—10 推进到 11—20，第二页不再执行完整性查询，事务已经结束。自身写入、其他连接提交、回滚、换连接和取消均使复用失效。
- 轮中变化：观察历史尾后、读取页面前，外部提交将一个候选移到旧游标之前；新页从该候选重新开始，并清除其他查询种类的旧位置。
- 回滚失败：临时故障诊断确认沿原数据库结果通道交付 `unknown`，执行器关闭旧连接并在下一任务重开，原错误及回滚错误均保留。
- 报告历史读取：后续提交产生的新当前边界在新事务中可见；异常回滚后可继续读取；外部异实例连接被拒绝，调用者仍拥有外部事务。

P1、P2、P3 均由 `gpt-6.1-sol / xhigh` 独立审查通过。最终 6 个生产文件与各评审阶段逐字节一致，完成不执行代码的语法编译和 `git diff --check`；27 项生成资源与权威来源一致。数据库表、列、索引和格式均未修改，不需要数据库迁移。
