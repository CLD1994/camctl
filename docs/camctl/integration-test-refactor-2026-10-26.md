## 目标与验证边界

从删除阶段的 `51a0e20b` 继续重构 camctl 组件集成测试与根目录跨组件测试。保留原来的功能、失败、取消、未知提交恢复、文件所有权、分页和容量目标，集中环境创建与关闭，通过模块正式公开接口提交输入并观察结果。实施与完成状态由[优化计划 S13](../superpowers/plans/2026-10-25-integration-test-optimization.md#s13通过公开入口重构保留的集成测试)维护，原目标清单由[删除阶段审计](integration-test-pruning-2026-10-26.md)提供。

本阶段只修改测试、测试支持、测试运行器与相关文档。生产代码保持删除阶段的身份；测试发现的生产问题保留证据并单独交接。

质量复盘与后续编写示例见[重构复盘](integration-test-lessons-2026-10-27.md)。每批迁移同时检查目标是否有效、真实协作者是否执行、故障是否命中以及原结果与资源是否收场；评审发现的假承接继续修正，不能只按通过数量认定迁移完成。

## 已集成的调用与资源边界

共享支持位于 `apps/camctl/tests/integration/support`。状态库采用正式结构；业务连接在真实数据库线程创建并关闭，观察连接属于测试线程。受理经过实际文件读取、解析与 `accept_input`。拍摄运行对象由 `session_capture_assembly` 创建，取回与清理由各自正式会话工厂创建。完整业务链使用默认 `build_runtime`、`execute_command` 和 `close_runtime`。报告分别验证实际冻结、worker 生成、文件发布与默认会话。

冷恢复必须关闭上一次实际数据库 worker 和相关任务，然后重新创建协作者。只重开测试的观察连接不算冷恢复。纯状态与精细交互分支可以移到单元测试，但须隔离真实资源，包括导入模块时读取的包资源。

静态事件校验另有明确公开入口：[历史计划 H1](../superpowers/plans/2026-09-30-camctl-history.md#h1-事件版本与具名校验消费者)规定 `validate_event` 接收 `EventContext`，[模块契约](module-contracts.md#当前事件的限定事实读取)规定用 `ReadCoverage` 说明静态范围。专门验证当前事实与未来提案隔离时，可以将这些正式输入与真实登记、业务守卫组合，保留为窄集成；它不代表整个未来事务能够提交。真实保存和回滚仍通过事务入口验证，功能场景仍通过业务入口建立状态。

旧缓存文件已移除对缓存名称和私有核验调用次数的依赖。当前六个实例保留五类目标：后续事务发现篡改、不同连接隔离、当前引用及尝试范围核对、未提交候选不取得已提交资格且整笔回滚、三页六个成员跨四加二读取边界并保留未知元数据。它们使用真实事务与公开结果页、成员分页入口。

来源存储的原 Python 分配增长检查仍未通过：移除 SQL 观察器后，20／200／600 条输入的原键核实峰值分别为 215,003／1,307,066／2,441,281 字节，增量 2,226,278 字节超过原 2,000,000 字节阈值；保存和原键重放均成功，库内容不变。只读诊断定位到交接下一批固定 64 个事件时，上批对象仍存活。该现象尚不能证明无界增长或整个程序违反 2GiB 预算。旧基线未经适配时先被测试的 `fetchall` 禁令阻断，不能将诊断对照称为旧内存断言已经原样重现。
