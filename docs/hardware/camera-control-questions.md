## OSMO 360 II：普通录像 STOP 无输出超时并继续录像

记录日期：2026-10-19 UTC。相机 ADB product 为 `eagle4_oq102`，通过开发容器访问宿主机 ADB 服务。独立诊断使用官方设置映射、受管工具及生产响应解释器，普通全景录像请求 10 秒、标准码率、手动曝光；固定参数及命令由[控制交接资料](camera-control-handoff.md#osmo-360--360-ii-全景录像)维护。固件及控制工具版本尚未取得。

### 实际控制与观察

十二项设置均通过各自响应检查，随后发送 START：

```sh
dji_mb_ctrl -R diag -g 1 -t 0 -s 2 -c 02 01
```

START 于 11:54:53.701591 UTC 完整正常返回 `Resp message, len = 1, data: 00`。等待目标 10 秒后，于 11:55:03.711083 UTC 发送首次 STOP：

```sh
dji_mb_ctrl -R diag -g 1 -t 0 -s 2 -c 02 00
```

本地主机等待 20 秒，没有收到 stdout 或 stderr。期限到后向本地 ADB 进程发信号，实际取得信号 15 退出；这不证明相机端控制进程已经退出，也不证明 STOP 已到设备。相机日志最后观察仍为 `recording:1`。当时停止后续硬件操作，没有自动重试或取回。

用户随后从现场确认相机仍在录像，已持续 8 分 35 秒。依据这项确认，于 12:04:01.469339 UTC 再发送上述 STOP；12:04:03.192200 UTC 收到完整正常 `00`、本地退出 0。之后连续五条回调均为 `timelapse:0,recording:0`，boot ID 未变，进程快照没有残留 `dji_mb_ctrl`。没有再次 START、重启相机或删除文件。停止后等待至少 30 秒，观察到新增 OSV 9281473728 字节、LRF 988994565 字节；源文件保留，未读取实际媒体时长。

首次 STOP 的无输出阶段尚未定位，不能把它归因为已证实的固件故障、网络故障或曝光模式限制。详细对照见[录像时长报告](osmo360ii-record-duration-report.md#零启动余量的独立对照)。

日志对照中，成功的手动 START 和此前自动曝光 STOP 都有与工具 stdout 中 PID 对应的 `host 1e00` 路由初始化记录；失败 STOP 没有 stdout，手动轮日志在 START 初始化后也没有后续同类路由记录。这是当前可见记录的差异，尚不能区分 ADB、远端 shell、工具初始化或设备服务中的哪一步未推进，也不能证明请求未送达。`RecorderService` 重连及 `-1003` 等记录在成功调用中同样出现，不能单独作为此次超时的原因。

相机随后接回 TX2，改用本机 ADB 串行完成四轮对照：标准库直接命令、生产驱动和两种曝光的正式 CLI 计划，均只发送一次 START／STOP 并正常停止。直接命令不经过 camctl 受管执行或调度。两轮正式 10 秒计划的原片为 11.211200 秒和 11.778433 秒，实际 STOP 进程在意图保存后约 35～40 毫秒启动，完整响应写入后约 15～24 毫秒退出。原停止超时尚未复现；这项差异不证明远程 ADB 是原因，也不能排除设备偶发等待。分层条件和原片依据见[TX2 本机对照](osmo360ii-record-duration-report.md#相机接回-tx2-后的分层核验)。
