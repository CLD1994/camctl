# 结果读取性能人工验证

本指南验证[单次目录列举与调度优化](../superpowers/specs/2026-10-25-result-reading-performance-design.md)。软件单元测试验证接口和状态分类，实际 ADB 耗时、相机工具兼容性与拍摄结果由本指南核对。

## 准备与执行

使用人工验证环境的 `config.toml`，将 `[log]` 的 `level` 设置为 `"INFO"`，使阶段计时进入 `paths.log_file`。本次环境的文件为 `/home/cld/.camctl/manual-validation-20261025/camctl.log`。日志仍遵守普通队列与轮换规则，业务事实以报告和数据库为准。

重新生成具有新 `request_id` 和未来绝对时间的计划，使用与对照轮相同的设备、录像时长、分段模式及后续延时摄影参数。动作间隔和允许延迟分别记录，不能将允许延迟等同于录像时长或任务间隔。通过既有 host 终端提交，完成后用 `claim` 领取报告和媒体。

验证期间保留原相机历史媒体，用相同目录规模比较阶段耗时。需要比较其他规模时，使用人工明确准备的样本；不为性能测量自动删除设备正式产物。

## 计时与结果

普通日志中以 `性能计时` 开头的消息包含阶段、经过毫秒数及适用的设备、动作、尝试或页身份。计时覆盖真实调用返回或异常，不能把事件中的业务事实时刻当作事务提交返回时刻。

核对实际目录与元数据调用数量、候选筛选输入与新增计数、前页历史核对、结果页保存，以及分段结果提交的耗时。目录计时中的 `mode="page"` 表示普通逐页调用，`mode="single_scan"` 表示当前结果尝试的单次完整枚举；缓存复用页不增加 ADB 调用次数。文件完成等待通过独立的 `file_completion_wait` 阶段计时，并与原结果页中的可靠等待事实核对，不从目录计时推断它已缩短。

启动前的基准收集也须核对实际目录调用数量。`baseline_preparation` 记录一次准备推进至返回的经过时间，包括该次推进中的页保存；暂停后的多次推进分别记录。`camera_setting` 记录实际派发的每条设置命令，`camera_start_command` 单独记录真正启动命令。二者携带原设备、活动与尝试身份，设置计时不能用来证明拍摄已经启动。动作在设置阶段过期时，允许只有设置计时而没有实际启动计时。

使用窄启动窗口时，同时记录首次窗口观察、完整基准保存、每条设置和实际启动的顺序。按时观察但在基准或设置阶段耗尽窗口，与拍摄结束后的结果读取延迟分别判断；文件完成等待只在适用的停止确认后发生，不参与启动前的预算。

对“126 份旧文件、10 份新增文件”的对照场景，完整路径范围应仍有 136 份，元数据查询对象应只有新增的 10 份。实际元数据调用数由这些新增文件分布的结果页决定；它们位于同一页时只需要一次批量查询。正式原片与预览的数量、配对、大小和取回内容应与真实文件一致。

后序动作在允许窗口内应具有窗口观察依据，即使设备当时仍被前序任务占用。设备在窗口内释放且其他资格满足时，动作取得执行机会；窗口结束后仍不能启动。已观察但未能启动的动作报告 `window_exhausted`，不能以改变过期名称代替实际性能改善。

报告维护和本地结果保存期间继续观察后序动作。报告取消或会话结束时，已经开始的文件操作先完成实际收场，再释放连接与临时目录清单。对真实进程中断的恢复验证单独记录，不把正常停止等同于物理断电。
