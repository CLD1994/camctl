# 客户端计划编辑

[返回设计总览](../2026-09-08-camctl-cli-design.md) · [阅读路线](reading-guide.md)

本专题定义第一版网页中的拍摄参数编辑方式。客户端采用表单作为主要入口，保留 JSON 编辑以处理通用表单无法充分表达的参数。部署及人工交接见[客户端的本地部署](client-deployment.md#客户端的本地部署)，参数规则来自[能力说明](capabilities.md)。

**阅读提示：** 从用户添加一个拍摄动作开始阅读。表单和 JSON 编辑使用同一份参数；随后各节说明切换编辑方式、发现错误和导出时怎样保留用户输入。

## 正常编辑流程

用户在计划中添加拍摄动作，依次选择目标设备、拍摄动作类型和参数类型。设备及类型选项来自当前成功启用的能力说明，按[设备、动作、参数类型的关联](capabilities.md#客户端选择与校验)取得对应 Schema。选择结果写入动作的 `device_id`、外层 `type` 和 `params.type`；网页根据这些字段显示当前选择。

选定参数类型后，网页展示其名称、任务说明和固定设置，并根据 Schema 为普通参数生成控件。用户填写参数，浏览器即时校验并指出字段或组合错误；完成整个计划后，由客户端后端校验当前准备导出的完整内容，再生成计划 JSON 文本供用户交接。

动作名称、执行时间、业务策略等公共字段仍按[执行计划输入契约](plan-input.md)编辑和校验。拍摄参数表单处理选定类型的 `params`，不能代替整份计划校验。此流程用于准备新请求；已经导出的请求按[确认与重送规则](plan-acceptance.md#客户端确认与重送)保留原内容和身份。

## 根据 Schema 生成表单

表单控件及说明从同一份已启用的参数 Schema 派生。普通字段的第一版编辑能力如下；具体控件外观由客户端实现确定：

| 参数形态 | 编辑行为 |
| --- | --- |
| 明确的字符串字段 | 提供文本输入，保留字符串值 |
| 明确的整数或数值字段 | 提供数值输入，按用户有效输入生成对应 JSON 数值；未填写或尚未完成的输入不解释为 `0` |
| 布尔字段 | 提供明确的真假选择；字段缺省与显式 `false` 分开表达 |
| 明确列出的枚举选项 | 提供选项选择，写入所选项原有的 JSON 值和类型 |
| 嵌套对象、数组或其他通用表单无法充分表达的结构 | 提供 JSON 编辑入口，保留完整参数和同源校验 |

参数类型的名称与任务说明使用能力说明中的 `name`、`description`；具体字段的名称、含义和单位使用 Schema 中相应的 `title`、`description`，同时保留字段标识以便定位。必填性、默认值及取值限制按 Schema 展示，不另外维护一套相机专属的表单校验规则。

可选字段允许保持未填写。缺省、显式 `null`、空字符串、`0` 和 `false` 按用户实际输入及 Schema 分别处理；控件不能将这些值互相替换。Schema 中的默认值展示为说明，打开表单或切换视图不自动把它写入参数。校验及 camctl 首次受理时的生效参数计算遵守[默认值契约](camera-capabilities.md#拍摄参数的-json-schema)。

固定任务可能只需要 `params.type`。此时网页展示任务的固定设置，不生成驱动没有开放的调整项。

### 字段显示与必填性

正常字段以控件内的值为准，不另列“当前值”或重复的缺省提示。字符串选项显示原字符串，不显示 JSON 的引号；写入的值仍保持原有类型。必填字段标明“必填”，不提供“省略”操作；用户可以清空输入继续编辑，但缺失或未完成时阻止导出。可选字段通过明确的“填写／不填写”选择表达字段是否存在，只有启用后才显示输入控件；空字符串、`0`、`false` 和 `null` 仍分别保留。清除待修正输入是放弃这段输入，不代表必填字段已经满足。

仅当原值无法被控件正常表达时，在字段旁展示待修正的原值与原因。字段标识用于辅助定位，主要标签、选项和说明优先面向普通使用者。

### 参数选项联动

可完整枚举的参数使用当前完整 Schema 推导合法组合，所有下拉框双向联动。对字段 F，候选值只有在保留其他已填写字段后，仍存在一组满足完整 Schema 的参数时才可选择；未填写字段只在计算中尝试可能值，不向草稿写入默认值。以[演示参数类型](capabilities.md#完整示例)为例，已选 `4K` 时帧率只提供 `30`；已选 `60` 帧时分辨率只提供 `1080p`。要换到与已有选择冲突的配置，先清空对应选择，再选择新组合。清空是编辑中的未完成状态，不能导出。

| 状态 | 控件与数据行为 |
| --- | --- |
| 规则可完整枚举，其他已填字段兼容 | 仅展示存在合法补全的选项；选择只写入当前字段 |
| 字段尚未填写 | 展示“请选择”；用全部合法补全计算其他字段选项，不自动选首项 |
| JSON、预设、旧草稿或说明重新加载带来非法值或非法组合 | 保留原值，独立提示问题；非法原值仅用于显示，不作为可选择项；用户可清空或选择兼容值修正 |
| 未完成输入影响组合判断 | 保留原文，暂停相关选项选择；先修正或放弃未完成输入 |
| 完整规则下不存在兼容选项 | 明确显示无兼容选项，引导清空冲突字段或使用参数 JSON，不自动替换其他值 |
| 规则有效但无法可靠枚举，或组合规模超过客户端处理上限 | 明确说明不能生成联动选项，使用 JSON 编辑这些参数并执行完整校验；不把未知解释成无合法组合 |

第一版的自动联动覆盖根对象以 `additionalProperties: false` 封闭、所有属性可由常量、枚举或布尔值限定的参数，包括本地引用和完整 Schema 中的条件、交集、并集、互斥及依赖约束。可选字段的缺省也是一个独立候选。最多检查 4096 个候选组合；超出时使用上述复杂参数入口。非有限字段仍可用普通输入控件编辑，复杂结构通过 JSON 编辑。联动能力不会改变能力说明的加载合法性及后端完整校验。

### 动作折叠

每个动作可独立展开和收起，并提供“全部展开／全部收起”。新加入的动作默认展开。收起时保留动作顺序、名称、类型、执行时间及问题数量，用户无需展开即可识别待修正动作。折叠只是当前页面的显示状态，不写入执行计划，不改变参数、未完成输入或自动保存；展开后恢复原来的编辑内容。删除动作后，其他动作的折叠状态与对应动作一致。

## 表单与 JSON 共用参数

两种编辑方式操作同一个拍摄动作的完整 `params`，不分别维护两套可导出参数。JSON 编辑入口显示当前完整对象，包括 `type`，使用同一份能力说明选择规则并执行校验。

从表单进入 JSON 编辑时，使用当前参数生成文本。JSON 已能解析为对象时，其内容成为当前参数，表单据此显示可表达的字段；即使参数未通过 Schema 校验，也保留内容并提示错误。JSON 中修改了 `params.type` 时，类型选择和校验依据同步使用该值，未知类型按输入错误显示。

表单不能完整表达对象中的某些字段时，保留这些字段并提供 JSON 编辑；修改表单中的其他字段不能丢弃它们。切换视图本身不改变字段是否存在、字段值或 JSON 值类型。JSON 的缩进及对象键顺序可以随展示变化，不属于参数业务内容。

尚未完成的 JSON 文本保留在当前编辑状态中，并显示解析错误。该文本修正前，不能用旧的已解析对象覆盖它，也不能导出旧对象冒充当前编辑结果。JSON 对象出现重复键时，同样按输入错误处理。

表单不能提供合适控件与校验器不能解释 Schema 是两种不同情况。前者可通过 JSON 编辑继续使用有效规则；后者遵守[能力说明加载失败规则](camera-capabilities.md#客户端加载能力说明)，不能绕过校验生成计划。

## 校验与导出

对于包含拍摄动作的新计划，按下表从上到下判断当前参数编辑结果。每一行均以不满足前面行的条件为前提：

| 当前条件 | 反馈与后续行为 |
| --- | --- |
| 控件输入尚未形成有效 JSON 值，或 JSON 文本存在语法错误、重复键 | 保留当前输入并指出问题；不导出计划，不使用旧值代替 |
| JSON 有效，但拍摄 `params` 不是对象 | 提示参数必须是对象，保留内容供修正；不导出计划 |
| 参数为对象，但能力说明不可用，或设备、动作、参数类型无法匹配有效规则 | 区分说明加载错误与选择错误；保留参数供修正，不导出该计划 |
| 匹配规则有效，但参数不符合 Schema | 提示对应动作、字段或组合错误；允许继续通过表单或 JSON 修改，不导出计划 |
| 参数符合规则 | 参数校验通过；整份计划还须通过公共字段、业务条件及客户端后端的导出前校验 |

以上参数规则仅应用于拍摄动作。没有拍摄动作的计划按自身动作契约校验，例如空设备目录下仍可准备和导出合法的 `report_status` 计划。

浏览器负责即时反馈，后端校验实际准备导出的最新完整计划，不根据浏览器先前的通过提示或旧的草稿值直接导出。两处使用同一份已启用的规则及既定校验配置。校验器不自动转换类型、删除字段或填入默认值；例如 JSON 中的 `"30"` 不能因字段要求整数而变成 `30`。

输入错误应定位到对应动作及字段；组合错误还应说明相互约束的参数，帮助用户作出修改。草稿可以处于未完成或非法状态，导出成功才表示当前内容已完成客户端校验；它不表示 camctl 已受理、设备在线或计划已经执行。

## 验收要求

- 使用能力说明中的演示类型，验证逐级选择、名称与单位显示、普通字段控件以及只填写类型的固定任务。
- 验证合法参数可通过两种编辑方式得到相同的参数对象；切换视图保留字段缺省、显式值和 JSON 值类型。
- 在表单中验证参数双向联动、缺省时的合法补全及清空后重新选择；JSON 或预设带入非法组合时，验证原值保留、能定位原因且不会自动替换。JSON 中的数值字符串保持字符串并按规则报错。
- 验证必填字段没有省略按钮，普通字段不重复显示当前值，字符串选项不带 JSON 引号，可选字段启用和关闭不混淆缺省与显式值。
- 验证多动作的单独及全部折叠、收起后的错误提示、添加和删除动作后的状态对应，以及未完成输入在折叠和展开后保留。
- 编辑表单无法表达的参数及额外字段，验证通过 JSON 仍能修正；切换视图或修改其他字段不丢失原内容。
- 从有效参数进入未完成、不可解析、重复键或非对象输入，验证保留当前内容、阻止导出且不回退导出旧值；修正后重新校验。
- 分别验证规则有效但表单不支持、参数不符合规则、规则本身不可用，保持三者的处理区别。
- 验证浏览器提示通过后，后端仍校验此次导出的完整计划；其他公共字段有误时不能仅凭参数通过而导出。
