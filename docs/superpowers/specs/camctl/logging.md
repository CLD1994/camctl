# 运行日志

[返回设计总览](../2026-09-08-camctl-cli-design.md) · [请求受理与会话](protocol-session.md)

本专题定义普通运行日志文件的保留方式。CLI 的 stdout 结果、stderr 诊断及退出状态由[进程结果协议](protocol-session.md#stdout-与退出状态)定义。

## 日志用途

普通运行日志用于排查近期运行问题。计划受理、动作结果、设备恢复证据及报告重建依据仍按[持久化规则](../2026-09-08-camctl-cli-design.md#持久化与配置基础)写入数据库并永久保留；这些事实不能只写日志而不保存到状态库。

业务恢复与报告重建依据数据库历史，日志轮换或删除不会删除业务历史。日志文件不登记为正式产物、delivery 或状态报告。

## 配置与默认值

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `paths.log_file` | `$HOME/.camctl/camctl.log` | 正在写入的日志文件 |
| `session.log_level` | `WARNING` | 日志级别 |
| `session.log_max_bytes` | `10485760`（10 MiB） | 单文件轮换阈值，按文件字节数判断 |
| `session.log_file_count` | `3` | 保留文件总数，包含正在写入的文件 |

轮换阈值和文件总数均为大于等于 1 的整数；0、负数、布尔值及其他错误类型属于本地配置错误。配置文件可省略这些字段，按[默认值与覆盖规则](scheduling-execution.md#本地配置的加载与更新)处理。配置更新后，后续进程使用新值；日志策略属于会话配置，不作为动作执行预算固化。

## 文件轮换

当前文件使用 `paths.log_file`。归档文件在该路径后追加数字后缀，`.1` 是最近一份，数字越大表示越旧。按默认配置，正常保留的文件为：

```text
$HOME/.camctl/
    camctl.log
    camctl.log.1
    camctl.log.2
```

设轮换阈值为 `B`，保留总数为 `N`。处理一条日志前，先按表判断；只有配置合法且相关文件操作可以完成时，才适用表中的正常结果。

| 当前文件状态 | 处理 |
| --- | --- |
| 当前文件不存在 | 创建当前文件并写入本条日志，不因缺少当前文件而清空已有归档 |
| 当前文件大小小于 `B` | 向当前文件追加本条日志 |
| 当前文件大小大于等于 `B`，且 `N = 1` | 轮换时淘汰旧内容，只保留新当前文件并写入本条日志 |
| 当前文件大小大于等于 `B`，且 `N > 1` | 将当前文件转为最近归档，已有归档依次后移，删除超过 `N - 1` 份的最旧归档，再写入新当前文件 |

阈值按一条完整日志写入后的大小判断，因此跨过阈值的那条日志可以使文件略大于 `B`；下一条写入前轮换，不为凑齐阈值截断诊断内容。重启沿用已有文件的实际大小与归档顺序，不重新累计一套进程内文件额度。

将保留数量调小时，下一次写入前清理本机制管理的超限旧归档，使正常完成后的文件总数符合新值。清理范围仅为所配置日志路径对应的归档文件，不扩大到其他目录、状态库或业务文件。

## 多进程共用

相同日志路径对应一组文件和一个保留上限；并发运行的 `run`、`submit` 共用这组文件，而不是每个进程各保留 `N` 份。

追加与轮换须在所有写入进程之间协调，避免某个进程移动归档时另一个进程仍把新日志写进旧文件。一次正常完成的写入追加到当前文件，轮换后保持上述归档顺序及数量上限；不能仅以进程内互斥保护多个进程共享的日志路径。具体协调方式由实现选择。

## 验收要求

单元测试按配置合法性和文件状态分类，验证默认值、阈值以下、恰好达到阈值、跨过阈值、保留数量为 1 和大于 1，以及重启继续采用已有文件大小。通过受接口约束的替身验证轮换顺序、最旧归档淘汰与删除范围，日志文案不逐字断言。

集成测试使用真实文件系统验证追加、轮换、减少保留数量及重启后的文件内容与数量；使用真实并发进程验证同一路径的写入与轮换共同满足约束。在不会触发正常淘汰的场景中，每条成功写入的测试日志完整出现且不重复；发生淘汰时按最旧归档边界判断，不要求已淘汰内容仍然存在。验证普通日志删除不修改状态库、产物及报告文件。
