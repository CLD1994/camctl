# 当前相机录像参数

[返回设计总览](../2026-09-08-camctl-cli-design.md)

本专题定义当前 ADB 相机普通录像的参数组织。录像生命周期及框架的参数类型扩展机制见[相机拍摄](camera-recording.md)，参数规则的导出见[能力说明格式](capabilities.md)。

## 适用范围与资料依据

第一版接入当前相机的 `camera_record`。Action / Action6 与 OSMO 360 / 360 II 的命令和会议记录见[相机控制交接资料整理](../../../hardware/camera-control-handoff.md)。这些记录用于提取任务意图和候选命令，设备适用版本、可调范围及命令响应由用户后续与提供方核对，并通过驱动联调落实。

当前以 MVP（最小可行版本）验证真实录像任务能否贯通计划生成、受理、设备执行、产物取回和状态报告。优先完成验证任务使用的参数契约、命令映射及必要结果确认；更多可调选项与设备参数细节在完整交接后完善。实际启用的驱动仍须完整定义其接受的输入和执行结果，不能把尚未核实的行为解释为成功。

本专题已确定普通录像的参数组织、曝光分支及下文列出的固定设置。正式参数类型标识和其余参数定义，按“设备接入时补齐”的范围继续完善。交接资料中的 5—20 秒和 8 秒均为参考时长，不据此制定执行计划的时长限制或默认值。

## 普通录像与曝光选择

每个目标驱动在当前普通录像的 `camera_record` 下使用一种参数类型，通过 `params.exposure.mode` 选择曝光方式。手动和自动曝光共享该驱动的普通录像参数类型标识、公共画面参数，以及启动、计时、停止和产物处理流程。

| 字段 | 职责 |
| --- | --- |
| 动作的 `type` | 为 `camera_record`，选择录像动作 |
| `params.type` | 选择目标驱动声明的整套普通录像参数契约；两种曝光方式使用相同标识 |
| `params.exposure` | 必填对象，包含曝光方式及该方式允许的设置 |
| `params.exposure.mode` | 必填字符串；`manual` 表示手动曝光，`auto` 表示自动曝光 |
| `params.exposure` 中的其他字段 | 由所选曝光分支和驱动定义约束 |

`exposure` 属于当前相机的录像参数契约。其他驱动可以按自身任务定义参数结构；框架仍允许一种拍摄能力拥有多种参数类型。客户端预设保存选定设备、参数类型和具体参数值，生成计划时按既有规则展开。

### 曝光分支

| 曝光方式 | 参数组织与执行含义 |
| --- | --- |
| `manual` | 固定曝光设置由动作参数或驱动明确的固定设置确定。开放 ISO 调整时使用 `exposure.iso`；本分支不接受 `exposure.compensation_ev` |
| `auto` | 驱动调用相机的自动曝光功能，曝光补偿使用 `exposure.compensation_ev`。本分支不接受固定 `exposure.iso` 或要求固定快门的输入；相机实际调整的项目与范围由设备契约定义 |

色彩、分辨率、帧率、视角和防抖等设置，按各自字段与设备组合规则定义。选择自动曝光本身不表示这些设置也采用自动控制；白平衡采用下文确定的固定值。

以下 JSON 只展示 `params` 中的 `exposure` 部分，用于说明字段组织，不是可单独提交的完整拍摄参数。示例数值来自交接资料，不定义默认值、完整取值范围或对所有相机的适用性。

手动曝光的结构示例：

```json
{
  "exposure": {
    "mode": "manual",
    "iso": 800
  }
}
```

自动曝光的结构示例：

```json
{
  "exposure": {
    "mode": "auto",
    "compensation_ev": 0
  }
}
```

### MVP 的固定设置

当前普通录像将以下设置作为驱动执行流程的一部分，执行计划不提供相应调整字段：

| 曝光方式 | 快门 | 白平衡色温 |
| --- | --- | --- |
| `manual` | 固定为 `1/60` 秒，由驱动设置 | 固定为 `5200 K`，由驱动设置 |
| `auto` | 按相机的自动曝光规则处理 | 固定为 `5200 K`，由驱动设置 |

驱动在拍摄准备中执行相应设置操作。手动快门的固定值只用于 `manual` 分支，不在进入自动曝光后强制设为 `1/60` 秒。

固定设置属于驱动参数契约，在能力说明的任务说明中展示；客户端不生成调整控件，执行计划不重复填写。参数 Schema 只接受已开放字段，提交额外的快门或白平衡调整字段属于动作自身参数错误，不静默忽略。

后续完整交接确认可调整选项时，可在同一录像参数类型中增加相应字段及约束，并补齐驱动操作映射。沿用既有的驱动定义、同源 JSON Schema 和 `camctl describe` 导出机制，再按部署流程同步客户端；无需为这类字段扩展改变框架的动作接口。已受理动作继续使用首次受理时确定的执行配置，遵守[参数固化规则](camera-recording.md#计划字段与参数校验)。

### 分支校验

以下规则以设备、动作、参数类型已经匹配到有效定义为前提，按表中顺序判断；每行以此前条件不成立为前提。参数错误沿用[计划字段与参数校验](camera-recording.md#计划字段与参数校验)：客户端阻止导出错误计划，camctl 首次受理时仅将对应录像动作登记为 `failed`，保留零次执行尝试，整份拒绝优先级保持既有规则。

| 条件 | 结果 |
| --- | --- |
| `exposure` 缺失、为 `null` 或不是对象 | 参数错误 |
| `mode` 缺失、不是字符串，或值不属于该驱动支持的曝光方式 | 参数错误，不推断曝光方式 |
| `mode` 为 `manual`，但提交了自动曝光补偿字段 | 参数错误，不忽略不适用字段 |
| `mode` 为 `auto`，但提交了固定 ISO 或固定快门设置 | 参数错误，不将固定值解释为自动调整的范围 |
| 曝光方式及前述字段归属合法，但提交了 MVP 未开放的快门或白平衡调整字段 | 参数错误，不覆盖驱动固定设置 |
| 分支选择及字段归属合法，但缺少该驱动要求的字段，或字段值、组合不符合规则 | 参数错误，指出对应字段或组合 |
| 曝光设置及其余拍摄参数均符合有效规则 | 拍摄参数校验通过，继续既有公共字段校验和调度流程 |

条件分支、允许字段及组合约束属于该参数类型的同源 JSON Schema。规则本身无效或无法取得时，遵守既有规则处理失败语义，不判为用户参数错误。

客户端按曝光选择展示对应设置，表单与 JSON 编辑仍遵守[参数保留与校验](client-editing.md#表单与-json-共用参数)。选择切换后按当前完整参数重新校验；隐藏字段不能绕过校验或在切换视图时被丢弃。对条件结构的展示依照同源规则生成，校验不另外维护一套相机字段清单。

## 设备接入时补齐

| 项目 | 需要形成的定义 |
| --- | --- |
| 设备绑定与参数类型 | 确定各型号、固件对应的驱动和正式参数类型标识 |
| 公共录像参数 | 确定时长、画面规格及其他开放字段的名称、类型、单位、必填性、默认值与限制 |
| 曝光设置 | 落实上述固定设置，补齐验证任务所需的 ISO、曝光补偿等其余参数规则；更多可调选项在完整交接后完善 |
| 命令与结果 | 将参数映射到设置、启动、查询及停止操作，提供响应及产物关联依据；按[驱动接入契约](camera-recording.md#第一版驱动接入契约)验证 |
| 能力说明与一致校验 | 从完整驱动定义导出参数 Schema，在浏览器、客户端后端和 camctl 使用同一组输入样例验证合法与非法分支 |

完整参数契约形成后，真实设备的能力说明按既有部署交接流程导出并同步给客户端。资料中的某条命令或参考数值不单独构成一份可用参数定义。
