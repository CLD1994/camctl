# MCU 动作

[返回设计总览](../2026-09-08-camctl-cli-design.md)

本专题定义 MCU 命令与当前值查询。动作状态、时效窗口及通信执行规则见[调度与设备执行](scheduling-execution.md)，查询结果的保留和取回见[正式产物与取回清理](outputs.md)。

## UART 通信与会话生命周期

MCU 通过 UART（通用异步收发接口）与主机双向通信，采用请求—响应模式：camctl 发送指令，MCU 返回对应响应。MCU 不会在没有收到指令时主动上报数据。

MCU 固件与通信协议均由项目团队维护，可以共同定义主机与 MCU 两端的行为。具体协议须同时落实两端实现与联调验证。

`camctl run` 负责指令发送、响应接收及处理，第三方主程序不负责解析 MCU 业务。接收等待须与相机调度、取消及其他会话工作配合，不能因等待串口响应而停止处理这些工作。

| MCU 工作情况 | 对 `run` 生命周期的影响 |
| --- | --- |
| 命令尚待执行，或响应尚在允许的等待、接收、解析与保存过程中 | 属于未完成工作，继续按动作规则处理 |
| 响应超时、接收失败或结果未知 | 按有限重试、失败及恢复规则处理，不无限等待 |
| 已没有需要继续驱动的 MCU 工作 | 串口本身不产生继续驻留的责任；是否退出仍按全部计划工作和会话收尾条件判断 |

具体退出边界遵守[`run` 生命周期](protocol-session.md#run-生命周期)。MCU 不主动上报，不代表收到的数据一定属于当前命令；此前命令的迟到响应及中断后残留数据仍须按通信协议识别。

### 指令与响应的对应关系

camctl 为指令附带通信编号，MCU 在对应响应中原样返回该编号。发送前须可靠保存编号、目标 MCU、指令内容与所属动作的关联；不同指令不能复用同一编号，主机重启也不能把旧编号分配给另一条指令。编号的编码与分配方式由双方协议细化。

对已按协议解析的响应，结合来源 MCU 和编号查找原指令，不能仅凭到达顺序、响应类型或当前正在等待的动作决定归属：

| 关联查询结果与原动作状态 | 响应处理 |
| --- | --- |
| 可靠找到原指令，原动作仍未结束 | 交给原指令的处理流程核实响应含义；匹配编号本身不表示执行成功 |
| 可靠找到原指令，原动作已终态 | 按迟到或重复响应处理，保留必要诊断与实际观测，保持动作终态，不转交给其他动作 |
| 编号缺失、无效，或可靠查询后没有对应指令 | 按协议异常处理并保留诊断，不以此完成任何正在等待的动作 |
| 持久化关联不可读或无法可靠判断 | 按持久化错误处理，不能冒充未知编号或猜测响应归属 |

通信编号用于确定响应归属。重复发令时 MCU 是否再次执行、重试如何使用编号，以及能否查询此前执行结果，须结合命令副作用定义，不由响应匹配规则直接推导。

## MCU 动作

### `mcu_send_command`

动作发送命令并等待 ACK（命令确认）。

按照时效动作处理。

### `mcu_read_data`

`mcu_read_data` 发送查询命令并取得实际执行时的当前值。

它是无时效动作：

> 晚一些执行没有问题，返回执行时的当前值即可。

不要求获取原 `scheduled_at` 对应的历史值。

结果文件路径由 CLI 管理。

一次成功读取产生一个独立正式产物并分配：

```text
output_id
```

读取成功并形成正式产物后，后续取回或重传必须使用这份已保存结果。

不得重新查询 MCU 后用新的当前值冒充历史产物。

## 持久化记录

以下是支撑本专题行为的逻辑记录建议；表划分和内部接口不构成已确认的实现约束。

查询成功形成正式产物时，应关联来源动作和稳定 `output_id`，保存本次查询结果。产物公共字段由[正式产物与取回清理](outputs.md)定义。

命令及查询的已知结果、产物登记等变化按[持久化与配置基础](../2026-09-08-camctl-cli-design.md#持久化与配置基础)追加历史并同步更新投影。历史回放只恢复已记录状态，不发送命令或重新查询当前值；外部操作结果未知时，仍按本专题的恢复契约处理。

## 验收要求

### 单元测试

使用符合 UART 请求/响应接口的替身，验证命令确认、查询当前值、失败与边界结果，以及已保存查询结果的使用。

按通信与会话生命周期表验证待执行命令、未完成响应处理、超时及 MCU 工作全部结束的情况；没有 MCU 工作不能阻止会话按其他工作情况正常收尾，等待响应不能阻塞其他动作调度。

按指令与响应对应关系表覆盖正常、迟到、重复、无效或未知编号及关联查询错误；旧指令的响应不能完成新动作，终态不被响应改写，关联未可靠保存时不能发令。

### 集成测试

验证真实串口协议协作者、命令/响应关联及结果文件登记；验证后续取回使用持久化查询结果。

结合 SQLite、串口协议实现与 MCU 固件联调，验证编号往返一致；安排主机中断后恢复及旧响应晚于新指令到达的情况，验证仍关联原指令，不将旧编号分配给新指令。

### 行为覆盖清单

以下按行为组织，执行时按上述单元测试与集成测试边界归类。

#### MCU

- 延后执行时读取当时的当前值；
- 结果文件路径由 CLI 管理；
- 结果产物独立登记；
- 已登记结果不会被后续查询替换。

## 待确认与待细化

本节不构成已确认的行为选择。涉及其结果的实现须先补齐契约。

### 后续契约完善

补齐 `command` 参数与响应结构、ACK（命令确认）语义、超时后结果未知的处理，以及重试是否可能重复产生 MCU 副作用。命令确认与报告累计 ACK 分属不同协议。

明确消息边界、通信编号编码及分配方式、同一串口的接收归属及命令并发规则，覆盖分段到达、迟到响应和主机重启后的残留数据；响应归属遵守已确认的编号关联规则。
