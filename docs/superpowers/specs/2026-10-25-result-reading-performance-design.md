# 结果读取与调度性能设计

## 目标与范围

ADB 相机的分段结果读取对固定输出目录进行一次完整列举，由主机按原活动已经保存的基准筛选新增文件，再查询新增文件的大小。目录和结果继续按有限批次处理，窗口观察、过期检查与报告维护独立于同设备的长时间文件处理。

本设计补充[结果与设备执行](../../camctl/file-runtime.md)、[结果分页](../../architecture/camera-capture.md#跨页配对与可靠前页历史)、[中央调度](../../architecture/scheduling-execution.md)及[报告维护](../../architecture/report-maintenance.md)。公共计划、正式产物和报告的机器协议保持原有含义，文件归属仍由框架根据原设备绑定和原活动基准核实。

## 单次目录列举

每次 RESULTS 尝试使用自己独占的目录读取上下文。相机端对每个固定目录只执行一次完整遍历和排序；主机流式接收并使用临时文件缓冲，内存只保留当前解码片段和当前页。临时清单是当前尝试的工作缓存，不作为新的业务权威来源。

采用临时文件是为了先确认实际工具退出与目录帧完整，再向结果登记流程交付页，避免把尚未收场的工具留在两个页调用之间。目录缓存不跨尝试或跨进程复用。退出失败、输出不完整或帧非法时不授予完整扫描资格；进程中断后仍按原尝试恢复规则处理，缺少工作缓存不证明目录为空。

| 状态 | 处理 |
| --- | --- |
| 完整目录帧、成功退出及固定绑定均已核实 | 沿原清单按稳定顺序分页，每页保持原范围和连续游标 |
| 工具失败、取消或清单解码失败 | 交付实际错误，不把清单末尾解释为设备目录结束 |
| 本轮暂停后继续且原缓存仍由同一拥有者持有 | 继续原读取位置，不重新启动全目录遍历 |
| 尝试结束、取消或拥有者退出 | 确认相关工具和本地操作已经结束后关闭临时文件 |

## 新增文件与元数据

主机提供受原绑定、活动及固定基准约束的候选筛选端口。驱动不得按文件名中的时间或序号猜测新旧，不自行维护第二份基准。完整路径页中的旧文件仍表达其实际身份；没有查询大小时保留未知，不编造完成事实。框架保存结果时继续独立核对基准差集。

分段读取只对本次新增的受支持文件查询元数据。每个文件的零大小、访问错误及成功取得的大小分别保存。批量元数据脚本减少辅助进程和临时文件操作，继续保留逐文件身份、返回状态、输出、错误和完整结束标记。

## 增量历史核对与调度

同一结果读取拥有者首次继续原尝试时核对可靠前页链，之后只核对新追加的末页、票据、范围及游标。拥有者更换、尝试改变或重启后重新建立核对依据。数据库中的页及连续引用始终是权威依据，缓存不授权越过未可靠保存的页。

中央流程直接观察到期动作的启动窗口并处理过期，不等待该设备已有任务结束。设备占用继续决定实际调用资格。报告生成由独立拥有者推进，不阻止下一轮调度；耗时工作结束与真实结果交接继续由原拥有者负责。

## 计时与验证

目录调用、元数据调用、前页核对、结果页保存及分段结果提交分别记录单调钟经过时间。复用目录清单不计作新的 ADB 调用；文件完成等待单独记录并保持原设备契约。

单元测试使用受真实端口约束的替身，覆盖一次列举跨多页、136 个路径中仅 10 个新增文件的筛选、完整与截断目录帧、逐文件元数据错误、清单关闭、增量历史核对、同设备长任务期间的窗口观察，以及报告生成期间的调度推进。

本次软件验证按用户指定只执行单元测试，不运行正在独立重构的集成测试。真实调用耗时、目标工具兼容性和相机行为由用户进行人工验证。
