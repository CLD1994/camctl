# 软件重启恢复的启用与固件核验

## 用户配置与驱动职责

`devices.<id>.software_recovery.enabled` 是是否允许创建自动软件重启恢复责任的部署选择，必须为布尔值，默认 `false`。启用不证明设备固件已通过验证。驱动维护唯一的已验证固件记录来源，记录精确固件指纹、适用原动作类型及结果模式；用户不配置内部指纹。

新责任依据原活动所属动作保存的类型和 `execution_spec_json.video_result_mode` 选择支持记录，不采用后续触发动作或当前设备结果模式代替原事实。当前记录只覆盖 OSMO 360 II 的构建增量 38390、普通录像和 `segmented`。已有验收记录包含该构建普通分段录像的活动重启资格及独立程序恢复；原资格 JSON 在当前工作区不可读取，不能声称已经重新取得其原始资料。完整指纹按本会话明确给定的构建对应关系登记。Action6、照片、原生延时及其他结果模式没有支持记录。

固件指纹读取及编码继续使用驱动现有同源规则。适用记录提供预期指纹，原 `checking` 阶段实际读取设备身份并精确核对；当前读数自身不会创建支持记录。固件不匹配时明确诊断“该固件尚未验证自动重启恢复”，保留实际指纹及原活动未知事实，不派发重启。拍摄范围不匹配时说明该类型或结果模式尚未验证。

## 状态分类与原责任

| 已有冻结责任 | 配置与支持情况 | 处理 |
| --- | --- | --- |
| 无 | `enabled=false` 或省略 | 不创建软件重启恢复责任，继续原资格及残留处理规则。 |
| 无 | 已启用，驱动没有该原动作类型及模式的支持记录 | 给出未验证诊断，不创建重启意图，不扩大普通 STOP 权限。 |
| 无 | 已启用且存在适用记录，实际身份尚未核实 | 保存原检查责任与预期指纹，沿原有次数、期限及排他规则核实。 |
| 无 | 已有适用记录，但实际固件不匹配 | 保存实际身份和失败分类，隔离原责任并诊断，不派发重启。 |
| 有 | 当前配置关闭、调整预算或支持记录变化 | 继续原冻结责任，保留原指纹、预算、期限和原活动，不按新配置重建。 |

稳定事务身份、重启意图先保存、`boot_id` 变化核实、设备排他、有限次数、原输出范围核对及占用释放继续遵守[软件重启恢复合同](../../architecture/camera-recovery.md#无人值守的软件重启恢复)。本变更不改变状态库格式或已有恢复状态正文，也不重写历史。未知指纹的诊断进入现有本地日志通道；内部指纹继续随原身份结果和恢复历史保存。

## 配置迁移与验证

旧用户字段 `verified_fingerprint` 不再接受。加载器给出迁移提示，要求用 `enabled = true` 表达原启用选择；省略或显式 `false` 表达关闭。内部已保存的 `fingerprint` 字段保留原职责。

单元测试使用受真实接口约束的配置、运行时、驱动和数据库替身，覆盖默认关闭、严格布尔值、旧字段提示、装配转发、精确固件及原动作范围、未知固件不重启、实际身份保存、意图前后中断和已有冻结责任不受配置迁移影响。不运行集成测试、真实相机或重启命令；打包、人工配置迁移和安装由统一交付执行。
