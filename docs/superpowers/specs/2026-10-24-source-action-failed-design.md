# 来源失败且无产物的取回错误

## 目标与公共表示

默认取回和预览依赖的拍摄动作已经失败、适用产物处理已经结束，而且完整正式产物目录为空时，来源级错误使用 `source_action_failed`。客户端说明来源动作失败、未生成可取回产物，并通过来源动作身份定位原失败；不将这种情况首先表达为分段范围未确认。

错误码、阶段、详情结构和数据库编号只由[公共错误登记](../../../protocol/errors/workflow-codes.json)定义。该码属于 `obtain_action_outputs.result.failures`，不是拍摄动作的最终错误。失败项和详情的 `source_action_instance_id` 必须相同；不创建 `output_id` 或 `delivery_id`，也不复制来源动作的驱动原始错误或完整详情。取回动作仍以 `obtain_items_failed` 汇总失败，原拍摄的错误保持其真实含义。

## 判定顺序

下表适用于每个已经解析的拍摄来源；组和计划取回分别判定各成员，其他成员继续处理。

| 来源与选择条件 | 处理 |
| --- | --- |
| 来源尚未终态或适用产物处理尚未结束 | 保持等待，不固定最终失败。 |
| 显式指定产物 ID | 保留逐 ID 的不存在、归属、可用性等判定，不以来源失败代替这些结果。 |
| 默认或预览选择，来源为 `failed`，完整正式产物目录为空 | 固定 `source_action_failed`，不创建取回项或交付。 |
| 来源失败，但已经登记正式产物 | 继续依据实际产物、所选角色及分段默认范围处理；来源失败本身不禁止取回。 |
| 来源已过期或取消，且没有正式产物 | 保持对应的无产物或分段范围错误，不将这些状态改称来源失败。 |
| 来源已有正式分段产物，但默认范围为空或未知 | 保持既有分段范围错误，允许显式 ID 取回保留产物。 |

完整目录为空是可靠查询的结果，不等于查询异常、尚未完成或文件暂不可读取。判定不删除产物、不扩大范围、不触发新的拍摄或结果扫描。

## 生产与消费边界

普通正式产物选择和公共分段选择使用同一优先级。首次选择、有限及有界事务、守卫重核和固定历史报告保持一致。来源动作状态和产物事实由实际读取取得，调用方不能只提交一个未经核验的失败标记。

客户端识别新来源级错误，展示来源失败与来源身份。自动预览可以利用同一报告状态中的来源动作说明进一步原因；原始错误仍可查看。默认、手动预览和自动预览共享同一机器契约。

## 开发交付与验证

开发环境按新 SQL 与协议重建状态库，客户端包在新的数据目录初始化；不实现旧状态迁移。相机媒体和已归档诊断继续保留。验证覆盖失败空目录、失败保留产物、显式 ID、过期、取消、组成员混合、固定历史报告与客户端展示。真实相机复测由用户执行。
