# Action6 视频分段产物与异常恢复设计

## 目标与范围

Action6 的视频由一次拍摄生成一份或多份 MP4 原片，各段的实际时长不固定。camctl 将这些原片登记为同一拍摄动作下的独立正式产物，在异常恢复时检查必要分段的实际内容，确定覆盖任务目标的最短连续前缀，并按完整原片交付。

本规格适用于 `camera_record` / `action6_record` 普通录像，以及 `camera_timelapse` / `action6_timelapse` 原生有限延时生成的视频。原生延时同时生成的 RAW/JPEG 继续作为独立照片处理，视频覆盖判定不改变照片的必要格式、数量要求和取回规则。

普通录像的启动、停止、设备占用及取消遵守[相机录像](../../architecture/camera-recording.md)和[异常恢复](../../architecture/camera-recovery.md)。原生延时的有限任务、等待、停止与取消遵守[Action6 原生有限延时任务](../../architecture/camera-capture.md#action6-原生有限延时任务)。本规格定义两类任务的视频集合、异常内容检查、默认范围、检查副本复用及覆盖报告。

任务受理时保存显式的 Action6 分段结果策略及本次生效参数。单份 MP4 是分段集合的合法情况；策略不依据实际文件数、文件后缀或设备配置 ID 临时推断。恢复继续使用原任务冻结的结果策略、目标、采样间隔及控制完成规则。新分段规则只适用于首次受理时显式保存该策略的任务；已经冻结为其他策略、策略缺省或缺少该字段的旧任务，均按其原[执行定义](../../camctl/database/execution-definitions.md)处理，不重新调用当前驱动默认值解释。

## 设备文件与命名契约

视频原片和可选预览的路径为：

```text
/mnt/media_rw/emulated/DCIM/DJI_<目录编号>/DJI_<datetime>_<index>_D.MP4
/mnt/media_rw/emulated/DCIM/DJI_<目录编号>/DJI_<datetime>_<index>_D.LRF
```

例如：

```text
/mnt/media_rw/emulated/DCIM/DJI_001/DJI_20000101080621_0002_D.MP4
```

目录从 `DJI_001` 开始递增；目录内索引从 `0001` 递增到 `0999`，之后进入下一目录并从 `0001` 继续。目录编号使用至少三位的规范十进制形式。分段排序键为 `(目录编号的整数值, index 的整数值)`，`DJI_001/0999` 的后继位置为 `DJI_002/0001`。文件名中的 `datetime` 为十四位数字，保留原值，不用于排序、时长计算或归属判断。

同目录、同完整名称主干的 MP4/LRF 对应同一段。配对沿用[Action6 结果读取与跨页配对](../../architecture/camera-capture.md#跨页配对与可靠前页历史)的原字节身份及后缀比较规则。LRF 不贡献视频时长或帧数，照片不参与视频排序。

分段数量不设精确值或固定上限。普通录像至少需要一份归属可靠、写入完成且非零的 MP4；原生延时继续满足所选 `outputs` 对视频及照片的最低要求。不从目标时长推算必须存在的分段数量，也不从单段数量推导内容覆盖量。

## 文件归属、集合与连续前缀

### 原始观察与正式产物

启动前完整目录基准、本次活动关联、可靠结果页及文件自身事实共同确定归属，遵守[本次任务的文件归属](../../architecture/camera-capture.md#本次任务的文件归属)。递增编号只用于已归属文件的排序和后继判断，不替代完整基准，也不改变受管输出范围的占用规则。

每页实际返回的 MP4、LRF、照片及零字节文件先保存为观察，再判定归属、写入完成和配对。扫描到末页、文件写完、归属已确认、顺序已确认及完整集合已确定分别保存；文件出现或长度稳定不单独证明这些条件。

符合保留条件的原片全部登记，包括默认范围之外的原片。每段原片与对应预览分别拥有独立 `output_id`；预览通过真实原片身份关联。零字节、未完成及归属未知的文件保留观察，不登记为可取回产物。可选 LRF 缺少、为空或未能可靠配对，不单独使合格 MP4 失效。

先前可靠取得的文件不会被后轮失败、未完成或遗漏的扫描抹去。当前集合完整性只由当前可靠扫描及其文件事实证明；保留文件的并集不能冒充一次完整扫描。相关保存、读取与发布复用[分段集合及结果版本](../../camctl/database/segments.md)的共同边界，Action6 的内容指标及范围选择按本规格解释。

### 起点、后继与缺口

原基准及归属可靠时，视频序列起点采用本次已可靠观察并保存的最早视频分段位置。MP4 及其 LRF 的观察均参与起点判断；不能先排除空原片或孤立预览，再把剩余 MP4 的起点向后移动。照片不提供视频起点。已保存的早期观察继续参与判定，文件后来缺失时也不改变起点。

两个本次可靠位置之间缺少后继位置，或某个已知视频位置没有合格原片时，保存相应缺口或不合格事实。缺失位置只记录排序键、区间、前后可靠文件及依据，不补造完整路径、datetime 或正式产物身份。较长缺口按区间保存。

连续前缀从可靠起点开始，按后继位置逐段延伸；缺口、顺序冲突、原片不合格或内容度量未知均使异常内容检查停止向后选择。保留缺口之后的合格原片供显式 ID 取回，默认范围不越过中断位置。

没有可靠起点或顺序依据时，不能构造连续前缀，默认视频范围保持未确认。首段在首次可靠观察前已经消失，且没有任何原片、预览或历史观察留下该位置时，不承诺检测出该缺失；不从基准最大编号或固定 `0001` 补造起点。

## 任务目标与实际内容指标

目标来自原任务冻结的生效参数，实际内容来自所属分段的完整主机副本。主机控制计时、容器时长、主视频时长、播放帧率及采集时长分别保存，不相互代填。分段索引连续也不单独证明段间没有缺帧或重叠，媒体内容与边界质量由实际验收证据说明。

### 普通录像

设目标录像时长为 `T`，按原执行定义的精确目标毫秒表示。第 `i` 段可靠主视频时长为 `d_i`，前 `k` 段的已确认覆盖量为：

```text
C_k = d_1 + d_2 + ... + d_k
达到目标：C_k >= T
```

比较两侧统一单位并保持精度，不先四舍五入到整数秒。使用主视频轨道时长；容器、音频、封面或 LRF 的时长不计入。主视频无法可靠识别或其时长未知时，本段不能贡献猜测值。

### 原生延时视频

设目标采集时长为 `D`，采样间隔为 `I`。采样位置包含起点，并取不超过目标终点的各个间隔位置：

```text
采样位置：0, I, 2I, ... <= D
目标帧数 N = floor(D / I) + 1
```

`D` 与 `I` 使用同一精确单位计算；当 `D` 不是 `I` 的整数倍时，不额外虚构终点的一次采样。第 `i` 段主视频的可靠实际帧数为 `f_i`，前缀达到目标的条件为 `f_1 + ... + f_k >= N`。

已知任务播放帧率为 `F` 时，预期播放时长为 `N / F`；`F` 采用任务生效参数或已经核实的驱动声明，不用本次实测结果反推目标。例如采集 300 秒、间隔 2 秒、30 fps，目标为 151 帧，预期播放时长约 5.033 秒。选段直接比较整数帧数，播放时长用于解释和媒体核对，不参与舍入后的选段判定。

帧数由主机媒体工具从主视频取得。需要帧计数时，对已经完整拷贝的本地文件执行；不能以文件大小、目标帧率或 `时长 × 帧率` 的估计值冒充实测帧数。实际帧率及逐段媒体事实按工具可靠取得的值保留。

以上帧数目标只用于延时视频覆盖。RAW/JPEG 的必需格式和最低数量仍由原任务产物规则决定，不要求照片数量等于 `N`。

## 正常流程与异常检查入口

正常任务使用各自原有的控制完成或有限目标等待与产物核实规则。正常普通录像和正常原生延时默认选择全部合格视频原片；不为确定较短交付范围增加媒体检查或相机到主机的拷贝。没有执行检查时，实际内容量及媒体质量保持未知。

仅来源终态登记前中断，而可靠控制完成、等待及集合事实均已保存的任务，恢复后继续原正常登记，不因发生过进程中断就转入异常媒体检查。

发生提前停止、控制完成依据缺失、异常延迟停止等需要按异常恢复处理的情况时，先完成适用的有限收场、归属和文件完成核实，再进入下述分段检查。即使已有可靠恢复控制完成依据，也要通过实际内容确定异常任务的默认视频前缀。

| 当前情况 | 视频范围与检查行为 |
| --- | --- |
| 已有终态及默认范围 | 保持原结果；取回不重开采集或覆盖评价。 |
| 取消已经生效 | 按两类动作各自的取消规则收场，不为原目标继续检查后续分段。 |
| 正常完成，或只剩正常结果登记 | 默认全部合格视频，不增加内容检查。 |
| 异常恢复，已取得本次文件归属、完成及可靠起点和顺序 | 在正常执行资格下按顺序检查必要分段。 |
| 仍未确认停止、文件写完或归属 | 继续对应有限核实；不能读取仍在写入或归属不明的文件。 |
| 会话时钟异常，只能安全收场 | 保存已取得事实，等待有正常执行资格的会话继续拷贝及检查。 |
| 原基准、扫描、排序或状态记录仍不可靠 | 按所属错误及有限收场规则处理，不猜测完整范围。 |

## 异常分段检查与范围选择

### 逐段处理

1. 可靠保存本次异常检查责任、采用的目标、指标、集合引用及有限处理进度。
2. 从可靠起点读取下一份连续 MP4 的文件身份及完成事实。
3. 将该段完整拷贝到主机工作位置，沿用[文件拷贝](../../architecture/file-copy.md)的可靠读取、落盘、完整长度、摘要核对及断点续传契约。未完成或完整性未确认的副本不进入媒体检查。
4. 使用[受管媒体工具](../../camctl/file-runtime.md)取得主视频时长或帧数，保存可靠事实、工具错误及媒体问题。字节一致和工具正常退出均不单独表示媒体内容没有问题。
5. 将本段的可靠指标加入连续前缀并精确比较目标；首次达到目标时停止为覆盖选择继续拷贝后段。
6. 尚未达到目标时继续下一段；取得最终覆盖结论后，与默认范围及来源结果共同发布。

相机目前没有可供本流程直接使用的媒体元数据接口。索引和 datetime 只承担命名职责；必要的实际时长或帧数均从完整主机副本取得。

媒体探测保留逐流事实，明确选取主视频，排除附加图片及其他流。无法确认主视频、指标缺失或工具执行未得可靠结果时，保存具体未知原因。检查过程遵守有限超时、尝试、取消、子进程收场及空间不足规则；重启沿原责任累计预算，不为每次会话重新开始。空间不足按既有规则快速失败，不等待释放后无限重试。

### 覆盖与默认视频范围决策表

先保存能够确认的连续前缀，再按下表分类。表中的“全部内容”要求本次集合和末尾边界可靠，且没有未解释的缺口；仅检查过的文件已经读完不等于本次全部内容已经查清。

| 取得的事实 | 覆盖结论 | 固定的默认视频范围 |
| --- | --- | --- |
| 正常流程没有执行内容检查 | 未执行检查 | 全部合格视频。 |
| 连续前缀首次达到目标 | 已达到 | 达到目标的最短连续前缀。 |
| 全部内容已可靠检查且累计不足 | 已确认不足 | 已检查的完整连续集合。 |
| 尚未达到目标，下一段拷贝或指标检查有限处理后仍无可靠结果 | 未确认 | 中断位置之前已经检查的连续前缀。 |
| 尚未达到目标，前方存在已确认缺口或不合格原片 | 未确认，并保留明确缺口或媒体失败事实 | 中断位置之前已经检查的连续前缀。 |
| 起点、归属或顺序不足以确定任何可靠前缀 | 未确认 | 范围未确认，不把其他文件临时当作前缀。 |

已检查前缀可以为空。已确定为空的范围、范围未确认和来源没有任何正式产物分别保存。覆盖未确认不使已知前缀的范围也变成未知；反之，存在若干合格文件不自动提供可靠前缀。

选择保持各段完整原始内容，最后一段的超出部分随该段交付。例如目标 60 秒、各段为 18、27、22、40 秒时，默认前三段，共 67 秒；第四段仍保留。若第三段无法取得可靠指标，默认前两段，已确认 45 秒，整体覆盖未确认；不能据此宣称本次总共只录了 45 秒。

原生延时目标 151 帧、各段为 60、60、45 帧时，选择前三段，共 165 帧。未知帧数不填成零，也不跳过该段去累加后段。

范围冻结后，后续取回、清理、媒体补查或相机中新增文件均不改变它。范围外文件不替换已选文件，也不用于事后补足已提交的覆盖量。

## 动作终态与覆盖结论

动作是否成功、检查是否取得可靠指标、默认范围是否确定及具体取回是否成功分别判定。普通录像的控制成功依据沿用[录像成功标准](../../architecture/camera-recording.md#录像成功标准)；原生延时沿用其原任务的有限采集完成、等待与产物要求。原生延时的发送响应不能被改记为设备开始或完成观察。

异常流程可以通过本次归属可靠且已写完的连续主视频内容达到目标，取得相应的时长或帧数成功依据；这不补造历史控制计时或设备状态，也不承诺完成逐帧质量验收。其他必需产物、停止收场及明确失败事实仍须按所属规则判定。

下表适用于尚未生效取消、没有已有终态、记录可靠且必要处理已经结束的情况；明确失败事实优先，包含必需产物缺失、可靠缺口、已确认目标不足及明确媒体错误。

| 覆盖结论及其他依据 | 来源动作结果 |
| --- | --- |
| 存在明确失败事实 | 按对应失败规则结束，保留实际文件和失败原因；后续控制成功不能覆盖该事实。 |
| 正常任务满足自身控制、等待和全部必需产物条件，未执行内容检查 | 成功；媒体覆盖不写成已经检查达标。 |
| 异常内容已经达到目标，其他必要条件满足且没有明确失败 | 成功，保存实际取得的内容成功依据及适用控制依据。 |
| 异常覆盖未确认，但已经具有可靠的控制完成依据，且没有明确失败 | 成功，同时报告覆盖未确认及检查原因。 |
| 异常覆盖未确认，既无可靠控制完成依据，也无内容成功依据 | 失败，保留未知原因和已经确定的默认前缀。 |

尚有适用核实、拷贝、检查或收场未结束时，动作继续原处理阶段，不提前提交成功。停止失败不证明设备已经空闲；动作结束后的设备活动仍按[设备执行情况](../../architecture/report-format.md#动作结束后设备是否仍在执行)报告。

录像失败不直接使取回失败。来源已发布可靠非空前缀时，默认取回按实际选择、读取和发布结果判断；取回成功也不改写来源动作结果。

## 默认取回、照片与预览

Action6 的默认原片选择由两部分组成：按本规格固定的视频范围，以及按原有规则保留和选择的独立照片。视频覆盖选择只约束 MP4 及对应视频预览，不能把照片排除在默认原片取回之外。

| 请求与来源范围 | 选择行为 |
| --- | --- |
| 未指定 `output_ids` 的普通取回 | 选择固定视频范围内的原片，并按原有规则选择该来源的照片；不把范围外视频混入。 |
| 手动或自动视频预览 | 对同一视频范围内的每份 MP4 按实际关联选择对应预览；照片继续以独立原片处理。 |
| 明确 `output_ids` | 精确选择指定的已登记产物，可包含默认范围之外的视频或独立照片。 |
| 已确定为空的视频范围 | 视频选择保存来源级失败，不创建视频 delivery；说明没有可默认交付的连续部分，照片及其他来源继续按自己的选择处理。 |
| 视频范围未确认 | 视频默认选择保存来源级失败，不退回全部视频；照片及其他来源按各自规则继续处理。 |

单份预览缺失、读取失败或不合格按[预览选择](../../architecture/preview-obtaining.md#产物选择与失败)表达，不以原片或其他分段预览冒充该段预览。组、计划及自动预览均逐来源消费同一固定范围。

每份所选产物由本次取回创建独立 delivery 和交付文件，沿用[取回正式产物](../../architecture/obtaining-outputs.md)的逐项失败、发布和恢复规则。同一请求重送继续原身份；新取回创建独立交付。取回不删除相机原片，显式清理也不以默认范围代替请求所指定的完整清理范围。

## 检查副本与等待取回的复用

### 身份与截点

检查副本是来源拍摄后处理持有的主机工作文件，不构成正式产物、普通 delivery 或可以直接领取的交付文件。设备原片仍是正式源；副本复用不把设备正式源改为主机正式源。

来源结果提交时，固定当时已经等待该来源结果的正式取回集合，并保存其与可复用副本的关联。截点采用来源结束的数据库事务，不依赖墙钟时间、报告到达顺序或以后一次查询。来源结果、产物、范围、必要等待状态转换和复用关联须共同可靠提交。

只有已经完整准备、可靠校验、能准确对应所选正式原片的检查副本可以复用。各取回仍须满足自己的选择、读取及清理限制；复用不能绕过产物可用性或显式清理规则。每个取回将副本内容拷贝到自己独立的交付文件，再核对大小、摘要并按普通流程发布。

复用关联只提供同一原片的读取机会，不承诺副本始终可用。副本在实际使用前不能可靠确认为完整有效时，取回按原文件操作规则核实或从同一设备原片读取；仍使用原 `output_id`、已创建的 delivery 及累计预算，不更换产物、不扩大范围，也不重开来源检查。无法从合法读取路径取得完整文件时，按该取回项的实际错误结束。

截点之后新进入等待或新提交的取回，继续按设备正式源读取，即使检查副本尚未清理也不加入原复用集合。视频预览不会因存在 MP4 检查副本而改成交付 MP4；没有相应检查副本的文件沿原正式源读取。

### 保留、清理与恢复

| 副本及关联责任 | 处理 |
| --- | --- |
| 来源检查或结果提交尚未可靠完成 | 保留所需副本、进度和原申请，不提前公开或清理。 |
| 来源已经可靠发布，仍有已绑定取回需要该完整有效副本且尚未结束 | 保留可复用副本，按各取回的独立进度继续，不因第一个取回结束就删除。 |
| 来源已经可靠发布，已绑定取回全部结束，且相关读取、写入和工具进程实际结束 | 自动清理检查副本并保存结果。 |
| 来源已经可靠发布，副本完整有效，但没有已绑定取回需要它，且原处理责任已经结束 | 相关操作结束后清理副本，不为未来请求保留缓存。 |
| 来源已经可靠发布，副本不完整，原检查责任已经结束且没有其他用途 | 相关操作结束后清理部分副本，不再续传已结束的检查。 |
| 取回取消、失败或已经不再选择该文件 | 保存该取回的实际结果并结束相应使用责任；其他已绑定取回仍需要时继续保留。 |
| 文件身份、提交结果或使用责任是否结束仍未知 | 先核实原责任，不依据路径或文件存在性猜测可以删除。 |

断电恢复沿用原副本身份、完整性事实、绑定集合及交付进度。来源提交未知时先核实原完整申请，再决定等待者范围或清理；不能以重启后的等待集合替换原截点。来源提交前，仍有有效检查责任的不完整副本沿原拷贝责任续传，不能拿部分字节交付。来源已经可靠提交后，不再续传已经结束检查责任的部分副本；只为已绑定取回保留可复用的完整有效副本，其余无用文件按本节清理。

清理失败保存后续责任，不改写来源或取回已有终态。相机原片、独立照片、配对预览及正式交付文件不属于检查副本自动清理范围。相关保留与清理遵守[内部中间文件规则](../../architecture/camera-recovery.md#内部中间文件的保留与清理)，本节的已绑定取回是必须计入的后续用途。

## 持久化、发布与历史

### 责任归属

| 所属对象 | 持有的事实 |
| --- | --- |
| 原拍摄动作 | 冻结策略与目标、异常检查决定、有序集合、覆盖评价、固定视频范围、缺口及来源结束依据。 |
| 独立文件及文件操作 | 精确设备身份、完成和完整性事实、主机副本身份、拷贝进度、媒体工具所得事实及实际操作结果。 |
| 来源后处理的复用关联 | 原片与检查副本的准确关系、来源提交截点、已绑定取回及其副本使用责任。 |
| 各取回动作 | 自身产物选择、独立 delivery、交付文件、读取或复用进度、取消、逐项失败与发布结果。 |

同一事实只由其所属对象维护；报告嵌套或复用关系不复制独立文件历史。保存实际使用的目标、指标、已评估分段、连续累计量、首个中断位置及原因，不能只保存一个“完成”标记。

来源发布前可靠保存判断输入及检查事实，在来源结束事务中共同提交全部应保留产物、固定视频范围与产物的准确关联、覆盖结论、动作结果及适用等待与复用责任。不能先公开终态再补范围，也不能让取回看见半套关联。

增长集合、逐段事实、缺口、范围及复用等待者按[公共存储规则](../../camctl/database/common.md#普通列子表与-json-的分工)分页保存和读取，不累积完整集合到执行定义、错误 JSON 或单个内存列表。共同事务按[分批形成事件](../../camctl/database/transactions.md#分配事件编号与核对引用)保持原子可见性，具体物理表、端口及任务拆分由实施计划按生产数据流确定。

### 中断与取消顺序

恢复先核对已有终态、已生效取消及原持久化申请，其余沿已保存责任继续。已确认的 START、STOP、文件等待、指标结果及范围均复用原事实；不重发 START、不重复已确认完成的停止、不重置预算。

普通录像取消遵守[放弃内容规则](../../architecture/camera-recording.md#camera_record-取消)：取消先于终态生效时，终止检查并按原规则处理废弃内容，不登记为正常可取回产物。原生延时取消遵守[保留已完成文件规则](../../architecture/camera-capture.md#取消失败与文件保留)：停止继续追求原采集目标，保留已确认归属且写完的文件，默认选择这些合格视频及原有照片；不因取消造成目标不足再把动作改成失败。

取消后仍须等待已经发出的文件操作和工具进程实际收场，再清理无用副本。已有终态时不改写来源结果；联动预览、取回撤回及已经进入主程序处理的文件继续按各自取消规则处理。

### 同一边界的历史重建

新增记录纳入[历史归属及快照成员](../../camctl/database/history-formats.md#自身记录与快照成员)，登记事件、快照及报告依赖。报告与历史查询从[同一历史边界](../../camctl/historical-state-query.md#分批读取与分段生成报告)恢复拍摄、范围、覆盖、文件、取回及复用关联。

后来取得的摘要、媒体检查、原片清理及新取回不进入旧边界；后续事实不重新选择原前缀。改变读取批次、正反向恢复路径或增加无关历史，均不改变同一报告的入选身份、覆盖量及原字节。历史回放不执行设备读取、媒体工具、交付或清理。

## 报告与客户端

### 整体覆盖结果

`camera_record` 和 `camera_timelapse` 的分段结果均通过 `result.coverage` 表达整体覆盖评价。它与单份产物 `media`、录像媒体 `check`、动作 `status/error` 及取回的 delivery 结果分别维护。参数尚未生效或尚未形成覆盖决定时不补造结果。

覆盖报告至少表达以下业务信息，准确机器字段、类型及枚举只在根 `protocol` 维护：

| 信息 | 必须表达的含义 |
| --- | --- |
| 采用的目标和指标 | 普通录像的精确目标时长，或由原采集时长、间隔推导的目标整数帧数；单位明确。 |
| 覆盖结论 | 未执行检查、已达到、已确认不足、未确认分别表达，不能将未执行或未知记作媒体达标。 |
| 已确认连续内容量 | 实际已经可靠检查的主视频时长或整数帧数；其未知与零分别表达。正常未检查时不填入目标值。 |
| 所评估前缀及默认范围 | 关联实际的分段及正式产物身份，明确视频范围已知非空、已知为空或未确认；照片不冒充视频范围成员。 |
| 判断原因 | 保留检查中断、缺口、指标未知及明确错误的实际原因；能定位相关真实分段，不为缺失位置创造身份。 |

例如动作成功但检查未确认时，报告同时保留 `succeeded`、覆盖未确认和已确认的 45 秒前缀。没有控制成功依据而动作失败时，可以保留相同覆盖事实，并单独报告前缀的成功取回。

原生延时的整体覆盖是对现有拍摄结果报告的扩展，两类动作必须具有一致的覆盖语义。覆盖未确认不能只放进失败动作的 `error.details`，也不能把多个分段累计值填入某个文件的 `media.duration`。单文件实际时长、帧数和帧率只描述该文件；动作覆盖描述有序集合相对于任务目标的结论。

公共协议扩展须同步报告字段说明、JSON Schema、错误登记中适用的详情、安装资源以及客户端导入和展示。结构化覆盖及范围均须通过正式协议，不能只写人类可读文本。具体错误码从公共登记使用，不由各组件各自维护列表。

### 查看、接收与确认

客户端展示来源动作结果、覆盖结论、默认视频范围和每份文件的实际交付结果，范围外保留原片仍可明确选择。设备分段顺序用于覆盖判定；公共报告实体排序、客户端稳定分页及交付命名仍遵守各自契约，不从 `output_id`、报告数组位置或显示名称推导拍摄顺序。

每份原片、照片、预览和 delivery 分别关联。客户端按完整交付文件名、大小及 SHA-256 核验，部分段未到、文件先到、报告后到、重复输入和单段错误均按逐文件事实表达。报告完整应用后的[累计 ACK](../../architecture/status-reports.md#ack)资格与媒体是否全部到达分开判断。

## 协作边界

| 责任 | 输入与交付 |
| --- | --- |
| 设备任务与结果读取 | 固定设备策略和产物要求，提供实际文件、基准、归属、等待与页链事实；不猜测媒体时长。 |
| 拍摄结果处理 | 消费可靠集合及控制事实，编排异常逐段检查、覆盖判定、范围选择及来源发布。 |
| 主机文件与媒体工具 | 提供完整副本、可靠校验、主视频指标和实际工具结果，不决定动作终态。 |
| 持久化与历史 | 保持事实唯一归属、分页、原申请核实、来源共同提交及同边界重建。 |
| 取回与文件交接 | 消费固定范围和复用资格，创建独立 delivery，处理逐项结果及发布，不重新判定来源覆盖。 |
| 公共协议与客户端 | 统一表达并消费整体覆盖、范围、产物和交付，不将接收成功改写为拍摄成功。 |

这些职责复用既有分段及文件基础能力；本规格不要求通过某个固定新类或物理表组织实现。

## 验收要求

### 软件契约

| 范围 | 必须覆盖的行为 |
| --- | --- |
| 命名与排序 | 同目录递增、`DJI_001/0999 → DJI_002/0001`、datetime 不同、跨页、重复冲突键及非法名称；归属始终由基准和活动确定。 |
| 必需产物 | 单份及多份非空 MP4 均有效；空集合、孤立 LRF、零字节、缺少必需照片、归属或完成未知分别保留结果。 |
| 正常流程 | 普通与原生延时均登记全部合格分段并默认全部交付；不因正常登记中断增加内容检查或拷贝。 |
| 旧冻结任务 | 缺少新策略的旧定义恢复后仍按原产物要求处理；原定义要求恰好一个 MP4 时，多份文件不会被当前驱动默认值改判为新分段集合。 |
| 普通异常覆盖 | 不等长分段累计、恰好达到目标、最后整段超出目标、容器与主视频时长不同、精确小数及范围外保留。 |
| 延时异常覆盖 | `floor(D/I)+1` 的整数倍与非整数倍边界、300/2 为 151 帧、分段累计帧数、帧数缺失及实际帧率；照片不按此公式验收数量。 |
| 未确认与不足 | 首段未知形成空前缀，中间拷贝或检查失败形成已知非空前缀，已确认缺口不跨越；可靠完整集合不足与未知尾部严格区分。 |
| 动作结果 | 有控制依据但覆盖未知、无控制依据且覆盖未知、内容足够、全体不足、明确媒体错误及其他必需产物缺失；来源失败和前缀取回成功并存。 |
| 混合产物与预览 | `video_raw`、`video_jpeg` 的照片默认取回保留；视频预览采用同一固定前缀；明确 ID 可取范围外文件。 |
| 副本复用 | 来源提交前已等待、提交后新取回、多个等待取回、一项失败或取消、无等待者及全部相关取回结束；每次交付独立，清理不早于责任结束。 |
| 取消与执行资格 | 普通录像放弃内容、原生延时保留已完成文件、终态优先、时钟异常不启动检查、停止未知不冒充设备空闲。 |
| 恢复与资源 | 拷贝断点、探测结果保存前后、来源 COMMIT 回执未知、等待者绑定、交付和清理中断均沿原身份及预算继续；来源可靠提交后不再续传已结束检查责任的部分副本；集合和等待者增长保持有界处理。 |
| 历史与协议 | 覆盖、范围、缺口、产物及交付从同一边界恢复，后续清理和媒体事实不改旧报告；公共资源、客户端导入及累计 ACK 共同验证。 |

单元测试从上述状态与比较规则独立推导预期；集成测试验证真实协作者和失败恢复。安装版联合链经实际 wheel、C host、CLI、持久化、取回、报告、客户端导入及 ACK，分别覆盖普通录像与原生延时。组件进程及资源隔离遵守各自测试指南；软件替身不提供固件或真机媒体结论。

### 部署与真实设备

设备验收分别记录设备、固件、工具、安装包版本、拍摄参数、控制响应、等待、目录、文件及媒体证据。覆盖正常单段或多段、异常不等长分段、普通录像和原生延时，核对实际默认前缀、范围外原片保留及每份源与副本的长度和 SHA-256。

原生延时保存独立于实测结果推导的目标帧数，核对各段主视频帧数、实际帧率及播放时长。普通录像核对主视频时长，不使用较长音轨或容器时长补足目标。对默认范围与全部保留原片分别保存媒体结论，并检查段间内容及独立播放情况。

新固件不定长分段及目录递增规则作为本规格的设备运行契约；既有单原片的路径或媒体样本不能替代新固件分段验证。软件、ARM 部署、相机控制、媒体内容、客户端接收及 ACK 各自保留证据。设备操作和故障场景按独立的验收安排执行。
