# Action6 视频结果模式与分段特化设计

## 目标与范围

Action6 同时提供单文件与多段视频结果处理。部署选择及公共分段能力由[视频结果模式与公共分段处理设计](2026-10-23-video-result-modes-and-segmentation-design.md)定义，本规格只维护 Action6 的视频文件、目标解释和设备特化。

适用任务为 `camera_record` / `action6_record` 普通录像，以及 `camera_timelapse` / `action6_timelapse` 原生有限延时。RAW/JPEG 作为独立照片，继续原有产物与取回规则。

普通录像的启动、停止与完成遵守[相机录像](../../architecture/camera-recording.md)；原生延时遵守[Action6 原生有限延时任务](../../architecture/camera-capture.md#action6-原生有限延时任务)。本规格不改变设备命令的含义、启动余量、停止后文件等待或原有限目标等待。

## 部署模式与单文件流程

Action6 消费公共部署项 `devices.<id>.video.result_mode`，默认 `single_file`，显式选择 `segmented` 后为两类视频任务绑定本规格的分段特化。模式与特化在首次受理时固定，部署配置不进入拍摄参数。

| 模式及动作 | 结果合同 |
| --- | --- |
| `single_file` 普通录像 | 一份非空 MP4 为必要视频原片；正常流程及异常单原片检查、适用多录修复和派生成品继续原有规则。多份必要视频按该模式的数量错误处理。 |
| `single_file` 原生延时 | 采用原有限任务、等待及所选 `outputs` 的最低产物要求，实际文件按原结果流程登记；不进行视频序列的覆盖和前缀选择。 |
| `segmented` 普通录像 | 至少一份合格 MP4，按有序视频集合登记；正常默认全部，异常采用公共实际内容检查。 |
| `segmented` 原生延时 | 视频按有序集合处理，异常按主视频实际帧数选择前缀；照片保持原格式及最低数量规则。 |

Action6 的分段能力使用公共实际内容检查策略。设备特化只提供名称、主视频识别、目标及必要产物规则；逐段拷贝、覆盖判定、范围发布和检查副本复用由公共层完成。

## 文件与命名契约

视频原片和可选视频预览为：

```text
/mnt/media_rw/emulated/DCIM/DJI_<目录编号>/DJI_<datetime>_<index>_D.MP4
/mnt/media_rw/emulated/DCIM/DJI_<目录编号>/DJI_<datetime>_<index>_D.LRF
```

例如：

```text
/mnt/media_rw/emulated/DCIM/DJI_001/DJI_20000101080621_0002_D.MP4
```

目录从 `DJI_001` 开始递增，使用至少三位的规范十进制编号。目录内索引从 `0001` 到 `0999`，随后进入下一目录并从 `0001` 继续；`DJI_001/0999` 的后继为 `DJI_002/0001`。分段排序键为目录号和索引的整数值。

`datetime` 为十四位数字，只保留原文件名，不参与排序、归属或计时。文件归属继续使用原完整基准和本次活动，不因索引单调递增而改用编号猜测归属。

唯一同目录、同完整名称主干的 LRF 与对应 MP4 配对。配对使用[现有原字节及跨页规则](../../architecture/camera-capture.md#跨页配对与可靠前页历史)，缺少或不合格的可选预览不使合格原片失效。照片不参与视频序列，也不提供视频起点。

## 必要产物与空文件

普通录像的必要原片为非零 MP4。分段模式允许一份或多份，不规定精确数量或固定上限；各段时长不固定，文件数量不能推算实际覆盖。

原生延时的 `outputs`、必需格式及最低数量由[原生有限延时产物合同](../../architecture/camera-capture.md#action6-原生有限延时任务)维护。两种视频模式使用与驱动结果读取共用的同一格式映射，不另外维护一套要求。其他已确认归属且写完的照片继续保留；DNG、JPEG 和视频不能相互替代所需格式。

零字节原片不合格，保存实际观察和位置，不登记为可取回产物。视频起点、缺口及连续范围按[公共观察规则](2026-10-23-video-result-modes-and-segmentation-design.md#观察有序集合与产物)判定；可选 LRF 不贡献实际时长或帧数。

## 分段目标与主视频度量

### 普通录像

目标为原任务冻结的精确录像时长。每段度量为 MP4 中唯一主视频的可靠时长，排除附加图片、音频和预览；容器时长不代替主视频时长。存在未能解释的多个主视频或缺少所需指标时保持未知。

### 原生延时

采样位置为 `0, I, 2I, ... <= D`，包含起点及不超过目标终点的间隔位置。`D` 为采集时长，`I` 为采样间隔，目标帧数为 `floor(D/I)+1`；非整数倍时不增加一个不在采样位置上的终点帧。

例如采集 300 秒、间隔 2 秒，目标为 151 帧。任务已知播放帧率为 30 fps 时，预期播放时长约 5.033 秒。播放帧率采用生效参数或已核实的驱动声明，不能从实测结果反推目标。

实际度量为各段 MP4 主视频的可靠整数帧数，选段直接累计帧数。需要计数时使用完整本地副本；不以播放时长乘帧率估算实测帧数。照片数量仍按上节的产物要求，不要求等于视频目标帧数。

## 正常、异常与动作结果

分段模式的正常普通录像和正常原生延时，均登记全部合格视频并默认全部交付，不额外拷贝或检查媒体。正常完成事实已经可靠保存、仅终态登记尚未完成时，恢复继续原正常登记。

异常恢复完成必要的停止、归属及文件完成核实后，调用[公共实际内容检查](2026-10-23-video-result-modes-and-segmentation-design.md#公共实际内容检查)。普通录像按主视频时长，原生延时按主视频帧数，选择达到目标的最短连续前缀，最后一段完整交付。

例如目标 60 秒，实际各段为 18、27、22、40 秒时，默认前三段，共 67 秒。若第三段无法可靠检查，固定前两段，已确认 45 秒，整体覆盖未确认。延时目标 151 帧、各段为 60、60、45 帧时，选择前三段，共 165 帧。

范围外合格原片继续保留，默认范围跨重启和后续取回固定。未知指标不跳过、不补零；全部内容可靠检查且不足才确认不足。

动作终态按公共规则结合本设备完成合同判定：可靠控制完成或足够的实际内容可以提供成功依据；覆盖未知但已有可靠控制完成时可成功，无成功依据时失败；明确设备或媒体失败优先。原生延时的 `SENT` 仍只表示发送确认，完成依据须包含本任务适用的有限等待与产物核实。

普通录像取消放弃内容；原生延时取消沿自己的停止或有限自然结束责任保留已完成文件，动作保持取消。控制和文件等待仍使用 Action6 各自原有的普通录像与原生延时合同。

## 取回、复用与报告

默认视频及对应预览消费同一固定范围，RAW/JPEG 按原有规则一并选择。来源失败与取回结果分别表达，已发布前缀可成功取回；明确 ID 可以选择范围外产物。

检查副本、来源提交时已等待的正式取回、独立 delivery 及副本清理统一遵守[公共副本复用](2026-10-23-video-result-modes-and-segmentation-design.md#检查副本与等待取回的复用)。本设备特化不另建缓存或清理流程。

实际内容策略通过[整体覆盖结果](2026-10-23-video-result-modes-and-segmentation-design.md#整体覆盖结果)报告目标、已检查连续量、结论及范围；普通录像和原生延时使用相同业务语义。未检查的正常任务不报告实测达标。

## 验收要求

- 两种模式分别覆盖普通录像和原生延时；单文件普通录像验证恰好一份 MP4、多份数量错误和原单原片异常处理，原生延时验证原有格式及最低数量合同。
- 分段模式验证单段、多段、不等长、跨目录、跨页预览及独立照片；正常流程的拷贝和媒体检查为零。
- 普通异常验证主视频与容器时长不同、精确阈值和整段超出；延时验证 `300/2 -> 151`、非整数倍采样及可靠帧数。
- 验证空前缀、未知指标、明确缺口、完整内容不足，以及可靠控制完成但覆盖未知时的动作与取回结果。
- 公共副本、取消、范围固定及历史重建按公共验收执行；真实设备另记录固件、控制、目录、完整源与副本校验、各段实际媒体及客户端接收证据。
