# OSMO 360 II 视频结果模式与分段特化设计

## 目标与范围

OSMO 360 II 同时提供单文件和多段视频结果处理。部署选择、公共分段集合、取回、副本及历史边界由[视频结果模式与公共分段处理设计](2026-10-23-video-result-modes-and-segmentation-design.md)定义；本规格维护 OSMO 的文件、分段时长下界、空尾、完成及范围特化。

适用普通录像 `camera_record` / `osmo360ii_record` 及原生延时视频。控制、启动语义、停止、自然目标等待和取消继续遵守[拍摄完成设计](2026-10-18-osmo360ii-capture-completion-design.md)与[启动余量设计](2026-10-18-camera-startup-margin-design.md)。独立单张拍照不属于本规格范围。

`devices.<id>.video.result_mode` 默认 `single_file`，显式选择 `segmented` 后由驱动为普通录像和原生延时绑定各自分段特化。单文件普通录像采用一份非空 OSV 原片合同及独立的单原片异常处理；单文件原生延时继续有限目标、原产物规则及结果处理。多段模式使用下文合同。

两种模式均在受理时明确保存，不按设备型号、文件数量或后缀自动切换。模式配置及公共层重构的规则只在公共规格维护。

既有 OSMO 软件交付与设备证据由[分段执行计划](../plans/2026-10-21-osmo360ii-record-segmentation.md)及[组件验证记录](../../camctl/verification.md)保留。公共模式和分段层的重构完成度不由这些既有记录代替。

## 设备分段与命名契约

普通录像以完整非尾段的 **4.5 秒**可靠下界支撑运行时判定。**4.5～5.5 秒**是段长的参考范围，5.5 秒不是硬性验收上限；超过参考范围时保留逐路实际时长及偏离事实，不仅因段长偏长判定失败。较长分段不改变下界和默认选段数，也不能覆盖缺段、文件不完整、解码失败或整体内容不足等独立问题。不足预期段长的尾段按实际内容计，零字节尾段不贡献内容。分段模式运行时不为测量时长增加主机拷贝；实际媒体时长由实机验收独立核对。

离线验收按下表核对分段时长，整体覆盖仍按[整体时长短缺规则](#时长短缺容限与验收时机)独立判断，不以单段观测改写原业务终态。

| 时长事实 | 对分段下界的判断 |
| --- | --- |
| 完整非尾段的可靠实测时长至少为 4.5 秒 | 满足该段的下界；超过参考范围只保留偏离记录。 |
| 完整非尾段的可靠实测时长短于 4.5 秒 | 该段不满足部署下界假设，保存差值并核对设备合同适用性，不能以该段声称至少 4.5 秒内容。 |
| 最后非零尾段或零字节尾段 | 不计入完整非尾段数量，按原尾段规则处理。 |
| 单段可靠时长未知 | 保持实测未知，不以参考范围或整体累计值补造该段时长。 |

该约定属于本设备部署的驱动运行合同，更换设备、固件或工具后按[设备运行假设](2026-10-18-osmo360ii-capture-completion-design.md#设备证据与完成方式)核对适用性。

```text
/mnt/media_rw/emulated/DCIM/CAM_<目录编号>/CAM_<datetime>_<index>_D.OSV
/mnt/media_rw/emulated/DCIM/CAM_<目录编号>/CAM_<datetime>_<index>_D.LRF
```

目录从 `CAM_001` 开始递增；每个目录内索引从 `0001` 到 `0999`，随后进入下一目录并从 `0001` 继续。排序键为目录号和索引的整数值，`CAM_001/0999` 的后继为 `CAM_002/0001`。十四位 datetime 保留原值，不用于排序、归属和计时。

同目录、同完整名称主干的 OSV/LRF 对应同一段，按[名称配对规则](2026-10-18-osmo360ii-capture-completion-design.md#产物与预览)识别。名称无法解析、同键冲突或目录关系无法解释时保留顺序未知。

## 分段与必要原片规则

必要视频为本次可靠归属、写入完成且非零的 OSV，至少一份，不设置精确数量或固定上限。LRF 是可选预览，不增加段数、时长或原片数量。空文件先按本设备规则分类并保留观察。

预期段长不构成每份文件必须达到的阈值，不据此推算必须生成的数量。完成下界和默认选段数用途不同，均不填作实际媒体时长。源文件完整性和媒体内容仍按公共规则分别核对。

## 文件归属、有序集合与缺口

本设备提供上述名称、排序与后继规则，其余归属、分页、有序集合及缺口表示遵守[公共观察与集合](2026-10-23-video-result-modes-and-segmentation-design.md#观察有序集合与产物)。OSV、LRF 及空文件的实际页观察均须保留。

### 结果观察与保留依据

跨轮可靠文件保留与当前完整扫描分别判断，不能用前轮文件补造最后一轮完整性。原片与 LRF 在完整名称主干下配对，孤立预览不成为视频原片。

### 本次起点与第一版识别边界

起点使用[公共起点规则](2026-10-23-video-result-modes-and-segmentation-design.md#起点连续性与缺口)，OSV、LRF 和空文件位置都参与观察。没有可靠记录的位置不补造首段；已观察文件后来消失时，不把起点后移。

### 缺口记录

相邻可靠 OSV 之间缺少后继位置，或非尾部只有零字节 OSV 时，记录缺口。缺失位置、空文件和已登记原片分别表达；长缺口使用区间。零字节 LRF 只影响可选预览，不单独中断合格 OSV 前缀。

## 零字节尾段与整体媒体验收

完整集合、顺序、停止或自然完成及文件等待可靠后，位于序列末尾的零字节 OSV、LRF 或两者单独保存异常事实，不登记为可取回产物，也不单独构成整次失败。非尾部零字节 OSV 作为缺口；尾部分类尚未知时继续有限核实，不按已确认空尾排除。

最后一份非零 OSV 仍是可能较短的尾段，其后的空文件不使它成为完整非尾段。空尾不增加有效内容，只有空文件或孤立 LRF 仍不满足必要非零原片要求。

媒体验收按非零 OSV 的两路主视频分别核对整体有效时长，不把两路相加，也不重复计入 LRF。容器、音频、实际帧覆盖和解码事实分别保存，索引连续或时长汇总不保证段间无缺帧或重叠。

## 原生延时的采样数量验收

OSMO 原生延时以采样帧数作为离线数量验收依据，允许首尾采样口径差异和少量帧数短缺。基准来自原任务的可靠采集目标与采样间隔，不要求先核实唯一采样端点或播放帧率，也不从本次实测帧数反推预期。其他相机仍按各自采样合同处理。

设目标和间隔统一为正整数毫秒 `T_ms`、`I_ms`，参考帧数范围为 `ceil(T_ms/I_ms)` 至 `floor(T_ms/I_ms)+1`；前者记为 `B`。该范围表达两种端点口径的参考数量，不宣称固件实际采用其中哪一种，也不作为实际帧数的硬性上限。整体帧数短缺容差默认 **3 帧**，可配置为非负整数，记为 `E`；每路最低合格数量为 `max(1, B-E)`。配置为零时仍允许两种端点口径的差异；较大容差最多把数量下限降至一帧，不允许零帧视频据此通过。

例如目标 300 秒、间隔 2 秒时，参考范围为 150～151 帧，默认最低数量为 147 帧。150 帧、151 帧及更多帧均可满足数量条件；帧数偏多保留实测与偏离事实，不单独判失败。容差只用于数量评估，不修改设备采集目标、间隔、自然等待或运行时完成依据，也不把少量帧数短缺换算为已确认的实际采集时长。

全部保留范围和默认交付范围分别核验，每个范围的两路主视频各自累计全部所选原片的可靠帧数，分别应用一次上述容差。LRF、封面图、空尾及范围外原片不参与该范围计数，不能在段间重复增加容差，或用另一路视频补足。来源文件与副本身份未确认时，保留本地计数，源采样数量保持未知；已知身份不一致仍按文件一致性错误处理。身份已匹配的源文件范围按下表判断，可靠不足优先于其他维度的未知。

| 当前范围的数量事实 | 数量验收结果 |
| --- | --- |
| 范围可靠完整、两路全部所需计数均可靠，且各自累计不少于最低合格数量 | 数量达标，保留实际帧数及偏离；文件一致性、解码和段间连续性仍分别判定。 |
| 范围可靠完整，且任一路全部所需计数均可靠、累计少于最低合格数量 | 该路数量不足；另一路或范围外内容不能补足，其他未知维度仍保留。 |
| 范围不完整或所需成员的可靠帧数未知 | 数量保持未知，不以已知子集或零值代替。 |

实际播放帧率和播放时长如实记录。能够取得独立的预期帧率及端点依据时，仍可推导并单独比较预期播放时长；缺少这些依据时，预期播放时长保持未知，不阻止已有独立依据的帧数数量判断。不得把数量达标写成端点已核实、时间比较通过或段间无缺帧、无重叠。

## 时长短缺容限与验收时机

分段模式运行时依据可靠控制或下文分段完成依据，不执行成片时长检查或处理输入拷贝。媒体状态保持未检查、实际时长未知；分段下界不填入实测覆盖。

实机媒体验收的整体时长短缺容限默认 **100 毫秒**，允许非负整数毫秒，零表示不允许短缺。采用预期播放时长 `T`、可靠整体时长 `D`、本次容限 `E`，统一单位后按 `max(0, T-D) <= E` 判断。两路主视频各自比较且均满足才时长达标，不按分段重复增加容限，也不先舍入到边界。

下表只表达时长比较。原生延时的数量判断按[采样数量验收](#原生延时的采样数量验收)独立表达，帧数容差与毫秒容限不互相替代。

| 时长事实 | 验收结果 |
| --- | --- |
| 预期、测量依据或实际时长未知 | 无法核实，不冒充达标。 |
| 两路整体短缺均不超过容限 | 时长达标，空尾诊断及其他媒体问题继续保留。 |
| 任一路整体短缺超过容限 | 时长未达标，保存实际值及短缺；合格原片仍可取回。 |

例如预期 10 秒、容限 100 毫秒时，9.900 秒恰好达标，9.899 秒未达标。容限采用值进入本次验收记录，调整不改写旧验收或动作终态，不改变运行时目标、停止、下界和选段数。工具配置及操作入口由[媒体验收说明](../../hardware/osmo360ii-segment-media-validation.md)维护。

## 完成、归属与结果判定

分段模式的普通录像使用本设备的控制或分段下界成功依据。原生延时继续自身有限目标与必要产物合同，并应用本设备空尾分类；普通录像下界和选段公式不用于原生延时采集目标。

### 普通控制完成与分段完成依据

普通控制完成沿原 START 语义、可靠计时、STOP 和文件等待规则取得。跨运行计时遵守[可信计时及连续性](../../architecture/camera-recovery.md#断电恢复后的控制完成依据)，不拼接不同会话的单调钟。

停止、写入完成、完整扫描、归属、顺序及从起点开始的连续性均可靠且无明确错误时，设原执行定义的目标为 `T`，其精确毫秒数为 `T_ms = target_duration_ms`，完整非尾段数为 `K`。分段完成下界为 `L = K × 4.5 秒`，以精确整数比较 `4500 × K >= T_ms` 取得独立成功依据；不使用浮点近似或受固定整数上限影响的运算改变结论。

最后非零 OSV 不计入 `K`，空尾也不计入。目标 12 秒时，三份完整非尾段保证至少 13.5 秒；两份完整非尾段与一份未知短尾只能提供 9 秒下界。保存计入的文件、`K`、`L` 和比较条件，不把它们写成媒体实测值。

下界不足不证明实际内容不足；可靠控制完成仍可独立提供成功依据。两种依据均不足时按有限核实与无法确认规则结束。

### 结果决策表

取消、已有终态及持久化错误先按公共规则处理，其余普通录像按下表优先级判断。

| 事实 | 结果 |
| --- | --- |
| 停止或必要文件等待尚未可靠完成 | 继续原控制和有限收场，文件数量不替代停止依据。 |
| 归属、完整扫描、写入完成或顺序仍未知 | 保存未知，继续适用核实，不按空集合或成功解释。 |
| 可靠确认没有非零 OSV | 必要原片缺失，失败。 |
| 可靠确认缺段、非尾零 OSV 或其他明确失败 | 失败，保存缺口前范围并登记其他符合保留条件的文件。 |
| 零字节 OSV 尾部分类未知 | 继续有限核实，不直接豁免。 |
| 其他必要条件满足、无明确失败，控制完成或 `L >= T` | 成功；空尾诊断与实际媒体未知分别保留。 |
| 有限处理结束且仍无成功依据 | 结果未确认失败，保留实际原片和默认范围。 |

## 默认交付范围

### 异常多录与保守选段

正常默认全部合格非零 OSV。异常时，可信控制证明录制严格超过原目标，或满足分段完成前提的 `L > T` 时，确认多录；不能从重启、重连或文件数量本身推断多录。

确认多录后，默认选段数 `N = ceil(T / 4.5 秒)`。按精确目标毫秒计算为 `N = (T_ms - 1) // 4500 + 1`，以整数运算保持边界；不枚举尚未生成的段，不把 `N` 当作必要文件数。

从可靠起点选前 `min(N, 已有合格原片数)` 个连续原片，最后一段整段交付，短尾保持原内容，空尾不入选。目标 9 秒时 `N=2`，目标 10 秒或 12 秒时 `N=3`；目标 12 秒有六份合格原片时，其余三份仍保留供明确 ID 取回。

### 缺口前的连续范围

| 事实 | 默认视频范围 |
| --- | --- |
| 集合、起点和顺序可靠，无缺口，多录未确认 | 全部合格非零 OSV，不要求来源动作成功。 |
| 已确认多录，其他前提可靠，无缺口 | 受 `N` 限制的连续前缀。 |
| 首个缺口之前有可靠连续部分 | 选择该部分；确认多录时同时受 `N` 限制。 |
| 已观察首段可靠缺失，前缀为空 | 固定空范围，其他保留原片仍可明确取回。 |
| 起点、顺序或边界不足以确定范围 | 范围未确认，不改取全部原片。 |

范围的取回、跨重启固定及范围外保留按公共合同执行。该策略不为选择范围获取实际媒体时长，也不产生派生成品。

## 原片与预览登记

本设备为合格非零 OSV 登记独立原片，为可靠同主干 LRF 登记独立预览，实际原片身份用于预览关联。空尾、其他不合格文件及孤立 LRF 保留观察，不制造原片。文件、产物和 delivery 继续使用公共身份规则。

## 取回与报告

默认、预览、明确 ID 及组／计划选择遵守[公共取回规则](2026-10-23-video-result-modes-and-segmentation-design.md#动作结果与默认取回)。缺口前缀可以在来源失败时独立交付，空范围与未确认范围分别失败，不扩大范围补位。

OSMO 分段缺口报告保存实际 CAM 排序键、可靠邻接文件、默认范围及保留原片身份。缺口完整详情从同一历史边界分页展开，不能只提供人类文本；公共机器字段由根 `protocol` 维护。

运行时分段下界是内部完成依据，不填进 `result.coverage` 的实测量或单文件 `media.duration`。单文件模式适用的媒体检查和修复结果继续按原合同报告。

### 客户端查看、导入与确认

按[公共报告与客户端](2026-10-23-video-result-modes-and-segmentation-design.md#报告与客户端)逐文件关联及核验。OSV 内联播放依赖浏览器实际解码能力；已经保存且核验通过的原文件继续可下载。双路主视频不改变一份 OSV 的原片身份，LRF 独立交付。

## 持久化与恢复

公共层维护集合、范围、原申请核实、来源共同提交及等待转换；本设备特化额外保存实际采用的分段约定、计入下界的文件及 `K/L`、多录结论、`N`、空尾分类和缺口依据。小型判断与增长成员分别保存。

### 核实结束与终态提交

有限核实结束需要原尝试、预算及完成或失败的实际依据。流程关闭标记不替代判断。完成与取消继续同一来源发布边界；普通录像取消放弃，原生延时取消按其合同保留完成文件。

### 有界处理与历史重建

共同提交、分页及同边界恢复按[公共持久化合同](2026-10-23-video-result-modes-and-segmentation-design.md#持久化共同提交与恢复)，内部字段由[分段存储专题](../../camctl/database/segments.md)维护。报告不以新的文件或检查重算旧下界和旧范围。

## 验收要求

### 软件契约与联合链

公共模式及分段验收之外，本设备须覆盖：

- 两种模式的普通录像及原生延时分派；单文件普通录像为一份 OSV，分段允许一份或多份。
- `CAM_001/0999 → CAM_002/0001`、完整主干配对、跨页及不同 datetime。
- 下界小于、等于和大于目标；最后非零 OSV 不计入 `K`，空尾不使短尾成为非尾段。
- `9000 -> N=2`、`10000 -> N=3`、`12000 -> N=3`，以及已确认多录、缺口前缀、空范围和未知范围。
- 普通与原生延时的空尾、非尾零 OSV、孤立 LRF、全部为空及当前集合未完整分别分类。
- 分段策略运行时无媒体拷贝，实际时长保持未知；单文件策略的单原片检查和修复仍可运行。
- 双路主视频验收容限内、等于边界、越界、零容限及测量未知；容限按整次任务计算。

安装版链分别核对真实 wheel、C host、CLI、来源登记、逐段交付、客户端导入及累计 ACK；已有软件证据按其实际版本和范围引用。

### ARM 与实机媒体

部署明确记录模式和安装版本，正常普通录像覆盖自动和手动曝光，逐份核对唯一控制、等待、完整扫描、原片与预览及交付关系。单文件和分段模式分别取得自己目标固件的证据。

分段异常多录按专项安排核对下界、默认范围、范围外保留及重启不变。默认范围与全部保留原片分别核对媒体，不借范围外文件补足默认覆盖。源和副本逐份核对长度与 SHA-256，双路主视频、实际音频、完整解码和诊断分别归档。

空尾及参考帧诊断按真实观察记录；软件业务通过不代替媒体内容通过。物理断电及构造故障按独立设备安排执行。
