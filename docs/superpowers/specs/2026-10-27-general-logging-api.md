# 通用日志调用接口

通用入口与[阶段及命令日志](2026-10-26-operational-logging.md)共用上下文、JSON 格式、错误诊断及现有日志通道。调用立即提交，返回一份可选等待的写入回执；不等待回执，日志也由原通道继续处理。接口不为每条记录创建 Task，也不创建新的文件消费者。

## 调用与完成

`camctl.logging_runtime` 导出 `get_logger(name)` 和 `get_sync_logger(name)`。Logger 只持名称，创建时不绑定命令或通道，模块级对象可由并发任务复用。

```python
logger = get_logger(__name__)
logger.info("准备设备 %s", device_id)
receipt = logger.error("操作失败", exc_info=error)
do_something()
result = await receipt
```

| 调用 | 处理 |
| --- | --- |
| `logger.debug/info/warning(message, *args, ...)` | 调用时冻结并按相应级别提交，立即返回回执；配置过滤、采样及丢弃保持现有规则。 |
| `logger.error/critical(message, *args, ...)` | 调用时冻结并登记重要日志，不能因写入队列满而阻塞当前业务或丢失原责任；CRITICAL 使用 ERROR 接纳优先级并保留输出严重程度。 |
| `logger.exception(message, *args, ...)` | 默认捕获当前异常，以 ERROR 提交完整异常图；没有当前异常时不伪造异常。 |
| `logger.log(level, message, *args, ...)` | 接受现有 `LogLevel` 及标准 DEBUG、INFO、WARNING、ERROR、CRITICAL 数值；其他级别显式拒绝。 |
| `await logger.info/error/...(...)` 或 `await receipt` | 调用仍先提交，再等待该条实际追加并 flush 的回执；不是仅等待入队，也不要求每条 fsync。 |
| 同步 Logger 的 `debug/info/warning/log` | 低于 ERROR 时采用同一立即提交和回执方式；同步重要级别仍明确拒绝，工作线程经原结果通道交付错误。 |

回执不是协程对象。忽略它不产生未 await 警告；重复等待不会重复提交。取消某个等待者不撤回日志，也不取消其他等待者共享的写入事实。写入、过滤、丢弃、通道故障及 stderr 降级分别给出明确结果；失败或未写入不得被表示成文件追加成功。普通日志故障继续不覆盖业务结果，显式等待返回实际结果供调用方判断。stderr 通道的完成点为 stderr 写入及 flush，不代表已有持久文件。

消息、`extra`、`exc_info`、`stack_info`、`stacklevel` 及重要日志可选的 `state` 保持标准消息参数和原身份语义。字段、UTC、PID、异常及业务源位置在调用时冻结，不因之后等待改变。输出包含 `logger`、`message`、`pathname`、`lineno`、`function` 和公共 JSON 字段，继承当前上下文及阶段；系统元数据不能由 extra 冒充。非法参数明确报错，普通格式化故障保留可取得的原事实。已知工具媒体 stdout 只保留字节数量，stderr 经共同诊断快照无损编码并保留可读文本。

## 顺序、满载与关闭

同一通道内，提交顺序以取得通道接纳锁的顺序为准；同一线程连续调用自然保持先后，多线程不以墙钟调用开始时间推断顺序。被过滤、采样或丢弃的记录不承诺写出；留下的记录不能越过较早已登记的重要日志。

实际写入队列继续有界。自身 ERROR 队列满时，由通道暂存原记录并按先后补入写入队列；消费者取得一个位置时先处理较早待投递责任，不能让后来的低级日志或另一条 ERROR 抢先。所有自身重要日志的底层入口共用该提交顺序；第三方同步 ERROR 的满载 stderr 规则保持原义。待投递重要日志的总内存不保证固定上限，当前[第一版故障范围](../../architecture/README.md#第一版完善与验收范围)不增加持续压力自适应机制。

通道禁用须结算未写出的回执并承担一次适用 stderr 交付，不能把尚未入队项标成已入队。正在实际写入的记录以 writer 返回的追加及 flush 事实结算；通道在写入途中禁用不能提前把它判成未写入。停止新增提交后，原待投递项仍须推进，正常退出在全部已持有记录写完或按故障结算后关闭消费者。必要设备停止和原业务结果交付不等待文件写入。

没有命令日志上下文的低级别调用不创建通道。重要日志沿当前诊断目标或已绑定通道交付；没有通道时沿原 stderr 降级规则处理，不为调用凭空新建消费者。

## 原错误与副本责任

带异常的重要日志复用原异常的 `DiagnosticState`；同一原结果的后续调用复用首次记录与同一写入回执，不改写原事实、不重投。独立文本 ERROR 每次调用生成独立记录。`ADMITTED` 仍只表示原状态已接纳，不能据此宣称已经 flush；原拥有者必须保存同一条实际写入事实。

副本预留或实际副本任务持有原记录时，通用调用只能绑定、等待原写入回执，不能抢回或重新投递。副本实际追加成功后，即使后续复制失败，该条普通日志仍具有真实追加事实；抑制、未开始及未写入分支继续按既有规则交回原诊断。低层 `alog` 的接纳完成和特殊交付接口保持各自已定义的事实边界，通用回执的实际写入完成单独表达。

## 验证

覆盖不 await 也提交、混合级别连续调用顺序、无协程警告、可选 await 确认追加与 flush、过滤及失败结果、取消等待不撤回、多个等待者、队列满载时较早 ERROR 不被超过、通道禁用与正在写入项竞争、正常退出排空，以及原异常去重和副本预留／抑制／复制失败的真实组合。源位置、上下文隔离及媒体边界保留原覆盖。
