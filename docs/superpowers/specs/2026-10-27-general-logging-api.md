# 通用日志调用接口

通用入口用于业务消息、警告及明确交接的错误诊断，与[阶段及命令日志](2026-10-26-operational-logging.md)共用上下文、JSON 外层和现有日志通道。[全局错误诊断责任](../../architecture/logging.md#全局错误诊断责任)、队列接纳、必要停止、取消及有序关闭规则保持原契约。接口不创建文件处理器、额外队列、逐条后台任务或全局去重集合。

## 调用方式

`camctl.logging_runtime` 导出 `get_logger(name)` 和 `get_sync_logger(name)`。Logger 只持有名称，不绑定创建时的命令、通道或动作；模块级对象可由并发命令和任务复用，调用时取得当前上下文。

| 接口 | 处理 |
| --- | --- |
| `await logger.debug/info/warning(message, *args, ...)` | 使用相应级别，立即完成接纳判断，不等待队列空位。 |
| `await logger.error(message, *args, ...)` | 由当前协程交接 ERROR，接纳前的取消按已有重要日志规则处理。 |
| `await logger.critical(message, *args, ...)` | 采用 ERROR 的接纳策略，输出保留 `CRITICAL` 严重程度。 |
| `await logger.exception(message, *args, ...)` | 默认捕获当前异常，以 ERROR 交接完整异常图。没有当前异常时仅记录消息，不伪造异常。 |
| `await logger.log(level, message, *args, ...)` | 接受现有 `LogLevel` 及标准日志的 DEBUG、INFO、WARNING、ERROR、CRITICAL 数值。其他级别显式拒绝。 |
| 同步 Logger 的 `debug/info/warning/log` | 低于 ERROR 时同步接纳、不等待空位。ERROR 及以上明确拒绝，工作线程仍通过原结果通道交付错误。 |

常用参数为 `extra`、`exc_info`、`stack_info`、`stacklevel`，重要日志还可显式提供原 `state`。低级别或同步调用不接受诊断状态。消息格式化复用标准日志的 `%` 参数语义；`exc_info` 接受布尔值、异常对象或标准异常三元组。消息、异常、附加字段、UTC、PID 及业务调用位置在调用时、首次等待前冻结；业务来源不能指向 Logger 内部包装函数。调用本身的参数不合法时明确报错；消息或诊断格式化的普通故障保留可取得的原事实，沿现有日志降级规则处理，不覆盖业务结果。

输出包含 `logger`、`message`、`pathname`、`lineno`、`function` 及现有公共 JSON 字段。当前 `log_context` 的业务字段和当前阶段被继承，`extra` 可补充或覆盖业务字段；公共级别、UTC、PID 和源位置由接口生成，不能被 `extra` 冒充。未指定阶段时使用 `runtime`。ERROR 的 `exception` 保持结构化原异常图，不先转成字符串。`CRITICAL` 在底层继续使用现有 ERROR 优先级，不改变配置合法级别或接纳规则。

异常及附加诊断沿共同诊断快照转换，不复制编码规则。已知工具结果中的媒体 stdout 只保留字节数量，stderr 保留原始字节编码及可读文本；格式化失败时仍沿同一边界保留可取得事实。

低级别调用没有日志上下文时不创建输出通道。ERROR 使用当前命令的诊断目标；没有命令目标时，使用已绑定的通道与降级入口，仍没有通道时向 stderr 交付。同一上下文内同步入口和异步入口使用同一通道和策略；上下文退出后恢复原值，文件线程沿现有 `copy_context` 传播。

## 错误身份与接纳

不带异常对象、也没有显式诊断状态的文本 ERROR，每次调用是独立记录。带异常的 ERROR/CRITICAL/exception 查询并复用原异常上的 `DiagnosticState`；已有记录的消息、字段和来源保持首次冻结的事实。原异常向上层继续传播时，`record_error` 复用该状态，不再次投递。

单条诊断的公共接纳接缝由诊断组件维护所有权，不由 Logger 操作队列或副本凭据。

| 原状态 | 通用异步入口的处理 |
| --- | --- |
| 尚未冻结 | 冻结本条，登记原拥有者和原异常身份，再执行接纳。 |
| HELD，有 pending 拥有者且尚未接纳 | 首次等待前移出这一条，由当前协程执行单次接纳。其他 pending 记录不受影响。 |
| HELD，原拥有者正在接纳 | 不抢占、不再次投递，等待原交接结果。 |
| HELD，由日志副本预留或已接管的实际副本任务持有 | 不抢回记录，等待原副本拥有者完成交接或按既有规则释放、交回。 |
| ADMITTED 或 FALLBACK | 直接完成，不改写或重新登记。 |

完成通知只附着于原状态，不能通过新建任务或轮询等待。接纳侧、普通诊断任务及副本确认共用同一终态通知。调用在日志通道正常时完成意味着已经接纳；stderr 降级仍明确为降级，不声称落盘成功。协程取消、重复取消及通道禁用竞争保持原重要日志语义。

通用 await 接口适用于必要停止已经安排、或可由其他已有责任独立推进的调用点。如果必须先让异常传播到外层才能停止设备，该处继续使用 `record_error` 同步冻结后传播，不能先等待通用 Logger 的队列接纳。工作线程和同步回调不能用同步 ERROR 绕过这条责任。

## 验证

单元覆盖级别、消息参数、字段优先级、调用位置及 stacklevel、等待前异常快照、异步任务隔离、同步重要级别拒绝、格式化失败和上述完整诊断状态分类。真实组合覆盖队列满载及重复取消、原错误外层重记、正在交接及副本预留去重、文件和 stderr 输出、原业务继续推进和有序关闭。至少接通一个实际同步生产调用点和一个实际协程调用点，原阶段和设备确认含义不变。
