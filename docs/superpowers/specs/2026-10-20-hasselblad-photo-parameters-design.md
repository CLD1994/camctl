# Hasselblad 单张拍摄参数与中文选项设计

## 目标与适用范围

用户在客户端为 Hasselblad CFV 100C 的一次单张拍摄明确选择图片格式、曝光、白平衡和对焦设置。客户端从设备能力说明生成中文选项及关联字段，camctl 按同一份参数规则受理计划，驱动依据已保存的生效参数设置相机并执行一次拍摄。

拍摄使用驱动 `hasselblad_cfv100c`、动作 `camera_take_photo` 和参数类型 `hasselblad_photo`。参数类型名称为“Hasselblad 单张拍照”，支持 RAW（3FR）和 JPEG，并声明 `preview_supported=true`。RAW 与 JPEG 使用同一参数类型，具体格式由拍摄参数决定。

本设计面向当前固件和指定镜头的开发验证。光圈、ISO、快门及色温采用本文定义的允许域；手动调焦量继续使用[工具说明](../../hardware/hasselblad/hb_cli.md#对焦)中的两个示例值作为临时选项。参数域定义软件接受的输入，不构成实际设备验收结果，也不推断其他镜头或固件具有相同范围。

参数规则及设备执行依赖[驱动参数契约](../../architecture/camera-capabilities.md)、[单张拍摄契约](../../architecture/camera-capture.md)和[Hasselblad 驱动设计](../../camctl/hasselblad-driver.md)。客户端编辑依赖[Schema 表单与对象级联规则](../../architecture/client-editing.md#根据-schema-生成表单)，公共机器表示继续由根 [protocol](../../../protocol/README.md)维护。

## 参数来源与责任划分

驱动的一份权威参数定义同时提供允许值、关联规则、中文标题、说明和命令映射。camctl 的受理校验与 `camctl describe` 使用该定义；浏览器和客户端后端使用导出的同源 Schema。客户端不维护按相机标识判断的选项或中文名称表。

| 信息 | 负责选择或管理的参与者 | 约定 |
| --- | --- | --- |
| 图片格式、曝光、白平衡、对焦 | 用户通过拍摄参数选择 | 四项均显式填写；可选的手动调焦量按其缺省语义处理。 |
| 拍摄驱动模式 | 驱动 | 每次设置 `drive-mode single`，执行一次 `capture`。 |
| 手动白平衡色调 | 驱动 | 设置色温时显式将色调设为 `0`；拍摄参数不提供色调字段。 |
| 相机身份与工具入口 | 部署配置及驱动 | 沿用工具绝对路径、序列号和产品标识配置；发送设置命令前核对设备身份。 |
| 正式源位置 | 部署配置 | 沿用 `devices.<id>.hasselblad.output_storage`；首次受理将选择保存到执行定义。 |
| 完整调用期限 | 驱动任务定义 | 提供内部 `start_call_timeout_s`，首次受理保存；客户端不填写该字段。 |
| 拍摄工作目录、文件身份、归档和交付 | camctl 的驱动、拍摄及文件流程 | 使用原动作或活动对应的工作目录和文件责任，按正式源模式处理。 |
| 任务名称、固定设置、允许域及相对调焦说明 | 同源能力元数据 | 客户端直接展示说明；手动调焦量的临时选项须明确标注。 |

`capture` 的相机与主机双落盘属于工具行为。`output_storage` 表示 camctl 登记的正式源位置，不表示工具只在该位置生成文件。预览生成、自动取回意图和正式源清理分别沿用既有契约，不新增拍摄参数开关。

## 完整参数结构

`params` 是封闭对象，必填字段恰为 `type`、`capture_format`、`exposure`、`white_balance` 和 `focus`；不接受其他顶层字段。`type` 固定为 `hasselblad_photo`。下面展示手动曝光、手动白平衡和手动调焦的一个合法组合，不表示默认配置：

```json
{
  "type": "hasselblad_photo",
  "capture_format": "jpeg",
  "exposure": {
    "mode": "M",
    "iso": 100,
    "aperture": 8,
    "shutter_s": 0.008
  },
  "white_balance": {
    "mode": "manual",
    "temperature_k": 5500
  },
  "focus": {
    "mode": "MF",
    "relative_move": 5
  }
}
```

Schema 使用 Draft 2020-12，根对象约束完整 `params`。`exposure`、`white_balance` 和 `focus` 分别通过局部 `oneOf` 表达互斥的封闭对象分支，判别字段统一为必填的 `mode`。各分支只声明该模式允许的字段，并设置 `additionalProperties=false`。这三个对象及 `capture_format` 相互独立，不建立无关的跨对象组合限制。

选择模式只写入其机器标识，不自动补齐子参数。所有必填字段缺失、显式 `null`、类型不符、允许域以外的值及不适用字段均按参数错误处理。Schema 不声明用于自动补值的拍摄默认配置，驱动也不为缺少的必填参数补值。色调的固定值是驱动命令要求，不作为 Schema 的 `default` 或计划中的隐藏参数。客户端允许保存未完成草稿，完整计划导出前必须校验通过。

### 图片格式

`capture_format` 是必填字符串，通过命名常量选项表达允许值及中文展示，具体 Schema 结构见[中文选项声明](#中文选项声明与客户端解析)。驱动每次按用户选择执行 `set capture-format <值>`；命令失败时保留所选格式和实际错误，不替换成另一种格式。

### 曝光

`exposure` 的标题为“曝光设置”，`mode` 的标题为“曝光模式”。分支必须完整表达下表，不能只在文字中说明关联关系。

| `mode` | 分支 `title` | 除 `mode` 外的必填字段 | 由相机自动决定的曝光量 |
| --- | --- | --- | --- |
| `M` | 手动曝光 | `iso`、`aperture`、`shutter_s` | 无。 |
| `A` | 光圈优先 | `iso`、`aperture` | 快门。 |
| `S` | 快门优先 | `iso`、`shutter_s` | 光圈。 |
| `P` | 程序曝光 | `iso` | 光圈和快门。 |

每个分支只接受表中列出的字段。驱动先执行 `set exposure-mode <mode>`，再设置该分支的 ISO、光圈及快门。相机自动决定的字段不发送设置命令，也不补造为生效参数中的具体数值。实际曝光结果与计划中的曝光要求分别表达，不把计划值当作相机回读值。

### 白平衡

`white_balance` 的标题为“白平衡设置”，`mode` 的标题为“白平衡模式”。

| `mode` | 分支 `title` | 除 `mode` 外的字段 | 驱动操作 |
| --- | --- | --- | --- |
| `auto` | 自动白平衡 | 无。 | 设置所选 `wb-mode`。 |
| `daylight` | 日光 | 无。 | 设置所选 `wb-mode`。 |
| `cloudy` | 阴天 | 无。 | 设置所选 `wb-mode`。 |
| `shade` | 阴影 | 无。 | 设置所选 `wb-mode`。 |
| `tungsten` | 钨丝灯 | 无。 | 设置所选 `wb-mode`。 |
| `fluorescent` | 荧光灯 | 无。 | 设置所选 `wb-mode`。 |
| `flash` | 闪光灯 | 无。 | 设置所选 `wb-mode`。 |
| `manual` | 手动白平衡 | 仅 `temperature_k` 必填。 | 先执行 `set wb-mode manual`，成功后执行 `set wb <temperature_k>,0`。 |

手动分支的色温使用整数输入框，允许 `2000`～`10000` K，包含上下界，用户必须显式填写。非手动分支不接受色温字段。所有分支均不接受 `tint` 字段；色调 `0` 由驱动在手动白平衡命令中显式设置，客户端只在固定设置说明中展示。其他白平衡模式仅发送对应的 `wb-mode` 命令，不在非手动模式发送工具要求只能用于手动模式的色调命令。

### 对焦

`focus` 的标题为“对焦设置”，`mode` 的标题为“对焦模式”。

| `mode` 及调焦量状态 | 分支 `title` | 接受的字段 | 驱动操作 |
| --- | --- | --- | --- |
| `MF`，未填写 `relative_move` | 手动对焦 | 仅 `mode`。 | 执行 `set focus-mode MF`，不发送 `focus` 命令，保持当时焦点位置。 |
| `MF`，填写合法 `relative_move` | 手动对焦 | `mode` 及可选 `relative_move`。 | 先执行 `set focus-mode MF`，成功后执行一次 `focus <relative_move>`。 |
| `AF-S` | 单次自动对焦 | 仅 `mode`。 | 先执行 `set focus-mode AF-S`，成功后执行一次 `autofocus`，成功返回后才继续拍摄。 |

`relative_move` 的标题为“手动调焦相对移动量”。正值向无限远移动，负值向近处移动，绝对值表示相对移动量。它不表示距离、百分比或目标焦点位置；相同输入在不同初始焦点下可以得到不同结果。CLI 单位与设备协议移动量的换算由工具承担，驱动原样传入 CLI 数值。

`relative_move` 省略和显式 `0` 是不同输入；临时允许值中没有 `0`。AF-S 分支不接受该字段。客户端显示“未填写时不移动焦点”的说明，不用数值占位替代真正的缺省状态。

### 数值字段与控件

| 字段 | JSON 类型 | 允许值或范围 | 控件与显示 |
| --- | --- | --- | --- |
| `iso` | `integer` | `[64, 100, 200, 400, 800, 1600, 3200, 6400, 12800, 25600]` | 下拉选择，标题为“ISO 感光度”。 |
| `aperture` | `number` | `[4, 4.8, 5.6, 6.8, 8, 9.5, 11, 13, 16, 19, 22, 27, 32]` | 下拉选择，依次显示对应的 f 值，例如 `f/4`、`f/4.8`、`f/32`；保存数值。 |
| `shutter_s` | `number` | 下文列出的 34 个档位及十进制秒值。 | 下拉选择，显示秒数或分数形式，保存对应十进制秒数。 |
| `temperature_k` | `integer` | `minimum:2000`、`maximum:10000`，上下界均包含。 | 整数输入框，标题为“色温”，单位 K；不枚举成下拉列表。 |
| `relative_move` | `integer` | 临时 `enum:[-5, 5]`。 | 下拉选择，标题为“手动调焦相对移动量”，单位为 CLI 调焦单位；保留未填写状态。 |

光圈、ISO 和快门只接受目录中的离散值，不把最小值与最大值之间的任意数值视为合法。色温允许区间中的每个整数，不附加其他步进。手动调焦量的说明标注“开发验证临时选项”，其完整允许域后续补充。所有控件均不自动补入首项或示例值。

数值采用[既有精确 JSON 数字规则](../../camctl/data-types.md)解析、比较、保存及导出。驱动把数值转换为工具需要的十进制参数，不先经过二进制浮点数；快门使用十进制秒数，不传分数字符串。相同字段出现在多个曝光分支时，从同一个驱动字段定义生成节点，客户端、脚本和测试不分别维护完整生产允许值表。

## 中文选项声明与客户端解析

Schema 的 `title` 提供面向用户的名称，`const` 保留工具和计划使用的机器值。字段标题、分支标题和枚举选项标题承担不同角色；客户端不从说明文本或机器标识猜测中文名称。

对象分支的 `title` 是模式选项名称，分支中 `mode.const` 是保存值，`mode.title` 是模式字段的名称。例如，曝光的手动分支标题为“手动曝光”，其 `mode.const` 为 `M`，`mode.title` 为“曝光模式”。三个对象均使用此形式，客户端选择模式后按该分支展示关联字段。

带显示名称的标量选项使用匹配值类型的 `type` 加直接 `oneOf`。字符串或数值的每个分支声明唯一 `const` 及非空 `title`。图片格式使用字符串常量，光圈与快门使用数值常量；中文名称、f 值及分数名称均从标题取得。图片格式声明为：

```json
{
  "type": "string",
  "title": "图片格式",
  "oneOf": [
    { "const": "raw", "title": "RAW（3FR）" },
    { "const": "jpeg", "title": "JPEG" }
  ]
}
```

同一个命名选项字段只维护带标题的常量分支，不平行维护另一份允许值或专用标签数组。客户端对这种直接、有限且常量互异的标量分支提取保存值及标题，再由完整 Schema 判断值是否合法。数值常量的身份按精确数学值判断并保留原数字词元，不能因浮点舍入而合并短快门档位。对象级联解析也须接受这类可证明的有限标量成员，使光圈和快门能在曝光分支内显示为下拉框。此规则是通用 Schema 展示能力，不以 Hasselblad 身份作为生效条件。

| Schema 与当前输入的情况 | 客户端行为 |
| --- | --- |
| 对象分支可以可靠识别唯一判别字段 | 选择器使用分支 `title`，正文保存该分支的判别常量；随后展示该分支成员。 |
| 字符串或数值字段的直接 `oneOf` 全部为类型相符且唯一的常量选项 | 生成有限选择器，显示各分支 `title`，保存对应 `const`；数值原词元保留。 |
| 可解释选项未提供有效标题 | 使用既有机器值展示；不编造名称，不改变合法性。此驱动的命名选项必须提供标题。 |
| 两个选项标题相同，但机器值不同 | 保留两个独立选项，并附机器值帮助区分；标题不作为选项身份。 |
| 组合或引用不能可靠解析、分支常量不唯一，或数值事实不能精确表达 | 沿用原规则和高级 JSON 编辑入口，不猜测选项或改写 Schema。重复常量导致的合法性仍由完整校验器判定。 |
| 当前输入未知、非法或尚未完成 | 保留原值及诊断，不按标题相似度替换成某个选项。 |

选项下拉框、字段规则说明和设备说明页使用同一份已启用 Schema 中的名称。参数 JSON、预设及导出的计划保存机器值。更改标题、打开页面、切换表单与 JSON、展开说明及重新加载能力本身均不修改参数，不补首个选项或默认值。

切换对象模式遵守[对象参数级联编辑](../../architecture/client-editing.md#对象参数级联编辑)：按设备、动作、参数类型和对象分支保存编辑内容，恢复各分支已有值及未完成输入，完整导出只含当前分支允许的字段。曝光、白平衡和对焦之间不共享分支缓存或互相覆盖。能力加载继续整份校验和启用，Schema 无效与用户参数非法分别报告。

## 驱动执行顺序与调用预算

驱动从首次受理保存的生效参数构造以下有限命令序列。所有工具调用使用结构化参数列表，附带配置中的产品标识；主机目录由原活动工作区提供。每一步成功返回后，才有资格发送下一步。

| 顺序 | 操作 | 条件 |
| --- | --- | --- |
| 1 | `list`，再执行 `info` 核对序列号 | 同产品标识下恰有一台目标相机，且序列号匹配；否则不发送任何设置或拍摄命令。 |
| 2 | `set drive-mode single` | 身份核对通过。 |
| 3 | `set capture-format <capture_format>` | 单张模式设置成功。 |
| 4 | `set exposure-mode <mode>`，再依次设置 `iso`、适用的 `aperture`、适用的 `shutter` | 严格按曝光分支发送其所需字段。 |
| 5 | `set wb-mode <mode>`，手动分支随后执行一次 `set wb <temperature_k>,0` | 严格按白平衡分支发送。 |
| 6 | `set focus-mode <mode>`，再按对焦分支执行可选的 `focus` 或必需的 `autofocus` | AF-S 不省略自动对焦操作；MF 不触发自动对焦。 |
| 7 | `capture --output <原活动工作目录>` | 前序步骤成功，原动作仍有派发资格且预算未耗尽。 |
| 8 | 解析响应、核验原图及预览，可靠保存结果并按原源模式登记 | 工具返回满足完成条件；设置成功或文件存在不能单独证明拍摄成功。 |

设置、调焦及自动对焦命令的本地进程正常退出且退出码为 0，才允许继续下一步；工具错误、非零退出码、超时、中断或输出取得失败按实际事实保留。工具成功返回不等于已测得焦点距离或图像清晰度；不生成工具未提供的镜头位置和对焦质量观察。

身份核对、设置、对焦及 `capture` 共用一次已持久化的 START 尝试。每次新命令派发前重新检查取消、时间窗口和剩余调用预算。当前完整调用期限保持 `180` 秒，覆盖从驱动调用开始到 `capture` 返回所需的准备、设置、曝光和文件传输；它不是快门时间、调度等待时间，也不是每条命令各自的预算。结果核验、同步及登记仍须完成其自身条件，不能仅因调用尚未超时而认定文件可靠。

调用期限由任务工厂提供，首次受理与 `output_storage` 一起保存在[单张执行定义](../../camctl/database/execution-definitions.md#单张拍摄执行定义的存储位置与完整调用期限)。执行和恢复使用原保存值，参数对象不重复承载该字段。M、S 模式的最长显式曝光为 32 秒，共享预算还需容纳身份核对、设置、对焦及文件传输；A、P 模式的实际快门由相机决定，不能由允许值表推导本次曝光上限。保留 180 秒作为软件调用预算，是否覆盖所有目标场景由真实设备验证，不因列出 32 秒就宣称预算已经充分。

## 失败、副作用与恢复

相机设置和镜头移动可以在 `capture` 之前发生。驱动返回的步骤事实必须区分“拍摄命令未发送”“设置或镜头操作已执行”和“某个操作效果未知”，不能用“没有拍摄”概括相机完全没有变化。步骤信息随原调用结果保存；进程或主机中断导致步骤结果缺失时，保留未知，不依据缺记录推断未执行。

同一 START 内每条设置、调焦及拍摄命令最多调用一次。已启动或可能启动的原 START 不因参数设置、调焦、拍摄或保存失败而从头重放；恢复只核实原尝试及继续已可靠保存的结果责任。相对移动不能通过反向移动补偿，已经改变的曝光、白平衡或焦点也不自动恢复为推测的先前值。

| 发生情况及此前事实 | 处理 |
| --- | --- |
| 参数校验不通过 | 按既有逐动作受理规则保存参数错误，不进入驱动调用。 |
| 设备缺失、存在多个匹配设备、身份不一致或身份查询失败 | 保存具体原因；不设置相机，不调焦，不拍摄。 |
| 设置步骤失败，且本次流程尚未发送拍摄命令 | 停止后续普通命令；保存成功或可能生效的前序设置及失败步骤，不将动作登记为拍摄成功。 |
| MF 移动或 AF-S 自动对焦失败、超时或中断，且拍摄尚未发送 | 停止后续拍摄；保存镜头操作的实际结果或未知效果，不重复移动或自动对焦。 |
| 对焦完成后取消生效或已无派发资格 | 阻止后续 `capture`，保留已经发生的设置与调焦，不补发拍摄或撤销镜头移动。 |
| `capture` 已启动或可能启动，但错误、超时、中断或响应无法可靠解释 | 保留原错误、工作文件及拍摄结果未知；不重新拍摄，不把终止主机进程当作相机已经停止。 |
| 工具成功返回，但格式、配对、文件大小、内容或摘要核验不符 | 保存不符的具体事实；不改写用户所选格式，不把不符文件登记为成功产物。 |
| 完整拍摄结果已可靠保存，归档或登记尚未完成 | 沿原活动、原文件身份和原结果继续文件处理，不重新发送设置、对焦或拍摄命令。 |
| 原保存回执未知，或主机重启时缺少完整步骤结果 | 先核实原完整申请及原尝试；没有可靠完成依据时保持未知并按有限核实规则结束，不从头执行命令序列。 |

`hb_cli stop` 的设备含义是关机，不充当单张动作的取消或超时停止命令。原动作终态、设备活动、已取得文件和具体错误分别由既有拍摄与报告契约表达。

## RAW、JPEG 与产物角色

每次可靠拍摄分别登记 `original` 和 `preview`，使用 `preview_of_output_id` 保存配对关系。文件角色由本次成功响应的配对身份及原活动文件责任决定，媒体类型用于校验内容，不能用“JPEG 就是预览”判断角色。

| 用户选择 | 原图类型 | 预览类型 | 必须保持的角色区别 |
| --- | --- | --- | --- |
| RAW | `image/x-hasselblad-3fr` | `image/jpeg` | 3FR 是原图，其配对 JPEG 是预览。 |
| JPEG | `image/jpeg` | `image/jpeg` | 原图和预览虽然同为 JPEG，仍是两份独立身份和用途的文件。 |

响应解析须按[当前工具输出](../../hardware/hasselblad/hb_cli.md#拍摄和保存图片)识别 `capture: OK`、两份主机 `saved` 记录及工具返回的 `camera file:` 信息。原图格式必须与已保存的 `capture_format` 一致；预览必须与原图的主机名称按 `.thumbnail.jpg` 配对，二者不得重复引用同一文件。路径、完整长度、实际内容标识、SHA-256、文件及目录同步继续按既有可靠完成规则核验，不仅凭扩展名确认内容。

本地主机文件名、机内原图文件名和机内完整路径分别表达，不能假设本地 `capture_<编号>` 名称等于机内名称。相机正式源取回按工具要求使用 `camera file:` 中的机内文件名；主机工作目录与正式路径仍按原文件责任管理。工具提示未报告机内名称时，保存该事实：主机正式源仍按完整的本地成功及双文件依据判定；相机正式源缺少可靠身份，不能登记成功或回收工作副本。不用本地名称补造设备源身份。

主机源的原图、预览归档及恢复按明确的文件角色核对目标用途；相机源的原图、预览下载也使用各自的读取种类。JPEG 原图不得因媒体类型与预览相同而归入预览用途、覆盖预览文件或遗漏普通原图取回。当前工具的缩略图是从机内原图提取或生成的内容；主机缩略图不证明机身另存了独立缩略图文件。

本设计只延伸两种格式的拍摄、角色判定、登记及取回路径。正式源删除声明、删除责任和查询恢复能力继续按所属契约处理，不因工具包含删除命令或开放 JPEG 就自动改变。

## 持久化、展示与资源衔接

首次受理将明确的参数保存为原始输入和生效参数，存储位置及完整调用期限进入原执行定义。恢复、历史回放和报告使用当时保存的事实；相机自动决定的光圈、快门及自动对焦结果，在没有回读证据时不补充实际数值。

| 边界 | 需要保持的一致性 |
| --- | --- |
| 驱动参数定义、导出与受理 | 同一字段域、互斥分支、标题及描述供参数校验和完整能力导出使用；导出不连接相机。 |
| 客户端浏览器与后端 | 使用同源 Schema 校验；中文标签与机器值分离；精确数字、模式切换和未完成输入按既有规则保存。 |
| 预设、计划及摘要 | 预设展开为明确参数，计划保存机器值；名称和普通参数说明来自能力规则，不以中文标题作为参数身份。 |
| 驱动命令与步骤结果 | 字段映射、顺序、共用期限和至多一次的相对调焦执行一致；保留各步错误及已知副作用。 |
| 文件核验、归档、设备源登记与取回 | 同时识别 RAW、JPEG 及两种文件角色；内容类型、名称、大小、摘要和预览关联从原可靠结果消费。 |
| 历史与报告 | 输入要求、调用结果和文件事实分别保存；不把 Schema 通过、设置成功或进程退出等同于整次拍摄成功。 |
| 公共样例、演示生成器及安装资源 | 从同一权威定义取得参数要求或生成合法样例；安装包导出的说明与源码运行取得的规则一致。 |

落地时，Hasselblad 的参数与命令语义归入[驱动专题](../../camctl/hasselblad-driver.md)，中文字符串与数值选项、对象分支标签规则归入[公共客户端编辑专题](../../architecture/client-editing.md)，业务入口引用完整规则。部署样例、演示计划、测试输入及任务说明同步采用本设计的完整参数，不在多个责任专题复制整份允许值目录。具体修改位置和实施顺序由后续实施计划确定。

## 验收要求与证据边界

| 验证范围 | 可证伪的验收条件 |
| --- | --- |
| 参数 Schema | 覆盖 13 档光圈、10 档 ISO、34 档快门，目录中的值通过，目录外值失败。色温 2000 和 10000 及区间整数通过，1999、10001、非整数和缺省失败。曝光、白平衡、对焦分支按需接受字段；包括 `tint` 在内的额外字段、非法类型、`null` 及错误分支字段均失败。RAW 与 JPEG 和各参数对象独立组合，MF 缺省、正向与负向调焦及 AF-S 均覆盖。 |
| 中文选项 | 曝光选择器完整显示“手动曝光、光圈优先、快门优先、程序曝光”；光圈显示 f 值，快门显示原秒数或分数名称，均保存数值。其他模式及格式显示同源标题。改标题不改机器值、合法性或已保存输入；无标题及不可可靠推导的通用规则按分类处理。 |
| 客户端编辑 | ISO、光圈和快门使用下拉框，手动色温使用整数输入框，色调仅显示固定设置说明。首次选择模式不补子参数；MF 省略移动量能与显式非法 `0` 区分。模式切换恢复各自内容及未完成输入，当前计划不夹带其他分支字段。 |
| 三处校验及精确编码 | 浏览器、客户端后端和 camctl 对共同正反例判定一致。全部快门档位为正且数值互异；有限小数精确保留，循环小数与三位有效数字规则相符。`0.000667`、`0.000333` 和 `0.00025` 保持精确，不归零、不合并、不在执行时重复舍入；目录外数值不通过近似匹配。 |
| 命令与资格 | 按各分支核对实际命令及顺序。手动白平衡先设模式再以用户色温及固定色调 0 调用 `set wb`，其他模式不发色温或色调命令。身份不符不发设置；设置失败不发后续命令；MF 未填不发 `focus`，已填只发一次；AF-S 在设置后、拍摄前发一次 `autofocus`。 |
| 期限、副作用及中断 | 多条命令共享递减的 180 秒预算；对焦后取消、调焦返回未知、拍摄超时、步骤结果保存未知及重启均不能重复镜头移动或拍摄。未拍摄与已改变设置分别保留。 |
| 格式与文件 | 严格解析 RAW 和 JPEG 的当前成功输出；格式不符、错误配对、路径越界、重复文件和不完整内容均拒绝形成成功。JPEG 原图与 JPEG 预览的身份、用途和摘要始终分开。 |
| 主机源与相机源 | 两种格式分别完成原图和预览登记、独立取回及报告展示；主机源 JPEG 原图可正确归档和恢复；相机源使用机内文件名下载，不使用主机名称替代。 |
| 分发与演示 | 从已安装包导出完整能力说明，客户端能加载并编辑完整参数；演示计划不遗漏必填组，示例值与实际规则一致。 |

单元测试隔离工具、时钟、文件和数据库等协作者；真实文件、进程、状态库与组件组合归集成测试。软件检查证明规则解释与组件协作，不证明各模式在真实镜头和固件上的效果。ARM 安装验证与实际拍摄另行记录：核对四种曝光模式、白平衡命令、两种对焦流程、RAW／JPEG 文件和预览内容，以及调用耗时与 180 秒预算的适配性。手动调焦量的完整允许域补充后，再扩展该字段的规则及设备验收记录。
