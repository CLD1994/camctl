# 拍摄视频大小估算设计

## 目标与适用范围

客户端在用户编辑拍摄参数时显示拍摄视频的大致大小。估算覆盖普通录像和延时摄影的最终视频，预览视频不计入。

估算结果由当前启用的设备能力说明和当前拍摄参数共同确定。用户无需连接相机即可取得结果。界面使用“预计视频大小”和“约”等表达，帮助用户理解大致大小；实际文件大小以取得的文件事实为准。

估算属于客户端的编辑辅助信息，不写入执行计划、动作生效参数或状态报告，不参与动作完成判定。能否导出计划继续由既有的参数、公共字段、业务条件及能力加载规则决定。

本设计依赖[能力说明格式](../../architecture/capabilities.md)、[驱动参数与默认值契约](../../architecture/camera-capabilities.md)、[客户端计划编辑](../../architecture/client-editing.md)及[能力说明加载](../../architecture/client-deployment.md)。

## 权威来源与交接

驱动在同一份参数类型定义中维护参数规则、固定设置、任务说明及估算信息。`camctl describe` 从该定义和主机设备配置生成能力说明，客户端通过现有的文件交接与整份加载流程取得说明。

固定码率和固定成片播放帧率属于驱动的估算说明。只有驱动开放给用户调整的设置才成为拍摄参数。任务说明中的参考码率及估算元数据由同一份权威定义提供，不能分别维护相互独立的数值。

公共机器格式由根 `protocol/schemas` 定义，可解析样例放在根 `protocol/examples`。浏览器、客户端后端及 camctl 使用共同样例验证字段和含义。客户端的表单模式和 JSON 模式使用同一份参数与估算规则。

## 能力说明中的估算字段

设备、动作和参数类型的选择沿用现有精确匹配规则。在选定的 `parameter_types[]` 条目中，使用可选对象 `video_size_estimate`：

```json
{
  "video_size_estimate": {
    "bitrate_mbps": 175,
    "duration": {
      "method": "direct",
      "seconds": { "source": "parameter", "path": "/duration_s" }
    }
  }
}
```

该对象恰好包含 `bitrate_mbps` 和 `duration`。缺少整个对象表示驱动未提供估算信息；出现对象但缺少必要成员、值为 `null`、包含未知字段或未知计算方法，均属于能力定义错误。

驱动只为其契约明确生成目标拍摄视频的 `camera_record` 或 `camera_timelapse` 参数类型提供此对象。估算码率对应目标拍摄视频，不包含额外预览视频或独立照片。其他拍摄动作不声明此字段。

### 参考码率

`bitrate_mbps` 使用 Mbps，即每秒百万比特。它具有以下三种互斥形式：

| 形式     | 完整结构                                                                                                  | 取值含义                                                       |
| -------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 固定值   | 正的有限 JSON 数字，例如 `175`。                                                                          | 使用驱动提供的固定参考码率，允许小数。                         |
| 参数引用 | 仅含 `from` 的对象，例如 `{ "from": "/bitrate_mbps" }`。                                                  | 读取明确采用 Mbps 的数值参数。                                 |
| 选项查表 | 仅含 `by`、`values` 的对象，例如 `{ "by": "/bitrate_mode", "values": { "standard": 95, "high": 130 } }`。 | 读取字符串选项，精确匹配 `values` 的成员名，取得对应参考码率。 |

`values` 为非空对象，每个成员值都是正的有限数字；表中不能再嵌套引用或计算。查表保留字符串的大小写和空白，不转换数字、布尔值或其他类型。

查表允许只覆盖部分合法选项。当前参数符合 Schema，但所选字符串没有对应表项时，显示该选项未提供估算依据；这不是用户参数错误，也不是整个能力说明的格式错误。表中已经提供的值不合法时，仍属于能力定义错误。

驱动在参数类型说明中解释参考码率对应的模式、档位和统计范围。参考值用于粗略计算，其含义不能被界面改写为实际平均码率或设备测量结果。

### 成片播放时长

`duration.method` 明确选择一种计算方式。各方式只接受表中列出的成员，所有列出的成员均为必填：

| `method`             | 其他成员                                                | 成片播放时长                               |
| -------------------- | ------------------------------------------------------- | ------------------------------------------ |
| `direct`             | `seconds`。                                             | 直接使用 `seconds` 的数值，单位为秒。      |
| `timelapse_frames`   | `frames`、`playback_fps`。                              | 预计成片帧数除以播放帧率。                 |
| `timelapse_interval` | `capture_seconds`、`interval_seconds`、`playback_fps`。 | 采集持续时间除以采集间隔，再除以播放帧率。 |

各数值成员使用下表的互斥结构。单位由所在成员固定：`seconds`、`capture_seconds` 和 `interval_seconds` 为秒，`playback_fps` 为每秒帧数，`frames` 为预计成片帧数。

| `source`    | 其他成员           | 含义                                                     |
| ----------- | ------------------ | -------------------------------------------------------- |
| `constant`  | `value`。          | 使用驱动声明的固定数字。                                 |
| `parameter` | `path`。           | 读取采用对应单位的拍摄参数。                             |
| `lookup`    | `path`、`values`。 | 根据拍摄参数的字符串值精确查表，取得采用对应单位的数字。 |

各形式只包含本表列出的成员。数字均须为正的有限数；`frames` 还须为整数。`lookup.values` 为非空对象，只包含符合所在成员数值要求的数字，未覆盖合法选项时沿用码率查表的处理规则。单位由驱动定义明确，不从参数名称或说明文案中推测，也不进行隐式单位换算。

`direct` 适用于驱动明确声明成片播放时长的任务。延时摄影采用该方法时，所引用的值也必须是成片播放时长。

`timelapse_frames` 的 `frames` 表达预计成片帧数，不直接把可交付照片数量当作成片帧数。

`timelapse_interval` 表达“一次采集预计形成一帧成片”的估算关系。驱动只有明确采用该关系时才声明此方法。计算保留采集时长与间隔相除所得的比例，不自行向上或向下取整；首尾采集、停止时机和实际成片帧数继续由驱动执行契约定义。

### 参数路径

`from`、`by` 和 `path` 均为相对于完整 `action.params` 的 JSON Pointer（JSON 指针）。路径以 `/` 开头，使用现有路径规则解码成员名和数组位置；空路径、URI 片段形式或无效转义不属于有效估算路径。

例如，`/duration_s` 指向 `action.params.duration_s`，而不是整个计划根对象下的字段。路径只读取当前对象自身的成员，不读取原型上的值，不跨动作或参数类型寻找相同名称，也不读取客户端预设作为缺省补充。

路径语法错误属于能力定义错误。语法有效的路径在当前参数中没有对应值时，属于当前估算所需数据缺失。

## 计算与单位

客户端先取得参考码率和成片播放时长，再计算：

```text
预计大小（字节）= bitrate_mbps × 1,000,000 × 成片播放时长（秒）÷ 8
预计大小（MB）= bitrate_mbps × 成片播放时长（秒）÷ 8
```

显示采用十进制单位：`1 MB = 1,000,000 字节`，`1 GB = 1,000 MB`。计算过程保留精度，显示时才做合理舍入；舍入不能使正的估算值显示为 `0 MB`。

参考码率不额外叠加统一的音频码率、容器开销或百分比修正。驱动的任务说明解释其参考值覆盖的内容。界面统一说明实际大小可能随拍摄内容和编码结果变化。

任何必要输入或中间结果不符合本设计的数值要求，或计算不能得到正的有限结果时，客户端返回无法估算及具体原因，不生成一个有效数值。

## 估算资格与状态分类

客户端每次计算均使用当前启用说明及当前编辑内容的同一组输入。下表自上而下判定；后续行均以前面条件未满足为前提。

| 当前条件                                                                    | 可观察结果                                                   |
| --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 当前动作不是普通录像或延时摄影。                                            | 不显示视频大小估算区域。                                     |
| 能力说明不可用。                                                            | 显示能力说明不可用及既有诊断，无法估算。                     |
| 未完成输入覆盖计划根、动作集合、当前动作、当前选择字段或拍摄参数。          | 保留输入，显示当前输入尚未完成；不使用上次解析的值生成估算。 |
| 未完成输入的路径无法可靠解释，因此不能确认其影响范围。                      | 保留输入，显示当前输入范围无法确定，暂停估算。               |
| 设备、动作或参数类型没有明确匹配项，或当前 `params` 不是对象。              | 提示完成或修正当前选择和参数，无法估算。                     |
| 匹配的参数类型没有 `video_size_estimate`。                                  | 显示未提供估算信息；不解释为设备不支持该拍摄能力。           |
| 当前完整 `params` 不符合所选 Schema。                                       | 显示需要完成或修正拍摄参数，暂不显示有效数值。               |
| 参数通过 Schema，但引用值缺失、类型或数值不符合估算要求，或查表没有匹配项。 | 显示具体缺失路径或不适用原因，无法估算。                     |
| 所需数据有效，但计算结果不符合正的有限数要求。                              | 显示计算未能取得有效结果，无法估算。                         |
| 选择、参数、引用值与计算结果均有效。                                        | 显示预计大小、成片播放时长及参考码率。                       |

公共字段中与估算无关的问题不单独阻止取得估算。例如，拍摄参数完整但执行时间尚未填写时，可以显示估算，整份计划仍按既有规则校验。其他动作和无关公共字段的未完成输入不覆盖当前动作的估算依据。

参数缺省与显式的 `null`、零、空字符串等状态分别处理。客户端只读取当前参数中的显式值，不从 Schema 的 `default` 自动补齐估算输入。可选参数省略后即使仍符合 Schema，只要它被估算路径引用且没有当前值，就显示所需数据缺失。驱动的固定估算值使用 `constant` 或固定码率表达；用户填写合法参数后重新计算。

估算区域不改变输入、编辑资料、自动预览开关或派生动作。显示、折叠、切换编辑模式及计算本身均不触发草稿保存。已有的参数编辑操作仍使用原有保存流程。

### 能力加载与页面更新

能力定义的检查属于现有整份加载流程。估算对象存在但结构错误、字段错误或方法不受支持时，本次说明整份导出或加载失败；不能把错误字段删除后启用剩余规则。

加载成功后整体替换目录，并根据当前保留的参数重新计算。重载正在进行时，估算区域提示规则正在更新，暂停展示旧的有效数值。

重载请求已经发出但响应或后续状态读取未能取得时，页面保留“结果尚待核实”状态，并暂停展示估算数值。请求结束后重新发起的状态读取成功返回时，页面使用该观察中的实际启用说明、加载诊断及当前参数恢复估算。重载开始前或保存准备期间取得的观察不能解除暂停；读取再次失败时继续保留暂停状态。该观察确认后端当前启用的说明，不为结果未知的请求补造成功回执。

重载失败且没有此前启用的说明时，能力说明不可用。重载失败但仍保留此前成功启用的说明时，页面沿用该说明计算，并显示现有的“仍使用此前说明”提示；不会混入失败文件中的估算信息。拍摄计划能否导出仍遵守[加载结果与现有数据](../../architecture/client-deployment.md#加载结果与现有数据)，估算展示不放宽其中的限制。

用户修改参数、应用预设、切换类型、重新打开草稿或成功加载能力说明后，估算区域从实际当前内容重新推导。有效结果转为未完成、无效或缺失状态时，立即撤下有效数值；修正后可重新取得有效结果。

## 界面呈现

估算区域放在对应拍摄动作的参数编辑区域，表单模式和参数 JSON 模式均可查看。例如：

```text
预计视频大小：约 175 MB
预计成片时长：约 8 秒
参考码率：175 Mbps
根据参考码率估算，实际大小可能有所变化。
```

无法估算时显示状态和原因，例如“暂无法估算：请填写录像时长”。说明优先使用 Schema 中的字段名称，并保留实际路径供定位；不要求用户理解估算元数据的内部结构。

## 能力说明示例

以下为两个虚构参数类型条目，分别放入某演示设备的 `camera_record.parameter_types` 和 `camera_timelapse.parameter_types`。数值用于解释格式，不声明真实相机的能力或正式码率。

### 普通录像

```json
{
  "type": "example_record",
  "name": "演示：普通录像",
  "description": "帧率固定为每秒30帧，可设置录像时长并选择码率档位。视频大小按档位对应的参考码率估算。",
  "preview_supported": true,
  "schema": {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "type": "object",
    "properties": {
      "type": { "const": "example_record" },
      "bitrate_mode": {
        "title": "码率档位",
        "type": "string",
        "enum": ["standard", "high"]
      },
      "duration_s": {
        "title": "录像时长",
        "description": "单位为秒。",
        "type": "integer",
        "minimum": 1,
        "maximum": 3600
      }
    },
    "required": ["type", "bitrate_mode", "duration_s"],
    "additionalProperties": false
  },
  "video_size_estimate": {
    "bitrate_mbps": {
      "by": "/bitrate_mode",
      "values": { "standard": 95, "high": 130 }
    },
    "duration": {
      "method": "direct",
      "seconds": { "source": "parameter", "path": "/duration_s" }
    }
  }
}
```

`params` 为 `{ "type": "example_record", "bitrate_mode": "high", "duration_s": 60 }` 时，预计成片时长为 60 秒，参考码率为 130 Mbps，预计大小为 975 MB。

### 延时摄影

```json
{
  "type": "example_timelapse",
  "name": "演示：按时长采集的延时摄影",
  "description": "可设置采集持续时间和采集间隔。预计每次采集形成一帧成片，成片固定为每秒30帧，参考码率为175 Mbps。",
  "preview_supported": true,
  "schema": {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "type": "object",
    "properties": {
      "type": { "const": "example_timelapse" },
      "capture_duration_s": {
        "title": "采集持续时间",
        "description": "单位为秒，表示采集过程的持续时间。",
        "type": "integer",
        "minimum": 60,
        "maximum": 86400
      },
      "interval_s": {
        "title": "采集间隔",
        "description": "单位为秒。",
        "type": "integer",
        "minimum": 1,
        "maximum": 60
      }
    },
    "required": ["type", "capture_duration_s", "interval_s"],
    "additionalProperties": false
  },
  "video_size_estimate": {
    "bitrate_mbps": 175,
    "duration": {
      "method": "timelapse_interval",
      "capture_seconds": {
        "source": "parameter",
        "path": "/capture_duration_s"
      },
      "interval_seconds": { "source": "parameter", "path": "/interval_s" },
      "playback_fps": { "source": "constant", "value": 30 }
    }
  }
}
```

`params` 为 `{ "type": "example_timelapse", "capture_duration_s": 6000, "interval_s": 25 }` 时，预计成片时长为 8 秒，参考码率为 175 Mbps，预计大小为 175 MB。

## 验收依据

| 验证范围               | 必须能够证伪的行为                                                                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公共格式、导出及加载。 | 三种码率形式和三种时长方法合法；缺失整个估算对象仍合法；空对象、`null`、额外字段、混用形式、未知方法、非法路径和非法常量拒绝整份说明。                                  |
| 数据选择与引用。       | 相同类型名称在不同设备或动作下按精确作用域匹配；特殊成员名按路径解码；引用只读取当前参数自身的值。                                                                      |
| 数值与单位。           | 普通录像 130 Mbps、60 秒得到 975 MB；延时摄影 6000 秒、25 秒间隔、30 fps、175 Mbps 得到 8 秒和 175 MB；非整除采集比例不被取整；预计帧数方法和固定时长方法使用正确单位。 |
| 无法估算的分区。       | 覆盖状态表中的缺失、未选择、未完成、无效、查表不匹配和无有效计算结果；不产生零值、旧值或替代档位。缺省值不隐式补齐输入。                                                |
| 浏览器编辑组合。       | 表单、JSON、预设、类型切换、动作增删、草稿重开及能力重载使用当前对应内容；相关祖先或选择字段未完成时撤下数值，无关输入不影响当前结果。                                  |
| 副作用与恢复。         | 估算不修改或保存草稿，不改变自动预览资料，不进入导出的计划或报告；加载失败不启用部分说明，保留旧说明时明确实际使用来源；重载结果尚待核实时暂停，取得新的状态观察后按实际启用说明恢复。 |
| 展示。                 | 大小和时长带预计含义，单位正确；正数不会显示为零；错误原因包含对应事实和路径。具体阅读文案按既有测试规范验证结构和事实。                                                |

单元测试验证纯选择、引用、计算及状态分类，使用受真实接口约束的输入或测试替身；组件间导出、加载和真实浏览器编辑协作使用集成测试。真实相机实测不作为这组软件验收的前提。

## 实施状态与设备接入前提

本文件描述目标行为。公共 Schema、驱动导出及客户端估算功能尚未实施；本文件中的新增字段样例不能作为当前版本可加载的能力说明直接使用。

实施时将机器字段及样例加入根协议，并在相应能力、驱动和客户端责任专题引用本规则。内部模块、函数名称与文件划分由后续实施计划依据实际数据流提出。

真实相机的参考码率须在对应参数类型中明确模式、档位和统计范围后接入。现有[硬件交接记录](../../hardware/camera-control-handoff.md#码率和图片大小记录)提供候选记录，但部分设置的有效性及 OSMO 各记录的统计口径仍需核实。任务期望大小与公式吻合不等于完成了实际文件测量。
