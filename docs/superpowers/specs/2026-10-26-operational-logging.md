# 关键阶段、外部命令与性能明细日志

## 级别和格式

camctl 的关键业务阶段和全部外部工具调用使用 `INFO`。数据库事务、历史核对、逐页保存、基准准备推进等纯耗时明细使用 `DEBUG`。实际错误继续由原结果消费者或监督入口按[全局错误诊断责任](../../architecture/logging.md#全局错误诊断责任)记录，阶段日志不能代替或重复该责任。

正常日志逐行使用 JSON，公共字段为 `level`、`logged_at_utc`、`pid`、`stage`。时间采用带 UTC 时区的 ISO 8601，在生产记录时冻结；`pid` 表示产生记录的 camctl 进程，不使用相机工具的产品编号。阶段及命令另外包含 `event`，适用时携带 `elapsed_ms`。原有错误诊断保留完整错误、异常图和字节事实，不将其再次编码为消息字符串。普通文本及第三方记录保留原文，同时使用相同的公共 JSON 字段；格式化通道自身失效时沿原降级规则保留事实。

业务身份只使用调用方已经掌握的 `database_id`、`session_key`、`action_id`、`activity_id`、`run_id`、`attempt_id`、`report_id`、`job_id`、`copy_id`、`delivery_id`、`file_id` 等字段。未知字段省略，不为日志查询数据库或从命令参数猜测身份。子任务和文件线程沿实际工作继承上下文，不串用并发动作的身份。

## 外部工具

每次受管外部工具启动成功后记录一次开始，确认本地进程退出及输出收场后记录一次返回。启动失败记录实际启动失败，不写成已执行。记录实际 `tool_argv`、调用期限及本地退出、取消、超时或输出错误事实；相同进程内的 `tool_call_id` 关联开始和返回。设备驱动已知的逻辑 `command` 单独保留，不将其冒充主机实际 argv。stdout、stderr 和媒体内容不进入普通命令 INFO，实际错误仍由原诊断入口交付。

工具返回只证明本地调用结束；零退出不证明设备设置或拍摄成功。启动前拒绝、缓存复用、等待重试和撤回的工作不产生工具已执行记录。流式 ADB、恢复、哈苏及媒体工具共用相同受管启动入口。报告工作进程另记录工作进程阶段，不伪造 shell 命令。

## 关键阶段

关键阶段在实际工作开始和返回时记录；抛错或正常取消保留实际结束分类。返回一份含错误的业务结果仍是一次实际返回，不能仅凭无异常将阶段写成业务成功。可靠提交、设备确认等更强结论只能在原拥有者实际取得相应依据后记录。

| 范围 | INFO 边界 | 保持安静的分支 |
| --- | --- | --- |
| 会话与受理 | 命令开始、受理处理、会话收场完成 | 轮询、等待唤醒与空候选 |
| 拍摄 | 实际设置准备、START、STOP、结果核实轮次及首次完成 | 相同准备或保存申请的重复等待、逐页和事务耗时 |
| 取回与交付 | 动作开始、完整副本准备、交付发布与动作完成 | 逐段读取及未到执行资格的推进 |
| 清理、取消与电机 | 实际成员处理、停止或撤回、通知发送与已取得的结束结果 | 无新成员、重试间隔和终态重查 |
| 报告与恢复 | 实际报告生成、发布、软件恢复阶段与原责任恢复 | 无报告变化的检查、既有结果保存重送 |
| 文件与后台维护 | 实际文件任务及快照任务开始、返回 | 空维护轮次、清单扫描和成本统计 |

INFO 与 DEBUG 都是辅助日志，继续使用既有级别过滤、队列水位、采样和丢弃规则。记录不增加持久化状态、不等待落盘、不阻挡必要停止，也不改变工具调用、重试、取消、恢复或结果保存。

## 验证

单元验证公共字段、级别、原返回和异常不变、并发身份隔离、原 ERROR 结构、实际命令起止、启动失败及取消收场。阶段验证观察公开消费者交付的日志，覆盖真实工作、空轮询、原申请重送及新的实际尝试。组合真实日志通道与本地受管工具，验证 INFO 配置下命令记录存在而 DEBUG 明细被过滤，并保留既有错误诊断和资源收场。软件检查不代替相机验收。
