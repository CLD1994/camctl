# Hasselblad CFV 100C 单张拍摄接口核验

## 环境与范围

2026-10-12 在 ARM64 Ubuntu 18.04.6 开发主机上，通过 USB 直接调用现有 `hb_cli` 二进制，核对环境检查、参数读取、图片列举和一次单张拍摄。记录脚本使用 Python 3.11.17；相机报告固件 `v4.1.0`。

核验对象是工具与真实相机之间的接口。camctl 驱动、正式产物登记、独立取回及状态报告属于后续接入验证范围。

工具使用说明见 [hb_cli 使用说明](../../hardware/hasselblad/hb_cli.md)。本次二进制的 SHA-256 为 `b29be2fc6861e1de0192bb8c191cf5594198c996507032cc69f039f53908b18b`；后续换用二进制时须重新核对用于机器解析的返回格式。

## 环境检查与只读接口

相机接入后，USB 标识为 `2756:000a`。普通用户最初打开设备时收到 `LIBUSB_ERROR_ACCESS`；主机已有使用说明中的 udev 权限规则。重新加载规则并对该 USB 设备触发更新后，设备节点权限变为 `0666`，`doctor` 返回退出码 0，并输出 `doctor: PASS`。

实际命令帮助由不带参数的调用输出，该调用退出码为 1。帮助列出 `--pid <hex>`，用于按 USB 产品标识限制目标；图片下载接受完整相机路径或文件名。该版本对 `--help` 返回 `unknown flag: --help`。

| 调用 | 实际返回 |
| --- | --- |
| `list` | 每台相机一行，包含 `vid`、`pid`、USB `bus` 和 `addr` |
| `info` | 包含序列号、固件、曝光、ISO、光圈、快门、白平衡和对焦等信息 |
| `get drive-mode` | `param[65] = Single` |
| `get capture-format` | `param[128] = I2,0,1`；本次拍摄实际产生 3FR 文件 |
| `images` | 每个条目包含格式标识、原图字节数和完整相机路径，例如 `3FR 211562496 /SSD/100HASBL/B0000255.3FR` |

以上成功调用退出码均为 0。USB 无设备或打开设备被拒绝时，`doctor` 返回退出码 2；设备权限被拒绝时，`info`、`images` 和参数读取也返回退出码 2。调用错误的输出通道随命令而异，应分别保存 stdout 和 stderr。

## 单张拍摄结果

本次拍摄使用相机已有曝光与对焦设置，拍摄模式为 `Single`。调用 `capture --output <本次独立目录>` 后，工具在约 12.18 秒内退出，退出码为 0，stderr 为空。stdout 为：

```text
capture: OK
saved <本次独立目录>/capture_22544386.3FR (211222528 bytes)
saved <本次独立目录>/capture_22544386.3FR.thumbnail.jpg (689251 bytes)
```

主机上的两份文件均存在，实际大小与工具返回值一致。原图的头部为小端 TIFF 标识，缩略图的头部为 JPEG/JFIF 标识。

| 文件 | 实际字节数 | SHA-256 |
| --- | ---: | --- |
| `capture_22544386.3FR` | 211222528 | `fe9e984fce514ad1435eddb604bb737751bee77df47ecf7ddc902c229f1fc9d3` |
| `capture_22544386.3FR.thumbnail.jpg` | 689251 | `6634ee0383d33dcc282d94bc15b6cdce56edac29e7f2d59aa30d0b01518ecf82` |

拍摄前后分别调用 `images`，两次返回的 11 个条目完全一致，没有新增相机存储条目。本次证据只能确定工具已向主机保存两份文件，不能据此建立相机端正式源文件的关联，也不能推断其他配置下的相机保存行为。

## 接入需要落实的边界

当前正式产物规则由[正式产物与取回清理](../../architecture/outputs.md)定义，原片和预览通过设备文件承载，主机文件的正式承载目前用于修复成品。单张拍摄的主机文件接入需要明确其保存位置、业务归属、完成依据、原图与缩略图配对、长期保留、独立取回和重启恢复规则。

本次成功调用提供了可用于适配的返回样式；超时、中断、部分文件、保存成功后进程中断等分支仍需软件验证及适用现场核验。结果未知时沿原拍摄责任核实，不再次发送拍摄命令。
