## 整理结果

行为与实现规则由对应责任专题完整维护；导航、样例和组件使用说明改为引用权威契约。已由实现专题定义的细节不再写成“待细化”，实施任务从[路线图](../plans/2026-09-30-camctl-implementation-roadmap.md)核对；各日期的验证记录保留当次环境和范围。

正式源文件按驱动契约保存在设备或主机，客户端媒体说明区分图片预览和视频播放，并共用已实现的接收、关联、完整性核验与保存规则。数据库整体格式、事件格式及报告格式分别解释，不因新建格式变化否定旧格式的既有业务边界。

Action6 普通录像和 Hasselblad 单张拍摄的结果按[设备与部署验证记录](../../camctl/verification.md#部署交接与待核验项)使用各自证据范围。当前相机调试从[T9](../plans/2026-10-10-camctl-real-camera-demo.md#t9-设备事实补齐与-arm-linux-完整验收)跟踪；第三方实际接入、目标资源及物理断电仍是独立待核验范围。

源码对照发现的软件遗漏已登记为[SW-01—SW-06](../plans/2026-09-30-camctl-implementation-roadmap.md#文档复核发现的实现缺口)，有效规格保持，未将静态审阅结论写成修复通过。软件验收映射按具体用例修正过期前提，并补入主机原图与预览的配对登记及格式边界；当前结论以[逐项映射](../../camctl/software-acceptance.md)为准。

## 主 Agent 的逐文件复核

同日由主 Agent 亲自复核本批全部 71 个变更文件，包括本记录及沿引用补正的初始化、实现总览。复核逐文件阅读差异和相关上下文，并追踪责任专题、实际生产调用方、测试断言与现场记录；逐文件依据和结论保存在 `.local/docs-review/root-file-review.md`。机械测试执行由子代理承担，其输出由主 Agent 核对；业务判断由主 Agent 完成。

报告的旧覆盖、可衔接覆盖及缺口分类集中定义在[客户端接收与连续覆盖](../../architecture/status-reports.md#客户端接收与连续覆盖)，客户端页面说明引用该精确判定。参数开放与真机逐项确认、媒体一致性核验与浏览器解码、普通产物副本与报告文件的处理范围分别保留明确边界；部署依赖按实际驱动组织。

W-11 和验收 13 保留为部分覆盖：前者的默认读取发现仍需分批处理，后者的分项测试尚不能证明全部交错顺序。实际源码缺口与所需组合验证见路线图及软件验收映射。日志任务同时覆盖副本与标记诊断，以及两类旧文件的启动清理，不仅检查标记进度或临时文件。
