本次以 `b8bb4f3` 为基线，沿能力加载、设备／动作／参数类型选择、表单生成、选项联动、草稿保存和后端导出复核。输入包括当前本地 OSMO 360 II／Hasselblad 能力 JSON 及客户端通用夹具，哈苏采用主机正式源。环境、命令和实际结果见[验证记录](../../client/verification.md#设备能力解析与选项联动复核2026-10-18-utc)。

契约依据为[能力选择与校验](../../architecture/capabilities.md#客户端选择与校验)、[表单生成](../../architecture/client-editing.md#根据-schema-生成表单)、[选项联动](../../architecture/client-editing.md#参数选项联动)及[对象级联编辑](../../architecture/client-editing.md#对象参数级联编辑)。

## 问题一：级联控件缺少对象和当前模式说明

**触发与影响：** [ObjectBranchField](../../../apps/client/src/web/ObjectBranchField.tsx)的普通表单展示标题、模式和子成员，却不展示对象 description 或当前判别字段 description。OSMO 两个任务均已通过实际页面复现；没有子成员时选择器下方直接进入折叠的完整规则。任务总说明仍可见，参数选择和导出正确。

**根因与契约：** 控件只从首个分支读取判别字段标题，未消费对象和当前模式说明；普通子成员使用的 Field 已展示说明。字段含义与固定事实应来自同源 Schema，普通阅读不应依赖展开技术规则。这是客户端通用展示的原有缺口。

**修复建议：** 通用对象控件显示对象说明及当前分支的判别字段说明，共同审计分支自身说明和标题。未选择模式时仅显示公共说明；保持成员行为，不维护相机专属文案，不向草稿补值。

**验证：** 覆盖仅含模式与含子成员两种结构，核对说明来源及切换后对应关系；其他模式说明不冒充当前说明。查看、切换、刷新及能力重载保持参数、分支资料和未完成原文。真实 OSMO 页面复测。

## 问题二：能力源测试错误要求模式包含额外成员

**触发与影响：** 当前两设备文件通过 CAMCTL_TEST_CAPABILITIES_FILE 注入[元数据用例](../../../apps/client/tests/integration/browser-camera-parameters.test.ts)后，用例选中 OSMO 录像，再寻找手动分支中非 mode 的枚举字段。合法分支只有 mode，查找返回 undefined，解构时抛出 TypeError；失败发生在页面创建之前。同次仅模式曝光／码率用例通过。

**根因与契约：** 顶层选择只要求枚举和 exposure.oneOf，后续却要求首个分支具有枚举子成员。有效能力允许仅选择模式和固定任务，验证入口需要覆盖各自结构。这是测试结构假设，不能据此判断产品解析失败。

**修复建议：** 按实际结构分别验证判别字段、存在的成员及无成员分支，遍历适用任务；不依赖首个录像任务的形状，也不跳过两设备目录。审计同类能力源夹具选择条件。

**验证：** 默认合成目录、当前两设备目录和包含 Action6 的安装版目录运行同一目标；元数据断言真实执行，页面和导出继续通过。

这两项分别属于元数据呈现和测试输入分类，可按上述独立依据串行修复，无需改变公共协议、驱动选项或草稿状态契约。本次记录问题和证据，未修改客户端生产代码及测试。
