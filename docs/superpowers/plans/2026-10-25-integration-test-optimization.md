# 集成测试耗时优化计划

## 目标与基线

优化范围为 camctl 的全部组件集成目录、根目录跨组件 pytest 与 Node 集成测试。基线证据由[逐项耗时报告](../../camctl/integration-test-timing-2026-10-25.md)及其数据文件维护：10,394 个有效主实例，10,351 通过、38 失败、5 跳过；首轮串行进程耗时合计 8,773.415 秒。历史失败不是允许删除的覆盖。

优化必须回答四个问题：哪些断言在其他测试中已有等价证据；哪些局部合同应由单元测试验证；哪些准备、核验或等待造成异常耗时；哪些任务可在真实资源隔离后并行。实现应保持真实事务、安装、恢复、文件生命周期与各有效状态分区。只调整日常选择不能计作完整集成验收提速。

实施起点为 `266a4639`。解释器按部署要求使用 Python 3.11；每次记录实际工作区、命令、版本、日志、退出码和计时口径。历史单次采样用于选目标，不能直接充当新环境下的严格性能对照。

## 执行步骤与验收

以下文件划分为建议，具体改动依代码事实调整。各步骤可独立推进，合并前按对应目录运行指南验证；同一工作区一次只启动一个组件集成 pytest。

### S1：确认覆盖归属与准备合并

- [x] 合并 history 两个 220 成员快照世界、reporting 两个相同缺段来源，逐条映射保留的断言与失败阶段。
- [x] 按真实初始状态复用 cancellation 的只读／回滚拒绝矩阵；每个拒绝要求明确回滚、无活动事务、数据库与取消标记不变，成功提交保留独立世界。
- [x] 核对 acceptance、host_files、bootstrap 的纯局部断言。已有等价单元证据才删除；迁移用例保持同进程且不访问真实外部边界。安装、实际资源登记与文件操作保留集成见证。
- [x] 复用安装版 describe 等只读输入，核对 outputs 候选扫描、contracts 语法树与 capture 跨页准备的收益及独立性。

验收：保存修改前后受影响目标的实际结果与耗时、测试节点变化及合同映射；不以减少节点数代替减少覆盖。阶段改动独立审查后提交。

### S2：诊断并优化主要耗时

- [x] 审计四项容量测试及 native 结果链，分开记录世界构造、被测操作和验证成本；核对同结果页关系证明的重复次数及可复用边界。
- [x] 实施有证据支持的优化。保持原规模、页／批／磁盘缓存边界、内存和查询增长断言；不得替换真实提交、取消守卫或缩小原门槛。
- [ ] 修复已确认的测试夹具接口漂移及成功／恢复场景的时钟前提，并让等待准确识别本请求的不相容终态或执行错误，保留正常成功预算和原成功断言。接口与等待修正已通过，最终运行另暴露的时钟前提正在补齐。

验收：保留可证伪的正确性与失败证据，明确测试成本和生产成本；涉及生产行为或未定义语义的改变按设计缺口规则处理。其他原有失败分类交接，不通过删除或放宽断言隐藏。

### S3：建立隔离并行运行入口

- [x] 按实际共享边界设计工作区、包资源、临时根、客户端／C 构建和工具环境的隔离；组件目录仍各自启动 pytest，根目录按模块或场景分组。
- [x] 提供可复现的运行入口和进度／退出码记录，测试清单从真实收集结果或目录发现生成，避免另抄完整清单。

验收：每个目标恰好分配一次，失败准确传递，日志能定位执行目标；文档明确前提与命令。完整并行墙钟与各任务耗时分开记录，调度估算不能冒充测量。

### S4：形成长期规范并完成组合验收

- [x] 将根因与实际收益整理为验证记录，按重复准备、测试层级、等待、生产复杂度、串行调度分别归因。
- [x] 将可复用经验写入测试规则和组件运行指南：最小真实协作见证、只读基线与独立消费者、边界规模、确定同步点、负向完成信号及计时证据。
- [x] 审核所有候选，明确已实施、无需改动、收益较小或仍需设计决定的项目；更新本计划原步骤的进度与证据。
- [ ] 对最终合并树完成受影响组合验证、文档链接检查及完整范围结果核对，逐项审查用户目标后结束任务。
