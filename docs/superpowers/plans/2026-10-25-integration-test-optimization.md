# 集成测试耗时优化计划

## 目标与基线

优化范围为 camctl 的全部组件集成目录、根目录跨组件 pytest 与 Node 集成测试。基线证据由[逐项耗时报告](../../camctl/integration-test-timing-2026-10-25.md)及其数据文件维护：10,394 个有效主实例，10,351 通过、38 失败、5 跳过；首轮串行进程耗时合计 8,773.415 秒。历史失败不是允许删除的覆盖。

优化必须回答四个问题：哪些断言在其他测试中已有等价证据；哪些局部合同应由单元测试验证；哪些准备、核验或等待造成异常耗时；哪些任务可在真实资源隔离后并行。实现应保持真实事务、安装、恢复、文件生命周期与各有效状态分区。只调整日常选择不能计作完整集成验收提速。

实施起点为 `266a4639`。解释器按部署要求使用 Python 3.11；每次记录实际工作区、命令、版本、日志、退出码和计时口径。历史单次采样用于选目标，不能直接充当新环境下的严格性能对照。

## 执行步骤与验收

以下文件划分为建议，具体改动依代码事实调整。各步骤可独立推进，合并前按对应目录运行指南验证；同一工作区一次只启动一个组件集成 pytest。

### S1：确认覆盖归属与准备合并

- [x] 合并 history 两个 220 成员快照世界、reporting 两个相同缺段来源，逐条映射保留的断言与失败阶段。
- [x] 按真实初始状态复用 cancellation 的只读／回滚拒绝矩阵；每个拒绝要求明确回滚、无活动事务、数据库与取消标记不变，成功提交保留独立世界。
- [x] 核对 acceptance、host_files、bootstrap 的纯局部断言。已有等价单元证据才删除；迁移用例保持同进程且不访问真实外部边界。安装、实际资源登记与文件操作保留集成见证。
- [x] 复用安装版 describe 等只读输入，核对 outputs 候选扫描、contracts 语法树与 capture 跨页准备的收益及独立性。

验收：保存修改前后受影响目标的实际结果与耗时、测试节点变化及合同映射；不以减少节点数代替减少覆盖。阶段改动独立审查后提交。

### S2：诊断并优化主要耗时

- [ ] 审计四项容量测试及 native 结果链，分开记录世界构造、被测操作和验证成本；核对同结果页关系证明的重复次数及可复用边界。
- [ ] 实施有证据支持的优化。保持原规模、页／批／磁盘缓存边界、内存和查询增长断言；不得替换真实提交、取消守卫或缩小原门槛。
- [ ] 修复已确认的测试夹具接口漂移，并让等待准确识别本请求的不相容终态或执行错误，保留正常成功预算和原成功断言。

验收：保留可证伪的正确性与失败证据，明确测试成本和生产成本；涉及生产行为或未定义语义的改变按设计缺口规则处理。其他原有失败分类交接，不通过删除或放宽断言隐藏。

### S3：建立隔离并行运行入口

- [ ] 按实际共享边界设计工作区、包资源、临时根、客户端／C 构建和工具环境的隔离；组件目录仍各自启动 pytest，根目录按模块或场景分组。
- [ ] 提供可复现的运行入口和进度／退出码记录，测试清单从真实收集结果或目录发现生成，避免另抄完整清单。
- [ ] 用实际并发执行验证隔离及调度。运行全部范围取得新的墙钟、逐项结果和失败分类；有效范围必须包含容量测试及完整 Hasselblad 矩阵。

验收：每个目标恰好分配一次，失败准确传递，日志能定位执行目标；文档明确前提与命令。完整并行墙钟与各任务耗时分开记录，调度估算不能冒充测量。

### S4：形成长期规范并完成组合验收

- [ ] 将根因与实际收益整理为验证记录，按重复准备、测试层级、等待、生产复杂度、串行调度分别归因。
- [ ] 将可复用经验写入测试规则和组件运行指南：最小真实协作见证、只读基线与独立消费者、边界规模、确定同步点、负向完成信号及计时证据。
- [ ] 审核所有候选，明确已实施、无需改动、收益较小或仍需设计决定的项目；更新本计划原步骤的进度与证据。
- [ ] 对最终合并树完成受影响组合验证、文档链接检查及完整范围结果核对，逐项审查用户目标后结束任务。

尚未取得本轮改造后的耗时，当前没有省略容量测试或缩减正常链参数组合。

S1 的 contracts 已实现真实源码与语法树共享，规则和合成反例保持独立。完整目录修改前后均为 442 passed；外层墙钟分别为 14.466／11.330 秒，详见[优化记录](../../camctl/integration-test-optimization-2026-10-25.md)。其他 S1 项尚未完成，不能据此勾选整步。

六项独立任务已在各自 worktree 并行推进：快照／报告、取消矩阵、单元归属／安装输入、慢结果证明、跨组件等待、隔离运行入口。取消目标文件初测从 111 个节点合并为 47 个，全部输入组合保持，世界准备从 86 次降至 22 次；50.121／24.912 秒仅为执行分支初测，完整目录与协调者复核待完成。S2 的源码追踪确认部分原页读取先后两次进入整页核验，正在量化实际重复次数，生产代码尚未更改。

### 2026-10-25：取消矩阵集成与 S2 根因收敛

S1 的取消矩阵已通过完整目录 332 项、100.265 秒、退出 0，协调者独立核对补丁、原参数展开及 XML 后集成。目标文件的检查组合不变，减少 64 次世界构造，详细证据由[优化记录](../../camctl/integration-test-optimization-2026-10-25.md)维护。下一项准备复用检查 outputs 候选扫描及 capture 跨页目录轮换。

S2 的 native `[tail-False]` 计数诊断确认：同一原结果页进入 `_verify_page_relations` 8,909 次，主要发生于结果推进；带诊断包装的耗时不能当作纯性能基线。按[既定缓存契约](../../camctl/persistence-runtime.md#缓存范围与候选扩展)，实施有界的已提交不可变原页证明复用：只在同连接的单次真实事务内生效，只接纳开始时已完整提交的原页，容量限定为首批／当前／相邻页；事务结束即释放。候选 APPEND 不缓存，当前尝试范围、固定历史、文件归属和完成／配对、动态资格及独立提交守卫仍核验。跨事务、连接、损坏原页、未知提交与新候选必须由明确反例检验，正确性证据先于扩大容量测试；该改动不增加业务状态或改变错误分类。

### 2026-10-25：S1 集成完成，核对 S2／S3 独立边界

S1 的快照、报告、安装版能力输入、局部覆盖归属及候选扫描／跨页合并均已阶段验证并集成，具体前后耗时和合同映射集中在[优化记录](../../camctl/integration-test-optimization-2026-10-25.md)。contracts 最终逐模块计算规则事实后释放语法树，442 项通过，墙钟 9.825 秒；独立脚本按基线重算 306 份源码的五类事实，逐项相等。

S2 的扩大 persistence 验证发现既有“提案之后损坏原依据”矩阵有四项回归：同事务缓存不能让提案证明代替独立守卫重新核验。因此每个有限／有界事件在提案上下文形成后、独立读取及校验前清空页证明，保留同一次守卫内部的有界复用；修正后的 12 项原矩阵及 9 项缓存反例全部通过，完整 unit、native 与增长复验继续进行。该生产阶段尚未集成，不能据窄通过宣称完成。

S2 的失效任务工厂已在执行分支同步 `result_mode`，清理正常及取消恢复代表通过；六动作终态失败仍保留，明确诊断从 184.70 秒降到 6.89 秒。S3 入口的组件／SQL／Node／OSMO 冒烟及四项运行器契约通过，独立审查还发现完整 Hasselblad 模块需要仓库外客户端，正在补齐该隔离输入及真实参数实例验证。待两项阶段边界闭合后集成并启动完整并行回归，不重复已通过的无关目录。
