# 已保存拍摄结果的收尾恢复

## 目标与契约

RESULTS（拍摄结果核实）尝试的实际结果已经可靠保存后，后续集合整理可能尚未完成。恢复必须先消费原结果，不能仅因流程仍未结束而申请新尝试。重试依据沿用[重试等待规则](../../camctl/database/waiting.md#重试责任的完整转换)，累计次数、原返回、原错误和已保存页保持不变。

| 原可靠状态 | 恢复行为 |
| --- | --- |
| 最新尝试仍在执行 | 沿原拥有者及已有恢复依据处理，不提前新开尝试。 |
| 最新尝试已结束，流程要求重试 | 先恢复原文件子责任，等待本次间隔并检查原预算，具备资格后才申请下一轮。 |
| 最新尝试已结束，流程未要求重试 | 先恢复原文件子责任，返回经原校验的 `CLOSED`（原结果已保存）输入，由所属消费者继续收尾。 |
| 分段集合已经建立 | 继续原集合整理，不增加 RESULTS 尝试。 |
| 原结果或文件子责任无法可靠恢复 | 保留原异常及申请，停止依赖它的推进。 |

有无分页不改变上述阶段分类。正常响应成功但结果仍不完整时，首次保存原结果的事务已经建立重试要求，不能把这种状态当成无需重试。普通录像、单张、延时及分段结果共用原结果恢复入口，保留各自消费者的完成规则。

## 实施步骤

1. [x] 用受接口约束的数据库与仓储替身，证明已有失败结果、未建集合且未要求重试时，旧代码仍尝试申请新轮。覆盖有页、无页、原错误、重试间隔和在途尝试。
2. [x] 在公共结果轮次入口按可靠阶段恢复；复用原结果解码、票据与页核验，保持原事务守卫及正常重试逻辑。建议在现有原页发现查询中同时读取原重试标记，避免增加独立查询。运行拍摄与装配单元回归，并独立审查同类消费者。
3. [ ] 提交修复，构建并更新当前真机验证环境中的 camctl，核对发行物、安装内容、依赖及状态库和配置摘要，保留旧安装以便回退；由用户执行真实设备验证。本次不运行集成测试或发出设备命令。
