行为以[通用日志接口](../specs/2026-10-27-general-logging-api.md)及现有日志责任为准。文件与提交拆分是实施建议，不能改变入队、错误身份、取消、必要停止和字段语义。

1. [ ] 补诊断组件的单条接纳及终态通知，覆盖已有拥有者、正在接纳、副本预留及取消，保持原诊断和副本行为。
2. [ ] 提供统一 await Logger 和低级别同步 Logger，复用上下文及标准消息语义，公开工厂与完整 JSON 输出。
3. [ ] 接通实际协程及同步业务使用者，补真实队列、文件、stderr 和业务入口组合，完成独立审查及文档使用示例。
4. [ ] 合并后验证相应单元及组件集成，记录实际范围、失败归因和交付状态。

## 执行边界

先提交已确定的接口规格，再在独立工作区并行实现诊断接缝与通用调用层。双方公共接口确定后组合；上下文接线及生产调用方按依赖集成。不迁移所有结构化阶段和错误调用，不重写已有生命周期。

## 进度

用户选择协程统一 `await logger.info()/error()`，另提供同步入口。现有通道、阶段和完整错误诊断已具备；通用 Logger 及单条等待接缝待本计划落实。
