# 读取会话结束与停止确认

## 行为契约

设备读取会话通过 `read_chunk()` 提供数据，通过 `request_stop()` 请求停止，通过 `wait_stopped()` 向业务流程提供结束依据。相机读取机会只有在实际读取及适用重试结束后才能释放；关闭错误不能转换成停止成功，也不能使调用方永远等待已经返回错误的关闭操作。

依据：[读取接口](../../camctl/file-runtime.md#设备驱动接口契约)、[相机拷贝并发限制](../../architecture/file-copy.md#同一相机的拷贝并发限制)和[读取机会](../../camctl/database/waiting.md#相机读取机会与未完成责任)。本任务不扩大底层调用持续不返回的故障范围，也不改变业务尝试和机会归属。

| 读取及关闭情况 | 数据调用结果 | 停止等待结果 |
| --- | --- | --- |
| 读取仍在进行，或者源关闭尚未返回 | 保留在途调用 | 继续等待，不能确认停止。 |
| 全部内容读完，关闭成功 | 返回实际数据和 EOF | 返回停止成功及实际读取字节数。 |
| 停止请求或无数据超时，关闭成功 | 返回对应结束原因 | 返回停止成功，保留结束原因。 |
| 源读取抛出异常，随后关闭成功 | 保留并抛出原读取异常 | 返回停止成功，结束原因是读取失败；不表示内容读取成功。 |
| 关闭抛出异常 | 抛出实际关闭异常；若读取也抛错，则同时保留两个异常 | 抛出关闭异常，不返回停止成功。之后的观察继续保留该失败。 |
| 停止请求失败，读取仍在途 | 请求方取得实际异常，原读取继续跟踪 | 不由停止请求失败推定调用已结束。 |
| 停止请求失败，但没有在途读取 | 请求方取得实际取消异常；独立结束责任仍在工作线程执行关闭 | 返回实际关闭结果；取消异常与关闭异常分别在各自入口保留。 |
| 一个等待者被取消 | 只取消该等待，不改变会话或关闭操作 | 其他及后来的等待者仍能取得同一结束事实。 |
| 停止请求遇到在途读取，读取随后返回非 EOF 数据 | 保留本次实际数据，不要求消费者再调用读取来触发关闭 | 独立结束责任取得读取锁后执行关闭，停止请求成功或失败都不丢失这一责任。 |
| 空闲时请求停止，关闭需要有限时间 | 停止请求不在事件循环内等关闭；重复请求复用同一结束责任 | 关闭返回前继续等待；此时事件循环仍可推进必要控制。 |

关闭操作由持有读取锁的责任方执行一次。停止请求建立每会话唯一的结束任务，在默认线程池取得读取锁并关闭，覆盖读取返回与锁释放之间的交接。源端 `cancel()` 只发送停止信号，不能等待实际读取结束；其错误由 `request_stop()` 抛出。关闭错误由 `wait_stopped()` 抛出，不能要求非阻塞请求同步取得未来的关闭结果。正常读取路径在工作线程关闭时，读取调用仍可以直接取得关闭错误。

停止请求与关闭成功后的重复观察不重新调用源端。停止信号与关闭使用同一控制锁协调；停止请求不等待已在进行的关闭。取消等待者后，asyncio 包装 Future 仍有异常观察责任，共享完成事实继续供其他等待者取得。

## 实施安排

以下模块和内部实现是建议，实际实现可以调整，但须保持上表及资源责任。

1. [x] 源读取异常、关闭异常与双重失败的单元反例验证错误出口可观察且不伪造停止成功。源端使用受 `SourceStream` 接口约束的替身；不以真实等待耗时作为单元测试依据。
2. [x] `ReadSession` 使用标准库 `concurrent.futures.Future` 和 asyncio 适配传递线程完成结果；等待取消不取消共享完成事实，不为每个等待者创建额外常驻线程。
3. [x] 正常结束、停止、超时、读取及关闭失败、多等待者取消分别验证。实际工作线程与同步事件覆盖非 EOF 返回与锁交接、关闭返回前继续等待、控制协程继续运行及关闭失败通知既有等待者。真实分段函数停止新增读取后，会话仍能结束；测试失败出口也等待实际收场。
4. [x] 读取会话、分段传输及相关单元和集成测试通过 Python 3.11 回归，错误传播与资源释放经过独立复核，主路线图记录对应局部门禁。相机机会事务继续保持未完成，不能以会话测试代替数据库授予和释放验收。

## 验证证据与后续边界

Python 3.11 与 3.12 的 `tests/unit/devices`、`tests/unit/host_files` 各通过 158 项。保留既有 `test_source_stream_protocol_shape` 的 asyncio 标记警告。两版的读取会话及分段传输集成范围各通过 22 项，包含 11 项结束协调用例；单元与集成测试分别运行。事件循环异常处理器验证被取消的等待包装器不会产生未消费异常，而其他等待者仍能取得实际关闭失败。

独立复核核对结束任务的唯一性、读取锁与控制锁的次序、异常观察责任，以及非 EOF 数据返回后的关闭交接。[分段结果契约](2026-10-03-camctl-segment-results.md)规定分段函数保留读取异常、已确认写入范围及独立关闭结果。源端真实驱动接入、相机机会数据库事务与完整业务运行流程仍有独立门禁。
