# 开发环境恢复、测试提速与统一交付计划

目标：在更新后的开发容器中恢复可运行的锁定环境，完成遗留测试提速，再交付相互匹配的 CLI、客户端和 host 开发验证环境。

本计划接续[来源失败计划的步骤 5](2026-10-24-source-action-failed.md)、[基准恢复计划的安装交付](2026-10-24-baseline-waiting-recovery.md)和[host 失败诊断计划](2026-10-24-host-exit-log.md)。业务契约保持，旧数据库、诊断、报告和相机媒体保留；软件验证不调用真实设备。

## 步骤与验收

- [ ] **1：恢复运行条件。** 使用 Python 3.11 和符合 `docs/camctl/sqlite-runtime.json` 的实际 SQLite，按 `uv.lock` 安装开发与测试依赖；客户端按 `package-lock.json` 准备依赖及配套 Chromium。保存命令、解释器、环境路径、运行库检查与依赖检查结果。旧失效环境移入归档。
- [ ] **2：完成测试提速。** 审查 `audit/test-speed-capture` 的候选提交，逐项核对迁移矩阵及保留的集成协作覆盖；定位 outputs 慢用例的具体耗时路径。先在当前代码取得可对照的覆盖和耗时，再实施最小改动，执行受影响测试及单元、capture 和 outputs 目录检查。集成目录在各自工作区内顺序运行。真实数据库、持久化、文件和协作验证保持；不得降低生产同步强度、缩减必要数据规模或放宽断言来换取速度。既有失败单独复核和记录。
- [ ] **3：构建并重建开发验证环境。** 从集成后的源码构建 wheel、客户端 ZIP 和 host；独立安装后核对生产文件、权威资源、锁定依赖、能力说明及发行摘要。执行 host 完整 CTest、客户端类型检查、单元测试及来源报告导入和浏览器检查。确认相关会话结束，使用新目录初始化主机状态库与客户端数据，通过安装版 CLI、host 和真实客户端完成无设备检查。保留现有归档及恢复快照。
- [ ] **4：记录与交付。** 将新环境证据写入各组件验证记录，按实际验收结果更新上述三份原计划。交付资料给出启动命令、配置、数据目录、能力说明和发行物位置，并明确软件检查、真实设备复测及目标硬件验收的边界。

步骤 2 依赖步骤 1 的可执行环境；独立只读审查可以提前进行。步骤 3 使用已审查并集成的提速改动，步骤 4 依赖安装与运行证据。内部环境目录、辅助脚本和提交拆分由实施时决定。
