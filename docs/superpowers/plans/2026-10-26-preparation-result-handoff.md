# 拍摄准备结果交付与窗口观察修复

## 目标与已确认事实

录像提前准备成功后，设备后台任务与主循环可能同时保存同一份准备结果。数据库执行器以业务操作键覆盖等待句柄，导致最初的调用者永久等待，无法继续基准读取与 START；过期收场也无法释放相机，后续同设备动作因而受阻。

真实样本中，计划在 21:09:12 受理，录像于 21:11:03 开始提前准备，21:11:08.410 保存设置成功，计划启动为 21:11:13，窗口结束为 21:11:15。准备保存以同一键执行两次；动作没有 START 责任，活动一直持有占用。后续 21:12:55 的延时摄影同样过期，没有建立设备活动。该现象已用实际执行器与假连接受控复现。第一窗口另有 145 次窗口观察事务，第二窗口有 414 次。

用户授权修复以上问题，验证限定为单元测试与发行安装核对，真实设备由用户手测；集成测试另由独立任务重构。

## 行为契约

业务操作键标识完整保存申请。实际提交与结果交付分别完成；入队、已经执行、已经提交都不能替代调用者取得真实回执。原申请核实须继续使用原键和完整输入。

| 原申请及调用状态 | 必须发生的行为 |
| --- | --- |
| 同一准备申请正在保存，设备拥有者与恢复入口同时推进 | 共用该申请的在途保存任务，可靠结果及拥有者状态应用完成后各自结束等待 |
| 等待者取消，保存已经开始 | 保存继续到实际结果；可靠状态应用完成后传播取消，不重复设备设置 |
| 保存失败或结果未知 | 交付原错误并保留原完整输入及键，后续核实按既有分类推进 |
| 执行器已有同键申请，尚未交付结果 | 新提交明确拒绝且不修改原队列、结果句柄及撤回责任；不通过键相等推断两个完整输入等价 |
| 原结果已经交付，再次按原键提交核实 | 按仓储的完整输入核实规则正常处理 |
| 拍摄准备可靠完成且时间有效 | 继续完成所需基准，到原计划时间才取得并派发 START |
| 动作取消或过期，实际调用及保存均收场 | 沿原准备释放规则解除占用，后续同设备动作可取得资格 |
| 当前时刻在窗口内，首次观察尚未保存 | 进入原观察事务，事务内重新核验事实 |
| 首次观察已经保存、窗口尚未结束 | 不为相同观察进入写事务；保留实际业务完成与窗口结束的唤醒 |
| 已超过启动窗口末尾 | 进入原过期事务复核，不延长窗口、不修改已过期动作历史 |

数据库契约由[数据库执行](../../camctl/persistence-runtime.md)维护；准备及收场由[拍摄提前准备](../specs/2026-10-25-capture-preparation-design.md)维护；时间、首次观察及唤醒由[调度执行](../../architecture/scheduling-execution.md)维护。

## 实施与验收

建议的文件拆分不固定内部接口。三个修复任务可在共同干净基线的独立 worktree 并行，按完成提交集成。每步先用受真实接口约束的假协作者建立失败用例，再实现和复核。

### 1. 数据库结果交付

- [ ] 同键申请处于队列、执行或结果待交付时，拒绝新提交并保留原等待者。
- [ ] 检查撤回、入队超时、关闭及错误交付，旧申请的迟到通知不能删除或完成后来复用同键的新申请。
- [ ] 单元覆盖 READ／WRITE、队列满载、已执行但通知未交付、撤回后复用、超时后复用、关闭与实际错误；不启动真实线程或连接数据库。

### 2. 准备拥有者的保存与收场

- [ ] 意图和实际结果使用同一申请的在途保存任务；设备实际返回与主循环恢复同时发生时，保存及状态应用只推进一次。
- [ ] 核对准备预留与结束申请的同类并发，保持原键和完整输入，避免合法恢复触发执行器重复提交拒绝。
- [ ] 单元覆盖并发、实际成功、取消和重复取消、失败及未知结果、恢复核实；成功后继续基准及 START，终态后收场释放，后续同设备动作可取得资格。

### 3. 窗口观察与调度空转

- [ ] 已保存首次观察且未到期时不再提交观察事务，首次观察及过期仍在事务内复核。
- [ ] 按实际唤醒来源消除无进展即时循环，保留任务完成、新计划、取消及时间截止的及时重决策。
- [ ] 用可控时钟及假协作者覆盖窗口起止、既有观察、终态、取消和异步任务完成；记录同条件重复轮次的事务次数。

### 4. 组合验收与交付

前三步集成后开展，不以某个局部通过代替组合验收。

- [ ] 独立评审核对各修复接缝、取消与结果交付、实际生产调用方及同类风险；处理未解决发现。
- [ ] Python 3.11 完整单元通过，记录命令、源码身份、日志及退出码；执行受控的原缺陷复现对照。
- [ ] 在停止的人工环境安装受测 wheel，源码／资源／发行物／安装内容逐项一致；保留数据库、计划、文件和配置，不重新初始化。
- [ ] 更新验证记录与部署说明，服务保持停止，用户用新计划进行真机验证。

## 当前边界

该修复保持原持久化格式、公共报告、相机设置和 START 的真实证据规则。已过期动作保持原状态，重新手测使用新请求。单元与隔离复现只证明相应软件行为，设备响应和实际启动时延由真机验证确认。
