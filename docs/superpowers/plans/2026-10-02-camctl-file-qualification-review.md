# 文件读取资格与拷贝责任

## 目标与依据

取回对正式产物取得读取资格时，共同保存源依赖、交付、拷贝、目标文件和唯一读取流程。相机拷贝机会按设备单独取得，排队期间原源依赖继续成立。录像内部检查和修复使用原处理责任及设备文件，不要求提前登记正式产物。

行为依据为[逐产物资格顺序](../../architecture/outputs.md#延后执行时的取回与清理顺序)、[共同建档](../../camctl/database/sources-obtaining.md#取回的读取资格与依赖)、[相机候选顺序](../../architecture/file-copy.md#多个候选文件的选择顺序)、[读取机会](../../camctl/database/waiting.md#相机读取机会与未完成责任)、[文件身份与路径](../../camctl/database/file-fields.md)、[操作配置](../../camctl/database/operation-fields.md#操作流程的身份与参数)及[录像内部处理](../../camctl/database/operation-fields.md#录像内部处理)。读取与删除资格的完整验收已由本计划 F1—F5 闭合；实际调度装配、真实设备读取及跨组件组合按 X12/I5 等既定范围推进，本计划的通过不替代它们。

复用现有 SQLite 事务、精确 JSON 编码、共享身份类型、来源与选择纯规则、候选排序和用途目录定义。无需新增依赖。预计调整 `outputs/qualification.py`、产物仓储、必要的文件命名与候选查询接口；文件划分及内部签名是建议，以下行为契约是约束。

## 待修复的责任边界

| 边界及触发场景 | 根因、修复要求与验收 |
| --- | --- |
| 配置采用与写入 | 次数接受布尔值，超时接受零；秒数先转成字符串，再由 P3 编码为 JSON 字符串。输入限制为可保存的正整数次数、有限正 Decimal 超时和有限非负 Decimal 间隔，生产者直接提供结构化数字。用非法值、精确小数及 SQLite 数字类型验证，不放宽 SQL。 |
| 目标归属与原责任 | 候选输入可以混用动作、取回项、产物和源文件；内部处理依赖正式产物；已有内部拷贝也可能再次建档。沿取回项→来源选择→来源关联，以及处理→录像→源文件核对固定关系；已有责任必须完整复用，缺失、重复和矛盾明确失败。覆盖不同物理 ID、异动作和源身份、没有正式产物的内部检查，以及新键恢复。 |
| 共同建档与固定名称 | 交付创建字段不完整，路径与交付名来自尚未分配 ID 时的自由文本。分配身份后按正式用途、ID 和受约束扩展名生成路径及文件名；加载历史归属链，所有必要创建事实与取回项变化一次提交。覆盖交付和内部分支、正式守卫、每个写入阶段回滚、无外部文件副作用。 |
| 逐产物资格与相机机会 | 当前判断按设备阻挡建档，又把取回与清理的类型优先级用于内部处理。产物资格按同一产物上的取回与清理候选协调；共同建档不占相机机会。已有拷贝通过单独事务取得机会，按动作时间、计划、数组位置及文件登记顺序排列。覆盖同产物与不同产物、同设备与不同设备、内部处理及本地源。 |
| 有效限制与原源依赖 | 限制检查仅查询部分未终态清理项，读取流程状态又被当成机会及源保护。有效限制由各清理项的限制字段确定，不能因清理失败或取消而漏掉不可撤销限制；机会由 `slot_device_id` 表达，源依赖由取回项表达。覆盖终态但仍有限制、已获资格后新增限制、终态流程仍持有机会及已释放机会但保留源依赖。 |
| 原键恢复与只读出口 | 原键恢复从业务值中寻找创建行 ID，没有核对原目标、阶段及输入；已有交付返回的目标文件可能为空。按完整原组、`row.id`、原创建事实和固定关联恢复原结果；原配置只能从当时采用的事实取得。覆盖后来状态和配置改变、异目标/阶段/时刻、坏组和坏关联，返回完整身份且不新增事实。 |
| 读取资源与候选容量 | 多处游标未关闭，排序将全部候选一次载入列表。实际查询以相应设备或产物为范围，使用有界查询或逐批遍历；所有出口释放游标。读取失败不能成为“不存在”或“没有竞争者”。单元使用受真实接口约束的替身，SQLite 组合验证实际关系与排序。 |

## 状态与入口模型

### 两种建档责任

| 责任 | 必须核实的关系 | 建立的记录 |
| --- | --- | --- |
| 普通及自动预览取回 | 取回动作、实际取回项、已固定选择及来源、选中产物、产物的设备或主机源文件一致。源动作与发起取回是不同对象。 | 交付、交付目标文件、拷贝、READ_FILE 流程及取回项永久交付关联；源依赖从 0 变为 1。 |
| 录像内部原片检查或修复 | 原录像、处理责任及已可靠确认的原片一致；检查或修复确实需要该输入，取消、终态及收场不能成为新建普通输入的资格。 | 录像输入文件、原处理的唯一拷贝及 READ_FILE 流程；不建立取回项或交付，不要求存在正式产物。 |

设备源保存真实设备文件身份、固定长度和已知摘要；主机源保存原中间文件身份和完整依据，不占相机机会。主机读取采用一次本地操作的配置，不套用设备超时或定时重试。输入声称的身份必须与数据库一致，不能用名称、路径或输入来源动作替代原绑定。

| 候选责任及来源 | 配置与交付元信息 |
| --- | --- |
| 取回项引用设备产物 | 设备文件身份与 `OperationConfig` 必填；正式产物、交付扩展名和可读名称必填。 |
| 取回项引用主机修复产物 | 中间文件身份必填，设备身份及设备配置为空；正式产物、交付扩展名和可读名称必填。本地读取保存一次操作上限，超时与重试间隔为空。 |
| 录像内部处理引用设备原片 | 原处理及设备文件身份、`OperationConfig` 必填；正式产物、交付扩展名及可读名称为空。 |
| 同时填写两个源、未填写源、内部处理指向主机源，或配置及元信息不符合上述组合 | 在读取原键结果前拒绝非法输入，不保存事实。 |

目标扩展名可省略；填写时，目标扩展名和交付扩展名均须为非空 ASCII 字母或数字。调用方不提供完整目标路径或交付文件名。事务按实际分配 ID 生成名称并检查 255 字节上限；源中间文件的保存路径按其原用途及 ID 检查，非法保存路径属于一致性错误，不能重新命名源文件。

### 共同建档的判断顺序

| 可靠事实 | 行为 |
| --- | --- |
| 必需关系或原责任缺失、矛盾、重复、不可读 | 一致性错误，整组不产生新事实。 |
| 原键已有完整提交 | 核对原阶段、目标及适用输入，恢复原响应；不重判当前资格。 |
| 新键，动作取消或责任已有最终结果 | 保持原结果，交由必要收场；不新建普通资格。 |
| 新键，已有完整准备责任 | 复用全部原身份和源依赖；不因后来的限制、配置或读取结果另建责任。 |
| 新键，未到时间或仍需可靠来源/文件确认 | 只读等待，不消耗读取次数，不补造完整长度。 |
| 新键，取回尚无资格且有有效删除限制 | 保存该取回项的实际最终拒绝；其他取回项及原已授予资格保持。 |
| 新键，尚无资格且有排序靠前的合格竞争者 | 继续协调，不提前建档或登记保护；选择保存和唤醒次序不作为排序依据。 |
| 新键，所需依据齐全且取得资格 | 整笔保存本责任所需记录，初始进度及次数为零；提交后才允许实际文件工作。 |

逐产物排序只在同一产物的合格取回与清理之间比较：计划时间优先，同时间取回优先，再用计划及原数组顺序稳定排列。候选条件从可靠持久化来源、输入范围和产物事实取得；尚未保存选择的合格候选仍须参与。应复用现有来源/选择规则计算其是否涉及该产物，不创建假选择，也不能以缓存、已启动协程或现有明细行作为完整候选集合。

### 文件事实与新申请的拒绝原因

以下判断发生在原键、取消、已有终态及已有资格按各自规则处理之后。设备正式产物必须保留 COMPLETE、完整长度和完成依据；后续存在性变化不清除这些登记前提。主机正式产物的存在性与正式清理事实保存在产物和清理明细中，不重新打开中间文件自动清理责任。

清理查询以当前产物为范围，汇总所有 ACTIVE、IRREVERSIBLE 项，不按清理动作或明细是否终态排除。可靠成功优先，其次为 DELETING、PENDING_DELETE，最后为仍保留限制的已结束项；没有有效限制时，清理投影只允许 NOT_REQUESTED 或 CANCELED。查询使用有界结果并关闭游标；SQL 失败不解释为没有限制。状态与汇总矛盾时回滚，不保存逐项业务失败。

| 可靠事实分区 | 新申请的行为 |
| --- | --- |
| 清理成功事实与 CLEANED/COMPLETED 投影一致 | 保存 `output_unavailable`，详情为原产物 ID 和 `availability: cleaned`。其他请求尚有限制不改变已清理事实。 |
| 尚无成功事实，存在有效限制且 RESTRICTED 与清理阶段一致 | 保存 `output_cleanup_started`，详情为原产物 ID。FAILED、CANCELED 仍保留的限制同样有效。 |
| 没有有效限制，可靠文件事实与 MISSING 一致 | 保存 `output_unavailable`，详情为原产物 ID 和 `availability: missing`。设备源须为 ABSENT；主机源使用正式产物保存的存在性事实。 |
| 没有有效限制，可靠文件事实与 UNKNOWN 一致 | 只读等待文件确认，不创建交付、次数或最终错误。设备源须为 UNKNOWN；未完成查询不能当作可靠缺失。 |
| 没有有效限制，可靠文件事实与 AVAILABLE 一致 | 继续资格排序与建档；设备源须为 PRESENT。 |
| 内部处理的设备原片尚未完成或存在性未知 | 等待确认，不产生正式产物错误或建档。 |
| 内部处理的原片确认缺失，或有限完成核实已为 UNCONFIRMED | 返回原内部责任的最终不可读取结果，由录像处理保存其自身结果；不虚构取回项或产物。 |

默认和预览选择已确定目标但其存在性 UNKNOWN 时，保留选中身份供后续确认，不仅凭 UNKNOWN 保存最终错误。显式选择继续保留原 UNRESOLVED 项，按既定核实入口推进。涉及完整大小比较的选择继续遵守其独立选择依据，不据存在性未知改选。

来源选择和资格拒绝产生的错误详情直接满足公共登记，所有公共对象 ID 使用规范十进制字符串，实际关联列继续使用整数。具名守卫调用统一错误登记校验详情，避免保存后直到报告投影才发现字段缺失或类型错误。

- [x] 拒绝原因阶段：先覆盖上述分区、终态限制、多项限制的优先级、投影矛盾、SQL 失败和回滚，再修复生产判断；验证来源选择及拒绝详情均可由真实公共 Schema 消费。

### 相机机会

| 拷贝与设备事实 | 行为 |
| --- | --- |
| 源在主机，或只剩主机校验/发布/清理 | 不申请相机机会。 |
| 普通责任结束或取消，尚有原读取收场 | 不发起新读取；保留原机会直到满足明确释放条件。 |
| 原拷贝已持有机会 | 复用原责任；实际尝试仍检查重试、次数、取消及兼容性。 |
| 其他拷贝持有机会 | 保留本拷贝建档及源依赖，只读等待。 |
| 无持有者，本拷贝仍缺少必要读取条件 | 按实际条件等待或结束，不占位。 |
| 无持有者，本拷贝与其他候选均具备条件 | 按动作时间、计划、数组位置、文件登记顺序选择；用途不增加优先级。 |
| 本拷贝应被选中 | 在写事务内核对后保存 `COPY_CHANGED.SLOT`；读取尝试及实际调用仍遵守各自意图和派发边界。 |

相机机会释放、重拷取得新机会及实际派发消费者必须使用这一模型。不能在普通流程已终态时推断机会自动空闲；清理同样不能以相机机会已释放代替源依赖解除。

实际读取结束由[读取会话结束责任](2026-10-03-camctl-read-session-settlement.md)提供：停止请求与关闭结果分开，关闭成功前不确认停止，关闭错误必须可观察。该接口的局部验证不代替机会变化事务的原责任核对及历史保存。

## 实施顺序与门禁

### F1：配置与建档数据

- [x] 先写 `OperationConfig` 单元反例：布尔、非整数、零、负数和超出 SQLite 整数范围的次数；零/负/非有限超时；负/非有限间隔；精确小数与零间隔合法。
- [x] 输入类型拒绝非法值；建档事件使用 Decimal 数字，P3 负责唯一一次 JSON 编码。审计超时与间隔的所有产物生产位置。
- [x] 使用真实事务验证采用值、事件数字与 SQLite JSON 数字类型一致，确认失败整组回滚；首次建档不创建读取尝试。

`OperationConfig` 的 36 项单元测试覆盖输入域。`test_read_config.py` 验证内部读取的精确数字、零间隔、事件与投影一致及三个建档阶段回滚；`test_read_associations.py` 验证普通交付的精确数字、共同关联，以及交付和取回项写入失败后的整组回滚。两条路径共用读取流程的数字生产位置，不提前创建尝试。

### F2：类型化目标与完整共同建档

首次内部输入按以下顺序检查：固定关系与准备记录完整性、工具阶段所证明的原输入责任、动作取消或终态及丢弃责任、明确的当前处理需求、源文件就绪及适用协调。只有仍需输入的处理才进入源文件就绪判断；未决定、无需输入或处理已结束时，不因原片缺失而补造一次处理失败。

| 内部输入责任与处理状态 | 行为 |
| --- | --- |
| 准备责任完整 | 按 F4 复用原身份。后来检查、修复或丢弃状态不导致重新建档；实际工具执行另行判断资格。 |
| 准备责任只有一部分 | 一致性错误，取消或终态不能掩盖缺失。 |
| 三类准备记录均无，`check_state` 为 RUNNING/COMPLETED，或 `repair_state` 为 RUNNING/SUCCEEDED | 一致性错误。这些阶段要求已经取得有效主机输入；记录永久保留，不能重新创建替代输入。 |
| 三类准备记录均无，检查 FAILED/UNCONFIRMED 或修复 FAILED/CANCELED | 仅凭这些结束状态不能证明此前已建立输入，因为输入准备之前也可能失败或取消。是否还有另一项输入需求按相应决定判断：检查 REQUIRED 且 NOT_PERFORMED 而修复已终局结束是不可解释组合，按一致性错误拒绝；检查已 FAILED/UNCONFIRMED 时不保留待执行修复的输入需求，只读不授予。 |
| 三类准备记录均无，动作取消或终态，或已进入丢弃处理 | 不建立新的普通输入，保留既有处理事实；这类出口位于已证明的责任缺失检查之后。 |
| 三类准备记录均无，检查 REQUIRED 且 NOT_PERFORMED，修复为 UNDETERMINED/NOT_NEEDED/PENDING | 检查构成独立输入需求；无需修复不取消尚需完成的检查。仍须满足源文件等其他条件。 |
| 三类准备记录均无，检查为 UNDETERMINED/NOT_NEEDED 且 NOT_PERFORMED，修复 PENDING | 修复构成独立输入需求，不要求先将检查决定改为 REQUIRED。仍须满足其他条件。 |
| 三类准备记录均无，未保存检查或修复需求 | 只读不授予；区分未决和无需处理，不保存逐项错误或新的输入责任。 |

两个混合状态按 2026-10-03 的用户决策处理：检查待执行（REQUIRED 且 NOT_PERFORMED）而修复已 FAILED/CANCELED 时，按一致性错误拒绝——该组合不可经合法状态转换到达，出现即状态矛盾；检查已 FAILED/UNCONFIRMED 而修复仍 PENDING 时，不保留修复的输入需求，只读不授予——检查失败规则禁止猜测未超门槛或盲目裁剪。未决分区不得由通用 OR 条件或“任一失败阻止全部工作”的假设代替。

建议将工具阶段证明的责任要求放在仓储原准备责任核对与 `COPY_CHANGED.CREATE` 的内部输入分支共用的判定中。守卫从 `context.state_rows` 读取事件发生时的处理阶段；完整事务提案仅提供固定关联，不能用未来阶段批准或否定当前创建。纯建档构造及共同固定关联加载仍服务于原键和已有责任恢复，不承担当前首次资格判断。

- [x] 工具阶段与原输入责任：先验证检查 RUNNING/COMPLETED、修复 RUNNING/SUCCEEDED 且三类记录全无时，在普通和取消入口均报错；覆盖 FAILED/UNCONFIRMED/CANCELED 不足以推定责任缺失的对照，以及完整原责任的新键和原键复用。随后接入仓储及正式创建守卫，并验证未来事务阶段不能代替当前阶段。
- [x] 当前内部输入需求：明确上述混合状态后，补齐未知、无需处理、独立检查需求、独立修复需求、结束和丢弃的分区；仓储在源就绪判断前只读不授予，正式创建守卫拒绝不具备条件的提案。

### F3：完整候选与两层协调

#### 首次建档的计划时间

普通取回、自动预览取回、主机产物取回及内部原片输入都使用发起动作的 `scheduled_at`，与本次申请的 `occurred_at` 比较。计划时间以数据库保存的 UTC 微秒为准，等于申请时刻即视为已到时间。正常执行入口在会话墙钟检查通过后提供实际取得的 UTC 读数作为申请时刻。此检查不重新授予或撤销原责任，也不代替公共时钟及实际派发资格检查；仓储及事件测试不证明真实执行入口已完成装配。

| 入口与已有事实 | 时间检查及结果 |
| --- | --- |
| 原键已提交 | 按 F4 核对原事务和输入并恢复原响应，不进入首次资格判断。 |
| 新键，固定关系或已有准备责任不完整 | 先报一致性错误，不因尚未到时间而隐藏坏关系。 |
| 新键，动作取消、已终态，或取回项已有最终结果 | 保持原出口及结果，不创建普通责任。 |
| 新键，已有完整准备责任 | 按 F4 复用原身份；这只证明已经建档，不授予实际读取机会。 |
| 新键，首次建档，计划时间缺失或不是可解释的整数微秒 | 一致性错误，不把无效时间当作已经到期。 |
| 新键，首次建档，尚未到时间 | 只读等待，尚不判断源文件可读性、保存逐项失败或采用配置。到时间后仍使用原选择与固定身份重新判断。 |
| 新键，首次建档，时间已到 | 继续源就绪及协调检查，不因单独满足时间条件而直接建档。 |
| 正式 `COPY_CHANGED.CREATE` 或 `READ_PERMISSION_CHANGED.GRANT` 事件 | 根据事件发生时的发起动作事实及事件时刻核对时间；当前动作缺失、时间无效或尚未到时间则拒绝。事务后续提案不能提供当前执行资格。 |

建议仓储与两个正式事件守卫共用时间判定。拷贝创建的父对象可以通过事务提案取得固定关联，以保留联合创建的两种事件顺序；发起动作的时间只能来自 `state_rows`。回归测试先覆盖三类来源的未来时间、相等边界、延后申请、等待后重试、坏关联优先，以及事件守卫的当前事实与未来提案边界。

资格授予事件从当前取回项、来源选择和依赖关系确定发起动作，核对回填交付属于同一取回动作和同一产物后，才检查发起动作的时间。回填交付不能改变取回项的归属或目标，也不能提供另一个动作的时间作为许可。缺少上述任何当前关系，即使完整事务提案包含它，也拒绝本次资格授予。

- [x] 首次建档时间门禁：仓储与创建／资格授予事件均不提前建立责任；完整原责任仍可只读复用，未来请求不提前保存文件错误。

#### 成员、候选与协调

逐产物候选判断与首次完整选择共用同一份默认／预览选择规则。对一份已登记产物，只读取其原片、对应预览和修复成品，不载入该来源的其他原片或全库产物目录。已固定选择继续以保存的明细为准，不重新套用选择规则；未固定选择只进行只读判定，不保存虚假的成员或选择结果。

| 一份原片及其派生产物 | 默认取回 | 预览取回 |
| --- | --- | --- |
| 没有修复成品 | 选择原片，按原片可用性形成结果 | 有预览时选择预览；没有预览时保存该原片的预览缺失原因 |
| 有修复成品，没有预览 | 选择修复成品，其不可用时不回退原片 | 预览缺失；修复成品不能独自替代不存在的预览 |
| 预览与修复成品都有完整长度 | 选择修复成品 | 修复成品不大于预览时选择修复成品，否则选择预览 |
| 预览和修复成品都存在，但至少一个完整长度未知 | 选择修复成品 | 不猜测大小，返回原预览目标的 `source_file_unconfirmed` |
| 已由上述规则选中目标，但它被限制、已清理或缺失 | 保存目标的对应错误，不改选 | 保存目标的对应错误，不改选 |
| 已由上述规则选中目标，但存在性未知 | 保留选中身份等待确认 | 保留选中身份及比较依据等待确认 |
| 派生产物角色或原片关联不一致，或同一原片有多个同类派生产物 | 一致性错误，不能据此选择其他产物 | 一致性错误，不能据此选择其他产物 |

建议先提取一份原片的纯选择函数，由完整来源选择调用；逐产物候选查询再使用同一函数。完整选择仍负责来源完成条件、原片顺序、来源级无产物及全部预览缺失的汇总，纯函数不独立授予读取资格。精确 ID 选择继续使用原请求及固定来源核对，不经过大小替代规则。

- [x] 共享逐原片选择：先用默认、预览、可用性及无效派生关系反例确定纯函数契约，再让完整选择复用；验证完整选择的顺序、逐项错误和来源级错误保持。
- [x] 有界产物关联读取：按当前产物找到原片及至多一份同类派生产物，校验同源关系和文件长度；错误不折叠为空集合，读取不固定选择或产生事实。

关联读取同时验证产物与承载文件的固定关系。下表适用于从原片、预览或修复成品任一 ID 查询整个关联集合；可用性、设备存在性与完整长度未知分别保留，不用它们掩盖身份矛盾。

| 产物角色 | 承载文件必须满足的条件 |
| --- | --- |
| 原片 | 承载设备文件属于同一来源，角色为 `ORIGINAL`，保留完成事实，且不携带预览配对。 |
| 预览 | 承载设备文件属于同一来源，角色为 `PREVIEW`，保留完成事实；其可靠配对指向当前原片的设备文件，与 `output_origins` 一致。 |
| 修复成品 | 承载主机文件由来源动作拥有，用途为 `REPAIR_OUTPUT`，保留状态为 `PROMOTED`，自动清理状态为 `NOT_NEEDED`。正式产物清理不改变这些责任。 |

实施顺序：先补三个查询入口的角色、配对、完成事实及主机责任反例，确认失败发生在查询结果上；再在有界读取边界统一验证。合法控制组覆盖已清理、缺失、未知存在性及未知长度，不从可用性反推固定身份。最后隔离纯选择单元测试的登记查询协作者，阻断真实资源入口，并验证完整来源选择与真实资源装配的集成行为。

- [x] 文件固定关系校验及三个查询入口的反例、合法生命周期控制组通过。
- [x] 逐原片单元测试隔离真实登记资源；替身约束真实接口，独立源码加载及测试执行均不访问包资源。

- [x] 完整来源两个入口共用文件关系校验：`load_selection_facts` 与首次固定选择均核对承载文件的角色、完成事实和预览物理配对，缺失文件按一致性错误处理。完整目录保留来源顺序，选择规则保留逐项失败；已固定集合不重新选择。

完整来源读取按下列分区验收，固定选择只在首次写入时消费当前目录。建议让逐原片查询与完整目录共用关联读取和文件校验，并以有界批次枚举来源产物 ID；同一原片的各成员只加载一次。完整选择的返回集合仍包含该来源全部产物，按 ID 升序，不以查询批次截断集合。

| 入口与当前事实 | 必须产生的结果 |
| --- | --- |
| 来源可靠存在且没有产物 | 完整目录为空，原来源完成状态及来源级选择规则保持。 |
| 来源包含合法产物 | 全部成员保留角色、原片关联、可用性和完整长度；无关来源的坏文件不影响本次读取。 |
| 来源产物缺少文件、原片或必需关联，或者文件身份与关联矛盾 | 完整读取报 `ConsistencyError`；首次固定事务回滚，选择、条目及历史不变。 |
| 读取完整目录后、首次固定之前，关联事实变得矛盾 | 写事务重新核对并回滚，不把此前快照当作当前文件关系的证明。 |
| 选择已经固定，后续又有新产物 | 原键及新键都沿用已保存集合，不因本次目录读取规则扩大或改选。 |
| 查询、取行或精确 JSON 解码失败 | 传播实际读取错误，关闭已取得的游标，不生成空目录或来源级无产物结果。 |

先分别验证只读入口和首次固定入口的关系反例，再统一读取实现；随后修正已有集成夹具的实际文件角色和修复文件承载方式。最后验证完整选择顺序、跨批次结果、无关来源隔离、已有选择复用及失败原子性。不得通过放宽生产校验兼容不符合真实登记契约的夹具。

- [x] 来源处理状态及已保存选择读取的游标：来源处理查询在 `load_selection_facts` 和首次固定中，对有行、无行及取行异常释放游标；保存条目和目标存在性查询在 `load_selection`、新键复用及原键恢复中，对非空、空、目标缺失、解码错误和查询错误释放游标。执行查询失败不关闭尚未取得的游标，SQL 异常保持原对象；不借资源修复改变来源完成判定或原键输入规则。

- [x] 限定产物存在性查询范围：`load_selection_facts` 只按实际请求和此前可靠确认的 ID 补查本来源目录之外的记录，每批最多 128 个 ID。`SelectionFacts.checked_output_sources` 显式区分未核实、可靠不存在与其他来源，完整目录证明本来源成员。验收覆盖本来源存在、其他来源存在、可靠不存在、此前确认后缺失、未覆盖请求、目录矛盾及 SQL 错误；无关产物数量增加不扩大本次存在性查询范围。

存在性事实的完整分类如下。本来源完整目录是本来源成员的唯一依据；补充查询只保存目录之外、实际请求或此前可靠确认的 ID。查询结果必须包含归属，不能以单一存在布尔值把完整目录遗漏的本来源成员误判成其他来源。

| 本来源目录及补充查询的事实 | 精确 ID 选择 | 此前已确认记录的核对 |
| --- | --- | --- |
| ID 位于本来源完整目录 | 按原可用性规则选择、等待或保存逐项错误 | 记录仍存在。 |
| ID 不在目录，补充查询确认属于其他来源 | 保存 `output_source_mismatch`，保留请求 ID | 记录仍存在，不要求其属于本来源。 |
| ID 不在目录，补充查询可靠确认不存在 | 保存 `output_not_found`，保留请求 ID | 一致性错误，不生成普通缺失结果。 |
| ID 不在目录，也没有补充查询结果 | 事实不完整，拒绝生成固定选择 | 事实不完整，拒绝核对，不能推断记录缺失。 |
| 补充查询声称属于本来源，但完整目录中没有该 ID | 一致性错误，不生成来源不匹配结果 | 一致性错误。 |
| 补充查询重复表达本来源目录成员，或者归属不是合法 ID | 拒绝矛盾或不可解释的选择事实 | 同样拒绝，不能按真假值解释归属。 |

来源尚未完成时仍返回未固定选择；此前可靠确认的记录须先完成存在性核对，保持现有错误顺序。默认及预览方式不为未使用的显式请求产生查询。数据库读取失败向上传播，不能把部分查询结果作为完整事实返回。

建议 `load_selection_facts` 接收实际请求 ID，按固定容量批次查询非本来源的请求及此前确认 ID；`SelectionFacts.checked_output_sources` 以键表示已核实范围，值为实际来源 ID 或可靠不存在的 `None`。先验证纯选择函数对未查询、可靠不存在及目录矛盾的区别，再实现按需读取，并同步所有显式 ID 调用方。集成验收包含无关来源增长、本地 ID 不重复查询、跨批次结果、重复 ID 去重、后续批次失败与游标释放。

#### 首次固定选择的请求依据

取回动作已保存的 `execution_spec_json.selection_mode` 决定选择方式；精确 ID 的值及顺序来自同一动作的 `input_fields_json.params.output_ids`。调用方提交的 `SelectionSnapshot` 是待核对结果，不能替代这两项权威输入。首次固定必须在写事务内重新取得当前来源目录、文件关系及所需的目录外存在性事实，并调用共同选择规则。快照的来源错误、完整条目顺序、实际及请求身份、选择依据、比较大小和逐项错误必须全部符合该结果。

三种方式都要求保存的原参数是对象。下表定义选择字段与固定方式的一致性；不符合任何一行时，按状态库错误拒绝，不改写固定方式。来源与用途的完整受理校验仍属于受理边界，首次选择使用已经固定的来源关联。

| 固定方式 | 原参数中的选择字段 |
| --- | --- |
| DEFAULT | 没有 `output_ids`；`filter` 省略或为 `default`。 |
| PREVIEW | 没有 `output_ids`；`filter` 为 `preview`。 |
| EXPLICIT_IDS | `output_ids` 为非空、无重复的合法对象 ID 字符串列表；没有 `filter`，即使其值为 `null` 也不能出现。 |

| 入口或事实 | 行为及失败语义 |
| --- | --- |
| 原键已有事务 | 进入原事务身份与原输入核对，不根据当前目录重新选择；完整原键核对单独验收。 |
| 新键，来源选择已为 FIXED | 读取保存结果，不采用新快照或当前选择规则扩大原集合。 |
| 首次固定，但动作不是有效取回、来源未固定、依赖指向非拍摄或其他来源计划 | 拒绝矛盾事实；不能只凭动作执行中和来源已终态保存选择。 |
| 首次固定，取回取消或不在执行中，来源或适用处理未完成 | 保持既有拒绝出口，不保存选择、条目或历史。 |
| 首次固定，选择定义缺失或无效，精确 ID 原列表缺失、非法或重复 | 按状态库一致性错误拒绝；不能采用调用方快照补齐或改用默认方式。 |
| 首次固定，当前事实导出的完整结果与快照一致 | 在同一事务中保存 FIXED、全部条目和历史。默认与预览规则及精确 ID 逐项失败均保持。 |
| 首次固定，快照遗漏、增加、重排或改变任意选择事实，或读取后当前可用性已经改变 | 拒绝本次提案并整体回滚。调用方须按当前可靠事实重新计算，不能静默保存旧结果或部分结果。 |
| 查询、记录解释或写入失败 | 传播实际错误；已取得的游标释放，不以空目录或部分结果继续提交。 |

建议保留现有提交接口，在仓储首次固定边界核对完整快照，复用共同选择函数与有界查询。保存事件守卫另行核对当前请求及选择依据，不从后续事务提案取得首次资格。实施和验收顺序如下，各阶段不能替代其他阶段：

- [x] 仓储首次固定：核对固定定义与原列表，并在同一写事务中重算完整结果。覆盖默认请求收到预览、精确请求漏项／换项／重排、错误或比较依据被改写以及目录读取后状态变化；已有测试夹具保存真实请求与执行定义，结果断言保持。
- [x] 正式选择事件守卫：审计直接事件、仓储生成事件及历史校验入口，补齐所需当前事实的装配，验证请求、来源、完整集合和选择依据的一致性；事务未来事实不能授权当前选择。
- [x] 原键完整恢复：核对事务阶段、选择身份、原时刻和原输入；明确首次响应与当前条目进度的边界，恢复不重新采用当前目录。阶段验证覆盖跨选择重用原键、条目已推进及提交未知核实。

首次提案核对、正式事件守卫、原键恢复、候选发现及相机机会事务均已按上述阶段闭合；实际调度唤醒入口与真实读取执行按 X12/I5 推进。

#### 选择固定的原键恢复

`FixSelection` 的操作键绑定一次来源选择固定。原事务保存的选择状态变更和按条目 ID 排列的创建事实共同确定首次响应；当前条目可以继续核实、建档和结束，但不能替换首次响应中的状态、错误或实际产物身份。新键访问已固定选择仍返回当前保存结果，两种入口不能混用。

| 原键及请求 | 当前保存状态 | 结果 |
| --- | --- | --- |
| 可靠不存在原事务 | 任意 | 继续既有首次固定或新键读取流程，不把查询失败当作不存在。 |
| 原事务不是恰好一个 `TARGETS_FIXED.OBTAIN` 事件，或选择 ID、事实时刻、完整快照不同 | 任意 | 按事务输入不一致拒绝，不读取另一个选择作为成功响应。 |
| 原事务完整且输入相同 | FIXED 及完整原成员保持，条目尚未推进 | 只读返回原事件确定的首次快照。 |
| 原事务完整且输入相同 | 条目沿原身份继续核实、建档、失败、取消或交付 | 只读返回首次快照；当前状态、源依赖和交付身份保持，不重新判断普通执行资格。 |
| 原事务完整且输入相同 | 选择或成员缺失、成员增加、原成员 ID 或不可变选择事实改变、已知产物记录缺失 | 按一致性错误拒绝，不补造记录或缩减成员。 |
| 原事务范围、事件正文或读取无效 | 任意 | 保留实际错误，不重新选择或写入；已取得游标均释放。 |

完整快照比较包含固定标志、来源错误、条目数量及顺序，以及每项的请求 ID、实际 ID、依据、原片和预览身份、比较大小、状态和错误详情。数值使用现有 JSON 比较规则，布尔值不能充当数字。事件正文行顺序不决定条目顺序。

`FixSelection` 在构造时按 `ObjectId` 校验选择身份，按 `UtcMicros` 及 SQLite 有符号 64 位范围校验事实时刻。两者仅接受非布尔整数；时间零值和负值合法。仓储在读取原键前要求规范的 `FixSelection` 实例，不能通过具有相同字段的其他对象绕过构造校验。该输入规则同时覆盖首次提交与原键恢复，快照中数值的 JSON 等值规则不扩大身份和时刻的类型范围。

成员的 ID、`selection_id`、请求身份、依据、原片和预览身份及比较大小保持原创建事件中的事实。首次已选中的实际产物不能替换；首次 UNRESOLVED 的显式项可以继续关联其原请求 ID，其他首次空关联保持为空。首次终态条目保持终态及原错误。当前产物可用性和文件目录变化不触发重选；普通取消或动作终态不否定已经提交的选择固定。

已知产物包括首次或当前实际关联、原片及预览引用，也包括首次 UNRESOLVED 项和 `output_source_mismatch` 证明存在的原请求 ID。即使实际关联仍为空，这些记录缺失也按一致性错误处理。首次 `output_not_found` 不证明记录存在；后来登记该 ID 不改变原失败，也不要求其出现。

建议继续使用 `saved_transaction_events` 核实原完整事务，在选择仓储内解释原创建事实；沿当前选择查询核对完整成员及不可变事实，避免扫描其他来源或依赖当前目录重算。既有正式事件守卫负责后续状态转换，恢复入口不重新执行外部副作用。实施顺序与阶段门禁如下：

- [x] 原请求与首次响应：先用真实事务证明跨选择、跨阶段、时刻或快照改变被拒绝，证明后续正式核实及拒绝事件不替换首次响应，再实现原事件解释与精确输入比较。
- [x] 当前保存事实：覆盖完整成员缺失或增加、固定依据改变、原成员 ID 改变和原产物缺失；核对选择仍为 FIXED，允许实际产物按上述 UNRESOLVED 规则推进。错误先于成功返回，失败不产生写入。
- [x] 恢复及资源：覆盖提交完成但回执丢失、首次写入回滚后原键重做、重启及目录变化、查询失败与游标释放；新键的当前结果语义保持。Python 3.11 运行相关集成门禁，并复核路线图及本计划的勾选范围。

正式事件校验还须保证完整集合的前后状态。选择为 `PENDING` 时，该选择不能已有目标条目；否则先报一致性错误，不能向残留集合追加新条目。首次写入保存的目标次序按 `obtain_items.id` 解释；校验时据此与原请求或原片顺序比较，不能把事件正文的行排列当作保存后的顺序。仅重排事件行而不改变条目 ID 及其事实，不改变选择语义。

`EventContext.state_rows` 只包含加载的相关行，缺少某个产物不能独立证明已经查询且不存在。正式守卫消费的读取依据须明确完整来源目录、实际请求的核实范围及可靠缺失，并证明 `PENDING` 选择没有旧条目；不能恢复全库扫描，也不能用事件自身的结果证明其选择正确。历史解码和回放继续验证并应用已保存事实，不按当前目录重选；这一边界与写入时的正式守卫分别验收。

- [x] 仓储完整集合的前置状态：`PENDING` 下已有 SELECTED、UNRESOLVED 或 FAILED 条目时拒绝追加；有界查询错误保持实际异常并回滚，已取得游标在空、有行及取行失败时释放，已有 FIXED 复用不受此首次检查影响。
- [x] 正式守卫完整集合的前置状态：读取依据证明 `PENDING` 选择当前没有旧条目；事务前序事件形成的当前条目也阻止首次固定，不能凭局部空映射猜测无条目。
- [x] 保存顺序：正式事件覆盖原条目 ID 对应正确顺序、事件行重排、条目 ID 交换、遗漏及增加条目的分区；读取后的顺序与共同选择规则一致。

#### 已保存产物引用与后续成员判定

当前选择读取及成员推进共同保留已经保存的产物身份。已固定项可能不再需要源文件，但实际文件清理只改变文件事实和可用性，不能使数据库中的产物记录消失。`load_selection`、新键访问 FIXED、原键恢复、普通读取建档以及直接提交成员事件均须覆盖各自消费的已知身份；不能只在实际选中产物上核实存在性。

| 保存的依据 | 要求存在的产物记录 | 读取或推进规则 |
| --- | --- | --- |
| 非空 `output_id` | 实际产物 | 保留当前状态及关联，不按新可用性重新选择。 |
| 非空 `original_output_id` 或 `preview_output_id` | 每个被引用的原片或预览 | 比较依据可以引用未选中的产物，相关记录也须保留；不重新读取文件大小替换旧比较。 |
| `output_source_mismatch` | `requested_output_id` 所指的其他来源产物 | 记录缺失按一致性错误处理；不把它关联为本来源实际产物，不改写原失败。 |
| 只有请求 ID，且结果为 `output_not_found` | 请求本身不证明记录存在 | 记录仍不存在或后来登记均不改变原失败。 |
| 只有请求 ID，且当前结果尚未判定 | 当前状态本身不补充存在性依据 | 原键使用首次固定事实的既定核对；普通读取和后续核实对尚未保存的事实按各自契约处理，不能仅凭裸请求补造产物关联。 |

建议在仓储内共用“从保存字段取得已知产物身份”的规则，SQL 读取与正式守卫分别提供可靠当前事实。首次固定前的目录查询、原键所恢复的首次状态和当前结果读取仍各自承担原职责。本项不重新应用选择规则，也不要求已清理的设备文件实际存在。

- [x] 当前读取与新键复用：覆盖未选中的原片／预览缺失、来源不匹配目标缺失，以及原不存在目标仍缺失或后来出现的控制分区；共享身份核对后，错误传播、游标释放和只读结果保持。
- [x] 后续资格与正式事件：普通建档在取消、终态或复用出口前读取项内保存的全部产物引用；成员核实、拒绝及授予守卫只从当前事实核实这些引用，后序事件不能补足当前缺失。初次建档与原键复用共同覆盖，内部录像输入仍按其独立责任处理。
- [x] 新成员错误的查询依据：`output_source_mismatch` 只在当前请求记录可靠存在且归属其他来源时保存；`output_not_found` 只在该请求 ID 的当前完整查询为空时保存。未查询或查询错误拒绝保存，不以事件提案补足查询；原未决项在可靠空查询后仍可保存不存在结果。
- [x] 已保存引用的回归：运行实际 SQLite 的读取、建档及成员事件回归，核对仍存在但已清理或可用性未知的产物不会被误认为数据库记录缺失。
- [ ] 未决项的历史存在依据：明确曾找到产物但可用性为 UNKNOWN 时如何保留已知身份，再覆盖首次固定、普通读取、新旧键复用及后续核实；不能由状态名猜测额外事实。

上述新错误以当前查询及已知引用为依据。历史上曾发现产物但没有保留实际关联的未决项，仍须单独明确如何保存该存在依据；不得用新增当前查询规则声称已经补齐该历史语义。

#### 正式选择守卫的读取范围与实施顺序

写事务向守卫提供两类相互补充的输入：`state_rows` 保存当前业务行；完整读取范围说明哪些等值查询已经可靠完成。范围只证明读取覆盖，不保存业务行的另一份副本。内核按顺序应用前序事件，守卫从推进后的当前行计算选择。完整事务的未来提案、待验证事件的结果及其 `evidence` 均不能补足当前读取范围或资格。数据库查询失败时不产生相应范围证明，也不能返回部分目录。

| 必须可靠取得的范围 | 当前事实的用途及缺失处理 |
| --- | --- |
| 所选来源的全部正式产物 | 确定完整默认或预览集合；范围未核实时拒绝，可靠空目录才可以形成无产物结果。 |
| 本来源目录外的原精确请求 ID | 区分其他来源与可靠不存在；没有读取覆盖时不能保存 `output_not_found`。 |
| 来源产物所需的全部原片关联 | 核对原片和派生关系；必需关联缺失或关系矛盾时拒绝，不能改选。 |
| 所有成员的设备文件或主机文件 | 核对角色、完成事实、配对、修复责任及比较大小；必要文件缺失或不可解释时拒绝。 |
| 来源的适用处理记录 | 按同一处理完成规则判定是否可以选择；未查询不等于没有处理责任。处理状态模型本身的未决事项仍独立保留。 |
| 当前选择的已有取回项 | 只有可靠空集合才允许从 PENDING 首次固定；任何已有条目均拒绝追加。 |
| 当前选择、依赖及两端动作 | 固定请求、来源身份、类型、计划与资格只能来自当前可靠行，不从待验证结果补齐。 |

`CommandPlan` 与 `EventContext` 使用默认为空的 `ReadCoverage`，以表、身份等值列和已完整查询的身份集合表达读取范围。内核只传递范围并推进业务行，不导入取回业务类型；范围及校验用的中间计算不写入机器协议或历史正文。相关业务行仍由 `state_rows` 唯一提供。

`EventContext.complete_rows` 只返回已声明范围内的当前行。上下文创建时对涉及表的物理行 ID 统一校验，主键查询直接定位记录；其他身份等值查询逐行核实成员字段，字段缺失或身份无效均拒绝，显式空关联不匹配正身份。读取范围保存独立、只读的身份集合，不随调用方后续修改扩大。

SQL 事实收集器只在同一个读取快照中使用。存在性、原片关联和处理状态查询提供局部字段；完整行查询提供后续关系解释所需的全部字段。原始行只有一份，局部读取与完整读取通过共同合并边界维护；查询范围完整与记录字段完整分别记录，不能互相替代。

| 已保存字段与本次读取 | 合并与后续读取规则 |
| --- | --- |
| 没有该行，本次取得局部字段 | 保存已读字段及成功查询范围，不标记为完整行。 |
| 已有局部字段，再取得相容的局部字段 | 保留已有字段并补齐新字段；重复局部读取不删除其他字段。 |
| 已有局部字段，需要完整行 | 执行完整行查询，核对重合事实并补齐字段，再设置完整行标记。 |
| 已有完整行，再取得相容的局部字段 | 保留完整字段及标记；后续完整行读取直接复用，不重复查询文件。 |
| 同一记录的重合字段不相容 | 报一致性错误，不改写已保存行，不声明本次读取范围；命令不能继续形成事件提案。 |
| 查询执行、取行或解释失败 | 传播实际错误，释放取得的游标，不以空集合或局部目录继续提交。 |

以上分区共同覆盖 `processing`、`origin`、`related`、`checked_sources` 与 `required`，不得由各入口自行覆盖或猜测字段完整性。关系定位使用已校验的物理整数 ID；原始行中等价的整数表示保持原值，布尔值或不一致的嵌入身份不能替代物理身份。

#### 取回成员守卫与后续协调

成员守卫先独立闭合 `REJECT` 与 `RESOLVE` 的共有边界，随后再完成拒绝原因与两层协调。守卫读取事件发生前的完整行事实；事务后续提案不能提前提供成员、固定选择或动作资格。真实查询失败由事务生产者向上传播，不能用缺省空集合表示可靠不存在。

#### 读取意图对当前机会的核对

设备拷贝建档后，机会可以尚未取得、已持有或已经释放。`BeginAttemptCommand` 保存新的 READ_FILE 尝试前，必须核对该拷贝的当前机会；正式 `attempt_intent` 守卫执行相同规则。当前实现只核对拷贝与流程的固定关系及次数，没有消费 `slot_device_id`，因而释放机会后仍可能登记新读取意图。这个遗漏独立于机会授予的候选模型，须先闭合消费边界，再将建档与机会授予分开。

| --- | --- | --- |

### 相机机会事务的阶段验证

机会授予与释放入口为 `OutputsRepository.grant_read_slot` / `release_read_slot`（`SlotRequest(copy_id, occurred_at)` 与 `SlotDecision` 由 `outputs/slots.py` 提供），各自独立操作键，经 P3 事务内核保存 `COPY_CHANGED.SLOT`（事件 22 reason 6）；正式 `read_slot` 守卫已注册。判定顺序遵守[相机读取机会](../../camctl/database/waiting.md#相机读取机会与未完成责任)：已持有只读复用（`HELD`）、归属矛盾与主机源申请为一致性错误、责任结束或取消生效不再授予（`FINISHED`）、未到时间与重试间隔只读等待、其他持有者等待（`device_busy`）、统一文件顺序中存在更早合格候选等待（`predecessor`）后授予。候选合格条件（动作执行中未取消、已到计划时间、流程未终态、无重试等待、源内容写完）在仓储与排序中同一套使用，`file_key` 的第四项用拷贝登记顺序表达；用途不参与排序。释放按当前事实核对：归属为空幂等只读返回（`ALREADY_RELEASED`）、实际尝试仍在途或重试等待期间只读等待（迟到通知不能清空）、源内容读完（`committed_bytes` 达到建档长度）或流程终态才保存释放。排序与持有者核对发生在生产者写事务内，唯一归属由 `slot_device_id` 的 UNIQUE 约束物理保证；守卫核对从空授予、绑定一致、资格、在途尝试与释放依据，候选排序由真实组合测试验证。

### F4：原键响应与已有责任

新键恢复已有准备责任时，先读取并核对固定关联，再处理动作资格，最后才允许进入尚未建档的判断。普通取回从原取回项和动作、产物组合定位交付；内部处理分别从原处理定位拷贝、从原录像定位输入文件及内部 READ_FILE 流程。三类记录全无才属于尚未建档。拷贝、目标中间文件和 READ_FILE 流程必须同时存在，流程再按拷贝与规范责任键交叉核对；所有查询限定到当前责任，最多读取两条身份以识别重复，并在空结果、成功及错误时关闭游标。

| 当前准备责任及动作 | 新键申请的行为 |
| --- | --- |
| 交付关联、拷贝、输入文件或流程只存在一部分，或者身份、归属、路径矛盾 | 返回一致性错误；取消或动作终态不能掩盖坏关系。不创建替代记录，不重置次数。 |
| 责任完整，动作已取消或不再 RUNNING | 保持原身份和状态，返回动作不具备普通执行资格；必要收场仍沿原责任进行。 |
| 责任完整，动作仍可执行 | 返回原拷贝、流程、目标文件及适用交付 ID，不重判首次资格。不增加事件、次数、机会或源依赖；该返回只表明原建档责任存在，实际读取仍检查原流程及调用资格。 |
| 普通取回依赖已解除，或者其源后来出现删除限制、缺失或未知 | 原关联与解除事实保持；复用结果不得触发重新建档或重新建立源依赖。 |
| 内部处理已有输入拷贝，其流程已结束或相机机会已释放 | 保留原责任、次数、进度和结果，不再创建输入或尝试。后续媒体处理按自身状态推进。 |
| 当前责任及其关联准备记录均未建立 | 继续既定的首次资格判断；不得从只缺一部分记录推断这一分区。 |

新键下的配置、目标扩展名和交付可读名称仅供首次建档采用；复用原责任时不改名、不替换原配置。源长度是建档时固定事实；恢复核对同一源的长度，源摘要可按正式规则后来取得。拷贝与源记录都保存摘要时，两者必须相同；只有一方保存或双方均未知时，保留各自已有事实，不补造或清除摘要。当前配置、文件存在性及后来取得的摘要不作为原建档输入重新采用。目标文件的保留、清理状态及大小按其后续生命周期保持，不要求它仍处于新建状态。原键的完整事件组核实独立实施。

3. [x] 仓储与正式授予守卫共同调用纯规则。守卫拒绝缺范围、缺必要行、未来候选事实、未解除限制和较早合格候选；生产者保存已有最终拒绝、只读等待及原责任恢复的边界保持。
4. [x] 替换建档路径的设备占用、旧拷贝保护及设备级用途排序；补齐直接守卫、真实事务、前后事件顺序、查询失败和跨批次回归。机会授予和释放仍按独立入口实施。

来源已经固定并且涉及当前产物时，来源未结束或产物处理未完成的取回不成为候选。满足来源完成条件后，候选判断区分取回动作是否已经开始。受理阶段只建立本计划来源依赖，来源选择记录在取回开始执行时初始化；不得要求尚未开始的动作提前具有选择记录，也不能把运行中缺记录解释成未选择。

| 较早取回当前状态 | 对应来源选择记录 | 候选判断 |
| --- | --- | --- |
| PENDING、来源已固定 | 可靠查询为空 | 在来源已完成时，只读使用原请求和执行定义判断当前目标，不创建选择记录。 |
| PENDING、来源已固定 | 已有选择记录 | 一致性错误，不把提前存在的进度作为有效选择。 |
| RUNNING、来源已固定 | 缺记录或有多个记录 | 一致性错误，不静默跳过，也不重新初始化。 |
| RUNNING、来源已固定 | 唯一 PENDING 选择且没有条目 | 在来源已完成时，只读计算候选目标。 |
| RUNNING、来源已固定 | 唯一 FIXED 选择 | 只按保存的成员身份及逐项状态判断，不重新应用当前默认／预览规则。 |
| 尚未固定来源 | 无保存依赖 | 按原引用只读判断可能来源；无法可靠查询时失败，不补造固定集合。 |

固定选择中的 SELECTED 及尚待确认的显式 UNRESOLVED 项在目标当前可靠可用且满足其他条件时参与竞争；已有交付或已有最终结果的项不重新竞争。固定清理集合只包含保存的请求目标，合法空集合及已结束项不会因后来产物登记而重新扩大或恢复。

- [x] 待执行取回只具有受理阶段保存的依赖，共用候选规则区分合法空选择与运行中缺失选择；覆盖来源未完成、可靠空查询、非法提前初始化、重复选择及未固定选择已有条目。

首次建档的发起动作资格由仓储、`COPY_CHANGED.CREATE` 及 `READ_PERMISSION_CHANGED.GRANT` 共同核对，覆盖设备交付、主机交付和录像内部输入。两个正式事件只消费事件发生前的当前动作，不能用事务后序提案补齐取消标志、状态或时间。原键恢复及已有准备责任的复用继续遵守各自入口顺序，不重新解释首次授予事实。

| 当前发起动作 | 仓储首次建档结果 | 正式首次创建／授予提案 |
| --- | --- | --- |
| RUNNING、未取消、已到计划时间 | 继续核对来源、目标及逐产物顺序。 | 继续核对其他不变量。 |
| PENDING 或任一终态，或已请求取消 | 只读等待，不增加准备责任。 | 拒绝并回滚整组。 |
| RUNNING、未取消、尚未到计划时间 | 以 `not_due` 只读等待。 | 拒绝并回滚整组。 |
| 缺少状态、取消标志或计划时间，或字段值不能解释 | 一致性错误，不推测可执行。 | 拒绝并回滚整组；未来事实不能补足当前事实。 |

- [x] 五个正式入口组合复用发起动作资格判定，覆盖状态、取消、非法字段及当前／未来事实；仓储等待和事件拒绝保持不同返回语义。时间测试的合法控制用例提供真实完整查询范围。

事件组合使用下列判定分区。申请者的固定目标保持不变，变动的是当前产物事实或竞争者的资格；准备建档的全部事件仍属于同一事务。

| 同事务的其他业务事实 | 该事实先于首次授予生效 | 该事实后于首次授予生效 |
| --- | --- | --- |
| 目标主机产物观察为 MISSING | 拒绝已有授予提案，产物观察与全部准备记录共同回滚。 | 允许先保存资格，再保存缺失观察；原交付和源依赖保留。 |
| 新增修复成品及原片关联，使较早默认取回选择修复成品而非申请者的原片 | 原片已无该较早竞争者，允许授予。 | 较早取回此时仍指向原片，拒绝提案；不能提前使用修复成品。 |
| 范围清理等待的最后一个拍摄来源完成，且没有待完成的产物处理 | 范围清理成为同产物较早候选，拒绝提案。 | 清理尚不合格，允许先授予，随后保存来源完成事实。 |

允许的组合若在后续准备投影写入时失败，业务事实、准备记录及历史均回滚。测试必须观察正式守卫实际取得的当前行，避免其他守卫提前报错掩盖目标分支。

资格矩阵与两层资源复核通过 531 项相关集成回归：`test_qualification.py` 的 35 项覆盖上表八个入口，`test_fixed_candidates.py`、`test_product_competition.py`、`test_read_schedule.py` 与 `test_read_slot.py` 覆盖候选生命周期、来源解析、时间门禁及独立相机机会。仓储与正式 `read_permission` 守卫两处共用 `has_product_predecessor` 纯规则及同一套当前候选事实，设备级建档阻挡已由完整逐产物候选替换。F2 遗留反例与合法组合由 `test_read_associations.py`（混合固定关联、缺记录、内部无正式产物、完整归属链、写入失败重送）、`test_local_read.py`（主机源与同一主机产物独立交付）、`test_read_names.py`（按实际 ID 的名称路径）、`test_copy_creation_slot.py`（空初始机会）及 `test_read_recovery.py`、`test_grant_reuse.py`（原键与提交未知）另行通过 578 项。

Python 3.11（uv 独立环境，SQLite 3.53.1）串行通过全部 2929 项单元测试、组件集成 3002 项另 7 项跳过（含本阶段新增 10 项）、根跨组件集成 34 项另 342 subtests；`check-protocol.mjs`、`check-report-dependencies.mjs` 与 `check-doc-links.mjs`（2914 个链接）全部通过。此前单独跟踪的日志等待用例 `test_accepted_record_delivers_receipt` 已随 L5 修复进入常规全量，不再保留排除项。

独立复核确认：逐产物资格协调与相机机会授予、释放是两层独立事务且两侧共用判定；各状态、入口及原键恢复未发现剩余缺口。E2—E5 事件契约审查属于独立审查周期，与本收口无范围交集。唯一保留的未完成项是"未决项的历史存在依据"：当前 `UNRESOLVED` 显式项按规格只保留请求身份、由 `RESOLVE` 核实闭环，是否额外保存"曾找到产物"的存在依据属于增强决策，需要时另行明确。

## 待决事项与实施边界

`test_qualification.py` 的守卫装配、连接释放、原请求归属、清理投影、时间精度及新键复用断言与对应契约一致，35 项准备资格测试通过。正式事件顺序组合和独立相机机会事务已按 F3—F5 各自阶段验收，见[F5 总收口的阶段验证](#f5-总收口的阶段验证)。

拒绝分支没有采用读取配置、扩展名等建档参数，也没有这些原值的保存位置。2026-10-03 用户决策：原键恢复只核对该分支实际使用的输入（原取回项、产物、实际错误及事件时刻），不增加持久化依据比较全部原输入；重送携带不同未用参数时返回同一首次拒绝。设备/主机来源与读取配置的重送对照由 `test_grant_reuse.py` 固定。

源删除的实际调用、取消收场、分段续传、摘要重拷和交付发布遵守各自模块契约。本计划必须闭合它们在资格与机会边界消费的事实；不将本计划的局部门禁声明为这些模块或 X3—X12 的完整验收。
