# 文件读取资格与拷贝责任

## 目标与依据

取回对正式产物取得读取资格时，共同保存源依赖、交付、拷贝、目标文件和唯一读取流程。相机拷贝机会按设备单独取得，排队期间原源依赖继续成立。录像内部检查和修复使用原处理责任及设备文件，不要求提前登记正式产物。

行为依据为[逐产物资格顺序](../../architecture/outputs.md#延后执行时的取回与清理顺序)、[共同建档](../../camctl/database/sources-obtaining.md#取回的读取资格与依赖)、[相机候选顺序](../../architecture/file-copy.md#多个候选文件的选择顺序)、[读取机会](../../camctl/database/waiting.md#相机读取机会与未完成责任)、[文件身份与路径](../../camctl/database/file-fields.md)、[操作配置](../../camctl/database/operation-fields.md#操作流程的身份与参数)及[录像内部处理](../../camctl/database/operation-fields.md#录像内部处理)。X3 的读取、删除资格及全部消费者门禁仍须完整验收；本计划内各阶段的通过不能代替整个 X3。

复用现有 SQLite 事务、精确 JSON 编码、共享身份类型、来源与选择纯规则、候选排序和用途目录定义。无需新增依赖。预计调整 `outputs/qualification.py`、产物仓储、必要的文件命名与候选查询接口；文件划分及内部签名是建议，以下行为契约是约束。

## 待修复的责任边界

| 边界及触发场景 | 根因、修复要求与验收 |
| --- | --- |
| 配置采用与写入 | 次数接受布尔值，超时接受零；秒数先转成字符串，再由 P3 编码为 JSON 字符串。输入限制为可保存的正整数次数、有限正 Decimal 超时和有限非负 Decimal 间隔，生产者直接提供结构化数字。用非法值、精确小数及 SQLite 数字类型验证，不放宽 SQL。 |
| 目标归属与原责任 | 候选输入可以混用动作、取回项、产物和源文件；内部处理依赖正式产物；已有内部拷贝也可能再次建档。沿取回项→来源选择→来源关联，以及处理→录像→源文件核对固定关系；已有责任必须完整复用，缺失、重复和矛盾明确失败。覆盖不同物理 ID、异动作和源身份、没有正式产物的内部检查，以及新键恢复。 |
| 共同建档与固定名称 | 交付创建字段不完整，路径与交付名来自尚未分配 ID 时的自由文本。分配身份后按正式用途、ID 和受约束扩展名生成路径及文件名；加载历史归属链，所有必要创建事实与取回项变化一次提交。覆盖交付和内部分支、正式守卫、每个写入阶段回滚、无外部文件副作用。 |
| 逐产物资格与相机机会 | 当前判断按设备阻挡建档，又把取回与清理的类型优先级用于内部处理。产物资格按同一产物上的取回与清理候选协调；共同建档不占相机机会。已有拷贝通过单独事务取得机会，按动作时间、计划、数组位置及文件登记顺序排列。覆盖同产物与不同产物、同设备与不同设备、内部处理及本地源。 |
| 有效限制与原源依赖 | 限制检查仅查询部分未终态清理项，读取流程状态又被当成机会及源保护。有效限制由各清理项的限制字段确定，不能因清理失败或取消而漏掉不可撤销限制；机会由 `slot_device_id` 表达，源依赖由取回项表达。覆盖终态但仍有限制、已获资格后新增限制、终态流程仍持有机会及已释放机会但保留源依赖。 |
| 原键恢复与只读出口 | 原键恢复从业务值中寻找创建行 ID，没有核对原目标、阶段及输入；已有交付返回的目标文件可能为空。按完整原组、`row.id`、原创建事实和固定关联恢复原结果；原配置只能从当时采用的事实取得。覆盖后来状态和配置改变、异目标/阶段/时刻、坏组和坏关联，返回完整身份且不新增事实。 |
| 读取资源与候选容量 | 多处游标未关闭，排序将全部候选一次载入列表。实际查询以相应设备或产物为范围，使用有界查询或逐批遍历；所有出口释放游标。读取失败不能成为“不存在”或“没有竞争者”。单元使用受真实接口约束的替身，SQLite 组合验证实际关系与排序。 |

## 状态与入口模型

### 两种建档责任

| 责任 | 必须核实的关系 | 建立的记录 |
| --- | --- | --- |
| 普通及自动预览取回 | 取回动作、实际取回项、已固定选择及来源、选中产物、产物的设备或主机源文件一致。源动作与发起取回是不同对象。 | 交付、交付目标文件、拷贝、READ_FILE 流程及取回项永久交付关联；源依赖从 0 变为 1。 |
| 录像内部原片检查或修复 | 原录像、处理责任及已可靠确认的原片一致；检查或修复确实需要该输入，取消、终态及收场不能成为新建普通输入的资格。 | 录像输入文件、原处理的唯一拷贝及 READ_FILE 流程；不建立取回项或交付，不要求存在正式产物。 |

设备源保存真实设备文件身份、固定长度和已知摘要；主机源保存原中间文件身份和完整依据，不占相机机会。主机读取采用一次本地操作的配置，不套用设备超时或定时重试。输入声称的身份必须与数据库一致，不能用名称、路径或输入来源动作替代原绑定。

| 候选责任及来源 | 配置与交付元信息 |
| --- | --- |
| 取回项引用设备产物 | 设备文件身份与 `OperationConfig` 必填；正式产物、交付扩展名和可读名称必填。 |
| 取回项引用主机修复产物 | 中间文件身份必填，设备身份及设备配置为空；正式产物、交付扩展名和可读名称必填。本地读取保存一次操作上限，超时与重试间隔为空。 |
| 录像内部处理引用设备原片 | 原处理及设备文件身份、`OperationConfig` 必填；正式产物、交付扩展名及可读名称为空。 |
| 同时填写两个源、未填写源、内部处理指向主机源，或配置及元信息不符合上述组合 | 在读取原键结果前拒绝非法输入，不保存事实。 |

目标扩展名可省略；填写时，目标扩展名和交付扩展名均须为非空 ASCII 字母或数字。调用方不提供完整目标路径或交付文件名。事务按实际分配 ID 生成名称并检查 255 字节上限；源中间文件的保存路径按其原用途及 ID 检查，非法保存路径属于一致性错误，不能重新命名源文件。

### 共同建档的判断顺序

| 可靠事实 | 行为 |
| --- | --- |
| 必需关系或原责任缺失、矛盾、重复、不可读 | 一致性错误，整组不产生新事实。 |
| 原键已有完整提交 | 核对原阶段、目标及适用输入，恢复原响应；不重判当前资格。 |
| 新键，动作取消或责任已有最终结果 | 保持原结果，交由必要收场；不新建普通资格。 |
| 新键，已有完整准备责任 | 复用全部原身份和源依赖；不因后来的限制、配置或读取结果另建责任。 |
| 新键，未到时间或仍需可靠来源/文件确认 | 只读等待，不消耗读取次数，不补造完整长度。 |
| 新键，取回尚无资格且有有效删除限制 | 保存该取回项的实际最终拒绝；其他取回项及原已授予资格保持。 |
| 新键，尚无资格且有排序靠前的合格竞争者 | 继续协调，不提前建档或登记保护；选择保存和唤醒次序不作为排序依据。 |
| 新键，所需依据齐全且取得资格 | 整笔保存本责任所需记录，初始进度及次数为零；提交后才允许实际文件工作。 |

逐产物排序只在同一产物的合格取回与清理之间比较：计划时间优先，同时间取回优先，再用计划及原数组顺序稳定排列。候选条件从可靠持久化来源、输入范围和产物事实取得；尚未保存选择的合格候选仍须参与。应复用现有来源/选择规则计算其是否涉及该产物，不创建假选择，也不能以缓存、已启动协程或现有明细行作为完整候选集合。

### 文件事实与新申请的拒绝原因

以下判断发生在原键、取消、已有终态及已有资格按各自规则处理之后。设备正式产物必须保留 COMPLETE、完整长度和完成依据；后续存在性变化不清除这些登记前提。主机正式产物的存在性与正式清理事实保存在产物和清理明细中，不重新打开中间文件自动清理责任。

清理查询以当前产物为范围，汇总所有 ACTIVE、IRREVERSIBLE 项，不按清理动作或明细是否终态排除。可靠成功优先，其次为 DELETING、PENDING_DELETE，最后为仍保留限制的已结束项；没有有效限制时，清理投影只允许 NOT_REQUESTED 或 CANCELED。查询使用有界结果并关闭游标；SQL 失败不解释为没有限制。状态与汇总矛盾时回滚，不保存逐项业务失败。

| 可靠事实分区 | 新申请的行为 |
| --- | --- |
| 清理成功事实与 CLEANED/COMPLETED 投影一致 | 保存 `output_unavailable`，详情为原产物 ID 和 `availability: cleaned`。其他请求尚有限制不改变已清理事实。 |
| 尚无成功事实，存在有效限制且 RESTRICTED 与清理阶段一致 | 保存 `output_cleanup_started`，详情为原产物 ID。FAILED、CANCELED 仍保留的限制同样有效。 |
| 没有有效限制，可靠文件事实与 MISSING 一致 | 保存 `output_unavailable`，详情为原产物 ID 和 `availability: missing`。设备源须为 ABSENT；主机源使用正式产物保存的存在性事实。 |
| 没有有效限制，可靠文件事实与 UNKNOWN 一致 | 只读等待文件确认，不创建交付、次数或最终错误。设备源须为 UNKNOWN；未完成查询不能当作可靠缺失。 |
| 没有有效限制，可靠文件事实与 AVAILABLE 一致 | 继续资格排序与建档；设备源须为 PRESENT。 |
| 内部处理的设备原片尚未完成或存在性未知 | 等待确认，不产生正式产物错误或建档。 |
| 内部处理的原片确认缺失，或有限完成核实已为 UNCONFIRMED | 返回原内部责任的最终不可读取结果，由录像处理保存其自身结果；不虚构取回项或产物。 |

默认和预览选择已确定目标但其存在性 UNKNOWN 时，保留选中身份供后续确认，不仅凭 UNKNOWN 保存最终错误。显式选择继续保留原 UNRESOLVED 项，按既定核实入口推进。涉及完整大小比较的选择继续遵守其独立选择依据，不据存在性未知改选。

来源选择和资格拒绝产生的错误详情直接满足公共登记，所有公共对象 ID 使用规范十进制字符串，实际关联列继续使用整数。具名守卫调用统一错误登记校验详情，避免保存后直到报告投影才发现字段缺失或类型错误。

- [x] 拒绝原因阶段：先覆盖上述分区、终态限制、多项限制的优先级、投影矛盾、SQL 失败和回滚，再修复生产判断；验证来源选择及拒绝详情均可由真实公共 Schema 消费。

### 相机机会

| 拷贝与设备事实 | 行为 |
| --- | --- |
| 源在主机，或只剩主机校验/发布/清理 | 不申请相机机会。 |
| 普通责任结束或取消，尚有原读取收场 | 不发起新读取；保留原机会直到满足明确释放条件。 |
| 原拷贝已持有机会 | 复用原责任；实际尝试仍检查重试、次数、取消及兼容性。 |
| 其他拷贝持有机会 | 保留本拷贝建档及源依赖，只读等待。 |
| 无持有者，本拷贝仍缺少必要读取条件 | 按实际条件等待或结束，不占位。 |
| 无持有者，本拷贝与其他候选均具备条件 | 按动作时间、计划、数组位置、文件登记顺序选择；用途不增加优先级。 |
| 本拷贝应被选中 | 在写事务内核对后保存 `COPY_CHANGED.SLOT`；读取尝试及实际调用仍遵守各自意图和派发边界。 |

相机机会释放、重拷取得新机会及实际派发消费者必须使用这一模型。不能在普通流程已终态时推断机会自动空闲；清理同样不能以相机机会已释放代替源依赖解除。

## 实施顺序与门禁

### F1：配置与建档数据

- [x] 先写 `OperationConfig` 单元反例：布尔、非整数、零、负数和超出 SQLite 整数范围的次数；零/负/非有限超时；负/非有限间隔；精确小数与零间隔合法。
- [x] 输入类型拒绝非法值；建档事件使用 Decimal 数字，P3 负责唯一一次 JSON 编码。审计超时与间隔的所有产物生产位置。
- [x] 使用真实事务验证采用值、事件数字与 SQLite JSON 数字类型一致，确认失败整组回滚；首次建档不创建读取尝试。

`OperationConfig` 的 36 项单元测试覆盖输入域。`test_read_config.py` 验证内部读取的精确数字、零间隔、事件与投影一致及三个建档阶段回滚；`test_read_associations.py` 验证普通交付的精确数字、共同关联，以及交付和取回项写入失败后的整组回滚。两条路径共用读取流程的数字生产位置，不提前创建尝试。

### F2：类型化目标与完整共同建档

- [x] 候选构造校验各身份、SQLite 整数 UTC 时刻、配置类型及两种目标组合；仓储在原键读取前拒绝非候选类型。内部处理不携带正式产物身份。
- [x] 新键设备源申请在状态出口前核对固定来源、来源计划、选择、取回项、产物、文件，或录像、处理、原片；设备绑定取自最初观察者并与可靠来源核对。用途未知和预览不能充当内部原片，正式设备产物与源文件角色一致。
- [x] 交付创建包含全部业务列；在真实事务中验证来源关联、交付与取回项共同保存，内部读取无需正式产物。
- [x] 将上述两种责任分别表达为受约束输入；交付使用可靠取回项与产物，内部处理使用原处理及文件。所有 ID、时间、配置和扩展名先通过类型检查，包含原键入口。
- [x] 目标路径及交付名由事务已分配的身份和受约束扩展名生成；保存、恢复定位及源路径检查共用纯规则。覆盖未填写扩展名、非 ASCII 或非法字符、实际 ID 对应关系、255 字节边界及分配 ID 后超长的整组回滚。
- [x] 主机来源取回核对已提升修复文件的归属、用途、完整长度及规范路径；保留源长度和已知摘要，建立独立交付副本。本地读取上限为 1，超时和间隔不适用，不占相机机会；设备来源同样保留已知摘要。
- [ ] 先补异动作、异来源、异产物、错误设备绑定、错误父对象、缺选择链以及缺原责任的反例。保存与只读复用共用固定关联核对，不以取消或终态掩盖坏关系。
- [ ] 先补没有正式产物的内部检查、设备与主机产物、同一产物多份独立交付的合法组合；生成符合用途及实际分配 ID 的路径和交付文件名，复用现有用途目录规则。
- [ ] 补齐交付全部业务列及可靠历史关联，写入源依赖与完整准备记录；共同建档不取得相机机会。覆盖每个投影写入阶段回滚和提交未知后的原键核实。

### F3：完整候选与两层协调

成员守卫先独立闭合 `REJECT` 与 `RESOLVE` 的共有边界，随后再完成拒绝原因与两层协调。守卫读取事件发生前的完整行事实；事务后续提案不能提前提供成员、固定选择或动作资格。真实查询失败由事务生产者向上传播，不能用缺省空集合表示可靠不存在。

| 当前成员及事件 | 必须成立的条件与结果 |
| --- | --- |
| 两个入口共有条件 | 当前项已经存在，来源选择为 FIXED 且没有来源级错误，依赖属于仍在 RUNNING 且未取消的取回；取回来源为 FIXED，来源动作必须是属于固定来源计划且已终态的拍摄动作。来源自身失败、过期或取消不取消该成员资格；未结束来源与已固定选择相互矛盾。缺失关联或不满足资格则拒绝事件。 |
| `RESOLVE` | 当前项为 EXPLICIT、UNRESOLVED，尚无实际产物；核实后的产物 ID 等于原请求 ID，且产物属于固定来源。状态进入 SELECTED。 |
| `REJECT`，原项为 SELECTED | 保留原产物及选择依据，产物仍须属于固定来源；仅保存 FAILED 和实际错误。 |
| `REJECT`，原项为 UNRESOLVED | 原项为尚无实际产物的 EXPLICIT 请求；保留原请求与空产物关联，仅保存 FAILED 和实际错误。 |
| 已建档或终态项 | 两个入口都不能重新推进；不得清除交付或重新开启源依赖。 |

- [x] 成员守卫阶段：先用真实事件登记验证上述分区及缺失关联、未来事务事实、请求 ID 替换反例，再接入守卫；真实事件事务验证注册、投影、历史和写入失败回滚共同工作。

- [ ] 分别建立逐产物与逐相机的决策表反例；包含来源选择尚未保存但已经合格的候选、未来时间、取消、终态、无完整源及其他设备。
