# 草稿编辑响应与布局修复计划

按 `superpowers:executing-plans` 在当前 `implement_camctl` 工作区逐步实施。

目标是在正常输入、自动保存及状态轮询期间保持表单位置稳定，并复用未变化的设备规则。行为依据为[计划编辑](../../client/plans.md)、[保存与恢复](../../client/storage-and-recovery.md)和[页面反馈](../../client/page-interactions.md)。

## 实现边界

- 保存调度、完整草稿比较、并发冲突、异常核实和能力重载的资格判断保持现有契约。
- 设备能力版本标识由后端产生。同一非空版本且新旧能力均可用时，前端复用此前的能力对象；本次错误和其他观察字段仍使用新响应。版本变化、版本缺失或能力变为不可用时消费本次实际对象。
- 保存反馈的文字和操作分别布局，普通已保存、等待保存和保存中状态预留相同空间。异常信息完整展示。
- 编辑派生结果按内容、能力、报告依据和覆盖进度复用；报告依据或能力变化仍即时更新对应诊断。输入原文立即进入会话，不延迟输入接纳。

## 步骤与验收

### 1. 状态观察中的规则复用

- [x] 单元用例覆盖同版本复用、版本切换、缺少版本、不可用及错误更新；原入口未复用的断言已先失败。
- [x] 在 App 接纳有效状态观察的共同入口复用能力规则对象，所有草稿观察继续消费完整本次状态。
- [x] 验证状态观察和能力重载相关单元。

### 2. 编辑派生结果与保存布局

- [x] 浏览器用真实保存接口检查桌面和窄屏的已保存、等待保存与保存中位置，原布局分别移动 20 和约 47 像素。
- [x] 将保存文字与操作拆成固定区域，保留异常和恢复入口；复用计划解析、预览协调、校验呈现及动作参数派生结果。
- [x] 浏览器验证轮询后仍能保存、完整输入仍持久化，能力新版本仍改变当前校验结果。

### 3. 联合验证与部署

- [x] 运行类型检查、构建、相关单元及保存、校验、能力重载和并发流程的浏览器回归。
- [x] 用同一隔离草稿、视口和操作复测布局与主线程长任务，记录测量口径和实际结果。
- [x] 更新验证记录，在原数据服务的内置浏览器展示新版页面，完成差异审查；阶段提交与本计划共同登记。
