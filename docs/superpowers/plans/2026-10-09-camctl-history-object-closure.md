# camctl 历史对象读取闭合实施计划

> 执行 Agent 按 `superpowers:executing-plans` 逐项执行；由评审者明确指派子 Agent 时使用既定分工。复选框只记录实际完成的交付。第一阶段实施 H、自身成员及派生字段的准确性，第二阶段单独完成短读事务和恢复路径选择。

**目标：** 历史对象读取只交付完整 H 处该对象的全部自身记录，独立依赖也在同一 H 恢复；读取期间的后续提交、批量和恢复方向不改变事实。

**组织建议：** 复用完整事务核验、权威行归属登记、精确事件解码和纯正逆应用。自身成员读取与报告依赖补齐分别承担责任；报告读取先绑定当前投影及 C，再在事务外恢复。内部类型、签名和文件拆分是实现建议，以下正式契约与状态分类是硬性要求。

**技术基础：** Python 3.11、sqlite3 显式事务、既有精确 JSON 和历史登记，不引入第三方依赖，也不另建完整对象或事件清单。

**规格依据：** [历史状态查询](../../camctl/historical-state-query.md)、[自身记录与快照成员](../../camctl/database/history-formats.md#自身记录与快照成员)、[历史快照](../../camctl/history-snapshots.md)、[历史引用与事务边界](../../camctl/database/consistency-verification.md#历史引用与事务边界)、[历史模块计划](2026-09-30-camctl-history.md)。

## 范围与现有入口

第一阶段修复完整 H 核验、取消对象与停止流程成员归属及主行派生历史字段，保持现有 `HistoryRepository.restore_entity(entity, entity_id, boundary, *, event_batch_size)` 返回形式。所有被恢复的对象必须使用完整已提交 H；取消对象只包含自身 `actions` 行、`cancel_items` 和依其归属进入的撤回明细，不包含 `target_action_id` 引用的独立动作行。报告需要目标类型时，按 H 恢复必要目标事实，不能扩大取消对象快照。停止流程和查询流程按各自正式归属区分，不能统一以触发者或目标活动分配成员。

第二阶段处理 `restore_entity` 目前覆盖全部恢复过程的读事务，以及其仅使用逆向路径的实现。第一阶段通过不代表第二阶段通过，也不据此勾选路线图中的完整历史对象读取门禁。

| 入口或文件 | 责任与需要核对的内容 |
| --- | --- |
| `persistence/repositories/history.py::restore_entity/restore_within/_reverse_to_boundary` | 核实 H、C、目录连续性及完整自身成员；拒绝虚假边界和损坏依据。 |
| 同文件 `_entity_row_ids` | 按正式归属枚举自身行；不把独立目标动作行加入取消对象。 |
| `operation_runs` 与 `operation_attempts` 的成员读取 | 残留停止与应急停止沿原活动归属；全部状态查询按自身触发动作归属，尝试随所属流程。 |
| 同文件 `SqliteSnapshotStore.load_entity_images` | 从同一 S 取得自身成员和计数；取消快照不包含目标对象行。 |
| `reporting/generation.py::_plan_facts` | 使用 H 时的取消项引用补齐目标事实；不把目标加入报告入选集合。 |
| `history/replay.py::apply_forward/apply_reverse/restore` | 只应用逐行归属属于本对象的事件影响；对照三种路径及独立预期。 |

| `entity_facts` 的五个受理测试调用 | 第二阶段迁移到限定对象读取；不能继续把全库当前读取当成对象接口。 |

## 共同不变量与失败语义

1. 初始化边界只有 `(0, 0)`；其他 H 必须实际存在，且事务身份与该事务末事件一致。事务中间位置可以是分页位置，不能是状态边界。
2. 每份当前投影、当前累计计数与 C 属于同一读视图，C≥H。副本取得后只处理固定 `(H, C]`；不能将较新的投影或计数补进旧副本。
3. 每行只有正式归属表规定的一个历史对象。引用目标、观察者和报告嵌套不改变归属；一条多对象事件分别应用到各对象，每个对象只计一次。
4. 对象自身成员、必要依赖、父子关系和公开结果均表达同一 H。对象在 H 尚不存在时明确返回不存在；已存在但必要成员或引用缺失时报状态库错误。
5. SQL、解码、事务核验或值连续性失败均保留可诊断错误并释放资源，不返回空成功，不跳过损坏记录，不以最新状态补齐旧状态。
6. 恢复只修改查询副本，不修改当前投影、不追加事件、不发送通知或执行文件副作用。快照保存沿自身维护事务，不增加业务变化。

## 完整状态分区

下表先判定 H，再判定对象和成员；后面的路径选择只适用于依据可靠且对象在 H 存在的情况。

| 条件 | 查询结果 |
| --- | --- |
| H 为 `(0, 0)`，数据库初始化及当前 C 可靠 | 恢复初始化状态；后来创建的对象明确不存在。 |
| H 的事务不存在、事务与末事件不配对、末事件处于事务中间或分组不完整 | 报 `ConsistencyError`；没有相关变化的对象也必须拒绝。 |
| H 晚于可靠 C | 报 `ConsistencyError`。 |
| H 完整，对象在 H 尚不存在，当前存在且创建历史可靠 | 返回该对象在 H 不存在，不保留后来成员或引用目标。 |
| H 完整，对象在 H 存在，必要投影、成员、目录和计数可靠 | 恢复全部自身成员；独立依赖另查同一 H。 |
| 当前对象应存在但主行、必要成员、创建依据或归属链缺失 | 报状态库一致性错误，不解释为未出生。 |
| 必需引用的目标在 H 不存在或归属矛盾 | 报状态库一致性错误，不使用当前目标或省略引用。 |
| 任何必要数据库读取或解释失败 | 传播实际错误并结束查询，结果不部分交付。 |

取消引用单独覆盖以下组合，不能用一个普通取消剧本替代：

| H 时取消成员 | H 后目标变化 | 同 H 处理 |
| --- | --- | --- |
| 尚未创建 | 无或有 | 取消对象没有该成员，也没有其目标动作行；报告不沿后来引用补齐。 |
| 已创建，目标与取消在同计划 | 无 | 自身映像只含取消对象行；需要目标字段时另恢复目标 H。 |
| 已创建，目标与取消跨计划 | 无 | 与同计划使用相同规则；目标不作为该计划的入选子动作输出。 |
| 已创建，目标独立发生变化，取消目录未增加 | 有 | 取消自身映像保持；目标独立恢复到 H，不带入目标 C 状态。 |
| 已创建，共同事件同时修改取消项与目标 | 有 | 两个对象分别只应用自身影响，计数和快照不混合。 |

### 任务 2a：停止流程与状态查询的唯一归属

真实场景中，动作 A 的设备活动仍有历史，动作 B 随后建立 `STOP_RESIDUAL` 流程；该行保存 B 的 `action_id` 和 A 的 `activity_id`。停止流程与全部尝试属于 A。B 对同一残留停止建立 `QUERY_ACTIVITY/RESIDUAL_STOP_CONFIRMATION` 时，查询流程与预算属于 B。只按 `operation_runs.action_id` 读成员会使 A 的恢复和快照遗漏停止及尝试，使 B 的恢复和快照包含别人的行；H 早于这些行创建时，同样会残留后来行。

**建议修改：** `persistence/repositories/history.py::_entity_row_ids`，并审计写侧 `operations.py::_run_owner_ref`、应急补记 `capture.py::SaveEmergencyCommand` 和历史归属核验。**测试：** `tests/integration/history/test_operation_ownership.py`。

## 第二阶段：短读事务与按对象选择路径

本阶段在第一阶段准确性门禁通过后实施，完整交付前保持未完成。

### 任务 5：固定恢复依据与事件分页分离

**建议接口：** `ObjectRestoreSeed` 明确数据库身份、对象、H、C、当前自身副本、C 处计数及 H 处目录头；`ObjectEventRequest` 明确数据库身份、对象、方向、固定端点、最后位置和批量；返回独立事件页并确认读资源结束。具体名称和文件由实现者按真实调用链调整，字段语义不能省略。

- [x] 写失败测试，在事件恢复纯函数与编码入口暂停，实际查询和显式读事务均已结束；单对象多页历史的每一页遵守相同要求。
- [x] 初始短事务取得自身投影、C 及计数，复制后关闭；每页另开短事务读取固定区间、核验并解码，关闭后才应用事件。不可变事务核验缓存有明确容量，绑定数据库身份。
- [x] 在页间提交新变化与新快照，验证已选依据、C 和范围保持，多个对象使用不同 C 仍恢复同 H；取消、读取失败及结束失败均释放资源并保留实际错误。

### 任务 7a：完整快照行的值与组合校验

本任务处理固定快照正文中的非法业务状态。输入是已经固定的快照身份、对象、完整 S、S 处累计次数及正文行，以及同一读视图取得的 C 种子；输出是全部必要自身行在 S 的映像。每列保留精确解码后的原值，并满足权威 SQL 的类型、空值、JSON 结构与行内组合。任一必要行不合法时整体报 `ConsistencyError`。本任务不扩大合法成员子集遗漏的故障范围，也不对独立对象复制整库状态。

| 校验维度 | 合法分区 | 非法分区及处理 |
| --- | --- | --- |
| 正文与固定身份 | 完整主行、列集合、创建位置、派生计数和唯一归属均符合原固定依据 | 保持已有拒绝规则，不从 C 补值或回退路径 |
| 空值 | 权威 SQL 允许该列为空 | 必填列为空，整体拒绝 |
| 整数列 | 使用项目精确 JSON 整数规则接受整数及数学值为整数的有限 Decimal；验证适配不改变返回映像 | 布尔值、字符串、浮点值、非整数 Decimal 及范围越界，整体拒绝；不依赖 SQLite 自动转换掩盖类型 |
| 文本列与 JSON 列 | 普通文本使用字符串；JSON 使用精确编码且满足该列声明的类型和必要结构 | 错误类型、JSON 形状或必要成员不符合已登记契约，整体拒绝 |
| 有限枚举 | 精确整数编号属于权威登记且满足该列约束 | 未登记编号及错误类型，整体拒绝 |
| 行内组合 | 各列单独合法且共同满足权威 CHECK 与已有业务结构约束 | 各列单独合法但组合矛盾，整体拒绝 |
| 路径 | 精确 S=H、S<H 正向与没有相关事件增量均使用相同完整行规则 | 后续事件恰巧覆盖非法列不能成为接受损坏 S 的理由 |

现有事件校验器针对事件分支及前后变化，不能伪造创建事件来验证任意 S。`_check_enum_value` 仅覆盖部分枚举，不能作为完整行校验。实施前核对权威 SQL、精确 JSON、现有动作结构与归属校验的复用能力；不得另写完整表、列、枚举或组合清单。

建议在一次快照读取范围内复用基于权威 DDL 的空内存 SQLite 校验器，先按实际 `table_xinfo` 核原类型，再逐行适配、校验和回滚。它不连接生产状态库、不保存业务事实、不触发外部副作用；外键与独立依赖仍由既有唯一归属及同 H 查询负责。实际实现可以采用更窄且等价的方式，但必须证明所有上述分区，不能每行重复创建整套结构或积累完整第二份对象副本。

完整值校验还须保证选中对象 S 内实际包含的行共同满足权威 UNIQUE 约束。逐行回滚只验证单行类型与 CHECK，不能独立证明可变唯一键没有重复。跨独立对象的关联仍由固定关系与同 H 依赖查询负责，不能使用 C 证明 S，也不复制其他对象。权威 DDL 的 `table_xinfo`、`index_list`、`index_xinfo` 与实际索引定义是索引范围、列、排序规则和条件的来源，不另写唯一键或部分索引条件清单。

| 唯一键分区 | 判定与结果 |
| --- | --- |
| 不同物理行具有相同非空唯一键，且两行都适用该索引 | 整体拒绝快照；普通复合键比较全部索引成员 |
| 唯一键含 SQL NULL | 按 SQLite 的 UNIQUE 语义允许重复，不将 NULL 编码为普通相等键 |
| 部分唯一索引的条件只适用于零行或一行 | 不产生键冲突；条件由权威索引定义交给 SQLite 判定 |
| 部分唯一索引的条件同时适用于两行，非空键相同 | 整体拒绝快照 |
| 唯一键及其条件均由已核对的不可变事实组成 | 仍按权威索引范围核验；固定事实检查不得省略 |
| 表达式键、不同排序规则或生成列出现在实际结构中 | 先报告真实结构和现有适配缺口，不自行选择等价规则 |

2026-10-09 的实际结构审计显示业务表没有生成列或隐藏列。单个交付或处理对象最多有一行 `file_copies`，单个动作最多有一行 `recording_processing`。`cleanup_items.output_id = requested_output_id` 与动作内不可变的请求目标唯一键共同保证单个清理动作内不会形成两个相同的非空产物持有键；`one_preview_choice` 的键及条件均属于不可变事实。取回动作的 `obtain_items.delivery_id` 与 `(selection_id, output_id)` 则包含可变关联，须有两个真实目标项的快照反例，不能把跨对象的拷贝重复写成单对象反例。部分索引适用条件及 NULL 的通用规则使用真实 SQLite 校验器的组件集成测试证明。
