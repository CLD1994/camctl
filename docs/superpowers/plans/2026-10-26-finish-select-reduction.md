## 事实可见性与实现边界

本次保持数据库结构、事件表示、公开协议及既有原子保存边界。业务状态继续随业务事件立即可靠保存；成功查询可以复用，但消费者不能登记可信通过结论。缓存预算仍由现有权威实现维护，新增固定关系必须进入共同预算，不能各自增加无界字典。

| 情况 | 必须保持的行为 |
| --- | --- |
| C0 内已提交的固定文件、成员、页关系、配对及决定 | 根据完整身份和直接依赖从真实连接取得后，在本事务容量内共享；阶段切换和无关写入不改变固定旧事实。 |
| 固定引用不同、类型不同、边界不同，或来源缺失、归属矛盾 | 分别读取或拒绝；布尔值不与整数合并，不用一个较宽的缓存键掩盖不同条件。 |
| 当前行被实际前序修改，包含派生历史字段；原缺失行被创建 | 后续判断必须看到实际新值。有限入口只叠加已验证前序，有界入口还要求前序已经实际落地。 |
| 当前行没有被本次已知写入触及 | 可评估按受影响范围保留读取结果；必须由内核实际写入边界证明，不能由业务调用方声称未改变。 |
| 无法确定写入影响范围，或存在内核外直接写入 | 保留能够保证正确性的整体失效路径；未登记写入不能静默使缓存继续有效。 |
| 当前集合存在性、数量和增长范围 | 保持按当前状态直接查询和分页。可以整理调用组织、交付本批已经取得的事实；不得建立任意 SQL 结果缓存或查询依赖图来保留 COUNT、EXISTS 或整份集合。 |
| 当前事件、未来 marker、未来产物及未完成事务 | 只作提案比较，不能成为当前授权或已提交事实。预览只引用真实已验证前序的原片产物。 |
| 查询失败、非法事实、空有效页、可靠不存在 | 保持各自语义；错误不缓存、不转为空页或缺键，空有效页继续按原游标推进。 |
| 成功、回滚、提交未知、取消、异常、跨连接或事务结束 | 原结果和原键核实责任保持，结束本次保留范围；不得跨连接或跨事务沿用。 |

集合计数和范围的直读约束已经明确；本计划不把十次 COUNT 一律改成一次缓存。如果优化要求改变该契约，执行 Agent 先说明所需语义与证据并交由用户决定，只暂停依赖该决定的工作。既定的固定事实共享和分页组织可以继续。
