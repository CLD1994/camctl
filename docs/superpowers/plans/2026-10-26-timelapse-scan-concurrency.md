# 延时摄影共享结果清单的并发修复

## 目标与依据

同一会话可以并发推进不同设备。延时摄影处理器恢复原结果页时，只处理属于当前动作的原申请；另一设备登记或移除结果扫描，不得中断当前动作，也不得使结果页跨动作保存。

执行与设备所有权沿用[实现总览](../../camctl/implementation.md#调度与会话接口契约)。当前实现的 `pending_result_scans` 由会话共享，每设备的普通拍摄任务顺序推进；残留恢复跳过已有拍摄任务持有的设备。结果扫描只有在原调用结果可靠保存后才移除，原页保存继续保留原票据、申请与操作键。

问题发生在 `capture_handler("camera_timelapse")`：处理器直接遍历共享字典，筛选条件中的归属查询会异步等待。另一设备在此期间增删扫描，导致字典迭代器失效。

## 修复边界与验收

建议在第一次归属查询前同步取得 `items()` 的有限快照，再异步筛选当前动作。保持原扫描对象及原页保存流程，不改变设备并发、数据库结构、错误交付和恢复资格。

| 查询等待期间的变化 | 当前推进必须满足的结果 |
| --- | --- |
| 另一设备移除自己的扫描 | 当前动作正常返回，另一设备的页不由当前动作保存。 |
| 另一设备登记新的扫描 | 当前动作正常返回，新扫描留在共享清单，后续推进可以发现。 |
| 当前动作持有原待保存页，同时发生上述任一变化 | 原页按原票据和操作键保存一次，其他动作的页保持原责任。 |
| 归属查询或原页保存返回错误 | 原异常继续交付，不因并发修复而被忽略或转换为成功。 |

## 验证记录

Linux 开发容器、Python 3.11.17 下，新增六项单元覆盖四种增删交错及查询、保存错误交付。旧代码的四种交错均触发字典大小变化异常，错误交付两项通过；修复后六项通过。最终拍摄与装配单元共 2213 项通过，耗时 32.79 秒，退出 0。命令及证据见[软件验证记录](../../camctl/verification.md#延时摄影共享结果清单的并发修复2026-10-26)。

步骤 3 尚待审查、提交及发行包安装核对；真实设备验证由用户执行。
