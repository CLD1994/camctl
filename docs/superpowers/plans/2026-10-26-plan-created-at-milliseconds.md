# 计划创建时间毫秒精度实施计划

执行方式：在当前会话按业务路径实现，完成受影响范围的验证、代码检查和本地部署。

**目标：** 客户端以 UTC 毫秒格式生成计划 `created_at`，下载文件名直接取自该字段；camctl 完整保存毫秒并在报告中表达。

**架构：** 公共协议为计划创建时间定义独立格式，兼容已有秒级记录。客户端沿用原请求事务；camctl 沿用整数微秒存储和公开投影，仅创建时间启用毫秒转换。

**技术：** TypeScript、Node.js、Python 3.11、既有 JSON Schema 与 SQLite。

**规格：** [计划时间字面量](../../architecture/plan-input.md#时间字面量)、[计划导出](../../client/plans.md#导出与原请求)。

## 契约与核对重点

- 新 `created_at` 固定为 `YYYY-MM-DD HH:mm:ss.SSS`，表示 UTC；同一请求下载及重启后保持原值和文件名。
- 秒级历史计划和报告继续有效；历史原请求不改写，文件名毫秒位补 `000`。
- 仅创建时间接受恰好三位小数秒；其他公共时间维持秒级；错误日期、非三位小数及非整毫秒存储值明确拒绝。
- 报告保留非零毫秒；整秒保持已有秒级表示，以维持已冻结历史与客户端合并的一致性。
- 文件名与正文共用创建时间，不保存另外一套毫秒资料。主机时间可信性、动作调度与请求身份规则沿用原契约。
