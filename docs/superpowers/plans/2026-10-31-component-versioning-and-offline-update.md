# 组件版本、启动记录与离线更新实施计划

## 已确定的契约

三个组件独立编号。Python、host、客户端分别以自身构建元数据为版本权威，运行输出从该来源读取或生成；部署包仅记录实际版本组合。程序发行版本、公共协议版本与数据库格式版本分别管理。后续发布按照主版本、次版本、修订版本表达不兼容变化、兼容功能及修复；已交付版本不覆盖发布，开发提交以源码身份区分。

每个组件启动时输出自身版本一次。Python 的 `run`、`submit`、`init`、`describe` 在所属日志建立后记录一次 INFO 启动版本，不受普通日志级别过滤和 INFO 采样影响；日志通道不可用或满载时按已有 stderr 通道交付，不阻挡业务启动。`--version` 只输出版本并退出，不写启动日志。机器结果和版本日志使用各自已有的输出通道。

部署包提供 Python 包离线更新入口。操作者先停止 host 及全部 CLI，更新器保持原虚拟环境绝对路径，安装包内配套依赖和 wheel，并检查依赖、实际版本、原配置及原状态库。包内携带适用于 Python 3.11 的 Linux ARM64、x86_64 依赖 wheel；目标机已安装 Python 3.11 和 uv。

自动迁移、失败回滚及断电后恢复由[更新规格](../../architecture/versioning-and-updates.md)统一定义，后续实现由[自动更新计划](2026-10-31-transactional-camctl-update.md)跟踪。数据库以 V9 为自动维护基线，更新前保存可恢复的环境和数据库；必要时在副本上迁移。能力说明按原配置导出，明确指定同步目标时同时承担恢复责任。原配置、媒体和客户端数据库保留，更新结束保持停机。

## 步骤与职责

- [x] V1：补齐版本与更新规格，明确日志例外、离线包契约及失败边界。
- [x] V2：Python 版本查询和启动记录使用单一来源，补齐默认过滤及拥塞下的单元分区。
- [x] V3：host 和客户端按各自版本来源输出启动版本，核对源码包、构建和安装入口。
- [x] V4：部署包携带离线依赖及更新入口，接通原环境安装、锁、收据和只读部署检查；同步 skill、模板及说明。
- [x] V5：执行适用的隔离单元和静态检查，完成独立评审并提交；明确保留未运行的发行物、SQL 组合及设备范围。

根代理负责整体规格与集成，V2、V3 由同一执行代理依次在其独立工作树完成，V4 在另一工作树实施。V4 独占部署包格式、脚本、更新器及对应测试，并拥有只读部署检查模块；V2 不修改这些文件。根代理按接口和源码依赖集成，再统一验证。独立代码评审由另一代理负责。

V1—V4 的接口和生产调用已接通。集成后的六个隔离单元文件为 57 项及 5 个子测试通过；host 和客户端完成配置、语法及类型检查。实际发行物和更新组合仍属未运行范围，详见[验证记录](../../camctl/component-versioning-verification-2026-10-31.md)。

本项不新增或运行集成测试，不构建测试发行物、安装到真实或历史环境、不操作设备。构建与更新脚本的真实执行验证属于未运行范围，不能由内存替身推断通过。Python 3.11 为验证解释器。
