# 组件版本、启动记录与离线更新实施计划

## 已确定的契约

三个组件独立编号。Python、host、客户端分别以自身构建元数据为版本权威，运行输出从该来源读取或生成；部署包仅记录实际版本组合。程序发行版本、公共协议版本与数据库格式版本分别管理。后续发布按照主版本、次版本、修订版本表达不兼容变化、兼容功能及修复；已交付版本不覆盖发布，开发提交以源码身份区分。

每个组件启动时输出自身版本一次。Python 的 `run`、`submit`、`init`、`describe` 在所属日志建立后记录一次 INFO 启动版本，不受普通日志级别过滤和 INFO 采样影响；日志通道不可用或满载时按已有 stderr 通道交付，不阻挡业务启动。`--version` 只输出版本并退出，不写启动日志。机器结果和版本日志使用各自已有的输出通道。

部署包提供 Python 包离线更新入口。操作者先停止 host 及全部 CLI，更新器保持原虚拟环境绝对路径，安装包内配套依赖和 wheel，并检查依赖、实际版本、原配置及原状态库。包内携带 Python 3.11、Linux ARM64 和 x86_64 对应的依赖 wheel。目标机已安装 Python 3.11 和 uv；更新不得联网、探测设备、改写配置、自动迁移数据库或启动业务。

| 更新阶段或实际结果 | 应执行的行为 |
| --- | --- |
| 交付物缺失、摘要不符、平台不支持或原环境不成立 | 在修改 Python 环境前拒绝，报告具体事实。 |
| 原状态库缺失、配置无法解释或会话锁仍有持有者 | 拒绝更新；不创建新库，不以更新代替首次部署。 |
| 前置条件成立 | 持有原稳定会话锁和接纳锁，记录原安装信息及原配置身份，在原环境离线安装。 |
| 安装或检查失败 | 以失败结束并保留日志、收据及原版本信息；Python 环境可能已改变，不声称自动回滚。 |
| 新软件不支持原数据库格式 | 保留原库，明确报告不兼容；后续迁移须另行显式执行，不能恢复 host 普通调用。 |
| 安装、版本与原部署检查均通过 | 报告更新完成但未启动；操作者按原入口恢复 host。 |

旧部署包及其配套依赖由运维保留，失败后可以按原包重新安装；重新安装旧软件不撤销数据库升级。能力说明按原配置重新导出为更新产物，是否同步客户端由明确目标路径决定，不覆盖客户端数据库或媒体。

## 步骤与职责

- [ ] V1：补齐版本与更新规格，明确日志例外、离线包契约及失败边界。
- [ ] V2：Python 版本查询和启动记录使用单一来源，补齐默认过滤及拥塞下的单元分区。
- [ ] V3：host 和客户端按各自版本来源输出启动版本，核对源码包、构建和安装入口。
- [ ] V4：部署包携带离线依赖及更新入口，接通原环境安装、锁、收据和只读部署检查；同步 skill、模板及说明。
- [ ] V5：执行适用的隔离单元和静态检查，完成独立评审并提交；明确保留未运行的发行物、SQL 组合及设备范围。

V2 由根代理负责；V3、V4 分别在独立工作树实施。V4 独占部署包格式、脚本、更新器及对应测试，并拥有只读部署检查模块；V2 不修改这些文件。根代理按接口和源码依赖集成，再统一验证。独立代码评审由另一代理负责。

本项不新增或运行集成测试，不构建测试发行物、安装到真实或历史环境、不操作设备。构建与更新脚本的真实执行验证属于未运行范围，不能由内存替身推断通过。Python 3.11 为验证解释器。
