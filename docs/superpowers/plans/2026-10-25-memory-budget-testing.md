# 固定内存预算测试实施计划

## 目标与行为契约

行为契约、计量范围与环境错误由[内存预算测试说明](../../camctl/memory-budget-testing.md)完整维护。本计划实施测试侧的统一预算配置、进程边界、资源核验和业务见证，不修改生产代码、生产配置或依赖。测试发现的生产缺陷保留独立失败证据。

## 实施步骤和进度

以下文件拆分属于实现建议；每步按数据流和现有入口调整。

- [x] S1：将测试侧预算配置、资源组控制和独立进程证据接到内存与交换空间合计预算；v1 核验同一合计计数器的限额与峰值。用受控状态验证配置、超限、内存不足、子进程及清理语义。
- [x] S2：保留直接 pytest、隔离运行器及 CLI／host 入口的统一配置，增加 sudo 创建本次专属委派目录的测试启动器；原测试及业务进程继续以调用用户身份运行，失败和中断仅清理本次目录。现有同进程组件测试不宣称已覆盖独立程序预算。
- [x] S3：重做固定批量持久化容量测试的执行边界，在组外准备真实输入，在受限进程执行原生产写入与原键核实，在组外核对完整结果。移出逐分配追踪，保留读取边界、索引及真实提交的等价验收。覆盖跨页、缓存淘汰与多轮累计输入，明确有限样本的证明范围。
- [x] S4：核验预算执行器能发现超限或子进程内存不足，即使父进程返回成功也不能通过；验证业务缺失仍失败。完成相关单元与集成检查、独立评审和测试侧变更范围审计。
- [x] S5：更新运行说明和验证记录，记录实际耗时、环境限制、未执行范围及发现的生产问题；提交可审查结果。

S3 的独立业务边界已接通，三轮累计输入采用同库新增三次文件摘要记录后核实原操作，未覆盖多次新动作或长期完整会话。S1／S2 的合计预算与 sudo 委派接线、S4 的真实内核专项和 513 项容量入口均已完成；CLI／host 真实部署检查、组件直接 pytest 加载和中断后收据恢复也已核验。实现和实际验证结果见[改造记录](../../camctl/memory-budget-test-results.md)。严格无交换运行能力另行验收。

## 验收分类

| 输入或运行情况 | 必须观察到的结果 |
| --- | --- |
| 默认预算或显式合法容量 | 各入口取得相同精确字节值，实际限制和证据与请求相符。 |
| 非法单位、零或负容量 | 测试启动前明确拒绝。 |
| 主进程及短命、长期、脱离父进程的后代 | 全部仍归属同一预算范围，峰值和内存不足事件不能因父进程退出而漏记。 |
| 合计超预算、内存不足后父进程吞错 | 测试失败，保存内存及合计峰值、事件和业务结果。 |
| 业务输出缺失但进程退出成功 | 业务断言失败，不把低内存或退出码当作成功依据。 |
| 控制器只读、缺失或不能核验合计预算 | 明确环境错误，未执行的容量验收不算通过。 |
| 有限输入跨过原页上限和缓存容量、反复处理后历史持续增长 | 完整业务与恢复结果正确，仍满足同一绝对预算；不再以两个小规模的峰值差代替整体预算。 |
| 测试失败、取消或外层中断 | 只清理本次创建的资源组和已拥有进程，并保留失败证据。 |

## 环境与验证记录

实施前已核对 Python 3.11.17。当前开发容器的内核为 WSL2 5.15，使用混合资源组层级，内存控制器权限和交换限制能力须在 S1 实测确认。目标部署为 ARM64 Ubuntu 18.04；其内核、控制器版本与授权范围须独立核对，不能将开发容器验证等同于目标设备验收。

当前容器使用 memory v1，具备合计限额与合计峰值接口，宿主交换空间已启用。普通用户不能在共享根下创建叶组；免密 sudo 可创建本次专属委派目录。真实运行已确认普通用户能够创建叶组、落实两个限额并完成收场。64MiB 专项正确识别父进程隐藏的子进程内存不足；513 项容量与 CLI／host 部署检查在配置预算内通过，专属叶组与委派目录均已删除。资源证据、实际耗时、源码审计及未执行范围见改造记录。
