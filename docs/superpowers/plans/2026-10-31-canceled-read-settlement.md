# 取消读取的实际结果与可靠进度收场

## 目标与契约

普通取回和录像内部输入都必须分别判断源读取是否实际结束、主机副本的全部进度是否已经可靠提交。源会话到达末尾不能替代 `committed_bytes=source_size`。取消先于最后一段保存生效时，保存原读取结果并结束取消责任，不申请缺少可靠完整进度的 `READ_END`。

行为依据为[实际读取结束与所属结果](../../architecture/file-copy.md#实际读取结束与所属结果)、[完整读取结束的持久化与恢复](../../architecture/file-copy.md#完整读取结束的持久化与恢复)及[取消动作的完成时机](../../architecture/task-cancellation.md#取消动作的完成时机)。保留原票据、次数、来源、轮次、真实 `ReadEnd`、原观察时刻及操作键；不放宽独立守卫，不用本地文件长度补造进度或驱动成功。

| 实际源返回 | 可靠进度 | 取消及原保存状态 | 结果 |
| --- | --- | --- | --- |
| 未确认停止 | 任意 | 任意 | 保留原责任和保护，继续必要停止。 |
| 正常 EOF 并实际停止 | 尚未完整提交，段保存因拥有者资格跳过 | 取消已经生效 | 不保存完整 `READ_END`；原尝试 `SUCCEEDED`，流程 `CANCELED`。 |
| 控制停止，尚未读完整 | 任意 | 取消已经生效 | 原尝试 `UNKNOWN/read_stopped`，流程 `CANCELED`，保留可靠进度。 |
| 控制停止或拥有者资格跳过，已经实际停止 | 任意 | 没有业务取消，原流程仍为 `PENDING` 或 `ACTIVE` | 保留原观察及原尝试，等待原资格恢复；不把会话退出解释为业务取消。 |
| 源已实际停止并取得原返回 | 任意 | 原读取流程已经终态 | 保存真实尝试结果，保持原流程状态和错误；不建立续读责任。 |
| 正常 EOF 并实际停止 | 全部进度已可靠提交 | 取消已经生效 | 先保存真实完整结束，原尝试 `SUCCEEDED`，流程 `CANCELED`；不继续发布或处理。 |
| 正常 EOF 并实际停止 | 全部进度已可靠提交 | 仍可普通执行 | 按原校验、重拷及所属业务规则处理。 |
| 明确读取或主机错误 | 任意 | 任意 | 保留原错误及其责任，不用控制停止或取消掩盖错误。 |
| 已持有完整结果或业务保存申请 | 任意 | 后到取消、回执未知或回滚 | 优先核实原申请及原键，不重算结果或打开来源。 |
| 旧未结束尝试缺少原返回 | 任意 | 已取消，旧拥有者结束边界和驱动恢复契约均成立 | 沿原票据保存 `ASSUMED/UNKNOWN/result_not_saved` 并将流程收场为 `CANCELED`；不推断原 EOF，不重新读取。 |
| 旧未结束尝试缺少原返回 | 任意 | 旧拥有者结束边界或驱动契约不能确认 | 保留责任及恢复诊断，不释放保护。 |

## 实施步骤

- [x] C1：核对普通设备取回、本机及照片缓存、录像检查和修复输入的生产者、结果消费者与冷恢复入口；以隔离单元反例证实缺陷。
- [x] C2：分别传递真实源完整性和可靠副本完整性；将拥有者跳过时的真实返回接入原读取结果收场，并覆盖普通本机入口。
- [x] C3：接通已取消旧读取的有界发现及原票据恢复。优先持有结果、未决业务保存及持久结束依据；旧拥有者仍活动时不恢复，不修改历史失败现场。
- [x] C4：运行受影响的隔离单元验证和静态检查，完成独立评审，修复确认的问题，记录实际验证边界并提交。

实现位置和拆分可按实际共同责任边界调整。根代理统一负责生产事实，测试子代理仅在独立工作树补充单元用例，评审子代理只读审计。每步更新本计划；验证证据保存在 camctl 验证记录。

C1 的基线反例为 3 项失败；C2、C3 已接通三个结果消费者及共同冷恢复入口。定向隔离验证为 66 项及 4 个子测试通过，详细边界见[验证记录](../../camctl/canceled-read-settlement-verification-2026-10-31.md)。

## 验证范围

验证覆盖源 EOF 与可靠进度不一致、正常完整提交、部分停止、明确错误、后到取消、原键重送及恢复阻挡。单元测试在导入前隔离资源与协作者，使用内存替身；不新增或运行集成测试，不操作相机，不修改旧真机环境或其状态库。部署包 `70316ef3` 在取消修复前交付，后续源码修复不改变该包的内容或版本含义。
