# 普通尝试的目标与流程关联

## 目标与依据

普通意图、结果和原键读取都必须指向原责任实际拥有的对象。规范责任键与合法目标列不能代替跨表关系核对。读取流程与拷贝共同创建时，事务内校验必须允许相互引用，并拒绝缺失或矛盾的关系。依据为[操作身份与参数](../../camctl/database/operation-fields.md#操作流程的身份与参数)、[查询用途](../../camctl/database/operation-fields.md#查询用途责任键和目标字段)、[事务边界](../../camctl/database/transactions.md#写操作目录)、[延迟外键](../../camctl/database/common.md#结构定义与校验边界)及[软件验证](../../camctl/verification.md)。

本计划完成固定身份及目标归属。普通意图的完整原组组成、原配置和时刻复用、操作类别的可靠保存、状态与次数的完整资格模型仍由[事件审查](2026-10-02-camctl-event-contracts-review.md#未完成的消费者与恢复边界)跟踪。普通入口能否读取原子启动授予的票据尚待业务决策，不能在本计划内自行决定。设备绑定、动作类型及可执行资格的完整业务核对另行闭合；不把固定关联校验的通过解释为已经取得执行资格。

## 已确定的行为契约

流程创建后，种类、发起动作、用途、规范责任键、三个目标列、交付引用与会话引用不改变。输入与原流程的固定身份逐列一致，才可继续判断终态、次数和等待；错误关联不能被终态或额度耗尽掩盖。原键读取只核对这些固定关系，不用后来采用的配置、次数或合法终态否定原身份。

| 责任种类或用途 | 目标与归属 |
| --- | --- |
| `START`、`STOP`、`CHECK_CAPTURE_RESULTS` | 仅填写原活动；活动所属动作等于流程和输入动作。 |
| `STOP_RESIDUAL` | 仅填写历史活动；流程和输入动作是触发者，允许与活动所属动作不同。 |
| `READ_FILE` 的交付拷贝 | 仅填写原拷贝；恰归属交付或处理之一。交付引用等于拷贝的交付，流程动作等于交付动作。源文件可以属于其他拍摄动作。 |
| `READ_FILE` 的内部处理拷贝 | 仅填写原拷贝；交付引用为空，流程动作等于拷贝关联的录像处理动作。 |
| `DELETE_FILE`、`CHECK_FILE_EXISTS` | 仅填写原清理项；流程与输入动作等于清理项所属动作。源文件保留自身来源。 |
| `QUERY_ACTIVITY / BEFORE_EXECUTION` | 三个目标列为空；固定发起动作。 |
| `QUERY_ACTIVITY / START_CONFIRMATION`、`STOP_CONFIRMATION` | 仅填写该动作的活动；恰有一个同动作、同活动的原启动或停止流程，其固定身份同样有效。 |
| `QUERY_ACTIVITY / ACTIVITY_OBSERVATION` | 仅填写该动作自身活动。 |
| `QUERY_ACTIVITY / RESIDUAL_STOP_CONFIRMATION` | 仅填写历史活动；恰有一个相同触发动作、相同历史活动的原残留停止流程，其固定身份同样有效。 |

只有查询填写用途；只有交付读取填写交付引用；所有普通流程的会话引用为空。身份使用合法的正整数，未知种类和用途明确拒绝。原键读取及结果保存同样核对上述关系，不能只在写事件时保证。

| 入口与已有事实 | 处理结果 |
| --- | --- |
| 新键，已有流程且固定身份及归属有效 | 继续既有次数、状态和等待判断；本计划不改变其资格规则。 |
| 新键，已有流程但目标或归属不同 | 一致性检查失败，整组回滚；不返回普通预算或终态拒绝。 |
| 新键，按规范键找不到流程，但相同实际责任已有流程，或键和实际责任各自命中不同流程 | 核对原固定责任；错误键或多条记录按一致性错误拒绝，不把它解释为可创建的新责任。查询同时按规范键与所属种类的责任字段定位，最多取两条。 |
| 新键，没有流程，且所属责任允许首次建立 | 先核对目标关系，再创建原责任。 |
| 新键，拷贝存在但没有其必需读取流程 | 按一致性错误拒绝，不创建替代流程。 |
| 查询确认的原流程为零条、多条，或查到身份后记录缺失 | 按一致性错误拒绝；有界查询最多取两条，不忽略缺失行或任选一条。 |
| 原键，固定身份和关联有效，后来状态或配置已改变 | 保持原票据或结果的既定恢复行为；不重新消耗额度。本计划不补齐尚未定义的原组复用规则。 |
| 原键，固定身份或关联矛盾 | 明确拒绝，数据库保持原值。 |
| 结果首次保存、迟到或原键恢复 | 共同核对原流程的固定关联；后续已确定结果保持原有语义。 |
| 查询或读取抛出数据库错误 | 保留原错误；所有已取得游标释放，不把错误解释为不存在。 |

### 同一事务的关联事实

文件资格共同保存目标文件、适用交付、读取流程和拷贝。读取流程可以先于拷贝出现在事件顺序中，延迟外键在共同提交时检查引用，业务关联也按完整事务检查。关联守卫使用完整提案中的固定身份；状态、资格、报告影响及前后值检查仍使用各事件之前的事实。

| 当前事件与完整事务 | 关联判断 |
| --- | --- |
| 目标已在当前事件之前存在 | 按目标原固定身份核对。 |
| 目标在当前事件之后创建，完整提案中关系有效 | 允许共同创建；不能将尚未应用的创建解释为数据库缺失。 |
| 完整提案没有必需目标或父对象 | 拒绝整组，不推迟业务核对到外键或省略检查。 |
| 完整提案中目标、父对象或唯一流程的关系矛盾 | 拒绝整组，历史和投影不产生部分提交。 |
| 未提供完整事务事实的独立校验 | 使用事件之前的事实叠加当前事件的 `after` 行。当前新建拷贝或读取流程参与关联核对及唯一性判断；缺少必需关系就拒绝，不默认存在后来创建。 |
| 完整事务事实显式为空 | 按空图拒绝必需关联，不退回事件之前的事实。 |

建议扩展 `EventContext`，提供可选的 `transaction_rows`。P3 已为报告排序建立完整提案行图，应复用该图，不再复制全库或引入查询。只有固定关联守卫使用它；明确的空图不能退回旧图，未提供才使用事件事实。拷贝关联守卫也使用完整提案，避免事件顺序成为联合创建的额外限制。历史归属沿登记的固定列解析，同样可以读取后来创建的关联对象；当前登记的条件、继承、关联链和终点列均为不可变身份，不读取后来的状态。报告影响继续使用事件时事实。该接口及文件划分是实施建议，不是公共协议变更。

## 禁止采用的捷径与剩余事项

不能只把输入责任键与保存的键比较，不能跳过原键或只读分支的关系检查，不能以终态和预算掩盖关联矛盾，不能为已有拷贝补建流程，不能任选查询原流程，不能要求残留触发动作等于原活动动作，不能要求取回动作等于源拍摄动作。完整提案只能证明固定关联，不能用后来的状态倒推此前已经取得资格。不能改变枚举、SQL 约束或正式守卫来迁就错误测试夹具。

原完整意图、原操作类别、次数连续性、未收场尝试及设备资格不在本计划的完成声明中。完成固定关联后，继续沿这些已有余项审查并修复；本计划不替代路线图 O2 等完整任务的验收。
