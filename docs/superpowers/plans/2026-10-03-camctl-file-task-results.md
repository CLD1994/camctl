# 文件任务结果与等待中断

## 行为契约

依据[文件执行](../../camctl/file-runtime.md#本地文件执行使用默认线程池)及[取消收场](../../architecture/obtaining-outputs.md#拷贝期间的取消与文件操作收场)，文件任务的执行状态与等待者的状态分别判断。执行方保存唯一完成结果；等待者未取得结果时，已经执行的任务由监督器登记的拥有者接手，包括操作刚结束而等待随后被取消的情况。任务的文件修改资格在实际执行结束或可靠撤回时释放。

| 中断时的任务状态 | 原等待者结果 | 任务、文件资格与实际结果的责任 |
| --- | --- | --- |
| 提交调用抛错，执行体尚未开始 | 原提交异常 | 在执行器锁内撤回，释放资格；后到执行包装器不得执行文件操作。 |
| 线程执行包装器等待时失败，执行体尚未开始 | 原包装器异常 | 同样撤回，后续同文件任务可以提交。 |
| 等待者取消，执行体尚未开始 | 取消 | 在锁内与开始竞争；成功撤回后不执行，不登记实际操作接手。 |
| 等待者取消或执行包装器报错，执行体已开始且尚未结束 | 取消或原包装器异常 | 登记唯一接手责任；实际结束前保留资格，接手方等待原结果。 |
| 等待者取消或执行包装器报错，执行体已结束，结果尚未交给原等待者 | 取消或原包装器异常 | 仍登记接手；句柄立即提供已保存结果，不重做操作。 |
| 普通等待成功 | 实际任务结果 | 不登记接手，资格已按实际结束释放。 |

执行体正常返回 `None` 也是成功；`ran=False` 区分从未执行。执行体抛出普通异常时保留任务失败诊断。文件操作所需的分阶段效果由执行体返回结构化结果，通用执行器不解释或推断这些业务事实。

执行体自身抛出 `asyncio.CancelledError` 时，先保存 `ran=True` 的实际失败结果并释放文件修改资格，再将原取消传播给执行包装器。原等待者尚在等待时按取消接手；原等待者已取消时，既有接手方仍能取得结果。此情况不能留下永久未完成的句柄。

| 实际状态 | 文件修改资格 | 任务身份与结果责任 |
| --- | --- | --- |
| 可靠撤回，执行体从未开始 | 释放 | 结束身份保留；迟到包装器仅取得原撤回事实。 |
| 执行仍在进行 | 保留 | 保留身份，原等待者或接手者拥有结果责任。 |
| 实际结束，结果尚未交付 | 释放 | 保留身份，同名任务在执行前拒绝；异名同文件任务可以提交。 |
| 结果交给原等待者或句柄等待者 | 已释放 | 结束身份保留，允许再次使用此任务身份；旧句柄后续观察不得移除新任务身份。 |

句柄只通过已登记的监督责任交给接手方。监督器开始调用拥有者前取出该待消费责任，句柄交付结果后才允许复用身份。多个观察者取得同一结果时，身份释放幂等且核对原任务对象。

句柄可以有多个等待者。取消某个等待不得取消共享完成事实，也不能要求为每个等待者创建额外线程。执行包装器的后台结束由执行器保持引用并观察异常，直到实际完成；业务接手方仍负责观察实际任务结果。普通执行异常与 asyncio 取消属于本任务范围，进程强制退出等不扩展成新的应用内恢复机制。

## 修复责任与实施安排

实现位置预计是 `host_files/tasks.py`，沿 `run_file_task → _execute → FileTaskHandle.wait → Supervisor` 追踪；辅助函数及状态字段可以调整。优先复用标准库 `concurrent.futures.Future` 和 asyncio 适配，不新增等待线程或重复结果缓存。

- [x] 用受 `ThreadRunner` 契约约束的可控执行器，先复现完成后取消漏接手、同步提交失败、异步提交失败、执行完成后包装器失败及正常返回 None 被误判失败。分别断言结果身份和文件资格，不依赖睡眠碰撞时序。
- [x] 将提交纳入异常责任边界；中断时在锁内判断撤回或接手，不以任务已结束为由丢掉未交付结果。统一保存完成事实，句柄等待取消不影响后续观察。
- [x] 先用反例验证执行体取消的完成事实和未交付结果的身份保留；按上表分别处理文件资格、任务身份与结果交付，复验多等待者及旧句柄观察。
- [x] 用实际线程池与监督器验证完成／取消交错、已有操作错误、多个等待者、后续同文件任务，以及失败出口的实际收场。审计任务身份与修改资格释放，不把等待取消当成操作结束。
- [x] 运行单元、集成测试的 Python 3.11 回归，独立复核并更新主路线图。业务进度提交、相机机会释放仍由各自流程验收。

## 验证证据与后续边界

新增 7 项单元反例先失败后修复，分别覆盖提交失败、完成后取消、包装器失败、None 返回、执行体取消及身份保留。Python 3.11 与 3.12 的 `tests/unit/devices`、`tests/unit/host_files`、`tests/unit/session` 各通过 370 项。保留既有 `test_source_stream_protocol_shape` 的 asyncio 标记警告。

两版的读取会话、会话结束、分段传输及文件任务集成范围各通过 46 项，其中 `tests/integration/host_files/test_tasks.py` 通过 11 项。实际线程池与监督器验证在途操作、完成后取消、后台包装器失败、多个等待者以及身份复用；事件循环异常处理器验证未交付包装器的错误仍被观察。

独立复核核对实际结束、资格释放、身份保留、结果交付及迟到包装器的状态转换。身份保留以结果交付为终点，不代表接手者后续的数据库保存或业务处理已经结束。完整拷贝流程仍须独立验证进度事务、取消清理和相机机会释放。
