# 空业务会话的后台收场与退出

## 目标与既有契约

`run` 在持久化动作、必要收场和适用报告工作完成后，必须能够结束本次本地责任并关闭接纳。只有本次报告失败时返回 `report_error`。已开始的任务及未消费错误先交付，正常收场不能取消它们或提前释放资源；新工作仍由原关闭写事务决定继续处理或交给后续会话。权威规则见[请求受理与会话](../../architecture/protocol-session.md#run-正常关闭接纳)及[会话接口](../../camctl/implementation.md#调度与会话接口契约)。

本地发现轮次可能尚在查询，也可能已经结束但未消费。若把它们先计入“是否需要继续驱动”再决定是否收场，每轮新建的空取回、空清理任务会反复阻止收场。修复在共同会话边界完成，保留各后台拥有者的原责任计数与结果消费。

## 状态与处理

| 数据库原责任与本地结果 | 会话处理 |
| --- | --- |
| 仍有未完成动作、持久化必要收场或待报告变化 | 继续驱动业务，本地任务仍由原拥有者持有。 |
| 无上述责任，本地任务正在执行或结果尚未消费 | 先收场现有本地任务，不启动新轮次、不请求正常任务停止。 |
| 本地收场失败或收到取消 | 沿原异常及取消规则交付，资源按实际结果收场。 |
| 本地收场结束，关闭事务观察到新工作 | 保持接纳并继续驱动。 |
| 本地收场结束，关闭事务确认无新工作 | 事务内释放接纳，按当前报告责任返回成功或 `report_error`。 |

1. [x] 建立有限、可证伪的退出反例，覆盖成功与报告失败、实际任务等待、晚到错误和关闭期间新增工作。
2. [x] 分开数据库预判与包含本地责任的最终检查；在两者之间复用原正常收场，不重启发现轮次。
3. [x] 重跑原日志副本失败用例及相关会话、后台、清理测试，独立复核关闭竞争和错误交付。
4. [x] 完成 Python 3.11 回归并更新验证记录；真实设备、安装包与目标部署分别保留范围。

模块和内部参数为实现选择。建议保留 `_run_work_facts` 的完整检查入口，仅使主循环的收场预判读取数据库原责任；最终 `_try_close` 继续在写事务内检查完整工作事实及释放接纳。不能通过忽略已完成任务、增加固定等待或减少真实责任检查使测试通过。
