# 报告编码与生成前置的实施审查

## 范围与依据

冻结报告进入生成链后，编码器负责将固定事实变成确定字节。行为依据为[报告编码](../../architecture/report-encoding.md)、[报告生成接口](../../camctl/report-runtime.md#报告模块接口契约)及 `report-dependencies.json`。本计划先闭合确定字节及编码缓冲；历史分页恢复和真实进程装配继续按 R3—R5 完成，不将当前事实集合接口当作完整生成器。

## 缺陷与修复边界

1. 编码直接复用数据库 JSON 保存函数，字段依照字典插入顺序输出，Decimal 保留原表示。这违反同值同字节、固定字段顺序及精确数字统一写法。报告编码使用自己的固定业务排版；数据库保存规则不改变。
2. 计划及动作的实体数组依照输入次序输出，未保证整数 ID 排序和同集合唯一性。编码必须按所属实体集合的规范 ID 升序输出，重复身份拒绝；普通参数数组仍保留输入顺序。子集合只在声明的协议层级识别，参数中的同名字段不能误分类。
3. 所谓分批输出先生成完整正文再按全文长度切片，缓冲大小还随正文增长。将字节输出改为容量明确的流式接口；完整编码只作为小型调用的便利包装。每个片段不超过缓冲容量，不能调用完整报告编码后切片。
4. 工作进程任务及结果携带完整正文，真实控制消息、spawn、工作锁、冻结历史生成和进程监督缺失。现有子进程测试运行独立大写转换脚本，并不证明生产实现。R4/R5 的完整任务保持未完成，后续沿下列前置顺序接入真实生成链。

标准库 `json` 提供固定字符串转义，但不能直接编码 Decimal，也不提供本项目按数值分区规定的统一数字表示。自有逻辑只处理这些业务规则；字符串转义继续使用标准库。字段及实体结构从共享投影的权威登记推导，不复制完整结构清单，不新增依赖。

## 输入、输出与分类

输入是合法精确 JSON 值及已确定的入选实体事实。公开 ID 使用规范十进制字符串；实体排序比较完整整数值。字段名必须是字符串。编码不读取时间、配置、设备或新的数据库状态。

| 值或所在层级 | 编码规则 |
| --- | --- |
| 根报告、计划、动作的自身字段 | 按 Unicode 码点顺序输出，再输出该层声明的实体子集合 |
| 实体子集合 | 按权威登记 `encoding_order` 顺序放在自身字段之后；顺序从 1 开始连续且唯一，与字段书写次序无关；按整数 ID 排序，重复身份报错，空集合省略 |
| 自身字段中的对象及普通数组 | 对象成员递归排序，数组保序；保留 `[]`、`{}`、`null` 与缺省的区别 |
| 精确数值为零 | 输出 `0`，不保留负号或尾随零 |
| 非零且 `10^-6 <= abs(value) < 10^21` | 普通十进制，去掉小数尾随零，不舍入 |
| 其他非零有限数值 | 小写 `e` 的科学计数法；尾数和指数无多余零或正号，不舍入 |
| bool、null、合法字符串 | 使用对应 JSON 字面量；字符串直接输出 UTF-8，固定转义，不归一化 |
| float、非有限数值、非法 ID、重复实体或无法解释的投影 | 明确失败，不能返回空实体或成功；可能已产出的字节是未完成文件，不能发布 |

根对象后仅有一个 LF。字节缓冲容量是正整数，不能以 bool 或浮点值充当容量。批次和缓冲变化不影响拼接字节及摘要。

## 实施顺序

文件划分及内部接口是实施建议；上述契约为硬性要求。

- [x] E1：先以现有公开编码入口证明字段顺序、数字等价、实体排序、参数同名字段及重复身份的反例；数字各分区直接使用独立字节预期。
- [x] E2：在共享公开投影提供由权威登记推导的实体结构；登记语法及检查器共同校验明确的子集合编码顺序。报告编码复用该结构与标准库字符串转义，实现精确数字及按层级的确定输出。先验证失败，再实施，再运行对应单元测试。
- [x] E3：提供 `iter_report_chunks(document, facts, *, buffer_size)`；不生成完整报告正文后再切片，先输出元数据，再逐个投影根实体。`encode_report` 只拼接该接口。验证容量、早期输出、延后发生的投影错误及缓冲变化同字节。
- [x] E4：组合真实受理、SQLite、冻结范围、公开投影、编码和公共 Schema，独立检查输出次序、精确值及 SHA-256。数据库在冻结后不再写入；历史恢复和分页由后续任务验证。单元测试隔离稳定协作者，集成测试验证真实组合。
- [x] E5：执行 Python 3.12/3.11 单元与相关集成门禁、字段登记检查，独立复核实际改动，记录验证边界及既有全量门禁问题，更新 R3/R4/R5 和路线图的勾选状态并提交。

## 生成链后续顺序

- [ ] 按固定 H 分页选择实体及父实体；修正当前 `entity_facts` 忽略范围、读取全库且没有绑定恢复边界的问题。
- [ ] 公开投影及写出按子集合跨页衔接；一个计划或动作拥有大量子实体时，不形成完整子树。
- [ ] 建立小型生成任务、结果和受校验控制消息；区分 report_id、task_id、数据库身份与独占临时文件，保留状态库错误分类。
- [ ] 建立真实 spawn、父死亡保护、工作锁、短读事务、文件同步和通信所有权；按已确认状态表监督结果、停止、超时及退出。
- [ ] 维护协调器消费实际冻结依据与生成结果，接入报告专属发布、同步动作本地完成及正常会话。

## 验证证据

现有公开编码入口的反例有 9 项目标失败，覆盖自身字段顺序、同值同字节、数字分区、实体顺序与重复身份；缓冲与早期输出反例有 2 项目标失败。字段结构登记的反例验证缺省、非法、重复及不连续顺序；Node 检查器在实施连续性规则前，重复和缺号用例各自因没有抛出异常而失败。

编码与字段结构单元测试共 74 项通过。Python 3.12 与 3.11 的单元门禁各有 1202 项通过、1 项排除；命令为 `pytest -q apps/camctl/tests/unit -k 'not test_accepted_record_delivers_receipt'`。被排除的既有日志凭据等待问题及两项同步测试误标异步的警告见[发布事实审查的验证记录](2026-10-02-camctl-report-publication-review.md#验证证据)，没有删除测试或放宽配置。

Node 字段登记与条件测试共 57 项通过，正式登记检查通过：23 个投影、99 条字段映射及 123 个来源与关联列均与真实 SQL 对应。

Python 3.12 的真实编码组合有 3 项通过，覆盖独立字节预期、缓冲不变性、公共 Schema、摘要，以及权威字段成员换序。成功替身在集成层通过真实公共 Schema 校验，单元层只隔离稳定协作者，不读资源文件。

Python 3.12 与 3.11 各执行 `pytest -q apps/camctl/tests/integration/contracts apps/camctl/tests/integration/history apps/camctl/tests/integration/reporting`，各有 229 项通过。独立复核覆盖数字分区、精度、非法值、字段登记及成功替身；文档链接与 `git diff --check` 通过。没有据此宣称全量组件集成门禁通过；既有产物资格模块的 9 项失败仍见发布事实审查的验证记录，后续按所属业务修复。

当前没有真实 `messages.py`、`communication.py`、`supervisor.py` 或冻结历史生成入口；不能以独立演示脚本或状态模型测试证明这些交付。字节缓冲有限不等于全部生成内存有限：传入的事实和选中身份仍是完整集合，单个计划或动作的投影仍组装完整子树，R3 的分页生成任务保持未完成。
