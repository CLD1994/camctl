# 报告管理的变化事实与原键恢复

## 目标与依据

报告首次确定的字节、每次发布及文件错误来自不可变历史。管理事件只保存变化；原操作键读取恢复原完整事务时的结果，不要求未变化字段再次出现在正文，也不从后来阶段补造原结果。依据为[报告发布规则](../../architecture/report-publication.md#记录报告已经发布)、[确定字节与管理状态](2026-10-02-camctl-report-publication-review.md#状态分类与不变量)、[事务核实](../../camctl/database/transactions.md#公共完成与失败契约)、[变化事实消费者](2026-10-02-camctl-event-contracts-review.md#未完成的消费者与恢复边界)及[限定行恢复](2026-10-02-camctl-attempt-result-reuse.md#限定行恢复的边界)。内部函数及文件划分是实施建议。

## 状态与输入契约

输入是原操作键、报告 ID、管理分支、整数微秒的事实时刻及该分支的实际事实。`PREPARE` 接收受约束的长度与摘要，`FAIL` 接收精确、可持久化的 JSON 对象，`PUBLISH` 接收符合既定文件端口契约的可靠完成证明。`INTENT` 没有额外字节输入，原响应来自当时已经确定的字节。默认时刻 `0` 同样核对。

| 原键与输入 | 结果 |
| --- | --- |
| 原键不存在，输入合法 | 按同一事务的当前可靠管理状态判断保存、只读或拒绝。 |
| 原键存在，恰好一条对应报告与分支的管理事件，时刻和输入相符 | 核实原完整事务并恢复原 H 的管理列，只读返回原结果。 |
| 原键属于其他目标、阶段、组成，或时刻及事实不同 | 拒绝，数据库不变，不执行文件副作用。 |
| 原组、报告、固定字节来源、历史目录或 H/C 不可解释 | 一致性错误，不返回当前阶段的替代结果。 |
| SQL 查询或迭代失败 | 保留实际数据库异常，关闭已取得游标，整项回滚。 |

没有持久化事件的只读结果不绑定操作键。可靠查不到该键只证明没有原事务，后续仍按当前资格判断。

| 管理分支 | H 时的结果及输入核对 |
| --- | --- |
| `PREPARE`，首次形成字节 | 原完整状态为 `PREPARED`，原长度与摘要匹配输入，返回原字节。 |
| `PREPARE`，已知字节重建 | 正文可只有阶段或错误变化；核实首次字节历史并恢复 H，匹配输入，返回原字节。 |
| `INTENT` | 原完整状态为 `PUBLISHING`，原错误保持；核实已知字节来源，返回原字节。 |
| `PUBLISH` | 原完整状态为 `PUBLISHED`；次数恰好增加一次，成功引用为原事件，返回该次发布身份与次数。 |
| `FAIL` | 原完整状态为 `FAILED`，原错误非空且与输入精确相等；返回 `None`。未变化的错误从 H 恢复。 |

`B` 是首次确定的长度与摘要。最早的 `PREPARE` 必须实际将共同为空的两列变为合法 `B`，且属于对应报告的完整历史事务。首次字节查询限定于 H，不将 H 后首次形成的字节带入较早失败响应。读取完整原组并核对物理行、事件及分支；没有来源只表示 H 时尚无字节，恢复出的管理状态也必须共同为空。已有来源时，两者精确一致；所有后续重建不能改变 B。查询只取最早一项，复用共享完整事务解码，不加载全部报告历史。

限定恢复使用原管理事务的完整末边界 H 和当前写事务的完整 C，只恢复 `status`、`size_bytes`、`sha256`、`publication_count`、`last_published_event_id`、`last_error_json`。复用有界目录读取及值连续性，不把六列结果声明为完整历史对象。原事件所有变化后值都必须与恢复值一致；由原前值形成完整前状态，与完整后状态一起核对分支。正式写守卫也核对同一完整状态；分支约束从权威 `event-transitions.json` 读取，不维护第二套阶段清单。

## 失败事件的变化分类

| 原状态 | 本次错误与原错误 | 保存事实 |
| --- | --- | --- |
| `FAILED` | 精确相同 | 只读，不产生历史，不绑定新键。 |
| `FAILED` | 精确不同 | 仅错误变化；完整后状态仍为 `FAILED`。 |
| 其他允许失败的阶段 | 精确相同 | 仅阶段变化；错误保留，不重复写入正文。 |
| 其他允许失败的阶段 | 精确不同 | 阶段与错误变化。 |

`FAIL.required` 允许省略未变化错误，完整状态守卫要求后状态为 `FAILED` 且错误非空。省略不等于清空，也不允许把错误更新提交在其他阶段。报告字节和既有发布次数及成功引用保持。

## 顺序与门禁

- [ ] M1：建立真实 SQLite 反例，覆盖重建准备的原键重送、发布意图与失败后的原响应，以及相同错误伴随阶段变化。确认失败来自契约而非夹具。
- [ ] M2：为最早字节来源建立受接口约束的纯单元反例，覆盖合法、未知、错误归属、缺字段、坏原组、超出 H 和读取故障；实现单项查询、共享完整组证明及游标释放。
- [ ] M3：管理命令先核对纯输入和原键阶段。原键存在时恢复六列到完整 H，核对最早字节来源、完整前后状态和全部输入，返回原结果。后来发布、清错、失败、字节形成和多次补投不能改变原响应。
- [ ] M4：在正式报告守卫复用权威分支对完整状态的约束；修正 `FAIL.required`，同步派生登记与实际包资源。先用绕过普通入口的反例证明省略阶段或错误不能绕过完整状态规则，再调整生产逻辑；不得重写未变化列或放宽完整状态。
- [ ] M5：验证错目标、阶段、时刻、字节、精确错误、坏目录、原组、首次字节、恢复及 SQL 故障。重建与相同错误状态变化分别覆盖确认回滚及提交收据丢失后的同键核实。两版相关门禁、独立复核和全量基线比较后更新局部 checkbox 并提交。

预计修改 `reporting/policy.py`、`persistence/repositories/reporting.py`、权威事件登记及其生成文件，新增报告管理复用的集成测试，并扩充报告守卫和报告读取的纯单元。真实文件机会、生成工作进程、同步本地完成、完整 H4、其他 E3 消费者及 E4 证据成员仍按各自门禁实施。
