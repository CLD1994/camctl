# 拍摄公共准备与哈苏接入

## 目标与行为依据

将现有提前准备流程用于单张照片、录像和延时摄影。公共流程管理准备资格、设备占用、原调用保存、启动窗口及收场；驱动负责具体命令和可靠结果。正式合同由[拍摄提前准备规格](../specs/2026-10-25-capture-preparation-design.md)定义，哈苏参数及拍摄结果沿用[单张参数规格](../specs/2026-10-20-hasselblad-photo-parameters-design.md)。

准备阶段不得触发采集，不建立 START 进入事实，也不创建照片文件责任。真正 START 保留动作原有的取消、次数、结果核实与恢复规则。MF 的相对调焦与 AF-S 的自动对焦仅在真正 START 内按互斥分支执行，不因设置准备的恢复而重复镜头操作。

使用现有标准库、驱动端口和持久化机制，不引入新依赖。模块划分和提交拆分属于实施建议；行为与数据一致性是验收要求。

## 实施与验收

- [x] 1. 提取驱动共用的准备完成证据、默认提前量和会话凭据缓存，建立拍摄动作到控制操作的唯一映射。ADB 使用公共实现，原命令顺序、参数快照及准备匹配行为保持一致。先用单元测试覆盖设备、序列号、活动、参数、准备票据和会话清除。
- [x] 2. 扩展准备占用、失败保存、操作授予及历史复核到照片。查询从公共映射取得动作集合；格式 V5 扩展照片准备失败的数据库约束和事件规则，原显式升级入口保留 V3/V4 全部历史后升级。覆盖候选顺序、原事务重送、准备未收场、取消释放、未开始失败和完整事件复核。
- [x] 3. 哈苏提供独立设置准备和凭据核对，按同一命令定义派生阶段。准备只执行可重复的身份核对和参数设置；实际 START 持有匹配凭据后执行其余对焦和拍摄步骤。保留旧完整控制入口及实际工具诊断，覆盖失败、超时、窗口、凭据不符和无采集副作用。
- [x] 4. 接通调度发现、运行时装配、照片实际入口和恢复责任。照片文件责任在准备完成且具备实际 START 资格后创建；任何既有照片 START 责任优先沿原路径处理，不回到设置准备，不增加拍照次数。目录基准按活动归属规则选择，照片无需基准时直接完成该前置条件。
- [x] 5. 审查生产入口与存储守卫的完整链路，执行受影响单元测试及完整单元测试，记录命令、环境、日志和退出码。不运行集成测试，不操作真实相机。
- [x] 6. 同步架构与哈苏说明，构建并核对安装包。在原人工验证环境无拍摄及在途责任时更新安装，保留配置、数据库、历史及产物，提供人工测试入口。
