# 录像 START 真实消费者闭合执行计划

本计划落实[运行配置闭合计划](2026-10-09-camctl-runtime-configuration-closure.md#rc3-预算调用时限与真实收场使用本次配置)的录像启动子路径。正式行为依据是[录像启动流程](../../camctl/database/recording-start.md)、[录像计时与有限次数](../../architecture/camera-recording.md)、[操作结果和恢复](../../camctl/database/operation-fields.md#正常返回恢复与历史保存)。只覆盖第一版既定数据格式和正常运行／故障范围。

## 输入、事实与输出

真实入口是 `bootstrap.capture_flow → dispatch_ready → capture.handlers._record_handler`。目前独立 `capture.recording.start_recording` 已表达一次授予、派发再检查和调用；生产处理器需要复用这一骨架，并沿原动作、唯一 START 流程、活动和尝试推进。输入包括本次固定配置、原设备与驱动、可信墙钟、会话单调钟、真实 `CallOutcome` 和已经保存的业务事实。输出是共同提交的尝试结果、适用 START 转换与活动事实，以及下一步计时、重试、核实或必要收场责任。

以下为已确认的行为契约：

- 尝试意图与次数在调用前可靠提交；调用一次，只使用原票据和本次 `start_config.timeout_s`。不在驱动或适配器隐藏业务重试。
- `DeviceCallResult.outcome` 为完整结果权威；观察与错误是同源视图。保存原状态、错误详情、效果、`settlement` 和 `call_info`，不得另造 `operation_returned` 覆盖实际假设依据。
- `await` 返回后立即从运行时读取确认墙钟与单调钟，在任何数据库保存之前取得；`StartDispatch` 传同组读数。可靠确认同时带错误时，尝试保留错误，普通 START 按确认事实成功，不重试；录像停止目标仍从实际确认锚点加首次固定时长取得。
- 尝试结果与由本结果派生的 START、发送／启动观察共同提交。提交回滚沿原结果、原票据重送；提交未知先核实，不追加尝试或再次派发。
- 安全重试依据是全部原启动尝试可靠无效果、没有待核实责任和实际在途调用，且取消、终态、窗口、预算、间隔、绑定、设备条件及机会归属均允许。最近一次无效果不能撤销此前未知或已确认的效果。
- 未知启动先使用原 `START_CONFIRMATION` 查询责任；次数独立于 START 且跨启动重试／会话保留。查询成功不自动证明启动，可靠观察按原驱动任务契约解释。
- 取消、已有终态和流程终态保持。迟到调用结果及实际观察仍保存，不重开 START；窗口只限制新派发，窗口内已派发后的迟到确认可以继续录像。

## 完整状态分类

先核对状态库与原事务，再依次应用以下表。取消及终态可结束普通资格，却不能提前结束仍在执行的实际调用或释放未知活动。

| 已保存状态与现实条件 | 本次结果及后续责任 |
| --- | --- |
| 状态不可读、关联矛盾或原提交未知 | 返回状态库错误或核实原事务；不执行新设备调用。 |
| 动作或 START 已终态 | 保持原终态；保存实际到达的原尝试结果与必要活动事实，继续原调用／活动收场。 |
| 取消已经生效 | 不授予新 START；未结束 START 与取消共同结束，原实际调用继续收场，可能活动按取消停止规则处理。 |
| 启动核实的实际调用仍在 await，取消已经生效 | 原查询尝试保持 RUNNING，等待实际收场；不新增冲突 STOP。迟到可靠观察及完整结果共同保存，原 START／查询终态保持。 |
| 原实际调用尚在执行或收场，未取得结束结果 | 原尝试保持 RUNNING，无新增启动；时间和预算到达不代替实际结束。 |
| 已可靠确认启动，包括确认同时带调用错误 | 保存实际结果及确认；普通资格仍有效时 START 成功，进入计时／停止；不追加启动和无必要查询。 |
| 调用已结束但启动效果未知，或原启动核实尚未结束 | 保持未知，沿原 START_CONFIRMATION 有限查询；不凭剩余 START 次数重发。 |
| 启动核实可靠确认启动 | 查询结果、查询成功、START 成功及活动确认共同提交；原未知启动尝试保持。 |
| 核实预算耗尽或所属契约不能继续核实，效果仍未知 | 查询及 START 无法确认，动作以 `capture_result_unconfirmed` 失败；未知活动与占用保留。 |
| 所有原尝试已结束且可靠无效果，没有待核实责任；窗口尚未开始 | 等待窗口，不登记新尝试。 |
| 同上；窗口内，次数小于本次上限，但间隔或设备条件未满足 | 保留 START 与机会，不登记新尝试；间隔完成按既定规则清除标记。 |
| 同上；窗口内，次数小于本次上限，其他条件全部满足 | 同一 START 与活动登记新尝试，采用本次配置并增加一次；提交后再检查派发。 |
| 同上；窗口内，次数达到本次上限 | 保存确定的启动失败及动作结果，次数保持，不重开。 |
| 普通资格有效且窗口内，全部启动尝试可靠无效果，原驱动精确返回已登记的 `device_start_failed` | 按其永久拒绝语义共同保存 START FAILED 与动作错误 11；剩余次数不提供重试资格。其他错误不推导此语义。 |
| 同上；窗口已经结束 | 共同保存动作与 START 过期及原过期原因，不等待重试间隔。 |
| 意图已提交，派发再检查发现取消或窗口结束，可靠阻止执行 | 原尝试保存 NOT_DISPATCHED／NO_EFFECT，次数保持；普通资格按取消／过期共同结束。 |
| 窗口内已派发，返回时窗口已结束 | 可靠确认沿成功分支；可靠无效果沿过期分支；未知沿有限核实分支。 |

重试次数变化以本次上限与原已用次数相比较：原已用 2，本次上限 5 最多新增 3；上限 1 无新尝试且原次数仍为 2。已终态不因上限增大重开。一次会话采用固定配置，跨会话等待按本次间隔从首次观察重新建立，不退款。

可靠无效果最终失败与统一占用释放共同处理。全部原启动尝试均已结束且无效果、没有待核实或在途调用、准备和输出范围限制已经解除时，以 `decide_release` 保存 RELEASED；永久拒绝、次数耗尽及跨会话降低上限的入口采用同一判定。未知效果、实际调用未结束或目录准备仍未完成时保持 HELD，不从动作 FAILED 推定设备可用。释放与产生最终结果的同一事务共同提交；尚允许原 START 重试时保留必要机会，不提前释放。

## 既定恢复边界的内部输入

`RecoveryBoundary` 是内部枚举，取值 `UNCONFIRMED`、`HOST_LOCAL_SETTLED`、`HOST_POWER_CYCLE`。普通运行时构造和直接工厂默认 `UNCONFIRMED`。正式 CLI `run` 的外部调用方须满足[host 本地收场契约](../../host-demo/design.md#接入模块的本地进程收场责任)；命令装配明确注入 `HOST_LOCAL_SETTLED`，表达该已确定部署前提，不从仅有程序重启或 DB.RUNNING 推导。嵌入式调用方实际确认主机重新上电时可注入 `HOST_POWER_CYCLE`；CLI 不自行推测内核或主机重启，不新增公共参数或 host 协议。

恢复只使用原 `actions.driver_id` 的登记证据和按操作声明的适用范围。`DriverDeclaration.adb_foreground_recovery_operations` 默认空集合，合法值由 `devices.evidence.OPERATIONS` 核对，不复制操作清单。设备声明缺失或被换成其他驱动时，原驱动登记查找仍能提供恢复所需事实；不得以当前其他驱动代替。可靠边界、原驱动适用声明及 `adb_foreground_recovery/version1` 契约都满足时，普通前台发令沿原票据保存 UNKNOWN、ASSUMED、空 data、空观察，省略没有依据的 `call_info`；已有可靠效果按原事实保留。原读取续传分支及不适用普通前台假设的操作继续各自契约。

| 恢复状态 | 处理 |
| --- | --- |
| 原尝试已有可靠结果 | 保留，不生成恢复结果覆盖。 |
| 实际调用仍由本会话 await 持有 | 等待原调用，不使用会话启动边界提前结束本次新调用。 |
| 旧尝试无结果，可靠启动边界和原操作假设均满足 | 保存正式恢复结果，只结束发令责任；未知拍摄仍走 START_CONFIRMATION 或取消收场。 |
| 无可靠边界、原驱动未登记、证据缺失或操作不适用 | 保留责任与诊断，不结束原尝试，也不放行冲突调用。 |

首次可靠会话数据库视图在任何本会话设备意图之前固定 `recovery_max_event_id`，所有普通、残留与受限工厂共享同一 H。恢复同时要求可靠 `RecoveryBoundary` 与原 `intent_event_id ≤ H`；两者任何一个缺失均不恢复。本会话新派发的 RUNNING 不因启动时旧工作已收场而提前结束，不在每个工厂首次推进时分别读取新的 C。

无依据的分支返回未完成责任，使用类型化 `RecoveryBlockedReason` 和单份 `last_recovery_diagnostic` 保存原因及原 run／attempt 身份，成功核实后清除。诊断不增加公共协议或数据库状态；接入既有业务日志是运行时装配的后续责任。

装配来源预计沿 `RuntimeDeps → SessionContext` 初次可靠库视图固定 H，再经 `execute_command/_report_assembly → session_capture_assembly → CaptureRuntime` 共享边界，时钟失信的受限会话使用同一输入。具体划分为实现建议：协调 Agent 接 CLI/lifecycle、首次视图 H 和完整受管端口；录像实施者接恢复类型、START 骨架与处理器；绑定实施者接原驱动查找及缺失绑定恢复消费。没有可靠依据的默认分支不作为永久 RUNNING 的自动收场机制。

## 实施顺序与门禁

1. 写真实消费者有效反例并交协调 Agent 独占运行，确认失败是目标不变量。已支持的完整端口结构不得以非法 fixture 或缺 guard 制造失败。
2. 复用一次启动骨架，保留原完整结果和确认读数；接原票据与本次期限。正常、CONFIRMED+error、ASSUMED 和派发再检查先闭合。
3. 在最窄仓储增加 START 结果与活动的复合事务，复用原尝试与活动校验；所有相关事实一次提交。具体命令名称不固定，不绕过具名守卫。
4. 以完整已保存事实建立可靠 NO_EFFECT 重试与有限 START_CONFIRMATION，沿原机会和累计预算推进。窗口、取消、终态、实际在途及恢复入口覆盖同一状态模型。
5. 接显式恢复输入和原驱动证据，分别证伪无依据等待、可靠恢复 UNKNOWN、绑定缺失恢复与已终态未结束尝试；不得伪造原超时、宽限、退出码或观察。
6. 先运行 `integration/capture/test_recording_start_runtime.py`，再独占执行完整 `integration/capture`；改仓储后分别执行 `integration/operations`、`integration/scheduling` 和 `integration/history`，装配与正式命令入口分别执行 `integration/bootstrap`。完整端口与骨架单元门禁单独执行。

结果保存责任须从真实运行时闭合：授予事务回滚或提交未知向上报状态库前提错误，不能当成普通未授予留在循环。正常设备返回后，原完整结果、实际读数及稳定 `operation_key` 由原执行者持有；结果事务回滚后沿同一输入重送，提交未知先查清原事务是否可靠存在，不能重新派发设备或由下一会话的未知恢复替代同会话已取得的可靠结果。仍有事务时不得把其中的新值当成已提交事实，无法完成核实时保留原结果和诊断并停止新调用。

`integration/capture/test_recording_start_save_boundary.py` 独立覆盖：授予 ROLLED_BACK／UNKNOWN，结果投影故障，COMMIT 前错误和成功后错误，未派发结果与过期共同提交，复合结果原键改变时刻／活动／流程输入被拒，以及真实 `capture.residual.residual_flow` 发现终态录像动作下旧 RUNNING 尝试。后者只有可靠启动边界与固定旧 H 都满足才恢复；无依据和本会话意图保留。残留流程的普通停止与查询用相同原绑定规则发现必要责任，不能只扫描 ACTIVE 的 STOP_RESIDUAL 流程。

所有 pytest 由协调 Agent 按 `apps/camctl/tests/AGENTS.md` 前台独占顺序运行，解释器使用部署 Python 3.11。验收预期直接来自状态分类、原响应和独立时钟，不能从被测 START 分支计算同一预期；确认时钟测试通过真实 SQLite 提交延迟控制时间。生产改动前保留有效红，修复后审计同类入口。真实设备、物理断电和目标主机性能不属于组件集成测试通过范围。

## 验证记录

START 结果持有只覆盖录像 START 与 START_CONFIRMATION，装配层共享未核实结果，以原结果优先于未知恢复。普通 STOP、其他 QUERY、RESULT、残留与 cleanup 适配器也承担原可靠结果与原事务身份责任；这些消费者尚待公共保存边界的后续闭合，不能以 START 门禁通过宣称全部调用保存已经闭合。`integration/capture/test_recording_start_query_cancel.py` 验证实际启动核实在途时取消不得新增停止，以及迟到确认同时有无错误时均保存活动观察并保持原 START／查询终态。

未运行的命令保持未验证。记录实际日期、解释器、有效失败分区与回归范围，不以局部绿色代替完整模型闭合。
