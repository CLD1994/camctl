# 事务事实读取与普通完成消费重构

本计划落实事务事实生产、读取和消费的责任边界，接通真实 `finish_segment_recording`。行为契约以[文件事实](../../camctl/database/file-fields.md#文件事实的形成与消费)、[固定事实与普通发布](../../camctl/database/segments.md#固定事实与普通发布的责任)、[事务事实生命周期](../../camctl/persistence-runtime.md#单次完整事务的读取复用)和[当前事件端口](../../camctl/module-contracts.md#当前事件的限定事实读取)为准。

## 目标与范围

共同实现以下四项职责：

1. 来源校验在事实首次形成或实际改变时完成。普通 finish 消费已保存的固定文件、成员及 assessment／conclusion，独立执行本次行为自己的判断。
2. 事务内核提供统一事实读取接口，拥有 C0、实际前序推进、容量及结束释放。调用者不登记可信通过结论。
3. 业务规则消费显式事实，消除判断中隐含的重复查询及重新执行旧保存命令的来源分类。
4. 按批取得依赖并保持有界内存。大集合允许有界多遍；缓存容量、SQL 次数、解码量及实际驻留分别验证。

现有 schema 提供所需事实和固定引用；本计划调整内部接口，不增加持久化目录或格式。现有历史、业务身份、事件表示、公开报告及操作键语义保持。内部调用方统一采用新的责任边界。

[历史性能计划](2026-10-25-history-performance-closure.md)中尚未完成的通用有限主行正反向择路、正常 run 快照维护及数据库派发装配，仍按原计划验收，不并入本计划完成范围。已有报告与快照直接读取能力作为回归边界。

## 输入与可观察结果

基线真实完整保存见[完整录像保存重放记录](../../camctl/verification.md#真实历史副本的完整录像保存重放2026-10-25)：原事务 609 在边界 H893 后形成 894—897，动作 21、集合 4、RESULTS run28，原片 device_file30 登记 output29，预览 device_file29 登记 output30，并保存 origin15；最终发布集合。原输入包含相同操作键、事实时刻、有限申请和批量。基线完整调用为 1881 次 execute，其中 1855 次 SELECT；这是完整写操作口径，不能与只读 `verify_segment_finish` 的 360 次 SQL 混作同一对照。

最终结果必须保持原四事件、五项业务行变化、业务结果及共同提交边界。已保存报告 43、44 继续重建为原登记字节。优化收益以相同输入、相同计数窗口和真实历史副本比较，不预先承诺固定 SQL 下限或目标硬件提速。

## 事实可见性与拒绝分区

| 输入或状态 | 必须得到的行为 |
| --- | --- |
| C0 内已提交事件、事务及固定文件、成员、决定 | 在本事务容量范围内复用事实；阶段切换及无关后续写入不使固定旧事实失效。 |
| 当前动作、文件或流程状态已被本事务前序改变 | 后续读取取得实际前序状态，不误用 C0 旧值。有限入口只叠加已验证前序；有界入口只消费已验证且已落地前序。 |
| 当前事件、未来 marker、未来产物或未完成事务 | 只能用于提案结构比较；不能提前取得当前资格或冒充 C0 内已提交事实。 |
| 当前集合存在性、数量及范围 | 直接查询并分页，保持遗漏、重复、外来记录及数量不符的拒绝，不建立任意 SQL 缓存或依赖图。 |
| 固定引用缺失、越界、属于另一文件或集合；配对端点、同源或用途矛盾 | 普通消费拒绝，错误继续传播；不能转为空页、未知、缺键或成功。 |
| 普通消费不再依赖的旧基准、START／WAIT 来源链 | 不展开、不重新审计。首次形成事实和独立完整性验证按自己的范围检查。 |
| 原保存回执未知或原键重送 | 对应核实入口继续比较完整原申请、时刻、原事件及该接口明确要求的前后状态；不由普通消费替代。 |
| 容量淘汰、跨连接、事务结束后重用 | 在正确范围重新读取；成功、失败、回滚、未知及取消均释放本次保留内容。 |

## 实施步骤与进度

模块划分和内部命名属于实现建议；以下步骤、依赖及验收项是推进基准。每个实现步骤先编写能够失败的纯单元用例，再实现并运行对应范围，阶段结果更新到本节原验收项。

### 1. 固化责任契约

前置：已确认四项职责及普通消费的错误可观察范围。

- [x] 在文件、分段、历史格式、事务执行、共享端口和测试规则中区分首次形成事实、普通消费、原键核实及独立完整性验证。
- [x] 定义 C0 固定事实、当前可变单行、集合直读及实际前序的可见性，保留独立业务判断和共同发布不变量。
- [ ] 独立审查规格接缝，确认没有把普通消费保留成隐含的全来源链审计，并向实现步骤交接可审查提交。

### 2. 接通内核拥有的事实读取

依赖步骤 1 的责任与可见性。建议在 `persistence/fact_reads.py` 提供 `operation_fact_scope`、`read_event`、`read_transaction` 等限定事实端口，接通完整事务入口；接口名随实际实现核对。

- [ ] 先以单元反例覆盖内核绑定的连接与 C0、作用域外直读不缓存、同输入跨阶段复用、严格类型及不同边界分离、只读值隔离、错误不缓存。
- [ ] 由真实事务入口建立一次生命周期；C0 内固定事件、完整事务和小型固定事实共用有界条目及字节预算，超大值或淘汰只影响复用，不改变结果。
- [ ] 当前可变值随实际前序推进更新或失效；当前集合存在性、计数及范围保持直读。不得把连接任意写入解释为全部固定旧事实失效。
- [ ] 有限与有界入口共用实际事实语义，本事件及未来提案不进入前序；现有原子分组、完整事务核验和独立守卫继续成立。
- [ ] 提交或回滚前停用，成功、回滚、未知提交、外部取消及异常全部结束范围；原键核实另建作用域，跨事务与跨连接不共享。

### 3. 普通消费显式取得固定依赖

依赖步骤 1；普通消费责任调整可先按原读取接口落实，跨阶段共享依赖步骤 2。建议审计 `segments`、`segment_transactions`、`segment_result_members`、`segment_check_conclusions`、`segment_dispositions`、`segment_native`、`result_file_proofs`、`result_file_pairing`、原页及基准读取，并检查所有同类消费者。

- [ ] 先用单元反例区分首次保存的来源错误、普通消费的直接依赖错误和原键完整核实，避免以删除已有拒绝断言代替重新确定责任。
- [ ] 普通成员和候选读取固定 `file_event_id` 的文件事实、适用配对事实及直接关系；不递归执行文件归属、完成、配对的原保存核实。
- [ ] 普通 finish 读取固定成员及已保存 assessment／conclusion，不重新运行基准、START／WAIT、旧来源分类或已保存成员评估算法；保留决定身份、版本、适用来源、位置和直接关系检查。
- [ ] 将一批候选所需公共行、固定文件及关联显式取得后交给业务规则；规范事件生成和独立比较不隐含各自重开同一来源链。原页及基准内容在确有生产者责任时通过统一事实接口读取。
- [ ] 保留当前执行及取消资格、流程收场、候选与产物双向完整覆盖、预览到实际已验证前序原片、范围关系、唯一 marker 及整组原子发布；覆盖原片、预览、空集合、失败和取消分区。
- [ ] 保持有界分页和批次释放；跨页、空有效页、配对反查及容量淘汰不漏项、不改序，不积累整个动作、完整页数组或全部候选。

### 4. 对照复核与交付

依赖步骤 2、3 的真实生产接线。单元测试使用 Python 3.11，按[组件测试指南](../../../apps/camctl/tests/AGENTS.md)隔离资源；本计划不运行组件或跨组件集成测试，不启动 camctl 或设备。

- [ ] 运行受影响单元及 camctl 单元全量、相关静态检查，记录实际源码、环境、命令、日志和退出码；未执行的集成覆盖明确单列。
- [ ] 独立审查首次形成事实的来源守卫、普通消费的直接检查、C0 与当前前序分离、共享值隔离、容量及所有退出；检查未知原保存键未被普通消费路径替代。
- [ ] 从已有真实历史准备独立数据库副本，恢复到同一 H893 前态，使用相同原申请和操作键执行一次完整 `finish_segment_recording`；准备和事后核验不计入目标窗口，不新增拍摄业务世界，原来源及停止的进程保持不变。
- [ ] 对比完整事件字节、五项业务行变化、回执、前后状态和共同提交；重新生成原报告 43、44 并比较原登记长度和摘要。
- [ ] 分别记录 execute／SELECT／写入、SQL 与实际绑定重复、事实缓存命中与淘汰、读取与解码量、各阶段事务时间、外层耗时及峰值驻留。详细归因观测的时间开销与轻量计量分开；不给不同操作混算收益。
- [ ] 更新本计划原步骤和软件验证记录，制作并审计人工验证发行物，交付源码与资源清单及实际安装状态；进程继续保持停止。其他计划的未完能力按各自原验收项保留。
