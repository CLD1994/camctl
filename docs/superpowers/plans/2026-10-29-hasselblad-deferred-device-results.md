# Hasselblad 相机源按需取回实施计划

目标是在 `device` 模式保留相机作为正式来源，以 `hb_cli capture` 的可靠返回建立拍摄结果，不在拍摄后为了取得大小、摘要或格式再次下载原图和预览。用户只安排拍摄时，不产生结果确认下载；需要取回时按所选角色读取或复用临时副本。

业务前提是相机内文件不会被修改，`hb_cli` 对拍摄时生成的主机文件及其与相机照片的关系负责。相机原图与预览的对应关系不再通过两次下载比较字节。拍摄时主机预览和后来由 `download thumbnail` 取得的预览可以有不同的大小和摘要；每次交付的大小和 SHA-256 对应该次实际交付的字节。

## 目标行为与边界

| 情况 | 结果 |
| --- | --- |
| 拍摄调用正常收场、唯一成功响应和机内定位可靠 | 保存原机身、定位、拍摄结果及原图与预览的角色关联；不为确认大小、摘要或格式新增相机下载。 |
| 拍摄响应、机内定位或调用收场不可靠 | 保留实际失败或未知事实；不推断成功，不重拍。 |
| 拍摄返回后已有取回正在等待，CLI 同步副本可用 | 依据原拍摄返回和原等待者范围复用对应副本，不再对照相机下载决定资格。 |
| 无等待者，或原等待者已结束 | 沿原工作文件责任清理临时副本；后来的取回从原机身读取对应角色。 |
| 首次或后续从相机取回 | 各次读取按本次可靠下载取得的实际完整大小组织交付；预览不以另一份预览的长度或摘要作为通过条件。 |
| 取回或交付失败 | 取回保留真实错误和原读取责任；不改写已确定的拍摄结果。 |

原图与预览的正式来源仍为相机。输出可表达未知大小及未取得的源摘要；实际交付文件必须有自己的完整大小和 SHA-256。`capture` 本身仍由 CLI 同步输出主机文件，该计划仅取消拍摄后额外的来源确认下载。

旧动作、旧来源身份、已经固定的结果和读取责任须继续按原保存依据恢复；新行为的选择在受理时固定，不能仅凭当前部署或运行中的代码版本改变已有动作。未知长度不能用零或某份不同预览的长度替代；相机读取、文件保存、取消与实际调用收场仍按各自责任处理。

## 实施与验证

- [x] 固定新动作的来源语义，保留旧动作和旧文件身份的读取与恢复。
- [x] 表达已确认来源但尚未取得大小和摘要，调整相关状态库结构、迁移、历史及报告；不得改变其他设备已有的完成事实。
- [x] 将新 DEVICE 拍摄从可靠 START 结果直接推进至原图与预览登记及动作终态，删除新动作拍后来源下载；按原等待者截点复用 CLI 生成的对应临时副本。
- [x] 使未预先取得大小的相机来源在实际取回时固定本次读取大小，并按实际交付内容形成独立的大小和摘要；覆盖预览的不同字节表示、失败及恢复。
- [x] 同步受影响的正式来源、文件拷贝、数据库和驱动规格及部署说明；既有行为历史保持可解释。
- [x] 在 Python 3.11 下执行有针对性的单元测试和必要静态检查。按用户要求不编写集成测试；软件组合和真实设备验证分别记录实际执行范围。

本计划不把局部模型或单元测试通过视为生产路径已经完成。迁移、读取和拍摄登记必须共同接通后，才可宣称新行为可用。

## 本次验证范围

隔离软件模拟覆盖新动作拍摄、拍后独立取回、两角色等待者复用、缓存失效回退以及分段读取中断后重新下载。另用旧程序保存实际 START 结果并模拟中断，升级其 V6 库后由新程序沿旧 RESULTS 语义完成结果及预览取回。模拟工具不连接真实相机，未进行本次真机验证。

设备与主机文件目录单元测试分别通过 2035 项和 444 项，受影响的拍摄及初始化定向单元测试通过 278 项。输出目录非隔离单元测试的 116 个失败与原始基线逐项一致；隔离文件按各自进程执行，仍有原始基线可复现的替身失败。整目录的隔离测试与其他测试同进程收集也存在原始基线问题。数据库规格检查因原始基线缺少部分结构样本而未通过；事件登记、报告依赖、文档链接、协议和包资源检查分别执行。
