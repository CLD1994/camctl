# 媒体工具结果与正式文件资格

## 范围与行为契约

本计划承接[正式产物登记 R3](2026-10-03-camctl-output-registration-review.md#实施步骤与门禁)，检查 `probe_media`、`repair_media` 的实际结果及其消费者。规则来自[原片检查范围](../../architecture/camera-recovery.md#第一版原片检查的范围)、[精确类型](../../camctl/data-types.md)和[文件运行边界](../../camctl/file-runtime.md)。下面的任务拆分和预计接口属于实施建议。

媒体入口输入已登记文件身份、工具参数与停止信号。工具结果包含实际退出和调用错误两个独立维度，不能只用退出码覆盖取消等错误。停止之后仍须等待工具实际退出；结果不能改变动作终态或修改原片。

| 调用错误 | 实际退出 | 结果 |
| --- | --- | --- |
| 无 | 退出码为 0 | 继续校验工具输出或成品，不直接宣称业务成功 |
| 无 | 非零退出码、信号退出或没有退出结果 | 返回工具失败，保留实际退出信息 |
| 有 | 任意退出结果，包括退出码为 0 | 返回工具失败，同时保留调用错误与实际退出信息 |
| 工具无法启动 | 无 | 返回工具不可用；已有文件不能证明本次处理完成 |

工具正常完成后，时长字段遵循以下分区。检查结果保持全部十进制精度；零是有效观测值，是否满足录像目标由业务规则判断。

| 输入状态 | 时长解析结果 |
| --- | --- |
| 数字或数字字符串，值有限且非负 | 返回精确 `Decimal`，不经过二进制浮点数，也不按目标精度舍入 |
| 字段缺失 | 返回缺少时长，不能补零 |
| 布尔、null、数组、对象、非数字字符串、负数或非有限值 | 返回结构错误，时长未知 |
| 无效编码、非法 JSON、重复成员名或结构不符 | 返回结构错误，不从剩余片段提取时长 |

解析出合法数字不等于取得可靠视频时长。容器总时长不能替代视频内容时长；视频来源和可靠性依据须由设备文件适配明确。文件存在、完整性、摘要、文件同步、目录同步及结果保存也各有独立事实，不能折叠为单一成功值。

## 实施顺序与验收

- [x] M1：先对两个媒体入口补调用错误与退出结果的组合测试，对 probe 补数字精度及非法时长分类测试；确认失败后复用现有精确 JSON 解析，统一按调用错误和退出结果判断工具完成。保留原有错误分类并包含实际原因。以真实受管子进程验证取消后退出码为 0 的两条入口，以及精确数字输出。审计所有 `RawToolOutcome` 消费路径，不以扩大工具重试或改变动作终态替代修复。
- [ ] M2：核对视频时长的来源及可靠性。当前入口查询 `format.duration`，不能满足可靠视频时长契约；须细化适配结果，覆盖音视频时长不同、无视频、缺少可靠时长、矛盾信息和明确媒体错误。真实媒体样本、工具结果和独立已知时长共同验收，脚本输出不能代替此证明。
- [ ] M3：统一修复成品的文件观察、大小、摘要和同步事实。审计缺失、非普通文件、观察错误、空文件、摘要失败、同步失败及组合错误；保留已知效果和每个失败阶段。核对摘要读取的字节数与保存大小的一致性。将阻塞文件工作接入现有任务责任边界，覆盖等待取消、实际任务继续成功或失败、结果领取前文件责任，以及不能提前登记或释放文件的条件。先补可证伪测试再实现，不把观察错误当作不存在，不丢弃同步错误，也不以未确认的持久性推断完整文件资格。
- [ ] M4：将结果保存、修复状态及文件提升接入 R3 的实际仓储和正式守卫；覆盖失败回滚、取消、恢复、原身份和后续读取。R3—R5 的门禁仍分别适用，不用预置完成记录替代生产路径。

M1 可以独立验证；M2、M3 提供 M4 所需的可靠事实。单元测试隔离进程和文件边界；集成测试使用真实受管进程和文件，按 Python 3.11、3.12 串行执行。预计修改 `host_files/media.py` 及对应测试；新依赖只有在标准库和现有协作者不能满足契约时才评估。

## 现有缺口与验证边界

现有 `repair_media` 在事件循环内执行文件检查、摘要和同步；同步错误没有完整进入结果。`MediaArtifact` 本身不代表数据库已保存完整文件事实。现有媒体集成测试使用可执行脚本验证受管进程协作，尚不能证明真实视频检查和无重新编码修复正确。F6 的完整实施和审阅门禁需在上述实际边界闭合后验收。

## M1 验证记录

新增反例在修复前产生 30 项预期失败，分别证明调用错误被忽略、数字时长精度丢失、非法时长被接受，以及重复字段等结构歧义被忽略。修复后媒体单元测试通过 64 项。

Python 3.11、3.12 分别执行以下命令，单元测试各通过 840 项，集成测试各通过 58 项。使用开发环境各自的虚拟环境解释器，单元与集成分开执行，两个版本的集成串行执行。单元测试均有一条既有警告：`unit/operations/test_process.py::test_local_exit_is_exclusive` 是同步函数，但继承了模块级 asyncio 标记；没有测试失败。

```bash
env PYTHONPATH=apps/camctl/src:apps/camctl/tests python -m pytest -q \
  apps/camctl/tests/unit/host_files apps/camctl/tests/unit/operations \
  apps/camctl/tests/unit/contracts apps/camctl/tests/unit/capture
env PYTHONPATH=apps/camctl/src:apps/camctl/tests python -m pytest -q \
  apps/camctl/tests/integration/host_files \
  apps/camctl/tests/integration/operations/test_process.py
```

真实进程用例等待工具安装终止处理器并写出内容，再发出取消；工具以退出码 0 结束，两条媒体入口均返回包含取消及实际退出信息的失败。数字输出通过真实进程管道进入精确解析器。另一处 `RawToolOutcome` 消费者 `devices.adb_transport.invoke` 已将 `raw.error` 纳入调用失败分类；媒体入口没有其他生产消费者。此验证不证明 M2—M4 完成，也不证明取消等待协程后的完整责任交接。
