# 媒体工具结果与正式文件资格

## 范围与行为契约

本计划承接[正式产物登记 R3](2026-10-03-camctl-output-registration-review.md#实施步骤与门禁)，检查 `probe_media`、`repair_media` 的实际结果及其消费者。规则来自[原片检查范围](../../architecture/camera-recovery.md#第一版原片检查的范围)、[精确类型](../../camctl/data-types.md)和[文件运行边界](../../camctl/file-runtime.md)。下面的任务拆分和预计接口属于实施建议。

媒体入口输入已登记文件身份、工具参数与停止信号。工具结果包含实际退出和调用错误两个独立维度，不能只用退出码覆盖取消等错误。停止之后仍须等待工具实际退出；结果不能改变动作终态或修改原片。

| 调用错误 | 实际退出 | 结果 |
| --- | --- | --- |
| 无 | 退出码为 0 | 继续校验工具输出或成品，不直接宣称业务成功 |
| 无 | 非零退出码、信号退出或没有退出结果 | 返回工具失败，保留实际退出信息 |
| 有 | 任意退出结果，包括退出码为 0 | 返回工具失败，同时保留调用错误与实际退出信息 |
| 工具无法启动 | 无 | 返回工具不可用；已有文件不能证明本次处理完成 |

工具正常完成后，时长字段遵循以下分区。检查结果保持全部十进制精度；零是有效观测值，是否满足录像目标由业务规则判断。

| 输入状态 | 时长解析结果 |
| --- | --- |
| 数字或数字字符串，值有限且非负 | 返回精确 `Decimal`，不经过二进制浮点数，也不按目标精度舍入 |
| 字段缺失 | 返回缺少时长，不能补零 |
| 布尔、null、数组、对象、非数字字符串、负数或非有限值 | 返回结构错误，时长未知 |
| 无效编码、非法 JSON、重复成员名或结构不符 | 返回结构错误，不从剩余片段提取时长 |

解析出合法数字不等于取得可靠视频时长。容器总时长不能替代视频内容时长；视频来源和可靠性依据须由设备文件适配明确。文件存在、完整性、摘要、文件同步、目录同步及结果保存也各有独立事实，不能折叠为单一成功值。

### M3 的阶段与结果分类

文件结果按原协作者返回的事实组织，媒体结果持有文件观察、摘要结果和同步结果；便捷属性由这些事实派生，不再分别维护另一套成功标志。`complete` 表达工具正常完成、普通非空成品与完整摘要长度相符且摘要阶段无错误；同步结果独立表达，`complete` 不能用于替代正式登记所需的持久性判断。

| 工具及文件条件 | 后续操作与结果 |
| --- | --- |
| 工具失败或不可用 | 观察输出位置并保留实际状态，不为该次处理计算成品摘要或同步 |
| 观察明确缺失 | `exists=False`、不完整；保留缺失分类 |
| 观察因访问错误失败 | `exists=None`、不完整；保留原始观察错误，不解释为缺失 |
| 观察为非普通文件 | `exists=True`、不完整；不读取内容或同步 |
| 工具正常完成、普通文件大小为零 | 不完整；不计算成品摘要或同步 |
| 工具正常完成、普通非空文件 | 计算摘要并同步；两个阶段分别保存结果，即使摘要失败也保留实际同步结果 |
| 摘要阶段无错误、摘要完整且长度与观察相符 | 成品完整性成立；同步仍按实际结果表达 |
| 摘要失败、缺少必要结果或长度不符 | 成品完整性未成立；保留已知大小、摘要及独立同步结果 |
| 文件同步或目录同步失败 | 保留发生阶段、成功部分和错误；不能返回无错误的处理结果 |

底层文件操作关闭句柄时出错，不能覆盖此前已完成的截断、同步、摘要或先前错误。关闭只尝试一次；关闭错误不被忽略，也不通过再次关闭同一描述符恢复。截断已经完成仍保留该事实，但关闭失败时禁止继续写入；文件同步已完成仍保留该事实，文件阶段有错误时不再尝试目录同步。摘要已读至结尾时保留完整摘要和长度；读取中途失败则没有完整摘要。摘要关闭错误仍阻断 `complete`，不能因已得到字节摘要而忽略该阶段错误；若同时发现长度矛盾，两个问题都保留。目录同步自身的同步错误和关闭错误也分别保留。

- [x] M3a：先补媒体观察、同步及组合错误反例，再修复文件观察和同步/摘要/截断协作者的关闭结果；媒体结果统一持有各阶段事实，覆盖真实文件及注入的文件系统错误。同步执行体的接口不代表异步责任已经闭合。
- [ ] M3b：在 M3a 事实结构上接入线程任务和受管媒体任务的整个生命周期，验证取消前后、排队/已开始/已结束未领取各分区及结果接手；M3 的总 checkbox 仅在 M3a、M3b 都通过后勾选。

## M2 的证据与未决输入

开发环境使用 FFmpeg/ffprobe `6.1.1-3ubuntu5` 生成一个 25 帧、25 帧/秒的视频流和一个 3 秒音频流，封装为 MP4。独立生成条件确定视频时长为 1 秒；ffprobe 返回视频流时长 1 秒、音频流及容器时长 3 秒。现有 `probe_media` 查询容器字段，返回 3 秒，因此不能作为可靠视频时长入口。

[FFmpeg 的 AVStream 文档](https://ffmpeg.org/doxygen/7.0/structAVStream.html)说明，源文件没有时长但有码率时，流时长也可能由码率和文件大小估算。不能仅将 `format.duration` 改成 `stream.duration` 就宣称时长可靠。相机文件容器、主视频流规则及适配的可靠性依据尚待明确；当前没有具体设备文件适配。M2 保持未完成，M3 的文件结果工作不依赖该决策。
