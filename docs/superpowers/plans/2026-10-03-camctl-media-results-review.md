# 媒体工具结果与正式文件资格

## 范围与行为契约

本计划承接[正式产物登记 R3](2026-10-03-camctl-output-registration-review.md#实施步骤与门禁)，检查 `probe_media`、`repair_media` 的实际结果及其消费者。规则来自[原片检查范围](../../architecture/camera-recovery.md#第一版原片检查的范围)、[精确类型](../../camctl/data-types.md)和[文件运行边界](../../camctl/file-runtime.md)。下面的任务拆分和预计接口属于实施建议。

媒体入口输入已登记文件身份、工具参数、共享执行器、任务身份与责任拥有者。停止通过执行器或接手句柄请求。工具结果包含实际退出和调用错误两个独立维度，不能只用退出码覆盖取消等错误。停止之后仍须等待工具实际退出；结果不能改变动作终态或修改原片。

| 调用错误 | 实际退出 | 结果 |
| --- | --- | --- |
| 无 | 退出码为 0 | 继续校验工具输出或成品，不直接宣称业务成功 |
| 无 | 非零退出码、信号退出或没有退出结果 | 返回工具失败，保留实际退出信息 |
| 有 | 任意退出结果，包括退出码为 0 | 返回工具失败，同时保留调用错误与实际退出信息 |
| 工具无法启动 | 无 | 返回工具不可用；已有文件不能证明本次处理完成 |

工具正常完成后，时长字段遵循以下分区。检查结果保持全部十进制精度；零是有效观测值，是否满足录像目标由业务规则判断。

| 输入状态 | 时长解析结果 |
| --- | --- |
| 数字或数字字符串，值有限且非负 | 返回精确 `Decimal`，不经过二进制浮点数，也不按目标精度舍入 |
| 字段缺失 | 返回缺少时长，不能补零 |
| 布尔、null、数组、对象、非数字字符串、负数或非有限值 | 返回结构错误，时长未知 |
| 无效编码、非法 JSON、重复成员名或结构不符 | 返回结构错误，不从剩余片段提取时长 |

解析出合法数字不等于取得可靠视频时长。容器总时长不能替代视频内容时长；视频来源和可靠性依据须由设备文件适配明确。文件存在、完整性、摘要、文件同步、目录同步及结果保存也各有独立事实，不能折叠为单一成功值。

### M3 的阶段与结果分类

文件结果按原协作者返回的事实组织，媒体结果持有文件观察、摘要结果和同步结果；便捷属性由这些事实派生，不再分别维护另一套成功标志。`complete` 表达工具正常完成、普通非空成品与完整摘要长度相符且摘要阶段无错误；同步结果独立表达，`complete` 不能用于替代正式登记所需的持久性判断。

| 工具及文件条件 | 后续操作与结果 |
| --- | --- |
| 工具失败或不可用 | 观察输出位置并保留实际状态，不为该次处理计算成品摘要或同步 |
| 观察明确缺失 | `exists=False`、不完整；保留缺失分类 |
| 观察因访问错误失败 | `exists=None`、不完整；保留原始观察错误，不解释为缺失 |
| 观察为非普通文件 | `exists=True`、不完整；不读取内容或同步 |
| 工具正常完成、普通文件大小为零 | 不完整；不计算成品摘要或同步 |
| 工具正常完成、普通非空文件 | 计算摘要并同步；两个阶段分别保存结果，即使摘要失败也保留实际同步结果 |
| 摘要阶段无错误、摘要完整且长度与观察相符 | 成品完整性成立；同步仍按实际结果表达 |
| 摘要失败、缺少必要结果或长度不符 | 成品完整性未成立；保留已知大小、摘要及独立同步结果 |
| 文件同步或目录同步失败 | 保留发生阶段、成功部分和错误；不能返回无错误的处理结果 |

底层文件操作关闭句柄时出错，不能覆盖此前已完成的截断、同步、摘要或先前错误。关闭只尝试一次；关闭错误不被忽略，也不通过再次关闭同一描述符恢复。截断已经完成仍保留该事实，但关闭失败时禁止继续写入；文件同步已完成仍保留该事实，文件阶段有错误时不再尝试目录同步。摘要已读至结尾时保留完整摘要和长度；读取中途失败则没有完整摘要。摘要关闭错误仍阻断 `complete`，不能因已得到字节摘要而忽略该阶段错误；若同时发现长度矛盾，两个问题都保留。目录同步自身的同步错误和关闭错误也分别保留。

### M3b 的任务责任与实施顺序

媒体任务与同步文件任务共享文件占用登记。probe 占用输入文件，repair 同时占用输入和输出；任一文件存在冲突即整项拒绝，不启动工具。修复不能把同一文件作为输入和输出。媒体任务包含工具实际退出和后续文件结果采集，阶段之间不释放文件。阻塞文件操作在默认线程池执行，工具仍由事件循环异步管理。

| 任务实际阶段 | 等待取消后的处理 | 文件与结果责任 |
| --- | --- | --- |
| 已登记，执行体尚未开始 | 与开始裁决竞争；成功撤回则不启动工具或文件操作 | 释放全部文件及任务身份，无实际结果接手 |
| 已开始，工具仍运行或正在终止 | 等待者取消不取消内部执行任务；先登记拥有者接手，再传播取消 | 输入和输出继续被占用；拥有者可发停止请求并等待实际退出 |
| 工具已退出，文件任务尚未执行 | 保留原工具结果；停止请求禁止新的摘要和同步，必要输出观察用于收场 | 直到适用文件观察结束才释放实际占用 |
| 文件调用已开始 | 不取消底层调用，等待实际成功或失败；在后续阶段开始前检查停止请求 | 保留已经产生的摘要、大小、同步和错误，不为取消补造缺失或成功 |
| 实际任务已结束，结果未领取 | 同样登记接手，不重新运行工具或文件操作 | 文件执行占用已经结束；任务身份直到结果交付才可复用 |
| 正常领取结果 | 返回实际结果，不登记接手 | 持久化及通知仍由业务拥有者完成，领取不表示数据库已保存 |

以下接口是实施建议，不能削弱上述契约：在 `FileTaskExecutor` 增加异步文件任务入口，复用已有状态、共享完成结果、接手句柄和文件占用；异步任务明确列出全部文件 ID。媒体调用显式接收任务身份、共享执行器和责任拥有者，返回执行结果及媒体事实。未开始与已开始失败继续由 `FileTaskResult.ran` 区分。媒体停止请求与等待取消分别处理，不用取消内部执行协程代替停止工具。

### M3b 的进程异常收场契约

`operations.process.execute_tool` 分别观察实际退出与输出结束。发送信号的系统错误独立保留，不能结束尚在运行的工具调用。进程已退出但退出等待尚未恢复时，发送信号可能得到 `ProcessLookupError`；此时仍从原等待取得实际退出结果。媒体入口只把启动边界的 `ToolStartError` 解释为工具不可用。停止和期限观察任务在所有结束路径中取消并等待结束。

受管进程边界保持以下分类，不让通用文件执行器推测进程已经结束。

| 实际情况 | 必须保留的责任与结果 |
| --- | --- |
| 工具未启动 | 返回启动失败，不补造退出结果 |
| 发信号时进程已经退出 | 沿原退出等待取得实际结果，再进行适用的输出观察 |
| 发信号失败，退出尚未确认 | 保留错误并继续承担实际退出责任，不能提前释放文件 |
| 已取得退出结果，输出读取失败 | 同时保留退出结果与读取错误 |
| 任意结束分支 | 完成停止与期限观察任务的收场 |

- [x] 先为上述分区补失败测试，再在 `execute_tool` 中组合实际退出与各阶段错误，收窄媒体启动失败分类。不得吞掉终止异常，也不得把异常当作退出证明。
- [x] 审计 `host_files.media` 与 `devices.adb_transport.invoke` 两处消费者；通过两个真实媒体入口验证异常期间文件持续占用、接手结果及输出观察。全部通过后再验收 M3b。

实施先处理信号发送与启动分类，再处理输出读取及退出等待的异常。信号阶段遵循以下细分契约：

| 条件 | 动作与保留事实 |
| --- | --- |
| 启动调用抛出系统错误 | 以专用启动异常保留原因；只有该异常可映射为媒体工具不可用 |
| 开始停止时退出任务已经完成 | 取得实际结果，不发送信号，不记录未使用的宽限 |
| 请求终止成功或抛出系统错误 | 错误按终止阶段保存；进入固定宽限等待，记录实际采用的宽限，不重复发送终止请求 |
| 宽限内取得退出结果 | 返回实际退出与所有已知错误，不发送强制终止信号 |
| 宽限结束仍未取得退出结果 | 请求一次强制终止，保留该阶段的系统错误，继续等待原退出任务，不把发送失败当作退出 |

超时与用户停止的触发原因分别使用 `timeout` 或 `cancelled`；信号错误另存有明确阶段的详情，不拼接成机器错误码。媒体诊断同时呈现触发原因、实际退出和信号错误。设备调用保留传输错误详情；响应解释者同时报告错误时，结果以传输错误为外层，并在详情中完整保存响应错误。原有设备效果和观察不受错误组合影响。辅助停止及期限任务须在 `finally` 中取消并等待其结束。输出读取和退出等待按下述独立契约处理。

输出读取结果单独保存有界前缀与读取错误。读取错误不能让退出等待提前返回，也不能覆盖已取得的退出结果。没有超时或取消时，读取失败的调用错误为 `output_failed`；同时存在超时或取消时保留原触发原因，并在独立字段保留读取错误。媒体入口不解析失败的输出为成功；设备解释者仍可从已经取得的字节中提取其契约认可的可靠观察，调用结果保持失败并保存读取错误，收场使用已声明的运行假设。

| 输出与退出的先后状态 | 处理规则 |
| --- | --- |
| 输出正常结束，进程未退出 | 继续观察退出、停止与期限，不重复观察已经完成的输出任务 |
| 输出读取失败，退出未确认 | 启动同一有限终止流程；保留输出前缀、读取错误和适用信号错误，继续等待退出 |
| 退出先确认，输出尚未结束 | 等待输出实际结束；读取失败也保留已知退出，不发送多余终止请求 |
| 停止或期限与输出错误共同到达 | 期限优先于停止，停止优先于输出错误作为调用错误码；读取错误始终独立保留 |
| 退出与停止或期限共同被观察到 | 优先取得已结束结果；输出读取错误仍独立使调用失败，不补写未发生的终止步骤 |

实际进程适配器使用 `asyncio.subprocess.Process.wait()` 确认退出，输出读取的系统错误在读取边界转成结果，不再从退出等待抛出。标准适配器的退出等待不以系统错误返回未确认退出；内部编程错误、直接取消内部受管协程及事件循环退出不属于普通工具调用结果。媒体拥有者须沿文件执行器发停止请求，不能直接取消内部执行协程。测试替身须保持这一端口契约；对辅助任务 `finally` 的异常验证不代表未知退出已经收场。

## M2 的语义裁决

2026-10-06 用户裁决：视频时长以 ffprobe 容器时长（`format.duration`）为准，按码率与文件大小估算出的值同样可用，精度要求为误差几秒可接受，不要求真实媒体样本共同验收。默认原则"不把工具没有明确保证的输出当成观察结果"继续适用于其他事实；用户明确同意的例外按本裁决执行。开发环境对照事实说明误差来源：视频流 1 秒、音频流 3 秒的样本容器时长为 3 秒，采用容器时长即接受该偏差。工具未给出任何时长时按缺少可靠时长分类，不补造；矛盾信息和明确媒体错误维持原有错误分区。判定与登记的接入归 M2 任务实施，M3 的文件结果工作不依赖该接入。
