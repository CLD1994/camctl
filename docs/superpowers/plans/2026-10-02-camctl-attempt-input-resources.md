# 普通尝试的输入与读取资源

## 目标与依据

普通尝试开始和结束的输入必须表达真实身份、采用配置和事实时刻；原键存在不能使非法输入变成合法输入。读取者释放自己取得的游标，并保留实际数据库错误。本计划依据[普通尝试字段](../../camctl/database/operation-fields.md#尝试字段与结果)、[日期时间存储](../../camctl/database/common.md#日期时间的存储)、[对象身份](../../camctl/database/common.md)、[事务失败契约](../../camctl/database/transactions.md#公共完成与失败契约)及[软件验证](../../camctl/verification.md)。文件划分及内部辅助函数是实施建议，不增加公共协议或依赖。

本计划完成输入和资源责任，不代替普通意图的完整原键恢复、已有流程关联、连续次数及业务资格验收。

## 已确定的行为契约

`AttemptIntent` 接收已构造的 `AttemptTarget` 和 `AttemptConfig`，事实时刻必须显式提供。省略时刻不生成意图，不能用默认的 UTC 起点表达尚未提供的时间。这些类型各自校验字段，意图再校验种类、用途、目标列及拷贝轮次的组合。`BeginAttemptCommand.plan` 在读取原操作键之前检查意图类型；非法类型按事务错误返回并回滚，不能返回原票据。合法对象仍使用原有事务和业务守卫，不重新执行已经构造完成的输入转换。

查询责任键只由动作、用途及适用的活动身份决定，不需要事实时刻或执行配置。建议用 `query_responsibility_key(action_id: int, purpose: QueryPurpose, activity_id: int | None) -> str` 作为两种调用方的共同来源：意图责任键及 `QueryResponsibility.responsibility_key` 均使用它。静态查询责任不为生成键而构造尚未发生的调用意图。函数校验动作身份、用途及目标组合，并保留已有规范键格式。

| 输入字段与分区 | 结果 |
| --- | --- |
| 动作和非空目标身份是 1～9223372036854775807 的整数 | 接受并保留精确整数；各目标列的空值组合仍由种类和查询用途决定。 |
| 次数上限及适用的拷贝轮次是上述范围内的正整数 | 接受；不适用的拷贝轮次必须为空。 |
| 身份、次数或轮次为布尔值、浮点数、字符串、空值、非正整数或越界整数 | 按 `AttemptConfigError` 拒绝；可空目标的空值及不适用轮次除外。 |
| 显式提供的开始或结束时刻是可用 SQLite 64 位有符号整数保存的 UTC 微秒 | 接受；0 表示 UTC 起点，负数表示起点之前的时刻，均保留原值。 |
| 开始或结束时刻被省略 | 构造器拒绝缺少必填参数，不生成默认时刻。 |
| 时刻为布尔值、浮点数、字符串、空值或越界整数 | 按 `AttemptConfigError` 拒绝，不转换、不舍入，也不把假值视为省略。 |
| `target` 或 `config` 不是相应类型 | 按 `AttemptConfigError` 拒绝，避免访问其他对象的属性或在原键分支跳过校验。 |
| `operation` 是 D2 已登记的操作类别 | 通过该字段的结构校验；类别只从 `devices.evidence.OPERATIONS` 读取。 |
| `operation` 未登记或不是字符串 | 按 `AttemptConfigError` 拒绝。不同流程种类允许哪些已登记类别，继续由设备及业务契约定义；本计划不自行添加映射。 |

配置秒数仍使用现有精确 `Decimal` 转换：调用时限为有限正数，重试间隔为有限非负数，空值表示所属操作不适用。原有种类与用途的目标互斥规则必须保留。

| 查询阶段与结果 | 游标及失败处理 |
| --- | --- |
| 责任键查询返回已有流程或无结果 | 解释结果前关闭已取得的游标；无结果按原有创建资格继续判断。 |
| 累计次数查询返回实际最大编号或空表的 SQL `NULL` | 解释和核对结果前关闭已取得的游标；本计划不改变次数判定的业务规则。 |
| `execute` 抛出异常 | 保留原异常，不关闭尚未取得的游标。 |
| `fetchone` 抛出异常 | 关闭已取得的游标，保留原异常。 |
| 成功读取后发现次数不一致 | 已取得的游标仍须关闭，事务按原有错误规则回滚。 |

## 待完成的普通意图审查

下列项目仍由[事件生产者审查](2026-10-02-camctl-event-contracts-review.md#未完成的消费者与恢复边界)跟踪，实施前须完成对应状态模型和执行计划。

| 问题与触发场景 | 后续修复与验收边界 |
| --- | --- |
| 原键重送改变实际目标、配置或时刻，仍从新输入构造票据 | 核对原物理尝试、原意图事件、只读身份和原采用配置；后来重试及合法终态不改变原票据。分别覆盖每项不同输入、物理 ID 与流程内编号不同、缺失原记录及数据库不变。 |
| 原组混入其他阶段或多条尝试创建 | 核对完整组成和唯一关联，不能取首条事件或最后一行。普通入口能否读取原子启动授予的原票据尚待业务决策；相关原键组成修改暂停。 |
| 已有流程与新输入的实际目标或业务归属不一致 | 在新键及原键共用的责任边界核对三种目标、交付、会话、活动归属和查询所需原流程；残留收场保留历史活动与触发动作的区别。每种入口单独验证错误关联先于预算或终态拒绝。 |
| 拷贝存在但必需的唯一读取流程缺失 | 按一致性错误拒绝，不创建替代流程或刷新预算；外部交付和内部处理两种归属都须验证。 |
| 流程状态、次数、等待或已有编号连续性矛盾 | 按各业务完整分类检查后再判断是否结束或额度耗尽；已有未收场尝试不能仅凭额度另建调用。查询可用其他可靠证据在零调用时完成，不能套用录像启动的所有状态限制。 |
| 原响应的操作类别没有可恢复的权威保存事实 | 明确业务种类与操作类别的适用关系，以及原类别的可靠来源；不得从本次输入或错误夹具猜测原值。内部存储方式不构成公共报告字段需求。 |
| 未结束读取尝试后来采用新配置 | 原键身份核对使用原意图的采用配置；读取恢复按契约保存后续实际采用配置及变更历史。不能将当前配置必须等于原创建配置作为通用规则。 |

身份核对必须区分发起动作与目标所属对象。取回动作读取另一拍摄动作产生的文件时，读取流程归属取回交付，源设备绑定沿源文件读取；不能要求源文件所属动作等于取回动作。残留停止由新动作触发时，流程的 `action_id` 表示触发者，活动仍属于原拍摄动作。后续修复使用下表的关系，不能把所有目标统一解释为发起动作的活动。

| 责任种类或查询用途 | 必须核对的目标与归属 |
| --- | --- |
| `START`、`STOP`、`CHECK_CAPTURE_RESULTS` | 原活动；活动的 `action_id` 与流程及输入动作相同。 |
| `STOP_RESIDUAL` | 原历史活动；流程和输入动作是触发者，允许与活动所属动作不同。 |
| `READ_FILE` 的普通交付拷贝 | 原拷贝及其唯一流程；流程的 `delivery_id` 与拷贝相同，流程动作与交付动作相同。源文件所属动作不必等于取回动作。 |
| `READ_FILE` 的内部处理拷贝 | 原拷贝及其唯一流程；流程的交付引用为空，流程动作与拷贝所关联的录像处理动作相同。 |
| `DELETE_FILE`、`CHECK_FILE_EXISTS` | 原清理项；流程与输入动作等于清理项所属动作，源文件保持自身来源身份。 |
| `QUERY_ACTIVITY / BEFORE_EXECUTION` | 三个目标列为空；设备绑定来自原动作。 |
| `QUERY_ACTIVITY / START_CONFIRMATION`、`STOP_CONFIRMATION` | 原动作的活动，并存在同动作、同活动的原 `START` 或 `STOP` 流程。 |
| `QUERY_ACTIVITY / ACTIVITY_OBSERVATION` | 原动作自身活动，仍承担适用管理责任。 |
| `QUERY_ACTIVITY / RESIDUAL_STOP_CONFIRMATION` | 相同触发动作及历史活动的原 `STOP_RESIDUAL` 流程；保留触发者与活动所属动作的区别。 |

所有普通流程还须核对种类、用途、规范责任键、三个目标列、不适用的交付引用及空会话引用。核对先于普通终态或预算拒绝；原键恢复还须另核对原完整事实和原采用配置。必有记录缺失、关联矛盾和查询失败分别保留错误，不默认解释为不存在。

## 验证证据

首批 135 项纯单元运行有 39 项失败、96 项通过。其中 1 项是空责任分支的内存登记不完整；补齐夹具后，该分支进入实际规划。其余 38 项分别证伪输入校验、合法时间和游标责任。真实 SQLite 的新增 10 项反例有 7 项失败、3 项通过，其中字段齐全但未使用类型化输入的对象，在新键和原键下都被旧入口接受。时刻省略及纯查询键函数的补充反例有 14 项失败，分别对应缺少必填校验和共同键函数。

最终的输入、读取资源及查询责任纯单元组合有 175 项通过。独立复核运行同一组合，并以实际源码和受 SQLite 接口约束的替身验证五个合法时刻原样进入事件、四类错误输入先于键读取被拒绝、十五个已取得游标关闭，以及五种用途的两种键来源；真实包资源读取为 0，读取函数引用、缓存、具名守卫及模块实例均保持原状。未执行集成测试，不将诊断作为 P3 组合证据。
