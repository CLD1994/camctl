# 错误日志内容与诊断责任修复

## 目标与边界

ERROR 记录保留失败原因、原始失败诊断和可靠关联身份，同时避免完整业务结果的重复展开。成功设置调用保留命令、顺序和结果摘要；原调用结果、持久历史、业务判断及重试预算保持原契约。相同错误在一条记录中只展开一次，后续位置引用该节点。原异常已经取得诊断责任时，会话最终摘要引用原诊断；新的包装事实和实际收场错误仍须交付。

本项不要求兼容旧日志布局。验证使用 Python 3.11 隔离单元测试及独立静态评审，不新增、修改或运行集成测试，不构建、安装或操作设备。单元测试在导入前和实际调用期间隔离包资源、业务文件、数据库、网络、线程及子进程。原日志只用于只读分析，不作为单元测试的真实文件输入。

## 不变量与状态分类

- 日志投影与业务结果分开；不能为了缩短日志而改写设备结果、数据库证据或永久历史。
- 完整失败字节、可读 stderr、实际异常图及新增收场错误继续保留。成功调用摘要不能把未知输出填成零字节或空串；媒体 stdout 继续原排除规则。
- 相同对象的不同角色继续可辨认，引用必须能够定位本记录的实际节点或已准备的原诊断。内容相同的独立实际失败不共用投递责任。
- 诊断身份随原结果或异常持有，不建立进程全局错误集合，不新增状态库字段。尚未准备的诊断不能被当成已交付引用。
- 日志副本、接纳及写入回执继续复用原记录；文件与 stderr 的既有失败语义保持。必要停止、结果保存和资源收场不等待诊断空位。
- SessionOutcome 的机器 reason 和 details 保持，日志使用独立展示；原异常转成会话失败后仍保留非持久化的诊断关联。

| 输入事实 | 日志处理 |
| --- | --- |
| 设置调用成功 | 保留步骤、命令、状态及输出摘要，不展开成功 stdout 的全部十六进制字节。 |
| 设置调用失败或结果未知 | 保留实际错误、工具返回及适用原始输出；同一调用被多处引用时只展开一次。 |
| 同一错误同时承担调用错误和流程错误 | 各角色引用同一完整错误节点。 |
| 调用错误与流程错误不同 | 分别保留；共享的原异常节点仍可引用。 |
| 原异常已有准备中的诊断 | 保持原拥有者及投递责任，后续摘要引用原诊断。 |
| 原异常还没有诊断 | 最终拥有者准备完整诊断，不以摘要代替。 |
| 新包装异常包含已经记录的原因 | 保留新增阶段和包装事实，原原因使用可靠引用。 |
| 会话结束同时发生新的清理、控制或日志通道错误 | 保留各自实际事实和原有选择顺序，不因原错误已记录而省略。 |

## 实施步骤

### 1. 固定契约与协作接口

- [x] 核对原日志、交付代码及当前生产者、投影、异常和最终输出路径，确认三类冗余。
- [x] 明确公共诊断引用接口与会话非持久化关联，划分单一责任负责人并创建独立工作区。

### 2. 统一 ERROR 投影

- [x] 先增加成功调用输出摘要、相同错误多角色引用、独立错误及失败字节保留的隔离反例。
- [x] 在日志边界统一投影，接入附属设置调用及公共调用结果；不改变实际结果和持久证据。
- [x] 保留单条内部引用、原诊断身份和异常原因的关系，覆盖无目标、编码失败、stderr 降级及重送。

### 3. 会话失败复用原诊断

- [x] 先覆盖已记录异常转会话结果、未记录异常、新包装原因及新增收场错误的隔离反例。
- [x] 在实际会话与受限会话入口保留原诊断关联，最终输出使用结构化摘要和适用引用。
- [x] 检查报告 worker 收场、启动失败、直接异常及日志副本，保持原错误、机器结果、必要停止和交接。

### 4. 评审与交付

- [x] 独立审查完整生产者、投影、会话转换和输出链，处理并复核确定问题。
- [x] 在统一源码上执行经审计的隔离单元检查，保存命令、环境、日志、退出码和源码身份。
- [ ] 更新日志权威说明和验证记录，核对部署及工作规则影响，完成差异检查与提交。
- [ ] 汇报体积变化、事实保留和未执行的真实组件／设备验证范围。

内部函数和文件拆分属于实施预估，可根据实际依赖调整；上述事实保留、诊断所有权和验证边界是验收依据。
