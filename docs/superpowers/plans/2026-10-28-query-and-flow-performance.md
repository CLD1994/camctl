# 查询与流程性能优化实施计划

## 目标与边界

报告生成、READ 候选发现及历史读取保留现有业务结果、错误发现、排序、精确数字校验和事务隔离语义，减少重复初始化、扫描、排序和事实查询。本计划不改变数据库格式，不迁移现有环境，不接入相机。

基线为 `2b52c2df`。2026-10-28 的临时诊断表明：报告校验结构首次初始化约需 1.07 秒；READ 每页重复完整性扫描及候选排序，完整枚举 1000／10000 个合成活动候选分别约需 26／1962 毫秒；50 个报告动作的报告子进程执行 8140 次 SELECT。它们分别是固定初始化成本、规模增长成本和事务内查询复用问题，不能将查询数量减少直接换算成端到端提速。

遵照本任务的验证范围，不编写或运行单元测试、集成测试，也不使用测试框架或测试装配。使用临时诊断脚本保留同输入的结果、查询计划、调用次数、阶段耗时和错误事实。阶段完成条件是实现接入生产调用方、必要诊断完成并经过 `gpt-6.1-sol` 评审；这些证据不代替完整软件或真机验收。

## 必须保持的契约

| 对象 | 必须保持的行为 |
| --- | --- |
| 报告校验结构 | 按权威 Schema 和错误登记派生；规则非法仍报错；保留精确数字、引用和延迟字段校验，不改变报告字节。 |
| READ 候选 | 检出原有坏关联、缺流程和重复流程，不能以 JOIN 过滤隐藏错误；保留持有者优先及完整动作排序、DEVICE／HOST 分类和时间资格。 |
| 当前事实复用 | 明确绑定实际连接、事务和当前视图；写入、换连接及结束事务后不沿用旧边界；冻结报告 H 不代替当前投影上界。 |
| 资源与恢复 | 分页和缓存有界，取消、失败及关闭后释放；优化不增加整份工作集常驻内存，也不影响原 READ、ReadEnd、取消及重试责任。 |

## 执行步骤

三个实现范围不共享业务事实的所有权，可以在独立 worktree 中并行；根 Agent 负责集成、正式进度和整批耗时对照。以下模块划分为实施建议。

- [ ] P1 报告首次初始化：定位固定子规则重复检查，在最窄校验构造边界复用可靠规则事实；对照首次初始化和重复调用，保留非法规则及精确数字诊断。
- [ ] P2 READ 候选发现：消除每页重复全量探测和全量排序；保持有界内存、坏关联发现、完整排序与视图失效；对照相同 1000／10000 规模的查询次数和结果顺序。
- [ ] P3 报告历史读取：在实际只读事务内共享实例身份及完整当前边界，及时结束读事务；对照报告选择、固定历史边界、原始报告字节和查询次数。
- [ ] P4 集成与交付：整合经评审的实现，使用同一版本资源运行必要的临时流程诊断，保存前后数据及未覆盖范围；更新本计划及正式验证记录。

## 调度与交付

P1、P2、P3 分别由明确指定 `gpt-6.1-terra / xhigh` 的执行 Agent 负责；代码评审统一使用 `gpt-6.1-sol / xhigh`。发现需要新增持久化结构或改变业务语义时，先提交具体证据及方案，不在性能修复中悄然扩展数据库和故障范围。

正式结论按诊断环境注明源码身份、计时口径、输入规模和结果一致性；现场部署、真实相机响应、完整软件验收及目标 ARM 主机性能单独保留边界。
