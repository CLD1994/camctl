# camctl 基础类型与校验实施计划

> 执行者使用 `superpowers:executing-plans` 在当前共享工作区逐项实施。每项任务先运行能够证伪契约的测试，再实现并验证。复选框记录实际完成情况。

**目标：** 使时长换算、公共及受理 Schema 校验、分页类型和枚举测试满足既有基础契约。

**实现建议：** 复用标准库 `Fraction` 完成精确单位换算，复用 `jsonschema` 的扩展机制集中数字规则。分页数据与游标通过关联泛型表达；枚举转换单元测试隔离资源读取，实际包资源组合由集成测试覆盖。文件位置和内部函数名可以依据实际代码调整，行为契约保持不变。

**技术基础：** Python 3.11 及以上版本、`Decimal`、`Fraction`、`typing.Generic`、`jsonschema`、`referencing` 和 `pytest`；依赖版本来自组件锁文件。

**规格依据：** [输入类型与数字适配](../../camctl/data-types.md)、[模块协作契约](../../camctl/module-contracts.md)、根目录 [AGENTS.md](../../../AGENTS.md) 和[共享类型计划](2026-09-30-camctl-contracts.md)。

## 共同约束

- 公共字段、对象身份、原始输入和错误机器表示保持既定契约。
- 数字的解析、校验、单位转换和输出不得经过二进制浮点或默认舍入。
- 公共 Schema 与相机参数校验采用相同的精确数字规则，本地引用仍由登记资源提供。
- 用户文档不合法与 Schema 规则无效分别报错；资源、引用和内部错误不能转换为用户参数错误或有效空结果。
- 分页继续位置属于所属查询，结果结束属性仅由游标是否为 `None` 推导。
- 测试预期由行为契约和独立常量推导。单元测试使用资源替身，真实文件、数据库和包资源组合放在集成测试。
- 本计划覆盖基础接口及已知消费者；真实设备、目标硬件性能和物理断电属于独立联调。

## 输入分类与结果

时长接口先检查类型和有限性，再精确换算。通用时长允许零，所属动作要求为正时由动作契约另行检查。

| 秒值输入 | 换算结果 |
| --- | --- |
| `int` 或有限 `Decimal`，换算为非负整数毫秒。 | 返回精确 `DurationMillis`，不受上下文精度、舍入或陷阱设置影响。 |
| 有限数值为负，或不能表示为整数毫秒。 | 抛出 `ValueRangeError`。 |
| 非有限 `Decimal`。 | 抛出 `ValueRangeError`。 |
| 布尔值、字符串、浮点、`None` 或其他类型。 | 抛出 `ValueTypeError`，不隐式转换。 |

两个 Schema 入口对数字采用同一判定：有限 `int` 和 `Decimal` 属于数值，数学值为整数时满足 `integer`；布尔值不属于数值。范围、倍数、`const`、`enum`、`uniqueItems` 与组合规则保持精确含义。Schema 中的数字同样精确读取。

| 校验过程 | 结果 |
| --- | --- |
| 规则有效，文档符合规则。 | 成功返回。 |
| 规则有效，文档不符合规则。 | 公共入口抛出 `SchemaValidationError`，受理入口抛出 `BodySchemaError`。 |
| Schema、资源或必需引用不可解释。 | 公共入口报告规则错误，受理入口映射为 `RuleError`，不报告为用户参数错误。 |

分页的四种合法结果继续遵守模块协作契约。排序仅接受 `ReadOrder.ASCENDING` 和 `ReadOrder.DESCENDING`；其他类型或分类在构造时拒绝，不能作为降序处理。游标必须按有效排序严格推进，并遵守既有位置及批量限制。

## 审阅重点

1. 长小数只与整数毫秒差极小的值仍须拒绝；低精度不能改变合法时长。由任务 1 覆盖。
2. 公共报告的整数水位使用 `1.0` 或 `1e0` 时仍合法，布尔值仍非法。由任务 2 覆盖。
3. Schema 中的小数边界和倍数不能在资源读取时变成浮点；无效规则及缺少引用分别归为规则错误。由任务 2 覆盖。
4. 非法排序不能接受倒退游标；分页注解必须可以求值且游标类型与范围关联。由任务 3 覆盖。
5. 枚举缓存不能让单元测试偶然读取或依赖真实资源，真实登记与公共 Schema 的一致性仍由集成测试验证。由任务 4 覆盖。

## 任务 5 独立复核后的契约闭合

本任务依据[参数 Schema 版本契约](../../architecture/camera-capabilities.md#拍摄参数的-json-schema)和既有 CLI 失败规则。资源划分复用 `referencing` 的结构识别，不遍历任意 JSON 对象猜测 Schema。

| 对象与声明 | 结果 |
| --- | --- |
| 校验根规则或具有 `$id` 的独立资源声明 Draft 2020-12。 | 按统一精确数字规则解释。 |
| 根规则或独立资源缺少声明、声明其他已知版本或未知版本。 | 公共入口抛 `SchemaRuleError`，受理入口抛 `RuleError`；不进入用户文档错误分类。 |
| 普通内部子规则缺少声明。 | 继承所属资源版本，仍保持精确数字规则。 |
| 内部子规则显式声明其他版本。 | 报告规则错误，不能使校验器切换。 |
| `const`、`enum`、`default` 等实例数据含 `$schema` 或 `$id`。 | 作为实例数据解释，不要求资源版本声明。 |
| `describe` 遇到文档或规则错误。 | 返回 `1`，stdout 为空，stderr 保留实际诊断；不捕获所有异常。 |
| 单独选择基础契约单元测试。 | 测试启动不执行包资源同步，枚举与 Schema 测试使用内存替身。 |
| 选择组件集成测试。 | 集成装配显式同步权威包资源，再验证真实组合。 |

**预计文件：** 共享 Schema、CLI、Schema 与命令单元测试、组件测试装配，以及参数定义替身和 `ConfigCapabilityCatalog` 所提供根规则的版本声明。该目录原有开放对象规则保持原约束。

- [x] 为版本分类、带 `$id` 的资源、本地引用和普通子规则补双入口反例；为 CLI 规则错误补出口反例，为单元装配补不调用资源同步的反例。先观察失败。

```bash

PYTHONPATH="$PWD/apps/camctl/src" uv run --no-project --python "$HOME/.venv/bin/python" python -m pytest apps/camctl/tests/integration -q
```
