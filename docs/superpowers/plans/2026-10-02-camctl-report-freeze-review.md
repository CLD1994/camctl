# 报告范围与事务内选择的实施审查

## 范围与行为依据

检查报告机会的纯规则、报告仓储的写事务，以及受理和发布测试对冻结入口的使用。范围依据为[报告覆盖区间](../../architecture/status-reports.md#报告覆盖区间)、[同步报告范围](../../architecture/status-sync.md#报告范围)和[已有报告处理](../../architecture/status-sync.md#已有报告怎样处理)。文件位置、发布、失败重试触发、同步实际开始及动作本地完成另行实现；数据库选择结果不表示文件已经交付。

## 缺陷与责任边界

1. 纯规则使用调用者的单个起点，忽略累计 ACK 与其他同步。普通范围可能遗漏未确认内容，局部同步可能遗漏其他较早起点。修复在同一历史边界取得 A 和全部未结束责任，计算 F=min(A,S₁,…,Sₙ)，没有同步时 F=A。
2. 已有报告只比较业务区间，不能识别范围足够但早于同步开始的报告。复用须同时满足覆盖区间和全部同步开始边界；不能拼接多份部分覆盖的报告代替一份完整满足的报告。
3. 冻结仓储只取新的右端，仍采用事务前起点，并无条件登记新报告。入口须在写事务内重新判断生成、复用或跳过；事务外的决定不作为持久化依据。
4. 空业务区间与没有本地职责被混为一谈。未结束同步仍可需要反映开始之后状态的报告；没有同步且没有未确认业务变化时不登记新报告。
5. 局部同步读取没有核对起点报告的登记顺序，可能接受开始边界之后才登记的起点。共用读取层须核对原报告终点与 S 一致、创建事件不晚于 B；矛盾时冻结及 ACK 输入均按状态库错误回滚。验证空局部范围不能复用这样的起点报告，以及 ACK 不能在不可靠定义上结束责任。
6. 已有报告的非零左端缺少完整事务检查，可能把一次受理中间的业务水位保存为起点。共享报告读取须验证非零起点对应真实业务事件、其事务已包含在冻结 H 内、同事务没有更大的业务水位；后续管理事件不影响业务末位资格。原始 ACK、累计 ACK、局部同步起点与报告复用均须拒绝同一无效依据，保持原报告及全部历史不变。

## 输入、输出与不变量

仓储输入为操作键、已打开的状态库连接及实际事件时间，不接收预先计算的报告范围。输出显式区分 GENERATE、REUSE、SKIP：前两者提供实际固定报告依据，SKIP 不提供报告。错误沿 P3 区分确认回滚与提交未知；不将数据库错误变成 SKIP。

在同一短写事务中取得完整边界 H、其业务终点 W、累计 ACK A、全部未结束同步的起点 S 和开始事务末位 B。F=min(A,S₁,…,Sₙ)，M=max(B₁,…,Bₙ)，无同步时 F=A、M=0。均须是精确合法值，A/S 不晚于 W，B 不晚于 H；已有累计身份与其报告终点一致。未开始的 report_status 动作不影响范围；已确认及已取消责任不影响新报告范围。

| F < W | 存在未结束同步 | 数据库选择 |
| --- | --- | --- |
| 否 | 否 | SKIP；不登记报告、不追加管理历史 |
| 是 | 否 | 选择覆盖 (F,W] 的一份报告，否则登记新报告 |
| 否 | 是 | 仍检查覆盖范围和同步历史；无合格报告则登记新报告 |
| 是 | 是 | 检查一份报告是否同时覆盖 (F,W] 及全部同步历史，否则登记新报告 |

| 已有报告 R 的范围覆盖 (F,W] | R.frozen_event_id >= M | R 的固定依据有效 | 结果 |
| --- | --- | --- | --- |
| 否 | 任意 | 任意 | 不采用该报告 |
| 是 | 否 | 任意 | 不采用该报告 |
| 是 | 是 | 否或无法读取 | 状态库错误，不解释为不存在 |
| 是 | 是 | 是 | REUSE 原身份、历史边界、范围和生成版本，不增加历史 |

新报告保存当前 H、F、W，且冻结位置早于自身登记事务。管理事件不增加业务水位。已有报告与冻结内容保持不变；REUSE 仅表达数据库依据满足内容要求，交接目录观察和本地发布仍由发布流程负责。

## 实施顺序与门禁

模块、函数和测试文件是实现建议，允许按实际数据流调整；复用 SQLite、P3、已有 ACK 事实读取和 SyncResponsibility，不增加依赖。纯规则按流消费同步和候选报告，避免复制完整历史或长期保留所有报告。

- [x] T1：用当前入口复现累计 ACK 未参与范围、空同步被跳过、复用仍登记新报告及事务前范围失效，确认目标断言失败。
- [x] T2：定义精确的报告需求和选择结果；覆盖 A/S/W、历史边界与空范围决策矩阵。去除无约束 kind 字符串和冗余起点。
- [x] T3：在同一写事务读取真实事实、选择有效旧报告或登记新报告；统一同步边界验证。SKIP/REUSE 使用 P3 只读命令，不追加事件；范围或读取不可解释时保持状态库错误。
- [x] T4：迁移所有已知冻结调用方和真实事务测试准备，保留 ACK 不推进时的身份保持、旧报告不满足新同步、多个责任及提交未知等既有断言。测试需要多份报告时以真实内容或同步要求变化驱动，不用无条件登记建立重复报告。
- [x] T5：补齐同一 H 的受控并发受理与 ACK、全部同步起点及最晚开始边界、正式守卫、读取与写入失败、提交未知及旧报告不变的反例；执行 Python 3.12/3.11 相关门禁并独立审查。同步生产者尚未实现，其真实并发组合归下述未闭合消费者。
- [x] T6：更新 R2 和路线图的分项 checkbox、记录全量验证的实际限制并提交。文件规则与真实 run 装配未完成时保留完整 R2 未完成状态。
