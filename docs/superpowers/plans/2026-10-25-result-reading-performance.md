# 结果读取与调度性能实施计划

依据：[结果读取与调度性能设计](../specs/2026-10-25-result-reading-performance-design.md)。

## 步骤与依赖

- [x] **1：实现单次目录列举和元数据脚本优化。** 提供当前尝试独占、流式接收且临时文件缓冲的目录读取上下文，按连续游标交付有限页；失败和取消不产生完整扫描结论。精简元数据脚本，保留逐路径错误与响应帧。用单元测试验证真实端口契约和资源关闭。
- [x] **2：前移基准筛选并接入目录上下文。** 为结果驱动提供原基准的只读候选筛选端口，只查询新增分段文件大小；继续保存完整路径观察与独立差集校验。拥有者负责尝试结束及异常时的目录缓存关闭。减少同一拥有者对完整前页链的重复读取，增加分阶段计时。
- [x] **3：修正窗口观察和报告推进。** 将到期动作的窗口观察与过期处理从同设备长任务中独立出来；报告维护独立推进，保留取消、实际结束及失败交接规则。用受控等待验证长任务期间窗口观察和其他流程继续推进。
- [x] **4：集成、审查与单元验证。** 分别审查隔离分支后集成，执行受影响单元测试及完整 camctl 单元测试。核对共享契约、恢复入口和计时记录。按用户要求不运行集成测试。
- [x] **5：更新人工验证安装与交付。** 构建并核对安装版 CLI，在没有相关 CLI 会话执行时更新当前人工验证入口，保留现有配置、数据库和媒体。交付运行方法、计时位置与人工验收范围。

步骤 1 和 3 可从干净基线在隔离工作区并行实施。步骤 2 依赖步骤 1 的目录读取接口，框架筛选和历史核对可提前准备。步骤 4 依赖步骤 1–3，步骤 5 依赖步骤 4。内部类名和提交拆分为实施选择；实际收益以人工验证计时为准。

## 启动准备优化

人工验证表明，启动前基准尚未使用步骤 1 的单次目录读取能力；136 个路径的两页基准读取耗尽了 3 秒启动窗口。优化从 RESULTS 扩展到同一活动的基准收集，并核对参数设置和实际 START 的边界。

- [x] **6：接入基准单次扫描。** 复用现有目录上下文，覆盖普通及结果策略入口；保持逐页可靠保存、提交未知、取消、冷恢复和原范围占用规则。实际调用结束及保存交付后关闭缓存，会话退出处理剩余责任。先增加可证伪的单元测试，再实现和定向验证。
- [ ] **7：接通独立准备与实际启动。** 沿准备发现、设备及输出范围占用、设置、完整基准、等待计划时间和实际 START 接通生产流程；默认提前 10 秒。取消、过期、失败和冷恢复保持独立准备责任及原启动窗口，原活动、真实结果和完整保存申请共同核对。
- [ ] **8：组合审查与单元验证。** 审查真实生产接线及资源生命周期，执行受影响及完整 camctl 单元测试，不运行集成测试。
- [ ] **9：安装与人工交付。** 构建并核对源码、发行物与独立安装，在原 CLI 会话结束后更新人工验证入口，交付实际收益的验证方法。

步骤 6 的实现与步骤 7 的合同核对可并行；步骤 7 按独立准备合同实施。步骤 8、9 按依赖顺序执行。

步骤 7 按[拍摄提前准备规格](../specs/2026-10-25-capture-preparation-design.md)实施，默认提前量为 10 秒。内部接口和文件划分为建议，可按实际生产数据流调整。

- [ ] **7a：准备占用、意图和状态保存。** 支持 pending 准备活动、独立设置尝试、开始事务复用、原申请核实、取消和过期收场、失败状态及格式更新。先验证状态分类，再实现共享存储边界。
- [ ] **7b：驱动设置与 START 分离。** 实现独立准备端口和当前会话凭据，匹配原设备、活动、参数和准备票据；没有凭据不能跳过设置，实际 START 仍核完整窗口。此项可与 7a 并行。
- [ ] **7c：接通真实调度。** 加载设备准备提前量，发现准备期限，保持原候选顺序及持有者；共享实际调用和原保存责任，完成准备后退出后台推进，到点才开始并派发 START。接通取消、终态发现、冷恢复、报告和会话退出，先审计真实边界再作单元组合验证。

## 当前进度

步骤 1–5 已完成。目录与元数据最终 82 项定向单元测试通过，结果适配三个目录为 3322 项通过；报告最终交接目标为 33 项通过。合并树完整单元测试为 7258 项通过、1 项跳过，107.86 秒，退出 0；两条警告来自既有同步用例的 asyncio 标记。本次没有运行集成测试。

独立评审发现并修正了报告前提错误延迟公开、取消时丢失文件阶段返回值，以及失败诊断取消绕过资源关闭的问题。窗口、报告和缓存拥有者分别保留原执行资格、真实文件结果及必要收场，关闭失败不重新派发已经完成的读取。

CLI 已更新到原人工验证入口，日志级别为 INFO。wheel 的 308 个生产 Python 文件和 27 份权威资源与源码、安装版逐字节一致；依赖检查和安装版能力导出退出 0，主机及客户端的能力说明与新导出逐字节一致。构建、测试、配置备份和安装核对由 `.local/deployments/20261025-result-reading-performance/delivery-manifest.json` 引用，完整单元回执在 `.local/verification/result-reading-performance-20261025/`。实际 ADB 工具兼容性、相机行为和性能由用户按[人工验证指南](../../hardware/result-reading-performance-validation.md)继续验证，软件测试不作为真实设备耗时结论。
