# 结果读取与调度性能实施计划

依据：[结果读取与调度性能设计](../specs/2026-10-25-result-reading-performance-design.md)。

## 步骤与依赖

- [ ] **1：实现单次目录列举和元数据脚本优化。** 提供当前尝试独占、流式接收且临时文件缓冲的目录读取上下文，按连续游标交付有限页；失败和取消不产生完整扫描结论。精简元数据脚本，保留逐路径错误与响应帧。用单元测试验证真实端口契约和资源关闭。
- [ ] **2：前移基准筛选并接入目录上下文。** 为结果驱动提供原基准的只读候选筛选端口，只查询新增分段文件大小；继续保存完整路径观察与独立差集校验。拥有者负责尝试结束及异常时的目录缓存关闭。减少同一拥有者对完整前页链的重复读取，增加分阶段计时。
- [ ] **3：修正窗口观察和报告推进。** 将到期动作的窗口观察与过期处理从同设备长任务中独立出来；报告维护独立推进，保留取消、实际结束及失败交接规则。用受控等待验证长任务期间窗口观察和其他流程继续推进。
- [ ] **4：集成、审查与单元验证。** 分别审查隔离分支后集成，执行受影响单元测试及完整 camctl 单元测试。核对共享契约、恢复入口和计时记录。按用户要求不运行集成测试。
- [ ] **5：更新人工验证安装与交付。** 构建并核对安装版 CLI，在没有相关 CLI 会话执行时更新当前人工验证入口，保留现有配置、数据库和媒体。交付运行方法、计时位置与人工验收范围。

步骤 1 和 3 可从干净基线在隔离工作区并行实施。步骤 2 依赖步骤 1 的目录读取接口，框架筛选和历史核对可提前准备。步骤 4 依赖步骤 1–3，步骤 5 依赖步骤 4。内部类名和提交拆分为实施选择；实际收益以人工验证计时为准。

## 当前进度

已核对用户验证范围、当前干净工作区及已有环境。实施中。
