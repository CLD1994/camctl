# 目录切换的可靠结果与软件验收计划

**目标：** 显式 `init` 按实际目录对象和三路径提交结果判断切换，保留数据库身份、业务历史、文件 ID、累计 ACK 与旧报告字节。

**执行方式：** 当前 `implement_camctl` 工作区中顺序实施，先失败测试再修改生产代码，最后独立审阅。模块及函数组织属于实施建议，行为契约以[目录绑定与变更](../../architecture/configuration.md#文件目录的绑定与变更)及[验收 F-07/F-08](../../camctl/database/consistency-verification.md#中间文件的路径与定位)为准。

**技术基础与项目约束：** Python 3.11、现有 sqlite3 与 pathlib；不增加依赖。单元和集成测试分别执行，pytest 进程独占、集成目录顺序运行。状态库仅由显式初始化创建。路径切换不生成业务事件，不迁移或删除文件。

## 行为契约与状态分类

| 输入或观察 | 初始化结果与不变量 |
| --- | --- |
| 新配置根目录是符号链接，包括链接到空目录或悬空链接 | 初始化失败；不跟随链接后把它当作实际空目录，不改变已有绑定。 |
| 原三目录、数据库责任及新目录均合法 | 准备目录并将三路径一起提交；成功后才报告 `SWITCHED`。 |
| COMMIT 报错，重读三路径均为新值 | 切换已经完成，返回 `COMPLETED`，初始化报告 `SWITCHED`。 |
| COMMIT 报错，重读三路径均为旧值 | 切换尚未完成，报告错误并说明原绑定仍有效；可以重新检查。 |
| COMMIT 报错，三路径混合、缺失或重读失败 | 报告未能可靠确认的错误，不宣称原绑定有效，也不选择一套路径继续。 |
| 提交前或提交后返回前进程终止 | 后续显式 `init` 按原库整套绑定判断；旧值重新检查，新值按重复初始化验证。 |
| 事务内责任重查遇到数据库读取错误 | 结束未完成事务，可靠重读整套绑定并返回类型化失败；初始化不得让数据库异常逃逸。 |
| 目录包含大量空的同级子目录 | 逐项核对，不将全部待扫描子目录积累在内存中；资源随当前目录深度变化。 |
| 带业务历史的库切换成功 | 除三处部署路径外，数据库全部事实保持；原 H 的报告重建字节、文件与产物身份和 ACK 保持。 |

审阅关注：悬空链接不能成为“不存在”；别名和相互包含的检查仍使用实际位置；回滚失败不能推出提交未完成；保存结果不可读时不得输出“原绑定仍有效”；业务历史重建不得改写部署绑定。
