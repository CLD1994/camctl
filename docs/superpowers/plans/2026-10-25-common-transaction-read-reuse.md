# 公共事务读取复用

## 目标与依据

结果完成组的同快照只读核实，在结果页及文件证明复用版本中仍执行 1416 次 SQL；仅有 198 种不同语句及参数，1218 次为重复执行。事务范围、前一边界及成员计数共 594 次，完整当前行共 381 次。随后合并的有限原页窗口保留了原始页的容量边界，但完成及严格文件证明绕过小值复用，同一快照变为 16772 次 SQL。两份结果相同，原始证据位于 `.local/verification/segment-query-amplification-20261025/`。

本计划延续[事务读取复用](../../camctl/persistence-runtime.md#单次完整事务的读取复用)，不改变业务、历史及独立守卫的契约。原子写事务和原保存完成组核实共用相同入口，照片、录像、延时及恢复中的调用均按各自原资格处理。

## 方案选择

| 方式 | 收益和代价 | 采用范围 |
| --- | --- | --- |
| 在公共语义读取入口复用 | 不改变调用顺序，消除同一事务反复加载相同事实；已有连接、写入失效及容量机制可直接使用 | 完整行、历史事务范围及有容量限制的已提交事实；优先实施 |
| 显式批量预取 | 适合首次读取许多不同对象，但需调用方提前掌握身份及共同边界；当前主要成本是反复读取少量相同事实 | 根据复用后测量，再处理仍然突出的集合读取 |
| 跨事务通用状态缓存 | 可消除后续事务重读，但需数据库身份、依赖版本及跨进程刷新机制 | 继续由原 P6 后置事项管理，本任务使用单次事务作用域 |

复用沿业务语义入口接入，不在 SQLite 执行器中缓存任意 SQL。标准库已有的容器、上下文和隔离复制继续由现有实现统一维护，不新增缓存依赖。

## 行为契约与状态

| 条件 | 行为 |
| --- | --- |
| 同一可靠事务、相同连接、相同写入代及完整类型化输入 | 复用已经成功核实的读取，返回独立结果 |
| 没有事务复用作用域、连接不同或事务已结束 | 执行原读取，不跨事务保留 |
| 连接写入、独立守卫或提案阶段切换 | 既有失效及清理继续生效，下一次重新读取 |
| 事务范围首次读取，未提供 `validated` | 完整核对本事务、前一边界及成员计数后才保留 |
| 提供 `validated` | 保持原范围比较及错误语义；其输入与完整成员核验使用不同复用身份，不能向未提供该参数的读取授予完整资格 |
| 查询、解码或完整性错误 | 保留原异常及游标释放，不缓存失败 |
| 有限原页窗口已经生效 | 整页仍由原窗口管理；完成及严格文件证明仅复用其小型结果，不额外保留整页 |
| 缓存达到条目或字节上限 | 沿用既有淘汰和重读，不增加随总对象数增长的保留量 |

全局历史分页跨短读事务时继续重新核对事务首尾及前一边界。守卫仍从自己的核验阶段比较实际申请、当前资格及事件，不使用提案阶段的成功标记替代独立判断。尚未完成的当前历史组不能因旧缓存而通过；成员写入和阶段清理均使相关事实重新核验。
