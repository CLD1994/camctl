# 调用即提交与可选写入回执实施

目标由[通用日志接口](../specs/2026-10-27-general-logging-api.md)定义，各级别的完成点由[写入完成要求](../../architecture/logging.md#分级写入完成与断电持久性)统一维护。重要级别的持久化接线与验证由[错误日志持久性计划](2026-10-27-error-log-durability.md)跟踪。

1. [x] 在原日志通道实现有序同步提交、可等待写入回执及满载 ERROR 原责任托管；保留原接纳水位、取消和关闭事实。
2. [x] 使原诊断及日志副本共用同一回执，区分接纳与真实写入，保持原异常身份与所有权，不抢回副本记录。
3. [x] 接通通用 Logger 和生产调用点，调用无需 await 也执行；更新实际语义、源位置及原格式／媒体／上下文验证。
4. [x] 完成真实满载、取消、关闭、失败及混合顺序组合，独立复核并执行合并检查，记录来源和交付范围。

## 建议组织

先冻结回执和通道公共接口，再在独立工作区实现通道与诊断桥接。消费者接入按依赖集成。可复用 Janus 的持锁取出扩展点处理较早 ERROR 补位，复用线程安全 Future 保存一次写入事实；具体内部拆分可调整，但不创建逐条后台 Task。低层只等接纳的接口和显式写入回执分别验证，不能互相冒充。
