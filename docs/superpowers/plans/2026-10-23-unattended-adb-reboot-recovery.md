# 无人值守 ADB 软件重启恢复实施计划

本计划实现[软件重启恢复](../../architecture/camera-recovery.md#无人值守的软件重启恢复)，由后续有效拍摄动作触发，保持旧拍摄和 STOP 的终态及失败事实。

## 已固定的实现边界

恢复责任以原活动为唯一身份，保存在独立的 `software_recoveries`，普通 `phase` 枚举列承担责任发现，`state_json` 含版本、原绑定及 serial、验证固件、触发动作、重启前后 boot_id、累计派发与核实次数、首次期限、下次检查时刻和原目录基准引用。原任务定位结构保持原有职责。`DEVICE_OBSERVED.SOFTWARE_RECOVERY` 分支保存每次可靠推进；新表采用整体格式 V3；旧 V1/V2 库保留原有全部读写及业务资格，使用软件恢复前通过显式 `init --upgrade-software-recovery` 升级，不由 `run` 隐式修改结构。

阶段为 `checking`、`intent`、`confirming`、`preparing`、`scanning`、`ready`、`isolated`、`abandoned`。意图可靠保存后才允许一次派发。意图后中断按可能已发出恢复，只核实 boot_id，不盲目补发。boot_id 变化与固件重启合同共同保存 `ENDED`；会话准备和独立目录范围完成后才通过原释放事务放行。目录核实以固定原范围逐页保存证据，不重开原 RESULTS，不证明文件完成或采集满足目标。

每设备 `[software_recovery]` 默认不使能。真机核实机型及固件的操作系统重启会终止采集和控制且不会续拍后，设置 `verified_fingerprint`，与设备实际固件资料按驱动来源类型生成的指纹精确比较才使能；两机型资料入口、编码和离线复算统一见[恢复配置](../../camctl/configuration-reference.md#相机软件重启恢复)。默认重启最多 1 次，整体 180 秒，单次调用 10 秒，核实间隔 3 秒，最多 64 次核实与 256 目录页。参数首次责任创建时冻结，跨触发动作和 run 保留。

恢复期间原 HELD 保持。正式驱动端口按相机建立排他恢复范围，普通控制、停止和文件访问不能进入；恢复自身仅在所属阶段调用有界核实、设置和目录端口。其他相机继续运行。恢复开始前核对没有其他有效活动、启动保留或未收场尝试、读取及目录调用。

升级入口先在会话锁内使用 SQLite backup 保存原库一致副本并同步文件与目录，再在一个事务中创建独立表和更新 metadata 版本约束。已有历史编号、不可变历史与业务投影保持。普通 `init` 仅验证原库；`run` 不升级。升级发生提交未知或中断时，先重新打开核实实际格式、表与外键，不能重复套用迁移；备份保留供核查。V1 原有照片用途限制保持，本次升级入口先要求 V2，不能通过恢复升级隐式扩大照片用途。

初始检查、意图、确认和准备/目录是独立故障分区。可靠保存意图前不派发；意图存在即按可能已派发恢复；boot 未变或无法核实时继续有界确认；新 boot 只结束旧设备活动；准备与范围任一未定均保持 HELD；到期或核实预算耗尽保存隔离，其他相机继续。恢复终态不因新触发动作重新开始。

## 步骤与验收

- [x] R1：沿正式 gate、驱动和历史事务接线，并用真实 SQLite 的正式处理器集成场景验证；旧 FAILED/UNKNOWN_HELD 且 query 不可用仍可触发，不能给 UNKNOWN 增加 STOP 权限。
- [x] R2：实现独立意图、boot 核实、设置和分页范围责任；验证意图前后中断、重复 run、原绑定不符和跨触发预算。
- [x] R3：验证完整正式处理器释放链，准备失败、boot 未变、文件范围未知及期限耗尽保持占用；旧错误、START 与 STOP 不变，其他设备继续。
- [ ] R4：检查事件、报告依赖、数据库结构、配置及受影响组件回归，保存 UTC、命令、工作目录、日志、退出码并提交。

软件替身只证明生产链和故障分区。真实 ADB、两机型重启与无自动续拍合同由协调者独占执行；软件实现代理不连接设备，不修改原验收库。

## 实施进度

R1 至 R3 的正式处理器链、原 UNKNOWN_HELD 候选、无查询能力、原 START/STOP/错误保留及新动作再次启动已通过软件集成。跨触发动作和连接重启不重置责任，实际 SQLite COMMIT 回执未知不重复派发；原 boot 一次写入、连续页和原基准差集反例、其他相机继续、旧 V2 缺表历史读取、初始化发布竞态和完整报告链均已验证。迁移单独覆盖非空历史及原 ID 保持、提交前回滚并复用原备份、实际提交回执丢失后新连接核实。R4 正在完成候选独立评审与受影响范围回归。

恢复期间的普通拍摄、STOP、状态/文件查询、读取和删除意图在共同操作授予边界阻止；读取调度同时按持久恢复占用等待，即使旧活动已 ENDED 也不交错文件工作。会话取得资格时先恢复驱动排他记录；原本机文件持有者、按源文件归属的调用及目录责任均在恢复前核对。

表的最低格式通过事件登记 `minimum_format` 统一维护，打开旧库、有界历史复制与旧对象恢复消费同一登记；V3 新恢复表的自身行包含在动作历史和快照中。
