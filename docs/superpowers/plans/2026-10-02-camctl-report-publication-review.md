# 报告字节与发布事实的实施审查

## 范围与行为依据

沿已登记报告检查确定字节、发布意图、可靠发布和文件处理失败的数据库生产者及正式守卫。行为依据为[报告字段](../../camctl/database/reports-runtime.md#报告字段)、[记录报告已经发布](../../architecture/report-publication.md#记录报告已经发布)、[状态报告发布前落盘](../../architecture/file-handoff.md#状态报告发布前落盘)和权威 `event-transitions.json`。实际生成、目录恢复、替换、补投资格、同步动作本地完成及维护装配仍由 R5—R8 的相应任务负责。

## 问题、根因与修复边界

1. 失败报告保存后，准备及发布命令仍把 `last_error_json` 的旧值写成空。P3 对比真实旧值时拒绝合法恢复。每次更新须从同一写事务读取并解析完整管理事实，使用真实错误作为前值；后续完整成功清空当前错误，历史保留原错误。
2. 正式报告守卫忽略更新事件。错误的准备生产者可以改变首次确定的字节依据；错误的发布生产者可以错误增加次数或指向其他历史事件。守卫须验证字节一经确定不再改变，每次发布次数恰好增加 1，成功引用为当前发布事件。准备、意图、发布及失败都使用同一管理状态校验。
3. 现有发布入口在一次事务内补写意图与成功，只接收报告 ID，无法把实际交接结果与成功记录明确关联。拆分发布意图与可靠发布的持久化入口；后者消费真实文件端口的完整结果，未移动、结果未知、源清理或目录同步未完成时不能记录成功。目录同步明确不受平台支持时遵循文件端口的既定语义。成功后文件被领取或删除不撤销当前进程已经取得的移动与同步结果。
4. 字节登记入口接收完整正文并再次计算摘要，与报告进程只返回长度和摘要的边界不一致。使用小型、受约束的确定字节值，正文仍由生成器流式写出。仓储不读取全文、不验证公共 JSON，也不补造生成及同步完成；调用方取得合格生成结果后才能登记。
5. 管理投影中的成功次数和事件引用只有形状校验，不能证明它们属于该报告的最近一次成功发布。准备、意图、发布及失败入口都须沿报告的历史目录读取最近一条实际发布事件，核对对象、分支、前后阶段、次数递增及引用。不得接受其他事件、旧的合法配对，或者在已有发布历史时接受零次数与空引用；读取只取得一条事件，不加载全部历史。
6. Python 的普通相等比较将布尔值与数值混同，导致错误详情变化被当成重复输入。精确 JSON 比较须复用现有 `jsonschema` 的公开 `const` 语义，区分布尔与数值、忽略对象成员顺序并保留精确数值等价。编码、解析和正式守卫中的比较无法完成时须转成可诊断的校验错误并回滚，不能折叠为默认比较结果；普通命令内的失败继续由 P3 的规划失败边界处理。
7. 受约束枚举重建后，等价成员不具有原缓存对象的身份。状态分区先严格解码存储整数，再按成员值判断，不依赖缓存对象身份。状态模型、正式守卫及原发布事件读取共同保持这些规则。

不存在与不可解释分别失败；不把读取或提交错误转成发布成功、无任务或自动重试。缺失报告不新建。固定报告依据继续使用共享读取校验，报告管理不增加业务水位。

## 状态分类与不变量

`B` 表示首次确定的 `(size_bytes, sha256)`。两字段共同为空或共同合法；形成后所有重建均须匹配。长度是 SQLite 非负整数，摘要是 64 位小写十六进制。`publication_count` 是 SQLite 非负整数，0 对应空成功事件，正数对应可靠成功事件；错误是可持久化的 JSON 对象，`FAILED` 必须有错误。

新登记报告尚未执行文件处理，当前错误为空。最近发布事件是成功次数及引用的权威依据；后续文件处理失败不能抹去该依据。原操作键只能复用同一报告、管理分支和输入的已提交事实，复用不重做文件操作，也不增加历史。即使后来已有新的成功发布，重读旧发布操作仍返回该操作原本保存的结果。

| 原状态 | 登记相同 B | 登记不同 B | 保存发布意图 | 保存可靠发布 | 保存文件处理失败 |
| --- | --- | --- | --- | --- | --- |
| REGISTERED，尚无 B | 首次形成 B，进入 PREPARED | 同左，首次没有旧 B | 拒绝 | 拒绝 | 进入 FAILED，保留未知字节 |
| REGISTERED，已有 B | 进入 PREPARED，保留 B | 拒绝 | 拒绝 | 拒绝 | 进入 FAILED，保留 B |
| PREPARED | 无新事实，不增加历史 | 拒绝 | 进入 PUBLISHING | 拒绝 | 进入 FAILED |
| PUBLISHING | 无新事实，不倒退阶段 | 拒绝 | 无新事实，不增加历史 | 合格交接结果使次数增加 1，进入 PUBLISHED | 进入 FAILED |
| PUBLISHED | 无新事实，不倒退成功 | 拒绝 | 新补投进入 PUBLISHING，保留原次数及成功事件 | 没有新意图时拒绝 | 进入 FAILED，保留原成功事实 |
| FAILED | 形成或核对 B，进入 PREPARED并清空当前错误 | 已有 B 时拒绝 | 仅已有 B 时进入 PUBLISHING | 拒绝 | 保存新的实际错误，保留已有 B 与成功事实 |

此表只定义已取得业务资格后的数据库操作，不授予文件生成、补投或恢复资格。PUBLISHING 的同意图重读不证明文件已移动，提交未知先按原操作键核实历史。仅恢复观察与实际业务机会可决定后续操作，不用阶段默认推断副作用未发生。

管理事件正文只包含变化。相同错误伴随进入 `FAILED` 时只保存阶段，`FAILED` 中不同错误只保存错误；完整状态守卫验证后状态为 `FAILED` 且错误非空。同键查询恢复原完整事务的状态及首次字节依据，核对原目标、分支、时刻和全部实际输入，返回该次准备、意图、发布或失败的原结果。具体分类及门禁见[报告管理的变化事实与原键恢复](2026-10-02-camctl-report-management-reuse.md)。

| 文件端口结果 | 可靠发布记录 |
| --- | --- |
| MOVED，源已移除，目录同步成功，且没有错误 | 可以保存；无需文件仍留在 ready |
| MOVED，源已移除，目录同步明确不受平台支持，且没有错误 | 按文件端口的既定平台语义可以保存 |
| NOT_MOVED、UNKNOWN、源未移除、同步失败或未尝试、任意错误或结果字段类型无效 | 拒绝成功记录；保存实际失败由独立失败入口负责 |

## 实施顺序与门禁

模块划分、接口名称及提交划分是建议；确认的契约及上表状态分区是硬性要求。使用已有 P3、共享报告读取、精确 JSON、权威枚举和文件端口结果，不增加依赖、不新增报告阶段。

- [x] T1：用真实 SQLite 复现失败恢复的旧值错误、错误准备可改摘要、错误发布可改次数或成功事件；区分目标断言失败与测试准备错误。
- [x] T2：定义小型确定字节及发布结果类型；登记、意图、失败及发布命令从同一事务读取完整管理事实。相同字节的重复登记不倒退阶段，不建立空历史事务。
- [x] T3：补齐正式报告更新守卫。用直接提交错误命令证明绕过普通入口也不能改变 B、跳增次数或伪造成功引用；旧错误与新错误由历史分别保留。
- [x] T4：迁移已知字节与发布消费者，补齐状态表、文件结果表、首次失败与补投失败恢复、读取和写入失败、提交未知及正逆向回放。真实文件边界与 SQLite 的集成验证后，才能声称可靠交接结果可保存。
- [x] T5：执行 Python 3.12/3.11 相关单元及集成门禁，独立审查实际代码和覆盖，记录全量测试的已知限制；更新 R7 分项及路线图并提交。

## 尚未闭合的业务消费者

- [x] 专用于报告的文件引用、命名、ready 保留与替换及 processing 保留。
- [x] staging 重建与恢复观察的真实生产者和数据库保存。
- [x] 同一报告补投资格及正常、受限会话中的真实机会处理。
- [x] 发布结果与同步本地完成及动作成功共同保存。
- [ ] 报告进程的真实生成结果、文件锁及维护协调器装配。

前四项由 `camctl.reporting.publication` 及 `record_recovered_publication` 于 2026-10-03 闭合：报告文件使用 `staging/reports/` 专属子目录与最终发布名，发布编排按"写入同步 → 字节登记 → 意图 → 撤下旧 ready 报告 → 原子移动 → 发布记录 → 同步本地完成"推进并逐步分类失败；恢复观察按目录位置与报告登记判定保留、重建或补投，staging 的报告子目录尚未创建视为无残留，ready 与 processing 缺失仍是观察错误；恢复发现以文件名摘要与首次确定字节核对后同事务补齐发布事实（PREPARED 补意图、FAILED 先恢复到发布中）。受限会话的一次报告处理入口随 run/submit 真实入口装配（R6 CLI 分项）。

## 验证证据

测试使用仓库外 Python 环境，`PYTHONPATH=/workspaces/camctl/apps/camctl/src:/workspaces/camctl/apps/camctl/tests`。单元测试隔离稳定协作者，不访问真实状态库或文件；集成测试组合真实 SQLite、P3 和相关文件端口。两个集成 pytest 进程不同时运行。

结果随实际完成的门禁登记，不能把数据库接口通过等同于完整 R7 已完成。

Python 3.12 和 3.11 的单元测试各为 1132 项通过、1 项排除。未排除的全量运行均在日志凭据用例 `TestPendingLog.test_accepted_record_delivers_receipt` 等待，分别在已通过 709 项后中止；该已知日志模块问题独立安排，排除命令为 `pytest -q apps/camctl/tests/unit -k 'not test_accepted_record_delivers_receipt'`。另有两项既有同步测试被误标为异步测试的警告，未放宽配置。

独立复核实际执行 publication 单元测试 50 项，并通过受 SQLite 接口约束的替身验证正式 INTENT 比较异常返回 `rolled_back` 且执行回滚。父 Agent 另行执行真实 SQLite 集成门禁，二者不互相替代。真实文件集成只组合通用 F5 交接结果与报告发布记录：完整写入及同步、移动、接收方领取删除，再保存成功；报告专属目录引用、替换与协调器仍属于上述未闭合消费者。
