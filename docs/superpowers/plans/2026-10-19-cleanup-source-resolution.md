# 范围清理的来源解析修复

## 目标与既有契约

修复合法 `delete_action_outputs.params.source` 跨计划引用在执行时尚未固定来源就申请固定目标，导致会话以 `state_db_error` 退出的问题。沿用[清理规格](../../architecture/output-cleanup.md)、[来源与目标状态](../../camctl/database/plans-actions.md#来源解析与目标集合)和[来源初始化守卫](../../camctl/database/event-transitions.json)；公共输入、数据库结构和设备删除命令不变。

用户已授权修复该缺陷。本计划在主工作区串行执行，先失败测试，再修改代码。TX2 原库、原动作和设备文件保持原状，软件验证与现场任务恢复分别记录。

## 状态与处理

| 输入与已有事实 | 必须执行的处理 |
| --- | --- |
| 精确 `output_ids` 清理 | 不解析来源，继续原目标固定与逐项处理。 |
| 本计划引用已在受理时固定 | 复用原完整来源；不创建取回选择记录。 |
| 范围清理的来源为 `PENDING` | 在执行资格有效时核实原引用，同一事务保存真实来源计划与全部依赖，然后才能固定产物集合。 |
| 来源不存在或类型不适合 | 保存来源解析失败和动作失败，必要时共同完成计划；不新增删除调用。 |
| 来源存在但没有拍摄成员或没有产物 | 固定有效空来源或等待来源结束后固定空目标，清理成功。 |
| 来源尚未结束或适用产物处理尚未完成 | 保留已固定来源并等待，不提前删除。 |
| 动作取消、已有终态或来源已经固定 | 保持取消及终态规则；不重新解析或扩大来源。 |
| 保存回滚、结果未知或运行时重建 | 接续原请求、操作键及发生时刻；核实原完整事务，不替换身份、不扩大集合。 |

## 实施与验证

1. 在 bootstrap 组件测试中，以真实受理和执行入口重现跨计划及跨动作实例范围清理。增加缺失来源、合法空范围和已开始动作恢复；先确认在原代码下由来源未固定导致失败。
2. 建议复用现有 `ResolveSources` 事务：允许取回和范围清理共同保存来源，只有取回初始化 `obtain_source_selections`。具名守卫继续拒绝清理创建取回选择；解析失败仍保存对应动作错误与计划聚合。
3. 在清理开始与目标固定之间增加来源解析，复用现有清理原申请保存责任。原请求参数重建采用同一纯解析函数；精确 ID 和受理时已固定的来源不进入新阶段。
4. 增加持久化回归，核对来源及依赖共同提交、取回选择隔离、原键核实、回滚和提交未知后恢复，以及固定来源不因新拍摄扩大。补充取消与尚未结束来源的等待验证。
5. 按组件指南串行运行新增测试、outputs、bootstrap、acceptance、cancellation、history、reporting 相关集成测试和 camctl 单元测试。核对生产装配及实际报告生成的跨计划清理路径；不以预填 `FIXED` 状态替代首次受理到执行的覆盖。
6. 检查全部 diff、文档链接及 `git diff --check`，记录实际命令、解释器、结果和证据位置。代码评审核对通用路径及失败恢复，不修改现场状态库或自动触发删除。

## 验收依据

从真实受理进入的跨计划范围清理可靠保存 `SOURCE_RESOLVED`，再固定 `TARGETS_FIXED`，最终逐项清理并生成报告。缺失来源成为动作级失败；合法空范围成功；精确 ID、本计划引用和现有取回行为保持。已经处于 `running + source=PENDING` 的原动作可在后续会话继续，不新增拍摄、请求或重复删除。
