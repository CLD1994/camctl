# 自动迁移与失败回滚实施计划

## 目标与边界

更新入口在停机条件下自动选择已实现的数据迁移路径。安装、迁移、发布或更新核验失败时，自动恢复更新前的 Python 环境与数据库；明确指定客户端能力同步时，同时恢复该能力文件。进程中断后，下一次运行更新器先恢复未完成更新，确认原状态后才开始新的更新。主程序保持停止，由操作者恢复运行。

自动更新以当前数据库格式 V9 为维护基线。当前 V9 库只验证，今后数据库格式变化时登记从基线开始的迁移步骤。更新仅接受基线和后续已登记格式；没有迁移路径、未知或无效的状态不能补造、清空或降级。格式号与迁移依据保持单一权威来源。

恢复范围覆盖更新错误、进程被强制结束以及断电后的下一次更新调用；不以环境部分改变或仅保存错误收据作为终局。底层持续不可写、备份丢失或介质损坏时保留恢复责任和诊断，不误报回滚成功。更新期间不运行设备任务，不修改原配置或媒体。

## 状态与不变量

| 阶段与实际事实 | 必须执行的行为 |
| --- | --- |
| 校验或备份尚未完成，没有修改意图 | 失败时保持原部署；中断恢复不依赖不完整备份。 |
| Python、数据库及适用能力文件的备份和清单已可靠保存 | 可靠保存修改意图后才允许安装。原路径、元信息、旧版本及恢复所需解释器身份同时保存。 |
| 安装或迁移进行中 | 持有更新级锁及原数据库两把稳定锁，不向普通业务开放中间状态。 |
| 数据库需要升级 | 在独立副本上执行已登记迁移链，验证身份、绑定、历史与当前结构后发布；不让子进程争夺父进程持有的原库锁。 |
| 任一提交前阶段失败 | 先恢复原 Python 环境、原数据库及适用能力文件，核验后保存回滚结果；保留原错误与恢复错误。 |
| 上次进程中断，且没有可靠完成记录 | 不读取部分环境来决定原配置；沿持久恢复记录取得原锁，按实际文件与备份状态完成幂等恢复。 |
| 父更新进程已退出，更新子进程仍可能写入 | 更新资格继续覆盖这些写入者；确认它们结束后才可恢复或开始新更新。 |
| 更新结果及全部核验已可靠提交 | 该次更新完成；后续诊断收场不重开或回滚已完成更新。 |
| 回滚尚未核实或明确失败 | 保留未完成记录，拒绝开始新更新；后续入口继续恢复。 |

恢复记录先于所描述的副作用可靠保存。文件及目录同步、原子发布和 SQLite 一致备份沿用项目及标准库已有能力；未知结果按实际文件、清单和元信息核实。备份不与正在修改的文件共享可写内容，虚拟环境最终恢复到原绝对路径。恢复入口不依赖仍然完整的待恢复 Python 包；当恢复涉及环境目录重命名时，控制进程和后续入口必须仍能运行。

## 实施步骤

- [x] U1：更新权威规格与维护边界，明确迁移、回滚、中断恢复及完成点。
- [ ] U2：登记 V9 维护基线和后续迁移路径选择，接入数据库副本自动迁移及严格校验。
- [ ] U3：实现可靠备份、持久更新记录、立即回滚和下一次调用恢复，保持环境与数据库一致。
- [ ] U4：接通更新脚本、解释器引导、能力同步与发行物清单；同步部署 skill 和操作说明。
- [ ] U5：完成隔离单元与静态检查、独立评审及提交，记录未运行的真实组合范围。

U2—U4 的生产者、更新流程和恢复消费者由同一实现代理在独立工作树统一负责，根代理负责规格、集成与进度。评审代理只读复核迁移数据流、持锁边界、未知发布、备份消耗及中断恢复分区。

## 独立审查后的收束步骤

更新入口、备份、独立写入等待进程、副本发布及恢复已接通，尚须完成下列修正才能验收 U2—U4。修正由同一实现负责人顺序完成，不新增并行实现分支。

1. 集中定义恢复记录的状态和类型校验。`preparing` 只接受真正的布尔 `False`，`updating`、`committed` 只接受真正的 `True`；`rolled_back` 保留合法准备或修改后的终态。缺失字段、未知状态、非法类型和材料不齐时，保留原责任并拒绝继续。立即恢复重取锁后消费重新读取的有效记录。
2. 在修改前集中定义全部保留对象与更新器实际写入、搬移、删除的集合。保留对象包括配置、数据库、稳定锁、已绑定媒体与交接目录及其内容、适用能力文件和既有材料；写入集合覆盖控制目录、日志、记录及其临时文件、备份、探针、迁移副本、数据库辅助文件、环境恢复树和各文件的发布临时路径。所有入口使用同一冲突规则，核对规范路径与已有硬链接身份。没有明确归属的既有对象不能覆盖或清理；本次临时路径先保存创建意图和归属依据。恢复消费冻结记录并允许原环境暂时不存在，不能依靠当前参数重新选择恢复对象。完成最后一次文件发布后，再核验全部对象。
3. 部署维护边界统一检查 SQLite 完整性及实际外键关系，覆盖原库、迁移副本和发布后原库；未来迁移处理者保留转换语义验证责任。数据库及能力文件保存和比较 UID、GID、权限及所承诺的其他元信息，不能只比较内容摘要。
4. 提交写入异常后，持锁核实正式记录。属于本次且仍为 `updating` 时立即回滚；属于本次且为 `committed` 时补同步确认完成；无法读取、身份不符或仍无法同步时保留未知责任。原提交错误始终保留。修改意图和回滚完成记录沿相同的实际结果分类审计。
5. 外层取锁、恢复或环境检查失败时，必要收场后交付阶段、原错误及证据目录。stderr 写入或刷新失败分别保留，不能覆盖原错误或可靠完成结果。
6. 从实际更新及恢复入口补齐上述合法、失败及未知结果的隔离单元。先静态复核隔离，再运行；最后独立复核完整生产改动及实际验证证据。

记录分类、完整性与元信息、提交异常分类和外层交付已经接通。保留对象与副作用集合、事务专用临时路径及其创建前校验也已接通。剩余修正集中在两组状态，不重做已经闭合且未受影响的部分：

| 状态分区 | 收束要求 |
| --- | --- |
| 只读扫描环境、事务目录、旧控制材料或媒体内容以核对文件身份 | 符号链接目标明确不存在时，保留链接并继续扫描；不存在的目标没有可与已存在保护文件共享的 inode。目标存在则继续核对，其他读取错误仍拒绝；必需保留根对象不存在或不可读也仍拒绝。 |
| 临时目录或文件已经应用原 UID/GID | 按冻结的原元信息、事务记录和创建事实核实归属，不能把控制进程 UID 当作唯一依据。覆盖环境副本、数据库及能力文件临时对象。 |
| 临时对象已经发布或恢复再次中断 | 依据正式对象与本次记录继续，不要求未完成副本已经具有完整环境结构；未知类型和归属仍拒绝。 |
| 旧记录仍为 `preparing` 或 `updating` | 使用冻结的旧配置、绑定及客户端事实完成恢复。 |
| 旧记录为 `committed` 或 `rolled_back` | 只核实终态可靠性及实际访问的证据对象，不再要求旧配置、旧目录或旧客户端链接继续存在。新的更新按当前参数预检。 |

记录结构、证据对象及未完成恢复的实时布局分别校验；`main`、`read_pending` 和公共校验入口保持同一分类。先复核新增单元隔离，再运行受影响范围，最后独立复核这两组及其实际影响。

UID/GID 重入与终态交接已经通过源码复核。剩余修正仅统一上述只读扫描语义，覆盖旧准备阶段遗留断链、新能力文件发布后的检查及必要回滚，不删除旧材料。

仍遵守此前不新增、不运行集成测试的约束。仅用隔离单元验证公开入口的状态和故障分区；不得读取真实包资源、创建业务文件或数据库、运行安装、子进程、线程、设备及历史环境。真实 SQLite 迁移、目录恢复、跨文件系统发布、断电及发行物验证单独保留为未运行范围。不能由模拟故障推断真实恢复已经验收。
