# 拍摄结果保存与交付恢复修复

## 目标与验证范围

修复结果文件首次配对受无关历史提交干扰、恢复结果缺少业务处置导致拍摄无法收尾，以及发布意图保存后交付无法重新发现的问题。公共保存和恢复规则覆盖 Action6、OSMO 360 II 与 Hasselblad；设备特化继续判断各自的完成依据，普通文件交付使用同一恢复流程。

实现以当前开发结构为准。验证采用 Python 3.11 隔离单元测试与独立代码评审；跨组件组合、安装版及目标设备验收单独安排。本计划不修改集成测试。单元替身隔离数据库、文件、包资源、网络、线程与子进程；源码加载在真实资源导入前完成隔离。

## 必须保持的规则

- 实际调用结果、设备是否结束、结果集合是否完整、业务后续处置和调度占用分别判断；一次调用结束不能冒充整项工作完成。
- 已取得的页、文件、完成观察、原始错误、时刻和尝试次数保持。新增检查沿原流程的有限预算，已发出的拍摄 START 不因恢复重新执行。
- 首次业务申请的稳定身份在入队前形成；依赖当前数据库的判断在实际写事务内完成。保存未知沿原申请和操作键核实，取消等待者不撤销已经开始的保存。
- 新轮检查先于设备操作保存意图；原文件子责任须先完成适用交接。基准和结果范围不足时，不能直接释放占用。
- 准备完成及发布意图都不表示交付成功。取消后的 staging 副本不能再次发布；ready 和 processing 的处理遵守原目录所有权。
- 原错误由所属消费者交付一次诊断。保存重送复用诊断状态，必要停止与实际收场不等待日志。

## 结果恢复的状态与责任

恢复与正常返回共用调用结果拥有者。拥有者先保留原事实；所属消费者确定重试、结束、集合固定及完成观察后，以原保存责任共同提交。通用残留恢复不提前替代业务消费者选择处置。

| 当前事实 | 处理责任与允许结果 |
| --- | --- |
| 原调用仍有实际拥有者，或缺少适用恢复依据 | 等待原拥有者或保留恢复阻塞，不产生新设备检查。 |
| 原尝试未保存结果，可靠末页已经返回 | 持有末页实际结果、原时刻和页；交原消费者判断集合及后续处置。 |
| 原尝试未保存结果，只有部分页或没有可靠页 | 持有原恢复 UNKNOWN 及实际已有页；消费者沿原预算决定有限核实或适用收场。 |
| 原实际结果已经持有，业务处置尚未确定 | 各入口共用同一拥有者，不重复生成结果或保存申请，不授予新轮。 |
| 已确定的保存尚在执行或提交未知 | 先沿原完整申请及键完成交接，再推进业务。 |
| 原结果及重试责任已经共同保存 | 沿原等待、次数和资格继续，预算耗尽时形成明确有限结果。 |
| 原结果及无需重试的处置已经共同保存 | 重放已保存结果，完成剩余文件、集合或终态保存，不重发设备调用。 |
| 动作取消、已经终态或绑定失败 | 对应收场消费者接回原结果及页，保持原终态与错误优先级，不遗留没有消费者的调用责任。 |

独立范围核实、普通照片、普通录像、原生延时、单文件和多段结果均须检查上述入口。Hasselblad 的主机照片 START 继续其专属文件恢复，不转成重复拍摄。

取消中的发布意图由目标交付独立接手，不依赖取消发起者继续运行。副本仅在 staging 时共同保存取消及首次清理责任；ready 中的同一完整副本补存已交接事实后撤回，processing 中的副本保持主程序所有权并保存不可撤回结果；文件位置无法确认时保存未知及相应失败，不生成新交付。观察依据进入原事务证据，重送恢复原时刻、身份和文件集合。撤回明细只补建或更新仍有效的父取消责任，已经结束的父请求及其历史结果保持不变。

普通发布取得原文件资格后重新读取交付状态。观察期间取消生效时，新的移动和普通未知失败保存都在写事务中核对当前资格；既成的交接事实继续保存，尚未形成的普通结论交给目标取消责任。普通完成的新申请在取消生效后只读跳过，原键仍恢复原可靠结果。目标、交付和有效撤回等待者的发现按现有会话配置分批推进。

## 实施步骤

### 1. 固定责任边界

- [x] 核对当前代码、错误传播、消费者与测试隔离规则，明确三项缺陷及共同不变量。
- [x] 为配对、结果恢复、交付恢复分配独立工作区；主代理承担共享接口及最终整合责任。
- [x] 核对取消中的发布交付及终态结果拥有者，补齐对应实现决策后再修改依赖代码。

### 2. 首次配对在事务内固定依据

- [x] 先以隔离单元反例证明首次申请跨读写任务产生过期依据。
- [x] 外部申请只固定预览、完整扫描及发生时刻；实际写事务选择保存前完整历史边界并形成持久证据。
- [x] 原键核实从原事务还原固定边界并独立验证申请与事实；保留来源不可靠时的未知结果、独立守卫、取消交接与未知提交规则。
- [x] 审计公共分段配对及驱动照片配对边界，更新设备文件权威说明，执行必要隔离单元测试。

### 3. 统一结果恢复与业务处置

- [x] 先覆盖部分页、实际错误末页、扫描结束但集合未定，以及完整集合的恢复反例。
- [x] 正常返回、通用残留和专门结果入口共用结果拥有者；取消、绑定失败、已有终态和独立范围均有明确消费者。
- [x] 消费者一次确定原结果的重试或结束处置，保存共同影响的完成观察、范围及流程事实；不得预先保存不完整处置。
- [x] 检查 Action6 与 OSMO 普通／原生、Hasselblad 照片及公共单文件处理，保持原预算、文件和必要占用。
- [x] 更新操作结果与等待的权威说明，验证各入口、保存未知、取消和诊断去重。

### 4. 普通交付完整发现与取消收场

- [x] 以隔离单元反例验证已保存发布意图的交付会重新进入恢复器。
- [x] 发布候选与结束前剩余项检查共用包含 PREPARED、PUBLISHING 的资格；保留读取成功、来源汇总、排序和批量预算。
- [x] 审计取消后的发布责任，依据实际文件观察接回已经开始的移动；不重新投放 staging 副本，不生成新交付身份。
- [x] 覆盖 staging、ready、processing、三处皆无、内容不符、观察失败及取消／撤回／终态，保障三相机全部普通产物交付。

### 5. 整合与交付

- [x] 独立评审完整生产者、保存、恢复、消费者和停止／释放链，处理审查发现并复核。
- [x] 在统一源码上运行符合隔离边界的必要单元测试，记录红测、绿测、解释器、源码身份、命令和退出码。
- [x] 检查部署脚本及工作规则是否受影响，更新必要权威文档及阶段进度，完成差异检查与阶段提交。
- [x] 按三项缺陷和三设备入口汇报已验证范围，单独注明尚未执行的组合及目标设备验收。
