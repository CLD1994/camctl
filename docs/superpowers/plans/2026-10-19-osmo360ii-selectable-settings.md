# OSMO 360 II 可选参数与会话设置实施计划

> 执行方式：使用 `superpowers:executing-plans` 和 `superpowers:test-driven-development`，在 `/workspaces/camctl` 串行实施。

**目标：** 客户端只选择有实际选项的拍摄参数；普通录像与原生延时的码率随每个动作动态设置，固定的相机设置在会话首次拍摄准备时执行。

**设计依据：** [交接资料的调用时机](../../hardware/camera-control-handoff.md#相机设置命令的调用时机)、[码率命令与适用范围](../../hardware/camera-control-handoff.md#曝光码率与录像触发)及用户已确认的参数清单。动作参数固化和调用责任沿用[拍摄能力契约](../../architecture/camera-capabilities.md#驱动执行与产物边界)。

**实现方式：** 参数 Schema、命令和能力说明从 ADB 驱动的同源定义派生。驱动合同声明会话固定命令；运行实例按设备绑定和 ADB serial 保存本会话已可靠接受的命令，执行会话取得锁并打开状态库后清空记录。设置仍在原 START 尝试及有限期限内执行。

**技术栈：** Python 3.11、现有 JSON Schema、pytest；无新增运行依赖。

## 全局约束

- 新普通录像参数为 `type`、`duration_s`、`bitrate`、`exposure.mode`；延时另有 `interval_s`。
- `bitrate` 必填，允许值从两档命令映射取得；每个动作都发送对应命令，包括相邻档位相同的动作。
- ISO、快门、白平衡、EV、画面格式和视频输出按当前命令的固定事实在驱动中维护，不成为用户调整字段。
- 会话固定设置按需执行；启动、`describe`、文件读取及恢复 STOP 不主动设置相机。
- 固定命令只有取得可靠接受结果后才记为已执行；失败、未知、取消和期限耗尽继续阻止后续 START。
- 本次按当前 OSMO 参数格式实施；Action6 的参数和命令契约保持原有范围。
- 设备调用使用受约束替身验证，不执行真实拍摄或部署；文件大小估算继续保留独立的固定假定参考值及相应说明。

## 重点复核

- 同一驱动的两台设备分别执行固定设置，不共享完成标记。
- 同进程新会话再次设置；重复静态登记和能力导出不清空正在使用的会话记录。
- 部分固定设置成功后，后续失败保留实际已接受项；未知项不能进入跳过记录。
- 普通录像、延时及曝光模式交替时，码率仍每个动作发送，固定格式命令保持其原准备位置。
- 设置失败、取消及剩余期限不足时，实际 START 为零。

- [ ] 运行定点测试，确认当前 Schema 与命令不能满足上述要求。
- [ ] 调整当前 OSMO 参数及编码结构，延时视频输出由驱动固定；两种动作每次附加所选码率命令。能力说明分别表达固定请求、动态参数及估算参考。
