# 结果页操作与执行时间实施计划

**目标：** 结果页使用简洁操作名称，避免再次取回已有合格本地副本，并展示主机保存的计划及动作状态时间。

**执行方式：** 在当前 `implement_camctl` 分支持续实现。主机默认取回与报告时间在独立工作树按明确文件边界实现，客户端在当前分支实现；通过提交顺序集成。用户已授权同步补齐报告和前端。

**行为依据：** 用户对结果页的十一项标注；[结果浏览](../../client/result-browsing.md)、[取回](../../architecture/obtaining-outputs.md)、[报告字段](../../architecture/report-format.md)。

## 已确定契约

1. 计划操作为“取回计划产物”“清理计划产物”“取消计划”；动作操作为“取消动作”“取回默认产物”“清理全部产物”；批量为“取回所选产物”；产物主操作为“下载”或“取回”。这些操作继续加入草稿并由用户检查、导出。
2. 产物主操作位于媒体内容后的同一位置。有任一可靠本地副本时只显示下载，否则只显示取回。无法播放但文件已核验可读时仍可下载。文件核验中、核验失败或不可读时不能按已取回过滤。
3. 所选取回按 `output_id` 去掉已有合格本地副本，保留未收到、核验中、核验失败及不可读文件。点击取回时重新核对文件可读取性；选择全部已收到时提示无需重复取回，不生成空取回动作。多个来源按未收到的目标分别加入草稿。
4. 默认取回保持主机保存的默认范围、排除预览及修复成品优先规则。不得把客户端增量报告已有的产物集合当作完整默认集合；不得因过滤而改取其他文件。
5. 计划显示真实受理、结束时间，动作显示状态转换时间。计划创建、请求执行时间和客户端收到报告时间分别表达。新报告提供真实历史中的时间，旧报告字段缺失显示报告未提供，不推测。
6. 报告新增字段不得改变已经冻结的报告重建字节、摘要和身份；旧版字段及样例继续可读取。报告时间取冻结历史水位，不取生成报告时的当前状态。

## 状态分类

| 副本事实 | 单产物主操作 | 批量及默认取回 |
| --- | --- | --- |
| 任一副本已核验且可读取 | 下载 | 排除该 `output_id` |
| 只有核验中、等待报告或尚未接收副本 | 取回 | 保留该目标 |
| 只有核验失败或不可读副本 | 取回 | 保留该目标 |
| 已核验可读，但浏览器不能解码 | 下载 | 排除该 `output_id` |

## 实施步骤

### 任务 1：结果页操作入口

建议修改 `Records.tsx`、`ActionResult.tsx`、`MediaResults.tsx` 及相关浏览器测试。现有 HTTP、草稿追加、文件核验与报告导入组合用于验证。

- [x] 更新现有下载测试及按钮定位，添加同一产物取回/下载互斥和所选取回排除合格副本的反例，先观察失败。
- [x] 统一按钮名称与产物主操作位置；在共同选择边界过滤已收到产物，保留多来源和空选择语义。
- [x] 浏览器验证实际生成的草稿引用、目标 ID、空选择零写入、不可读及不能解码分支。

### 任务 2：默认取回过滤

普通手动默认取回支持可选 `params.exclude_output_ids`，非空、唯一的对象 ID 数组；不与显式 `output_ids`、`filter: preview` 或自动用途组合。客户端没有已收到的产物时省略字段。主机先按原规则确定选集及最终修复目标，再按最终 `output_id` 排除；列表内不存在、不属于来源或不在默认范围内的 ID 不扩大选择，也不形成目标错误。来源未终态继续等待，来源范围未知、确认空或来源错误保持原失败。正常目标全部排除且没有其他失败时成功，不生成交付。

排除列表只保存在原请求，不新增第二份权威清单或表。普通选择、分段选择、事务与独立历史守卫、选择前的取回/清理竞争判断、完成事务和重送恢复都消费同一原输入规则。客户端报告校验拒绝把已排除的目标报告为本次交付。建议修改公共 `plan.schema.json`、`outputs/definitions.py`、`sources.py`、`obtain_flow.py`、`competition.py`、持久化 `outputs.py` 和 `segment_selections.py`。具体内部接口可按实际数据流调整。

- [x] 完成输入、执行定义、普通与分段选择、持久化守卫及恢复的契约追踪，记录精确接口。
- [x] 对合法/非法排除、来源未完成、默认范围未知、修复替代、全部排除及恢复先写失败测试，再实现。
- [x] 将计划和动作按钮接入相同规则，验证新增请求经客户端和主机校验一致。

### 任务 3：报告与前端时间

计划和动作均新增可选 `status_history` 完整自身字段；每项为 `{status, changed_at, clock_status}`。`status` 使用所属实体公共枚举；`changed_at` 使用现有 UTC 秒格式，事件微秒向下取整到秒；`clock_status` 为 `unchecked`、`trusted` 或 `invalid`。数组按历史事件 ID 排列，不能按墙钟排序或要求时间单调。计划首项表示受理，首个 completed 表示结束；动作首项可以直接为 failed，计划首项可以直接 completed，不补造 pending 或 running。只收录创建及真正状态改变，内部处理和设备后续活动不产生假状态迁移。数组末项状态必须等于该冻结边界实体状态。

从扩展的 `entity_event_links` 状态目录读取创建至冻结 H 的完整转换，通过部分索引跳过内部事件。报告统一生成状态时间，查询装配遵守现有报告连接与短读事务，公共投影只接收事实。本地报告完成及发布管理写入使用注入的真实时钟。实现与验证进度见[状态目录集成计划](2026-10-26-state-directory-integration.md)。

- [x] 定义报告、状态迁移、冻结水位、受理即失败/完成以及旧报告重建的完整分类。
- [x] 先验证冻结历史投影及确定字节，再补公共 Schema、主机生成端、客户端类型、导入和页面展示。
- [x] 展示时间使用统一的本地时间格式，计划标题旁显示受理和结束，动作详情提供状态时间线，摘要显示当前状态对应时间。

## 重点核查

核验失败后正确补发、多次交付中的合格副本、来源报告晚到、分段默认范围、修复成品替代、全部排除、冻结旧报告重建和旧报告时间未知必须分别得到验证。任何新增时间或排除规则不改变设备操作完成依据、原动作终态、历史事实或媒体字节。
