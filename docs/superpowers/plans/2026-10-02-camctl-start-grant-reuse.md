# 启动授予的身份与原键响应

## 目标与依据

启动授予共同保存原动作、启动流程、设备活动、尝试意图、次数和采用配置，提交后才允许派发。同键查询只返回该次授予的完整票据。依据为[启动机会共同提交](../../camctl/database/waiting.md#设备活动启动保留与未完成责任)、[操作身份与参数](../../camctl/database/operation-fields.md#操作流程的身份与参数)、[事务完成规则](../../camctl/database/transactions.md#公共完成与失败契约)和[未完成消费者](2026-10-02-camctl-event-contracts-review.md#未完成的消费者与恢复边界)。内部函数划分是建议，不增加状态、协议或依赖。

## 输入与状态契约

输入为操作键、动作与设备身份、采用配置、事件事实时刻及窗口资格观察。动作 ID 是正 SQLite 整数，事件时刻是整数微秒，配置使用 `AttemptConfig`。原目标、流程责任、活动和配置不可混用。窗口及可信时间用于新授予与派发复核；原键查询不重新竞争或授予。原票据不包含窗口或当前时钟，本计划不替代固定窗口来源及完整 Q4 资格审查。

| 键与保存事实 | 处理 |
| --- | --- |
| 键不存在，输入合法，设备属于原动作 | 按当前资格授予或只读拒绝；只有实际保存的授予绑定键。 |
| 键存在，原完整组、目标、配置及事实时刻相同 | 核实保存事实，只读返回原授予、流程内尝试编号、操作类别、目标、责任键、流程及活动身份。 |
| 键属于其他入口、目标、配置或事实时刻 | 拒绝复用，数据库不变。 |
| 原组、原记录及关联不可解释或缺失 | 拒绝，不把新输入或当前可变配置作为原响应。 |
| 查询失败 | 保留实际 SQL 异常，取得的游标由读取者释放，整项回滚。 |
| 提交阶段失败，是否落库未知 | 返回 `UNKNOWN`；再次用原键核实。原组存在时只读恢复，不存在时仍按当前资格处理。 |

原组必须恰好一条 `ATTEMPT_STARTED.NEW`，恰好包含一个尝试创建、一个对应流程的创建或更新、一个对应活动的更新。普通 `BeginAttemptCommand` 的两行意图不能作为启动授予。不能只搜索组中的首条尝试或最后一行，不能忽略额外成员。

尝试物理 ID 来自 `row.id`，`AttemptTicket.attempt_id` 仍是流程内编号。尝试的 `run_id`、`attempt_no`、`copy_round`、`intent_event_id` 与可靠记录相符；启动不保存拷贝轮次，意图引用原事件。采用配置从原尝试创建事实取得，核对精确数值与空值。后来新尝试更新流程配置、次数或状态，不改变原配置与原票据。

流程的只读身份为原动作、`START`、`start/<action_id>`、原活动，其他目标、查询用途、交付及会话引用为空。活动物理 ID 与动作 ID 独立，按 `device_activities.action_id` 查找所属活动；票据目标、活动引用和共同保存的行 ID 使用该活动的实际 ID。设备从原动作保存的设备身份取得。原流程创建正文的只读字段须与可靠记录相同；更新正文可以省略未变化配置和状态。共同保存的累计次数等于原尝试编号，原前次数连续；出现的配置、状态与等待变化须符合原尝试及启动语义。原尝试记录保存的配置与原创建事实一致。新键进入已有流程时也先核对这些只读身份，不能把非法关联当作普通结束或预算拒绝。

原 H 的流程恢复只读取状态、累计次数、采用的三项配置及等待标志，复用[限定行恢复](2026-10-02-camctl-attempt-result-reuse.md#限定行恢复的边界)。H 与 C 为完整事务末边界，目录和主表末事件及次数可靠；原组发生的每项流程变化须与恢复值相符。这不是完整历史对象恢复。

| 后来状态 | 原键响应 |
| --- | --- |
| 原尝试结束、流程结束、活动收场或动作结束 | 保留原票据，不重新派发、不倒退状态。 |
| 可靠失败建立等待，后来新尝试采用不同配置 | 原键只接受原尝试配置，返回原编号；当前流程配置不参与替代原输入。 |
| 原创建正文或当前只读关联矛盾 | 拒绝，即使新输入恰好匹配被改写的一方。 |

G2、G3 尚未完成启动流程的状态组合校验。依据[录像启动流程](../../camctl/database/recording-start.md#流程状态与合法组合)，`PENDING` 的次数和等待标志必须同时为 0，`ACTIVE` 的次数必须大于 0。新键的已有流程判断和原键恢复出的原前状态都必须遵守该规则；后来流程结束不改变原键的票据。

下表描述登记新尝试之前的状态，也用于核对原授予历史中的前状态；窗口、设备、预算等独立资格仍按各自规则判断。

| 原流程状态 | 次数与等待标志 | 登记规则 |
| --- | --- | --- |
| 尚无流程 | 不适用 | 与首次尝试共同建立 `ACTIVE`，次数为 1，等待标志为 0。 |
| `PENDING` | 次数为 0，等待标志为 0 | 与首次尝试共同转为 `ACTIVE`，次数为 1，等待标志为 0。 |
| `PENDING` | 次数或等待标志不为 0 | 非法组合；拒绝，数据库不变。 |
| `ACTIVE` | 次数为 0 | 非法组合；拒绝，数据库不变。 |
| `ACTIVE` | 次数大于 0，等待标志为 1 | 其他资格满足时登记下一次尝试，次数连续增加，等待标志清零。 |
| `ACTIVE` | 次数大于 0，等待标志为 0 | 不登记新尝试，按既有重试等待责任规则处理。 |
| 已结束 | 按结束字段契约保存 | 不登记新尝试；不能作为原授予的前状态。 |
