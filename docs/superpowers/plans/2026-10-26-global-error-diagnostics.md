# 全局错误诊断接入

## 目标与契约

所有被业务契约认定的错误、会话异常及第三方 ERROR 都必须产生可关联的完整诊断。错误被处理、继续重试、可靠入库或会话最终成功，不免除诊断责任。规则权威来源为[运行日志](../../architecture/logging.md)和[日志执行](../../camctl/logging-runtime.md)。

日志文件可用时，自身异步 ERROR 等待入队，普通投递不等待写盘。第三方同步 ERROR 在队列满载时立即把完整记录交给 stderr，不阻塞事件循环；文件日志失效和初始化前错误亦使用 stderr。stderr 的长期保存由调用方负责，不能把终端输出当作已经保存的文件。日志通道故障不改变业务结果，不递归投递。

同一原结果持有一次诊断状态，提交核实、重复等待及取消复用该状态；新的实际失败产生新诊断。异常和结果保留原类型、完整异常图、实际阶段、已知设备调用和所属业务身份。正常取消及不存在等控制分支维持原语义，其间真实发生的关闭或清理错误仍须记录。公共错误码继续从原登记读取。

必要设备停止、数据库结果交付和文件占用释放不得等待日志空位。在原业务结果形成时绑定不可变诊断，由每个命令唯一的受管诊断任务持续异步投递。业务流程只移交原诊断，不等待空位；致命错误先交给原会话错误处理。命令在必要停止、原结果的有限诊断回执及资源收场完成后，等待诊断交接再关闭日志。诊断不通过查询历史数据库补造，不为每条记录另建后台任务。

## 实施接口建议

公共模块建议为 `logging_runtime.diagnostics`：`DiagnosticState` 随原待保存对象持有；`record_error(error, *, stage, context=None, state=None, details=None)` 记录一个实际错误；`record_call_outcome(outcome, *, ticket=None, run_error=None, context=None, state=None)` 记录调用结果及伴随流程错误。两个入口同步准备诊断，不等待队列，仅由业务协程调用。

命令装配通过 `error_diagnostics_context(channel, fallback, background=True)` 提供当前命令的日志目标。`diagnostic_scope()` 包围既有流程任务，退出时移交尚未接纳的原诊断，并直接继续业务或传播原错误。`flush_diagnostics()` 在必要业务收场后、日志消费者关闭前停止并等待本命令唯一的诊断任务。作用域只持有现有未交接诊断；已结束结果不累积到全局去重集合。

报告副本复用原诊断时，在服务任务创建前用 `reserve_diagnostic` 同步转移原状态，实际子任务在自己的作用域 `adopt_diagnostic`；只有取得追加成功回执后确认原记录交接。尚未采用的预留责任在最终 flush 恢复。日志接纳在取消后附带实际接纳结果，建议由 `admission_result_for(error)` 取得；记录实际已入队时不得重投。具体内部类型和文件分工允许按真实数据流调整。

## 错误处理边界与验收

| 边界 | 必须接入的生产路径 | 可观察验收 |
| --- | --- | --- |
| 日志接纳与退出 | 自身异步、第三方同步、通道禁用、正常关闭 | 满载等待与 stderr 降级、取消竞争、多个等待者及有序关闭 |
| 读取与取回 | 设备及主机源、自动预览、内部读取、取回选择和发布 | 完整异常、可读 stderr 与原字节、原结果重送不重复，文件占用先释放 |
| 拍摄与媒体 | 设置、START、STOP、查询、结果核实、绑定失败、检查及修复 | 组合保存入口及非尝试结果均有诊断，必要停止继续推进 |
| 清理与电机 | DELETE、存在性查询、逐项业务拒绝、通知发送 | 业务失败即使可靠入库仍有日志，保留实际副作用与结果 |
| 报告与维护 | 生成、文件交接、失败恢复、快照维护停用 | 报告及维护错误有诊断，保留各自会话影响分类 |
| 命令与异常 | 早期调用及配置错误、init/describe、后台与资源收场 | 完整 stderr 或文件日志，异常链和已知次级错误不丢失 |
