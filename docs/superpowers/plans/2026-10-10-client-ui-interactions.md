# 客户端界面交互修复实施计划

**目标：** 修复后续操作弹窗、计划页签、草稿校验定位、文件选择焦点、窄屏编辑工具栏及辅助文字可读性。

**实施方式：** 当前工作区内按任务执行；独立文件由明确指派的子 Agent 并行修改，最终由主 Agent 核验完整改动和浏览器结果。交互改变先增加失败测试，再实现并验证。完成本计划不包含提交或推送。

**技术基础：** 客户端使用 React、TypeScript 和已安装的 Base UI。优先复用现有组件库，不自行实现弹窗的焦点捕获。公共协议与持久化规则分别遵守根 `protocol`、[草稿保存规则](../../client/storage-and-recovery.md)和[追加接纳规则](../../architecture/client-editing.md)。

**规格依据：** [页面反馈与长列表](../../client/page-interactions.md)、[计划编辑与交接](../../client/plans.md)，以及下列从本次评审修复要求形成的交互契约。业务状态规则已经确定；文件拆分和内部接口是实施建议，可按实际数据流调整。

## 必须保持的行为契约

- 界面导航、聚焦、展开动作或切换 JSON 显示不能修改草稿正文、未完成输入、动作身份、自动预览意图或追加操作记录。
- 保存、导出、删除及追加结果的成功、失败和未知状态沿用原有判定；关闭弹窗不表示撤销已经发出的操作，未知结果继续按同一操作核实。
- 每个校验错误继续保留原始 `path`、`code` 和 `message` 作为技术诊断。主要提示使用中文说明问题及修正对象；字段名、错误码等机器标识不改写。
- 修正一个输入后，校验和字段提示从当前草稿重新计算；不缓存旧动作索引，也不把未知路径映射到同名但无关的字段。
- 文件选择继续使用原生文件输入。仅获得焦点或取消文件选择不上传文件。

## 状态分类及可观察结果

| 对象与条件 | 用户操作 | 结果 |
| --- | --- | --- |
| 后续操作弹窗打开，当前没有提交正在进行 | Tab 或 Shift+Tab | 焦点在弹窗内循环，背景控件不能取得焦点 |
| 后续操作弹窗打开，当前没有提交正在进行 | Escape 或关闭按钮 | 弹窗关闭，焦点回到本次入口；入口已不存在时回到计划页的可用入口 |
| 后续操作正在提交或核实 | Escape、背景点击或重复提交 | 保持弹窗和原有操作状态，不产生第二次操作 |
| 后续操作得到失败或未知结果 | 查看提示或关闭后重新进入 | 原输入及核实入口保留，不将关闭解释为成功或撤销 |
| 计划页签获得焦点 | 左右方向键、Home、End | 按页签顺序移动并激活目标页签，活动项是唯一页签 Tab 停靠点 |
| 计划页签切换 | 查看对应内容 | 页签与面板通过 ID 关联；已有草稿会话及请求身份按原规则保留 |
| 校验指向公开字段或已显示的参数字段 | 点击错误 | 展开所属动作及必要的详情，聚焦准确控件；字段提供 `aria-invalid` 及关联的错误说明 |
| 校验指向未完成数值或 JSON 输入 | 点击错误 | 聚焦该路径的“未完成输入”控件，保留原文本；不能跳到旧合法值 |
| 未完成输入路径为空或无法解释为标准路径 | 点击错误或打开草稿 | 使用原始键关联独立的未完成输入控件，保留原键和文本；渲染不解析路径，根未完成输入不与整份 JSON 混淆 |
| 校验指向 JSON 控件中的子路径 | 点击错误 | 聚焦负责该对象的 JSON 控件，不猜测为另一个表单字段 |
| 非未完成输入校验指向没有表单控件的路径、非对象动作、根 JSON 错误或无法无歧义解析的路径 | 点击错误 | 展示并聚焦独立的整份计划 JSON 控件，显示完整技术路径，保留正文及编辑资料 |
| 动作折叠、存在多个动作、动作被删除或重排 | 点击当前错误 | 基于当前校验和稳定动作显示身份定位，不能打开或聚焦另一动作 |
| 输入通过校验 | 查看摘要和字段 | 清除对应错误关联，显示当前输入检查通过 |

校验定位接受现有点号/数组路径和 JSON Pointer 路径。参数属性包含特殊字符时，只有能与真实控件路径精确对应才定位字段；无法证明对应关系时使用整份 JSON。Schema 的分支错误及未知关键词使用准确但不过度推断的中文提示，原始诊断放在可展开的技术详情中。

- [x] 纯模型测试使用手写期望值，验证点号路径、Pointer 转义、多个动作、已命名动作、未知路径及 Schema 关键词呈现；精确断言机器路径，不逐字固定可翻译文案。
- [x] 浏览器失败测试覆盖：新草稿无动作的中文摘要；折叠录像的必填执行时间；相机参数枚举或数值；内置动作引用和报告范围；未完成数字与 JSON；未知字段和非对象动作回退 JSON。逐例断言聚焦对象、关联提示及正文和 `pending` 不变。
- [x] 验证当前失败后，统一建立字段路径与错误的责任边界。公共字段、Schema 字段、内置参数及未完成输入使用同一关联规则。
- [x] 校验摘要放在主要编辑区域之前，提供可操作的定位入口，技术诊断通过详情展开；普通文本不能遗漏问题对象。
- [x] 点击错误后先改变显示状态，再聚焦真实控件。已关闭的详情可以展开；没有准确控件时聚焦 JSON。定位过程不得调用修改/保存函数。

## 验证记录

2026-10-10，Windows，Node.js 24.16.0，客户端浏览器验证使用独立临时数据目录，不连接真实设备。完整结果同时记录在[客户端验证范围](../../client/verification.md#2026-10-10-界面交互验证)。

- 初始校验浏览器测试 9 项均失败，准确复现中文摘要及定位入口缺失。路径呈现单元测试 14 项通过，包含 Pointer 转义及有歧义的属性名。
- 弹窗及页签测试初始复现焦点、Escape 和方向键缺口，实现后 5 项通过；包括两种入口、挂起提交、未知追加恢复、入口卸载后的焦点和选择列表的 Escape 顺序。
- 文件焦点测试准确复现透明输入外层没有轮廓；实现后焦点及空文件选择 2 项通过。空选择通过原生文件输入的鼠标入口打开选择器；键盘焦点单独验证。并行运行时 Enter 打开选择器曾没有事件，具体机制未确认，不据此补造产品缺陷。
