# 会话取消后的普通派发边界

## 契约与范围

父协程取消与业务取消不同。会话收到父取消后停止新增普通工作，完成已取得资格的必要操作及本地责任，交付原结果并传播首次控制异常。沿用[取消收场契约](../../architecture/clock-recovery.md#时钟异常期间的报告)与会话已有错误优先级，不修改动作状态、设备停止策略或事务执行方式。

必要接纳事务由独立任务执行。等待者取消不撤销事务，必须接回真实结果，并保留已经取得的接纳句柄。以下两个恢复普通工作的出口同时适用：

| 必要阶段结果 | 无父取消 | 已观察父取消 |
| --- | --- | --- |
| 接纳成功 | 启动正常维护与流程 | 不启动快照或普通流程，进入已有收场 |
| 接纳失败或结果未知 | 按原错误退出 | 保留实际错误和收场，按原规则传播控制异常 |
| 原子关闭发现新工作 | 保留接纳并继续等待、驱动 | 不继续普通等待或下一轮派发，进入已有收场 |
| 原子关闭已完成或失败 | 交付实际结果 | 保留实际结果，按原规则收场及传播控制异常 |
