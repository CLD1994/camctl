# 关键阶段与命令日志实施

行为以[日志规格](../specs/2026-10-26-operational-logging.md)和[全局错误诊断责任](../../architecture/logging.md#全局错误诊断责任)为准。下列内部文件和接口组织是实施建议，可根据实际拥有者调整；级别、事实边界、取消收场、身份及验证要求必须保持。

1. [x] 建立公共 JSON 元数据及非阻塞事件入口；保留原 ERROR 所有权，性能明细使用 DEBUG，普通及第三方记录采用相同外层格式。
2. [x] 在受管工具实际启动和返回处记录 INFO，沿驱动、文件、媒体和恢复上下文提供可靠身份，保留逻辑命令与实际 argv。
3. [x] 接入拍摄、会话、受理、取回、交付、清理、取消、电机、报告、恢复和后台文件／快照的实际阶段；空轮询与原申请重送不重复记录阶段变化。
4. [x] 完成定向单元与真实日志／工具组合验证，独立审查完整变更，按已授权流程更新验证安装并保留配置和业务数据。

## 阶段门禁

先核对统一格式、上下文及事件接口，再并行接入互不修改同一文件的组件。每个阶段都核对正常返回、实际失败、取消及没有执行的分支。集成前提交可独立审查的改动；最终验证来源身份、命令、退出码和日志分别保存，不将窄范围通过写成完整回归或设备通过。

## 进度

公共事件入口、工具边界及业务阶段均已接入生产调用方。性能计时使用 `DEBUG` 和 `event=timing`；事件上下文覆盖并发任务及真实文件线程的身份隔离，普通文本在实际输出时采用相同 JSON 元数据，原 ERROR 文档保持结构。第三方日志的降级同时保留公共格式、原异常图及格式化失败事实。

各域已分别完成定向单元和真实组合验证；最终合并状态全量单元 9565 项通过、1 项跳过，195 项定向集成通过。原日志文本断言已改为 JSON 事实断言，轮换测试按实际记录大小保留多进程近期记录，并继续检查备份确实产生。

步骤 3 的一次性命令入口已补齐：`init`、`describe` 沿原 stderr 契约接入实际阶段，不使用会话装配，相关组合及控制异常反例通过。结果扫描缓存关闭失败按实际异常记录，后续真实关闭重试单独记录。独立审查及安装交付均已完成，335 份包内 Python 文件和 27 项资源一致，5912 个受保护文件前后相同。完整范围、来源、基线失配及安装证据见[验证记录](../../camctl/operational-logging-validation-2026-10-26.md)；未进行新的相机拍摄。

扩展检查保留两类现有测试失配的原始失败：一项 ADB 元数据测试仍期待旧帧版本，已在实现前基线独立复现；旧拍摄集成夹具仍向 `CaptureRuntime` 传入 `owned`，在日志路径执行前拒绝装配。当前公开数据库装配的拍摄组合已另行验证。这些旧测试不计入通过结果，也不改变本计划的软件与真机验收边界。

一次性命令的扩大检查还保留 3 项基线失败：两个初始化夹具向 `accept_input` 交付旧连接类型，一个报告配置故障用例的设备流程预期不符；已在不含本次 CLI 改动的独立基线复现，不计入通过结果。
