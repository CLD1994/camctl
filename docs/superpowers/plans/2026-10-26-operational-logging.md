# 关键阶段与命令日志实施

行为以[日志规格](../specs/2026-10-26-operational-logging.md)和[全局错误诊断责任](../../architecture/logging.md#全局错误诊断责任)为准。下列内部文件和接口组织是实施建议，可根据实际拥有者调整；级别、事实边界、取消收场、身份及验证要求必须保持。

1. [ ] 建立公共 JSON 元数据及非阻塞事件入口；保留原 ERROR 所有权，性能明细使用 DEBUG，普通及第三方记录采用相同外层格式。
2. [ ] 在受管工具实际启动和返回处记录 INFO，沿驱动、文件、媒体和恢复上下文提供可靠身份，保留逻辑命令与实际 argv。
3. [ ] 接入拍摄、会话、受理、取回、交付、清理、取消、电机、报告、恢复和后台文件／快照的实际阶段；空轮询与原申请重送不重复记录阶段变化。
4. [ ] 完成定向单元与真实日志／工具组合验证，独立审查完整变更，按已授权流程更新验证安装并保留配置和业务数据。

## 阶段门禁

先核对统一格式、上下文及事件接口，再并行接入互不修改同一文件的组件。每个阶段都核对正常返回、实际失败、取消及没有执行的分支。集成前提交可独立审查的改动；最终验证来源身份、命令、退出码和日志分别保存，不将窄范围通过写成完整回归或设备通过。

## 进度

纯性能计时的 DEBUG 修改已经通过原有 28 项定向单元；关键阶段、命令及统一 JSON 仍待上述步骤完成。
