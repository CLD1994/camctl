# camctl 客户端 MVP 实施计划

> 执行者：使用 Superpowers 的子任务实施流程逐项实现并评审。业务规格与根目录 AGENTS.md 优先于本计划的实现建议。

## 目标与依据

实现可在 Windows 本机启动的 React / TypeScript 网页与 Node.js 后端，贯通客户端六组 MVP 验收。业务依据为 [客户端规格](../specs/camctl-client/README.md)、其六个专题及引用的公共协议。用户已确认技术方向；容器部署与容器验证由用户亲自执行。

## 全局约束

- 单台主机、一个逻辑客户端；所有持久化资料位于同一 `data/`。
- 日常启动不创建或重建数据库；显式初始化重新检查目录及数据库。
- 固定原请求与人工标记独立；导出检查此次最新输入；不完整输入允许保存草稿。
- 公共报告 Schema 为报告结构唯一来源；参数 Schema 使用 Ajv，禁用类型转换、自动默认值和字段删除。
- 报告原文件名和字节、成功身份、实体投影和覆盖进度在同一次事务提交。
- 已保存视频由后台继续核验；只有完整可读取、有效映射且核验成功的文件可播放下载。
- 单元测试隔离真实外部边界；真实 SQLite、文件、HTTP 和浏览器测试归集成测试。
- 在 Windows 本地验证；交付 Dockerfile 与 Compose，容器结果不得声称已经验证。

## 实现设计（内部结构为建议）

### 责任与接口

`src/shared/` 提供严格 JSON、能力说明和计划校验、编辑类型；`src/domain/reports.ts` 提供报告验证、覆盖判定与实体合并。`src/server/` 负责 SQLite、文件工作队列、HTTP；`src/web/` 负责 React 界面。测试按 `tests/unit/`、`tests/integration/` 分开。

关键共享接口：`parseJson(text): unknown`；`loadCapabilities(value): Capabilities`；`validatePlan(plan, capabilities, context?): Issue[]`；`validateParams(deviceId, actionType, params, capabilities): Issue[]`。`Issue` 包含 `path`、`code`、`message`。报告接口在任务 1 的交接报告明确导出签名，后端依照实际类型接入，不能另写一份协议清单。

后端使用 Node 24 的 SQLite 接口。SQLite 表分别保存元信息、草稿、原请求、预设、报告原文、合并快照、导入批次与文件、视频副本。可变草稿附保存版本号：提交携带预期版本，不匹配时明确冲突；首次导出以草稿 ID 唯一关联原请求，重试先核实是否已经导出。JSON 编辑文本和未完成控件字符串属于草稿内容。

报告原文以 BLOB 保存，避免报告接收跨数据库与文件的双重提交。报告批次先确定清单；各报告上传完整或明确失败后才处理，视频独立上传。每份报告提交后再按当前覆盖选择下一份，不按 ID 或上传次序决定。

视频先以独立内部 ID 写临时文件；完整写入并刷新后登记完整文件，持久化路径不取用户文件名。核验计算大小与摘要，结合已应用映射决定等待、成功、不符或无法读取。替换时新副本先完整保存且核验通过，数据库事务切换当前副本指针；旧文件在确认不再被引用后整理，诊断保留。重启只恢复完整登记视频，未提交报告不自动应用。

### 关键状态与提交边界

| 输入/条件 | 结果与不变量 |
| --- | --- |
| 无库且目录只有能力说明或为空 | 提供显式初始化；普通读取不建库 |
| 已有有效完整库 | 使用原数据 |
| 无库但有业务文件、半成品库、损坏或访问未知 | 数据故障；禁止替代空库 |
| 保存草稿版本相符 | 保存原始编辑内容并递增版本 |
| 版本不符、写入失败、提交未知 | 明确冲突或故障，页面保留输入；查询核实 |
| 草稿首次导出全部校验成功 | 同事务固定请求与只读结果，失败不部分转移 |
| 同一草稿导出已成功 | 返回原身份与正文；ACK 独立选择 |
| 报告非法/身份冲突 | 仅诊断，不推进覆盖或业务 |
| 报告重复 | 复用原接收及原文字节 |
| 新有效报告 T<=C | 保存原文和接收，不覆盖新状态 |
| 新有效报告 F<=C<T | 语义与关联检查后同事务合并至 T |
| 全批已检查，剩余 C<F<=T | 保存缺口诊断及目标 T，抛弃业务内容 |
| 视频未完整上传 | 中断或上传中，重新选择从头上传 |
| 视频完整无映射 | 保留等待；报告到达后继续 |
| 大小摘要匹配，文件可读 | 可靠保存核验，再开放播放和原文件下载 |
| 同名同内容 | 复用；不改变原有事实 |
| 同名不同内容且新正确、旧已证明错误 | 原子切换副本关联 |
| 同名不同且无映射、新错误或结果不明 | 保留旧副本，记录实际原因 |

## 端到端闭合检查

| 横切事项 | 权威输入→提交→失败与恢复→可观察结果 |
| --- | --- |
| 当前编辑 | 控件/JSON→版本保存→失败保留页面输入→重开恢复对应版本 |
| 请求身份 | 最新草稿→唯一原请求事务→丢响应查已有导出→重复下载同身份 |
| 能力切换 | 固定文件完整加载→进程快照切换→失败保留旧有效快照→网页更新后校验 |
| 报告覆盖 | 原字节与范围→语义检查及同事务提交→整批重导→C、缺口与ACK一致 |
| 视频关联 | 完整保存记录+已应用映射→摘要及指针提交→重启核实→仅合格副本开放 |
| 备份 | 停机完整目录→复制→不混合恢复→原身份、报告与文件共同恢复 |

具体模块签名与划分可在实现中依据实际数据流调整；不改变业务语义。测试通过不能代替覆盖审计，尚未核验的条件须记录。
