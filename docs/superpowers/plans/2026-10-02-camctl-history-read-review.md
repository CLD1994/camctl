# 冻结历史读取的实施审查

## 目标与依据

报告从同一完整 H 选择实体并恢复状态。读取方先取得独立数据、释放游标及短读事务，调用方才恢复或编码。依据为[历史状态查询](../../camctl/historical-state-query.md)、[历史格式](../../camctl/database/history-formats.md)、[分页契约](../../camctl/module-contracts.md#分页结果契约)及[历史模块计划](2026-09-30-camctl-history.md)。文件划分及内部签名均是实施建议，不固定完整 H4 的实现组织。

## 已定位的责任边界

1. `HistoryRepository.read_events` 只把 H 的事件位置绑定到 SQL，没有核实事务身份、完整边界或事件分组。输入为事务中间位置、未来边界或与事务不符的位置时，仍可能返回部分历史或空结束页。读取方须在同一短读事务中核验实际边界和本页涉及的完整事务分组；全局事件页还须核对连续位置，不能把必要事件缺失当作结束。
2. 读取范围的类型及继续位置未完整校验，上界通过 `min` 截断。错误范围必须明确拒绝，不能按 SQLite 的隐式类型转换读取另一范围；正反向读取均遵守同一上下界和严格续读。
3. 历史正文直接构造 `RowChange`，省略 `evidence` 被当作 `{}`，未知版本和分支未拒绝。格式 1 的结构及行权限须由同一生产规则解释。缺少必要成员、非法身份、存在性或恢复值须按状态库错误返回；创建前不存在时允许省略空 `values`，不能把存在行缺少值也解释为空。
4. `entity_facts` 忽略对象类型与身份，读取七张表的全库当前投影；没有明确的 H、读取边界 C 或独立对象范围。现有受理测试也使用这个入口。完整对象读取须替换该入口，逐项迁移已知消费者，而不能只修改报告调用。
5. 完整 H4 被勾选，但生产代码没有 `read_entities`、投影与 C 的联合读取或固定 H 的对象恢复组合。当前测试只证明事件读取及业务区间查询；进度须按实际交付分项记录。

标准库 sqlite3 提供显式读事务、范围查询和游标关闭；已有精确 JSON 解析器提供无歧义解析，已有事件登记及校验器提供版本、分支和行权限。实现复用这些能力，只补查询范围、存储事实校验及资源所有权，不引入依赖或维护第二套事件清单。

## 事件读取的行为分类

此阶段先闭合现有全局事件分页入口，不把它当作按对象索引读取或完整历史恢复。整数位置是该入口的底层范围参数；后续对象请求还须绑定数据库身份、H、对象及恢复方向。

| 输入或已读事实 | 输出及失败语义 |
| --- | --- |
| 范围下界、显式上界及继续位置 | 必须是 0～2^63-1 的整数，拒绝 bool、float、字符串；批量上限是严格正整数 |
| 首次读取 | 无继续位置；从所属方向的范围端点读取，事件位置从 1 开始 |
| 继续读取 | 位置在固定范围内；升序越过该位置，降序读到该位置之前；不能读取范围外事件 |
| 显式上界超过 H | 范围错误，不能截断后继续 |
| 类型合法但下界大于上界 | 在 H 可靠时返回空结束页；不跳过 H 的核验 |
| H 为初始化边界 `(0, 0)` | 历史范围为空；当前库可以已有较新提交，不能把它们加入本页 |
| H 为已提交完整边界 | 事务身份与末事件位置一致；相关分组首尾、事件数量、成员归属及相邻事务位置符合连续历史规则 |
| H 不存在、位于事务中间、分组矛盾或本页必要事件缺失 | `ConsistencyError`；不返回空页、截断页或部分成功 |
| 页跨事务或同一事务跨页 | 页内事件按指定方向排列；每个涉及的完整分组有效；分页位置可以位于事务中间，固定 H 仍为完整边界 |
| 不可变事务的核验复用 | 仓储绑定实际 `instance_id`，每次核对事务首尾及前一边界；至多保留 H 事务和上一页末事务的核验结果。逐页仍检查位置、成员归属和正文，结束或异常释放核验结果 |
| 正文合法，版本、分支及行结构可解释 | 返回新构造的精确事件数据，JSON 数字不经 float；不执行业务守卫、设备或文件副作用 |
| 正文缺项、未知版本或分支、行结构非法 | `ConsistencyError`，保留实际事件身份及原因 |
| SQLite 查询或事务结束失败 | 保留实际数据库异常；释放连接及游标，不解释为结束 |
| 返回页面 | 相关游标与读事务已经结束，数据由调用方独立持有；批间新提交不改变固定范围 |

全局事件位置连续，筛选到某个对象的关联事件可以不连续；连续性检查不得移用于后续按对象索引查询。正反向页以最后一个实际返回事件生成继续位置。恰好读到范围端点时交付最后一页数据并标记结束。

首次完整事务核验需要扫描该事务的全部事件。复用依据是已提交历史不可变；不承诺检测核验后历史被外部重写或删除，逐页成本也不能仅按 `batch_limit` 描述。仓储生命周期内数据库实例身份不能变化。

## 实施步骤及门禁

- [x] Q1：对现有入口增加反例，分别证明虚假 H、中间边界、丢失事件、范围类型和越界、缺少正文依据及未知版本不能返回成功页。确认失败来自缺失规则，而非测试准备错误。
- [x] Q2：复用事件的版本、分支及行权限校验；保存入口继续执行自身业务守卫，读取只解释已存事实。新增无文件访问的单元测试验证解码类型、存在性及精确数字；真实受理事件通过组合验证。完整事件结构余项单独跟踪。
- [x] Q3：在显式短读事务中校验 H 和本页事务分组，严格校验范围、校验全局连续事件位置，返回前关闭游标和连接。分别验证初始化、空范围、末页、正反向、跨事务及批间新提交。
- [x] Q4：验证失败路径实际释放资源，真实 SQLite 和 P3 保存与读取组合通过；执行两版 Python 的单元与相关组件集成门禁，并执行 Python 3.12 的全量组件回归，按名称记录既有失败。
- [x] Q5：独立复核实际改动和证据；更新 H4、路线图及本计划的分项状态，提交事件读取修复。完整对象恢复未完成时，完整 H4 保持未完成。

预计文件为 `history/decoding.py`、`history/validators.py`、`persistence/repositories/history.py`；测试为单元历史解码与组件历史查询。预计接口为 `decode_event_row(row) -> EventEnvelope` 及共用的 `validate_event_structure(event)`。完整结构校验与具名业务守卫分别承担自己的责任，不因读取复用而跳过保存入口的守卫。

## 对象读取及生成的后续顺序

- [ ] 从真实冻结记录建立绑定数据库身份、H、业务区间及对象种类的选择请求；实现 4096 条关联候选预查询与大范围 ID 续读，两个路径在交付前确定，范围不随 ACK 或新提交改变。
- [ ] 读取限定对象的自身记录、必要成员及计数，并在同一短事务取得 C；不读取全库、兄弟实体或完整依赖树。迁移 `test_fields.py`、`test_definitions.py` 中五类 `entity_facts` 调用。
- [ ] 沿对象历史目录分批取得固定 `(H, C]` 或 `(S, H]` 的相关事件，结合可靠计数选择路径；核对 H 时的存在性、完整自身成员及父子关系。审计 `apply_forward`、`apply_reverse` 和 `restore` 的缺失字段、计数及末事件语义。
- [ ] 独立文件及交付依赖恢复到同一 H；取回完整失败列表的读取范围与报告入选范围分别处理，零有效候选页仍能继续。
- [ ] 把固定 H 的对象分页接入报告逐层编码，真实工作进程不传完整正文；按 R3—R5 验证后续提交、不同批量、恢复方向和重新生成均不改变字节。

以上后续步骤涉及的内部类型须在读取实际调用链后具体定义；不能以当前全局事件页或无后续写入的小型数据库组合替代完整固定 H 恢复验收。

## 事件结构余项的实施顺序

独立复核已确认以下既有问题。保存入口与新增读取入口共用 `validate_event_structure`，后续须在共同边界完成规则，并审计 `acceptance`、`reporting`、`session`、`operations`、`outputs` 的事件生产者及历史恢复消费者。此清单不代表 H1 或完整 H4 已经覆盖这些条件。

- [ ] 先补更新反例，再实现精确变化校验。前后列集合必须相同且非空，只能包含允许列；`required` 必须出现且实际变化；整行没有变化时拒绝。比较复用 `json_equal`，区分布尔和数字。共用结构校验与构造器已有实现及反例，生产者、复用消费者和完整门禁仍按[事件审查](2026-10-02-camctl-event-contracts-review.md)闭合；不得以补入未变化列代替真实变化。
- [x] 先构造首个状态列合法、后一个非法的反例，并交换列次序，再修复 `_check_transitions` 的提前返回。每个改变的状态列均须满足登记转换，不能由另一个列的合法转换代替；公开保存、存储解码及实际登记组合均已验证，见[事件审查的验证记录](2026-10-02-camctl-event-contracts-review.md#验证记录)。
- [ ] 先核对登记中 `branch.evidence` 的必填语义和 `observation` 的具体结构，再建立证据决策表及失败测试。公共成员的允许名称、正整数 `attempt_id`、32 位十六进制 `input_key` 及基准成员按既定格式校验；基准分支成员从登记读取，不维护第二套分支清单。读取仅校验存储结构，不重新执行业务守卫或决策。
- [ ] 逐项验证保存入口、已存事实解码及真实 P3 写入和读取组合。违反契约的生产者应按真实变化形成事件，不能删除测试、放宽规格或把无法解释的事实跳过。独立复核每个反例及相关入口后再勾选上述项目。

| 更新行的条件 | 结果 |
| --- | --- |
| 前后列集合不同、含未允许列或集合为空 | 拒绝 |
| 必要列缺失或前后精确值相等 | 拒绝 |
| 整行没有实际变化 | 拒绝 |
| 非空允许子集、必要变化齐全且其余约束满足 | 接受 |

## 验证记录

事件解码的第一组反例有 40 项目标失败，历史查询的第一组反例有 16 项目标失败。独立复核后的补充反例验证局部更新、更新前枚举、必要列省略、降序下界 0、同一事务跨页的重复扫描及数据库实例切换。

Python 3.12 与 3.11 分别执行 `pytest -q apps/camctl/tests/unit -k 'not test_accepted_record_delivers_receipt'`，各有 1248 项通过、1 项排除及 2 条警告。被排除的日志凭据等待问题及同步测试误标异步的警告见[发布事实审查](2026-10-02-camctl-report-publication-review.md#验证证据)，没有删除测试或放宽配置。

Python 3.12 与 3.11 分别执行 `pytest -q apps/camctl/tests/integration/contracts apps/camctl/tests/integration/history apps/camctl/tests/integration/reporting apps/camctl/tests/integration/logging_runtime/test_handler.py::TestTwoProcesses::test_two_processes_share_file`，各有 260 项通过，保留多进程日志测试误标异步的既有警告。命令中的 `PYTHONPATH` 使用源码与测试目录的绝对路径，保证子进程改变工作目录后仍能导入包。

上述相关门禁包含 38 项真实历史查询测试，覆盖正常结束、空范围、实际新提交、事务分组、缓存复用、实例和事务元数据变化，以及开始、查询、解码和提交失败时的资源释放。独立复核另运行 46 项解码单元测试，并以接口替身核实每页顺序、两个事务范围的缓存容量及异常原样保留。文档链接检查和 `git diff --check` 通过；完整对象读取及结构余项仍按未完成清单推进。
