# 错误日志的持久化完成回执

目标以[分级写入完成与断电持久性](../../architecture/logging.md#分级写入完成与断电持久性)为准。通用调用保持立即提交，重要级别的回执在实际持久化完成后才确认成功；必要业务停止及原错误交付不等待同步。

1. [x] 定义共同写入事实，分别表达追加、持久性及本级别完成；接通普通文件 writer、接纳通道、原诊断、副本和会话消费者。低层 alog 保持接纳完成点，同步失败不重投已追加记录。
2. [ ] 在共享文件锁内同步重要记录及目录链。轮换在任何级别触发时保持仍须保留内容的持久名字，先整理已中断搬迁，再执行正常淘汰；新增同步故障分类并保留追加事实。
3. [ ] 以公共入口验证真实文件与回执、同步失败、INFO 创建／轮换后 ERROR、正常保留与中断整理、副本及生产装配。保留取消、禁用、关闭和原错误去重的已有覆盖。
4. [ ] 依赖集成并独立评审，执行受影响检查，更新使用说明和验证记录，明确软件证据及目标物理断电验收边界。

## 建议实现与依赖

共同完成值可放在不依赖通道或文件处理器的基础类型模块，详细文件诊断继续归文件适配器；其他层从真实事实计算结果，不能仅凭追加布尔值确认重要级别成功。

文件处理器仍复用 concurrent-log-handler 的共享锁、文件打开与格式化。可在原写入边界加入同步；现有轮换内部的临时搬迁不满足持久名字要求，需替换这一窄范围的搬迁算法。一个可验证的方案是在正式归档名字间建立硬链接并同步目录，再删除旧名字并同步，利用文件身份整理中断产生的重复名字及空位，不维护持久化清单或新的数据库。具体拆分可依据实际库接缝调整，须满足同一不变量。

先冻结共同结果类型，再分工作区实现结果消费与文件适配；真实文件验证跟随结果接口接入，最终按依赖合并。物理断电与目标存储性能仍由现场验收独立记录，不能用进程 kill 或普通文件重开冒充。

## 进度

第 1 步已接通共同事实及全部生产消费者。原文件同步失败保留追加事实并返回非成功回执，原副本拥有者不重复追加；真实 stderr 入口只确认 stderr 交付。分域单元与公共生产装配已验证同步失败、业务继续及原异常身份。

第 2 步已接通重要记录的文件与目录同步、正式名字间的持久搬迁，正在核对轮换中断后的身份整理及关闭结果。第 3 步的真实文件回执、取消、禁用、排空、原副本及生产装配见证已接入，最终组合检查和独立源码复核在第 4 步完成；分域结果不作为最终合并来源的通过记录。
