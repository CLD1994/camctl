# Hasselblad 相机正式源实施计划

执行使用 `superpowers:subagent-driven-development`，按[仓库规则](../../../AGENTS.md)和[驱动契约](../../camctl/hasselblad-driver.md)推进。内部接口、预计修改文件及任务划分属于实施建议，可在保持行为契约的前提下调整。

目标：保留主机正式源模式，通过部署配置增加相机正式源模式，可靠登记相机原图与配对缩略图后回收主机副本，并接入现有独立取回和报告流程。

本计划记录单张 RAW 基础参数实现上的正式源扩展及相应软件验证。[RAW／JPEG 与显式拍摄参数](../specs/2026-10-20-hasselblad-photo-parameters-design.md)的新增目标另按其验收要求取得证据；本计划的完成状态不代表 JPEG 相机源或新增曝光、白平衡和对焦组合已经验收。

技术边界：Python 3.11，受管工具进程及 `host_files` 文件接口，不新增跨组件协议。单元测试隔离外部操作，组件集成测试在同一工作区逐目录、逐进程运行。所有变更在当前工作区完成，保留使用者已经更新的工具说明。

## 契约与横切验收

- 部署字段的归属、合法值、默认值和首次受理固化以驱动契约为准；拍摄参数类型保持原结构。
- 设备身份、单次拍摄和 START 完整结果保存共用现有链路；结果未知不重拍。
- 本次主机照片的大小与摘要作为相机源内容核验依据；可靠登记前不删除，临时副本不提升为正式源。
- 相机原图与缩略图有各自稳定身份和配对关系；双模式均产生现有公共产物字段及独立交付。
- 拍摄与下载文件均有创建前已经保存的责任；正常结束、错误、取消和重启遗留沿同一责任回收，错误不得静默丢失。
- 下载到主机后从可靠偏移向交付提供字节；当前工具需要完整下载的资源与恢复限制由驱动契约说明。
- 相机模式不声明设备删除能力；缺失该能力不伪装为主机正式源删除或相机文件缺席。

## 实施任务

### Task 1: 部署配置与受理执行定义

建议范围：Hasselblad 配置与能力定义、`devices/catalog.py`、`devices/tasks.py`、`capture/models.py` 及对应单元、受理与启动组合测试。

接口建议：在 `ActionCapability` 末尾增加可选的部署绑定任务工厂，目录按设备声明绑定为现有 `ParameterDefinition.task_factory`；其他驱动继续使用原工厂。同一静态驱动定义可以为不同设备产生不同固定任务，不通过全局可变配置或驱动参数传递选择。

- [x] 先写并运行失败测试：合法部署选择反映到动作任务与保存定义；省略、非法类型、非法值分别覆盖；计划携带存储字段仍由原 Schema 拒绝。
- [x] 配置纯解析采用统一存储类型，既有部署配置与旧主机执行定义保持合法。
- [x] 绑定部署配置并扩展单张执行定义校验；保存选择和原完整期限，恢复不使用本次新配置重算。
- [x] 覆盖两台同驱动设备的不同部署选择，以及改变配置后旧动作定义不变。
- [x] 运行配置、能力目录、单张执行定义和受理相关检查，记录命令、日志、退出码及 Python 版本。

### Task 2: 相机文件定位与受管下载

建议范围：Hasselblad 驱动及独立文件适配、`host_files` 下载工作目录接口、READ 责任的遗留文件维护及对应单元、设备和文件集成测试。

接口建议：以原图文件名及读取种类形成相机文件身份；定位同时携带拍摄时已经可靠保存的摘要。读取使用既有 `SourceFile`、READ 票据和 `ReadSession`。主机工作目录由原票据确定；低层文件适配不持有业务数据库。

- [x] 先写并运行失败测试：指定原图和缩略图可读、内容与拍摄结果一致、身份不符或内容不符时拒绝交付字节。
- [x] 复用绑定核对与受管工具入口，实际文件操作通过 `host_files` 执行；不猜测工具未说明的 stdout 格式。
- [x] 从指定原图名称下载一份文件，核验文件后提供偏移读取；使用有限准备期限和有界读取缓冲，保留调用及收场错误。
- [x] 正常、错误及取消后回收自己拥有的下载副本；重启遗留按原 READ 责任恢复，未结束调用不得删除文件。
- [x] 声明读取支持，保持源端摘要与相机删除的能力声明符合真实接口；相机无配置或不匹配时保留真实绑定错误。
- [x] 覆盖非零偏移、完整长度、超时、中断、下载部分文件、清理失败、重启遗留及重复读取，记录各项验证证据。

### Task 3: 双模式拍摄登记、主机副本回收与完整业务链

建议范围：单张拍摄编排、设备文件登记与元信息保存、现有中间文件维护、报告与安装版专项及对应集成测试。

接口建议：将现有主机拍摄的结果加载、双文件归档和完整事实保存复用到两种模式；按首次保存的执行定义选择正式源登记。相机模式使用设备文件及产物登记仓储，主机归档文件保持临时责任，动作终态后进入既有文件维护流程。

- [x] 先写并运行失败测试：相机模式保存两份设备源及配对，主机副本最终回收；主机模式保持离线多次取回及显式清理。
- [x] 复用 START 及双文件完成事实，不引入另一套拍摄流程或全相机差集；按原身份幂等登记相机文件和正式产物。
- [x] 将捕获时的可靠完整摘要保存为固定设备源摘要，复用既有 CHECKSUM 事件及后续拷贝核验，不增加虚构的相机摘要查询端口。
- [x] 相机产物登记事务可靠保存后才授予主机副本回收；回执未知先核原申请，归档或登记中断不重新拍摄。
- [x] 验证拍摄完成后机身断开仍可完成登记、报告和副本回收；后续实际相机取回必须核对原绑定。
- [x] 验证原图和预览的多次独立取回、取消及读取恢复，交付大小和摘要与本次拍摄事实一致；相机正式源删除能力缺失时逐项保存明确失败，不发起删除或保存删除成功。
- [x] 覆盖最终报告、历史重建、安装包资源与驱动装配；运行受影响单元及按目录隔离的集成回归。
- [x] 同步配置样例、相关规格与验证记录，分别报告软件通过范围及目标固件现场验收边界。
