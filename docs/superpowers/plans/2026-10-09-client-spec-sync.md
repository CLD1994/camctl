# 客户端规格同步实施计划

> 执行人员按 `subagent-driven-development` 或 `executing-plans` 逐任务实施，使用复选框记录实际完成情况。用户已授权在 `codex/client-spec-sync` 分支实施。本计划的行为要求来自下列有效规格；建议文件、内部接口和提交拆分允许按实际数据流调整。

**目标：** 客户端按公共协议可靠导出计划、接受和合并报告，提供预览与范围操作，并使客户端规格、验收及验证记录对应实际行为。

**协作结构：** 浏览器与后端共用纯校验和编辑规则；后端独立校验完整草稿，在事务中保存原请求和复制所需的编辑资料。报告原文、投影、覆盖和确认保持既有原子边界；自动预览维护只改变尚未导出的草稿。

**技术基础：** Node.js 24、TypeScript、现有 Ajv、jsonc-parser、React、SQLite、Vitest 与 Playwright。优先复用已有 Schema、数字词元、草稿版本及报告索引，不增加另一套公共字段清单。

**规格：** [全局总览](../../architecture/README.md)、[公共协议](../../../protocol/README.md)、[计划输入](../../architecture/plan-input.md)、[报告字段](../../architecture/report-format.md)、[公共编辑](../../architecture/client-editing.md)、[自动预览](../../client/automatic-previews.md)、[客户端保存](../../client/storage-and-recovery.md)。各任务还须实际读取列出的责任专题。

## 全局约束

- 公共机器协议以根 `protocol/schemas` 为字段、类型和组合的权威来源，业务语义以责任专题为准；不复制完整清单，不放宽 Schema。
- 对象及请求 ID 使用 1～9223372036854775807 的规范十进制字符串，不经过 `Number` 比较身份。
- 公共时间固定为 UTC `YYYY-MM-DD HH:mm:ss`，年份 0001～9999，无小数秒、后缀或首尾空白，日期真实有效。
- 公共协议与能力参数的 JSON 全部成员名和字符串值由 Unicode 标量组成；整数判定依据原数字的数学值，不能依靠浮点舍入接受非整数。私有草稿的原文运输与恢复只检查编辑资料结构，保留未完成或业务非法的文本，不能在保存之前套用公共输入资格；完整校验与导出仍须拒绝这些非法内容。
- 实体自身字段整体替换，实体子集合按身份合并。未知关联保留引用，已知矛盾拒绝；旧报告不得覆盖新事实。
- 合法报告可靠保存后才能推进覆盖和确认。拒绝或保存失败不留下部分投影、成功接收或确认。
- 动作终态、设备执行、产物、交付和本地核验分别表达；不从缺席值或终态补造执行经历。
- 自动预览开关有开启、关闭、尚未设置三种状态；开关、稳定身份、关联、正文和未完成输入作为同一草稿版本保存。
- 固定原请求不包含客户端编辑资料。再次下载不重新派生；复制继承可靠保存的开关资料，不能从自动动作数量推断开关。
- 单元测试在同一进程中隔离真实文件、数据库及网络；真实持久化、服务和浏览器流程属于集成测试。采用受接口约束的测试替身，交互断言只用于行为契约。
- 每项先加入能够证伪对应契约的窄测试，实际确认失败，再实现、验证和独立审查。禁止删除有效测试、吞错、伪造默认字段或调整业务范围换取通过。
- 内部选择和模块划分属于实施建议。发现计划未定义的业务状态或需要改变协议时，停止受影响任务并报告证据；不自行选择业务语义。
- 本任务不合并或推送分支，不扩大设备故障范围，不把真实设备、目标主机性能或物理断电作为软件集成前提。

## 审查重点与任务依赖

五个横切分区必须在所属任务中闭合：报告关联先后到达；终态但未开始或无法判断经历；JSON 原始事实与解析值不同；正文相同但编辑意图不同；草稿或能力变化与保存、导出响应未知交错。

| 任务 | 前置交付 | 独立可观察结果 |
| --- | --- | --- |
| 1 | 当前公共报告协议和真实客户端导入入口。 | 合法状态及联动报告可保存，关联矛盾被拒绝，历史失败身份保持。 |
| 2 | 当前解析器、公共 Schema 和能力目录。 | 整份正文按原输入精确校验，局部来源及自动预览语义完整。 |
| 3 | 任务 2 的完整计划校验。 | 所有范围表单及详情操作可生成正确引用，操作文案表达实际范围。 |
| 4 | 任务 2 的输入与自动关联判定；任务 3 的当前编辑入口。 | 三态意图与稳定关联可保存、重启、重载、复制及固定导出。 |
| 5 | 任务 1 的报告关联和任务 4 的编辑资料。 | 自动预览开关和结果展示可实际使用，异常和不完整关联不被隐藏。 |
| 6 | 任务 1～5 的软件结果和实际验证证据。 | 客户端文档及完整验收与生产行为一致。 |

任务 1 与任务 2 的分析可以并行，但生产改动按任务顺序交接；共享代码修改须避免交叉写入。每项审查通过后才将其接口交给后续任务。

**必须保持的分类：**

| 条件 | 校验及合并结果 |
| --- | --- |
| `expired` 带合法 `window_missed` 或 `window_exhausted`，不存在公开矛盾 | 接受，不补造开始执行或设备尝试。 |
| 其他状态带过期原因 | 按公共 Schema 拒绝。 |
| `completed` 计划快照包含非终态动作 | 拒绝明确状态矛盾。 |
| `pending` 计划出现 `running` 或明确的执行成功、执行失败结果 | 拒绝明确执行矛盾。 |
| `pending` 计划包含受理失败、无明确执行事实的取消或过期动作，另有待执行动作 | 接受；不以终态名称推断曾执行，不由动作子集重算计划。 |
| 取消直接选中拍摄或组，结果还包含其合法自动预览取回 | 基于已知 `automation` 及来源关系接受联动项。 |
| 拍摄拒绝取消，关联取回不是直接目标 | 不将它解释为有效联动；已有公开矛盾拒绝。 |
| 整个计划或单个取回直接选中自动取回 | 按直接目标处理，不依赖拍摄的取消资格。 |
| 关联对象同份可见或已有可靠历史 | 核验来源类型、归属、范围和预览原文件。 |
| 关联对象尚未取得 | 保留引用；后续出现时核验，不补造也不直接拒绝缺席。 |
| 预览原文件关系改变，或指向自身、已知非原文件、其他动作 | 拒绝；旧报告不能恢复旧关联。 |
| 取回失败只有真实来源及 `requested_output_id`，没有有效产物实体 | 以显式请求 ID 区分失败，不填写虚构 `output_id`。 |

## Task 4 自动预览编辑资料与后端生命周期
