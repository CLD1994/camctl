# 同机批量文件调度与 Hasselblad 查询修复

行为契约由[同机文件批次](../../architecture/file-batches.md)定义。现场归档表明，同机取回与清理的工具调用重叠产生 USB 占用错误；成功返回的图片列表使用多空格对齐并包含 JPEG。实际删除返回的相机错误由设备侧独立排查，继续保留原错误及未知结果语义。

## 实施步骤

- [x] P1：同步权威调度规格，定义批次持久化、申请、释放与取消恢复；独立审查数据与控制入口。
- [x] P2：实现批次表、事件、事务守卫及 V8 显式升级，保持旧表、历史和预算；实现完整来源、目标及旧读取依赖的资格判断。
- [x] P3：接通取回、清理、逐文件读取和实际派发；拍摄、准备与设备检查反向核对批次；保持必要停止及本地后处理推进。
- [x] P4：统一 Hasselblad 实际调用互斥；修复列表格式解析，保留未匹配路径和列表缺项为未知。
- [x] P5：以隔离单元测试验证状态分类、调度、取消和恢复入口，运行适用静态检查；独立评审并修正实际变更。
- [x] P6：记录实际通过、未验证范围及部署格式要求，按可审查阶段提交。
- [x] P7：接通已明确的 Hasselblad 固件路径例外，保留原身份及诊断；以隔离单元核对查询、删除及歧义边界，并独立复核。

模块和文件划分由实现时的数据流核对决定。已有逐文件机会、重试及结果保存责任继续复用，整批归属不能仅靠内存锁或旧尝试顺序推测。

## 验证范围

不新增、不运行集成测试，不调用真实相机，不修改已有部署环境。新单元用例必须隔离文件、数据库、工具及包资源协作者，不能把真实组合包装为单元测试。批次事务、显式升级、历史回放和目标硬件的组合行为保持为未执行的验证范围。

## 验收依据

同机整批连续执行，不同相机可并行；来源等待及旧读取依赖等待不占设备、不增加尝试。分页完整性、原持有者优先、重试保留、取消实际收场及重启接续使用同一持久事实。所有 USB 路径共用互斥，列表接受已核验格式并继续拒绝未知、重复或非法条目；相机路径等价仅采用[固件路径例外](../../camctl/hasselblad-driver.md#固件路径例外)，不将相机删除错误转为成功。

最终隔离单元范围通过 202 项及 12 个子测试，独立只读评审未发现剩余明确阻断项。实际通过、静态检查及未执行的组合范围见[验证记录](../../camctl/verification.md#同机文件批次与-hasselblad-查询2026-10-30)。V8 既有环境须先显式升级到 V9；本次没有改写部署环境。

后续[2026-10-31 真机验证](../../camctl/file-batches-real-device-verification-2026-10-31.md)确认来源等待、批次连续执行和释放；物理删除仍失败，取消收场发现既有读取结束判据缺陷。该记录分别维护真实通过项及未通过范围，不改变前述隔离单元验证的证据边界。

固件路径例外的三个隔离单元文件共 121 项通过；单元验证的实际范围见[对应验证记录](../../camctl/verification.md#hasselblad-固件路径例外2026-10-31)。

[后续路径修复真机复验](../../camctl/hasselblad-path-real-device-verification-2026-10-31.md)确认两张 JPEG、两批实际取回及两次物理删除成功，原图和预览共四个清理角色完成。查询解析器使用保存的真实列表复核；原取消收场缺陷及 RAW 拍摄没有计入本轮通过范围。
