# 状态报告客户端适配实施计划

> 本计划是客户端后续待办，尚未执行。执行时使用 `superpowers:executing-plans` 按任务落实；如果另行选择子代理执行，再使用 `superpowers:subagent-driven-development`。当前阶段只更新协议、样例和文档。

**目标：** 客户端可靠接收公共报告格式，让非技术用户判断计划是否按要求执行，正确保留部分结果、设备执行提示及文件接收状态。

**设计依据：** [正式字段契约](../../architecture/report-format.md)、[状态报告与合并](../../architecture/status-reports.md)、[公共 Schema](../../../protocol/schemas/status-report.schema.json)和[结果浏览](../../client/result-browsing.md)。字段定义由公共 Schema 提供，业务含义由正式契约提供；本计划不另建协议副本。

**技术基础：** 现有 TypeScript、Ajv、json-schema-to-typescript、Vitest 和客户端集成测试。预计修改位置用于定位职责，允许依据实际数据流调整模块和内部接口。

**实施状态：** 公共 Schema、样例和字段说明先行更新。客户端直接读取公共 Schema，但生成类型、生产校验、合并和展示仍使用待适配的结构。协议检查通过不代表客户端可用。

## 必须保持的契约

- 原始文件名和字节摘要、无歧义 JSON、Schema、可观察业务关系及历史关系均须校验；全部通过并可靠保存后才能采用报告及推进 ACK。
- ID 使用公共定义的规范十进制字符串，支持到 `9223372036854775807`。身份比较和排序不能经由有精度损失的 `Number`；报告、计划、请求、动作、产物、交付及诊断身份都须审计。
- 实体自身字段完整替换，缺席的可选字段不沿用旧值；实体子集合按身份合并，缺席或空集合不删除旧成员。较旧报告不覆盖较新事实。
- 动作终态保持；动作结束后的设备执行情况、产物状态和交付撤回可按各自事实更新。设备执行情况只属于原动作，不能被同一设备的新任务覆盖。
- 未开始与进行中、成功空结果与尚未取得结果必须区分。客户端不从未公开的过程信息补算主机判断，不以空数组推定动作成功。
- 主机发布文件、客户端收到文件和客户端核验通过分别保存和展示。失败或取消不删除已经保留的产物；来源暂缺时保留可靠引用。
- 公共的设备执行字段保持设备无关；展示文案按具体动作表达。用户说明不要求逐字固定，测试断言状态、对象关联和必要事实。
- 不以放宽校验、复制一份旧 Schema、伪造字段默认值或删除有效测试来完成适配。已经不属于公共协议的内部过程契约由 camctl 测试验证。

## 横切状态分类与验收重点

新报告包含已知动作时，先检查身份与历史顺序，再按下表处理；该表不改变累计覆盖规则。

| 条件 | 必须发生的结果 |
| --- | --- |
| 较新报告的终态动作带 `device_execution` | 更新设备执行提示，保持原动作终态和已保留产物。 |
| 较新报告的同一终态动作省略 `device_execution` | 清除旧提示，不把原动作改成成功，也不补造停止命令。 |
| 较旧报告带不同的设备执行情况 | 按旧历史校验，不覆盖较新提示或使已清除提示重新出现。 |
| 同一历史边界的自身字段相互矛盾 | 拒绝矛盾报告，不能部分保存业务状态或推进 ACK。 |
| 动作不是适用类型，或者尚未终态，却携带设备执行提示 | 拒绝非法结构，不通过隐藏界面提示接受报告。 |
| 进行中的取回或清理结果为空 | 表达仍在执行；不显示成功或最终零产物。 |
| 成功的取回或清理结果为空 | 按主机已经确定的成功空结果解释；不补造产物或失败。 |
| 增量报告没有列出来源、兄弟动作、产物或交付 | 保留已有对象和可靠引用，只校验当前可取得的关联证据。 |

重点覆盖：设备提示消失后的乱序报告；大于安全整数范围的身份；仅有子对象变化的父对象补齐；输入非法值和执行失败的区别；发布成功但客户端尚未收到文件。各任务须覆盖所属情形，最终用真实导入串联验证。

- [x] 执行相关单元测试，确认失败来自旧字段或身份假设；记录实际失败，不能把解析异常当作期望分支通过。

## 任务二：导入校验及可观察关系

**预计位置：** `apps/client/src/domain/reports.ts` 的 `parseReport`、`validateReport`、`ownFacts`、关联和失败项校验函数，以及其单元测试。

**输入与产出：** 输入为原始报告文件名和字节，输出为通过公共结构及当前可观察关系校验的 `StatusReport`，或者明确导入错误。

- [x] 先补充行为用例：受理失败保留原非法输入、执行失败保留错误、失败或取消仍有合法产物、取回逐项失败可定位目标、进行中空结果、成功空结果、来源尚未出现。
- [x] 对设备执行字段覆盖两个合法状态、可选观察错误、未知状态、缺少状态、非适用动作及未终态动作；对媒体结果和交付核验覆盖最终结论与完整大小、摘要。
- [x] 观察上述用例在旧实现上的失败，再调整导入和关系校验。受理失败依据 `status: failed` 与 `error.stage: admission` 判断，不生成内部执行经历字段。
- [x] 逐项审计哪些关系仍有公开证据：保留身份、归属、结果和文件关联的校验；将内部选择、调用和拷贝过程的正确性验收归到 camctl，不能要求报告补回这些数据。
- [x] 运行相应测试。合法的未知错误码仍接受并保留；未知状态、非法结构、已知关联矛盾仍拒绝。失败时没有部分状态写入或 ACK。

## 任务三：历史合并及结果展示

**预计位置：** `reports.ts` 的 `validateReportAgainstHistory`、`mergeReport`、`reportDecision`、`selectSyncReport`；`src/web/result-model.ts`、`src/web/ActionResult.tsx`、`src/web/common.tsx`，及对应单元测试。

**输入与产出：** 输入为有效报告与客户端可靠历史；输出为按历史边界更新的业务状态和面向用户的计划、动作、文件结果。

- [x] 先按横切分类表建立失败用例，分别验证较新、较旧、重复及同边界矛盾；每个测试只验证一个合并行为分支。
- [x] 实现完整自身字段替换与实体子集合合并，确保设备提示可出现、改变和消失；保留身份、终态及确定结果不回退的约束。
- [x] 验证交付先到、来源后到、仅产物或交付变化时父对象补齐；客户端不能根据增量子集重算完整计划状态。
- [x] 为展示模型建立失败用例：动作结束但设备结束未确认、已停止提示解除、保留部分产物、取回部分失败、主机发布但本地未收到、文件核验失败。
- [x] 更新结果模型和界面，按具体动作使用自然语言。执行过程的内部细节不成为用户判断计划结果的前提。
- [x] 运行相关单元测试和类型检查，审计同类判断的其他入口，包括自动预览归并、同步建议及取消目标展示。

## 已有基线问题

本次协议调整前，`pnpm --dir apps/client test:unit` 为 14 个文件中 2 个失败，521 个用例中 226 个失败、295 个通过。失败集中在 `tests/unit/reports.test.ts`（225 项）及 `tests/unit/capture.test.ts`（1 项）。已核验的错误包括样例使用数字型报告 ID、非规范对象及请求 ID、过时的 `plan_seq` 等，与当前公共 Schema 不符；不能把这些已有问题全部归因于本次字段调整。

本次 Schema 调整后复测仍为相同的 226 项失败、295 项通过，失败用例分组未变；错误中同时出现旧字段不再合法的原因。这不能证明客户端已经兼容，现有非法身份等问题可能使测试在到达后续逻辑前就失败。

执行本计划时须重新取得基线，按失败根因完成上述适配。类型检查或测试通过不能替代对公开字段覆盖和历史合并语义的核对。
