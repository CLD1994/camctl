# 历史恢复与快照维护的性能补全

本计划落实[历史计划 H4、H6、H7](2026-09-30-camctl-history.md)及[路线图阶段 7](2026-09-30-camctl-implementation-roadmap.md#阶段-7-历史快照与规模验证)的生产缺口。恢复方向由[历史查询](../../camctl/historical-state-query.md#按对象选择恢复路径)定义，维护资格、调度和退出由[快照维护](../../camctl/history-snapshots.md)定义，事务内复用由[数据库执行](../../camctl/persistence-runtime.md)定义。

## 已核实的输入与验收边界

当前完整对象恢复按对象累计变化次数选择路径，报告主要对象数组已经使用该入口。有限主行和限定业务列恢复仍固定逆向；快照入口的读取范围须按已提交 S 状态及选定的 `(S,H]` 回放闭合，具体职责由历史查询的快照读取小节定义。

快照维护已经通过共同数据库执行器接入正常 `run`，包括维护拥有者、可靠提交通知及新对象发现通知；业务和维护操作按既定优先级派发。正常运行的报告轻量变化探测仍有周期读取，不能把本轮改动描述成完全取消数据库轮询。

录像收尾的固定只读样本在小结果复用前执行 405 次 SQL，其中有 199 种 SQL 与参数组合；步骤 1 后为 360 次。该样本所有对象均未达到默认快照阈值，不能将其查询次数归因于缺少快照，也不能用该样本证明新快照路径的收益。

保持以下不变量：

- H、C、S 必须是可靠完整事务边界；累计变化次数按对象目录核对，不以全局事件距离代替。
- 恢复只应用原事件，不执行设备、预算或其他业务副作用；不存在、缺失、NULL、非法及未知提交分别处理。
- 快照读取核对固定元信息、格式、主行、行结构、归属和重复身份；业务字段取自 S 状态。原事件只在所选恢复区间核验和应用，当前值不覆盖快照中的旧值或 `null`。构建完整性由独立回放验收。
- 内存和缓存保持有限容量，独立业务判断与实际事实读取分工遵守[事务事实生命周期](../../camctl/persistence-runtime.md#单次完整事务的读取复用)。后续责任重构由[事务事实读取计划](2026-10-26-transaction-facts-refactor.md)跟踪，本计划未完的历史恢复与正常 run 维护能力仍分别验收。
- 快照积压不延长会话、不产生 `needs_run`。入队前超时仅停用本次维护，实际数据库错误和结果未知仍按原规则处理。
- 使用 Python 3.11 单元测试及同一只读样本诊断；本次不运行集成测试、不启动 camctl、不调用真机。新增跨组件协作的实际验证限制必须单列。

#### 报告读取优化的执行顺序

以下工作对应本步骤的报告必要读取验收；正常运行的快照维护装配由步骤 3 独立验收。模块划分为实现预估，允许按实际调用关系调整。

1. 以纯单元反例固定取消目标重复读取、取回多来源重复遍历及事件批次未传递。传递已恢复的取消目标事实；按 H 处不可变来源关系有界组织交付，保留全部相关失败、唯一性、缺失关系错误和既定排序。事件批次与候选行批次分离，默认 256 及其他合法正整数均能进入实际恢复调用。
2. 增加报告专用的有限恢复范围并接通真实 `generate_report_file`。从字段依赖登记推导表、关联和前置校验闭包；动作先取得必要主行与适用有限事实，再读取正式集合和对应增长关系。普通产物、交付及其引用文件同样按必要范围恢复。通用完整对象、快照编码和精确旧版本查询保持完整。已有对象事件分页仍核对结构、计数连续性和完整事务；当前、精确快照、正向、逆向和平局按原路径契约处理。不得用报告变化目录代替恢复目录。
3. 在每份报告范围内复用有限只读连接与空校验结构。每页仍释放读事务，保留实例、格式及状态库错误语义；每个恢复对象使用独立唯一性账本，成功、失败、取消及重试均清理临时行和键。不能增加跨报告长事务、无界缓存或常驻全部对象。
4. 集成前分别审查范围推导、增长关系、快照中原业务值及正向回放时序、关联失败、配置传递、资源释放及所有同类入口。用受真实接口约束的单元替身覆盖必要行缺失、未来成员排除、晚赋值回退、无关内部投影不读取、运行中已有结果，以及跨来源和非入选交付失败。只读生成原报告 43、44，核对原登记长度和摘要；分别测量候选行、正文、源库与临时库 SQL、事件数和校验结构创建，不用新旧不同操作作提速对照。
5. 本轮运行 Python 3.11 单元全量和受影响静态检查，不运行集成、不启动 camctl、不调用设备、不修改真实状态库。更新验证及本计划原验收项；核对精确快照零事件与正向严格区间，再报告实际收益与未覆盖边界。
