# 参数字段编辑与普通录像时长实施计划

**目标：** 客户端为已证明独立且可准确校验的枚举字段提供选项；普通录像接受整数秒；曝光先选择模式，再选择对应子字段，并保存各模式的输入；规则数值按精确原值展示。

**执行方式：** 在当前工作区按责任边界并行实施，完成后由独立 Agent 审查整个改动。用户已指定本计划的行为目标。实现分工和文件划分属于建议，可以按实际数据流调整。变更保留为可审阅的工作区改动。

**规格依据：** [客户端计划编辑](../../architecture/client-editing.md#参数选项联动)、[当前相机录像参数](../../architecture/camera-parameters.md)、[客户端验收](../../client/acceptance.md)。这些责任专题同步维护下列目标契约。

## 已确定的行为契约

完整有限目录仍优先使用完整 Schema 校验候选组合，组合上限保持 4096。完整目录不可用时，以根对象能否证明属性互相独立为前提，再逐字段判断局部选项资格。加载合法性与表单生成资格保持不同责任。

| 根对象与当前字段的条件 | 当前字段结果 |
| --- | --- |
| 完整目录可以准确生成 | 使用完整合法组合双向联动。空合法组合保持明确空集合。 |
| 根为封闭对象，仅含属性、必填和说明；当前字段为受支持的标量规则，其候选与验证断言均没有数值精度损失 | 提供局部允许选项，取该字段全部断言的交集。 |
| 前述根成立，但其他字段为对象、数组、局部组合或存在精度损失 | 不影响当前合格字段；对象字段满足级联资格时按模式生成子字段，其他复杂字段使用 JSON；没有有限候选域的普通数值字段保留数值输入。 |
| 根包含跨字段组合、依赖、引用、资源作用域、开放属性或其他未覆盖的断言 | 不推断局部独立选择；按既有不可推导行为使用 JSON。 |
| 当前有限候选字段含引用、资源作用域、复杂结构、未覆盖断言、不可准确表达的数值事实或超过 4096 个候选 | 当前候选字段使用 JSON；不使其他合格字段失去选项。 |
| 当前为没有有限候选域的普通字符串或数值字段 | 保留普通输入并按完整 Schema 校验，不枚举整个区间。 |
| 当前合格字段的局部断言排除全部候选 | 返回明确的空允许集合；不能解释为未知。 |

当前字段、其祖先或设备／动作／参数类型身份有未完成输入时暂停对应选择。同一参数对象其他字段的未完成输入不阻止独立选项，必须完整保留原文。选择只修改目标字段，保留其他数字词元、复杂字段与可选字段缺省，不补默认值。后端仍校验整份参数与计划。

Action6 与 OSMO 360 II 的普通录像 `duration_s` 是数学整数秒，范围为 `1` 至 `9223372036854775`，不设置默认值；小数秒、零、负数、越界、字符串和空值拒绝。`1.0`、`1e0` 等数学整数写法按同一整数值校验。时长以既有毫秒计时范围约束，执行计时、产物和恢复契约保持既有责任。

浏览器与后端共享的数值范围校验对输入与 Schema 的原数字词元比较数学大小，覆盖 `minimum`、`maximum`、`exclusiveMinimum` 和 `exclusiveMaximum`；不能因两个不同数学值投影为同一 `Number` 而接纳越界时长。直接字段、数组、本地引用及条件分支使用同一责任边界。复用 Ajv 的其他 Schema 校验，仅适配其原生浮点范围与步进运算无法满足的精确数字契约。

`multipleOf` 使用原数字词元判定精确整倍数，不能把合法小数步进候选误报为空允许集合。零满足任意合法正步进，符号不影响整除，零或负步进仍作为规则错误拒绝。判定不使用容差，也不按巨大指数展开十进制数字。

编辑页与设备说明页展示 Schema 数值时读取其父容器保存的原数字词元。包含上下界、严格上下界、默认说明和完整组合中的数值。展示及切换视图不修改草稿或规则。

## 项目约束

- 中文规格和说明，保留准确字段、命令和协议字面量。
- Python 验证使用部署指定的 Python 3.11，Node.js 使用既有 v24.16.0 环境。
- 复用现有 Ajv、精确 JSON 和 Schema 节点访问能力，不增加依赖。
- 浏览器回归使用既有 Playwright 测试，现场通过 Codex 浏览器工具核验。
- 不删除真实约束、不忽略数字误差、不隐式选择选项或曝光方式。
- 软件测试和浏览器证据不作为真实相机、目标主机性能或物理断电的证明。

## 审查重点

1. 复杂兄弟字段与当前局部标量选项的独立性证明不能混淆。
2. 根跨字段规则必须阻止无法证明的独立选择。
3. 数字精度损失只影响无法准确校验的候选范围，整份校验仍保留原事实。
4. 未完成曝光或时长输入不被其他枚举选择覆盖；可选字段保持缺省。
5. 能力生成、浏览器、导出与 Python 校验对整数秒的接受与拒绝一致。

## 任务四：跨组件测试的设备文件响应

根跨组件测试使用 `WorldTransport` 将远端脚本映射到本机 Bash，实际文件工具仍执行原来的摘要、长度和读取操作。测试替身必须向生产消费者返回目标 POSIX 格式，并保存原始文件字节和工具失败事实。设备路径由唯一结果页生产者使用 `/`；本机路径仍由 `Path` 管理。

摘要命令只能通过原远端脚本与权威 `ShellFileTools.digest_script(path)` 完整相等来识别；不能仅搜索命令名称或根据输出形状判断操作。成功条件沿用真实工具接口：`error` 与 `output_failure` 均为 `None`，具有退出码 `0`，stdout 为 `bytes`。stderr 不参与该成功判定，始终保留原值。

| 原远端脚本、工具结果与 stdout 的条件 | 测试替身返回 |
| --- | --- |
| 已登记的软件相机命令 | 保持原有软件命令返回；不经过文件摘要转换。 |
| 本机文件命令不能与权威摘要脚本完整匹配 | 不进行摘要 marker 转换，维持各操作既有响应适配与错误语义；不能识别脚本时不新增解析异常。 |
| 摘要脚本，但工具结果不满足上述成功条件 | 保持退出、错误、输出失败及原响应；不补造成功。 |
| 成功摘要脚本，stdout 完整匹配 64 个小写十六进制字节与 ` *-`、LF | 仅将 binary stdin marker 转为目标的双空格与 `-`、LF；摘要及其余结果字段保持原值。 |
| 成功摘要脚本，stdout 已是目标格式 | 保持原始工具结果。 |
| 成功摘要脚本，stdout 属于其余格式 | 保持原始响应；长度错误、字符错误、CRLF、缺少 LF、文件名或附加内容仍由严格生产解析器拒绝。 |

## 任务五：跨组件测试的报告读取

状态报告的正式部署消费者在 POSIX 文件系统读取 READY 文件。发布者可以在消费者持有旧报告读句柄时撤下旧文件并发布新文件；已打开的消费者继续读取原报告。Windows 开发机上的测试观察器使用相同语义，不能因为默认文件共享方式阻止发布者撤下旧报告。

适配仅位于测试侧读取 READY 报告的边界。POSIX 继续使用标准文件读取；Windows 通过标准库调用系统文件打开接口，使用只读访问、打开已有文件和允许读、写、删除共享的方式。复用系统文件句柄与 Python 文件对象，不增加第三方依赖，不使用关闭时删除标记。`opener` 只负责取得只读句柄并转换为文件描述符；转换失败由它释放句柄。文件描述符返回 `io.open` 后，其后文本包装成功、失败及读取关闭均完全由标准库负责，不再手动重复关闭文件描述符。

观察器继续使用 `encoding="utf-8"` 的文本 reader 和默认换行转换，将取得的文本交给原 JSON 解析器。UTF-16、UTF-32、无效 UTF-8 与 UTF-8 BOM 仍按原读取或解析规则报错，不通过二进制 JSON 自动编码识别扩大输入范围。

| 文件和读取状态 | 测试观察器的行为 |
| --- | --- |
| READY 中报告存在且正文合法，动作状态匹配 | 返回该报告正文；保持既有动作状态判定。 |
| READY 中报告存在且正文合法，动作状态不匹配 | 继续等待 READY 中满足条件的报告。 |
| 观察器已打开报告，发布者随后删除或重命名该路径 | 发布者可以完成文件操作，观察器仍读取已打开的原报告；关闭读句柄不删除未被发布者撤下的文件。 |
| 路径在列举后消失，或打开时遇到既有权限竞争 | 保持既有 `FileNotFoundError`、`PermissionError` 跳过语义，不解释为动作成功。 |
| 正文 JSON 无效或发生其他读取错误 | 保留错误，关闭句柄；不吞掉错误，不改读 STAGING，不补造就绪报告。 |

生产发布、撤下失败、重试和报告生命周期保持各自契约。测试的同步条件、等待时限、媒体读取门和 ACK 断言保持原值；不通过延长超时或增加随机延迟掩盖读取竞争。

- [x] 在测试报告观察器的唯一读取边界完成适配；审计共用观察器的所有调用入口。
