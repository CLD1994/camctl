# 相机启动余量实施计划

> **执行方式：** 使用 `superpowers:subagent-driven-development` 按任务执行。用户已授权计划完成后直接实施，并使用持续在线的 OSMO 360 II 做实际验证。

**目标：** 两款相机的新普通录像及适用原生延时采用独立的 1000 毫秒启动余量，OSMO 新延时请求最小间隔为 2 秒，并保持既有任务和历史可恢复。

**架构：** 型号参数由设备参数定义派生到 Schema、能力和安装资源。启动余量作为首次受理的执行定义，与可靠命令确认语义一起保存；正常计时、恢复、自然等待和持久化守卫共用精确计算。目标时长、实际设备开始和实际媒体时长分别表达。

**技术栈：** Python 3.11、现有 SQLite 事件与投影、JSON Schema、TypeScript 客户端、C host，以及 TX2 上的正式安装物和 ADB 驱动。

**规格：** [相机启动余量设计](../specs/2026-10-18-camera-startup-margin-design.md)。本页中的内部模块划分、签名和提交拆分是依据当前源码提出的实施建议；调整时须记录原因并保持规格契约。

## 全局约束

- 新适用任务保存 `startup_margin_ms = 1000`；缺字段表示旧规则，不在读取、恢复或重放时补默认值。新普通录像的 SENT 与余量须共同冻结，半套或非法定义拒绝。
- 普通录像新 START 的完整正常响应仅证明可靠命令接受，保存 `sent_at`，不生成实际 `started_at`。取消可在余量期间立即 STOP，设备占用和停止预算不刷新。
- 普通录像正常 STOP 不早于 `A + S + D`；有限原生延时自然核实不早于 `A + S + D + R + E`。用户目标、设备时间负载和媒体修复目标仍为原值。
- `S` 冻结；未完成等待采用新配置 `E` 时按原锚点更新预计时点并保存实际采用值。已经完成的等待不重新打开。可靠 STOP 后保留原独立文件等待，不叠加 `S`。
- 控制经过时间、录制时间下界和实际媒体时长不能混用。下界未超阈值不能证明实际未超，实际媒体不足不能因余量而通过。
- OSMO 新间隔从 2 秒起；Action6 保留 1 秒。旧 OSMO 1 秒任务通过原生效参数恢复，字节编码不改写。客户端旧草稿保留原值并提示修正。
- 生产实现任务顺序集成；每项在独立工作树修改、测试和提交。只读调查与评审可并行，测试资源按组件指南隔离。
- Action6 只做不访问设备的软件验证。真实相机只由协调者操作 OSMO；保留原片、状态库、任务身份和原确认，不重新初始化，不自动重发未知 START。

## 评审重点

1. 旧记录缺字段和新记录只保存一半字段容易混淆：任务 2 的执行定义测试分别验证兼容读取和拒绝。
2. 余量期间取消容易被当成“尚未开始”而释放：任务 2 验证占用保持、立即 STOP 和唯一 START。
3. 未完成等待改变 `E` 与恢复重复加 `S` 容易改变原责任：任务 2 验证更新、完成后复用和只等剩余时间。
4. 下界被写成实际媒体时长会误判过录或不足：任务 2 验证未知保持、实际短片失败和原裁剪目标。
5. 源码参数已变而安装资源或旧任务恢复未变：任务 1、3 验证真实客户端、安装版和旧负载，而不是另维护枚举。

#### 自然等待的时钟映射与保存状态

本节细化步骤 5—7 的实现边界。截止时点仍为 `Q = A + (S + D + R + E) × 1000`，单位为微秒。正常、有限取消和恢复共用同一活动的等待状态，不能分别创建另一份锚点或安排责任。

建议使用不可变 `WaitClockReference(utc_us: int, monotonic_ns: int)`，提供纯计算 `logical_deadline_ns(expected_check_at_us: int) -> int`。每个原活动在一个会话内只建立一次参考对 `(U, M)`：本会话可靠 ACK 使用原响应 UTC 和单调钟；恢复缺少本会话 ACK 时使用同次可信 UTC／单调钟读数。候选逻辑截止为 `L = M + (Q - U) × 1000`。之后改变 `E` 或墙钟读数不改变参考对，也不从当前时刻或可变截止反推 ACK。

逻辑截止 `L` 使用内存中的精确有符号整数，可以为负或早于当前单调钟；实际剩余等待才取 `max(0, L - now_monotonic_ns)`。持久化 `Q` 和各时长仍分别检查原整数边界；不能把内存中过去的逻辑截止套用到要求非负的持久字段或 `CaptureTiming.deadline_ns`，也不能因已到期而丢弃原映射。`plan_capture_wait` 的已到期分支也须保留逻辑截止。时间不可信时沿原降级处理，不建立替代锚点。

映射、候选安排、可靠生效的安排、未决保存申请分别表达。映射不依赖安排写入结果，可以保留；生效缓存必须在可靠提交或原申请核实成功后更新。安排或完成保存结果未知时，持有原操作键和完整申请，先结束未决事务并核实该键的保存事件及完整持久输入。当前仓储入口为 `persistence/repositories/timelapse.py`：`ScheduleWaitCommand` 须补原键复用核验；`WaitCompletedCommand._reuse` 的既有核验可用于同一完成申请。底层 `saved_transaction_events(connection, key)` 必须在合法事务内读取，不能用同连接中尚未提交的投影代替可靠结果。不同动作、活动、分支、时刻或等待规则的同键申请应拒绝。

| 当前状态 | 保存与缓存 | 后续推进 |
| --- | --- | --- |
| 新 ACK，尚无安排 | 保留原响应参考对，按原 A/S/D/R 与当前 E 计算候选 Q/L；保存首次安排 | 可靠保存后才按 L 等待或完成，不把事务耗时作为新起点。 |
| 恢复，原 Q 在未来、等于现在或已过去 | 只建立一次恢复参考对，三类都保留有符号 L | 截止已过只提供到期资格，不自动生成完成事实。 |
| 未完成，E 增大、减小或不变 | 从原参考对重新计算 Q/L；变动先保存新 Q/E，未变不新写事件 | 增减可跨过当前时点；可靠保存后才使用新安排判断到期。 |
| 安排保存可靠回滚 | 保留映射，生效缓存不变，候选不成为已采用事实 | 下次可按当前 E 重新计算，不在原截止上累计偏移。 |
| 安排保存 UNKNOWN | 保留原键和申请；原键核实成功后发布原安排，核实未提交后才放弃候选或原样重送 | 未决期间不改 E、不完成等待、不读设备；原安排确认后，若最新 E 不同，再用新申请重配。 |
| 完成保存可靠回滚 | 尚无完成事实，保留原映射 | 下次重新采用当前 E；E 增大时可以恢复等待。 |
| 完成保存 UNKNOWN | 先核实原完成键；已提交则复用原事件；可靠确认未提交后才重新判断 E | 不先重配或创建另一份完成申请；重送必须沿原键和原完整输入。 |
| 已可靠保存完成，随后 E 改变 | 保留原 Q/E、完成事件及原结果页来源 | 不重配、不重开，正常和有限取消均复用该依据。 |
| 缺少可信时间、可靠 ACK 或完整历史 | 保留原未知及必要占用 | 继续原有限收场，不能以当前时刻补成可靠依据。 |

验收矩阵须同时覆盖旧 `S=0`、新 `S=1000`、E 连续增减及墙钟前后跳，检查保存行、缓存、事件次数和零新增设备调用。新增反例包括：`A=NOW、S=1000ms、D=1000ms、R=200ms`，恢复读数为 `(A+3s, 10s)`，完成保存回滚后 E 从 0 改为 2000ms，正确逻辑截止为 11.2s；再覆盖负逻辑截止、回滚后减 E、安排及完成 UNKNOWN 在提交前／后的原键核实、同键改变输入拒绝，以及完成后修改 E 不重开。主机 STOP、有限取消和自然结果消费者须一起审计，避免把只用于等待的映射当作实际采集开始或媒体时长。

#### 完成事实与结果来源的时间资格

本节同时闭合运行推进、完成保存、结果页、文件完成及有限取消守卫。沿现有第一版时钟保障范围处理，不增加全局持续监测。定义 `W` 为可靠等待完成事件的真实发生时刻，`P` 为本次消费所引用的可靠结果页实际时刻；均从原事件读取，不能由当前时间或预计时点替代。正常、恢复和有限取消共用下表，新旧定义交叉取 `S=1000` 或显式 `S=0`。

| 原事实与当前资格 | 本次允许的处理 |
| --- | --- |
| 未完成，`mono < L` | 保留原安排；墙钟前跳不使等待完成。 |
| 未完成，`mono >= L`，真实 UTC `< Q` | 保留原映射、安排和占用，继续主机等待；不保存完成、不读设备、不释放。 |
| 未完成，`mono >= L`，真实 UTC `>= Q` | 用真实 UTC 创建完成申请；可靠保存后才使用完成事件。仓储和事件守卫独立核对原公式及该时刻。 |
| E 重配置可靠提交、完成保存回滚或可靠确认未提交 | 沿上一节原映射与实际采用的 E 重新计算 Q/L，再核对上述两类时间资格；不把当前时刻设为新锚点。 |
| 安排或完成保存 UNKNOWN，期间发生后跳或 E 变化 | 先按原键核实原完整申请；原实际时刻不变。已提交的完成不重开，未提交后才按当前 E 判定；原安排不变时可原样重送已满足资格的原申请。 |
| 已可靠完成，但当前 UTC 早于原 W/Q，或新观察时刻早于其引用的 P | 原完成、Q/E 与有效页保留；延后新的结果读取或新文件事实，不重新等目标全长，不新增设备调用。已有可靠原申请仍可沿原键原时间核实和复用。 |
| 已可靠完成，当前 UTC 足以承载原 W/Q 及本次来源 | 消费已有合格页，或沿原预算进行必要的新读取；后续保存仍核对原页与真实观察时刻，不因预检通过而免除守卫。 |
| 结果调用已在途，期间后跳，实际返回页时间 `< W/Q` | 保存或持有原真实调用、页、时间和尝试身份；该页不具有时间与产物完成资格，墙钟后来恢复也不能改变其原资格。不得以新身份覆盖原页或将文件改成完成。 |
| 在途返回不具上述资格，需要后续核实 | 原实际调用成功与业务完成不足分别保存；不把真实调用改成失败调用。沿原结果核实责任及剩余预算保存本次处置，允许后续独立检查，但须先满足当前来源资格；没有额度时按既有结果无法确认／取消收场，保留未知活动与必要占用。不得重发 START、重复 STOP 或刷新预算。 |
| 缺少原等待、页或历史依据，或时钟已被现有机制判为不可信 | 按既有一致性错误及受限收场处理，不把此类缺失归入可等待的普通后跳，也不补造时刻。 |

等待完成、结果页和文件事实必须使用各自真实时刻。不能使用 `max(实际时间, Q/W/P)` 生成事件时间。调用前资格与调用后页资格分别核对，不能只在外层挡住新调用；`_listing_round` 的在途恢复、已保存页消费及 `_register_listing` 的原页登记也必须遵守同一规则。不合格的实际页仍保留原调用与原始数据，之后的合格检查使用独立尝试／页身份，不能修改原页使其符合条件。已有合格页的保存未知继续原申请对账，不再读设备补记录。

主机等待资格不足时须让调度器安排有限的下一次检查，不能因逻辑 L 已过而形成零间隔循环。当前 UTC 距来源下界的差值只用于本次唤醒安排，不更改冻结 Q、逻辑 L 或原映射，不增加 ADB 轮询／保活。

`SCHEDULE`、`RECONFIGURE`、`COMPLETE` 的独立事件守卫统一核对合法有限自然任务、原动作／活动、可靠 A、冻结 D/R、S 及采用的 E，验证有界 `Q=A+(S+D+R+E)×1000`；COMPLETE 还核对真实完成时间 `>=Q`。旧定义仅显式取 S=0 并保持字段省略，不能跳过公式。历史与原键复用使用相同规则，非法申请不得新增事件或投影。用于自然等待的测试须构造合法自然任务，不能以普通录像的简化定义代替。

新增失败测试须覆盖：旧／新 S 的三个事件分支公式错误、正常及有限取消的完成前／后后跳、在途返回后跳、原页永久不合格及后续检查不覆盖它、完成／安排回滚和 UNKNOWN 提交前后交叉 E 增减、合格原页恢复时零新增读取、历史守卫拒绝错误源、等待期间没有忙循环和预算重置。先运行最窄反例及受影响入口，再运行 capture、history、cancellation 与 bootstrap 门禁。完整安装测试显式设置 `UV_PYTHON` 为部署版 Python 3.11；验证快照同时包括生产代码与共享测试夹具。

#### 逐页事实、整轮集合与保留产物

结果资格沿三个维度分别处理：每页原观察是否能支持该文件事实、本轮扫描能否支持完整集合，以及当前或此前已可靠保存的文件能否作为保留产物。整轮存在不合格页，不撤销另一合格页或前轮的可靠文件事实；已知文件也不能补足本轮扫描的空集合、缺件或不合格来源。

| 本轮页面与已有文件 | 文件事实与失败／取消保留 | 本轮集合及活动结束 |
| --- | --- | --- |
| 全部页合格且完整扫描，必要文件规则满足 | 按原归属、非零、配对及完成规则登记，保留符合要求的产物 | 可以继续原完成判断；仍须独立满足完整集合与必要产物，不能仅凭已有文件。 |
| 页合格但扫描未结束，或本轮必要文件缺失／不足 | 保存各合格页能独立证明的事实，保留已有合格文件 | 不把此前文件用于填补本轮缺失，不据此结束或释放活动。 |
| 同轮前页合格、后页不合格，或先不合格后有已持有的合格页 | 逐页核对，合格页仍可按原规则形成并恢复文件事实；不合格页保留原始输入，不能提供完成事实 | 整轮来源仍不足；不能因保留了合格前页而宣称当前集合完成。停止尚未派发的后续页调用，后续独立检查沿原预算。 |
| 本轮全部不合格，前轮已有可靠 COMPLETE 文件 | 保留前轮原文件、原来源及产物身份；不清空保留视图，不降级其可靠事实 | 本轮仍不足，既有文件只用于保留，不授予当前集合或活动结束资格。 |
| 本轮全部不合格，也没有已有合格文件 | 原实际调用、页与时间保留，没有合格产物时不补造输出 | 沿原有限核实／收场处理，不重置预算。 |
| 合格预览页依赖另一页的原片或配对事实 | 继续原配对、归属及完成规则；不能使用不合格页补出其缺少的证明 | 可选预览不能代替必要原片或本轮完整集合。 |
| 合格文件／结果的保存 UNKNOWN，或进程恢复 | 原键、原页和原文件身份先核实，合格文件恢复不新读设备 | 不重开已完成责任，也不把不合格原页因当前校时恢复而改成合格。 |
| 核实额度耗尽，正常失败或取消收场 | 从本活动已可靠文件与合格页面分批取得允许保留的产物，使用原文件及输出身份；终态仍保留它们 | 目标失败／取消、取消动作失败及必要占用按原规则处理。实际保留的输出集合可按终态规则固定，不等同于当前设备扫描完成或活动结束。 |

来源资格不足不得以清空整个 `entries`／`registered_files` 的方式处理。新增的保留读取须限定原动作、原活动和可靠来源，遵守分页边界；不能一次缓存完整目录，也不能采用其他动作的文件。需要完整扫描才能成立的配对规则仍按原要求处理。正常、有限取消、结果额度耗尽、已结束结果消费及保存未知恢复使用同一分类；下游独立文件、集合和有限取消守卫保持严格。

等待依据也必须与消费者使用同一可靠 SENT 语义：SCHEDULE、RECONFIGURE、COMPLETE 及其历史／原键复用，除核对原成功尝试及时间、事件、动作／活动身份外，还须核对原完整结果确有同一活动的有效 `timelapse_sent` 观察。合法但无关的 `photo_taken`、`start_confirmed`、其他活动观察、失败／未知效果或无观察，不提供该依据。复用完成上下文的同源确认校验，不另外维护型号响应值清单。旧 S=0 和新正 S 均使用原冻结定义及相同来源资格；不补新默认字段。

新增失败测试按旧／新 S、正常／有限取消、剩余预算／耗尽交叉覆盖：前轮 COMPLETE 原片＋末轮坏页、合格前页＋坏末页、合格非最终页＋停止后续页、已知完整文件＋当前空／缺件集合、可选预览与原片跨页、合格保存 UNKNOWN／进程恢复。逐项断言原始页、文件和输出身份、保留产物、原调用结果、有限次数、目标与取消双终态、集合判定和占用，不能只断言动作失败。另以错误观察类型、错误活动、无观察、错误状态／效果及正确 SENT 验证三个等待事件和历史守卫；错误申请不得留下等待或完成投影。

#### 结果来源与控制阶段的转换

文件采用的完成依据随原 RESULTS 责任及实际页确定，不随当前最新 STOP 改写。区分原结果尝试意图 `I`、原可靠自然等待完成事件 `W`、可靠 STOP 结果事件 `T` 及实际页 `P`；事件顺序与各自真实时刻分别核对。`I` 之前已经可靠保存的控制及等待事实，决定原结果请求可以采用哪一种上下文。仅有本次进程内的 `PendingResultScan.completion_context` 不足以承担重启证明；原意图、原控制结果、原等待及实际页须能从持久事实重建。

下表 STOP 文件等待及其原页复用要求，只适用于原执行定义声明 `file_completion_wait_ms` 的任务；合法旧定义缺该字段时继续按原直接完成保证核对。原意图及实际页的来源选择、原结果和文件守卫仍适用，不追补等待。`S` 是否存在与是否声明文件等待分别判断。

| 原结果来源及后来发生的控制变化 | 本页采用的完成依据 |
| --- | --- |
| `I` 前已有合法 W，且 `I` 前没有可靠 T；随后没有 STOP 或 STOP 失败／未知 | 按原自然来源核对 A/S/D/R/E/Q、W、P 及文件规则；不以失败 STOP 改写原来源。 |
| 同一自然来源在调用、页保存或文件保存期间发生取消，随后可靠保存 T | 原自然来源保持；合格页仍可用原自然等待及原页登记文件，不强加后来 STOP 的文件等待。原不合格页不会因 T 出现而获得资格。 |
| 同一自然 RESULTS 跨页，T 在其原意图之后出现，页在 T 前或后返回／可靠保存 | 原轮保持同一种上下文及原游标、预算；每页仍分别核对真实 P 与原 W/Q。后续推进遵守原取消收场和调用资格，不将尚未派发的页悄然换成 STOP 来源。 |
| `I` 前已有可靠 T，本页提供与该 T 匹配的真实完成等待或合法原页复用 | 采用原 STOP 来源，按独立文件等待及实际页核对；不追加 S、不要求自然 Q，也不改写为自然来源。 |
| `I` 前已有可靠 T，但本页缺少应有 STOP 等待依据，或等待引用、活动、原意图与实际页矛盾 | 保留实际调用与原始页，按既有来源不足／一致性错误及有限收场处理；不能因同时存在 W 就将这张 STOP 页重新解释为自然页。 |
| 原意图早于 W，且没有合法的 STOP 完成来源；后来才出现 W/T 或墙钟恢复 | 后来的事实不能补造原请求的自然完成资格。保存原实际结果，合格单文件保证按其原契约处理；没有合法完成来源时不得登记完成。 |
| 原页或文件保存 UNKNOWN，或在上述任一阶段重启 | 先核实原键、原完整输入及原来源；来源保持后再处理最新取消／STOP，不换页、换时刻、换文件或重新读取来补依据。 |
| 旧 v1／v2 历史没有额外的请求上下文字段 | 沿原意图之前的可靠事实、原页实际 STOP 等待证据及原任务契约重建。无法可靠区分或必需历史缺失时保留诊断，不从当前最新模式补造来源；旧定义的原保证不升级。 |

原自然请求不可能由其意图之后才可靠保存的 STOP 提供完成依据；STOP 请求的等待来源则必须属于原意图之前的可靠 STOP。实际页提供的等待引用仍须独立验证，不能只按事件位置判断已完成等待。建议在结果来源的共同读取边界形成只读分类，供逐页时间资格、登记、当前集合和终态保留共用；不增加另一套型号响应清单，也不依靠“当前活动已经结束”跳过原文件守卫。

取消结果与文件来源分别处理。取消先提交后，合格自然页可保留原片并固定允许保留的输出，但不能新增目标采集完成事实。可靠 STOP 提供独立设备结束及释放依据，不把原自然文件完成依据改成停止依据。STOP 失败／未知则继续原有限取消的等待和结束核实；原页若不能证明当前完整集合，已有合格文件仅用于保留，不能凭其释放未知占用。终态先提交的动作继续保留原终态。后续独立 STOP 结果页可以按原剩余预算确认此前未知文件，但不能修改或重新赋予原坏页资格；已可靠完成的文件保留原身份、元信息及原完成依据。

验收按旧 S=0／新 S=1000、取消前后、STOP 成功／失败／未知、合格／不合格／部分页、保存可靠／回滚／UNKNOWN／重启交叉覆盖。必要反例包括：合法 W 后的自然读取回调中生效公共取消、STOP 一次成功，再消费原合格 OSV，不新增结果读取或等待且不写目标完成；同场景原页早于 W/Q 时仍不合格；原自然多页跨越 T 仍沿原来源；真正 STOP 页即使已有 W 也不能免除独立等待；合格前页＋坏后页＋后来 STOP 不丢前页；原页／文件 UNKNOWN 在 T 前后对账后零重读。逐项核对原调用结果、事件顺序和真实时刻、完成 basis、文件／输出身份、预算、取消双终态、当前集合与占用；不以单个动作成功或测试总数代替来源证明。
