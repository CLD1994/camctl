# 客户演示：双录像与定向取回

生成结果写入仓库根 `.local/capture-and-retrieve/`。输入媒体由使用者放到根 `tmp/HuffmanExplainer.mp4` 和 `tmp/ModelMemoryStoryboard.mp4`；能力说明读取根 `data/device-capabilities.json`，应包含本计划使用的演示设备。媒体不随源码提交。

## 文件用途

- `plan.json`：粘贴到客户端“计划 JSON”编辑框的内容，包含两个录像动作和一个取回动作。
- `prepare.mjs`：导出后，将报告与当前客户端保存的真实请求配对，并生成交接文件。
- `preview-…/`：运行 `prepare.mjs --preview` 后生成的报告样例，供查看演示节奏；请求身份是预览身份，不能用于正式演示导入。
- `ready-…/`：运行配对命令后生成的正式演示包，包含 15 份状态报告、1 份交付视频、导出请求副本、清单和步骤说明。

## 第一步：展示计划并导出

1. 打开 http://localhost:4310/，新建草稿，切换到整份计划 JSON 编辑。
2. 将 `plan.json` 全部内容粘贴进去，回到表单展示参数和取回来源。
3. 向观众说明：固定参数录像没有额外参数；可调整参数录像选择 1080p / 30 帧；取回仅指向“固定参数录像”。
4. 导出计划。可以按演示时间调整执行时间、最大允许延迟或合法画质，然后再导出；三个动作的名称、顺序、类型、设备及取回来源保持本演示设定。

预设时间在当前上海时区显示为 2026 年 9 月 16 日 16:00、16:02、16:04。JSON 按协议保存 UTC。演示使用预先编排的模拟执行事实，无须等待这些时刻；它不会向相机下发命令。

## 第二步：生成与导出计划配对的报告

在 `apps/client` 目录的 PowerShell 运行（先按客户端说明安装依赖）：

```powershell
node --import tsx ../../demos/capture-and-retrieve/prepare.mjs
```

命令只读取客户端的导出记录，找到唯一同名计划后自动配对，不修改客户端数据。完成后会打印 `ready-…` 文件夹路径。

如果导出过多份同名计划，请指定刚刚下载的导出文件：

```powershell
node --import tsx ../../demos/capture-and-retrieve/prepare.mjs "C:\Users\84580\Downloads\实际导出的文件名.json"
```

客户端分配的 `request_id` 和 `created_at` 会原样进入报告，所以这一步必须发生在导出之后。报告文件名含自身原始字节的 SHA-256；生成后不要修改内容或重命名。脚本不会覆盖已存在的演示包。

本套报告从空的报告历史开始。生成时会核对当前客户端尚无导入记录；如果已有历史，脚本会停止，需另安排演示环境或按既有历史重新编排，不能清空历史冒充首次导入。

## 第三步：逐步导入

在 `ready-…` 中，按目录编号逐个导入。每次只选择当前步骤内的文件，等处理完成后回到状态页面讲解，再进行下一步。间隔由你控制，例如每步 5～10 秒；客户端状态按导入推进。

| 步骤 | 导入后讲解的状态 |
| --- | --- |
| 01 | 计划已受理，三个动作等待执行 |
| 02 | 固定参数录像开始 |
| 03 | 固定参数录像进行中，控制计时达到 30 秒 |
| 04 | 固定参数录像已停止，尚未登记正式产物 |
| 05 | 固定参数录像完成，第一份产物出现 |
| 06 | 可调整参数录像开始 |
| 07 | 可调整参数录像进行中，控制计时达到 30 秒 |
| 08 | 两段录像完成，两份产物均已登记 |
| 09 | 取回固定参数录像，拷贝进度 0% |
| 10 | 拷贝进度 25% |
| 11 | 拷贝进度 75% |
| 12 | 拷贝进度 100%，核对摘要中 |
| 13 | 摘要匹配，交付准备完成 |
| 14 | 正在发布交付文件 |
| 15 | 计划完成，交付已发布；客户端尚未收到视频 |
| 16 | 导入交付视频，等待本地校验通过，打开播放 |

每份报告保存完整的当前计划快照，水位依次连续推进，报告也保留已经成立的尝试和产物事实。不要一次导入全部报告，否则观众会直接看到最终状态。界面已有的详情区可以展开查看录像控制计时、拷贝字节数和校验阶段。

## 两个视频的对应关系

| 原视频 | 对应动作 | 最终位置 |
| --- | --- | --- |
| `tmp/HuffmanExplainer.mp4` | 固定参数录像 | 登记正式产物，经取回动作形成交付，第 16 步导入并播放 |
| `tmp/ModelMemoryStoryboard.mp4` | 可调整参数录像 | 登记正式产物，保留在模拟相机端，本计划不取回 |

交付视频是 `HuffmanExplainer.mp4` 的逐字节副本，文件名按协议改为完整 delivery ID 加 `.mp4`。请导入第 16 步中的副本，不要导入原文件名。

两个视频均为现成演示素材，报告中的录像控制过程是模拟事实。文件大小与 SHA-256 取自实际文件；媒体检查状态表达为“未执行”、媒体时长表达为“未知”，不把模拟的 60 秒控制计时冒充素材时长。实际素材的画面、分辨率和时长不代表本次对真实相机的采集结果。

只取回固定参数视频意味着只有这一份会成为本地可播放的交付。可调整参数视频仍能在状态页体现“拍摄完成且已有产物”，但不能在没有取回交付记录的情况下伪装为已收到。

## 已执行的验证

- 执行计划通过当前 `data/device-capabilities.json` 校验。
- 15 份报告通过文件名摘要、Schema、语义约束及连续历史合并校验。
- 独立临时数据库通过真实客户端导入服务逐份接受 15 份报告，覆盖水位达到 150。
- 真实视频导入后状态为 `verified`，字节数和 SHA-256 与交付映射一致。
- Chromium 已实际打开并播放两个原视频：均为 1920×1080，固定参数素材实际长 131 秒，可调整参数素材实际长 84 秒。
- 正式配对命令每次生成文件前再次执行计划、报告、导入和文件摘要校验；失败时不生成交接目录。浏览器播放检查独立执行。

生成器和计划输入保存在本目录；媒体素材留在根 `tmp`，生成包写入根 `.local/capture-and-retrieve`。生成器只读取日常客户端资料，导入验证使用独立临时数据库。
